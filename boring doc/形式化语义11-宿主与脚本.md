## 一、本卷定位与分工边界

## 二、脚本模式五阶段管线

### 2.1 管线总判断式

$$\frac{\begin{aligned}&\text{L0: } \textit{tokens} = \text{Lexer}(\text{src}, \text{fileName}) \\ &\text{L1: } \textit{rawAst} = \text{parseScriptSource}(\text{src}, \text{fileName}, \textit{allowUntyped}) \\ &\text{L2: } \textit{userAst} = \textit{gi}\ ?\ \text{GlobalInference.infer}(\textit{rawAst}, \ldots) : \textit{rawAst} \\ &\text{L3: } \Phi;\ \text{Checker}(\textit{checkedAst}, \textit{scriptMode}=\text{true}) \Rightarrow \delta^{*} \qquad \neg\,\text{hasError}(\Phi) \\ &\text{L4: } \sigma \vdash \textit{stdlibEntries} + \textit{rawAst.entries} \Downarrow v^{*}\end{aligned}}{\mathcal{I} \vdash \texttt{run}(\text{src}, \text{fileName}) \Downarrow v^{*}} \quad (\text{B-Pipeline})$$

良构前提：src 为合法 UTF-8 源码；fileName 非空；$\mathcal{I}$ 已构造（registerStdlib 已完成）。

**阶段依赖链**：L1 依赖 L0（Parser 消费 token 流）；L2 依赖 L1（推导对象是 rawAst 中的 InferMarker 占位）；L3 依赖 L2（Checker 需完整类型标注，占位未填充时报 E-TYPE-MISMATCH）；L4 依赖 L3（求值前提是静态检查通过）。任一阶段失败即终止管线，不进入后续阶段。

可运行脚本示例（顶层语句直接执行、无需 main）：

```subs
// count.subs
var total : Nat = 0
fun bump(n: Nat): Nat = n + 1
total = bump(total)
print(total)          // 1
axiom nonNeg          // 顶层声明语句同样合法
```

### 2.2 L0-L1：词法与语法

$$\frac{\text{src} \in \text{String}}{\text{Lexer}(\text{src}, \text{fn}) \Rightarrow [\text{token}_1, \ldots, \text{EOF}]} \quad (\text{B-Lex})$$

$$\frac{\textit{allowUntyped} = \textit{gi}}{\text{parseScriptSource}(\text{src}, \text{fn}, \textit{allowUntyped}) \Rightarrow \textit{rawAst}} \quad (\text{B-Parse-Script})$$

`scriptMode = true` 使 Parser 顶层回退到 `parseStmt`（Parser.kt:204/208），允许语句直接出现在顶层。`allowUntyped = true` 时省略类型解析为 `InferMarker`（Ast.kt:111）；`false` 时 Parser 拒绝。L0/L1 失败抛 `RuntimeException`（E-LEX/E-PARSE）。

### 2.3 L2：全局类型推导（可选）

$$\frac{\textit{gi} = \text{true}}{\text{GlobalInference.infer}(\textit{rawAst}, \textit{stdlibEntries}, \textit{hostRets}, \textit{notes}) \Rightarrow \textit{userAst}} \quad (\text{B-GI}) \qquad \frac{\textit{gi} = \text{false}}{\textit{userAst} = \textit{rawAst}} \quad (\text{B-GI-Skip})$$

良构前提：`gi = true` 时 L1 须以 `allowUntyped = true` 完成。推导在 Checker 之前执行（Interpreter.kt:199-210），因为 Checker 需完整类型标注。推导产物仅填充类型/注解/前后件，**不影响运行时**：L4 求值对象是 `stdlibEntries + rawAst.entries`（Interpreter.kt:239）。冲突时抛 InterpreterError，脚本在进入 Checker 前中止（:206-209）。详见 §七。

### 2.4 L3：语义检查

$$\frac{\textit{checkedAst} = \text{FileAst}(\textit{stdlibEntries} + \textit{structEntries} + \textit{hostEntries} + \textit{userAst.entries})}{\text{Checker}(\textit{checkedAst}, \textit{scriptMode}=\text{true}).\text{run}() \Rightarrow \Phi} \quad (\text{B-Check})$$

`scriptMode = true` 使 `topPure = false`（Checker.kt:209），脚本顶层等价于隐式 `@impure` 主体。$\Phi$ 含 ERROR 时抛 InterpreterError（:216-220），不进入 L4。

### 2.5 L4：解释求值

$$\frac{\sigma = \text{ScriptFrame}(\textit{globalFrame}) \qquad \textit{eval} = \text{Evaluator}(\textit{hostFunctions}, \textit{hostStructs})}{\textit{eval.evaluate}(\text{FileAst}(\textit{stdlibEntries} + \textit{rawAst.entries}), \sigma, \textit{mainName}) \Downarrow v^{*}} \quad (\text{B-Eval})$$

求值规则见 06 卷。宿主函数调用先于帧查找（Evaluator.kt:513-518）。部分执行语义：已执行效果保留，不回滚。

## 三、`.subs` 独立执行语义

### 3.1 单脚本与隔离

$$\frac{p.\text{name}.\text{endsWith}(\texttt{".subs"})}{\mathcal{I}.\texttt{runScript}(p) = \mathcal{I}.\texttt{run}(p.\text{readText}(), p.\text{name})} \quad (\text{B-RunScript})$$

$$\frac{\mathcal{I} \vdash \texttt{runScripts}(p_1, p_2) \qquad p_1 \neq p_2}{\textit{frame}(p_1) \cap \textit{frame}(p_2) = \varnothing \ \land\ \Phi(p_1) \cap \Phi(p_2) = \varnothing \ \land\ \textit{hostFunctions}(p_1) = \textit{hostFunctions}(p_2)} \quad (\text{B-Iso})$$

隔离四项含义：① 帧不共享——每次 `run` 重建 `globalFrame`（:152），`declareFunction` 只增不去重，故必须重建；② 符号表不共享——Checker 每次新建（:214），符号表随 Checker 实例生灭，因此跨文件符号不可见是帧+符号表双重隔离的必然结果；③ 诊断不跨文件——DiagBag 随 Checker 生灭，CLI 在每个脚本执行后独立打印 inferNotes（Main.kt:409/421）；④ 宿主表是跨脚本常数——`hostFunctionInfos` 与 `hostStructs` 属于 Interpreter 实例（:28-29），不随 `run` 重建，这正是宿主注入能力的通道。

### 3.2 目录形态与退出码

$$\frac{\textit{subsIn}(d) = [s_1, \ldots, s_n],\ n > 0}{\mathcal{I}.\texttt{runScriptDir}(d) = \text{逐条}\ \mathcal{I}.\texttt{runScript}(s_i)} \quad (\text{B-DirSubs}) \qquad \frac{\textit{subsIn}(d) = \varnothing}{\Rightarrow \texttt{InterpreterError}} \quad (\text{B-NoSubs})$$

`subsIn` 取顶层（非递归）`.subs`，按名排序（:147-148）。任一脚本抛异常 → `[错误]` + 退出码 1，后续不再执行（Main.kt:383-385）。

## 四、工程模式入口

### 4.1 main 入口与约束

$$\frac{\textit{scriptMode} = \text{false} \qquad \texttt{fun main()} \in \sigma_{\textit{funs}} \qquad \nexists\ \text{顶层 StmtEntry}}{\sigma \vdash \texttt{main()}()} \quad (\text{B-Main})$$

$$\frac{\texttt{fun main}(\textit{params}) \qquad \textit{params} \neq \varnothing \ \lor\ \Theta \neq \varnothing}{\texttt{E-MAIN-PARAMS}@\textit{pos}} \quad (\text{B-Main-Params})$$

$$\frac{|\{m \in \text{tree} \mid m \vdash \texttt{fun main()}\}| \geq 2}{\texttt{E-DUP-DECL}} \quad (\text{B-Main-Unique})$$

`runDir` 固定 `scriptMode=false, mainName="main"`（:123）。main 唯一性是全树判据（MultiModule.kt:128-140）；普通声明唯一性是模块内判据。

### 4.2 无 `.subs` 时工程回退

$$\frac{\texttt{run-script}(d) \qquad \textit{subsIn}(d) = \varnothing \qquad \textit{sublTop}(d) \neq \varnothing}{\mathcal{I} \vdash \textit{runDir}(d) \Downarrow \text{合并顶层}.subl \Rightarrow \texttt{fun main()}} \quad (\text{B-Fallback})$$

CLI 目录分支（Main.kt:403-417）：有 `.subs` → 逐脚本；否则 `[工程]` + `runDir`。`runDir` 仅取顶层 `.subl`（:121-123），与 compile 全树语义不同。目录即模块的扫描/挂载/可见性见 08 卷。

## 六、宿主边界

### 6.1 绑定判断与注册 API

$$\frac{h \in \textit{hostFunctions} \cup \textit{hostStructs}}{\sigma \vdash_{\text{host}} h \mapsto v} \quad (\text{B-BIND})$$

良构前提：$h$ 的名称已在 $\mathcal{I}$ 中注册。宿主函数调用时先于帧查找解析（Evaluator.kt:513-518）：`hostFunctions[name]` 命中即 `toHost(args) → fn → fromHost(result)`。

三种注册形态（:55-78）：`register(name, params, retType, fn)` 带类型签名（推荐，Checker 据此做类型检查）；`registerGeneric(name, typeParams, params, retType, fn)` 泛型宿主函数，签名中 `ScriptType.Named` 名即类型变量；`register(name, fn)` 无签名兼容接口，签名按 Any→Any 处理。结构体注入 `injectStruct`（:81-95）：可变字段标 `@mut`，任一字段可变则结构体标 `@mut`，依赖顺序由宿主负责（不做拓扑排序）。

### 6.2 `@host` 声明合成

$$\frac{\mathcal{I}.\textit{hostFunctionInfos}[\textit{name}] = \textit{sig}}{\textit{checkedAst} \mathrel{+}= \texttt{@host fun}\ \textit{name}(\textit{params}) : \tau_{ret}\ (\text{无体})} \quad (\text{B-HostDecl})$$

空参补 `(x: Any)`；Checker 对 `"host" in annotations` 跳过 E-FUN-NO-BODY（Symbols.kt:246-251）。

### 6.4 跨边界值转换与引用语义

toHost（:383-393）：Num→Long, Real→Double, Str→String, Bool→Boolean, Null→null, ListV→List(递归), OptionalV→解包, ResultV/Struct/Fun→原样穿透。fromHost（:396-407）：反向映射，兜底 toString()→Str。

$$\frac{v \in \{\text{Struct}, \text{ResultV}, \text{ListV}, \text{Fun}\} \qquad v\ \text{跨宿主边界}}{v\ \text{保持对象标识（引用语义）}} \quad (\text{B-Ref-Semantics})$$

成立范围：Struct/ResultV/ListV/Fun 四类复合值。Num/Real/Str/Bool/Null 为不可变原始值，谈引用无意义。OptionalV 在 toHost 解包、fromHost 重包装，是包装层拆装而非例外。

**与 06 卷 bindCopy 的层面区分**：引用语义是跨宿主边界的默认行为（toHost/fromHost 路径）；bindCopy 是脚本内部绑定（var/赋值）时的行为（06 卷 §六）。二者属不同层面，不冲突。`var x = hostObj` 仍受 bindCopy 四规则支配（04 卷 §2），可能触发深拷贝；但 hostObj 从宿主传入时是引用语义。

### 6.5 stdlib prelude 与 @root 过滤

$$\frac{e = \texttt{@root fun}\ \_\_\_ \qquad e \in \textit{stdlibEntries}}{e \notin \textit{prelude}} \quad (\text{B-Prelude-Filter})$$

core 下全部 `.subl` 经解析后删去 `@root` 无体函数声明（:255-258）。理由：脚本模式内建由宿主表 + Checker 内建表提供，留着撞 E-DUP-DECL。过滤仅针对函数条目；struct/enum/类型类照常注入。解析失败即致命（:251-253）。

## 七、全局类型推导（`--global-inference`）

### 7.1 作用域与优先级

**脚本模式专属**：仅 `run-script` 解析（Main.kt:392）；USAGE 明示编译模式不受影响（:37-38）。

优先级序列（$T_x$ 为 InferMarker 占位的待解类型）：

$$\frac{T_x \neq \textit{InferMarker}}{\textit{infer}(x) = T_x} \quad (\text{B-INF-EXPL}) \qquad \frac{T_x = \textit{IM} \qquad \textit{ctorSites}(x) = \{\tau\}}{\textit{infer}(x) = \tau} \quad (\text{B-INF-CTOR})$$

$$\frac{T_x = \textit{IM} \qquad |\textit{ctorSites}| \geq 2 \qquad x \in \textit{arithUse} \qquad \forall \tau:\ \textit{numeric}(\tau)}{\textit{infer}(x) = [T: \text{Num}]} \quad (\text{B-INF-ARITH})$$

$$\frac{T_x = \textit{IM} \qquad x \in \textit{memberUse}}{\textit{infer}(x) = \text{Str}} \quad (\text{B-INF-MEMBER}) \qquad \frac{T_x = \textit{IM} \qquad \textit{ctorSites} = \varnothing \qquad x \notin \textit{arithUse} \cup \textit{memberUse}}{\textit{infer}(x) = [T: \text{Any}]} \quad (\text{B-INF-ANY})$$

### 7.2 冲突与效应

$$\frac{\tau_1 \neq \tau_2 \in \textit{ctorSites}(x) \qquad \text{不相容使用点或结构体字段}}{\texttt{E-TYPE-CONFLICT} \qquad \textit{infer}(x) := \text{Any}} \quad (\text{B-INF-CONFLICT})$$

错误级 → InterpreterError，Checker 前中止（:206-209）。效应不动点（solveImpurity :663-684）：@impure/非纯内建/自递归无递减 → impure 集，沿调用图冒泡。自递归未证停机 → D-AUTO-IMPURE。可变性回填（:774-865）；上下文前件反提/后件交集（:688-770）。

不变界：显式标注最高优先；stdlib/宿主返回仅作锚点；求值侧用 rawAst（:239）；gi 关闭时 Parser 拒绝省略类型。

## 八、`--target` 宿主调用侧

生成侧差异见 07 卷 §7。本卷定义宿主如何调用产物与桥接协议。

### 8.1 node 目标

$$\frac{\text{target} = \text{NODE}}{\text{node <file>} \Rightarrow \text{IIFE 自执行} \Rightarrow \text{main() 自动调用}} \quad (\text{B-Target-Node})$$

向后兼容。异步 IO 可用（main 天然 async）。

### 8.2 browser/wasm（S-1 装载模型）

$$\frac{\text{target} \neq \text{NODE}}{\text{宿主 eval 产物} \Rightarrow \text{globalThis.__subl.main 赋值} \Rightarrow \text{宿主显式调用}} \quad (\text{B-Target-S1})$$

宿主桥协议：

$$\frac{\text{name} \in \text{BRIDGE\_OPS}}{\text{JS 调用 } \texttt{globalThis.__subl.call(op, args)}} \quad (\text{B-Bridge-Call})$$

BRIDGE_OPS = {println, print, readLine, readFile, writeFile, appendFile, readDir, fileExists, getArgs, sleep}（Target.kt:51-54）。

### 8.3 wasm 同步 IO 拒绝与平台分派

$$\frac{\text{target} = \text{WASM} \qquad \text{name} \in \text{WASM\_REJECTED}}{\text{E-PLATFORM-UNAVAILABLE}} \quad (\text{B-Wasm-Reject})$$

WASM_REJECTED = {readLine, readFile, writeFile, appendFile, readDir, fileExists}（Target.kt:57-59）。println/print 在 wasm 走宿主桥（JsCodeGen.kt:1071-1072）。

平台分派级联：target=NODE ∨ name∈userFns → NODE_DIRECT；target=WASM ∧ name∈WASM_REJECTED → WASM_REJECT；name∈BRIDGE_OPS → BRIDGE（JsCodeGen.kt:1067-1073）。用户同名函数优先让位（:1068）。

## 一、本卷的地位与语义域

### 1.1 本卷定义什么

本卷形式化**宿主互操作与脚本**判断系统，即 00 卷分工表中的第 11 卷（判断 `σ ⊢_{host} h ↦ v`，规则前缀 `B-`）。固定五样东西：

1. **宿主域**（§1.2-§1.3）：宿主函数/结构体如何绑定成脚本侧的值与声明；
2. **脚本模式语义**（§2）：顶层语句直接执行、多脚本隔离、工程回退、stdlib prelude 注入；
3. **工程模式入口**（§3）：`fun main` 入口与 `E-DUP-DECL` 全树唯一性；
4. **全局类型推导**（§4）：`--global-inference` 的优先级序列判断式与冲突判据；
5. **两模式对照**（§七）：脚本模式与工程模式在同一判断框架下的差异表。

诊断码（`E-DUP-DECL`、`E-MAIN-PARAMS`、`E-TYPE-CONFLICT`、`E-ROOT-NOT-ALLOWED`…）以出现位置（诊断表/行文）与规则名区分；与 04 卷效应规则前缀 `E-` 同名异义的处理同 00 卷 §4 注。判断式体例同 00 卷 §1.2：横线上为前提、下为结论、右端规则名；中文一律置于 `\text{...}`；命题蕴含记 `→`，程序位分支/函数体记 `=>`。

### 1.2 宿主域

宿主域 `H` 由 `Interpreter` 的三张表给出（Interpreter.kt:28-34）：

$$h ::= \text{hostFun}(\textit{sig}) \mid \text{hostStruct}(\textit{info}) \qquad \textit{sig} = (\text{形参表},\ \tau_{ret},\ \textit{fn},\ \Theta)$$

- `hostFunctionInfos`：`LinkedHashMap<String, HostFuncSig>`——名 → 签名 + Kotlin 实现闭包 `fn: (List<Any?>) -> Any?`；
- `hostStructs`：`LinkedHashMap<String, StructInfo>`——名 → 字段类型/props/可变字段/注解；
- `globalFrame`：每次 `runEntries` 重建的顶层帧（H7：避免重复注册，`declareFunction` 只增不去重，Interpreter.kt:151-152）。

跨边界值转换 `toHost/fromHost`（Interpreter.kt:383-407）：`Num→Long`、`Real→Double`、`Str→String`、`Bool→Boolean`、`Null→null`、`ListV→List`、`OptionalV→null|值`、`ResultV` 与其余值**原样穿透**；宿主侧 `List`、`Boolean`、`Long`、`Int`、`Double`、`Float`、`String` 回包装为脚本值，其余降级为 `Str(toString())`。跨边界一律**引用语义**（不拷贝；脚本改宿主对象即改宿主对象本体）。

跨边界的函数值统一接口为 `ScriptFunction`（ScriptFunction.kt:10-33）：泛型与上下文（前后件）全部**擦除为属性**（`typeParams`/`preps`/`posts`/`paramTypes`/`retType` 为渲染字符串），宿主只读属性、调 `call(args)`；`instantiate(typeArgs)` 为可选的单态化通道（默认返回自身）。宿主不感知泛型实例化、值包装、前件检查——这些由解释器在 `call` 内完成。

### 1.3 执行环境

$$\mathcal{I} = (\textit{stdlibDir},\ \textit{gi}) \qquad \textit{gi} \in \{\text{false},\ \text{true}\}$$

`Interpreter(stdlibDir = File("core"), globalInference = false)`（Interpreter.kt:16-25）。`stdlibDir` 为 core 统一标准库目录（递归收集 `.subl`，按相对路径排序）；`gi` 为全局类型推导开关（§4）。CLI 的 `run-script` 子命令构造 `Interpreter(globalInference = …)`（Main.kt:378；单文件分支 Main.kt:352-353）。补充级诊断出口 `inferNotes`（Interpreter.kt:32-34）。

一个最小宿主回合（可运行形态）：

```kotlin
val interp = Interpreter(stdlibDir = File("core"))
interp.register("hostLog", "s" to ScriptType.Str, retType = ScriptType.Null) { args ->
    println(args[0]); null
}
interp.runScript(File("hello.subs"))
```

对应脚本（脚本侧感知不到「这是宿主来的」，看起来就是普通函数）：

```subs
// hello.subs
print("启动")
hostLog("来自宿主的一声问候")
```

## 二、脚本模式语义

### 2.1 脚本源解析

脚本模式的解析入口是 `parseScriptSource(src, fileName, allowUntyped)`（Parser.kt:1794-1795），构造 `Parser(..., scriptMode = true, allowUntyped = …)`：顶层允许直接出现**语句**（`parseFile` 在 scriptMode 下回退到 `parseStmt`，Parser.kt:204/208），工程模式顶层只允许声明（`parseEntry`：fun/type/enum/struct/impl/axiom）。`allowUntyped` 由且仅由 `gi` 开启（Interpreter.kt:105-108）：开启时省略的形参/字段类型解析为占位 `InferMarker`（`NamedType("<infer>")`，Ast.kt:111；Parser.kt:396），由 §4 的 `GlobalInference` 在 Checker 前替换。

### 2.2 顶层语句直接执行（无 main）

$$\frac{\Gamma_{\text{top}};\ \pi_{\text{top}} \vdash s_1 \dots s_n \qquad \textit{mainName} = \bot}{\mathcal{I} \vdash \texttt{run}(\text{src}) \Downarrow \text{逐条执行}\ s_1 \dots s_n} \quad (\text{B-TopLevel})$$

- 脚本顶层即入口：顶层语句按出现顺序求值（`Evaluator.evaluate` 遍历 `StmtEntry`，Evaluator.kt:29-48），**无需 `fun main`**；`runScript` 以 `entryName = null` 调 `run`（Interpreter.kt:130-132）；工程模式侧 `runEntries(scriptMode = false, mainName = "main")`（§3.1）。
- 顶层作用域：`var` 对后续顶层语句可见、`fun` 对脚本内所有语句可见（声明先于求值统一收集进帧，Evaluator.kt:31-36）；脚本结束作用域即消失、不对外可见。
- 顶层纯度：`topPure = !scriptMode`（Checker.kt:209）——脚本顶层等价于一个隐式的 `@impure` 主体，允许调用非纯函数（如 `print`）；工程模式顶层纯。

可运行示例（顶层 var 对后续可见、顶层 fun 全脚本可见）：

```subs
// count.subs
var total : Nat = 0
fun bump(n: Nat): Nat = n + 1
total = bump(total)
print(total)          // 1
axiom nonNeg          // 顶层声明语句同样合法
```

### 2.3 执行管线

$$\frac{\begin{aligned}&\textit{host} = \text{合成}\ @\texttt{host}\ \text{声明} \qquad \textit{struct} = \text{合成 StructDecl} \\ &\textit{prelude} = \text{stdlib}(.subl) \setminus @\texttt{root} \qquad \textit{user} = \textit{gi}\ ?\ \text{infer}(\text{raw}) : \text{raw}\end{aligned}}{\begin{aligned}&\textit{CheckedAst} = \textit{prelude} + \textit{struct} + \textit{host} + \textit{user} \\ &\Phi;\ \text{Checker}(\textit{scriptMode}) \vdash \textit{CheckedAst} \Rightarrow \delta^{*} \qquad \sigma \vdash \textit{prelude} + \textit{raw} \Downarrow v^{*}\end{aligned}} \quad (\text{B-Pipeline})$$

五步（Interpreter.kt:150-240，对应代码注释的 §4/§6 执行模型）：

1. **合成 @host 声明**：`HostFuncSig` → 无体 `FunDecl(annotations = ["host"])`（§5.2）；空参签名补一个 `(x: Any)`；
2. **合成宿主结构体**：`injectStruct` → `StructDecl`（可变字段标 `@mut`；任一字段可变则结构体标 `@mut`；字段携带 `defaultValueFor` 默认值，Interpreter.kt:178-192）；
3. **stdlib prelude**：core 目录递归收集 `.subl` → `parseSource` → **过滤 `@root` 函数条目**（§2.6），再拼用户条目；
4. **Checker**：`Checker(checkedAst, scriptMode = true)`——类型推断/上下文/纯度/HKT 全部静态检查（含 §2.2 的 `topPure`）；有错误级诊断即抛 `InterpreterError("脚本类型检查失败: …")`（Interpreter.kt:214-220）；
5. **Evaluator**：宿主函数表注入求值器；求值对象为 `stdlibEntries + rawAst.entries`（Interpreter.kt:239）——注意即使 `gi` 开启，**求值侧用的仍是未填充的 raw AST**：推导只填类型/注解/前后件，不影响运行时行为（不变式见 §4.5）。

### 2.4 多脚本隔离

$$\frac{\mathcal{I} \vdash \texttt{runScripts}(p_1, p_2) \qquad p_1 \neq p_2}{\neg\,(\textit{decls}(p_1) \rightsquigarrow_{\text{可见}} p_2) \quad \land \quad \neg\,(\textit{decls}(p_2) \rightsquigarrow_{\text{可见}} p_1)} \quad (\text{B-Iso})$$

- 每个脚本一次独立的 `run`：独立解析、独立 Checker、独立 `globalFrame`（H7：每次 `runEntries` 重建），与其他脚本**互不共享用户声明**（`runScript`＝`run(path.readText(), path.name)`；`runScripts` 逐个 `runScript`，Interpreter.kt:130-137）。
- 目录形态 `runScriptDir`：`subsIn(dir)` 取**顶层**（非递归）`.subs` 按文件名排序，各自独立运行（不合并、不共享，Interpreter.kt:140-148）；空目录抛 `InterpreterError("目录 … 下没有 .subs 脚本文件")`。
- 隔离是**声明级**的：宿主注入与 stdlib prelude 对每个脚本同样重新装载，两次 `run` 之间宿主表本身也不泄漏用户声明；同一 `Interpreter` 实例的宿主注册是跨脚本常数（这正是宿主注入能力的通道）。

### 2.5 无 `.subs` 时工程回退

$$\frac{\texttt{run-script}(d) \qquad d \in \text{Dir} \qquad \textit{subsIn}(d) = \varnothing \qquad \textit{sublTop}(d) \neq \varnothing}{\mathcal{I} \vdash \textit{runDir}(d) \Downarrow \text{合并顶层}.subl \Rightarrow \texttt{fun main()}} \quad (\text{B-Fallback})$$

CLI `runScriptCmd` 的目录分支（Main.kt:386-400）：`subsIn(f)` 非空 → 逐脚本执行并打印 `[脚本] <name>`；否则打印 `[工程] <path>` 调 `runDir(f)`——编译程序（编译器自身等 daily 工程）以 `.subl` 工程 + `fun main()` 入口解释执行。边界：

$$\frac{\textit{sublTop}(d) = \varnothing}{\textit{runDir}(d) \Rightarrow \texttt{InterpreterError}(\text{“目录 … 下没有 .subl 文件”})} \quad (\text{B-NoSubl})$$

`runDir` 只取目录**顶层** `.subl`（`listFiles` 非递归，按名排序）合并为单 `FileAst`（Interpreter.kt:120-124）——与 `check/compile` 目录模式的**全树**扫描（MultiModule，根 `/`）不同（§6.3、08 卷）。

### 2.6 stdlib prelude 注入

$$\frac{f \in \textit{stdlibFiles}(\textit{stdlibDir}) \qquad e \in \textit{entries}(f) \qquad e = \texttt{@root fun}\ \_\_\_}{e \notin \textit{prelude}} \quad (\text{B-Prelude-Filter})$$

- prelude = core 下全部 `.subl`（`walkTopDown`，按相对路径排序，Interpreter.kt:37-40）经 `parseSource` 解析后的条目，**删去 `@root` 无体函数声明**（Interpreter.kt:246-259）。
- 删除理由（同注释 v4）：脚本模式下内建由**宿主函数表**（`hostEntries`）与 **checker 内建表**（`builtinimpure`/`builtinPure`，Types.kt:50/145）提供；core 中的 `@root` 条目（`print`/`readFile`/`jsonParse`/`timeNow`…）仅为声明文档，留在合成 AST 里会与 `@host` 声明撞 `E-DUP-DECL`。
- 过滤只针对**函数条目**：`@root` 之外的 struct/enum/类型类声明及其他条目照常注入；core 是**隐式挂载**的（无需 mount，_langfacts.md §2）。
- 解析失败即致命：`InterpreterError("标准库文件解析失败 <name>: …")`（Interpreter.kt:251-253）。
- Checker 另有自身 prelude：每模块注册 `Bool`/`Null`/`Optional` 枚举（`collectPrelude`，Checker.kt:182-187）。

### 2.7 帧语义（ScriptFrame）

求值帧 `σ` 由 `ScriptFrame`（ScriptFrame.kt 全文，62 行）给出：

$$\sigma = (\textit{vars},\ \textit{muts},\ \textit{refs},\ \textit{funs},\ \sigma_{\text{parent}})$$

- `lookupVar/hasVar/isMutable/isRef` 沿父链查找；`declareVar(n, v, mut, ref)` 登记；`assignVar` 就近赋值，找不到抛 `InterpreterError("未定义的变量 … 无法赋值")`（ScriptFrame.kt:14-29）；
- 函数按名存**重载组**：`lookupFunctions` 合并本帧与父链并按 `signatureKey`（`名(形参类型渲染序列)`，ScriptFrame.kt:49-50）去重——承载标准库 List/Set/Map 容器方法按接收者类型的重载分派；`lookupFunction` 取重载组首项；
- `localFunctions()` 供闭包捕获快照复制（函数闭包捕获在 lambda 创建时深拷贝，`copedFrame` 沿父链逐值拷，06 卷）；`child()` 建子帧。

### 2.8 错误路径与部分执行语义

$$\frac{\sigma \vdash s_1 \Downarrow v_1 \dots \sigma \vdash s_k \Downarrow v_k \qquad \sigma \vdash s_{k+1} \Rightarrow \textit{err}}{\mathcal{I} \vdash \texttt{run}(\text{src}) \Rightarrow \textit{err} \qquad v_1 \dots v_k\ \text{的效果保留（不回滚）}} \quad (\text{B-Partial-Effect})$$

脚本执行到一半报错时，前面已执行的效果（标准输出、宿主侧状态、文件写入）**保留**——同 Python 的立即错误模型，没有事务回滚。错误种类：

- **解析期**：`E-LEX`/`E-PARSE` 由 `parseScriptSource` 抛 `RuntimeException`，尚未进入求值；
- **静态期**：Checker 错误级诊断 → `InterpreterError("脚本类型检查失败: …")`（Interpreter.kt:216-220）；推导冲突 → `InterpreterError("脚本全局类型推导冲突: …")`（§4.3）；
- **运行期**：`InterpreterError`（未定义函数/变量、异步特性不支持、赋值目标非法、`panic` 路径等，Evaluator 各处）；
- **CLI 层**：`RuntimeException` 统一捕获 → `[错误] <msg>` + 退出码 1（Main.kt:366-369）。

## 三、工程模式入口

### 3.1 `fun main` 入口

$$\frac{\textit{sublTop}(d) \neq \varnothing \qquad \nexists\ \text{顶层语句} \qquad \texttt{fun main()} \in \sigma_{\textit{funs}}}{\mathcal{I} \vdash \textit{runDir}(d) \Rightarrow \sigma \vdash \texttt{main()}()} \quad (\text{B-Main})$$

`Evaluator.evaluate`：顶层全是声明（无 `StmtEntry`）且 `mainName != null` 且帧中有 `main` 时，以 `<main>` 位置无参调用（Evaluator.kt:44-47）。`runDir` 固定 `scriptMode = false, mainName = "main"`（Interpreter.kt:123）。

入口形约束（决策 70，Symbols.kt:243-245）：

$$\frac{\texttt{fun main}(\dots) \qquad (\text{形参表} \neq \varnothing \ \lor\ \Theta \neq \varnothing)}{\texttt{E-MAIN-PARAMS}@\textit{pos}} \quad (\text{B-Main-Params})$$

消息固定为「入口函数 main 不能有形参或类型参数。写成 `fun main() { … }`」；重复声明由 `E-DUP-DECL` 兜底（同注释）。

### 3.2 `E-DUP-DECL` 全树唯一

$$\frac{\{m \in \textit{tree} \mid m \vdash \texttt{fun main()}\ (\text{0 形参、有体})\} = \{m_1, m_2, \dots\} \qquad |\{m_1, m_2, \dots\}| \geq 2}{\Phi \vdash \textit{tree} \Rightarrow \texttt{E-DUP-DECL}(\text{“多个模块声明了入口 main：…“})} \quad (\text{B-Main-Unique})$$

实现于 `MultiModule.runPhases`（MultiModule.kt:128-140）：全树每个模块统计「有体、0 形参的 `main`」，多于一个即报错。模块**内**重名由 `Symbols` 登记的 `putIfAbsent` 兜底报 `E-DUP-DECL`（Checker.kt:174 注；Symbols.kt:123-202：函数按名+首参、枚举/结构体/类型类/别名/自定义命题按名）。即：`main` 的唯一性是**全树判据**，普通声明的唯一性是**模块内判据**；本地名与挂载名冲突亦报 `E-DUP-DECL`（ModuleTree.kt:213）。

### 3.3 工程模式的解释执行与编译执行

- **解释执行**：`runDir`（§2.5 的回退路径，`run-script <dir>`）；顶层 `.subl` 合并为单 `FileAst`、`main` 为入口；
- **编译执行**：`check/compile <dir>` 走 `MultiModule` 全树模块化（挂载/可见性，08 卷）生成合并 JS（`generateJs`，MultiModule.kt:151）；执行由外部 `node` 承接（§6.2）。

## 四、全局类型推导（`--global-inference`）

### 4.1 开关与定位

`gi` 是**脚本模式专属**旗标：`--global-inference` 只在 `run-script` 解析（USAGE 明示「脚本模式专属，编译模式不受影响」，Main.kt:31-32；解析见 Main.kt:375-378）。定位（GlobalInference.kt:1-22）：用户省略标注时填一个「能过检查、符合所想」的标注，**不追求 principal type**；解析期以 `allowUntyped` 放行（§2.1），推导在 **Checker 之前**执行。

### 4.2 优先级序列判断式

优先级（doc 与 USAGE 一致）：**显式标注 > 构造点 > 使用点 > 默认 Any**。以参数/字段 `x` 的待解类型 `T_x`（`InferMarker` 占位）为对象：

$$\frac{T_x \neq \textit{InferMarker}}{\textit{infer}(x) = T_x} \quad (\text{B-INF-EXPL})$$

（不变式：非 InferMarker 的类型与已有注解/前后件**一律保留、只填不盖**，GlobalInference.kt:21。）

$$\frac{T_x = \textit{InferMarker} \qquad \textit{ctorSites}(x) = \{\tau\}}{\textit{infer}(x) = \tau} \quad (\text{B-INF-CTOR})$$

构造点 = 字面量/构造调用形态（`IntLit→Nat`、`FloatLit→Rat`、`StrLit→Str`、`true/false→Bool`、`null→Null`、结构体构造→结构体名，GlobalInference.kt:404-422）。**函数参数**允许多构造点（每次调用独立实例化）：

$$\frac{T_x = \textit{InferMarker} \qquad |\textit{ctorSites}(x)| \geq 2 \qquad x \in \textit{arithUse} \qquad \forall \tau \in \textit{ctorSites}(x):\ \textit{numeric}(\tau)}{\textit{infer}(x) = [T: \text{Num}]\ (\text{同一函数内共享该}\ T)} \quad (\text{B-INF-ARITH})$$

$$\frac{T_x = \textit{InferMarker} \qquad \textit{ctorSites}(x) = \varnothing\ \lor\ |\textit{ctorSites}(x)| \geq 2 \qquad x \in \textit{memberUse}}{\textit{infer}(x) = \text{Str}} \quad (\text{B-INF-MEMBER})$$

使用点成员约束由 `x.length()`（方法糖 `callee` 为 `FieldExpr`，或自由形态 `length(x)`）采集（GlobalInference.kt:189-192、239-244）。

$$\frac{T_x = \textit{InferMarker} \qquad \textit{ctorSites}(x) = \varnothing \qquad x \notin \textit{arithUse} \qquad x \notin \textit{memberUse}}{\textit{infer}(x) = [T: \text{Any}]} \quad (\text{B-INF-ANY})$$

结构体字段同构（`solveStructFields`），但字段**不**按调用独立实例化：多构造点给异类型即冲突（§4.3）；无构造点字段泛型化 `T: Any`（GlobalInference.kt:368-402）。因此「默认 Any」有两种落地：参数级 `[T: Any]`（类型变量，按调用点实例化）与冲突兜底字面 `Any`（§4.3）。

返回类型（`solveReturnTypes`，GlobalInference.kt:433-485）：Tarjan SCC 按**被调者先解**排序；无环函数以 `BodyTyper` 近似体类型（只填确信类型：字面量/参数/算术/公共分支/已知返回的调用，未知即 `null`）；环（自递归/互递归）走**假设签名-验证**的 3 轮迭代，收敛不了不报错、交回 Checker（GlobalInference.kt:453-484）。

推导示例（脚本，可运行）：

```subs
// infer.subs —— 省略标注，run-script --global-inference
fun add(a, b) = a + b          // B-INF-ARITH：a、b → [T: Num]
fun shout(s) = s + "!"         // B-INF-CTOR(+B-INF-ARITH)：s → Str
fun first(xs) = xs.length()    // B-INF-MEMBER：xs → Str
fun mystery(z) = 42            // 无构造/使用点：z → [T: Any]
print(add(1, 2))
```

### 4.3 冲突判断式（E-TYPE-CONFLICT）

$$\frac{\tau_1, \tau_2 \in \textit{ctorSites}(x) \quad \tau_1 \neq \tau_2 \qquad (x \in \textit{memberUse} \land \tau_i \neq \text{Str})\ \lor\ (x \in \textit{arithUse} \land \neg\,\textit{numeric}(\tau_i))\ \lor\ x\ \text{为结构体字段}}{\texttt{E-TYPE-CONFLICT}@\textit{pos}(\tau_1, \tau_2) \qquad \textit{infer}(x) := \text{Any}} \quad (\text{B-INF-CONFLICT})$$

错误级语义：`InferNote(severity = "ERROR", "E-TYPE-CONFLICT", …)` 由 `runEntries` 检出后抛 `InterpreterError("脚本全局类型推导冲突: …")`，**脚本在进入 Checker 前中止**（Interpreter.kt:206-209）。诊断消息指明两个冲突来源位置（`CallExpr.pos` 为空时退回声明处，GlobalInference.kt:428-429）。参数级「多构造点 + 相容使用点」不报错（走 B-INF-ARITH/B-INF-ANY 泛型化）；结构体字段多构造点必报错（doc §4.2/§十一）。另一形态：同一参数既被算术使用又被成员使用（要数值又要 `Str`），直接报冲突（GlobalInference.kt:348-352）。

### 4.4 效应、可变性与上下文推导

$$\frac{f \in \textit{userFuns} \qquad \text{“impure”} \in \textit{anns}(f)\ \lor\ \exists c \in \textit{bodyCalls}(f): \textit{builtinimpure}(c) \neq \bot\ \lor\ (f \in \textit{bodyCalls}(f) \land \textit{selfRecShrinking}(f) \neq \text{true})}{f \in \textit{impure}} \quad (\text{B-INF-IMPURE-Direct})$$

$$\frac{f \in \textit{userFuns} \qquad \exists c \in \textit{bodyCalls}(f): c \in \textit{impure}}{f \in \textit{impure}} \quad (\text{B-INF-IMPURE-Lift}) \qquad \frac{f\ \text{为自递归未证停机}\ \land\ f \notin \textit{impure}}{\texttt{D-AUTO-IMPURE}@f \quad f \in \textit{impure}} \quad (\text{B-INF-AutoImpure})$$

效应是**不动点**（`solveImpurity` 迭代至稳定，GlobalInference.kt:663-684）：`@impure` 显式标注、调用非纯内建、自递归无递减实参（递归调用实参中无 `-` 二元表达式，GlobalInference.kt:184）三者直接入集，再沿调用图向上冒泡。自递归未证停机的纯函数被降级为 `@impure` 放行并产**补充级** `D-AUTO-IMPURE`（用户自担「可能不停」风险；显式标注返回类型是精确控制的逃生舱，Main.kt:98 的 explain 文案）。

- 可变性（B-INF-MUT）：赋值目标链（`AssignStmt.target`）收集后回填——根变量标 `@mut var`、字段标 `@mut`、结构体任一字段可变则标 `@mut`（`walkTarget`/`rebuildStruct`，GlobalInference.kt:774-865）；
- 上下文（B-INF-CTX）：前件从被调者**反提**至调用者（命题参数 `@q` 一并提升，fixpoint 至稳定、至多 8 轮，`solvePreps`，GlobalInference.kt:688-723）；后件取**所有 return 处可证命题的交集**（`∵` 注入参与，`postFacts`/`walkForPosts`，GlobalInference.kt:737-770）；`@theorem` 函数不参与（`isTheorem`，GlobalInference.kt:114）；
- class 成员签名回填：impl 已解出的形参/返回类型回填到 class 声明（`buildClassBackfill`，GlobalInference.kt:637-659）。

### 4.5 不变界

1. 显式标注最高优先（B-INF-EXPL），产物仍**整体过 Checker**——推导只管填充，闸门仍在 Checker；
2. stdlib 与宿主返回类型只作**约束锚点**（`hostRets`：`HostFuncSig.retType` 取 `NamedType` 名、否则 `Any`，Interpreter.kt:199-210；stdlib 返回类型表 `stdlibRets`），不参与被推；
3. `D-AUTO-IMPURE` 等补充级诊断经 `Interpreter.inferNotes` 暴露，CLI 在每个脚本执行后按 `[提示] [CODE] msg` 打印（Main.kt:392、404）；
4. **求值侧与推导产物解耦**：Evaluator 求值 `stdlibEntries + rawAst.entries`（Interpreter.kt:239），推导填充的类型/注解/前后件不影响运行时；
5. `gi` 关闭时 `allowUntyped = false`——省略类型在解析期即被 Parser 拒绝（Parser.kt:396 的 else 分支），脚本不进入推导路径。

## 五、宿主函数注册与内建

### 5.1 注册 API 判断式

$$\frac{\textit{sig} = (\textit{params},\ \tau_{ret},\ \textit{fn}) \qquad \mathcal{I}.\texttt{register}(\textit{name},\ \textit{params}^{*},\ \textit{retType},\ \textit{fn})}{\mathcal{I}.\textit{hostFunctionInfos}(\textit{name}) := \textit{sig}} \quad (\text{B-Reg})$$

- `register(name, vararg params, retType = ScriptType.Null, fn)`：带类型签名注册（Checker 据合成声明做类型检查，Interpreter.kt:55-62）；
- `registerGeneric(name, typeParams, params, retType, fn)`：泛型宿主函数——签名中的 `ScriptType.Named` 名即类型变量（`map[A,B]` 形态），合成 `@host` 声明的 `theory` 域带 `TypeParam`（Interpreter.kt:64-73、156-175）；
- `register(name, fn)`（兼容旧接口）：签名按 `Any → Any` 处理（`retType = ScriptType.Any`，Interpreter.kt:75-78）；
- `injectStruct(name, fields, props, mutableFields, annotations)`：注入结构体类型定义（§2.3 第 2 步），`StructInfo` 由字段表/props/可变字段/注解构成（Interpreter.kt:80-95）；依赖顺序由宿主负责（不做拓扑排序）。

### 5.2 `@host` 声明合成

$$\frac{\mathcal{I}.\textit{hostFunctionInfos}(\textit{name}) = \textit{sig}}{\textit{CheckedAst}\ \mathrel{+}=\ \texttt{@host fun}\ \textit{name}(\textit{params}) : \tau_{ret}\ \ (\text{无体})} \quad (\text{B-HostDecl})$$

合成细节（Interpreter.kt:156-175）：`sig.params = []` 时补**一个** `(x: Any)` 形参（兼容简单调用）；`retType == ScriptType.Any` 时返回类型合成 `Any`，否则由 `typeFromScriptType` 映射（`ListT/OptionalT/TupleT/FunT/AnyT/NullT/Named` → 对应 AST 类型，Interpreter.kt:272-283）；`@host` 无体——体由宿主提供。Checker 的无体豁免：`"host" in decl.annotations` 跳过 `E-FUN-NO-BODY`（Symbols.kt:246-251）。求值期宿主函数在 `callFunction` 中**先于**帧查找解析（Evaluator.kt:513-518：`hostFunctions[name]` 命中即 `toHost → fn → fromHost`）；全局帧里另登记无参存根 `FunDecl(@host)` 供查找完备性（Interpreter.kt:222-231）。

脚本侧的 `@host` 使用形态（声明签名、实现由宿主注入；与 `@root` 同构的写法）：

```subs
// host.subs
@host fun hostLog(s: Str): Null
hostLog(" vía 宿主通道")
```

### 5.3 `@host` 与 `@root` 对照

| 维度 | `@root` | `@host` |
|---|---|---|
| 实现来源 | **编译期内建**（checker 内建表 + codegen 按名字特判翻译为原生 JS） | **宿主运行时注入**（`Interpreter.register` 的 Kotlin 闭包） |
| 白名单门 | 名字必须在 `ROOT_WHITELIST`（否则 `E-ROOT-NOT-ALLOWED`；命中给 `H-ROOT-BUILTIN`，Symbols.kt:262-266） | 无白名单——任意名可注册，声明由解释器合成 |
| 无体豁免 | 有 `@root` 才允许无体（否则 `E-FUN-NO-BODY`） | `@host` 同样豁免 |
| 脚本模式可见性 | core 中 `@root` 条目被 prelude **过滤**；内建由宿主表与 checker 内建表提供 | 合成 `@host` 声明注入 CheckedAst，宿主实现注入 Evaluator |
| 编译模式 | codegen 按名字特判（`panic` → `throw`、async 族、JS 原生） | 不存在（工程模式无宿主） |

二者在类型系统、诊断、调用点检查上同构（旧文档 §4.1 的表述与实现一致），区别只在「谁提供实现」。

### 5.4 `print` / `toStr` / `panic` 判断式

**print**：`registerStdlib` 以无签名重载注册（Interpreter.kt:289-293）：

$$\frac{\sigma \vdash e \Downarrow v \qquad \mathcal{I}.\textit{hostFunctions}(\texttt{print}) = \textit{fn}}{\sigma \vdash_{\text{host}} \texttt{print}(e) \Downarrow \text{Null} \qquad \textit{stdout}\mathrel{+}= \textit{join}(\textit{toHost}(v)\ \text{以空格})} \quad (\text{B-Print})$$

注释明示：「已在内建表（Types.kt `builtinimpure`），Checker 自行解析；解释器兜底」。即脚本里 `print` 的**类型检查**走 checker 内建表（core/io/io.subl 的 `@root fun print(v: Any): Null` 被 prelude 过滤、仅作文档），**运行时**走宿主表。

**toStr**：`register("toStr", retType = Str)`，实现对齐编译模式 `__dshtoStr`——List 元素间无空格（`[a,b]`）、整数 Rat 去浮点尾巴、空字段结构体打印类型名（Interpreter.kt:295-305）。

**panic**：

$$\frac{\Gamma \vdash \texttt{panic()} : \text{Nothing} \qquad (\textit{builtinPure, Types.kt:180})}{\Sigma;\Gamma \vdash \texttt{panic()} \Rightarrow\ \texttt{throw new Error('panic: unreachable')}\ (\text{JsCodeGen.kt:1256})} \quad (\text{B-Panic-JS})$$

$$\frac{\sigma \vdash \texttt{panic()} \qquad \texttt{panic} \notin \mathcal{I}.\textit{hostFunctions} \qquad \texttt{panic} \notin \sigma_{\textit{funs}}}{\sigma \vdash \texttt{panic()} \Rightarrow \texttt{InterpreterError}(\text{“未定义的函数 panic”})} \quad (\text{B-Panic-Script})$$

即脚本模式**没有** `panic` 的宿主实现：Checker 放行（内建表），Evaluator 走 `callFunction` 的兜底抛异常（Evaluator.kt:533）。core 标准库里的 `panic()` 落点（`list.subl` 下标越界分支（`core/collection/list.subl:82`）、`encoding`/`regex`/`net` 的能力占位函数）在脚本模式下一旦真正执行到，即以 `InterpreterError` 终止——与编译模式的受控 JS 抛错**不对称**（§8 待核条目）。

`unwrapOr` 等错误路径是**普通标准库函数**（`core/collection/result.subl:25`），随 prelude 注入，两模式同构（事实表 §7 的「panic/unwrapOr 错误路径」指此）。

### 5.5 宿主结构体注入示例

```kotlin
interp.injectStruct("Counter",
    "value" to ScriptType.Nat,
    mutableFields = listOf("value"))   // 字段标 @mut → 结构体标 @mut
interp.register("getCounter") { _ -> mapOf("value" to 0L) }   // Map 传值（fromHost 包装）
```

$$\frac{\mathcal{I}.\texttt{injectStruct}(\textit{name}, \dots) \qquad \textit{fn}\ \text{返回}\ \textit{Map}}{\textit{CheckedAst}\ \mathrel{+}=\ \texttt{@mut struct}\ \textit{name}(\dots) \qquad \sigma \vdash_{\text{host}} \textit{Map} \mapsto \text{Struct}(\textit{name})} \quad (\text{B-Reg-Struct})$$

脚本侧（完全感知不到「这是宿主来的」，看起来就是一个普通 `Counter` 值）：

```subs
var c = getCounter()
print(c.value)          // 0
```

结构体字段默认值由 `defaultValueFor` 合成（Nat/Rat→`0`/Str→``/Bool→`false`/Null→`null`，复杂类型无默认值须显式构造，Interpreter.kt:262-269）；依赖顺序由宿主负责（`injectStruct` 不自动拓扑排序）。

### 5.6 `printable` 勘误

事实表 §7 原文「print/printable 输出」已被全库检索否证：`printable` 仅出现在 `_langfacts.md` 自身与旧 wiki 的勘误条目中，**实现里只有 `print`**（本卷 §5.4）。本卷按事实表与源码写，不设 `printable` 规则；凡旧文出现 `printable` 一律以 `print` 勘误。

## 六、异步宿主与执行接力

### 6.1 脚本模式不支持异步

$$\frac{e \in \{\texttt{Task}\{\dots\},\ \texttt{Flow}\{\dots\}\}}{\sigma \vdash e \Rightarrow \texttt{InterpreterError}(\text{“异步特性不在脚本中支持”})} \quad (\text{B-NoAsync})$$

Evaluator.kt:268 的显式拒绝。进一步：core 的 async/flow/mutex/channel `.subl` 随 prelude 注入其**声明**（非 `@root` 条目），但配套的 `@root @impure @async` 内建（`delay`/`runBoth`/`runSeq`/`withMutex`/`channelPipe` 等 14 个，Types.kt:298 注；DiagCoverageTest.kt:252 起）**全部**被 prelude 过滤（§2.6）且未在 `registerStdlib` 注册宿主实现——脚本里调用它们在 Checker 侧可过、运行时不可达。脚本是**同步解释**：异步引入挂起-恢复语义，与线性执行模型冲突（旧文档 §5 的设计表述与实现一致）。

### 6.2 `compile` → node 接力

$$\frac{\Sigma;\Gamma \vdash \textit{prog} \Rightarrow \textit{js} \qquad \textit{js} \rightsquigarrow \textit{file}\ (\texttt{-o})\ \text{或 stdout}}{\text{node}\ \textit{file}\ \vdash \textit{prog} \Downarrow\ (\text{main 天然 async；IO/async 内建经特判翻译为原生 JS})} \quad (\text{B-Node-Relay})$$

异步宿主的承载路径是**编译侧**：`fun main()` 天然 async（`E-NEED-ASYNC`：异步调用需要在异步上下文，main/Task 体天然 async，Main.kt:108）；`readFile`/`writeFile`/`sleep` 与 async 族内建由 codegen 特判为 JS 原生（Promise/setTimeout/小运行时类，JsCodeGen.kt:1155 起）。CLI 不内置 node 调用——`compile` 产物交给外部 `node` 执行（USAGE 无 `run` 子命令；工程执行走 `run-script` 目录回退或 `compile`+node，_langfacts.md §8）。

工程形态示例（异步只在工程模式可用）：

```subs
// app.subl（工程模式：compile <dir> 后 node 执行）
fun main() {
  var text = readFile("data.txt")       // @async 内建，main 天然 async
  print(text)
}
```

### 6.3 `run-script` 与 `compile` 的分工

$$\frac{\text{目标} = \texttt{.subs}\ \text{文件/目录}}{\texttt{run-script}:\ \text{解释执行（无产物）}} \qquad \frac{\text{目标} = \texttt{.subl}\ \text{工程（目录全树）}}{\texttt{check/compile}:\ \text{静态检查 + JS 生成}} \quad (\text{B-Mode-Split})$$

- `run-script` 先于通用路径分流（Main.kt:235-238 在路径存在性检查之前短路）；`when` 块内另有一支 `run-script` 分支（Main.kt:350-356）在当前调度下**不可达**——保留作单文件脚本的防御性入口（待核）；
- 目录参数语义差异：`run-script <dir>`＝`subsIn`（顶层 `.subs`，各自隔离）或**回退** `runDir`（顶层 `.subl` 合并 + main）；`check/compile <dir>`＝`MultiModule`（全树模块、挂载、根入口唯一性 §3.2）；目录模式仅支持 check/compile（脚本目录请用 run-script，Main.kt:244-247）；
- `-p <处理器>`/`-A key=value` 是编译模式的注解处理器通道（10 卷）；处理器本身是 `.subs` 脚本，由解释器解释执行（Main.kt:27、232）——即脚本模式作为**编译工具的宿主运行时**被复用。

### 6.4 宿主注入工程能力（`callTopLevel`）

$$\frac{\mathcal{I} \vdash \texttt{run}(\text{src}) \Downarrow v^{*} \qquad \textit{name} \in \sigma_{\textit{funs}}}{\mathcal{I}.\texttt{callTopLevel}(\textit{name}) \Rightarrow \sigma' \vdash \textit{name}()\ (\text{“<postcompile:name>”})} \quad (\text{B-PostCompile})$$

执行完顶层语句后调用脚本里已定义的顶级函数（V2：注解处理器 `@postcompile` 入口，Interpreter.kt:112-117；`callTopFunction` 无实参、`ScriptFrame(globalFrame)` 子帧）。宿主亦可用 `register("loadProject") { … }` 等把工程能力注入脚本（脚本操作注解处理器的典型用法：`loadProject`→`processAnnotations`→`writeGenerated`，旧文档 §7 的表述与实现一致）。

## 八、健全性底线、已知开口与待核

### 8.1 底线

1. **一切能力来自宿主或 core**：脚本不找依赖（无 import 产生式、无挂载、无跨模块引用），prelude 隐式注入（_langfacts.md §2）；
2. **隔离不可逃逸**：多脚本间无共享通道；每脚本重装 prelude，宿主表是唯一跨脚本常数（=宿主注入通道本身）；
3. **推导不破坏健全性**：`gi` 只填占位、显式标注只填不盖、产物整体过 Checker；冲突即中止（E-TYPE-CONFLICT），「证不出/推不出」不降级为「成立」（00 卷 I-1）；
4. **双侧同构的拷贝判据**：跨边界值引用语义，脚本内绑定/捕获仍走深拷四规则（04 卷；Evaluator.kt:104-130）。

### 8.2 已知开口（实现差异，非 bug 判定）

- **未达宿主的内建**：`panic` 与 async 族在脚本模式 Checker 可过、运行时不可达（§5.4、§6.1）；`builtinPure` 的其余成员（`emptyTuple`/`mathSin`/json 全族等）同样无宿主实现——脚本里碰到即 `InterpreterError`（未定义函数）；
- **`run-script` 的双分支**：`runScriptCmd` 短路后 `when` 内分支不可达（§6.3）；
- **`runDir` 非递归**：工程回退只看顶层 `.subl`，与 compile 的全树语义不同（§2.5）；
- **`ranAny` 兜底**：`runScriptCmd` 所有分支都置 `ranAny`，`!ranAny` 报错分支实际不可达（targets 为空已先退码 2，Main.kt:377、408-411）。

### 8.3 退出码判断式

$$\frac{\textit{args} = \varnothing \ \lor\ \textit{cmd} \notin \textit{已知子命令}}{\texttt{USAGE} + \text{exit}\ 2} \quad (\text{B-Usage}) \qquad \frac{\mathcal{I} \vdash \text{脚本} \Rightarrow \textit{RuntimeException}}{\texttt{[错误]} + \text{exit}\ 1} \quad (\text{B-Exit-Err})$$

`run-script` 特有：路径不存在 → `[错误] 路径不存在` + 2（Main.kt:382-385）；targets 为空 → USAGE + 2（Main.kt:377）；无脚本可运行 → `[错误] 未找到可运行的脚本` + 1（Main.kt:408-411，见 §8.2 的可达性说明）。

### 8.4 待核

- `print` 的合成 `@host` 声明（`(x: Any): Any`，由无签名重载合成）与 checker 内建表 `print(v: Any): Null` 的符号竞争/优先级关系（`findFun` 先查已声明符号，Types.kt:379）——两签名在调用点均放行，实际取舍需要实测确认；
- 事实表 §7 的「print/printable」勘误已落实（§5.6）；事实表 §9 的「精确行号复核」与本卷相关处（Evaluator 行数、Types.kt 内建表行位）尚未逐行复核；
- 旧文档 §4.2 描述的 `ScriptFunction` 多态实例化 `instantiate` 是否有宿主实际使用（接口默认返回自身）；
- `callTopLevel`/`@postcompile` 的实际调用方与触发时序（10 卷注解处理侧）。

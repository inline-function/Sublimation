# 第九卷 · 运行时与代码生成

> 本卷规定凝华的值域、求值语义、内建函数、脚本模式与宿主接口、全局类型推导，以及 JavaScript 代码生成的映射规则。

---

## 1. 两种执行模型

| 维度 | 工程模式 | 脚本模式 |
|---|---|---|
| 入口 | `fun main()`，全局唯一 | 顶层语句，顺序执行 |
| 顶层 | 只能声明 | **可以有语句** |
| 模块 | 目录即模块，有挂载 | **没有模块概念** |
| 依赖来源 | 同模块文件 + 挂载 | **仅宿主预置** |
| 执行 | 编译 → JavaScript → node | **解释器直接求值** |
| 产物 | JavaScript 文件 | 无产物，直接执行 |
| 类型标注 | 必填 | 可省略（全局类型推导） |
| 异步特性 | 完整 | 移除 |

## 2. 值域

### 2.1 值的种类

```
Value = Num    ⟨ value : Integer ⟩            自然数、整数
      | Rat    ⟨ value : Float ⟩              有理数（浮点表示）
      | Str    ⟨ value : String ⟩             字符串
      | Bool   ⟨ value : Boolean ⟩            布尔
      | Null                                   单值
      | ListV  ⟨ items : MutableSequence ⟩    列表（引用语义）
      | Struct ⟨ typeName, fields : Map, mutableFields : Set ⟩
                                              结构体、枚举构造子、宿主注入类型
      | OptionalV ⟨ value : Value? ⟩          可选值（null 表示 None）
      | ResultV   ⟨ isOk : Boolean, value : Value?, error : Value? ⟩
      | Fun    ⟨ fn : Function ⟩              函数值（宿主函数或脚本闭包）
      | Range  ⟨ lo, hi ⟩                     惰性区间
      | Nothing                                发散（不产生值）
```

### 2.2 值与类型的映射

| 类型 | 值 |
|---|---|
| `Nat`／`Int` | `Num`（整数） |
| `Rat` | `Rat`（浮点） |
| `Real` | 表达式树（编译期符号值，运行时降级为浮点） |
| `Str` | `Str` |
| `Bool` | `Bool` |
| `Null` | `Null` |
| `Nothing` | 无值（发散） |
| `List[T]` | `ListV`（数组形态） |
| `Set[T]`／`Map[K,V]` | `Struct`（结构枚举，构造子链） |
| `Optional[T]` | `OptionalV` |
| `Result[T,E]` | `ResultV` |
| 结构体／枚举 | `Struct` |
| 函数类型 | `Fun` |
| `Range[T]` | `Range` |
| `Json` | 宿主原生 JSON 对象 |
| `Task`／`Channel`／`Mutex`／`Flow` | 运行时小对象（§7） |

### 2.3 值的相等性

| 值种类 | 相等判据 |
|---|---|
| `Num`／`Rat`／`Str`／`Bool`／`Null` | 值相等 |
| `ListV` | 元素序列相等（结构相等） |
| `OptionalV`／`ResultV` | 载荷相等（结构相等） |
| `Struct` | 类型名与字段表相等 |
| `Fun` | **引用相等**（函数身份） |

### 2.4 引用语义

**列表与结构体是引用语义**：`ListV` 与 `Struct` 的传递不复制底层存储。因此可变性必须由类型层的 `@mut` 视图与运行时的深拷贝共同保障（第六卷 §6）。

**值跨宿主边界一律引用语义**（非拷贝）：脚本改宿主对象 = 改宿主对象。

## 3. 求值语义

### 3.1 求值判断式

```
e ⇓ v
```

读作：表达式 `e` 求值为值 `v`。这是**大步操作语义**（big-step）。

### 3.2 环境

运行时环境是**帧**的嵌套结构：

```
RuntimeFrame = ⟨
    vars      : Map<String, Value>        变量绑定
    muts      : Set<String>               可变变量名
    refs      : Set<String>               引用变量名
    functions : Map<String, Function>     函数声明
    parent    : RuntimeFrame?
⟩
```

变量查找沿父链；赋值沿父链查找目标帧后写入。

### 3.3 核心规则

```
────────────────────────────────────────  (V-LIT)
n ⇓ Num(n)        r ⇓ Rat(r)        "s" ⇓ Str(s)        null ⇓ Null

V(x) = v
────────────────────────────────────────  (V-VAR)
x ⇓ v

e₁ ⇓ v₁   e₂ ⇓ v₂
────────────────────────────────────────  (V-BIN)
e₁ ○ e₂ ⇓ apply(○, v₁, v₂)

V(f) = ⟨params, body, closure⟩   eᵢ ⇓ vᵢ
────────────────────────────────────────  (V-APP)
f(e₁…eₖ) ⇓ eval(body, extend(closure, params ↦ v⃗))

────────────────────────────────────────  (V-LAMBDA)
{ x => body } ⇓ Fun(⟨[x], body, 当前帧⟩)

V(c) ⇓ Bool(true)     V(e₁) ⇓ v
────────────────────────────────────────  (V-IF-T)
if (c) e₁ else e₂ ⇓ v

V(c) ⇓ Bool(false)     V(e₂) ⇓ v
────────────────────────────────────────  (V-IF-F)
if (c) e₁ else e₂ ⇓ v

V(c) ⇓ Bool(false)     e₂ 不存在
────────────────────────────────────────  (V-IF-NOELSE)
if (c) e₁ ⇓ Null
```

### 3.4 块的求值

```
S₁ … Sₙ 依次求值（在子帧中）     e ⇓ v（尾表达式，值位）
────────────────────────────────────────  (V-BLOCK)
{ S₁ … Sₙ ; e } ⇓ v

无尾表达式
────────────────────────────────────────  (V-BLOCK-NULL)
{ S₁ … Sₙ } ⇓ Null
```

依总纲公理一，块的值由尾表达式决定；无尾表达式的块值为 `Null`。

### 3.5 when 的求值

```
主题 s ⇓ vs     分支 b₁…bₙ     bᵢ 是首个匹配 vs 的分支     bᵢ 的体 ⇓ v
────────────────────────────────────────  (V-WHEN)
when (s) { b₁ … bₙ } ⇓ v

无分支匹配
────────────────────────────────────────  (V-WHEN-FAIL)
when (s) { … } ⇓ Null
```

匹配判定按模式种类（第七卷 §2）。

### 3.6 深拷贝

```
deepCopy(Num/Rat/Str/Bool/Null/Fun) = 原值（不可变或身份语义）
deepCopy(ListV(items))              = ListV(逐项 deepCopy)
deepCopy(Struct(t, fields, muts))   = Struct(t, 逐字段 deepCopy, muts)
deepCopy(OptionalV(v))              = OptionalV(deepCopy(v))
deepCopy(ResultV(ok, v, e))         = ResultV(ok, deepCopy(v), deepCopy(e))
```

触发条件见第六卷 §6.6。

### 3.7 字典方法调用

类型类方法按接收者类型分派：

```
V(r) ⇓ Struct(t, …)     methodImpls[t][m] = impl
────────────────────────────────────────  (V-DICT)
r.m(a⃗) ⇓ apply(impl, r :: a⃗)
```

### 3.8 错误处理

运行时错误抛出异常，携带位置信息。**执行到一半报错时，前面已执行的效果保留**（同 Python 语义）：脚本模式不会回滚已发生的输出与宿主副作用。

`panic()` 是内建的发散函数，其返回类型是 `Nothing`。

### 3.9 尾调用

**未实现尾调用优化。**深度递归可能耗尽宿主栈。

## 4. 内建函数

### 4.1 @root 白名单

标注 `@root` 的声明表示「该签名对应编译期内建实现」，代码生成层按名字特判翻译。

```
名字 ∈ ROOT_WHITELIST
────────────────────────────────────────  (V-ROOT)
允许 @root 无体声明      发 H-ROOT-BUILTIN 提示

名字 ∉ ROOT_WHITELIST
────────────────────────────────────────  (V-ROOT-DENY)
报 E-ROOT-NOT-ALLOWED

普通函数无体
────────────────────────────────────────  (V-NO-BODY)
报 E-FUN-NO-BODY
```

`ROOT_WHITELIST` = 不纯内建函数的键集 ∪ 纯内建函数的键集，与代码生成的特判一一对应。

### 4.2 内建不纯函数

以下函数标注 `@impure`（其中标注 `@async` 者还须在异步上下文调用）：

**输入输出**：

| 函数 | 签名 | 异步 |
|---|---|---|
| `print(v)` | `(任意) => Null` | 否 |
| `readLine()` | `() => Result[Str, Str]` | 是 |
| `readFile(p)` | `(Str) => Result[Str, Str]` | 是 |
| `writeFile(p, s)` | `(Str, Str) => Result[Null, Str]` | 是 |
| `appendFile(p, s)` | `(Str, Str) => Result[Null, Str]` | 是 |
| `fileExists(p)` | `(Str) => Bool` | 否 |
| `readDir(p)` | `(Str) => Result[List[Str], Str]` | 是 |
| `getArgs()` | `() => List[Str]` | 否 |

**时间与随机**：

| 函数 | 签名 | 异步 |
|---|---|---|
| `timeNow()` | `() => Nat` | 否 |
| `rand()` | `() => Rat` | 否 |
| `sleep(ms)` | `(Nat) => Null` | 是 |
| `delay(ms)` | `(Nat) => Null` | 是 |

**任务组合**：

| 函数 | 签名 |
|---|---|
| `runBoth(f, g)` | `(() => Null, () => Null) => Null` |
| `runSeq(f, g)` | `(() => Null, () => Null) => Null` |

**Flow 收集**：

| 函数 | 签名 |
|---|---|

| `collectCount[T](fl)` | `(Flow[T]) => Nat` |

**Mutex 临界区**：

| 函数 | 签名 |
|---|---|

| `bumpCounter[T](m, c)` | `(Mutex, @mut T) => Null` |

**Channel 配套**：

| 函数 | 签名 |
|---|---|
| `channelFromList[T](xs)` | `(List[T]) => Channel[T]` |
| `sendAll[T](ch, xs)` | `(Channel[T], List[T]) => Null` |
| `channelDrain[T](ch)` | `(Channel[T]) => List[T]` |
| `channelPipe[T](src, dst)` | `(Channel[T], Channel[T]) => Null` |

**元组**：

| 函数 | 签名 |

**其他**：

| 函数 | 签名 | 说明 |
|---|---|---|
| `panic()` | `() => Nothing` | 发散 |

- `Bool`、`Null`、`Optional` 的枚举注册；
- 内建函数表；
- 数值升格规则。

## 5. 脚本模式

### 5.1 定位

脚本模式**不是**「另一种编译模式」。它是**宿主-脚本运行时**，对应 Lua 嵌入 C、Python 嵌入 C++：

```
宿主  →  注入能力（API + 类型 + 工程）  →  解释器  →  执行脚本
```

**脚本不找依赖，依赖由宿主给。**脚本只有一个来源：**宿主预置的符号表**。

脚本 = 一段代码 + 宿主给的能力。它不是工程，不参与模块系统。

### 5.2 边界

**在脚本里**：

- 语言核心：类型、命题、模式匹配、变量、函数、运算符；
- 标准库：`List`／`Result`／`Optional` 与内建函数；
- 宿主注入的 API、类型、注解。

**不在脚本里**：

- **模块系统**：无挂载、无跨模块引用、无 `.settings`；
- **`@async`／`Task`／`Channel`／`Mutex`**：脚本移除所有异步特性（第六卷 §8.8）；
- **`fun main()`**：脚本顶层就是入口；
- **工程级特性**：多文件、模块扫描、字典跨模块分发。

### 5.3 @host 机制

脚本可以调用宿主注入的函数。声明语法与 `@root` 同构：

```subl
@host fun hostLog(s : Str) : Null
@host fun hostReadLine() : Str
```

| 注解 | 实现来源 |
|---|---|
| `@root` | **编译器**（编译期内建） |
| `@host` | **宿主**（运行时注入） |

两者在类型系统、诊断、调用点检查上完全一致。区别只是「谁提供实现」。

### 5.4 函数值的跨边界接口

**跨边界的函数值统一为一个函数接口，不转成宿主原生 lambda。**

```
ScriptFunction = ⟨
    typeParams  : List<String>       泛型参数名（非泛型为空）
    preps       : List<String>       上文（前置命题，渲染后的字符串）
    posts       : List<String>       下文（后置命题，渲染后的字符串）
    paramTypes  : List<String>       形参类型（渲染）
    retType     : String             返回类型（渲染）
    call(args)  : Value              调用
    instantiate(typeArgs) : ScriptFunction    可选：显式实例化
⟩
```

**泛型全部擦除为属性**：`[T](T) => T` 和 `(Nat) => Nat` 是同一个接口，区别只在 `typeParams` 的值。

**上下文全部擦除为属性**：宿主读到的是渲染后的字符串；实际检查在脚本侧进行。

**宿主调用 `f.call(args)` 时，解释器负责**：

1. 按实参推导／实例化泛型；
2. 把宿主值包装成脚本值；
3. 检查前件（走脚本证明器）；
4. 求值函数体；
5. 返回结果（包装回宿主值）。

**宿主不需要理解泛型和上下文**——它只读属性、调 `call`。

**多态函数值的实例化时机**：默认在 `call` 时按实参实例化；可选地提供 `instantiate` 返回单态函数值，供宿主多次调用。

### 5.5 结构体的跨边界接口

**不转换。宿主注入类型定义，用映射表传值。**

```
injectStruct(name, fields…, props?, mutableFields?, annotations?)
```

| 参数 | 作用 |
|---|---|
| `name` | 结构体名 |
| `fields` | 名 → `ScriptType` 的序列 |
| `props` | 伴生命题（渲染字符串列表，可选） |
| `mutableFields` | 可变字段名列表（可选） |
| `annotations` | 注解列表（可选） |

宿主构造值用映射表（或显式结构体值）：

```
register("getPoint") { _ -> mapOf("x" to 1, "y" to 2) }
```

脚本侧：

```subl
var p = getPoint()
print(p.x)     // 1
print(p.y)     // 2
```

**脚本完全感知不到「这是宿主来的」**——它看起来就是一个普通 `Point` 值。

`ScriptType` 须支持完整类型语法：Named、List、Optional、Tuple、Function。嵌套结构体（如 `List[Point]`）通过它表达。

**依赖顺序由宿主负责**——`injectStruct` 不自动拓扑排序。

### 5.6 注解的跨边界表示

**所有节点统一带 `annotations` 属性。**注解是通用容器：

```
Annotation = ⟨ name : String, args : List<Value> ⟩
```

**注解参数**：常量 + 类型引用，**不支持任意表达式**。

内置注解是编译器额外认识的名字（第八卷 §7）。用户自定义注解编译器不认识 → 透传 → 注解处理器读。

**用户不能自定义注解名**——注解的名字空间由宿主提供，用户只使用。

### 5.7 类型映射

| 脚本类型 | 宿主值 |
|---|---|
| `Nat`／`Int`／`Rat` | 整数／整数／浮点 |
| `Str` | 字符串 |
| `Bool` | 布尔 |
| `Null` | 空 |
| `List[T]` | 列表 |
| `Optional[T]` | 可选容器 |
| `Result[T, E]` | 密封类 |

### 5.8 执行模型

```
解释器启动
  → 加载标准库（语言自带）
  → 加载宿主 API（宿主注入）
  → 加载结构体定义（宿主注入）
  → 加载脚本（用户写的）
  → 逐条执行顶层语句
```

**顶层语句的作用域**：

- 顶层 `var` 对后续顶层语句可见；
- 顶层 `fun` 对脚本内所有语句可见；
- **声明不对外可见**——脚本结束，作用域消失；
- 多个脚本互不共享声明。

### 5.9 跨边界的三项擦除

| 擦除项 | 理由 |
|---|---|
| 类型类字典不跨边界 | 宿主 API 签名不用类型类约束 |
| 泛型擦除 | 宿主只读属性、不做静态对齐 |
| 上下文（前后件）擦除 | 检查在脚本侧，宿主看不见证明过程 |

这个原则把宿主的心智负担压到最小：**宿主只需要理解三种通用表示**（函数、结构体、注解）。

### 5.10 命令

```
run-script <file.subs | dir>     脚本模式解释执行：顶层语句直接运行（无需 main）
run-script demo.subs --global-inference    附加全局类型推导
```

## 6. 全局类型推导

### 6.1 定位

全局类型推导是**脚本模式专属**的机制，默认关闭。编译模式（编译到 JavaScript）**不启用**，标注必须显式。

它是：当用户省略类型／可变性／效应／上下文标注时，编译器**自动填入**合适标注的机制。

**目标不是「类型最准」（主类型），而是**：

1. **让脚本过编译**——缺失标注的地方，编译器塞一个值；
2. **符合用户所想**——用户心里的意图优先被采用。

代价可以承受：脚本往往很短，错误定位略差是能接受的。

### 6.2 推断域与锚点

```
推断域 = 当前脚本 + 解释器附加的脚本
推断边界 = stdlib
```

标准库是**显式标注**的，视为**类型锚点**：

- 不参与推断（不推它的类型）；
- 作为**约束源**向脚本流入约束；
- 编译器信任标准库的签名（不在脚本模式重复检查）。

**脚本内覆盖标准库符号**：脚本优先（局部优先）。

收窄带来的简化：

| 难点 | 收窄后 |
|---|---|
| 实例集边界 | 闭集——脚本内声明的全部 |
| 跨模块效应传播 | 不存在——标准库已标 |
| 循环依赖 | 脚本短，几轮收敛 |
| 错误定位 | 脚本短，用户看全貌 |
| 跨脚本一致性 | 不存在——脚本独立推断 |

### 6.3 优先级规则

缺失标注时，编译器按以下优先级选择：

```
1. 显式标注        ← 最高，用户说了算
2. 构造点          ← 具体类型（"张三" → Str）
3. 使用点偏好      ← "balance >= 1000" → Num；"n.length()" → Str
4. 默认类型        ← 兜底（数值 → Nat，文本 → Str，无信息 → Any）
```

**决策依据**：

- **构造点 > 使用点**：构造点是「值的确切形状」，使用点是「对值的要求」。`1000` 是 `Nat`（构造点），`balance >= 1000` 只要求 `Num`（使用点）。`Nat` 更具体，优先；
- **使用点参与**：`n + 1` 推 `n : Num`、`n.length()` 推 `n : Str`。使用点是**强偏好**，但不强于构造点；
- **默认兜底**：无任何信息时用默认。

### 6.4 各位置的规则

**变量位**：

```subl
var n = 0                    // n : Nat（构造点直接锁定）
var s = "hi"                 // s : Str
var x = unknown()            // x : Any
var a = A(1)                 // a : A
```

规则：变量类型 = 初值类型（构造点优先）。无信息则取默认。

**函数参数**：

```subl
fun f(n) { return n + 1 }        // 推：fun f[T : Num](n : T) : T
fun g(x) { return x.length() }   // 推：fun g[T : Str](x : T) : Nat
```

规则：

- 使用点有具体偏好 → 采用该类型（或约束）；
- 使用点只有宽约束（`Num`）→ **泛型化**为 `[T : Num]`；
- 无使用 → `[T : Any]`。

**返回类型**：

```subl
fun f() = 1                  // : Nat
fun g() = "hi"               // : Str
fun h() { return 1 }          // : Nat（块体，单一 return）
```

规则：

- 表达式体 → 体类型；
- 块体 → 所有 `return` 的共同类型；
- 多 `return` 冲突 → 报错；
- 无 `return` 且无尾表达式 → `Null`。

**结构体字段**：

```subl
struct Account(owner, balance, country = "中国")
var a = Account(owner = "张三", balance = 1000)
```

规则：

- **所有构造点的共同类型必须唯一**（不取上界，必须一致）；
- 多构造点类型不同 → **冲突报错**（用户违约）；
- 无构造点 → 该字段泛型化为 `[T : Any]`；
- 默认值参与：`country = "中国"` → `Str`（构造点）。

**impl 方法**的推演顺序：

```
① 先推结构体字段（构造点、使用点、默认值）
② 回填 impl 体（此时字段类型已知）
③ 推 impl 方法签名
④ 回填 class 声明
```

**impl 体内使用字段不产生约束**（字段类型已经定了），只是**消费**——消费合法性检查。

### 6.5 默认类型

| 位置 | 无信息时默认 |
|---|---|
| 数值字面量 | `Nat` |
| 字符串字面量 | `Str` |
| 布尔字面量 | `Bool` |
| 变量初值 `null` | `Null` |
| 无约束参数 | `[T : Any]` |
| 无约束字段 | `[T : Any]` |
| 无约束返回 | `Null`（无 return） |

**默认 `Any` 保证「过编译」**——不因缺类型而报错。

### 6.6 泛型化

**泛型化是最后手段，不是默认行为。**

**触发条件**：某位置**有约束但约束不具体**。

```subl
fun tryWithdraw(cur, amount) = if (cur >= amount) { Ok(cur - amount) } else { Err(…) }
```

- `cur >= amount` → `cur : Num, amount : Num`；
- 但 `Num` 是**宽约束**（`Nat`／`Int`／`Rat` 都满足）；
- 无构造点锁死具体类型；
- → 泛型化：`fun tryWithdraw[T : Num](cur : T, amount : T) : Result[T, Str]`。

**不触发泛型化的情况**：有构造点（`tryWithdraw(5, 10)` → `T := Nat`）；有更具体的约束（`cur : Nat` 而非 `cur : Num`）。

**泛型化的作用域**：

| 对象 | 行为 |
|---|---|
| 函数参数 | 每次调用独立实例化 |
| 结构体字段 | 结构体本身泛型化 `struct A[T : …]`，所有使用共享 |
| 变量 | 变量类型即初值类型（不泛化） |

### 6.7 递归与强连通分量

递归是唯一「拓扑排序不够用」的场景（依赖图有环）。

**分组步骤**：

```
① 建函数依赖图（谁调谁）
② Tarjan 算法求强连通分量
③ 拓扑序遍历强连通分量
```

**单函数分量（自环）**——策略：**先假设后验证**。

```subl
fun fact(n) = if (n <= 1) { 1 } else { n * fact(n - 1) }
```

```
① 假设 fact : (α) -> β
② 推 fact 体：n : α；n <= 1 → α : Num；n * fact(n-1) → β : Num；if 分支一致 → β = Nat
③ 用实际类型验证：fact : (α : Num) -> Nat
④ 泛型化：fun fact[T : Num](n : T) : Nat
```

**多函数分量（互递归）**——策略：**赋新鲜变量 + 迭代**。

```subl
fun even(n) = if (n == 0) { true } else { odd(n - 1) }
fun odd(n)  = if (n == 0) { false } else { even(n - 1) }
```

```
① 分量 = {even, odd}
② 赋新鲜变量：even : (α₁) -> β₁、odd : (α₂) -> β₂
③ 用待定签名推两个体，一次性收集约束
④ 迭代最多 3 轮，直到约束不再增长（收敛）
⑤ 求解：α₁ = α₂ = Num、β₁ = β₂ = Bool
⑥ 泛型化：fun even[T : Num](n : T) : Bool、fun odd[T : Num](n : T) : Bool
```

**迭代上限 3 轮**：不追求严格收敛。脚本短，3 轮足够。收敛不了则泛型化兜底，**不报错**。

**冲突**：

```subl
fun f(n) = if (n <= 1) { 1 } else { f(n - 1) + n.length() }
```

`n - 1` 要求 n 数值，`n.length()` 要求 n 是 `Str`——**冲突 → 报错**，与非递归冲突处理一致。

### 6.8 停机检查

```
自递归且实参不递减
────────────────────────────────────────  (E-AUTO-IMPURE)
自动标 @impure      发 D-AUTO-IMPURE 补充级诊断      不阻断编译
```

含义：把「未证明停机」当作一个**效应来源**，并入效应推断引擎。与「体内调 `print`」是同一种源，走同一传播（join）。

理由：脚本短，用户自己承担「这个函数可能不停」的风险；报错会破坏脚本的书写体验。

### 6.9 逃生舱

递归函数建议用户**显式标注返回类型**：

```subl
fun fact(n) : Nat = …
fun even(n) : Bool = …
```

用户显式标注 → 推断跳过该函数（信任标注），但验证体是否匹配。这给了用户**精确控制**的入口。

### 6.10 可变性推断

```subl
var acc = Account(owner = "张三", balance = 1000)
acc.balance = acc.balance + 500
```

推演：

```
① acc.balance = … 是赋值语句
② 赋值目标 acc.balance → 要求 balance 字段可变
③ → struct Account(…, @mut balance, …)
④ 赋值目标的根是 acc → 要求 acc 变量可变
⑤ → @mut var acc = …
```

规则：

- 赋值语句目标链上的所有节点（变量 + 字段）→ 标 `@mut`；
- 无可变操作 → 默认不可变（与编译模式一致）。

**边界**：可变性是**承诺**（用户主动声明「我要改这个」）。推断是「从使用点反推承诺」——哲学上是**退化**，但让脚本短好写。脚本模式专属，编译模式不变。

### 6.11 上下文自动填充

脚本模式专属扩展。编译模式下前件／后件必须显式标注。

**前件反推（从调用点）**：

```
若函数体内调用了需要前件 p 的函数，而当前上下文无 p
────────────────────────────────────────  (V-PRE-INFER)
p 自动提升为当前函数的前件
```

```subl
fun useQ()<q> : Null {}
fun f() { useQ() }        // 本地无 q
// 自动：fun f()<q> { useQ() }
```

多个调用点的前件 → **并集**：

```subl
fun f() { useQ(); useR() }
// 自动：fun f()<q, r>
```

命题参数同样提升：

```subl
fun witness[@q]<q> : Null {}
fun f() { witness() }
// 自动：fun f[@q]<q> { witness() }
```

`f` 也成为超越函数——保持「调用者供给」语义。

与显式前件**合并**（不覆盖）：

```subl
fun f()<p> { useQ() }    // 显式 p + 反推 q
// 自动：fun f()<p, q>
```

**后件反推（从 return 处）**：

```
在函数体末尾，取所有 return 处都能证明的命题
────────────────────────────────────────  (V-POST-INFER)
加入函数的后件
```

```subl
fun f() {
    ∵ q
    if (c) { return 1 } else { return 2 }
}
// 自动：fun f() : T <q>
```

**判据是所有 return 处的交集**（严格）——保证「我一定能给你 q」。

关于 `$` 的命题：`$ = 1` 只在第一支成立，`$ = 2` 只在第二支成立，交集为空 → 不推。**自动推的后件基本不含 `$`**——用户想约束返回值需显式写。

`∵` 注入的命题参与：注入的命题只要在**所有 return 处都可用**，就推入后件。

**循环依赖**用强连通分量 + 迭代解决，与类型推断同一套机制。

**边界**：

- 仅前件／后件参与——命题参数 `@q`、上下文列表 `<p>` 参与；**函数体内**的 `∵`／`∴`／`axiom` 不参与反推；
- **`@theorem` 函数不参与**——定理是显式的，不推；
- **编译模式不做**——前件／后件必须显式。

### 6.12 冲突与错误

**冲突 = 承诺失败 = 报错。**用户承诺不写错代码，冲突即用户违约。

**报错指向冲突点**（两个使用点各自的来源），不指向调用点。诊断码 `E-TYPE-CONFLICT`。

```
[错误][3:15] E-TYPE-CONFLICT: 字段 `A.n` 类型冲突
  3 | impl X for A { fun f() = n + 1 }
    |                             ^ 约束 n: 数值类型（此处 n + 1）
  5 | impl Y for A { fun g() = n.length() }
    |                             ^ 约束 n: Str（此处 n.length()）
    |
    | 两个约束无法同时满足。检查 n 的使用是否一致，或显式标注字段类型。
```

### 6.13 与编译模式的关系

| 维度 | 编译模式 | 脚本模式 |
|---|---|---|
| 类型标注 | **必填** | 可省略（推断） |
| 可变性 | **显式** | 可省略（推断） |
| 效应 | **显式** | 可省略（推断，含停机失败自动 `@impure`） |
| 上下文（前件／后件） | **显式** | 可省略（推断） |
| 类型类约束 | 完整 | 完整 |

**关键边界**：编译模式不变（本机制脚本模式专属）；显式标注可覆盖推断（用户在任何位置显式写类型／前件／后件，都以用户为准）。

### 6.14 推断的处理阶段

```
Pass 1  收集声明骨架
Pass 2  Tarjan 强连通分量分组
Pass 3  按拓扑序推类型约束
Pass 4  求解（合一 + 默认化）
Pass 5  回填 impl 体
Pass 6  可变性推断
Pass 7  效应推断（含停机失败 → @impure）
Pass 8  上下文自动填充（前件反推 + 后件反推）
Pass 9  注册 pure<f>
```

**核心安全契约**：所有产物仍整体经语义检查。推断只填不绕——如果推断出的标注让代码不合法，检查器照常报错。

### 6.15 性质

- **幂等**：重复运行同一脚本结果稳定（同输入推导出同输出）；
- **只增不减**：推断不删除任何用户已写的标注；
- **不在范围**：编译模式、效应多态、主类型、跨脚本一致性、`@theorem` 函数。

## 7. JavaScript 代码生成

### 7.1 生成原则

代码生成是**源到源**的：凝华源码直接翻译为可读的 JavaScript，**零运行时库**（按需注入的小运行时片段除外）、**零成本擦除**。

### 7.2 擦除映射

依总纲不变量 I-2，以下内容全部擦除：

| 擦除项 | 处理方式 |
|---|---|
| 命题层（类型、理论参数、上下文、`axiom`、`by`、命题算符） | 完全擦除 |
| `unchecked.axiom[q]` | 保留 `// axiom: q` 注释供审计 |
| `@theorem` 函数 | 擦除为 `null` |
| 类型别名 | 展开后不留痕迹 |
| `@atomic` 标记 | 透明擦除 |

值层映射到原生 JavaScript。

### 7.3 实体映射

| 凝华构造 | JavaScript 产物 |
|---|---|
| `struct` | 工厂函数 + 字段访问 |
| `enum` | 构造子工厂函数；零参构造子生成值引用 |
| 类型类字典 | `d_{Trait}_{Self}` 对象，方法签名含 `__self`（高阶类型除外） |
| 字典方法调用 | `$slot.m($slot, self, …)` |
| `@async` 函数 | `async`／`await` |
| `List` | 数组形态（`[]` / `[h, ...t]`） |
| `..` 区间 | `__range(lo, hi)` 惰性对象 |
| `var`／`@mut var` | `const`／`let` |
| 深拷贝 | `__dc(v)` 运行时助手 |
| 结构相等 | `__eq(a, b)` 运行时助手 |
| `when` 语句位 | 展平为真正的 `if` 链 |
| `when` 值位、lambda | 立即执行函数 |
| 模块前缀 | `mangle(absPath)` → `_` 连接（根模块无前缀） |
| `main()` | 文件尾部追加 `main();` |

### 7.4 按需注入的运行时片段

只有源码用到对应特性时才注入：

| 片段 | 触发条件 |
|---|---|
| `__range` | 用到 `..` 值或 `Range` 方法 |
| `__dc` | 存在深拷贝点 |
| `__eq` | 源码用到 `==`／`!=` 的结构相等 |
| `Channel` 小运行时 | 用到 Channel 内建或 `Channel<T>()` |
| `Mutex` 小运行时 | 用到 Mutex 内建或 `Mutex()` |
| `Flow` 小运行时 | 用到 Flow 内建或 `Flow { … }` |

**唯一常驻的运行时组件是 Channel 小运行时**（异步特性的基础）。

### 7.5 挂起点

`@async` 函数的挂起点由检查器标记，代码生成层翻译为 `await`。自动 `await` 发 `D-AUTO-AWAIT` 补充级诊断。

### 7.6 产物

编译产物是**单个 JavaScript 文件**，`node` 直接运行：

```
sublimation compile MY_PROJECT -o out.js
node out.js
```

不给 `-o` 时，JavaScript 直接打到标准输出。诊断文本打在标准输出，检查未通过时最后一行 `[错误] 语义检查未通过` 打在**标准错误**，进程非零退出。

通过时：`check` 打印 `[完成] 语义检查通过`（目录模式为 `[完成] 模块检查通过`）；`compile` 打印 `[完成] 已生成 out.js（N 字节）`。

## 8. 命令行接口

```
parse <file.subl>          词法+语法分析，打印语法树
tokens <file.subl>         打印 token 流（含邻接标记）
check <file.subl> [-v]     语义分析（弥散/证明义务/纯度/可变性/impl/when 穷尽）
check <project-dir>        走模块系统检查整个工程
compile <file.subl> [-o out.js] [-p <processor.subs|dir>]   语义通过后生成 JS
run-script <file.subs|dir> [--global-inference]   脚本模式解释执行
explain <CODE>             打印诊断码含义与修复建议
```

**证明相关旗标**（第四卷 §9.13）：

```
--prover=aggressive        激进证明模式（只作用于 compile/check）
--prove-verbose            提高进度输出频率
--prove-dump=<路径>        诊断报告路径（默认 sublimation-prover-dump.md，仅中断时写）
--prove-interval=<2s>      进度节流间隔（默认 5 秒）
```

**处理器旗标**：

```
-p <路径>                  附加注解处理器（可多次；.subs 文件或目录）
```

`compile`／`check` 传**目录**时按模块系统入口处理（目录 = 模块，自动挂载入口下的 `core/`）。目录模式只支持 `check` 与 `compile`；脚本目录用 `run-script`。

`-v` 显示补充级诊断（类型推导结果、自然命题注入、深拷贝等）。

**退出码**：

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 非 0 | 检查或编译失败 |
| **130** | 激进证明被 `Ctrl-C` 中断（SIGINT 标准） |

## 1. 生成模型总则

### 1.1 程序级判断式

代码生成是源到源的纯语法变换。JsCodeGen 不读符号表 Σ；跨模块引用名由 Checker 按调用点实例留痕进 `moduleHits`（JsCodeGen.kt:55），生成时直接取用。合并编译（MultiModule.generateJs，MultiModule.kt:150-197）把全部模块单元交给同一个 JsCodeGen 实例：

$$\frac{\text{units} = [(p_1, f_1), \ldots, (p_n, f_n)] \qquad \text{各单元声明按序翻译} \qquad \text{StmtEntry 汇成主序列}}{\Sigma; \Gamma \vdash \text{units} \Rightarrow \texttt{"use strict"} \oplus \text{IIFE}\big(\text{prelude} \oplus \text{runtime}_{\text{used}} \oplus \text{decls} \oplus \text{mainSeq} \oplus \text{entry}\big)} \quad (\text{J-PROG})$$

前提：

- 每个 $(p_i, f_i)$ 中 $p_i$ 为模块 absPath（根 = $\epsilon$），$f_i$ 为已检查的 FileAst；
- 全工程 main 至多一个（MultiModule.kt:139-140，多于一个报 E-DUP-DECL）；
- used 标志已由 Checker 置位（channelUsed/mutexUsed/flowUsed/rangeUsed/androidUsed/deepCopyHits/eqHit）。

产物结构（JsCodeGen.kt:276-452）：

- 外层 `"use strict";` + `(() => { … })();`（:450-451），顶层名字封在 IIFE 作用域内；
- prelude 恒生成：`None`/`Some` 工厂（:279-280）、`__dshtoStr`（:282-287）、`__isa`（:290-299）；
- $\text{runtime}_{\text{used}}$ 按 used 标志按需注入（§1.2）；
- $\text{decls}$ 为各单元声明按序翻译（:405-408）；
- node 目标：$\text{mainSeq}$ 在 IIFE 内联执行（:411-413），$\text{entry}$ 为 `main();`（:424）；
- browser/wasm 目标：$\text{mainSeq}$ 与 $\text{entry}$ 按 S-1 装载模型导出（§7）。

### 1.2 运行时按需注入

$$\frac{\text{flag}_X = \text{true}}{\text{注入片段 } X} \qquad \frac{\text{flag}_X = \text{false}}{\text{零输出}} \quad (\text{J-INJECT})$$

| 片段 | 触发条件（Checker 置位） | 源码位置 |
|---|---|---|
| `__eq` | 源码出现 `==`/`!=`（needEqPreScan，含前缀 SymbolCallExpr） | :301-309 |
| `__dc` | deepCopyHits 非空，或 @view 字段赋值（viewMutationPreScan） | :331-338 |
| `__dshAndroid` | androidUsed（@android 内建被调用） | :317-324 |
| `Channel` class | channelUsed | :342-366 |
| `Mutex` class | mutexUsed | :372-384 |
| `__flow` | flowUsed | :388-392 |
| `__range` | rangeUsed（`..` 值或 Range 方法） | :396-403 |

核实结论：`atomicUsed` 标志虽由 generateUnits 接收并存储（:193），但在整个 JsCodeGen 中无任何 `if (atomicUsed)` 分支触发代码注入。JS 单线程下 @atomic 透明反射到内层类型，无需运行时支持。**〔实现现状〕** atomicUsed 是预留标志，当前无对应注入逻辑。

### 1.3 J-SEQ（声明与程序拼接）

$$\frac{\Sigma; \Gamma \vdash d \Rightarrow js_1 \qquad \Sigma; \Gamma \vdash prog \Rightarrow js_2}{\Sigma; \Gamma \vdash d;\ prog \Rightarrow js_1 \oplus js_2} \quad (\text{J-SEQ})$$

此规则与总纲 §3.10 接口一致。声明翻译见 §2-§4，语句翻译见 §5。

## 2. 名字改写与模块前缀

### 2.1 标识符改写

$$\frac{n \text{ 仅含字母、数字、\_、\$} \qquad n \notin \text{JS 保留字}}{\textsf{mangle}(n) = n} \quad (\text{J-MANGLE-PLAIN})$$

$$\frac{n \in \text{JS 保留字}}{\textsf{mangle}(n) = \$n} \quad (\text{J-MANGLE-RESERVED})$$

$$\frac{n \text{ 含非法字符}}{\textsf{mangle}(n) = \texttt{"op\_"} \oplus \text{逐字符 hex4}} \quad (\text{J-MANGLE-OP})$$

实现：jsMangle（ModuleTree.kt:150-160）。保留字表含 function/return/var/let/const/class/new/this/typeof/in/of/if/else/null/true/false/instanceof 等。`$` 在 JS 标识符合法，直接保留。

### 2.2 模块前缀

$$\frac{\textsf{mangleModule}(\text{absPath}) = p \qquad p = \epsilon}{\text{JS 名} = \textsf{mangle}(n)} \qquad \frac{p \neq \epsilon}{\text{JS 名} = p \oplus \texttt{"\_\_"} \oplus \textsf{mangle}(n)} \quad (\text{J-MODULE-PREFIX})$$

实现：moduleJsName（ModuleTree.kt:146-167）。例：模块 `tool` 的 `triple` → `tool__triple`；根模块的 `main` → `main`。

### 2.3 字典名与重载后缀

$$\frac{\text{impl } C \text{ for } T \qquad \text{模块前缀 } p}{\text{dictName} = \texttt{"dict\_"} \oplus p \oplus \texttt{"\_"} \oplus C \oplus \texttt{"\_"} \oplus \textsf{sanitize}(T)} \quad (\text{J-DICT-NAME})$$

实现：dictNameOf（ImplCheck.kt:77-86）。HKT 简写：Self 为构造子应用占位时只取构造子名（:79-85）。

$$\frac{\text{模块内同名函数首参类型 render 不同}}{\text{JS 名} = \text{moduleJsName}(p, n) \oplus \texttt{"\$"} \oplus \textsf{fnTag}} \quad (\text{J-OVERLOAD})$$

实现：JsCodeGen.kt:749、ModuleTree.kt:171-177。fnTag 为首参类型基名（0 参 = v0，元组 = tup，函数 = fn）。

## 3. 擦除性 I-6 逐条落实

总纲 §5 I-6 规定：类型、命题、理论参数、定理函数、证明语句在代码生成阶段完全擦除，不产生运行时表示；唯一例外是类型类字典。以下逐条给出擦除规则与依据。

### 3.1 类型标注擦除

$$\frac{\tau \text{ 为任意类型标注}}{\Sigma; \Gamma \vdash \tau \Rightarrow \epsilon} \quad (\text{J-ERASE-TYPE})$$

类型标注不出现在 AST 的值位节点中（Parser 产出 Type 仅用于 Checker）；JsCodeGen 的 expr/genStmt 不接受 Type 参数。函数形参的类型标注在 genFun 中被丢弃（:743-746），仅保留参数名与默认值。

### 3.2 命题擦除

$$\frac{P \text{ 为命题表达式} \qquad P \text{ 出现在值位}}{\Sigma; \Gamma \vdash P \Rightarrow \texttt{true}} \quad (\text{J-ERASE-PROP-VAL})$$

$$\frac{P \text{ 为命题算符中缀} \qquad \circ \in \{=, :, \to, \leftrightarrow, \text{自定义双参符号}\}}{\Sigma; \Gamma \vdash e_1 \circ e_2 \Rightarrow \texttt{true}} \quad (\text{J-ERASE-PROP-BIN})$$

实现：bin(:991-992)。命题真值已在编译期由证明器判定，运行时只需恒真占位。量词擦除只留体：QuantExpr → expr(body)（:959）。

### 3.3 理论参数（泛型头）擦除

$$\frac{\Theta = [T_1, \ldots, T_n] \text{ 为理论参数列表}}{\Sigma; \Gamma \vdash \Theta \Rightarrow \epsilon} \quad (\text{J-ERASE-THEORY})$$

理论参数仅在 Checker 层参与类型推导与合一；JsCodeGen 的 genFun 不发射泛型头。InstExpr（供给角括号）整体擦除，只留被调名：expr(InstExpr) = expr(target)（:930）。

### 3.4 定理函数擦除

$$\frac{\texttt{"theorem"} \in \text{decl.annotations}}{\Sigma; \Gamma \vdash \text{decl} \Rightarrow \epsilon} \quad (\text{J-ERASE-THEOREM-DECL})$$

$$\frac{\text{calleeJs} \in \text{theoremJsNames}}{\Sigma; \Gamma \vdash \text{call} \Rightarrow \texttt{null}} \quad (\text{J-ERASE-THEOREM-CALL})$$

实现：预扫描收集 theoremJsNames（:205-208）；genDecl 跳过 @theorem（:608）；call 级联第 1 序命中返回 "null"（:1107-1109）。定理函数的体无论有无均不生成。解释器侧照常求值（06 卷 V-THEOREM）。

### 3.5 证明语句擦除

$$\frac{s \in \{\text{BTSStmt}, \text{WhenPropStmt}, \text{StrategyStmt}, \text{IfPropStmt}, \text{ExistIntroStmt}, \text{ExistsElimStmt}, \text{FunStmt}\}}{\Sigma; \Gamma \vdash s \Rightarrow \epsilon} \quad (\text{J-ERASE-PROOF-STMT})$$

实现：genStmt(:828)。ByStmt 分支为空（:854），t30 后语句式 by 已删为编译期错误 E-BY-REMOVED。

### 3.6 唯一例外：类型类字典保留

$$\frac{\text{impl } C \text{ for } T \qquad \text{字典名 } dn}{\Sigma; \Gamma \vdash \text{impl} \Rightarrow \texttt{const } dn = \{ m_k: \text{function}(d, \ldots) \{ \ldots \} \}} \quad (\text{J-IMPL-DICT})$$

类型类字典是运行时对象，承载方法分派（决策 60/68）。零参类型类方法签名含隐藏字典参数 d 与隐式接收者 __self；kind 类型类（HKT-D2）签名无 __self（:656-659）。这是 I-6 的唯一例外，因为字典是值层实体而非纯类型/命题层构造。

### 3.7 axiom 审计注释

$$\frac{\text{axiom } P_1, \ldots, P_n}{\Sigma; \Gamma \vdash \text{axiom stmt} \Rightarrow \texttt{// axiom: } \textsf{tag}(P_i) \text{ 逐条}} \quad (\text{J-AXIOM-COMMENT})$$

实现：genStmt(:852)。tag() 把命题项渲染为可读标签（:1920-1936）。注释供人工审计，不影响运行时行为。

## 4. 声明翻译判断式

### 4.1 函数声明

$$\frac{\text{body} \neq \text{null} \qquad \texttt{"theorem"} \notin \text{annotations} \qquad \text{slots} = \{d_{C_j\_{T_j}} \mid T_j : C_j, C_j \neq \text{Any}\}}{\Sigma; \Gamma \vdash \text{fun decl} \Rightarrow [\texttt{async}] \texttt{ function } \text{Name}(\text{slots}, \text{params}) \{ \text{body} \}} \quad (\text{J-FUN})$$

前提：decl 有体且非 @theorem。约束泛型槽：Any 是零字典默认类型类，不设槽（:739）。解构参数用合成名 __dtN，体入口 const 拆解（:756-765）。带默认值形参直出 JS 默认值（:745）。块体经 genBlockBody 展平：块式函数不隐式返回尾表达式，返回值只来自显式 return（:792-799）。main 天然 async（:751）。

### 4.2 结构体与枚举

$$\frac{\text{struct } S(f_1, \ldots, f_n)}{\Sigma; \Gamma \vdash S \Rightarrow \texttt{const } S = (f_1 = d_1, \ldots) \Rightarrow (\{ \text{tag: "S"}, f_1: f_1, \ldots \})} \quad (\text{J-STRUCT})$$

$$\frac{\text{enum } E\{c_k(\ldots)\} \qquad c_k \notin \text{listCtorSet}}{\Sigma; \Gamma \vdash c_k \Rightarrow \texttt{function } E\text{\_\_}c_k(a_0, \ldots) \{ \text{return } \{ \text{tag: "c\_k"}, 0: a_0, \ldots \} \}} \quad (\text{J-ENUM})$$

实现：genDecl(:609-633)。结构体字段按名存储，枚举构造子按下标存储。数组化 List（名为 List 的枚举的 Nil/Cons 形态构造子）不生成工厂——JS 层直接是数组：Nil() → []、Cons(h,t) → [h, ...t]（:619-621、:1124-1128）。ctorOwnerCounts ≤ 1 时另发裸名别名（:626/631）。

### 4.3 其余声明

$$\frac{\text{ClassDecl 成员有体}}{\text{按 J-FUN 生成}} \qquad \frac{\text{TypeAliasDecl / PropDefDecl}}{\epsilon} \quad (\text{J-DECL-REST})$$

实现：genDecl(:634-638)。无类型类 impl 已在 Parser 阶段脱糖为自由函数，零残留（:636）。

## 5. 表达式与语句翻译判断式

### 5.1 字面量与名字

$$\frac{}{\Sigma; \Gamma \vdash n \Rightarrow n \qquad r \Rightarrow r \qquad \texttt{"s"} \Rightarrow q(s)} \quad (\text{J-LIT})$$

$$\frac{}{\Sigma; \Gamma \vdash \top \Rightarrow \texttt{true} \qquad \bot \Rightarrow \texttt{false} \qquad \text{true/false/null} \Rightarrow \text{同名 JS 字面量}} \quad (\text{J-BOOL-LIT})$$

q(s) 对控制字符与 U+2028/U+2029 一律 \uXXXX 转义（:1943-1949）。NameRef 解析顺序（:875-896）：① true/false/null → JS 字面量；② E::A → E__A（零参则调用）；③ 零参构造子 → Name()；④ moduleHits 留痕名；⑤ 方法体字段 → __self.f；⑥ dictMethod 体内 self → __self；⑦ 其它 → mangle(n)。ParamRefExpr → /\* $n \*/ 注释占位（:899）；ReturnSym → __ret（:898）。

### 5.2 中缀与一元

$$\frac{\circ \in \{+, -, *, /, \%, <, >, <=, >=\}}{\Sigma; \Gamma \vdash e_1 \circ e_2 \Rightarrow (e_1 \circ e_2)} \quad (\text{J-BIN-ARITH})$$

$$\frac{\circ = \texttt{"=="} / \texttt{"!="}}{\Sigma; \Gamma \vdash e_1 \circ e_2 \Rightarrow \texttt{\_\_eq}(e_1, e_2) \;/\; (\neg\texttt{\_\_eq}(e_1, e_2))} \quad (\text{J-BIN-EQ})$$

$$\frac{x \text{ in } lo..hi}{\Rightarrow (lo \leq x \wedge x \leq hi)} \qquad \frac{lo..hi}{\Rightarrow \texttt{\_\_range}(lo, hi)} \qquad \frac{a \text{ \^{} } b}{\Rightarrow \texttt{Math.pow}(a, b)} \quad (\text{J-BIN-RANGE-POW})$$

实现：bin(:972-994)。==/!= 是结构相等（决策 32/53），__eq 递归比较 tag 与全字段。符号前缀调用 symbolCall(:1001-1008)。

### 5.3 调用级联

调用翻译是有序级联（call，:1097-1500），先命中先生成。关键序位：

| 序 | 判据 | 产物 |
|---|---|---|
| 1 | calleeJs ∈ theoremJsNames | null（J-ERASE-THEOREM-CALL） |
| 2 | in(a, b) 且 b 是 .. | 闭区间比较 |
| 3 | listCtorSet 命中 | [] / [h, ...t] |
| 4 | Channel/Mutex 构造 | new Channel(cap) / new Mutex() |
| 5 | platformOp ≠ NODE_DIRECT | bridgeCall 或 WASM_REJECT（§7） |
| 6 | @host 无体声明（非 node） | globalThis.__subl.call |
| 7 | println/print | console.log(__dshtoStr(...)) |
| 8 | IO/异步内建 | 内联 JS 片段 |
| 9 | listMethodHits | JS 原生数组方法 |
| 10 | consDicts/dicts | slot.m(...) / dn.m(...) |
| 11 | 其余 | calleeJs(args) |

$$\frac{\text{awaitHits}[e] = \text{true}}{\text{调用} \Rightarrow \texttt{await } \text{调用}} \quad (\text{J-AWAIT})$$

实现：awaited(:1058-1059)。panic() → (() => { throw new Error('panic: unreachable') })()（:1312 附近）。

### 5.4 复合表达式

$$\frac{(e_1, \ldots, e_n)}{[e_1, \ldots, e_n]} \quad (\text{J-TUPLE}) \qquad \frac{S(f_1 = e_1, \ldots)}{S(e_1, \ldots)} \quad (\text{J-STRUCTCTOR})$$

$$\frac{\text{值位块}}{\text{IIFE: } (() \Rightarrow \{ \text{stmts; return tail;} \})()} \quad (\text{J-BLOCK-IIFE})$$

$$\frac{\text{值位 if}}{(c \ ? t : (e \mid \texttt{null}))} \quad (\text{J-IF-EXPR})$$

实现：expr(:953-957)、blockIIFE、ifExpr。字符串插值在 Parser/Lexer 层已脱糖为 StrLit，codegen 经 q() 直出转义字符串。

### 5.5 语句翻译

$$\frac{\texttt{"mut"} \in \text{annotations}}{\Sigma; \Gamma \vdash \texttt{var } x = e \Rightarrow \texttt{let } x = \textsf{dcWrap}(e)\texttt{;}} \quad (\text{J-VAR-MUT})$$

$$\frac{\texttt{"mut"} \notin \text{annotations}}{\Sigma; \Gamma \vdash \texttt{var } x = e \Rightarrow \texttt{const } x = \textsf{dcWrap}(e)\texttt{;}} \quad (\text{J-VAR-IMM})$$

$$\frac{\text{var } (a, b) = e}{\texttt{const } [a, b] = \textsf{dcWrap}(e)\texttt{;}} \quad (\text{J-VAR-DESTRUCT})$$

$$\frac{\text{赋值（非视图）}}{x = \textsf{dcWrap}(e)\texttt{;}} \qquad \frac{\text{return } e}{\texttt{return } e\texttt{;}} \quad (\text{J-ASSIGN-RETURN})$$

$$\frac{\text{语句位 if/when}}{\text{展平为真 JS if/else 链}} \quad (\text{J-STMT-FLATTEN})$$

dcWrap(key, v) = deepCopyHits[key] == true ? "__dc(v)" : v（:822-823）。视图字段赋值走副本机制（:844-848）。

## 6. __dc 深拷运行时与函数穿透边界

### 6.1 注入与包装

$$\frac{\text{deepCopyHits} \neq \emptyset \;\vee\; \text{viewMutationUsed}}{\text{注入 __dc}} \quad (\text{J-DC-INJECT})$$

触发条件核实：deepCopyHits 由 Checker 按拷贝四条款谓词（binderNeedsCopy/bindCopy 同一谓词，_langfacts §6）在绑定/赋值点留痕。viewMutationPreScan(:481-507) 检测 @view 结构体字段赋值。**何时拷**两端一致（Checker 与 Evaluator 同一谓词），**怎么拷**不同（下节）。

### 6.2 __dc 的语义

$$\frac{v = \text{null} \;\vee\; \text{typeof}(v) \neq \texttt{"object"}}{\text{__dc}(v) = v} \quad (\text{J-DC-PRIM})$$

$$\frac{v \text{ 为数组}}{\text{__dc}(v) = v.\text{map}(\text{__dc})} \quad (\text{J-DC-ARR})$$

$$\frac{v \text{ 为普通对象}}{\text{__dc}(v) = \{ k \mapsto \text{__dc}(v[k]) \}} \quad (\text{J-DC-OBJ})$$

实现：:332-338。

### 6.3 函数穿透边界（既定边界）

$$\frac{\text{typeof}(v) = \texttt{"function"}}{\text{__dc}(v) = v} \quad (\text{J-DC-FUN})$$

J-DC-FUN 是 J-DC-PRIM 的直接推论：`typeof function !== "object"` 在 :333 早退。JsCodeGen 注释明示此为既定边界（:329-330）：「JS 闭包不透明，函数值经 __dc 时透传；修正案要求的『深拷贝闭包捕获变量』由脚本模式 Evaluator.deepCopy 的 ClosureFun 分支实现，编译模式不变。」

**精确语义**：编译产物里，深拷贝遇到函数值时不复制函数本体及其捕获环境，原样返回同一引用。影响范围：当 @mut 绑定的源值包含函数（如结构体字段为 lambda、元组含函数元素），编译产物的深拷结果与原值共享该函数引用；解释器侧 ClosureFun.copyCapture 沿父链逐值深拷全部捕获变量（06 卷 V-DC-CLOSURE）。非函数值的深拷两端语义一致。

此差异为**既定边界**，不是缺陷：JS 闭包的捕获环境不可 introspect，无法在不改变语言运行时前提下实现深拷。wiki/02-类型-拷贝规则.md「JS 边界」节记录了这一约定。

## 7. 装载模型（--target）

### 7.1 Target 枚举

Target.kt:24-28 定义三个目标：NODE("node")、BROWSER("browser")、WASM("wasm")。CLI --target 参数指定（_langfacts §8），默认 NODE。

### 7.2 node 目标（自执行脚本）

$$\frac{\text{target} = \text{NODE} \qquad \text{mainUnit} \neq \text{null}}{\text{IIFE 尾部生成 } \text{moduleJsName}(p, \texttt{"main"})()\texttt{;}} \quad (\text{J-TARGET-NODE})$$

主序列在 IIFE 内联执行（:411-413），main() 自动调用（:424）。向后兼容，既有行为不变。

### 7.3 browser/wasm 目标（S-1 装载模型）

$$\frac{\text{target} \neq \text{NODE} \qquad \text{mainUnit} \neq \text{null}}{\text{IIFE 尾部生成 } (\text{globalThis}.\text{__subl} \|\| (\text{globalThis}.\text{__subl} = \{\})).\text{main} = \text{moduleJsName}(p, \texttt{"main"})\texttt{;}} \quad (\text{J-TARGET-S1})$$

产物不自执行。宿主 eval 产物后调用 globalThis.__subl.main()。平台调用走宿主桥 globalThis.__subl.call(op, args)（:1078-1089）。主序列与 main 并存时，主序列导出为 prelude 函数（:429-435）。

### 7.4 wasm 同步 IO 拒绝

$$\frac{\text{target} = \text{WASM} \qquad \text{name} \in \text{WASM\_REJECTED}}{\text{抛出 CodegenError(E-PLATFORM-UNAVAILABLE)}} \quad (\text{J-WASM-REJECT})$$

WASM_REJECTED = {readLine, readFile, writeFile, appendFile, readDir, fileExists}（Target.kt:57-59）。wasm 无同步宿主调用通道，这些操作编译期拒绝。println/print 在 wasm 走宿主桥（:1071-1072）。

### 7.5 平台分派级联

$$\frac{\text{target} = \text{NODE} \;\vee\; \text{name} \in \text{userFns}}{\text{PlatformOp.NODE\_DIRECT}} \quad (\text{J-PLATFORM-NODE})$$

$$\frac{\text{target} = \text{WASM} \qquad \text{name} \in \text{WASM\_REJECTED}}{\text{PlatformOp.WASM\_REJECT}} \quad (\text{J-PLATFORM-WASM})$$

$$\frac{\text{name} \in \text{BRIDGE\_OPS}}{\text{PlatformOp.BRIDGE}} \quad (\text{J-PLATFORM-BRIDGE})$$

实现：platformOp(:1067-1073)。BRIDGE_OPS = {println, print, readLine, readFile, writeFile, appendFile, readDir, fileExists, getArgs, sleep}（Target.kt:51-54）。用户同名函数优先让位（:1068）。

## 8. unchecked 的代码生成

$$\frac{}{\Sigma; \Gamma \vdash \texttt{unchecked } s \Rightarrow \texttt{// unchecked} \oplus \Sigma; \Gamma \vdash s} \quad (\text{J-UNCHECKED})$$

## 9. when 与 lambda 翻译

### 9.1 值位 when

$$\frac{\text{subject } s \qquad \text{arms} = [(p_i, g_i, b_i)]}{\Sigma; \Gamma \vdash \texttt{when } s \{ \ldots \} \Rightarrow \text{IIFE}\big(\text{const __sN = s; if (cond) \{ bind; return body; \} \ldots}\big)} \quad (\text{J-WHEN-VAL})$$

实现：whenExpr(:1712-1753)。守卫与模式绑定并存时先绑定再判守卫（:1740-1748）。无兜底补 return null（:1751）。

### 9.2 语句位 when

$$\frac{\text{语句位 when}}{\text{const subject; if/else if/else 链; 分支体 return 真正退出函数}} \quad (\text{J-WHEN-STMT})$$

实现：whenStmtFlatten(:1608-1655)。

### 9.3 lambda

$$\frac{\text{params} \qquad \text{body}}{\Sigma; \Gamma \vdash \{ \text{params} \Rightarrow \text{body} \} \Rightarrow (\text{params}) \Rightarrow \text{body}} \quad (\text{J-LAMBDA})$$

解构参数用合成形参 __dtN + 体首 const 拆解（:932-951）。表达式体 → 箭头函数；块体 → 块体箭头函数（lambda 默认返回最后表达式）。

### 9.4 模式翻译

$$\frac{c(\ldots)}{\text{tag === "c"}} \qquad \frac{\text{结构体解构}}{\text{按字段名取}} \qquad \frac{\text{元组}}{\text{Array.isArray} \wedge \text{length} = n} \quad (\text{J-MATCH})$$

实现：matchJs(:1760-1807)。数组化 List：Nil → length === 0；Cons(h,t) → length >= 1 且 h=s[0]、t=s.slice(1)（:1779-1787）。is T：基本类型用 typeof，其余用 __isa tag 名义判定（:1809-1820）。

## 10. 边界与待核清单

### 10.1 核实结论

1. **__dc 函数穿透**：已核实。J-DC-FUN 是 J-DC-PRIM 的直接推论（:333 typeof !== "object" 早退）。源码注释(:329-330)明确标注为既定边界。编译产物与解释器在函数值深拷上行为不同，非函数值一致。此差异已被 wiki/02-类型-拷贝规则.md 记录。
2. **运行时注入触发条件**：已核实。七个片段的触发条件均经源码确认（§1.2 表格）。atomicUsed 标志虽被接收存储(:193)但无对应注入分支，属预留标志。
3. **命题断言化**：已核实。值位命题表达式一律退化为 JS 布尔字面量 true/false（:991-992、:900-901），不存在运行时 assert 断言。_langfacts §7「命题以断言形态落地」即此含义。
4. **装载模型三目标**：已核实。node 自执行(:423-424)、browser/wasm S-1 导出(:425-444)、wasm 同步 IO 拒绝(:1197-1200)均有源码支撑。

### 10.2 待核项

1. **⊤/⊥ 解释器失真**：⊤/⊥ 在解释器运行时都求值为 ScriptValue.Null（Evaluator.kt:270 附近），导致 print(⊤) → null、⊤ == ⊥ → true。是否既定边界待 06 卷核实。
2. **解释器 var 解构**：VarStmt 分支未判 destruct，整个元组绑到第一个分量名。修复状态待 06 卷核实。
3. **Nat 不变量口径统一**：Checker(-5 : Nat) 与解释器全局推导(-5 : Int) 的口径统一待核实。
4. **旧 unchecked.axiom[p] 引导句**：从未触发属实现细节，待 09 卷诊断码表确认。
5. **本卷未覆盖**：安卓视图生成的全部细节（recomposion 副本机制、__dshFn_* 回调注册）、HKT 字典签名的完整推导、具名实参重排与集合方法糖的 Checker 留痕细节——需要时另卷展开。

# 第三卷 · 类型系统

> 本卷规定凝华的类型种类、内建类型、类型相等判定、隐式转换、合一算法、类型类与字典、泛型与高阶类型、类型别名。
> 类型系统不含子类型关系（`Nothing` 作为底类型除外）；多态的适配通过**隐式转换**与**类型类字典**两种机制完成。

---

## 1. 类型域

### 1.1 类型的归纳定义

类型集合 `Type` 由以下七条规则归纳生成：

$$\frac{}{\text{NamedType}(n, [\tau_{1}\dots\tau_{k}]) \in \text{Type} \qquad \text{n 是名字，} k \ge 0} \quad (\text{T-NAMED})$$

$$\frac{\tau_{1} \in \text{Type} \dots \tau_{k} \in \text{Type} \qquad \tau \in \text{Type} \qquad \pi \in \{\text{""}, \text{"impure"}\} \qquad \Theta \text{ 是类型参数表} \qquad C \text{ 是上下文列表或空}}{\text{FunType}([\tau_{1}\dots\tau_{k}], \tau, \pi, \Theta, C) \in \text{Type}} \quad (\text{T-FUN})$$

$$\frac{\tau_{1} \in \text{Type} \dots \tau_{k} \in \text{Type}}{\text{TupleType}([\tau_{1}\dots\tau_{k}]) \in \text{Type} \qquad k \ge 0} \quad (\text{T-TUPLE})$$

$$\frac{\tau \in \text{Type}}{\text{MutType}(\tau) \in \text{Type}} \quad (\text{T-MUT})$$

$$\frac{\tau \in \text{Type}}{\text{AtomicType}(\tau) \in \text{Type}} \quad (\text{T-ATOMIC})$$

$$\frac{\tau_{1} \in \text{Type} \dots \tau_{k} \in \text{Type}}{\text{UnionType}([\tau_{1}\dots\tau_{k}]) \in \text{Type} \qquad k \ge 2} \quad (\text{T-UNION})$$

$$\frac{}{\text{QualifiedType}(m, n, [\tau_{1}\dots\tau_{k}]) \in \text{Type} \qquad m \text{ 是模块路径段列表}} \quad (\text{T-QUAL})$$

### 1.2 类型的元层分类

| 分类 | 判据 | 用途 |
|---|---|---|
| **名义类型** | `NamedType` 且首字母大写且非合成；或 `QualifiedType` | 决定结构相等是否适用 |
| **数值类型** | `Nat`／`Int`／`Rat` 且零实参 | 决定数值升格是否适用 |
| **合成类型** | `NamedType` 且名字以 `(推导:` 起始且零实参 | 推导期占位，恒放行 |
| **非密封类型** | `NamedType("(未密封)")` | 非穷尽 `when` 的值类型，仅与 `Null` 相容 |
| **底类型** | `NamedType("Nothing")` 且零实参 | 与任何类型相容 |

函数类型与元组类型**不是**名义类型，其相等判定一律走结构相等。

### 1.3 合成类型

当类型推导信息不足时，编译器不报错，而是填入**合成类型**作为占位：

```
syntheticT(reason) = NamedType("(推导:" + reason + ")")
```

合成类型的语义是「此处类型未知，且未知不构成错误」。它在一切类型比对中恒放行（§4.3）。这一设计遵循「有证据才报错」原则：推导不出不等于类型错误。

### 1.4 非密封类型

非穷尽的 `when` 作为表达式时，其值类型退化为 `NamedType("(未密封)")`：

```
unsealedT() = NamedType("(未密封)")
```

非密封类型**参与**真实的类型比对（它不是合成类型），但只与 `Null` 及自身相容。因此：把非穷尽 `when` 的值赋给 `Null` 类型的变量合法；流向 `Str`、`Nat` 等类型则报 `E-NON-SEALED-MATCH`。

## 2. 内建类型

### 2.1 基本类型集

以下名字是**内建基本类型**，无需声明即可使用：

```
Nat   Int   Rat   Real   Str   Bool   Null   Nothing   Any
EmptyTuple   SingleTuple
Task   Channel   Mutex   Flow   Range   Json
```

### 2.2 数值塔

$$\text{Nat} \subseteq \text{Int} \subseteq \text{Rat} \subseteq \text{Real}$$

| 类型 | 语义 | 实现层表示 |
|---|---|---|
| `Nat` | 自然数（非负整数）。每个 `Nat` 值恒有自然命题 $n \ge 0$ | 64 位整数 |
| `Int` | 整数 | 64 位整数 |
| `Rat` | 有理数。**实现层为浮点数**，会损失精度 | 双精度浮点 |
| `Real` | 精确实数。符号表示，不损失精度 | 表达式树（§8） |

`Rat` 与 `Real` 的关系需要明确：`Rat` 是日常数值计算的类型，快但有限；`Real` 是精确符号值，能表示分数、根号、$\pi$、$e$ 及其任意组合。

转换规则：

| 方向 | 语法 | 语义 | 精度 |
|---|---|---|---|
| `Nat`／`Int`／`Rat` → `Real` | 隐式 `toReal()` | 提升到精确实数 | 无损 |
| `Real` → `Rat` | 显式 `toRat()` | 展开计算，求值为浮点 | **有损** |

`Rat → Real` 无损的理由：浮点值本身是某个精确的二进制分数（例如 `0.1` 是 `3602879701896397 / 2^55`），`toReal()` 把它原样搬入 `Real` 的分数表示。

数值升格规则（§4.2）：

$$\frac{}{\text{Nat} \sqcup \text{Int} = \text{Int}} \quad (\text{U-NAT-INT})$$

$$\frac{}{\text{Nat} \sqcup \text{Rat} = \text{Rat}} \quad (\text{U-NAT-RAT})$$

$$\frac{}{\text{Int} \sqcup \text{Rat} = \text{Rat}} \quad (\text{U-INT-RAT})$$

其中 $\sqcup$ 是升格（join）运算。`Real` 不参与此升格——它是独立的精确数值通道。

### 2.3 单值类型与空类型

| 类型 | 语义 |
|---|---|
| `Null` | 单值类型（Unit 职责），唯一值是 `null`。**与 `Optional` 的 `None` 严格区分** |
| `Nothing` | 空类型（底类型）。返回 `Nothing` 的函数发散；其后代码报 `W-UNREACHABLE` |

依总纲公理一，全部语句的值类型是 `Null`；`return` 的类型是 `Nothing`。

### 2.4 `Any`

`Any` 具有**双重身份**，二者在不同语境下各自生效，互不冲突。

**身份一 · 自动类型类。**`Any` 是自动类型类（§6.5）。作为类型参数约束 `[T: Any]` 时，其语义是「T 是任意具体类型」，约束**恒满足**，不产生字典、不做实例查找：

```subl
fun id[T : Any](x : T) : T = x
id(1)        // T := Nat，类型信息完整
id("hi")     // T := Str，类型信息完整
```

类型信息在实例化点被实参的具体类型填满，因此「Any 导致信息丢失」不成立。

**身份二 · 受限顶类型。**`Any` 作为**具体类型**出现在结构体字段或函数形参时，是受限顶类型：

```
struct P(v : Any)
fun mk() : P = P(1)              // E-ANY-STRUCT：含 Any 成员的结构体必须用 unchecked 创建
```

```
fun inner(x : Any) : Null {}
fun outer(a : Any) : Null { inner(a) }    // E-ANY-CALL：涉 Any 的调用推导不出具体类型
```

两条限制的区别：`E-ANY-STRUCT` 可以被 `unchecked` 逃逸；`E-ANY-CALL` 不可逃逸，必须补类型标注。

### 2.5 元组类型

```
EmptyTuple                     空元组
SingleTuple[T]                 单元组
TupleType([τ₁…τₖ])             k 元组，k ≥ 2
```

内建函数 `emptyTuple()` 与 `singleTuple(a)` 用于构造前两者。字面量 `(a, b)` 构造 `TupleType`。

### 2.6 异步内建泛类型

```
Task[T]        协程任务
Channel[T]     通道
Mutex          互斥锁（无类型参数）
Flow[T]        惰性冷流
```

四者是内建泛类型，无用户声明。其运行时语义见第六卷 §8。

### 2.7 区间类型

```
Range[T]
```

`lo .. hi` 的类型是 `Range[Int]`（惰性区间，非列表）。`in` 的右操作数必须是区间字面量或 `Range[T]` 值。

### 2.8 Json 类型

```
Json
```

`Json` 是 JSON 值类型，代码生成层映射为原生 JavaScript 对象／数组／字面量。

### 2.9 标准库容器类型

以下类型由标准库 `core/collection` 以枚举形式定义，不是内建类型，但由 `core` 隐式挂载而普遍可用：

| 类型 | 构造子 | 语义 |
|---|---|---|
| `List[T]` | `Nil`／`Cons(h, t)` | 链表（运行层表示为数组） |
| `Set[T]` | `SetNil`／`SetCons(x, t)` | 去重集合 |
| `Map[K, V]` | `MapNil`／`MapCons(k, v, t)` | 关联表，`put` 覆盖同键旧值 |
| `Optional[T]` | `Some(v)`／`None` | 二值枚举 |
| `Result[T, E]` | `Ok(v)`／`Err(e)` | 成功／失败 |

容器**全程不可变**：`put`／`add`／`remove` 均返回新容器，原容器不变。

### 2.10 空安全类型

```
T?  ⟶  Optional[T]
```

`Optional[T]` 是两值枚举，`Some[T]` 表示有值，`None` 表示空值。可空语法糖可以嵌套：`T??` ⟶ `Optional[Optional[T]]`。

`Some[T]` 可以直接赋值给 `T` 类型的变量，此时发生隐式转换（§5.6）。

## 3. 类型相等

凝华定义两个类型关系：**严格相等** $\equiv$ 与**宽松相容** $\approx$。

### 3.1 严格相等 $\tau \equiv \tau'$

$$\frac{}{\text{NamedType}(n, \text{args}) \equiv \text{NamedType}(n', \text{args}')} \quad (\text{EQ-NAMED})$$

$$\text{当且仅当 } n = n' \text{ 且 } |\text{args}| = |\text{args}'| \text{ 且 } \forall i.\ \text{args}[i] \equiv \text{args}'[i]$$

$$\frac{}{\text{FunType}(\text{ps}, \tau, \pi, \dots) \equiv \text{FunType}(\text{ps}', \tau', \pi', \dots)} \quad (\text{EQ-FUN})$$

$$\text{当且仅当 } |\text{ps}| = |\text{ps}'| \text{ 且 } \pi = \pi' \text{ 且 } \forall i.\ \text{ps}[i] \equiv \text{ps}'[i] \text{ 且 } \tau \equiv \tau'$$

$$\frac{}{\text{TupleType}(\text{ts}) \equiv \text{TupleType}(\text{ts}')} \quad (\text{EQ-TUPLE})$$

$$\text{当且仅当 } |\text{ts}| = |\text{ts}'| \text{ 且 } \forall i.\ \text{ts}[i] \equiv \text{ts}'[i]$$

$$\frac{}{\text{MutType}(\tau) \equiv \text{MutType}(\tau') \qquad \text{当且仅当 } \tau \equiv \tau'} \quad (\text{EQ-MUT})$$

$$\frac{}{\text{AtomicType}(\tau) \equiv \text{AtomicType}(\tau') \qquad \text{当且仅当 } \tau \equiv \tau'} \quad (\text{EQ-ATOMIC-1})$$

$$\frac{\tau \equiv \sigma}{\text{AtomicType}(\tau) \equiv \sigma} \quad (\text{EQ-ATOMIC-2})$$

$$\frac{\tau \equiv \sigma}{\tau \equiv \text{AtomicType}(\sigma)} \quad (\text{EQ-ATOMIC-3})$$

$$\frac{\text{其他一切组合}}{\tau \not\equiv \tau'} \quad (\text{EQ-FAIL})$$

规则要点：

- **`MutType` 与其内层类型不相等**（$\text{@mut}\ T \not\equiv T$）。二者是同一对象的两个**视图**，不是子类型关系；
- **`AtomicType` 是透明标记**：$\text{@atomic}\ T \equiv T$。原子性不改变类型本身，运行时无额外包装；
- **函数类型的纯度参与相等判定**：$(\text{Nat}) \Rightarrow \text{Nat} \not\equiv \text{@impure}\ (\text{Nat}) \Rightarrow \text{Nat}$；
- 名义类型按名字与实参逐一比对，不做结构展开。

### 3.2 严格相等的适用

严格相等用于：

- 函数类型的比对；
- 字典方法签名的比对；
- 类型别名的展开结果比对。

## 4. 类型相容

### 4.1 宽松相容 $\tau \approx \tau'$

宽松相容是类型检查实际使用的关系。判定前必须**先展开类型别名**（§8）。

$$\frac{}{\text{Nothing} \approx \tau \qquad \tau \approx \text{Nothing}} \quad (\text{LOOSE-NOTHING})$$

$$\frac{}{\text{(推导:…)} \approx \tau \qquad \tau \approx \text{(推导:…)}} \quad (\text{LOOSE-SYNTH})$$

$$\frac{}{\text{(未密封)} \approx \text{(未密封)} \qquad \text{(未密封)} \approx \text{Null} \qquad \text{Null} \approx \text{(未密封)}} \quad (\text{LOOSE-UNSEALED})$$

$$\frac{\tau \text{ 是数值类型} \qquad \tau' \text{ 是数值类型}}{\tau \approx \tau'} \quad (\text{LOOSE-NUMERIC})$$

$$\frac{}{\text{MutType}(\tau) \approx \text{MutType}(\tau') \qquad \text{当且仅当 } \tau \approx \tau'} \quad (\text{LOOSE-MUT-1})$$

$$\frac{\tau \approx \sigma}{\text{MutType}(\tau) \approx \sigma} \quad (\text{LOOSE-MUT-2})$$

$$\frac{}{\tau \approx \text{MutType}(\sigma) \qquad \text{恒不成立}} \quad (\text{LOOSE-MUT-3})$$

$$\frac{\tau \approx \sigma \qquad |\tau| = |\sigma| \qquad \tau\text{、}\sigma \text{ 同名}}{\text{NamedType}(n, \vec{\tau}) \approx \text{NamedType}(n, \vec{\sigma}) \qquad \text{当且仅当 } \forall i.\ \vec{\tau}[i] \approx \vec{\sigma}[i]} \quad (\text{LOOSE-NAMED})$$

$$\frac{\text{其他}}{\tau \not\approx \tau'} \quad (\text{LOOSE-FAIL})$$

### 4.2 判定顺序

`LOOSE-*` 规则的判定**必须**按以下顺序进行，因为数值升格必须先于名字相等判定：

```
1. 别名展开
2. Nothing（底类型）
3. 合成类型
4. 非密封类型
5. 数值升格          ← 必须先于第 6 步
6. MutType 视图降级
7. 名字与实参递归
```

若把第 7 步提前，`Nat` 与 `Int` 会被判为不相等而误报 `E-TYPE-MISMATCH`。

### 4.3 三类恒放行的类型

| 类型 | 放行原因 |
|---|---|
| `Nothing` | 底类型：发散的值可以流入任何类型 |
| 合成类型 | 推导不足的占位：未知不构成错误 |
| `AtomicType` | 透明标记：在 §3.1 已展开 |

### 4.4 非密封类型的特殊地位

非密封类型**不是**恒放行类型。它是真实的类型，只是仅与 `Null` 相容。这一设计的意图是：非穷尽 `when` 作为语句使用时（值被丢弃，等价于流向 `Null`）合法；作为表达式流向具体类型时报专属错误 `E-NON-SEALED-MATCH`，而非含糊的 `E-TYPE-MISMATCH`。

## 5. 隐式转换

凝华不设子类型关系，但提供有限的**隐式转换**。每个转换点都是一个语义事件，其中部分伴随运行时行为。

### 5.1 转换关系全集

$$\tau \sqsubseteq \sigma \qquad \text{读作「}\tau \text{ 可隐式转换为 } \sigma \text{」}$$

$$\frac{}{\text{Nothing} \sqsubseteq \tau} \quad (\text{C-NOTHING})$$

$$\frac{}{\text{Nat} \sqsubseteq \text{Int} \qquad \text{Nat} \sqsubseteq \text{Rat} \qquad \text{Int} \sqsubseteq \text{Rat}} \quad (\text{C-NUMERIC})$$

$$\frac{}{\text{Nat} \sqsubseteq \text{Real} \qquad \text{Int} \sqsubseteq \text{Real} \qquad \text{Rat} \sqsubseteq \text{Real}} \quad (\text{C-REAL})$$

$$\frac{}{\text{@mut}\ T \sqsubseteq T} \quad (\text{C-MUT-VIEW})$$

$$\frac{}{T \sqsubseteq \text{Optional}[T]} \quad (\text{C-OPTIONAL})$$

$$\frac{}{\text{Some}[T] \sqsubseteq T} \quad (\text{C-SOME})$$

### 5.2 反方向不成立

$$\frac{}{T \sqsubseteq \text{@mut}\ T \qquad \text{恒不成立}} \quad (\text{C-MUT-NO-UP})$$

从不可变视图**不能**隐式获得可变视图。要得到可变视图必须显式书写 `@mut T` 标注，且该转换点触发深拷贝（§5.5）。

### 5.3 数值升格的语义

数值升格在类型检查层放行，在代码生成层**不产生任何转换代码**——`Nat`、`Int` 在实现层同为整数表示，`Rat` 为浮点表示。升格是类型层的承认，不是运行时的装箱。

### 5.4 可空转换的语义

$T \sqsubseteq \text{Optional}[T]$ 使 `Some(x)` 可以直接写给 `Optional[T]` 标注的变量。

反向的隐式解包（$\text{Some}[T] \sqsubseteq T$，即可选值自动拆给纯类型变量）曾存在过，已按根文档《空安全系统》移除：可选值必须显式拆包（模式匹配、`getOrElse` 等），`var b : Nat = a` 式的自动解包不再合法。

### 5.5 深拷贝触发

涉及 @mut / @ref 的转换点触发的深拷贝，其判定采根文档《副作用与可变性控制》修正案的四条款规则（E-DEEP-COPY，完整矩阵见第六卷 §6.6）：不可变值天然共享、引用是共享请求、其余涉及可变性的转换一律快照。

深拷贝点必须发 `D-DEEP-COPY` 补充级诊断。深拷贝的语义规则见第六卷 §6。

### 5.6 转换点与诊断

隐式转换不产生警告。但以下两种转换点必须留痕：

- 深拷贝 → `D-DEEP-COPY`；
- 类型推导结果 → `D-TYPE-INFERRED`。

## 6. 类型类与字典

### 6.1 类型类

类型类（`class`）是 Haskell 意义下的 typeclass，采用 Rust 的 `impl` 机制：

```subl
class Show {
    fun show() : Str
}

impl Show for User {
    fun show() : Str = self.name
}
```

类型类可以有理论参数：`class Eq[T] { fun eq(other : T) : Bool }`。

### 6.2 子类型类

```subl
class Functor[F[_]] {
    fun map[A, B](fa : F[A], f : (A) => B) : F[B]
}

class Monad[F[_]] : Functor[F[_]] {
    fun flatMap[A, B](fa : F[A], f : (A) => F[B]) : F[B]
}
```

规则：**实现子类型类之前必须先实现其父类型类。**违反报 `E-NO-INSTANCE`。父类型类的约束在子类型类的实例上自动可用。

### 6.3 impl 完整性

```
impl C for T { … }
```

必须满足：

| 条件 | 违反时的诊断 |
|---|---|
| 实现类型类声明的全部方法 | `E-IMPL-INCOMPLETE` |
| 每个方法的签名与类型类声明一致 | `E-IMPL-MISMATCH` |
| 不得有类型类未声明的额外方法，除非标注 `@new` | `E-IMPL-EXTRA` |

`@new` 表示「这不是实现类方法集的函数」，即反向 override：为某个具体类型添加类型类之外的方法。

### 6.4 隐式 self

impl 方法**不书写接收者参数**。方法体内：

- `self` 指代接收者；
- **裸用字段名**等价于 `self.字段名`：`name` $\equiv$ `self.name`；
- 形参可以遮蔽字段，此时发 `H-FIELD-SHADOW` 提示。

```subl
impl Show for User {
    fun show() : Str = name + "/" + toStr(age)    // 裸用字段
}
```

### 6.5 自动类型类

**自动类型类**是满足以下条件的类型类：其**所有**成员函数都有**提供者**。提供者有四种形态：

| 形态 | 提供者 | 例子 |
|---|---|---|
| 表达式体 | 用户 | `fun show() : Str = toStr(self)` |
| 块体 | 用户 | `fun show() : Str { return "x" }` |
| `@root` 标注 | 编译器 | `@root fun ==(other : Self) : Bool` |
| `@host` 标注 | 宿主（脚本模式） | `@host fun hostLog(s : Str) : Null` |

只要有一个成员是纯签名式（无提供者），整个类型类**不是**自动类型类。

**判定纯看形态，不看意图。**

自动类型类的语义：**对每一个类型自动实例化，无需用户书写 `impl`。**

$$\frac{\Gamma \vdash \tau : \text{Type} \qquad C \text{ 是自动类型类}}{\Gamma \vdash \tau : C} \quad (\text{T-AUTO-TRAIT})$$

对自动类型类的约束，编译器**不做实例查找**，恒满足，不生成字典。

**覆盖规则**：

1. 显式 `impl` 优先于自动实例化。用户书写 `impl Any for Point { }` 后，对 `Point` 使用该约束时走显式 impl；
2. 一个类型可以同时自动实现多个自动类型类，它们都是默认提供，不冲突；
3. 非自动类型类不自动实例化，必须显式 `impl`，否则 `E-NO-INSTANCE`；
4. 自动类型类之间不产生冲突判定——它们对所有类型恒满足，不参与歧义。

**当前预定义的自动类型类只有 `Any`**（§2.4）。用户不可自定义自动类型类，以防止消歧义问题与字典爆炸。

成员体的处理方式取决于提供者：

| 提供者 | 处理 |
|---|---|
| 用户体 | 在实例化点复制 |
| `@root` | 编译期内联为原生实现，**不生成字典字段** |
| `@host` | 脚本模式委托宿主 |

若某自动类型类的成员**全部**是 `@root` 或 `@host`，则不生成字典。

### 6.6 字典

**字典**（dictionary）是类型类方法的运行时载体。每个 `impl C for T` 生成一个字典：

```
字典名 = d_{C}_{T}
```

字典方法的调用形态（代码生成层）：

```
$slot.m($slot, self, args…)
```

其中 `$slot` 是字典对象，第一个实参是接收者 `self`。

**字典传递取代了单态化**：泛型函数不为每个具体类型生成特化代码，而是接受一个隐藏首参（字典），在调用点按实参类型解析并传入。

字典解析的判定：

$$\frac{\Sigma \vdash \text{impl } C \text{ for } T \text{ 唯一}}{\text{resolveDict}(C, T) = d_{C,T}} \quad (\text{T-DICT-OK})$$

$$\frac{\Sigma \text{ 中 } C \text{ 对 } T \text{ 有多个 impl 候选}}{\text{resolveDict}(C, T) = \text{E-AMBIGUOUS-INSTANCE}} \quad (\text{T-DICT-AMBIG})$$

$$\frac{\Sigma \text{ 中 } C \text{ 对 } T \text{ 无 impl 候选} \qquad C \text{ 不是自动类型类}}{\text{resolveDict}(C, T) = \text{E-NO-INSTANCE}} \quad (\text{T-DICT-MISSING})$$

字典解析的键是**调用点实例**（而非方法名）：同名方法在多个类型上有实例时，必须按接收者类型分派，否则会错。

### 6.7 方法糖的解析顺序

`x.f(…)` 的解析顺序（同第二卷 §7.2）：

```
1. 同名自由函数／扩展方法，且首形参类型匹配接收者      （优先）
2. 类型类字典里的方法（按接收者类型解析实例）
3. 结构体自身的字段（字段访问）
```

命中第 1 或第 2 条时发 `D-METHOD-SUGAR` 补充级诊断。

### 6.8 双形态调用

```subl
u.show()        // 方法糖
show(u)         // 自由式
```

二者等价，路由到同一实现。类型类方法的第一形参即接收者。

## 7. 泛型与高阶类型

### 7.1 理论参数

```
TheoryParam = TypeParam ⟨ name, constraint : String?, arity : Int ⟩
            | PropParam ⟨ name ⟩
```

类型参数携带两个附加信息：

- `constraint`：类型类约束，如 `[T : Show]` 的 `Show`；
- `arity`：kind 阶数，由声明中 `_` 占位符的个数决定。

命题参数见第四卷。

### 7.2 kind 与 arity

凝华没有独立的 kind 系统，而是以 `arity` 字段表示高阶类型：

| 声明 | arity | 含义 |
|---|---|---|
| `[T]` | 0 | 普通类型参数 |
| `[F[_]]` | 1 | 一阶类型构造子 |
| `[G[_, _]]` | 2 | 二阶类型构造子 |

arity 在类型类声明期检查。arity 不匹配报 `E-KIND-MISMATCH`。

### 7.3 高阶类型的应用

```subl
class Functor[F[_]] {
    fun map[A, B](fa : F[A], f : (A) => B) : F[B]
}

impl Functor for List[a] {
    fun map[A, B](fa : List[A], f : (A) => B) : List[B] = …
}
```

`impl` 的 `self` 位（`List[a]` 的 `a`）是隐式绑定的类型变量，直接书写小写名即可。

**限制**：类型参数不得嵌套（如 `F[G[A]]` 形态的形参），违反报 `E-NON-PATTERN-HKT`。二阶类型（如 `Result[T, E]` 的双参数）无法套入 `F[_]` 一阶类型类，其映射需走专用方法（`mapOk`／`flatMapOk`）。

### 7.4 泛型实例化

实例化发生在**调用点**，由实参类型反推：

$$\frac{f[T](x : T) : T \qquad \text{调用 } f(1)}{T := \text{Nat}，\text{结果类型 Nat}} \quad (\text{T-INST})$$

显式实例化优先于反推：

```subl
f<Nat>(1)
```

lambda 返回类型的反推采用**迭代定点**，最多 8 轮。

### 7.5 类型参数约束

```subl
fun render[T : Show](x : T) : Str = x.show()
```

约束的语义：函数体内对 `x` 调用 `Show` 的方法时，走**约束槽** `d_Show_T`；调用点解出具体类型后解析字典并填入该槽。

约束解析失败报 `E-NO-INSTANCE`。约束在运行时才能确定时报 `W-CONSTRAINT-UNPROVEN`。约束已被反证时报 `E-CONSTRAINT-VIOLATED`。

`Any` 约束恒满足，不设字典槽（§6.5）。

### 7.6 泛型擦除

理论参数在代码生成阶段完全擦除。因此脚本模式的宿主接口中，`[T](T) => T` 与 `(Nat) => Nat` 是**同一个接口**，区别只在元数据（第九卷 §5.2）。

## 8. 类型别名

### 8.1 形式

```subl
type Name [ TheoryParams ] = Target
```

### 8.2 展开规则

$$\frac{\Sigma(\text{name}) = \text{TypeAliasDecl}(\text{name}, [], \text{target})}{\text{expand}(\text{NamedType}(\text{name}, [])) = \text{expand}(\text{target})} \quad (\text{ALIAS-SIMPLE})$$

$$\frac{\Sigma(\text{name}) = \text{TypeAliasDecl}(\text{name}, [a_{1}\dots a_{k}], \text{target})}{\text{expand}(\text{NamedType}(\text{name}, [\tau_{1}\dots\tau_{k}])) = \text{expand}(\text{target}[a_{1} := \tau_{1}, \dots, a_{k} := \tau_{k}])} \quad (\text{ALIAS-GENERIC})$$

泛型头别名按**位置**逐位代入。展开是编译期的，不生成任何运行时代码。

### 8.3 展开的性质

- 别名与目标类型在类型检查中**完全互通**：`type Celsius = Rat` 后，`Celsius` 与 `Rat` 是同一种类型；
- 展开必须递归进行到不含别名为止；
- 别名可以前向引用（右值类型可以先使用尚未声明的别名）；
- 别名与已有的 struct／enum／class／内建类型重名报 `E-DUP-DECL`。

### 8.4 括号约定

| 位置 | 括号 | 例子 |
|---|---|---|
| 类型实参（声明位与代入位） | `[]` | `List[Nat]`、`Box[Nat]`、`Dict[Str, Nat]` |
| 函数调用的类型实参 | `<>` | `mapEmpty<Str, Nat>()`、`Channel<Nat>(2)` |

尖括号 `<>` 还兼任命题施加与显式供给（第五卷 §6）。

## 9. 类型推导

### 9.1 合一

凝华的类型推导**不是** Hindley-Milner 系统，而是实用主义策略：以结构合一为主，配合数值升格与合成类型的宽容处理。

合一算法有两个层次。

**其一，简化合一 `unify(τ, σ) → Type?`**，返回两者的公共类型或 `null`：

$$\frac{\tau \equiv \sigma}{\text{unify}(\tau, \sigma) = \tau} \quad (\text{U-EQ})$$

$$\frac{\tau \text{ 是合成类型}}{\text{unify}(\tau, \sigma) = \sigma} \quad (\text{U-SYNTH-L})$$

$$\frac{\sigma \text{ 是合成类型}}{\text{unify}(\tau, \sigma) = \tau} \quad (\text{U-SYNTH-R})$$

$$\frac{\tau\text{、}\sigma \text{ 均为数值类型}}{\text{unify}(\tau, \sigma) = \text{rank 较高者} \qquad \text{rank：Nat} = 0\text{，Int} = 1\text{，Rat} = 2} \quad (\text{U-NUM})$$

$$\frac{\tau\text{、}\sigma \text{ 同名且同 arity 的名义类型}}{\text{unify}(\tau, \sigma) = \tau} \quad (\text{U-NOMINAL})$$

$$\frac{\text{其他}}{\text{unify}(\tau, \sigma) = \text{null}} \quad (\text{U-FAIL})$$

**其二，带替换的合一 `unifyInto(τ, σ, sub)`**，把结果写入替换表 `sub`：

$$\frac{\alpha\text{、}\beta \text{ 是不同的类型变量}}{\text{sub}[\alpha] := \beta} \quad (\text{UI-VAR-VAR})$$

$$\frac{\alpha \text{ 是类型变量，} \tau \text{ 是具体类型，} \tau \text{ 不含 } \alpha \text{（occurs check 通过）}}{\text{sub}[\alpha] := \tau} \quad (\text{UI-VAR-TYPE})$$

$$\frac{\alpha \text{ 是类型变量，} \tau \text{ 含 } \alpha}{\text{失败（拒绝无限类型 } T \to \text{List}[T] \text{）}} \quad (\text{UI-OCCURS})$$

$$\frac{F[\vec{\tau}] \text{ 中 } F \text{ 是 arity} > 0 \text{ 的形参，} \sigma = C[\vec{\sigma}] \text{ 是具体构造子应用}}{\text{sub}[F] := C \text{，并逐一 unifyInto}(\tau_{i}, \sigma_{i})} \quad (\text{UI-HKT})$$

其余情形按结构递归；无法递归时退回宽松相容判定

### 9.2 occurs check

合一必须执行 occurs check，拒绝无限类型：

```
T = List[T]     非法
```

### 9.3 双向推导

lambda 参数类型可以从**期望的函数类型**反推：

```subl
var lambda : (Nat) => Nat = { _ + 1 }     // _ 的类型由标注反推为 Nat
xs.map({ x => x + 1 })                    // x 的类型由 map 的签名反推
```

### 9.4 返回类型推导

表达式体省略返回类型时，取体的类型；块体省略时，取全部 `return` 的共同类型。推导结果登记入符号表，供调用点查询。

多个 `return` 类型冲突时报错。无 `return` 且无尾表达式时，返回类型是 `Null`。

### 9.5 推导失败的处理

推导失败**不立即报错**，而是填入合成类型占位。只有在合成类型流向需要具体类型的位置时，才报 `E-ANY-CALL` 或 `E-TYPE-MISMATCH`。

这一策略的理由：脚本往往很短，推导不完整是常态；「有证据才报错」避免大量误报。

## 10. 类型层判断式

### 10.1 基本判断

$$\Gamma \vdash e : \tau$$

读作：在上下文 $\Gamma$ 下，表达式 `e` 具有类型 `τ`。$\Gamma$ 的构成与操作见第五卷。

### 10.2 核心规则

$$\frac{x : \tau \in \Gamma.V}{\Gamma \vdash x : \tau} \quad (\text{T-VAR})$$

$$\frac{}{\Gamma \vdash n : \text{Nat} \qquad n \text{ 是非负整数字面量}} \quad (\text{T-INT})$$

$$\frac{}{\Gamma \vdash r : \text{Rat} \qquad r \text{ 是浮点字面量}} \quad (\text{T-FLOAT})$$

$$\frac{}{\Gamma \vdash s : \text{Str}} \quad (\text{T-STR})$$

$$\frac{}{\Gamma \vdash \text{true} : \text{Bool} \qquad \Gamma \vdash \text{false} : \text{Bool}} \quad (\text{T-BOOL})$$

$$\frac{}{\Gamma \vdash \text{null} : \text{Null}} \quad (\text{T-NULL})$$

$$\frac{\Gamma \vdash e_{1} : \tau_{1} \qquad \Gamma \vdash e_{2} : \tau_{2} \qquad \circ \text{ 是内建或已声明的双参函数，形参类型 } (\sigma_{1}, \sigma_{2}) \text{，返回 } \sigma \qquad \tau_{1} \sqsubseteq \sigma_{1} \qquad \tau_{2} \sqsubseteq \sigma_{2}}{\Gamma \vdash e_{1} \circ e_{2} : \sigma} \quad (\text{T-BIN})$$

$$\frac{\Gamma \vdash e : \tau \qquad \tau \sqsubseteq \sigma}{\Gamma \vdash e : \sigma} \quad (\text{T-CONV})$$

$$\frac{\Gamma \vdash e_{1} : \tau_{1} \dots \Gamma \vdash e_{k} : \tau_{k}}{\Gamma \vdash (e_{1}, \dots, e_{k}) : \text{TupleType}([\tau_{1}\dots\tau_{k}])} \quad (\text{T-TUPLE-EXPR})$$

$$\frac{\Gamma \vdash e : \tau}{\Gamma \vdash \text{Some}(e) : \text{Optional}[\tau]} \quad (\text{T-OPTIONAL-INTRO})$$

### 10.3 函数类型规则

$$\frac{\Gamma, x_{1} : \tau_{1}, \dots, x_{k} : \tau_{k} \vdash \text{body} : \tau \qquad \pi \text{ 是纯度标注}}{\Gamma \vdash \{ x_{1} \Rightarrow \dots \} : \text{FunType}([\tau_{1}\dots\tau_{k}], \tau, \pi, [], \text{null})} \quad (\text{T-LAMBDA})$$

$$\frac{\Gamma \vdash e_{i} : \tau_{i}\ (i = 1 \dots k) \qquad \Gamma \vdash f : \text{FunType}([\sigma_{1}\dots\sigma_{k}], \sigma, \pi, \Theta, C) \qquad \forall i.\ \tau_{i} \sqsubseteq \sigma_{i} \qquad \Theta \text{ 可实例化} \qquad C \text{ 可被证明（第五卷 §6）}}{\Gamma \vdash f(e_{1}, \dots, e_{k}) : \sigma} \quad (\text{T-APP})$$

规则 `T-APP` 的三个前提分别对应：实参类型相容、类型参数可实例化、函数类型的上下文命题可证。第三者失败报 `E-CTX-UNPROVEN`。

### 10.4 结构体与枚举规则

$$\frac{\Sigma(S) = \text{struct } S(x_{1} : \tau_{1}, \dots, x_{k} : \tau_{k}) < p_{1}\dots p_{m}> \qquad \Gamma \vdash e_{i} : \tau_{i} \qquad \Gamma \vdash p_{j}[x_{i} := e_{i}]\ (j = 1 \dots m)}{\Gamma \vdash S(e_{1}, \dots, e_{k}) : S} \quad (\text{T-STRUCT})$$

$$\frac{\Sigma(C) = \text{构造子 } C \text{，属于枚举 } E \text{，字段类型 } [\tau_{1}\dots\tau_{k}] \qquad \Gamma \vdash e_{i} : \tau_{i}}{\Gamma \vdash C(e_{1}, \dots, e_{k}) : E[\text{实参}]} \quad (\text{T-CTOR})$$

规则 `T-STRUCT` 的第二前提是**伴生命题义务**：把实参代入伴生命题后必须可证。失败报 `E-STRUCT-PROP-UNPROVEN`。

### 10.5 类型错误

类型层的错误一律使用 `E-TYPE-MISMATCH`，除以下专属码：

| 码 | 场景 |
|---|---|
| `E-KIND-MISMATCH` | 类型构造子的实参个数不对（`List` 必须写 `List[Nat]`） |
| `E-NON-PATTERN-HKT` | 类型参数嵌套 |
| `E-NO-INSTANCE` | 类型类约束无实例 |
| `E-AMBIGUOUS-INSTANCE` | 多个 impl 无法分派 |
| `E-IMPL-INCOMPLETE`／`E-IMPL-MISMATCH`／`E-IMPL-EXTRA` | impl 与类型类声明不符 |
| `E-ANY-STRUCT`／`E-ANY-CALL` | `Any` 的受限准入（§2.4） |
| `E-NON-SEALED-MATCH` | 非穷尽 `when` 的值流向非 `Null` 上下文 |
| `E-TUPLE-DESTRUCT`／`E-TUPLE-ARITY` | 元组解构错误 |
| `E-TYPE-CONFLICT` | 全局类型推导的约束冲突（第九卷 §6） |

## 11. 精确实数 Real

### 11.1 内部表示

`Real` 的值是表达式树：

```
Real = RExact ⟨ num : BigInteger, den : BigInteger ⟩     精确有理数 num/den
     | RConst ⟨ name : ConstName ⟩                       数学常量
     | RSqrt  ⟨ radicand : Real ⟩                        平方根
     | ROp    ⟨ op : OpKind, args : List<Real> ⟩         运算

ConstName = PI | E
OpKind    = ADD | MUL | POW | NEG
```

| 节点 | 含义 | 约定 |
|---|---|---|
| `RExact(p, q)` | 精确有理数 `p/q` | $q > 0$，$\text{gcd}(p, q) = 1$ |
| `RConst(PI)` | 圆周率 $\pi$ | — |
| `RConst(E)` | 自然常数 e | — |
| `RSqrt(x)` | $\sqrt{x}$ | — |
| `ROp(ADD, [a, b, …])` | 加法 | n 元 |
| `ROp(MUL, [a, b, …])` | 乘法 | n 元 |
| `ROp(POW, [a, b])` | 幂 | 二元 |
| `ROp(NEG, [a])` | 取负 | 一元 |

设计理由：

- **`RExact` 用分数而非十进制**：十进制表示不了 `1/3`；分数能表示全部有理数，且加乘除后仍是有理数，可用 gcd 约分到唯一规范形；
- **用 `BigInteger` 而非 `Int`**：`1/3 + 1/5` 的分母会增长，`Int` 溢出会丢精度；
- **$\sqrt$ 是独立节点而非 `POW(x, 1/2)`**：平方根有专属规则（提取平方因子、平方消去、根号合并），独立节点让规则精确；
- **`ADD`／`MUL` 是 n 元而非二元**：结合律使 `a+b+c` 不必嵌套成人字形，展平后排序更利于同类项合并；
- **`NEG` 独立而非 `MUL(-1, x)`**：$-\sqrt{2}$ 比 $(-1)\cdot\sqrt{2}$ 更贴近数学直觉。

### 11.2 规范形

`Real` 的**规范形**是在规则集下跑到不动点的表达式。两个表达式相等，当且仅当它们的规范形结构相等。

```
normalize(r : Real) : Real =
    loop:
        r′ = applyRules(r)
        if r′ == r: return r
        r = r′

structuralEqual(a, b) : Bool =
    (RExact(p₁,q₁), RExact(p₂,q₂)) → p₁ = p₂ ∧ q₁ = q₂
    (RConst(n₁),    RConst(n₂))    → n₁ = n₂
    (RSqrt(x),      RSqrt(y))      → structuralEqual(x, y)
    (ROp(op₁,as₁),  ROp(op₂,as₂))  → op₁ = op₂ ∧ ∀i. structuralEqual(as₁[i], as₂[i])
    其他                            → false
```

**规则集必须合流**（confluent）：任意归约路径都收敛到同一规范形。这是等式判定可靠的前提。

### 11.3 重写规则集

**基础简化**：

```
R1.  ROp(ADD, [x])                → x
R2.  ROp(MUL, [x])                → x
R3.  ROp(ADD, […, 0, …])          → 删除 0 项
R4.  ROp(MUL, […, 1, …])          → 删除 1 项
R5.  ROp(MUL, […, 0, …])          → 0
R6.  ROp(NEG, [RExact(p,q)])      → RExact(-p, q)
R7.  ROp(NEG, [ROp(NEG, [x])])    → x
```

**有理数运算**：

```
R8.  ROp(ADD, [RExact, RExact, …])              → 合并为一个 RExact
R9.  ROp(MUL, [RExact, RExact, …])              → 合并为一个 RExact
R10. ROp(POW, [RExact(p,q), RExact(m,1)])       → RExact(p^m, q^m)
```

**加法合并**：

```
R11. ROp(ADD, [a, b, …])  → 按规范序排列
R12. 同类项合并：k·x + m·x → (k+m)·x
R13. x + NEG(x)           → 删除两者
```

**乘法合并**：

```
R14. ROp(MUL, [a, b, …])  → 按规范序排列
R15. 同底幂合并：x^a · x^b → x^(a+b)
R17. 有理数系数提到最前
```

**根号与幂**：

```
R18. RSqrt(RExact(p,q))   → 提取平方因子
R19. RSqrt(x²)            → x          （前提 x ≥ 0）
R20. RSqrt(a) · RSqrt(b)  → RSqrt(a·b)
R21. RSqrt(x) · RSqrt(x)  → x
R22. x^0                  → 1
R23. x^1                  → x
R24. 1^x                  → 1
R25. (x^a)^b              → x^(a·b)
R26. x^(-n)               → 保留
```

R19 与 R25 的数学前提：`Real` 是**正实数域**（$\text{Nat} \subseteq \text{Int} \subseteq \text{Rat} \subseteq \text{Real}$，`Real` 不含负数），因此二者无条件安全。

### 11.4 黑盒节点

$\sqrt{2}^{\sqrt{2}}$、$\pi^{e}$ 这类无法化简的表达式原样保留，作为**原子**处理：

| 能力 | 是否支持 |
|---|---|
| 自反相等判定 | 支持 |
| 参与排序 | 支持 |
| 参与同类项合并 | 支持 |
| 比较大小 | **不支持** |
| `toRat` 数值化 | **不支持** |

### 11.5 与证明系统的集成

`Real` 的等式判定构成自动证明的一条独立通道：

$$\frac{\text{目标形如 } a = b \text{，且 } a \text{ 或 } b \text{ 的类型涉及 Real}}{\text{normalize}(a) \text{ 与 } \text{normalize}(b) \text{ 结构相等} \Longrightarrow \text{目标可证}} \quad (\text{R-REAL-EQ})$$

该通道只对等式目标（`=`／`==`）生效，不处理不等式。

### 11.6 Real 的诊断

| 码 | 场景 | 等级 |
|---|---|---|
| `E-REAL-DIV-ZERO` | 构造 `RExact(p, 0)` | 错误 |
| `E-REAL-CANNOT-PROVE` | `Real` 等式证不出 | 错误 |
| `E-REAL-NO-NUMERIC` | `toRat` 遇黑盒节点 | 错误 |
| `W-REAL-HUGE` | 分子或分母超过阈值 | 警告 |

### 11.7 Real 的边界

`Real` **不是**：

- 浮点数的包装；
- 类型类（它是具体类型）；
- 完整的计算机代数系统（不做积分、极限、级数、三角化简）；
- 完备数值域（有些命题不可判定，证不出就是证不出）。

## 12. 类型层的擦除

依总纲 §2.3 与不变量 I-2，以下内容在代码生成阶段必须完全擦除：

- 全部类型标注与类型表达式；
- 全部理论参数（类型参数与命题参数）；
- 全部类型类约束；
- 全部类型别名（展开后不留痕迹）；
- `AtomicType` 标记（透明）；
- `MutType` 标记（保留其运行时的拷贝行为，但类型本身不出现）。

唯一保留的运行时构造是**类型类字典**。

## 0 记号与阅读约定

- EBNF 元符号：重复 `X*`（0 或多次）、`X+`（1 或多次）、`X?`（0 或 1 次）、选择 `( X | Y )`；终结符在引号内逐字给出（`"fun"`、`"∀"`）。
- **本语言自身把 `( ) [ ] { } < > , ;` 全部用作终结符**，因此本文不使用花括号/方括号作 EBNF 元符号，重复一律后缀 `* + ?`。
- 产生式编号：`L-n` 词法、`S-n` 短语结构、`D-n` 消歧。编号为本文自定；已被修正案移除的规则不再编号或引用。
- 判断式：消歧规则同时以 LaTeX 推理规则给出，元变量 `t` 指当前 token，`t.space` 即词法邻接属性 `precededBySpace`（L-7），`t₊₁` 指下一 token。
- 所有逗号分隔列表容忍**尾随逗号**（实现统一按「逗号后遇右括符即终止」处理），除文法另有说明外不再逐条标注。
- 「空格」在本文是**词法事实**而非排版建议：换行与空格在 token 层同为 trivia，区别只由 `precededBySpace` 与「同行」判定承载——这是本语言文法不是纯上下文无关文法的原因。

## 1 词法文法（L 层）

扫描器为 `Lexer.kt` 的 `tokenize()`（:54-66）：单遍自左向右、最长匹配；token 流以 `EOF` 终结。每个 token 是五元组 `(kind, text, line, col, precededBySpace)`（`Token` :23-29）。

### 1.1 trivia：空白、换行与注释（L-1 ~ L-4）

```ebnf
L-1 【trivia】     ::= 【空白】 | 【BOM】 | 【行注释】
L-2 【空白】       ::= " " | "\t" | "\r" | "\n"
L-3 【BOM】        ::= "\uFEFF"
L-4 【行注释】     ::= "//" （除 "\n" 外任意字符）* "\n"?
```

- trivia 不产生 token，但其**存在与否**被记入后继 token 的 `precededBySpace`（L-7），从而参与全部邻接消歧（§3）。
- **换行不是 token**：语句边界不是词法概念，而是「中缀糖要求同行」（D-5）等规则的涌现结果——单独成行的语句天然成立，因为下一行的 token 无法成为中缀右操作数（跨行被排除）。
- 只有 `//` 行注释；`/* … */` 块注释不受支持，`/` 按除法算符 lex。
- `skipTrivial()`（:69-84）返回「是否跳过过任何 trivia」；EOF 恒带 `.space=⊤`。

$$\frac{\text{token 前曾跳过 trivia（空格/制表/回车/换行/BOM/行注释）}}{\textit{precededBySpace}=\top} \quad (\text{L-7})$$

### 1.2 标识符通道（L-5 ~ L-8）

```ebnf
L-5 【标识符】     ::= 【标识符首】【标识符续】* "$"段*                  →  IDENT
      【标识符首】   ::= "_" | Unicode 字母（isLetter）
      【标识符续】   ::= Unicode 字母 | Unicode 数字 | "_"
      "$"段        ::= "$" (Unicode 字母 | "_") 【标识符续】* ("$" 数字+ )?
L-6 【反引号名】   ::= "`" （除 "`" 与换行外任意字符）* "`"            →  IDENT（不查关键字表）
L-8 【符号名】     ::= 【符号首】+                                       →  SYMBOL
      【符号首】     ::= c ∈ Unicode 且 c.code > 127 且 ¬c.isWhitespace
                       且 ¬c.isLetterOrDigit 且 c ∉ 【逻辑单例】 且 c ∉ {"∵","∴"}
      【逻辑单例】   ::= {"∀","∃","∧","∨","¬","→","↔","⊤","⊥"}
```

1. **Unicode 标识符**：英文、中文、希腊字母均可（`中文_α` 合法），首字符允许 `_`（`readIdent` :208-228）。
2. **反引号名**（Kotlin 风，`readBacktickIdent` :193-206）：内容可为任意字符（含空格与运算符），**禁止跨行**（否则词法错「反引号标识符不能跨行」）与内嵌反引号；一律 IDENT，不查关键字表（`` `when` `` 是普通名字）。定理库用其写带空格的定理名。
3. **"$"段粘连**（`readIdent` :217-225）：标识符**内部**的 `$` 若后随字母/`_` 则续读为同 token（如注解处理器合成名 `recomposion$Box$1`）；该机制只在 `$` **不在开头**时生效——开头的 `$1` 走 L-11 的参数引用通道。
4. **符号名**（`readSymbol` :235-242）：非 ASCII 数学符号的最大匹配串（`○`、`⊗`、`∈`…），可作函数名/名字位（`fun ○(a, b)`）。`∵`/`∴` 被显式排除（`isBecauseSym` :101-103），它们是固定单 token。
5. **`∈`（U+2208）、`≥`/`≤`（U+2265/2264）、`≠`（U+2260）不在【逻辑单例】**，落入 SYMBOL 通道（lexer 单字符分派的 `'≠'→NEQ` 等分支被 `readSymbol` 先收，属不可达代码，:135-138）。运算符文本保原文进入 AST（`BinExpr("∈",…)`），ASCII/Unicode 等价归一发生在命题层。**书写注意**：SYMBOL 中缀（D-6）要求符号**前**有空格，故 `a ≥ b` 合法、`a≥b` 截断；ASCII `a>=b` 紧贴可用（`>=` 是独立 GE token，binops 通道不查空格）。

### 1.3 关键字（L-9）

```ebnf
L-9 【硬关键字】 ::= "fun" | "class" | "struct" | "enum" | "var" | "impl" | "for" | "if"
                   | "else" | "unchecked" | "when" | "is" | "by" | "type" | "return" | "def"
```

- 共 **16 个**（`keywords` :39-45）；标识符读出后查表折算，不可再作普通标识符（需反引号转义）。
- **`in` 去关键字化（P51）**：普通 IDENT——可作函数名/参数名/命题名；其中缀位由 Parser 按文本识别并解为调用 `in(a,b)`（S-1a）。枚举里有 `Kind.IN` 但 **lexer 从不产出**（休眠项）。
- `forall`/`exists`/`exists1`、`as`、`not`、`then`/`else`（命题位）、`axiom`、`Task`、`Flow` 均为**普通标识**，其特殊语义只在特定语法位置生效。
- `for` 保留为关键字但仅服务于 `impl T for U`（无循环语法，迭代走 `forEach`）。

### 1.4 字面量（L-10）

```ebnf
L-10 【整数字面量】 ::= 数字+                                    →  INT
      【浮点字面量】 ::= 数字+ "." 数字+                          →  FLOAT
      【字符串字面量】::= '"' （【串字符】|【转义】）* '"'          →  STR
      【串字符】     ::= 除 '"' 与 "\" 外任意字符（含换行）
      【转义】       ::= "\" ( "n" | "t" | "r" | '"' | "\\" | <任意字符原样保留> )
```

- 浮点判定（`readInt` :156-166）：`1.0` 是 FLOAT；点号后必须紧跟数字才粘连，`1.` 与 `1.x` 都是 INT 紧跟 DOT。
- 字符串可跨行（词法不挡），未闭合报「字符串未闭合」（`readString` :168-189）；`\` 后非 `n t r '"' \` 时原样保留该字符。
- **字符串插值不在词法层**：STR 保留原文，`$name` 与 `"${expr}"` 由解析期脱糖（D-INTP）。**注意**：`\$` 在 lexer 还原为字面 `$` 后，解析层仍按 `$` 扫描插值——即 `"\$x"` 仍会插值 `x`；若需字面 `$` 目前无转义手段（**待核**：是否应在词法层引入 `\$` 短路）。

### 1.5 多字符算符表（L-12，固定匹配顺序）

`readToken()` 在数字/字符串/反引号/标识符/符号名分派**之后**按如下固定顺序逐条尝试（顺序不可调换，:106-122）：

| 序 | 拼写 | Kind | 备注 |
|---|---|---|---|
| 1 | `<->` | IFF | 等价 |
| 2 | `=>` | DARROW | **程序位箭头**：lambda 参数表、when 分支、函数类型、零参 lambda |
| 3 | `==` | EQ | 值相等 |
| 4 | `!=` | NEQ | |
| 5 | `<=` | LE | |
| 6 | `>=` | GE | |
| 7 | `->` | ARROW | **修正案后全位非法**：lexer 产出仅为诊断定位，无任何产生式消费 |
| 8 | `∃!` | EXISTS1 | 须先于单 `∃` |
| 9 | `+∵` | PLUS_BECAUSE | 须先于单 `+`；**token 存在但 Parser 无消费点**（§5.2） |
| 10 | `..` | RANGE | 须先于单 `.` |
| 11 | `::` | COLON2 | 须先于单 `:` |
| 12 | `&&` | LAND | **文本归一为 `∧`** |
| 13 | `\|\|` | LOR | **文本归一为 `∨`** |

单字符分派（上表全部不匹配时，:124-152）：`( ) [ ] { } , ; : . @ \\ $ # + - * / % ^ = < > & | !` 与 Unicode 单 token `∀ ∃ ∧ ∨ ¬ → ↔ ⊤ ⊥ ∵ ∴`。全角标点（`fullWidth` :51）触发带提示的词法错误（「请换成英文半角符号」，:139-142）。

### 1.6 `$n` 粘连与 `$`（L-11）

```ebnf
L-11 【参数引用】 ::= "$" 数字+        →  DOLLAR（单 token，文本含 "$"）
```

- `$` 紧跟数字即粘连为单 DOLLAR token（:146-150）；单独的 `$` 是返回值符号（解析层 `ReturnSym`）。
- `$n` 在表达式中读作第 n 形参引用（`ParamRefExpr`：`$` 后数字直接转整型；`$0` 词法合法——其语义层是否有效 **待核**）。

## 2 短语结构文法（S 层）

### 2.1 解析入口：工程模式与脚本模式

```ebnf
S-1  【编译单元】 ::= 【顶层条目】* EOF
S-2  【顶层条目】 ::= 【声明】 | 【语句】
S-3  【语句顶层】 ::= "axiom" 【命题】        /* 工程模式唯一合法的顶层语句；其余语句仅脚本模式 */
```

入口由构造参数区分（`Parser` :19-26）：

| 入口 | 模式 | scriptMode | allowUntyped | 说明 |
|---|---|---|---|---|
| `parseSource`/`parseSourceWithNotes`（:1775-1781） | 工程模式 | false | false | 顶层只允许声明与 `axiom` 语句；形参/字段类型强制标注 |
| `parseScriptSource`(WithNotes)（:1783-1795） | 脚本模式 | true | 可选 | 顶层允许任意语句与声明；`--global-inference` 时 `allowUntyped=true` |
| `parseDeclSnippet`/`parseFunBodySnippet`/`parseStmtsSnippet`（:1801-1817） | 片段解析 | true | false | 注解处理器宿主用：单条声明/函数体/语句序列，要求整段耗尽 |

- `parseEntry`（:194-209）分派：
  1. `fun class struct enum impl type def` → 声明（两种模式皆可）；
  2. `@` 注解前缀 → 仅 `@x fun` / `@x struct` / `@x class` 放行（struct/class 上的注解一律放行，交由处理器解释）；其余在脚本模式降为语句、工程模式抛「顶层只能写声明」；
  3. 其余 → 脚本模式为语句；工程模式**仅当** token 是 IDENT 且文本为 `axiom` 时为语句（公理注入是声明性命题，非执行代码），否则抛 `noTopLevel()`。
- **无类型类 impl 脱糖**：`parseFile`（:152-164）把 `impl T { … }`（trait==null）的成员在 AST 级展开为「以 `self` 为首形参、self 类型中的 kind 占位提升为成员类型参数注」的自由函数，后续链路零感知。
- **模块挂载不是源码语句**：语言无 import 产生式，Parser 无 ImportStmt；跨模块靠 `.settings` 的 `mount <路径> [as <别名>]` + 限定引用 `a.b.c`（ModuleTree.kt 独立解析，不在本卷范围）。

### 2.2 名字位（S-4）

```ebnf
S-4  【名字】     ::= IDENT | SYMBOL | "+" | "-" | "*" | "/" | "%" | "="
                     | "≠" | "≤" | "≥" | "&" | "|" | "<->" | "<" | ">"
      【命题名】   ::= 【名字】 ∪ {"==","!=","in"}      /* def 命名位；排除字面量/括号/EOF（defNameKinds :64-69） */
```

运算符可作函数名（仿 Scala：`fun +(a, b)`）。**一元负号 MINUS 不在可前缀调用名集合**（一元负优先，opPrefixKinds :58-60）。

### 2.3 声明（S-5 ~ S-14）

```ebnf
S-5  【声明】     ::= 【函数声明】|【类型类声明】|【结构体声明】|【枚举声明】
                     |【实现声明】|【类型别名】|【命题定义】
S-6  【注解】     ::= ("@" IDENT)*

S-7  【函数声明】 ::= 【注解】 "fun" 【名字】 【理论参数】? 【形参表】? 【头部角组】? 【返回区】? 【函数体】?
      【头部角组】 ::= "<" ( 【约束表】 | 【角表】 ) ">"      /* constraintListAhead 先行判定（D-13） */
      【约束表】   ::= 【约束项】 ("," 【约束项】)* ","?
      【约束项】   ::= 【名字】 ("<="|">="|"=="|"!="|"in") 【表达式】
      【返回区】   ::= ":" ( 【角表】 | 【类型】 【角表】? )   /* ": <q>" = 无返回类型的后置上下文 */
      【函数体】   ::= "=" 【表达式】 | 【块】                /* 二者互斥（D-11）；签名/定理可无体 */
```

- **S-7 的顺序是固定的**：`fun 名 [理论参数] [形参表] [<…>] [: 类型 [<…>]] [体]`。形参表 `()` 必须在头部角组**之前**——把 `<…>` 写在 `()` 之前（`fun f<score <= 100>()`）会使 `()` 悬挂，被报为「顶层只能写声明」；正确写法是 `fun f()<score <= 100>` 或无参形 `fun f<score <= 100>`。
- 约束表（D-13：角括内首项为 IDENT 且其后是**带空格的** `<= >= == != in`）「只登记不校验」（V1 占位）。
- 【函数体】`= {…}` 混写直接报语法错并给改写指引（:299-301）。

```ebnf
S-8  【理论参数】 ::= "[" (【命题参数】|【类型参数】) ("," …)* ","? "]"
      【命题参数】 ::= "@" 【名字】                        /* [@P] 命题元变量 */
      【类型参数】 ::= 【名字】 ("[" "_" ("," "_")* ","? "]")? (":" 【名字】)?
                     /* [T] / [T: Show] / [F[_]] arity=1 / [F[_, _]] arity=2 / [F[_]: Foldable] */
      【形参表】   ::= "(" (【形参】 ("," 【形参】)* ","?)? ")"
      【形参】     ::= 【注解】 【解构形参】? 【名字】 ":" 【类型】 ("=" 【表达式】)?
      【解构形参】 ::= "(" 【名字】 ("," 【名字】)* ","? ")"      /* fun f((a, b): Point) */
      /* 默认值仅 struct 字段允许（函数形参带默认值报 E-DEFAULT-PARAM）；@list 形参 = 变长实参 */

S-9  【类型类声明】 ::= 【注解】 "class" 【名字】 【理论参数】?
                      (":" 【具名类型】 ("," 【具名类型】)* ","?)?
                      ("{" 【注解】? 【函数声明】* "}")?          /* 父类型类链；无成员可省花括号 */
S-10 【结构体声明】 ::= 【注解】 "struct" 【名字】 【理论参数】? 【形参表】? 【角表】?
                      /* 体是圆括号形参表（大括号体报错并给改写指引）；无字段可省 ()；
                         <…> 是伴生命题 struct P(n: Nat) <n ≠ 0> */
S-11 【枚举声明】  ::= "enum" 【名字】 【理论参数】? ("{" 【构造子】 (","|";")* "}")?
      【构造子】   ::= 【名字】 ("(" 【类型】 ("," 【类型】)* ","? ")")?
```

### 2.7 lambda 各形态（S-36）

```ebnf
S-36 【lambda】       ::= "{" (【lambda参数】 ("," 【lambda参数】)* ","?)? "=>" 【lambda体】 "}"
                        | "{" 【隐式体】 "}"                 /* 无箭头=隐式单参，_ 引用形参 */
      【lambda参数】   ::= 【名字】 | 【lambda解构参数】
      【lambda解构参数】 ::= "(" 【名字】 ("," 【名字】)* ","? ")"   /* {(a, b) => …}，编码特殊名 "(a,b)" */
      【lambda体】     ::= 【语句】*                           /* 单条表达式语句退化为表达式体 */
```

- 三种显式形态：多参 `{ a, b => … }`、**零参 `{ => 7 }`**（参数表为空但箭头必写）、解构参 `{(a, b) => …}`；第四种是**隐式单参** `{ x + 1 }`（无箭头，体内 `_` 引用形参，Kotlin `{ it }` 同款）。
- 尾随 lambda（D-9）：`f(a) { … }` → 追加为最后位置实参；`Task { … }`/`Flow { … }` 例外——体是代码块。
- 旧 `\(x) =>` 形态已移除：BACKSLASH token 无任何产生式消费。

### 2.8 when 全形态（S-37 ~ S-39）

```ebnf
S-37 【when表达式】 ::= "when" ("(" ("var" 【名字】 "=")? 【表达式】 ")")? "{" 【when分支】* "}"
      【when分支】   ::= (【模式】|【条件表达式】) ("if" 【表达式】)? "=>" 【分支体】
      【条件表达式】 ::= 【表达式】                              /* 无主题 when 的分支条件 */
      【分支体】     ::= 【块】 | 【表达式】
      /* 主题可选：when(x) 模式匹配；when(var e = 0) 绑定主题；when { cond => body } 无主题布尔分支；
         when(t in _) 模板脱糖（D-15）；分支分隔符 => 必写（at(DARROW)，:1546） */

S-38 【命题if】   ::= 见 S-20                                  /* if[p] 排中律，块内是语句 */

S-39 【命题when】 ::= 见 S-21                                  /* when[p ∨ q] 分类讨论，体必须是块 */
```

要点：

- 值 when 与命题 when 的判据是**紧跟 `(` 还是 `[`**（D-12：方括号=命题层，圆括号=值层）。
- 模板 when（D-15）：主题为 `in _` 时脱糖为无主题 when，各分支模式 `p` 变为条件 `t in p`；模板分支的模式/守卫/体都在 stopArrow 下解析（§3.2）。
- 命题 when 分支的条件**不设 stopArrow**：`p → q => {…}` 中的 `→` 链被吸收进条件本身，无需括号；但体必须是 `{}` 块，且裸条件后直接跟 `{` 会被尾随 lambda 吞噬（见 §5.1）。
- ifis 智能解构：`if (e is 构造模式) A else B` 在 parseIf 层脱糖为 `when (e) { is 模式 => A (else => B) }`；组合条件中的模式哨兵在解析期拒绝（:1409-1412）。
- 数学风 if-then-else（命题位）：`if c then a else b`，`then`/`else` 为普通 IDENT，以 stopIdents 作停止词（§3.2、:1428-1445）。

### 2.11 axiom 语句与 unchecked 语句（S-23 / S-25）

- **axiom 语句**：`axiom p₁, p₂, …`。词法层 `axiom` 是普通 IDENT，语句位按**文本**识别；起命题判定 `canStartAxiomProp`（:701-704）允许下一 token 为 IDENT/SYMBOL/INT/FLOAT/STR/`(`/`¬`/`!`/`⊤`/`⊥`/`-`/`∀`/`∃`/`∃!`，否则该次分派不成立（回退到 S-30 表达式语句，`axiom` 被当普通名字引用）。顶层可用（S-3）；旧的 `unchecked.axiom[p]` 形态在 parseUnchecked 显式报错引导改写。
- **unchecked 语句**：`unchecked <语句>`（:796-803）。`unchecked.` 后随 `axiom` 报「公理请直接写 `axiom <命题>` 语句」；`unchecked.` 后随其它报「语句」；其余形态（含换行分隔）消费一条内层语句。uncheckedDepth 的语义后果不属于本卷。

## 3 歧义消解（D 层）

由于邻接属性与停止集参与分派，本文法是**上下文敏感文法**；敏感点收敛为下列有限规则。词法层只记录事实（L-7），消解全部在语法层。

### 3.1 箭头双通道

$$\frac{\text{程序位：lambda 参数表 / when 分支 / 函数类型 / 零参 lambda / 命题 when 分支}}{\text{箭头为}\ \texttt{=>}\ (\textsf{DARROW})} \quad (\text{A-1})$$

$$\frac{\text{命题位：蕴含 infix}}{\text{箭头为}\ \to\ (\textsf{IMPLIES})} \quad (\text{A-2})$$

$$\frac{\text{任意位置出现}\ \texttt{->}\ (\textsf{ARROW})}{\text{解析失败}\ (\text{lexer 产出仅为诊断定位；parseExpr 的 stopArrow 仍对其设防，:1025})} \quad (\text{A-3})$$

- 命题蕴含 `→` 是 binops 成员（可与 `∧ ∨ ↔ == !=` 同层混排，全部左结合无优先级）；程序位 `=>` **不在** binops 中，故中缀循环天然在 `=>` 处终止——这是 when 分支/lambda 参数表能被正确切分的机制基础。
- 等价：`<->`（IFF）与 `↔`（EQUIV）并存：IFF 在 binops，EQUIV 用于 def 等价式右值起首（S-14）；两者在命题层等价归一。

### 3.2 停止集（stop sets）

`parseExpr(angle, stopArrow)` 的循环在每个候选中缀前先查停止集：

$$\frac{\textsf{stopArrow}=\top \qquad \textsf{t}\in\{\texttt{->},\texttt{=>}\}\ \lor\ (\textsf{t}=\texttt{“(”}\ \land\ \textsf{t}.\textit{space}=\top)}{\text{中缀循环终止}} \quad (\text{D-21})$$

- **stopArrow=true 的位置**（仅模板 when 链路）：模板分支模式（:1529）、守卫（:1533）、分支体（`parseBranchBody` :1677-1678）。前半（`->`/`=>`）为分支箭头让路（`->` 修正案后非法，保留属防御）；**空格 `(`** 防止下一 arm 的模式（如 `(11..20)`）被后缀调用吞掉——无空格调用 `f(x)` 不受影响（:1020-1022）。
- **stopIdents**：数学风 if-then-else 的 `then`/`else` 是普通 IDENT，解析条件时停止集为 `{then}`、解析 then 分支时为 `{else}`（:1428-1441），防止两参中缀糖把 `then`/`else` 当函数名吞。
- **命题 when/if 的命题位**（`when[p]`、`if[p]`、`axiom`、`∵`/`∴`）用 `angle` 通道而非 stopArrow（`>` 的终止靠 D-2）。

### 3.3 中缀糖判定（D-5）

$$\frac{\begin{gathered}\textsf{t}:\textsf{IDENT} \qquad \textsf{t}.\textit{space}=\top \\ \textsf{t}_{-1}.\textit{line}=\textsf{t}.\textit{line} \qquad \textsf{t}_{+1}.\textit{space}=\top \\ \textsf{t}_{+1}.\textit{line}=\textsf{t}.\textit{line} \qquad \textsf{t}_{+1}.\textit{kind}\notin \textit{排除集}\end{gathered}}{\textsf{a f b} \Rightarrow \textsf{f(a, b)}\ (\textit{右操作数只取一元表达式})} \quad (\text{D-5})$$

- 排除集（`infixOperandAhead` :1109-1111）：`->  =>  ,  }  ]  ;  )  =  return`——即右操作数必须是**合法表达式起始 token**，避免把 when 下一分支的模式名或实参表尾误当中缀右操作数。
- 三重空格/同行约束的动机：`f(x)`（后无空格）是调用；`1\nx`（跨行）不是中缀；`a f(x)` 中 `f` 与左操作数同行但右操作数 `(x)` 前无空格 → 不是中缀（仍按后缀调用解析）。

### 3.5 lambda 诗据（D-17）

$$\frac{\text{大括号深度 1 内首个}\ \texttt{=>}\ \text{之前仅出现 名字/逗号/解构括号（括号内任意）}}{\text{该花括号为 lambda；参数表可为空 = 零参}\ \{\ \texttt{=>}\ 7\}} \quad (\text{D-17a})$$

$$\frac{\text{深度 1 内无}\ \texttt{=>}\ \text{且无}\ \texttt{:} \qquad \text{闭合于深度 0}}{\text{隐式单参体（}\ \texttt{\_}\ \text{引用形参）}} \quad (\text{D-17b})$$

- 诗据在**词法层先行**（parsePrimary/parsePostfix 调用 `braceIsLambda`/`braceHasImplicitBody` 前传 `pos`，扫描 token 流而非消费）：深度 1 内混入任何其它 token（数字、`∴`…）即否决为 lambda；`{ 1 => x }` 因此是代码块而非 lambda。
- 隐式体的 `:` 排除：`{ x: T }`（类型测）不当隐式 lambda。
- 区块体与 lambda 的最终裁决在 `parseBraceLambda`（:1684-1703）：显式参数表读到 `=>`（逗号分隔，支持解构参数）；否则整体作为 `LambdaExpr(["_"], body)`。
- `Task { … }`/`Flow { … }` 在 D-9 判定内被显式排除（:1209），再由专用分支承接为 TaskExpr/FlowExpr（:1215-1224）。

### 3.6 `by` 的两解

- **后缀断言**：`expr by [q]` → ByExpr（S-31 中缀循环 :1027）。Checker 层面 t30 后免验证供给已删，改为 proveOrDeep 核对义务。
- **语句式**：`by [q]` → ByStmt（S-27，:652）。Parser 仍解析此形态，但 Checker 报 E-BY-REMOVED。
- **impl 委托**：`impl C for T by field` → ImplDecl.delegate（:969-978）。此处 `by` 后必须跟 IDENT（字段名），否则报错。与前两解在不同语法位置，无歧义。

## 4 与第 12 卷的衔接：有界量化语法

> **本节描述的是规格而非现状。** 当前 Parser **无** `[X <: τ]` 有界量化语法形态，属 [形式化语义12-有界高阶类型](形式化语义12-有界高阶类型.md) 规格待实现的内容。本节旨在预登记未来引入时的文法冲突点。

### 4.1 有界量化语法的目标形态

第 12 卷定义了 Kernel Fω<: 的判断系统，其中有界量化形如 `∀X<:τ. σ`（类型层）与 `ΛX:𝕂. τ`（类型抽象）。映射到凝华的具体语法，预期形态为理论参数表内的 `[X <: τ]`：

```
fun map<[F <: Functor], A, B>(fa: F[A], f: (A) => B): F[B] = ...
```

### 4.2 与既有约束形参表的潜在冲突

当前 Parser 已有约束形参表 `fun f<score <= 100>`（D-13，constraintListAhead :311-316），其判定条件是「角括内首项为 IDENT 且其后是**带空格的** `<= >= == != in`」。若引入 `<:` 作为有界量化符号：

1. **Lexer 层**：新增 `<:` 双字符 token 须与 `<=`(LE)、`<->`(IFF) 的最长匹配不冲突。当前匹配顺序（:106-122）中 `<->` 在最前、`<=` 在第 5 序；`<:` 应插入 `<=` 之前以避免 `<=` 抢先匹配。**待核**：具体插入位置与回归影响。
2. **Parser 层**：`constraintListAhead` 当前检查 `op.kind in setOf(Kind.LE, Kind.GE, Kind.EQ, Kind.NEQ)` 及 `op.text == "in"`。若 `<:` 是新 token，需加入该集合；若复用现有 token（如 LT 后跟 COLON），则需调整前瞻逻辑。**待核**：选择新 token 还是组合判定。
3. **语义层**：约束表当前「只登记不校验」（V1 占位）；有界量化要求 Checker 真正执行子类型判定。这属 [编译器旗标扩展类型系统指导](编译器旗标扩展类型系统指导.md) 的 `fomega-bound` 方言档，工程分期 P3 落地。

### 4.3 旗标门控下的文法扩展

[编译器旗标扩展类型系统指导](编译器旗标扩展类型系统指导.md) 设计了 `--types=sub|fomega-bound` **两档**旗标：`sub` 是基础方言（默认，无子类型），`fomega-bound` 是 Kernel Fω<: 方言。文法层的有界量化语法 `[X <: τ]` 仅在 `fomega-bound` 档启用；基础方言档遇到该形态应报语法错并提示切换旗标。**待核**：Parser 是否需要接收旗标参数以控制产生式可用性，还是在 Checker 层统一拦截。

## 5 已知限制与脆弱产生式

### 5.1 `∃ x . P { … }` 的消去块受尾随 lambda 威胁

`parseExistsStmt` 的可选块（:789-791）只有在未被尾随 lambda 规则（D-9）吞掉时才归入消去语句。**若命题 `P` 的后缀链以可调用表达式结尾（名字、函数调用结果等），`{ … }` 会被解析为隐式单参 lambda 并追加为调用实参**。规避：把命题括号化（`∃ x . (q ∧ r) { … }`）或使命题结尾不是可调用形态（字面量/一元/双目结果被 D-9 明确排除）。**待核**：是否应在 `parseExistsStmt` 内对 `{` 做前瞻豁免。

### 5.2 `+∵` token 无产生式

lexer 产出 `PLUS_BECAUSE`（L-12 第 9 序），但 `Parser.kt` 无任何分支消费它（语句位/表达式位均报「期望表达式」）。全仓仅 lexer 与 LSP token 分类引用。

### 5.3 S-7 头部顺序固定

`fun 名 [theory] [形参表] [角组] [: 类型 [角组]] [体]`：形参表必须在角组之前，否则 `()` 悬挂并被报为「顶层只能写声明」。约束表「只登记不校验」（V1 占位）。

### 5.4 其它

- **算术无优先级**（D-10）：仅提示加括号。
- **Unicode 比较符紧贴失败**（D-6）：`a≥b` 截断成语句碎片；源码建议一律带空格书写 Unicode 比较符。ASCII 形（`>=`）紧贴无碍。
- **`return@label`** 的标签须紧贴 `return`（D-18）。
- **全角标点**一律词法错误并提示改半角。
- **块注释不存在；字符串可跨行**（词法不挡）。
- **类型别名右值**仅具名/应用类型（函数类型/元组右值不支持）。
- **`\$` 不能禁止字符串插值**（§1.4）。
- **`$0` 词法合法**：语义层是否有效 **待核**。

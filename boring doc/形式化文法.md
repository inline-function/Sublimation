## 0. 范围与阅读对象

本文覆盖 **词法文法**（L 层）、**上下文敏感的消歧规则**（D 层）、**语法文法**（G 层）、**脱糖/归一规则**（S 层），以及模块配置文法（M 层，附录）。

**不在本文范围**：类型系统、命题证明语义、纯度/可变性语义、JS 代码生成——这些属于 checker 与 codegen，最高权威为 `root doc/`。本文仅在语法载体层面提及它们（例如 `<…>` 是「上下文命题」的语法形式）。

**阅读对象**：想精确知道某个构造是否合法（写 LSP 插件、写格式化器、移植解析器、或和语法歧义搏斗）的人。

## 1. 记号约定

- 重复：`X*`（0 或多次）、`X+`（1 或多次）、`X?`（0 或 1 次）。
- 分组选择：`( X | Y )`。
- 终结符：引号内逐字给出，如 `"fun"`、`"+"`、`"∀"`。
- 非终结符以【中文名】书写，括注对应的 Parser.kt 函数或 Lexer.kt 方法，便于回溯（完整映射见附录 B）。
- 产生式编号：`L-n` 词法、`D-n` 消歧、`G-n` 语法、`S-n` 脱糖。
- **重要**：Sublimation 自身把 `{ } [ ] < > ( ) , ;` 全部用作终结符，因此本文**不**使用花括号/方括号作 EBNF 元符号，重复一律用后缀 `* + ?`。
- 「列表尾随逗号」：本文所有逗号分隔列表均容忍尾随逗号（实现里以「逗号后遇到右括符即终止」的统一惯用法处理），不再逐条标注。
- 「空格」在本文是**词法事实**而非排版建议：每个 token 携带邻接属性 `precededBySpace`（L-7），多个消歧规则依赖它——这是本语言文法不是纯上下文无关文法的原因（见 §3 前言）。

## 2. 词法文法（L 层）

扫描器：`Lexer.kt` 的 `tokenize()`，单遍自左向右、最长匹配。源文件是一段 Unicode 文本；token 流以 `EOF` 终结。

### 2.1 无关字符（trivia）

```ebnf
【trivia】     ::= 【空白】 | 【BOM】 | 【行注释】
【空白】       ::= " " | "\t" | "\r" | "\n"
【BOM】        ::= "\uFEFF"
【行注释】     ::= "//" （除 "\n" 外任意字符）* "\n"?
```

- trivia 在 token 之间出现，**不产生 token**，但其存在与否被记录进邻接属性（L-7）。
- **只有行注释**：`/* … */` 块注释**不受支持**，`/` 按除法运算符 lex。

### 2.2 标识符

```ebnf
【标识符】     ::= 【标识符首】【标识符续】*                →  IDENT
【标识符首】   ::= "_" | Unicode 字母（isLetter）
【标识符续】   ::= Unicode 字母 | Unicode 数字 | "_"
【反引号名】   ::= "`" （除 "`" 与换行外任意字符）* "`"      →  IDENT（不查关键字表）
【符号名】     ::= 【符号首】+                             →  SYMBOL
【符号首】     ::= c ∈ Unicode 且 c.code > 127 且 ¬c.isWhitespace 且 ¬c.isLetterOrDigit
                 且 c ∉ 【逻辑单例】 且 c ∉ { "∵", "∴" }
【逻辑单例】   ::= { "∀", "∃", "∧", "∨", "¬", "→", "↔", "⊤", "⊥" }
```

要点：

1. **标识符支持 Unicode**：英文、中文、希腊字母等均可（`中文_α` 合法）；首字符允许 `_`。
2. **反引号名**（Kotlin 风）：内容可为任意字符（含空格、运算符），禁止跨行；`` `when` `` 是普通标识符而非关键字。定理库用它写带空格的定理名（`` `law of excluded middle` ``）。
3. **符号名**：非 ASCII 数学符号的最大匹配串（如 `○`、`⊗`），可作函数名/名字位（`fun ○(a, b)`）。
4. **`∵` 与 `∴` 被显式排除**在符号名之外：它们是固定单 token（L-5）。
5. **实测发现（重要）**：`∈`（U+2208）、`≥`/`≤`（U+2265/2264）、`≠`（U+2260）**不在**【逻辑单例】中，因此落入【符号名】通道，lex 为 **SYMBOL**（运算符文本保留原字形），而非 IN/GE/LE/NEQ。**P51 已删除 `∈ -> IN`、`≥ -> GE`、`≤ -> LE` 三条单字符死分支**（`≠ -> NEQ` 保留无害、同为死代码）。它们经 D-6「带空格 SYMBOL 中缀」路径进入表达式；ASCII/Unicode 等价归一发生在命题层（`Prop.kt`：`∈` 归一 `in`；`<=`↔`≤`、`>=`↔`≥`、`!=`↔`≠` 等价判定）。

### 2.3 关键字

```ebnf
【硬关键字】   ::= "fun" | "class" | "struct" | "enum" | "var" | "impl" | "for" | "if"
                 | "else" | "unchecked" | "when" | "is" | "by" | "type" | "return" | "def"
```

- 共 **16 个**。【标识符】读出后查表折算为关键字 token，**不可**再作普通标识符（需反引号转义）。
- **`in` 已去关键字化（P51）**：普通 IDENT——可作函数名（`fun in(...)`）、命题名（`def in<a,b>`）、参数名；其中缀位 `a in b` 由 Parser 按文本识别为内建区间运算符（`BinExpr("in")`，非用户函数调用）。`for` 保留为关键字但**仅服务于 `impl T for U` 声明**（无循环语法——迭代一律走 `forEach`）。
- `forall` / `exists` / `exists1` **不是**关键字：普通 IDENT，仅当后继 token 是 IDENT 时在表达式层解析为量词别名并归一为 `∀`/`∃`/`∃!`（G-39、S-4）。
- `as`、`not`、`Task`、`Flow`、`in` 同为普通标识，其特殊语义仅在特定语法位置生效（D-3/D-9、G-32、D-in）。

### 2.4 字面量

```ebnf
【整数字面量】 ::= 数字+                                →  INT
【浮点字面量】 ::= 数字+ "." 数字+                      →  FLOAT
【字符串字面量】::= "'" （【串字符】 | 【转义】）* "'"    →  STR
【串字符】     ::= 除 "'" 与 "\" 外任意字符（含换行）
【转义】       ::= "\" ( "n" | "t" | "r" | "'" | "\" | <任意字符> )
```

- **浮点判定**：`1.0` 是 FLOAT；`1.` / `1.x` 是 INT 紧跟 DOT（点号后必须紧跟数字才粘连）。
- **字符串可跨行**：扫描器不禁止串内换行（仅未闭合时报「字符串未闭合」）。
- **未归一转义**：`\` 后非 `n t r " \` 时原样保留该字符。
- **字符串插值**不在词法层：STR token 保留原文，Parser 对 `$名字` / `"${表达式}"` 做解析期脱糖（S-7）；`\$` 在词法层已还原为字面 `$`。

### 2.5 运算符与标点

多字符运算符按**如下固定顺序**最长匹配（`readToken()` 在数字/字符串/反引号/标识符/符号名分派之后逐条尝试，顺序不可调换）：

```ebnf
【多字符运算符】 ::= "<->" → IFF | "=>" → DARROW | "==" → EQ | "!=" → NEQ
                 | "<=" → LE | ">=" → GE | "->" → ARROW（**修正案后非法**：程序位用双箭头 `=>`、命题位用单箭头 `→`，ARROW 仅词法保留供诊断定位） | "∃!" → EXISTS1
                 | "+∵" → PLUS_BECAUSE
                 | ".." → RANGE | "::" → COLON2
                 | "&&" → LAND（文本 "∧"） | "||" → LOR（文本 "∨"）
```

单字符分派（多字符全部不匹配时）：

```ebnf
【单字符】 ::= "(" | ")" | "[" | "]" | "{" | "}" | "," | ";" | ":" | "." | "@"
             | "\" | "$" | "#" | "+" | "-" | "*" | "/" | "%" | "^" | "="
             | "<" | ">" | "&" | "|" | "!"
             | "∀" | "∃" | "∧" | "∨" | "¬" | "→" | "↔" | "⊤" | "⊥" | "∵" | "∴"
             /* "∈" → IN、"≥" → GE、"≤" → LE、"≠" → NEQ：死代码，见 2.2 要点 5 */
```

要点：

1. **`&&` / `||` 归一**为 `∧` / `∨`（文本即 Unicode 形），命题、运算、codegen 全链路同信道。
2. **`$n` 粘连**：`$` 紧贴数字时作为一个 DOLLAR token，文本含 `$`（`$0`、`$1`）；单独 `$` 是返回值符号（G-33）。
3. **`\`（BACKSLASH）已退役**：v1.1 前 `\(x) =>` lambda 使用，现不接受于任何产生式，token 保留仅为诊断。
4. **`?` 不在字符集内**：空安全语法（`?` `?.` `?:` `>:` 转换、`as` 关键字）已整体移除，裸 `?` 是词法错误（「这个字符 '?' 语言不认识」）。
5. **全角标点**（`（）【】＜＞＝，；：＂＇！＆｜`）触发带提示的词法错误（「请换成英文半角符号」）。

### 2.6 邻接属性（词法的核心事实，L-7）

```ebnf
token ::= ( kind, text, line, col, precededBySpace )
```

每个 token 记录：**在其之前是否跳过 trivia**（空白/注释/BOM）。这是纯词法事实，不参语法；所有 `<` `>` `.` 中缀消歧只读它（§3）。

## 3. 消歧规则（D 层）

由于邻接属性参与分派，本文法严格说是**上下文敏感文法**；但敏感点被收敛为下列有限规则：词法层只记录事实，消歧全部在语法层。

| # | 规则 |
|---|---|
| D-1 | **紧贴名字的 `<` = 实例化**（命题项 `p<v>`、显式供给 `witness<torch>()`），由后缀循环消化；**带空格的 `<` = 比较中缀** `a < b`。 |
| D-2 | **angle 上下文中的 `>` 是尖括号终止符**，除非同时满足：前有空格 ∧ 后一 token 可起表达式（INT/FLOAT/STR/DOLLAR/IDENT/SYMBOL/LPAREN/MINUS/BANG/LNOT/LT）。邻接的 `>>`（`valid<7>>`）因内层 `>` 的后继仍是 `>` 而正确终止。 |
| D-3 | （已移除）`a >: T` 安全转换与 `a as T` 关键字已删除：表达式位 `>` 后紧跟 `:` 不再合成转换，`as` 回归普通标识符（按 D-5 中缀糖解析为 `as(a, T)` 调用，语义层报未定义）。 |
| D-4 | **`is` 仅同行作中缀类型测** `a is T`；与左操作数不同行的 `is` 视作 when 下一分支的模式起始；`is Ident(` 形态恒为构造子解构模式——**if 条件位（ifIsCond 标志）例外**：此时 `a is Ctor(模式)` 解析为 ifis 智能解构哨兵 IsPatExpr（S-11）。 |
| D-5 | **标识符中缀** `a f b`：`f` 前后均须空格、与左右操作数同行、右操作数为合法表达式起始（排除 `->` `,` `}` `]` `;` `)` `=` `return`）；展开为 `f(a, b)`（S-1）。 |
| D-6 | **带空格 SYMBOL 中缀** `q ○ p`：左结合、无优先级、运算符文本即符号原文。`∈`/`≥`/`≤`/`≠` 走此通道。 |
| D-7 | （已移除）`?.` 安全调用已删除：词法层不再产出 SAFECALL token，`?.` 序列首字符 `?` 即词法错误。 |
| D-8 | **`.` 字段访问**：点前无空格（`a.b`），或点位于行首（换行链 `\n .map`）；**同行带空格的点是 ∃ 语句的分隔符**（`∃ x = t . P`）。 |
| D-9 | （已移除）`T?` 可空类型后缀已删除：类型位不再接受 `?` 后缀（S-2 同步移除），可空值一律显式写 `Optional[T]`。 |
| D-10 | **尾随 lambda**：`{` 前是可调用结果（且不是字面量/运算结果）且大括号满足 lambda 诗据（D-18）时，追加为最后一个位置实参；`Task { … }` / `Flow { … }` 例外——体是代码块。 |
| D-11 | **算术无优先级、全左结合**：`1 + 1 * 1` 解析为 `(1+1)*1`；右侧算子优先级高于左侧已存算子时产生**提示级**诊断（建议加括号），不报错。 |
| D-12 | **函数体两形态互斥**：`= 表达式` 或 `{ 语句… }`；`= {` 混写直接报语法错并给出改写指引。 |
| D-13 | **顶层只允许声明**（决策 74）：执行代码必须进 `fun main()`；脚本模式（scriptMode）放宽为允许语句，属内部/实验通道。 |
| D-14 | **方括号 = 命题层、圆括号 = 值层**：`if[p]` / `when[p]` 是命题语句（排中律/分类讨论），`if(p)` / `when(p)` 是值表达式。判据仅为 IF/WHEN 后一 token 是 LBRACKET 还是 LPAREN。 |
| D-15 | **约束表前瞻**：函数头 `<` 内首项为 IDENT 且其后是**带空格的** `<=`/`>=`/`==`/`!=`/`in` 时判为约束表 `<score <= 100>`（仅登记不校验）；否则为上文命题表。`<`/`>` 被前瞻排除，避免与命题式冲突。 |
| D-16 | **命名字段构造前瞻**：大写名 + `(` + `IDENT =` 三元前瞻判为 `A(name = e)`；`()` 空括号不判（留给 `None()` 零参构造）。 |
| D-17 | **模板 when**：`when(t in _)` 主题为 `in _` 时脱糖为无主题 when，各分支模式 `p` 变为条件 `t in p`（S-8）。 |
| D-18 | **lambda 诗据**：大括号深度 1 内首个 `=>` 之前只允许名字与逗号（可为空 = 零参 `{ => 7 }`）则为 lambda；深度 1 内**无**箭头且无冒号则为隐式单参体（`_` 引用形参，Kotlin `{ it }` 同款）。混入任何其他 token（如数字 `{ 1 => x }`）即非 lambda。 |
| D-19 | **`E::A` 折叠**：`::` 左侧为大写 NameRef 时折叠为构造子复合名 `E::A`；左侧为其他表达式时是**方法引用**（FunRefExpr，不加括号传递函数值）。 |
| D-20 | **`return` 裸形判定**：下一 token 为 `}` / `;` / EOF 时为裸返回；`return` 紧贴 `@标签` 时为标签返回（lambda 内返回调用标签）。 |

## 4. 语法文法（G 层）

解析器：`Parser.kt`，手写递归下降。入口 `parseFile()`（普通模式）与 `parseScriptSource()`（脚本模式，允许顶层语句）。

### 4.1 编译单元与入口

```ebnf
G-1  【编译单元】     ::= 【顶层条目】* EOF
G-2  【顶层条目】     ::= 【声明】 | 【语句】            /* 语句仅脚本模式；普通模式顶层语句报错 */
G-3  【顶层注解条目】 ::= 【注解】 ( 【函数声明】
                                  | 注解含 "mut" 时: (【结构体声明】 | 【类型类声明】)
                                  | 脚本模式时: 【语句】 )
```

- **顶层禁语句**（决策 74）：非脚本模式下任何非声明起始的 token 直接报「顶层只能写声明」。
- **无 trait 的 impl 在 parseFile 层脱糖**：成员展开为「以 `self` 为首形参、self 类型中的 kind 占位提升为类型参数注」的自由函数（S-6），承担同作用域重载职责。

### 4.2 名字位

```ebnf
G-4  【名字】     ::= IDENT | SYMBOL | "+" | "-" | "*" | "/" | "%" | "="
                     | "≠" | "≤" | "≥" | "&" | "|" | "<->" | "<" | ">"
G-4a 【命题名】   ::= G-4 的名字位 ∪ "==" | "!=" | "in"    /* def 备选名；排除 STR/INT/括号/EOF */
```

即：运算符可作函数名（仿 Scala，`fun +(a, b)`；`fun `refl`[a]: Null <a = a>` 用反引号名）。**一元负号 MINUS 不在可前缀调用名集合**（一元负优先）。

### 4.3 声明

```ebnf
G-5  【声明】     ::= 【函数声明】 | 【类型类声明】 | 【结构体声明】 | 【枚举声明】
                     | 【实现声明】 | 【类型别名】 | 【命题定义】
G-6  【注解】     ::= ("@" IDENT)*

G-7  【函数声明】 ::= 【注解】 "fun" 【名字】 【理论参数】? 【形参表】? 【头部上下文】? 【返回区】? 【函数体】?
      【头部上下文】 ::= "<" ( 【约束表】 | 【角表】 ) ">"
      【约束表】     ::= 【约束项】 ( "," 【约束项】 )* ","?      /* 形如 <score <= 100>；仅登记不校验 */
      【约束项】     ::= 【名字】 ( "<=" | ">=" | "==" | "!=" | "in" ) 【表达式】
      【返回区】     ::= ":" ( 【角表】 | 【类型】 【角表】? )    /* ": <q>" = 无返回类型的后置上下文 */
      【函数体】     ::= "=" 【表达式】 | 【块】                /* 二者互斥（D-12）；签名/定理可无体 */

G-8  【理论参数】 ::= "[" ( 【命题参数】 | 【类型参数】 ) ("," …)* ","? "]"
      【命题参数】   ::= "@" 【名字】                           /* [@P] 命题元变量 */
      【类型参数】   ::= 【名字】 ("[" "_" ("," "_")* ","? "]")? (":" 【名字】)?
                      /* [T] / [T: Show] / [F[_]] arity=1 / [F[_, _]] arity=2 / [F[_]: Foldable] */
      【形参表】     ::= "(" (【形参】 ("," 【形参】)* ","?)? ")"
      【形参】       ::= 【注解】 【解构形参】? 【名字】 ":" 【类型】 ("=" 【表达式】)?
                       /* 默认值仅 struct 字段允许；@list 形参 = 变长实参 */
      【解构形参】   ::= "(" 【名字】 ("," 【名字】)* ","? ")"   /* fun f((a, b): Point) */

G-9  【类型类声明】 ::= 【注解】 "class" 【名字】 【理论参数】?
```

## 6. 已知限制与失效产生式

如实记录当前实现中「定义了但不能正常用」或「实现与文档不一致」的语法点。

### 6.1 `when[p]`（分类讨论语句，G-21）实际不可解析

`root doc/手动证明.md` 给出形如 `when[p ∨ q] { p => {…} q => {…} }` 的用法，Parser 亦实现了 `parseWhenProp()`，checker/interpreter/codegen 均登记了 `WhenPropStmt`——**但该产生式当前无人能写出来**：

- 分支条件用 `parseExpr(angle = false)` 解析（无 stopArrow），`=>` 前的条件若含 `→` 中缀会被一路消费，后随 `{…}` 被 lambda 诗据（D-18）吞为右操作数；
- 随后 `parseBlock()` 要求下一 token 是 `{`，而实际是下一分支的条件 → 报「期望 LBRACE」；
- 单分支、字面量条件、花括号包裹条件等变体均经实测**全部失败**；`compiler/src/test` 内无任何 `when[` 形态的测试。

结论：**WhenPropStmt 是语法上的死产生式**（v3.0）。临时替代：`if[p] { … } else { … }`（排中律，G-20，已验证可用）。

### 6.2 `∈`/`≥`/`≤`/`≠` 的词法归属

见 §2.2 要点 5：它们 lex 为 SYMBOL，Lexer 单字符 map 的 IN/GE/LE/NEQ 分支为死代码；运算符保原文进入 `BinExpr`，等价归一发生在 checker 命题层（`Prop.kt`：`∈` 归一 `in`，ASCII/Unicode 等价判定）。**书写注意**：SYMBOL 中缀（D-6）要求符号**前**有空格，故 `a ≥ b`（带空格）合法、`a≥b`（紧贴）解析失败；而 ASCII 形 `a>=b` 紧贴可用（`>=` 是独立 GE token，binops 通道不检查空格）。**建议源码一律带空格书写 Unicode 比较符**（与 wiki 样式规范一致）。

### 6.3 约束表仅登记

`fun f<score <= 100>`（G-7 约束表、D-15）解析并登记进 `FunDecl.constraints`，但 **V1 不做语义校验**（依赖类型方向的占位）。

### 6.4 其它

- **类型别名右值**仅具名/应用类型（`type Pair[T] = Optional[T]`）；函数类型/元组右值不支持。
- **空安全语法已整体移除**：`T?` 后缀、`?.` 安全调用、`?:` 空替代、`a >: T` / `a as T` 安全转换、`Some(x)` → `T` 隐式解包均不再存在；类型测统一用 `a is T`，可空值一律显式 `Optional[T]` + `when` 解构。
- **块注释**不存在；**字符串可跨行**（词法不挡，但样式规范不建议）。
- **算术无优先级**：`1 + 1 * 1 = (1+1)*1`（D-11），仅提示加括号。
- **`return@label`** 的标签须紧贴 `return`（无空格），标签为 lambda 调用名。
- **全角标点**一律词法错误并提示改半角。

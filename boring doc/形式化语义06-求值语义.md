## 1. 判断系统的定位

本卷给出语言**运行时**的形式化语义：一个树遍历解释器（`Evaluator`，Evaluator.kt:8）对已通过 `Checker` 静态检查的 AST 做大步求值（big-step evaluation）。判断式形如

$$\frac{前提}{结论} \quad (\text{E-…})$$

即 `E ⊢ e ⇓ v`：$E$ 是帧链（环境，§3），$e$ 是 AST 表达式，$v$ 是值域 $\mathbb{V}$（§2）中的值。求值**不重复做类型系统**——类型、可变性、纯度、命题义务全部是编译期概念，在求值期或者退化为 `ScriptValue.Null`，或者以 `InterpreterError` 显式拒绝（§4.11）。

求值的三个出口：

$$E ⊢ e ⇓ v \qquad E ⊢ e ⇓ \bot \qquad E ⊢ e ⇓ \texttt{return}\ v$$

- $v$：正常值；
- $\bot$：`InterpreterError`（§8.1），沿 Kotlin 调用栈抛出；
- $\texttt{return}\ v$：`ReturnException`（Evaluator.kt:979），由最近的函数体边界拦截（§8.2）。

设计基线（ScriptValue.kt:6）：**值跨边界一律引用语义（非拷贝）**——脚本改宿主对象即改宿主对象本身；深拷贝只发生在 §5/§6 规定的显式路径。

## 2. 值域：ScriptValue 模型

### 2.1 值构造子

值域由 sealed 类 `ScriptValue`（ScriptValue.kt:19）给出，共 9 个构造子：

$$v ::= \textsf{Num}(n) \mid \textsf{Real}(r) \mid \textsf{Str}(s) \mid \textsf{Bool}(b) \mid \textsf{Null} \mid \textsf{ListV}(\vec{v}) \mid \textsf{Struct}(T, f, m) \mid \textsf{OptionalV}(v?) \mid \textsf{ResultV}(b, v?, e?) \mid \textsf{Fun}(\phi)$$

| 构造子 | 载荷 | 源码 | 说明 |
|---|---|---|---|
| `Num` | `Long` | ScriptValue.kt:22 | Nat/Int 整数 |
| `Real` | `Double` | ScriptValue.kt:27 | Rat 浮点 |
| `Str` | `String` | ScriptValue.kt:31 | 字符串 |
| `Bool` | `Boolean` | ScriptValue.kt:35 | 布尔 |
| `Null` | 单例对象 | ScriptValue.kt:39 | Null 类型唯一成员 |
| `ListV` | `MutableList<ScriptValue>` | ScriptValue.kt:44 | List **与元组**的运行时载体（§2.2） |
| `Struct` | typeName / 字段表 / 可变字段集 | ScriptValue.kt:51 | 结构体、enum 构造子、宿主注入类型、Range、Set/Map 链 |
| `OptionalV` | `ScriptValue?`（null ⇒ None） | ScriptValue.kt:61 | Optional |
| `ResultV` | isOk / value / error | ScriptValue.kt:66 | Result[T,E] |
| `Fun` | `ScriptFunction` | ScriptValue.kt:71 | 宿主函数与脚本闭包的统一接口 |

函数值接口 `ScriptFunction`（ScriptFunction.kt:10）擦除地携带 `typeParams`/`preps`/`posts`/`paramTypes`/`retType` 与 `call(args: List<Any?>)`——即**泛型与上下文（前后件）在运行时全部擦除为字符串属性**，宿主无需理解（ScriptFunction.kt:7-9、26-27）。

### 2.2 类型→值映射

映射表（ScriptValue.kt:8-17 注释 + Interpreter.kt:383-407 宿主转换）：

| 类型 | 值 | 宿主（Kotlin）态 |
|---|---|---|
| Nat / Int | `Num` | `Long` |
| Rat | `Real` | `Double` |
| Str | `Str` | `String` |
| Bool | `Bool` | `Boolean` |
| Null | `Null` | `null` |
| List[T] / 元组 | `ListV` | `List<*>` |
| Optional[T] | `OptionalV` | 宿主边界解包为内值或 `null` |
| Result[T,E] | `ResultV` | 保留 `ScriptValue` 身份 |
| 结构体/宿主类型 | `Struct` | 保留 `ScriptValue` 身份 |
| 函数 | `Fun` | `ScriptFunction` |

两点实现决策必须显式记录：

1. **元组无独立构造子**。`TupleExpr` 求值为 `ListV`（Evaluator.kt:240）；元组解构参数 `(a, b)` 在 lambda 绑定时按编码名 `"(a,b)"` 拆 `ListV` 分量（Evaluator.kt:820-831）。命题层另有 `emptyTuple`/`singleTuple` 内建（Types.kt:146-150），脚本运行时无此注册 **待核**。
2. **Struct 保留身份跨界**。`toHost` 对 `Struct`/`ResultV` 原样返回（Evaluator.kt:951-953，注释明言“否则跨函数值参数往返后 typeName 丢失，字典分派错位”）；而 `OptionalV` 在宿主边界被解包（Evaluator.kt:952）。

`fromHost`（Evaluator.kt:957-975）做反向映射：已有 `ScriptValue` 原样穿过，`ScriptFunction` 包 `Fun`，`Map<*,*>` 造 `Struct("Map", …)`，其余基本类型按表升格，兜底 `v.toString()` 成 `Str`（注意：`Int`→`Num`、`Float`→`Real`，而未知类型**不报错**而是降级为字符串，属宽松边界）。

### 2.3 值的相等性

`==`/`!=` 求值到 `structEquals`（Evaluator.kt:402-425）：

$$\frac{E ⊢ l ⇓ v_1 \qquad E ⊢ r ⇓ v_2 \qquad v_1 \doteq v_2}{E ⊢ l == r ⇓ \textsf{Bool}(\top)} \quad (\text{E-EQ})$$

其中 $\doteq$ 为结构相等，逐层定义：

- 数值：`Num`/`Real` **升格比较**（`1 == 1.0` 为真，Evaluator.kt:405-406）；
- `Str`/`Bool`：按值；
- `Null`：同一单例（Evaluator.kt:409，用 `===`）；
- `ListV`：长度相等且逐元素递归（Evaluator.kt:410-411）；
- `Struct`：typeName 相同、字段键集相同、逐字段递归（Evaluator.kt:412-414）；
- `OptionalV`/`ResultV`：`optEquals` 递归，Result 另要求 isOk 一致（Evaluator.kt:415-417）；
- 兜底：Kotlin `==`，`Fun` 因此**按引用身份**比较（Evaluator.kt:418；ScriptValue.kt:72-73 重写 equals 为身份比较）。

陷阱：`SymbolCallExpr` 的 `==(…)`（符号前缀调用 `==(a,b)`，Evaluator.kt:680）走的是 Kotlin `==` 而非 `structEquals`——中缀 `a == b` 与前缀 `==(a, b)` 语义不一致 **待核**。

### 2.4 引用语义

`ListV`、`Struct`、`Fun` 是可变/对象型值；变量绑定存的是引用。除 §5/§6 的显式拷贝路径外，赋值与参数传递**永不复制**：结构体的 `mutableFields` 是**类型元数据**，深拷贝时只复制值字段、元数据只读共享（Evaluator.kt:149-150，注释标为判定 P3）。

$$\frac{E ⊢ e ⇓ \textsf{Struct}(T,f,m)}{E ⊢ \texttt{var } x = e ⇓ \textsf{Struct}(T,f,m)} \quad (\text{E-Share})$$

## 3. 环境模型：ScriptFrame

环境 $E$ 是帧链（ScriptFrame.kt:7），每帧四张表：

$$E ::= E_0 \mid E \cdot \langle \textit{vars}, \textit{muts}, \textit{refs}, \textit{funs} \rangle$$

判断式：

$$\frac{x \in \textit{vars}(E) \qquad \textit{vars}(E)(x)=v}{E ⊢ x ↦ v} \quad (\text{E-LookupLocal, :14}) \qquad \frac{x \notin \textit{vars}(E) \qquad E' ⊢ x ↦ v}{E \cdot E' ⊢ x ↦ v} \quad (\text{E-LookupParent})$$

实现要点（ScriptFrame.kt）：

- `lookupVar`（:14）沿父链查找；`hasVar`（:16）同法。
- `declareVar(name, value, mutable, ref)`（:18-22）在**本帧**声明并登记 `muts`（:11）/`refs`（:12）两个集合——可变性/引用性是**变量名上的运行时标记**，不在值内。
- `assignVar`（:24-29）先在本帧找键；否则**递归委托父帧**（改写定义帧的槽位，而非在本帧遮蔽）。
- `isMutable`（:31）/`isRef`（:32）沿父链查询标记——bindCopy 的目标侧判据（§6）由此而来。
- `lookupFunctions`（:39-47）合并本帧与父帧同名重载组，`distinctBy(signatureKey)`（:49-50，形参类型 render 拼接）去重。
- `localNames`（:54）/`localFunctions`（:57）只列本帧直接声明者——闭包捕获快照（§5.2）沿父链收集由调用方完成。
- `child()`（:59）造子帧。

帧层次在求值中出现于五处：块体（Evaluator.kt:689）、函数体（:586）、impl 方法体（:615）、when 作用域与各分支（:705/:713）、lambda 调用（:847）。

## 4. 大步求值规则

### 4.1 字面量与名字

$$\frac{n \in \mathbb{Z},\ \textsf{合法}}{E ⊢ n ⇓ \textsf{Num}(n)} \quad (\text{E-Int, :201-205}) \qquad \frac{}{E ⊢ r ⇓ \textsf{Real}(r)} \quad (\text{E-Real, :206}) \qquad \frac{}{E ⊢ s ⇓ \textsf{Str}(s)} \quad (\text{E-Str, :207})$$

`IntLit` 经 `toLongOrNull` 解析，失败抛 `InterpreterError("非法整数")`（Evaluator.kt:202-204）。

$$\frac{E ⊢ x ↦ v}{E ⊢ x ⇓ v} \quad (\text{E-Var, :208}) \qquad \frac{x \notin \mathrm{dom}(E) \qquad \Gamma(x) \neq \varnothing}{E ⊢ x ⇓ \textsf{Fun}(\textit{重载组})} \quad (\text{E-FunRef, :214})$$

名字查找分派（Evaluator.kt:208-216）：帧内变量 → 字面量 `true`/`false`/`null` → `None` → `Nil` → 同名函数声明组（包成函数值，Evaluator.kt:899-914：单数直接包装，重载组造成按实参 tag 分派的“重载调度函数值”）→ 否则 `InterpreterError("未定义的变量")`。

### 4.2 表达式位的 var（VarExpr）

$$\frac{E ⊢ e ⇓ v \qquad v' = \textit{bindCopy}(v, \textit{ref}, \textit{ref}_s, \textit{ref}, \textit{mut}_s)}{E ⊢ \texttt{var } x = e ⇓ v' \mid E[x ↦ v']} \quad (\text{E-VarExpr, :242-249})$$

`VarExpr`（解析自表达式位 `var`，Parser.kt:1342-1343）求值为初值本身并在帧内声明，支持 `var n = var m = 0` 嵌套（Parser.kt:827 注释）；支持元组解构声明 `var (a, b) = e`（Parser.kt:816-825），但求值期只绑定首分量 **待核**（见 §11）。

**待核**：该位第 4 位置传的是 `ref` 而非 `mutable`（Evaluator.kt:246：`bindCopy(v, ref, …, ref, …)`），与语句位 `VarStmt` 传 `mutable`（:166）不一致——`@mut var x = e` 在表达式位的目标 @mut 维度可能错位。

### 4.3 运算符

$$\frac{E ⊢ l ⇓ v_1 \qquad E ⊢ r ⇓ v_2 \qquad \textit{op} \in \{+,-,*,\%}}{E ⊢ l\ \textit{op}\ r ⇓ \textit{arith}(v_1,v_2,\textit{op})} \quad (\text{E-Arith, :282-285})$$

`arith`（Evaluator.kt:311-316）：两侧一律转 Double 计算，**若任一侧是 Real 则结果 Real，否则截断回 Num（Long）**。`/` 固定产生 Real（:284，JS double 语义）。`+` 特判：任一侧为 Str 则做字符串拼接 `strOf(l)+strOf(r)`（:281）；`strOf`（:331-338）对 Num/Real/Bool 取字面、Null 取 `"null"`、其余取 `toString()`。

$$\frac{v_1 \doteq v_2}{E ⊢ l == r ⇓ \textsf{Bool}(v_1 \doteq v_2)} \quad (\text{E-Eq, :287}) \qquad \frac{}{E ⊢ l \neq r ⇓ \textsf{Bool}(\neg(v_1 \doteq v_2))} \quad (\text{E-Neq, :288})$$

比较 `< <= > >=` 走 `cmp`（:289-296/:340-343）：数值化后 Double 比较。`& ∧`/`| ∨` 走 `truthy`（:297-298/:395-399）：Bool 取值、Null 为假、**其余一切为真**（结构与函数均为真）。

$$\frac{E ⊢ l ⇓ n \qquad E ⊢ r ⇓ m \qquad n,m \text{ 为整数}}{E ⊢ n\ ..\ m ⇓ \textsf{Struct}(\text{"Range"},\{\textit{lo},\textit{hi}\})} \quad (\text{E-Range, :302-306})$$

区间求值为惰性 Range 结构（Evaluator.kt:357-362，v3.0 特性 3：闭区间，不预生成列表）。`∈`/`in`（:301/:345-354）左操作数需为数字，右操作数为 `ListV`（任意元素数值相等）或 Range 结构（闭区间成员）。

**运行时拒绝的编译期算子**（Evaluator.kt:286/299/300）：

$$\frac{}{E ⊢ l = r ⇓ \bot(\text{"命题等式 '=' 是编译期概念"})} \qquad \frac{}{E ⊢ l → r ⇓ \bot} \qquad \frac{}{E ⊢ l ↔ r ⇓ \bot}$$

一元（Evaluator.kt:427-437）：`-` 取负（Real 保持 Real，其余截断 Num），`!`/`¬` 取 `truthy` 的否定。

### 4.4 lambda 与函数值

$$\frac{}{E ⊢ \{\vec{p} ⇒ e\} ⇓ \textsf{Fun}(\langle \vec{p}, e, E \rangle)} \quad (\text{E-Lambda, :838-854})$$

`evalLambda` 产出闭包型函数值：捕获**定义点帧** $E$。调用判断式：

$$\frac{E_c \cdot E[\vec{p} ↦ \vec{v}\ ] ⊢ e ⇓ v}{E ⊢ (\{\vec{p} ⇒ e\})(\vec{v}) ⇓ v} \quad (\text{E-LambdaCall, :846-851})$$

注意三点：

1. **捕获按引用**：调用时 `ScriptFrame(frame)`（:847）挂在定义帧上，闭包内读到的是**当下**的外层变量值——求值器没有“创建时快照”语义；快照只由 §5.2 的深拷路径触发。
2. `ClosureFun`（:834-836）：闭包型函数值都实现 `copyCapture(): ScriptValue.Fun`，这是深拷贝穿透函数的统一接口。
3. 形参绑定不经 bindCopy（:847-849）；解构参数 `(a,b)` 由 `bindLambdaParams`（:820-831）拆 `ListV` 分量，缺位补 `Null`。

同族规则：

$$\frac{}{E ⊢ \textit{fun}_{\textsf{anon}} ⇓ \textsf{Fun}(\langle \cdot, e, E \rangle)} \quad (\text{E-AnonFun, :856-872}) \qquad \frac{\Gamma(f)=\{f_1\}}{E ⊢ f ⇓ \textsf{Fun}(\textit{wrap}(f_1, E))} \quad (\text{E-FunDeclAsValue, :875-896})$$

`funDeclAsValue`（:875-896）对 `@host` 函数委托宿主表（:883-887），其余按定义帧造子帧求值体；重载组（:899-914）调用时 `pickOverload` 按首参运行时 tag 分派。

方法路径作值（`o.f` 不加括号，:537-558）与 `o::f`（FunRefExpr，:251-267）都产出**绑定 receiver 的闭包**：调用时求 `f(o, …args)`；`ReturnException` 在此被拦截并转成返回值（:263/:554）。

### 4.5 调用

调用分派是本卷最重的规则。三种 callee 形态（Evaluator.kt:440-505）：

**(a) 点号 callee（`o.m(args)`）**——字段优先 + 方法糖回退：

$$\frac{E ⊢ o ⇓ \textsf{Struct}(T,f,\cdot) \qquad m \in f \qquad f(m) = \textsf{Fun}(\phi)}{E ⊢ o.m(\vec{v}) ⇓ \phi(\vec{v})} \quad (\text{E-FieldCall, :447-452})$$

$$\frac{E ⊢ o ⇓ \textsf{Struct}(\text{"Range"},\cdot,\cdot)}{E ⊢ o.m(\vec{v}) ⇓ \textit{rangeMethod}(m, o, \vec{v})} \quad (\text{E-RangeMethod, :454-456})$$

$$\frac{E ⊢ o ⇓ v \qquad \textit{traitDict}(m, \textit{tag}(v)) = \textit{impl}\ (\text{唯一})}{E ⊢ o.m(\vec{v}) ⇓ \textit{invokeImpl}(\textit{impl}, v, \vec{v})} \quad (\text{E-TraitMethod, :457-459})$$

$$\frac{\text{上述皆不中}}{E ⊢ o.m(\vec{v}) ⇓ m(v, \vec{v})\ (\text{自由函数重载分派})} \quad (\text{E-FreeMethod, :460})$$

**(b) 名字 callee（`f(args)`）**——内建构造子特判在先（:465-481）：

$$\frac{E ⊢ e ⇓ v}{E ⊢ \texttt{Some}(e) ⇓ \textsf{OptionalV}(v)} \quad (\text{E-Some, :466}) \qquad \frac{E ⊢ e ⇓ v}{E ⊢ \texttt{Ok}(e) ⇓ \textsf{ResultV}(\top, v, \cdot)} \quad (\text{E-Ok, :468})$$

同族：`None`→`OptionalV(null)`、`Err(e)`→`ResultV(\bot,…,v)`、`Nil()`→空 `ListV`、`Cons(h,t)`→头部加进尾表（尾须为 `ListV`，否则 ⊥，:479）。缺位实参自动补 `null` 名字引用（:466/:472）。其后：结构体构造（:483-489，位置实参按 `fieldNames` 落位，合并命名实参后转 `evalStructCtor`）→ 变量持有函数值（:491-495）→ 普通函数调用。

**(c) 其余 callee**：`evalExpr` 求值后须为 `Fun`，否则 ⊥（:499-504）。

**`callFunction` 分派序**（Evaluator.kt:507-534）：

$$\textit{resolve}(f, \vec{v}) ::= \begin{cases} \textit{evalIn}(v_1,v_2) & f = \texttt{in},\ |\vec{v}|=2 \\\ \textsf{ListV}(\vec{v}) & f = \texttt{listOf} \\\ \textit{buildSet}(\vec{v}) & f = \texttt{setOf} \\\ \textit{host}(f)(\vec{v}) & f \in \textit{hostFuns} \\\ \textit{invoke}(\textit{pickOverload}(\Gamma(f), \vec{v})) & \Gamma(f) \neq \varnothing \\\ \textit{invokeImpl}(\textit{traitDict}(f, \textit{tag}(v_1)), v_1, \vec{v}') & \text{否则若首参在字典中} \\\ \bot(\text{"未定义的函数"}) & \text{否则} \end{cases}$$

要点：`in` 是**普通函数**（中缀糖 `a in b` 解析为 `in(a,b)`，:508-509）；`listOf`/`setOf` 特判（core 中二者的体是占位，:510-512；`setOf` 打 `SetCons`/`SetNil` 结构链，:573-582）；同名自由函数**优先于**类型类字典（:519-523 先于 :527-531）。

**重载分派** `pickOverload`（:635-639）：单候选直取；多候选按首参运行时 `typeTag`（:642-653：`ListV`→List、`Struct`→`ctorToEnum` 回溯所属 enum（SetCons→Set）、`Num`→Nat、`Real`→Rat、`Fun`→Fun…）匹配首形参类型；不中则取第一个。`paramTypeMatches`（:656-660）对类型变量（不在具体类型名集 `concreteTypeNames` :662-666 内）通配。

**impl 方法执行** `invokeImplMethod`（:614-632）：普通类型类注入 `self` 变量并把结构体字段平铺进子帧（:617-621，impl 方法体内裸字段名解析为 self 字段，形参随后覆盖同名）；**HKT 形态**（`impl Functor for List[a]`，self 带类型实参）不设 self 变量，receiver 注入首形参位、用户实参后移一位（:623）。`lookupTraitMethod`（:600-608）多候选立即报消歧错误（P4）。

**函数体执行**（`invokeFunDecl` :585-596 与上同构）：子帧绑定形参（**不经 bindCopy**）、登记本函数进子帧（供递归）、求值体、`ReturnException` 截获取值。命名实参由 `applyNamedArgs`（:561-570）按形参名落位到位置列表，缺位补 `Null`（H4：不再静默丢弃）。

### 4.6 结构构造与字段访问

$$\frac{\textit{structInfo}(T) = \langle F, M, D \rangle \qquad \theta = \{\textit{eval}(a)\}_{a \in \vec{a}} \qquad \forall f \in F:\ f \in \theta \vee f \in D}{E ⊢ T(\vec{a}) ⇓ \textsf{Struct}(T, \theta \cup \textit{defaults}, M)} \quad (\text{E-StructCtor, :918-933})$$

位置实参按 `fieldNames` 顺序对位（:485-488/:923）；缺字段若无默认值则 ⊥（:929）；默认值表达式在构造时**按帧求值**（:930）。`StructInfo`（:982-992）承载字段类型/可变字段集/字段默认值，来源是脚本声明（`collectLocalDecls` :58-102）或宿主注入（`hostStructs`，:27）。脚本声明的 enum 构造子造同构 `Struct`（字段名 `_0,_1,…`，:76-84），并登记 `ctorToEnum`（:17）供重载分派回溯。

$$\frac{E ⊢ o ⇓ \textsf{Struct}(T,f,\cdot) \qquad n \in f}{E ⊢ o.n ⇓ f(n)} \quad (\text{E-Field, :227-232}) \qquad \frac{n \notin f \qquad \textit{methodPath}(n, o) \neq \varnothing}{E ⊢ o.n ⇓ \textsf{Fun}(\textit{绑定}\ o)} \quad (\text{E-MethodPath, :231-233})$$

字段优先、不中则尝试方法路径作值（H6）；对非结构体值只走方法路径，否则 ⊥。

`evalTypeTest`（:936-940）：`a is T` 求值为 `matchType(PatIs(T,null), v)`（§4.8）。

### 4.7 元组与列表

$$\frac{E ⊢ e_1 ⇓ v_1 \qquad \cdots \qquad E ⊢ e_n ⇓ v_n}{E ⊢ (e_1, \dots, e_n) ⇓ \textsf{ListV}(v_1, \dots, v_n)} \quad (\text{E-Tuple, :240})$$

元组与列表共享 `ListV`（§2.2）；`InstExpr`（类型实参化）对目标直接再求值（:241），`ByExpr`（`by [q]`）对其 target 再求值（:250）——证明依据在运行期不可见。

### 4.8 when 与模式匹配

$$\frac{E_w = E \cdot \langle\rangle \qquad E_w[\textit{sb} ↦ \textit{eval}(s)] \qquad \exists a \in \vec{a}:\ E_a = E_w \cdot \langle\rangle,\ \textit{match}(p_a, v, E_a),\ \textit{guard}_a(E_a)}{E ⊢ \texttt{when}(s\ \texttt{as}\ sb)\{\vec{a}\} ⇓ \textit{eval}(b_a, E_a)} \quad (\text{E-WhenMatch, :703-722})$$

实现细节：`whenFrame` 限定主题绑定与分支作用域（:705）；**每分支独立子帧**（:713），模式变量不泄漏到下一分支或外层；无主题 when 的分支必须有 cond（:714-717）；守卫失败则 `continue`（:719-720）；首个命中的分支体求值后立即返回。

$$\frac{\forall a \in \vec{a}:\ \neg\textit{match}(p_a, v, E_a)}{E ⊢ \texttt{when}(s)\{\vec{a}\} ⇓ \textsf{Null}} \quad (\text{E-WhenFall, :723})$$

**不可判穷尽的 when 固定返回 Null，不抛异常**（:723 注释明言这是语言语义决定）——“类型层保证穷尽、运行层宽容”的分层设计。

`matchPattern`（:728-748）诸条：

$$\frac{\textit{eval}(lit) \doteq v}{\textit{match}(lit, v)} \ (\text{P-Lit}) \qquad \frac{x \neq \_}{\textit{match}(x, v) \leadsto E[x ↦ v]} \ (\text{P-Bind}) \qquad \frac{}{\textit{match}(\_, v)} \ (\text{P-Else, :732})$$

$$\frac{p \notin \{\texttt{true,false,null}\} \qquad p\ \text{小写无参}}{\textit{match}(p, v) \leadsto E[p ↦ v]} \quad (\text{P-CtorBind, :735-738})$$

PatCtor 的零参小写名按绑定变量处理（Parser 把绑定变量与零参构造子同形输出，语义层按此规则判定，:734；判据 `isBindName` :751-753）；其余 `matchCtor`（:755-796）逐构造子判定：`true/false/null` 直判；`Some/None/Ok/Err` 判 OptionalV/ResultV 形状后递归单参；`Cons(h,t)` 拆表头与**新造的尾表**（:781，不共享尾部视图）；自定义构造子判 typeName 相同后按**字段表顺序** zip 递归（:786-794，按位置而非按名）。

`matchType`（:797-815）：`Any` 恒真；`Nat/Int`→Num、`Rat`→Real 或 Num、`Str/Bool/Null/List`→对应形态；`Set` 在脚本里也按 `ListV` 判（:807）、`Map` 按 `Struct` 判（:808）；其余按 Struct typeName 相等。绑定变量 `x as T` 在成功时声明（:813）。

### 4.9 块、if、return

$$\frac{E_b = E \cdot \langle\rangle \qquad s_n\ \text{为最后语句}}{E ⊢ \{s_1;\dots;s_n\} ⇓ \textit{eval}(s_n, E_b)} \quad (\text{E-Block, :688-695})$$

空块求值 `Null`；块内 var 声明留在子帧（作用域限块内）。

$$\frac{E ⊢ c ⇓ v \qquad \textit{truthy}(v)}{E ⊢ \texttt{if}\ c\ t\ \texttt{else}\ e ⇓ \textit{eval}(t)} \ (\text{E-IfT}) \qquad \frac{\neg\textit{truthy}(v)}{E ⊢ \texttt{if}\ c\ t\ \texttt{else}\ e ⇓ \textit{eval}(e)} \ (\text{E-IfF, :697-701})$$

无 else 分支返回 `Null`。`if` 条件位的 `a is 模式` 已在 parse 期脱糖为 when（Evaluator.kt:239 哨兵拒绝未脱糖形态）。

$$\frac{E ⊢ e ⇓ v\ (\text{或}\ v = \textsf{Null})}{E ⊢ \texttt{return}\ e ⇓ \texttt{return}\ v} \quad (\text{E-Return, :187-190})$$

`return` 以异常实现（`ReturnException`，:979），拦截点仅在函数体边界（§8.2）。**顶层 `return` 不在任何函数体内，异常泄漏为运行时错误**（§8.1）。

### 4.10 插值解糖的求值

字符串插值在**解析期**脱糖（Parser.kt:1258-1299，决策 84），不引入新 AST 节点：

$$\frac{}{\textit{parse}(\texttt{"}\dots\$\{expr\}\dots\texttt{"}) \leadsto \texttt{concat}(\texttt{"}\dots\texttt{"},\ \texttt{concat}(\texttt{toStr}(\textit{expr}), \dots))} \quad (\text{D-Interp})$$

- `$name`（标识符起始，Parser.kt:1284-1290）与 `${expr}`（子解析器重新 lex，:1279）恒包 `toStr`（已泛型化，Types.kt:166-167）；
- 段间左折叠为 `concat` 链（Parser.kt:1296-1297），单段直接返回 StrLit；
- `${}` 内空串跳过（:1278）；`$` 转义在 lexer 已还原为字面 `$`（Parser.kt:1260）。

因此在求值层没有插值规则——它落回 E-Arith 的 `+` Str 拼接语义与宿主 `concat`/`toStr`（Interpreter.kt:295-305/308-310）。**限制**（Parser.kt:1261）：`${...}` 内不支持可能吃掉 `}` 的文本（内嵌字符串字面量中的 `}` 暂不处理）。

### 4.11 编译期位的求值退化

以下 AST 位在求值期**不执行任何逻辑**，固定返回 `Null`（Evaluator.kt:191-195/:269-272）：

`AxiomStmt`、`ByStmt`、`BTSStmt`（∵∴）、`WhenPropStmt`、`IfPropStmt`、`StrategyStmt`、`ExistIntroStmt`、`ExistsElimStmt`、`FunStmt`（局部函数声明：函数值经名字查找路径产生）、`QuantExpr`（∀/∃）、`TopExpr`/`BotExpr`（⊤/⊥）、`ReturnSym`（`$` 返回值符号）。

$$\frac{}{E ⊢ \textit{命题位} ⇓ \textsf{Null}} \quad (\text{E-PropVoid})$$

即：**命题层在运行时完全透明**——证明义务、上下文、量词都不产生任何运行时观察。这与 §7 的 unchecked 直通一起构成“编译期闸门 / 运行期直通”的统一取舍。

明确抛 ⊥ 的位：`TaskExpr`/`FlowExpr`（“异步特性不在脚本中支持”，:268）、`IsPatExpr`（哨兵，:226/:239）、`ParamRefExpr`（`$n` 不可运行时使用，:272）、以及 §4.3 的编译期算子。

## 5. 深拷贝与闭包捕获

### 5.1 deepCopy

$$\frac{}{\textit{dc}(\textsf{Struct}(T,f,m)) = \textsf{Struct}(T,\ \{k ↦ \textit{dc}(f(k))\},\ m)} \quad (\text{C-Struct, :145-151})$$

$$\frac{}{\textit{dc}(\textsf{ListV}(\vec{v})) = \textsf{ListV}(\textit{dc}(\vec{v}))} \ (\text{C-List, :152}) \qquad \frac{}{\textit{dc}(\textsf{OptionalV}(v?)) = \textsf{OptionalV}(\textit{dc}(v)?)} \ (\text{C-Opt, :153})$$

$$\frac{}{\textit{dc}(\textsf{Fun}(\phi)) = \begin{cases} \phi.\textit{copyCapture}() & \phi \in \textit{ClosureFun} \\\ \phi & \text{否则（宿主函数原样穿过）} \end{cases}} \quad (\text{C-Fun, :156})$$

同族：`ResultV`/:154 递归；`Num/Real/Str/Bool/Null`（`else` 分支，:157）原样返回——它们不可变，拷贝即自身。`mutableFields` 元数据只读共享（:149）。

**关键**：函数值被深拷贝时，解释器对闭包型函数调用 `copyCapture`（:156），把**闭包捕获一并深拷**——这是修正案“函数闭包捕获的变量在 lambda 创建时深拷贝”在求值侧的落地；但注意触发时机是**包含该函数的值被深拷时**（§6 的拷贝判据成立），而非 lambda 创建本身（§10 与 JS 端的差异入口）。

### 5.2 copiedFrame / copyCapture：沿父链的完整快照

$$\frac{E^* = \textit{reverse}(E \cdots E_0)}{\textit{copiedFrame}(E) = \textit{fold}(\varnothing, E^*)} \quad (\text{C-Frame, :130-143})$$

`copiedFrame`（:130-143）沿父链收集**全部**帧（内层 → 外层，`while` :132-133），再**外层优先**地逐名字深拷装入新帧（`asReversed` :135，内层同名覆盖），可变/引用标注按源帧保留（:138）；帧内局部函数一并登记（:140）。

注意 :137 的查找用 `f.lookupVar(n)`（最内层解析变量值）而非 `fr.lookupVar(n)`——即每个名字都按**当前最内层可见值**拷贝，以处理遮蔽；若外层名字被内层遮蔽，外层名字会拿到内层值 **待核**（这是有意的遮蔽语义还是实现疏漏）。

`copyCapture` 的实现（evalLambda :845 / evalAnonFun :863）：

$$\textit{copyCapture}(\langle \vec{p}, e, E \rangle) = \langle \vec{p}, e, \textit{copiedFrame}(E) \rangle$$

即**用快照帧替换定义帧**重新造一个 lambda。此后对原帧的写操作与该函数值绝缘。

可运行的对照示例（.subs 语法）：

```sublimation
var n = 10
var f = { => n }          // 闭包按引用见 n
n = 20
print(f())                // 20
@mut var g = f            // 目标 @mut → bindCopy → deepCopy(Fun) → copyCapture
n = 30
print(g())                // 20（捕获被深拷冻结）
```

### 5.3 拷贝只落在三个绑定点

bindCopy 的**唯一三处调用**：`VarStmt`（:166）、`AssignStmt` 的 NameRef 目标（:174）、表达式位 `VarExpr`（:246）。因此：

- **函数形参绑定不拷贝**（`invokeFunDecl` :587-591 / `invokeImplMethod` :624-627 / `bindLambdaParams` :820-831 都是直接 declareVar）；
- **字段赋值不拷贝**（`AssignStmt` 的 FieldExpr 目标直接 `obj.fields[name] = v`，:177-181，且对非结构体目标抛 ⊥，:180）；
- **结构体构造的字段表达式不拷贝**（`evalStructCtor` 直接 evalExpr 装入，:923-925）。

$$\frac{E ⊢ e ⇓ v \qquad \textit{copy}(v, \dots)}{E ⊢ \texttt{var } x = e ⇓ \textit{dc}(v) \mid E[x ↦ \textit{dc}(v)]} \quad (\text{E-VarCopy}) \qquad \frac{\neg\textit{copy}(v, \dots)}{E ⊢ \texttt{var } x = e ⇓ v \mid E[x ↦ v]} \quad (\text{E-VarShare})$$

## 6. bindCopy：四条规则的求值落地

谓词（Evaluator.kt:112-119，与 `Checker.binderNeedsCopy` 同一判据，修正案四条款；源/目标维度来自 `sourceIsRef` :121-122、`sourceIsMut` :125-126 与目标处的帧标记/语句注解）：

$$\textit{copy} \iff (\textit{tm} \wedge (\neg \textit{tr} \vee \textit{sp})) \vee (\textit{sm} \wedge \textit{tp}) \vee (\textit{sr} \wedge \neg \textit{tr})$$

其中 $\textit{tp/tr/tm}$ = 目标纯 / 不带 ref / 带 mut；$\textit{sp/sr/sm}$ = 源纯 / 带 ref / 带 mut。四条规则逐条对应代码注释（:106-110）：

| 规则 | 条件 | 语义 | 落地示例 |
|---|---|---|---|
| ① | `tm ∧ (¬tr ∨ sp)` | 向 @mut 目标引入须快照 | `@mut T ← T` 深拷；`@ref @mut T ← T` 源纯亦拷 |
| ② | `sm ∧ tp` | 割除可变性须快照 | `T ← @mut T` 深拷 |
| ③ | `sr ∧ ¬tr` | 冻结引用快照 | `T ← @ref T` 深拷 |
| 其余 | — | 共享同一对象 | `@ref @mut T ← @mut T` 别名共享；纯值互传 |

判定例（langfacts §6 与 :110 注释）：`b.n = 1` 后 `a.n` 也变，仅当目标为 `@ref`（或双方皆纯）——`@ref @mut T ← @mut T` 时 $\textit{tr}=\top$ 使三条全假 ⇒ **共享**。

对照实现差异注记：语句位 `VarStmt` 的目标 mut 判据是 `"mut" in stmt.annotations || stmt.type is MutType`（:164），ref 判据是注解 `"ref" in stmt.annotations`（:165）——即脚本里写作 `@mut var x = …` / `@ref var x = …`（Parser.kt:663-664 注解前置于 `var`）。**待核**：`VarExpr` 位（:246）把 ref 误作 targetMut 传入，见 §4.2/§11。

## 7. unchecked 的运行时语义

$$\frac{E ⊢ s ⇓ v}{E ⊢ \texttt{unchecked}\ s ⇓ v} \quad (\text{E-Unchecked, :194})$$

求值器对 `UncheckedStmt` **直接执行 inner**——没有任何运行时闸门、没有深度计数、没有动态检查回退。unchecked 纯粹是**编译期开关**（Checker `uncheckedDepth++`，langfacts §6），它放行的是 E-IMMUT-ASSIGN、pure 传播、CallCheck 的 Any 准入、impure 调用闸、async-in-sync 闸这些静态闸门；运行期本来就没有这些闸，故“直通”是唯一可实现的行为。

对照入口（§10）：JS 编译端对 unchecked 语句生成 `// unchecked` 注释后透传（JsCodeGen.kt:822）——两端语义一致（都不产生运行时检查），差异只在注记形式。

## 8. 错误路径

### 8.1 InterpreterError

$$\frac{}{E ⊢ e ⇓ \bot(\textit{msg})} \quad (\text{E-Err})$$

`InterpreterError`（ScriptFrame.kt:62）是 `RuntimeException`。CLI 出口（Main.kt:366-368）：`catch (RuntimeException)` → `[错误] ${e.message}` + exit 1。主要 ⊥ 位：未定义变量（:215）、非法整数（:203）、运算符需数字（:319-320）、编译期算子（:286/299/300）、不可调用（:504）、结构体缺字段/无字段（:230-234/:929）、未定义函数（:533）、方法消歧（:605）、赋值目标非法（:180/:182）、异步不支持（:268）、未定义 panic（§8.3）。

### 8.2 ReturnException

`return` 的实现是抛 `ReturnException(v)`（:979），**拦截点且仅拦截点**为函数体边界：`invokeFunDecl`（:595）、`invokeImplMethod`（:631）、`evalLambda`（:850）、`evalAnonFun`（:868）、`funDeclAsValue`（:892）、重载调度值（经 :910 的 invokeFunDecl）、`FunRefExpr` 绑定闭包（:263）、`methodPathValue` 绑定闭包（:554）。

**陷阱**：顶层（脚本直接位）的 `return` 不在上述任何边界内，`evaluate` 不截获 → 泄漏为 `RuntimeException` → CLI `[错误] return` + exit 1。

### 8.3 panic

`panic` 在类型层是内建纯函数（Types.kt:180：无参、返回 `Nothing`），核心库多处用它作“理论不可达”兜底（如 core/collection/list.subl:82 `None => panic()`、core/encoding/encoding.subl 全体占位、core/net/net.subl 的签名先行登记）。`unwrapOr` 式取值管 `Err` 回退则**先于** panic 生效（core/collection/result.subl:25-28：`when(r) { is Ok(v) => v; is Err(_) => d }`），即 panic 只在 Err 未被消费时才被触及。

**求值侧事实**：解释器没有注册 `panic` 的运行时实现（Interpreter.kt:287-380 的 `registerStdlib` 无 panic；core 亦无 `fun panic` 声明）。因此脚本模式一旦执行到 `panic()`：

$$\frac{\textit{hostFuns}(\texttt{panic}) = \varnothing \qquad \Gamma(\texttt{panic}) = \varnothing}{E ⊢ \texttt{panic}() ⇓ \bot(\text{"未定义的函数「panic」"})} \quad (\text{E-Panic-Script})$$

编译模式的对应行为是 `throw new Error('panic: unreachable')`（JsCodeGen.kt:1256）。两端**不等价**：脚本模式把 unreachable 变成了“未定义函数”错误而非显式停机断言——列为差异入口（§10）与待核（是否为有意省略）。

### 8.4 unwrapOr 与容错路径

`unwrapOr(r, d)` 是 core/collection/result.subl:25 的**普通库函数**（无内建特判），求值落回 E-WhenMatch + E-StructCtor：`Ok`→`ResultV(⊤,v,·)` 命中 `is Ok(v) => v`，`Err`→回退 `d`。与之配套的 `mapOk`/`mapErr`/`flatMapOk`（result.subl:32-47）同为 when 重弹。这条错误路径**不依赖任何运行时特权**，是标准库可自身表达的证据。

### 8.5 其他非异常出口

- when 不可判穷尽 → `Null`（E-WhenFall，:723）；
- 宿主函数返回 `null` → `ScriptValue.Null`（fromHost :958）；
- 缺位实参/缺位形参 → 补 `Null`（:588/:564/:826 等）；
- 宿主函数自身抛异常 → 不被解释器捕获，直达 CLI 的 `RuntimeException` 出口。

## 9. 脚本模式执行

### 9.1 管线

`Interpreter.run`（Interpreter.kt:103-110 → :150-240）：

$$\textit{run}(src) = \textit{eval}\big(\textit{stdlib} + \textit{hostDecls} + \textit{structDecls} + \textit{parse}(src),\ E_g\big) \quad \text{（前置 Checker 全过）}$$

1. **解析**：`parseScriptSource`（:106-108；`--global-inference` 时放行省略标注，:105-107）。
2. **宿主注入**：`hostFunctionInfos` → `@host FunDecl`（:156-175，无签名者近似为 `fun name(x: Any): Any`）；`hostStructs` → `StructDecl`（:178-192）——**仅为 Checker 提供类型信息**，合成 @host 声明不参与求值（:233 注释）。
3. **stdlib 合并**：`loadStdlibEntries`（:246-259）读取 `stdlibDir`（默认 `core`，:18）下全部 `.subl`（递归、按相对路径排序，:37-40），**过滤掉 `@root` 注解的 FunDecl**（:255-258：@root 内建声明仅为声明文档，留着会与 @host 声明撞 E-DUP-DECL）。
4. **Checker**：`Checker(checkedAst, scriptMode)`（:214-215），错误即抛 `InterpreterError("脚本类型检查失败")`（:216-220）。
5. **求值**：新 `Evaluator`（:234-237）+ 挂在 `globalFrame` 上的脚本帧（:238-239），求值体为 `stdlibEntries + rawAst.entries`（**不含**合成的 host/struct 条目）。

工程模式（`runDir` :120-124）：目录下顶层 `.subl` 合并为单 FileAst，`main()` 为入口；`evaluate` 在“全是声明、无顶层语句”时自动调用 main（Evaluator.kt:44-47）。

### 9.2 全局帧与 stdlib prelude

- `globalFrame`（:30）：**每次 run 重建**（:151-152，H7：避免 declareFunction 只增不去重导致的重复注册）；宿主函数先登记进 globalFrame（:222-231）供名字解析兜底。
- stdlib 是**与语言同源的 `.subl` 源码**（:194-195 注释），脚本模式与编译模式共享同一抽象能力：`List`/`Set`/`Map`/`Result` 容器、类型类（`Functor`/`Foldable`…）、定理库。脚本声明的 struct/enum/impl 由 `collectLocalDecls`（:58-102）登记进 `localStructs`/`ctorToEnum`/`methodImpls`。
- 宿主内建（`registerStdlib` :287-380）：`print`（:290-293，println 宿主行）、`toStr`（:295-305，对齐编译模式 `__dshtoStr`：List 元素无空格、整值 Rat 去浮点尾巴）、`concat`/`length`/`charAt`/`substring`/`strCmp`/字符串族（:308-343）、`parseNat`/`parseRat`/`toRat`/`abs`/`floor`/`ceil`/`pow`/`mathMin`/`mathMax`/`mathRound`（:344-370）、泛型 `apply(f, a)`（:372-378）。
- langfacts §7 记“print/printable 输出”：`print` 见上；**`printable` 在源码中未能定位**（全仓 grep 无命中）——待核，疑为旧称或宿主侧概念。

### 9.3 多脚本隔离

$$\frac{f \in \textit{decls}(p_1)}{f \notin \textit{scope}(p_2)} \qquad \textit{runScript}(p_1)\ \text{与}\ \textit{runScript}(p_2)\ \text{各自独立} \quad (\text{E-ScriptIsolation})$$

落地（Interpreter.kt:130-148 + Main.kt:374-404）：

- `runScript`/:130 → `run` → **每次重建 globalFrame**（:152）+ **每次新建 Evaluator**（`localStructs` 等随构造清空，:59-61）；
- `runScripts`/:135 顺序循环、`runScriptDir`/:140-144 每文件独立；CLI `run-script` 对目录逐个 `.subs` 打 `[脚本] name` 后独立运行（Main.kt:389-394），无 .subs 时目录降级为 `.subl` 工程（:395-399）；
- 隔离的**共享部分**只有宿主注册表（同一 `Interpreter` 实例，Main.kt:378 只造一次；但宿主表在 `init` 后不可变，脚本源码无 `import` 产生式可触及）。

### 9.4 CLI 出口

`run-script`（Main.kt:350-356）：`Interpreter(globalInference)` → `interp.run(src, path.name)` → `[完成] 脚本执行结束`。`ProverInterrupted`（激进证明 Ctrl-C）单独走 130 退出码 + dump 报告（:359-365）。目录多脚本见 §9.3。

## 10. 与 JS 编译端的对照注记（差异入口，不做对表）

两端共享同一 Checker 与同一 AST，差异集中在**深拷贝与内建的落地方式**。入口清单（细节属代码生成卷，此处只标差异点供交叉引用）：

1. **深拷贝对函数的处理**——解释器：C-Fun 对闭包型函数调 `copyCapture`，**捕获一并深拷**（Evaluator.kt:156 + §5.2）；JS 端：`__dc`（JsCodeGen.kt:325-330）对函数**穿透**（`typeof function` 早退，:322 注释明言“JS 闭包不透明”）——修正案称此为既定边界，即两端对“函数值深拷”的语义**不对称**。
2. **panic**——脚本模式无运行时实现（§8.3 E-Panic-Script）；编译模式生成 `throw new Error('panic: unreachable')`（JsCodeGen.kt:1256）。
3. **unchecked**——解释器直行 inner（Evaluator.kt:194）；JS 生成 `// unchecked` 注释后透传（JsCodeGen.kt:822）。两行为一致。
4. **Range**——解释器是 `Struct("Range", {lo,hi})` + `evalRangeMethod`（:357-393，length/size/toList/contains/map/fold；fold 回调按 `[元素, 累积]` 单元组调用，:384-388）；JS 端是 `__range` 助手对象（JsCodeGen.kt:390+，rangeHits 按需注入，:107）。
5. **字符串展示**——解释器宿主 `toStr`（Interpreter.kt:295-305）与 JS 端 `__dshtoStr`（JsCodeGen.kt:275-277）**互为对齐目标**（print/toStr 统一走 `__dshtoStr`，:1127-1128）；但解释器 `+` 的 strOf 拼接（:281/:331-338）与 JS 原生 `+` 在 Null/容器拼接上不完全同构 **待核**。
6. **数值**——解释器 Num=Long / Real=Double 二分（算术有 Real 提升与 Long 截断，:311-316）；JS 端统一为 Number（langfacts §3 决策 86 候选 A）。
7. **结构性差异**——闭包、重载分派、类型类字典在 JS 端分别编译为闭包/函数引用/dict 装配（如自由形态类型类方法的“dict 首实参装配”，对应解释器 :524-531 的 tag 字典分派）；元组在两端表示不同（解释器 `ListV`，JS 端按数组/元组约定）**待核**。

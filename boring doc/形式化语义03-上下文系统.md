## 1. 上下文系统的地位

### 1.1 判断对象

上下文系统判断四类对象，全部落在编译期：

| 对象 | 载体 | 判断位置 |
|---|---|---|
| 具名函数的上文 | `FunDecl.preps : List<Expr>`（Ast.kt:24） | 每个调用点 |
| 具名函数的下文 | `FunDecl.posts : List<Expr>`（Ast.kt:26） | 函数声明处 + 每个调用点 |
| 函数值的上下文 | `FunType.context : List<Expr>?`（Ast.kt:162） | 函数值调用点 + lambda 体帧 |
| 约束表 | `FunDecl.constraints : List<Expr>`（Ast.kt:28） | 每个调用点 |

上下文**不是参数、不是值**：`preps`/`posts` 不进运行时实参表；函数体是证明义务（§5），下文亦以断言形态参与代码生成（_langfacts §7）。

### 1.2 Γ：命题事实集

上下文记为 Γ，承载于帧（§2）。Γ 的条目形态：

| 形态 | 例子 | 来源 |
|---|---|---|
| 类型归属 `e : τ` | `n : Nat` | 形参/变量声明注入 |
| 等式/比较 `e₁ = e₂` | `n = 0` | 变量声明、字段构造 |
| 谓词原子 | `n ≥ 0`、`tagged<7>` | 自然命题、公理、定理 |
| 命题绑定 | `p`（零元） | 命题参数供给 |
| 伴生记录 | `f⟨a, b⟩` | 函数调用（§6.2） |

命题的表示、归一与证明算法见第四卷；本卷只规定**上下文位**的判断式。

## 2. 帧与弥散载体

### 2.1 帧的定义

```
Frame = ⟨ parent, vars, facts, localTheorems, muts, refs, children, used, audited ⟩
```

（`Diffusion.kt:10–42`）其中 `facts : LinkedHashSet<Prop>`——去重且保插入序，使事实成员判定为常数时间（Diffusion.kt:12 注 P8）。

### 2.2 注入判断式

$$\frac{}{\text{inject}(F, p) \triangleq F.\text{facts} \cup \{p\} \quad (p \neq \top)} \qquad \frac{p = \top}{\text{inject}(F, p) \triangleq F.\text{facts}} \quad (\text{G-INJECT})$$

`⊤` 不被注入（Diffusion.kt:40：`if (p != PTop) facts.add(p)`）——恒真命题没有信息量。

### 2.3 事实可见性

$$\frac{}{\text{allFacts}(F) = \text{allFacts}(F.\text{parent}) \!+\! F.\text{facts}} \quad (\text{G-ALLFACTS})$$

方向**自下而上**：子帧沿父链读取全部事实；父帧不主动读取子帧事实（Diffusion.kt:41）。

### 2.4 弥散的三个作用域判断式

$$\frac{\text{块表达式检查结束}}{\forall p \in F'.\text{facts}.\ \text{inject}(F, p)} \quad (\text{G-BLOCK})$$

块内事实**回溢**父帧（Checker.kt:1161：`nf.facts.forEach { f.inject(it) }`）——这是「弥散」的字面含义。

$$\frac{\text{lambda 体检查结束}}{F'.\text{facts}\ \text{不回溢}} \quad (\text{G-LAMBDA})$$

lambda 帧**隔离**：其内部事实不外泄（体求值时机与次数不受定义点控制，外泄破坏健全性）。唯一例外是纯度命题 `pure<λ>` 注入外层帧（Checker.kt:1141）。

`if`/`when` 分支帧同样不回溢：分支事实只在该分支条件下成立。

### 2.5 弥散的事实来源

1. **显式注入**：`axiom`、`by [q]`、`var` 声明、自然命题（Nat ≥ 0 等）；
2. **函数下文**：调用成功后注入（§6）；
3. **分支条件**：`if`/`when` 的条件在分支内成为事实。

## 3. 签名语法：多上下文 `<p, r>`

### 3.1 具名函数签名

```
fun 名[理论参数](实际参数)<上文> : 返回类型<下文> { 体 }
```

解析（Parser.kt:274–306）：

- 形参表后、冒号前的 `<...>` = **上文**（`preps`）；
- 冒号后的 `<...>` = **下文**（`posts`）；返回类型可省略——`: <q>` 是无返回类型的后置上下文（Parser.kt:290），旧形态 `: T <q>` 仍兼容（Parser.kt:293）；
- 用户拍板（Parser.kt:283–285 注）：冒号是上下（前后置）的分界。

**多上下文**：`<...>` 内以逗号分隔的命题表达式列表，逐项解析为 `List<Expr>`（`parseAngleList`，Parser.kt:603–617）：

```subl
fun both()<p, q>: Null { }                  // preps = [p, q]
fun pair(n: Nat): Nat <n > 0, $ < 10> = n   // posts = [n > 0, $ < 10]
```

每个逗号项是一个独立命题；上文逐项证明（§4.1），下文逐项兑现（§5.1）。尾随逗号被接受（Parser.kt:610）。

### 3.2 与约束表的分派

形参表后的 `<` 先经 `constraintListAhead()`（Parser.kt:311–316）判别：

$$\frac{\text{角括内首项为 IDENT 且其后跟带空格的比较算符（LE/GE/EQ/NEQ 或文本 }\texttt{in}\text{）}}{\text{按约束表 }\texttt{<score <= 100>}\text{ 解析，不作为上文}} \quad (\text{G-CONSTRAINT-DISPATCH})$$

约束表只解析登记（Parser.kt:318–337），其判断式见 §9.2。`<`/`>` 比较被排除在约束表触发条件之外，避免与上文命题 `<a < b>` 歧义（Parser.kt:315 注）。

### 3.3 匿名函数与函数类型

- 匿名函数 `fun _(参数)<上文> : T <下文> = 体`（Parser.kt:838–858）——同具名函数的上/下文位，但**不做约束表分派**（待核：是否有意）。
- 函数类型携带上下文（Parser.kt:566–585）：

$$\frac{\texttt{(}\tau_1,\dots,\tau_n\texttt{)}\texttt{<}C\texttt{>}\texttt{=>}\tau}{\text{类型为 }\text{FunType}([\tau_i],\ \tau,\ \text{context}=C)} \quad (\text{G-FUNTYPE-CTX})$$

```subl
(Nat) <$1 > 0> => Null
```

渲染时上下文以分号连接（Ast.kt:170：`"<" + ...joinToString("; ") + ">"`）——**与源码的逗号分隔不一致**，渲染串不可直接回解析（待核：是否应为统一分隔符）。

## 4. 上文 `<p>`：调用方供给义务

### 4.1 上文判断式

$$\frac{\begin{gathered} \text{调用点 } f(a_1\dots a_k) \qquad f.\text{preps} = [p_1\dots p_m] \\ \text{① 声明期改写：}\$n \to \text{形参名，}\ \text{this} \to f \\ \text{② 调用点代入：命题参数绑定 }\sigma_p\text{、类型替换 }\sigma_t\text{、实参环境 }\sigma_e \end{gathered}}{\forall j.\ \Gamma \vdash p_j[\sigma_p, \sigma_t, \sigma_e]} \quad (\text{G-PRE})$$

- 声明期改写：`rewriteDollarN`（Checker.kt:256–264）+ `substThisExpr`（Checker.kt:276–288），在 checkFun 内完成一次（Checker.kt:375）；
- 调用点代入：`substAll`（CallCheck.kt:1067–1075），依次套用命题参数绑定、类型替换、实参环境 `envSub`（CallCheck.kt:893–897）。

任一上文证不出报 `E-PRE-UNPROVEN`（ERROR，CallCheck.kt:921–925）：

$$\frac{\Gamma \nvdash p_j[\dots]}{\texttt{E-PRE-UNPROVEN}} \quad (\text{G-PRE-FAIL})$$

```subl
fun use()<p>: Null { }
fun main() { use() }        // E-PRE-UNPROVEN：Γ 中无 p
```

（测试核实：CheckerTest「未证明前置报 E-PRE-UNPROVEN」、DiagCoverageTest:37。）

### 4.2 上文的双重身份

$$\frac{\text{checkFun}(f)\ \text{时}}{\forall p \in f.\text{preps}.\ \text{inject}(F_0,\ p[\$n \to \text{形参名},\ \text{this} \to f])} \quad (\text{G-PRE-IN-BODY})$$

上文在声明处被改写后**注入函数体帧**（Checker.kt:377）。即：上文既是调用方的义务，也是被调函数体内可用的前提——函数体不用重新证明自己的上文。

### 4.3 命题参数的供给

带理论命题参数（超越函数）`fun witness[@q]<q>: Null {}` 的上文 `q` 需要绑定到具体命题。供给有两种形态（CallCheck.kt:898–918）：

**自动供给**：

$$\frac{\begin{gathered} q\ \text{被上文/下文引用（}\texttt{usesQ}\text{）且未显式供给} \\ C = \{\, c \in \Gamma \mid c\ \text{是 0 元原子且}\ c.\text{head} \notin \text{排除集}\,\} \end{gathered}}{\begin{gathered} |C| = 1 \Rightarrow \sigma_p(q) := c \\ |C| = 0 \Rightarrow \texttt{E-PROP-UNBOUND}\ (\text{WARN}) \\ |C| > 1 \Rightarrow \texttt{E-PROP-AMBIGUOUS}\ (\text{ERROR}) \end{gathered}} \quad (\text{G-SUPPLY-AUTO})$$

```subl
fun witness[@q]<q>: Null { }
fun main() { axiom torch
witness() }       // 自动供给：Γ 中唯一 0 元候选 torch
```

（测试核实：CheckerTest「命题参数自动供给」。）

**显式供给**：调用位尖括号 `witness<torch>()`（InstExpr 项经 `propFromSupply` 解析，CallCheck.kt:1062–1065）：

$$\frac{\text{显式供给 } s\ \text{且}\ s\ \text{是原子}\ \text{Prop}}{\sigma_p(q) := s \qquad \Gamma \nvdash s \Rightarrow \texttt{E-PROP-UNBOUND}\ (\text{WARN})} \quad (\text{G-SUPPLY-EXPLICIT})$$

```subl
fun witness[@q]<q>: Null { }
fun main() { witness<torch>() }   // E-PROP-UNBOUND（警告级）：torch 不在 Γ
```

（测试核实：CheckerTest「显式供给但作用域无该命题」——封存决定：显式供给失败降级为警告。）

### 4.4 排除集（Diffusion 的供给边界）

$$\frac{}{\text{排除集} = \{=,\ ==,\ !=,\ <,\ >,\ <=,\ >=\} \cup \{\$,\ :,\ \text{\_\_call\_\_},\ \text{\_\_inst\_\_},\ \text{\_\_t\_\_}\}} \quad (\text{G-EXCLUSION})$$

（`Prop.kt:25–27`：`structuralHeads = cmpHeads + setOf("$", ":", "__call__", "__inst__", "__t__")`。）

排除集在两处控制弥散命题的候选范围：

1. **自动供给候选过滤**（CallCheck.kt:911）：等式、比较、类型归属、`$` 原子、调用/实例化记录是**推理的材料**，不是可「供给」的弥散命题；
2. **显式供给合法性**（`propFromSupply`，CallCheck.kt:1064）：结构性原子不允许作为显式供给项。

理由：等式与类型事实由推理通道（MP 闭包、算术通道、类型判定）消费；若它们同时充当供给候选，会把「材料」误当「结论」，供给歧义也会爆炸。

### 4.5 上文的自动证明通道

供给完成后，上文的证明走通用证明器（_langfacts §4），包括：

- MP 闭包：`p ∧ (p → q)` 饱和产 `q`——`axiom p` + `axiom p → q` 可证上文 `q`（测试核实：CheckerTest「modus ponens 自动证明」）；
- ∀ 实例化：`axiom forall n. valid<n>` 可经命题池合一供给上文 `valid<7>`（测试核实：CheckerTest「全称合一特化供给」）；
- 常量原子真值、算术通道（Diffusion.kt:278–337）。

## 5. 下文 `<$ = 7>`：体内兑现

### 5.1 下文判断式（声明处）

$$\frac{\begin{gathered} \text{fun } f(\dots) : \tau\ \text{<posts>}\ \{\ \text{body}\ \} \\ \$ := \text{dollarOf}(\text{body}) \qquad \text{posts 经}\$n/\text{this}\ \text{改写} \end{gathered}}{\forall q \in \text{posts}.\ \text{allFacts}(F_0) \vdash q[\$]} \quad (\text{G-POST-CHECK})$$

（Checker.kt:407–418：`tail = dollarOf(body)`，`goal = substDollar(fromExpr(post), tail)`，`proveOrDeep(f.allFacts(), goal)`。）

**函数体是证明义务**：声明不是可信公理，体结束时 Γ 必须蕴含下文。证不出报 `E-POST-UNPROVEN`（ERROR）：

$$\frac{\text{allFacts}(F_0) \nvdash q[\$]}{\texttt{E-POST-UNPROVEN}} \quad (\text{G-POST-FAIL})$$

```subl
fun bad(): Null <p> { }             // E-POST-UNPROVEN：体内无 p
fun test1(): Null <p> { axiom p }   // 兑现：体内注入 p
```

（测试核实：CheckerTest:30、DiagCoverageTest:39。）

### 5.2 `$` 的解法（体内）

`dollarOf`（Diffusion.kt:52–59）按优先级解 `$`：

$$\frac{\begin{gathered} \text{① 块内有唯一一处带值的显式}\ \texttt{return}\ e \Rightarrow \$ := e \\ \text{② 否则取尾表达式} \Rightarrow \$ := \text{tailExpr} \\ \text{③ 都没有} \Rightarrow \$ := \texttt{null} \end{gathered}}{\$\ \text{的解}} \quad (\text{G-DOLLAR-OF})$$

**多路 return 保守取 null**：`if/else` 各返回一个值时无法归一为单一项，`dollarOf` 返回 `NameRef("null")`，让后件核对**显式失败**——不猜测，因为猜测会产生「看似通过实则错误」的证明（Diffusion.kt:48–50 注）。

```subl
fun get7(): Int <$ = 7> { return 7 }   // 唯一 return → $ := 7，兑现
```

（测试核实：CheckerTest「美元等式自反」。）

### 5.3 `@axiom` 豁免

$$\frac{\texttt{"axiom"} \in f.\text{annotations}}{\text{免除 } f\ \text{的下文验证义务} \qquad \text{发 D-AXIOM-POST（补充级）}} \quad (\text{G-AXIOM-FUN})$$

（Checker.kt:410–412。）签名即公理：下文由作者声明、编译器信任；函数体仍正常类型检查与代码生成，**上文仍在调用点强制证明**（§4.1）。

### 5.4 匿名函数的下文义务

匿名函数同样检查下文（Checker.kt:1330–1334）：

$$\frac{\texttt{fun}\ \_(\dots) : \tau\ \text{<posts>}\ \text{body}}{\forall q \in \text{posts}.\ \text{allFacts}(F') \vdash q[\text{dollarOf}(\text{body})]} \quad (\text{G-POST-CHECK-ANON})$$

```subl
fun main() { var f = fun _(): Int <p> { } }   // E-POST-UNPROVEN
```

（测试核实：CheckerTest:373。注意：`AnonFunExpr` 的 preps 注入其独立帧（Checker.kt:1322），但结果 `FunType` **不携带**其 posts（Checker.kt:1341–1346）——函数值的下文不随类型弥散，见 §8.4。）

## 6. 弥散规则：下文兑现后进作用域

### 6.1 下文注入判断式（调用点）

$$\frac{\begin{gathered} e = f(a_1\dots a_k) \qquad f.\text{posts} = [q_1\dots q_n] \\ \text{上文检查已通过（G-PRE）} \qquad \sigma = [\$ \to e,\ \$n \to a_n,\ \text{this} \to f,\ \sigma_p,\ \sigma_t,\ \sigma_e] \end{gathered}}{\forall i.\ \text{inject}(F,\ q_i[\sigma])} \quad (\text{G-POST-INJECT})$$

（CallCheck.kt:939–943：`goal = substDollar(substAll(...), c)` 后 `f.inject(goal)`——`$` 替换为**调用表达式本身**。）

**下文在调用点直接注入，不经验证**——下文是被调函数的**保证**（其兑现义务已在声明处以 E-POST-UNPROVEN 强制），不是调用点的义务。注入的目标帧 `F` 是**调用点所在帧**：

- 块内调用 → 注入块帧，块结束后随 G-BLOCK 回溢父帧；
- lambda 体内调用 → 注入 lambda 帧，不外泄（G-LAMBDA）；
- 分支内调用 → 注入分支帧，不回溢。

### 6.2 伴生记录机制（companion）

$$\frac{\text{调用 } f(a_1\dots a_k)\ \text{成功}}{\text{inject}(F,\ \text{PAtom}(f,\ [a_1\dots a_k]))} \quad (\text{G-COMPANION-INJECT})$$

（CallCheck.kt:939：`f.inject(PAtom(name, c.args))`，与下文注入在同一点发生。）

伴生记录把函数名当作谓词符号、实参当作项，记录「**这次调用发生过**」。两个用途：

1. **证明「参数被调用过」**：`f<a>` 是关于调用行为的事实，可作推理前提；
2. **调用痕迹**：方法路径的伴生记录用**全量实参**（含 self，作调用痕迹），而实参替换表只含真实形参（CallCheck.kt:891 注）。

旧文档（05 §6.1/§6.3）另有设计规定「`f⟨a…⟩ → ∧posts`」（伴生命题推出下文）。**源码核实：通用证明器（Prover，Prop.kt:404 起）不含由伴生记录展开下文的规则**（Prop.kt 全文无 posts/preps 处理）；该规定在实现上由 G-POST-INJECT 的同点直接注入等价覆盖——普通调用点无需经伴生命题推导即可得下文。伴生记录到下文的一般推理规则是否存在其他消费路径，**待核**。

### 6.3 弥散范例

```subl
fun test1(): Null <p> { axiom p }      // 下文：兑现 p
fun test2()<p>: Null { }               // 上文：调用方须供给 p
fun main() {
    test1()        // 下文注入：Γ 得 p
    test2()        // 上文 p 已在 Γ（弥散供给）→ 通过
}
```

（测试核实：CheckerTest「弥散通过 - 最初例子做对了的样子」。）

下文亦可携带量词与 `$`：

```subl
fun notZero(list : List[Nat]) : List[Nat]
    <∀ e . e ∈ $ → (e ≠ 0)> =
    list.filter { _ != 0 }
```

（测试核实：CheckerTest「filter 后置全称e属于结果不等于0可证 notZero」。）

### 6.4 全局弥散：纯度与异步事实

$$\frac{\texttt{"impure"} \notin f.\text{annotations}}{\text{globalFacts} \cup= \{\text{pure}\langle f\rangle\}} \qquad \frac{\texttt{"async"} \in f.\text{annotations}}{\text{globalFacts} \cup= \{\text{async}\langle f\rangle\}} \quad (\text{G-GLOBAL-FACTS})$$

（Symbols.kt:26–28；跨模块按裸名补全且任一处 `@impure` 则整名不注册，Symbols.kt:30–51。）这两个事实驱动纯作用域调用闸与异步闸（第六卷）。

## 7. `$` 与 `$n`：指代系统

### 7.1 `$n` 第 n 形参引用（1 起，仅前件/后件位）

$$\frac{\$n\ \text{出现在具名函数的上文或下文中}}{\text{声明期（checkFun）统一改写为第 } n\ \text{个形参的名字}} \quad (\text{G-DOLLAR-N})$$

（Checker.kt:375–376 调用 `rewriteDollarN`；替换器 `substDollarNExpr`，Checker.kt:266–274：`params.getOrNull(e.index - 1)`。）

附带诊断（Checker.kt:259–262）：

$$\frac{n > |\text{params}|}{\texttt{E-PARAM-REF}\ (\text{ERROR})} \qquad \frac{n \le |\text{params}|}{\texttt{H-PARAM-REF}\ (\text{HINT：可直接使用参数名})} \quad (\text{G-DOLLAR-N-DIAG})$$

**位置限制**：

$$\frac{\$n\ \text{出现在函数体（值位）}}{\texttt{E-PARAM-REF-IN-BODY}\ (\text{ERROR：请直接使用参数名})} \quad (\text{G-PARAM-REF-IN-BODY})$$

（Checker.kt:904–908：`ParamRefExpr` 在 `checkExpr` 中直接报错并回退取 `paramTypes`。）

```subl
fun f(n: Nat): Nat = $1            // E-PARAM-REF-IN-BODY
fun g(n: Nat) <$1 > 0> : Null { }  // 合法：$1 在上文位，声明期改写为 n
```

（测试核实：CheckerTest:688。）

函数**值**调用点的上下文（FunType.context）不经声明期改写，而由 `substParamRefToArg` 在调用点内联为实参表达式（§8.2）。

### 7.2 `$` 返回值指代

| 出现位 | 解法 | 判断式 |
|---|---|---|
| 下文（声明处） | `dollarOf(body)`：唯一 return / 尾表达式 / null | G-DOLLAR-OF |
| 下文（调用点注入） | 调用表达式本身 `f(a…)` | G-POST-INJECT |
| 上文 | 不参与替换（substDollar 只用于 posts） | — |

$$\frac{\text{调用 } e = f(a)\text{，}f\ \text{的下文含}\ \$ \ge 0}{\text{注入 } e \ge 0} \quad (\text{G-DOLLAR-CALL})$$

（Prop.kt:232–256：`substDollar` 把 `ReturnSym` 替换为给定项；`ParamRefExpr` 原样透传——声明期已改写，漏到此处说明上游未覆盖。）

词法层：`$` 是单 token `ReturnSym`（Ast.kt:383），`$n` 粘连为单 token `ParamRefExpr`（Ast.kt:386；_langfacts §1：`$` 后紧跟数字）。命题归一时二者映射为 0 元原子 `PAtom("$")` / `PAtom("$n")`（Prop.kt:32–34），其中 `"$"` 恰在排除集（§4.4）——裸返回值原子不作为供给候选。

### 7.3 `this` 与 `self`、字段裸名

$$\frac{\text{this 出现在函数签名（上文/下文）中}}{\text{声明期改写为函数名（}\texttt{p<this>} \to \texttt{p<f>}\text{）}} \quad (\text{G-THIS})$$

（`substThisExpr`，Checker.kt:276–288，与 `$n` 改写串连：Checker.kt:375–376。）

$$\frac{\text{调用点 } r.f()\text{，}f\ \text{的上下文含 self}}{\sigma_e(\text{self}) := r} \quad (\text{G-SELF})$$

（方法路径的 envSub 补 `self := 接收者`，CallCheck.kt:893–897；接收者取 `c.callee.target` 或首实参。）

impl 方法体内字段裸名等价 `self.字段`（`injectSelfAndFields` 注入 `字段 = self.字段` 与 `字段 : τ`，Checker.kt:482–498），伴生命题中的字段引用因此在方法体内以裸名形态出现、在调用点以 `接收者.字段` 形态出现，由 G-SELF 对齐。形参名遮蔽字段发 `H-FIELD-SHADOW` 提示（Checker.kt:351–352）。

### 7.4 内联改写时机汇总

| 标识 | 改写时机 | 源码 |
|---|---|---|
| `$n`（具名函数） | 声明期（checkFun） | Checker.kt:375–376 |
| `$n`（函数值类型） | 调用点（→ 实参表达式）；lambda 体检查时 → 形参名 | CallCheck.kt:490、Checker.kt:1114 |
| `this` | 声明期（→ 函数名） | Checker.kt:375–376 |
| `$` | 声明期解为 dollarOf(body)；调用点解为调用表达式 | Checker.kt:415、CallCheck.kt:941 |
| `self` | 调用点（→ 接收者） | CallCheck.kt:894–897 |
| 字段裸名 | 方法体检查时注入等式事实 | Checker.kt:491–494 |

## 8. FunType.context：函数值的上下文

### 8.1 字段与语法

```
data class FunType(
    val params: List<Type>, val ret: Type, val purity: String = "",
    val theory: List<TypeParam> = emptyList(),
    val context: List<Expr>? = null,   // 上下文：命题表达式列表，null 表示无上下文
) : Type
```

（Ast.kt:153–177。）`context` 是**唯一的类型级上下文载体**：`(Nat) <$1 > 0> => Null`（Parser.kt:581–583）。`substT` 屏蔽 theory 绑定者但原样保留 context（Ast.kt:172–176）——上下文不随类型替换改变。

### 8.2 函数值调用的上下文判断式

$$\frac{\begin{gathered} \text{调用点 } g(a_1\dots a_k)\text{，}g : \text{FunType}(\dots,\ \text{context} = [c_1\dots c_m]) \\ \text{① } c_j\ \text{中的}\ \$n\ \text{内联为实参表达式 } a_n\ (\texttt{substParamRefToArg}) \\ \text{② 目标 } \text{fromExpr}(c_j) \end{gathered}}{\forall j.\ \Gamma \vdash c_j[\$n \to a_n]} \quad (\text{G-CTX-VALUE})$$

（CallCheck.kt:488–497，分派自 checkCall 的函数值回退（CallCheck.kt:371–372）。）任一上下文证不出报：

$$\frac{\Gamma \nvdash c_j[\$n \to a_n]}{\texttt{E-CTX-UNPROVEN}\ (\text{ERROR})} \quad (\text{G-CTX-FAIL})$$

诊断信息会附上当前 Γ 的全部事实（CallCheck.kt:493–494），便于定位缺哪条前提。

```subl
fun apply(n: Nat, g: (Nat) <$1 > 0> => Nat) <n > 0> : Nat = g(n)

fun main() {
    var r = apply(1, { x => x + 1 })    // 上文 1 > 0 常量判定为真；
                                        // lambda 期望类型携带 <$1 > 0>，体内 x > 0 已注入
}
```

说明：此例按代码路径构造（`g(n)` 的上下文目标 `n > 0` 由 apply 的上文注入供给；lambda 体帧由 §8.3 注入 `x > 0`）。**该路径未见等价测试用例（E-CTX-UNPROVEN 在 compiler 测试中无行为测试，仅 explain 覆盖，ExplainCoverageTest:45），标 待核。**

### 8.3 lambda 体帧的上下文注入

$$\frac{\text{lambda 的期望类型为 }\text{FunType}(\dots,\ \text{context} = [c_i])}{\forall i.\ \text{inject}(F_\lambda,\ c_i[\$n \to \text{lambda 第 } n\ \text{形参名}])} \quad (\text{G-CTX-LAMBDA})$$

（Checker.kt:1112–1116：`ft?.context?.forEach { nf.inject(fromExpr(substDollarNExpr(ctxExpr, e.params.map { Param(it, ...) }))) }`。）

即：函数类型的上下文对 lambda 而言是**前提事实**——`(Nat) <$1 > 0> => Null` 的 lambda 体内可以直接用 `x > 0`（`$1` 已换为形参名 `x`）。

### 8.4 与具名函数上下文的差异

| 维度 | 具名函数（preps/posts） | 函数值（FunType.context） |
|---|---|---|
| 位置 | 签名两处（冒号前后） | 类型位 `(...)<C> => ...` |
| 角色 | 上文＝义务 + 体内前提；下文＝体内义务 + 调用点弥散 | 仅上文角色：调用点义务 + lambda 体前提 |
| 命题参数供给 | 有（自动/显式，§4.3） | 无（context 中的 `$n` 直接内联为实参） |
| `this`/`self` | this → 函数名（声明期）；self → 接收者（调用点） | `self` 无（无方法路径）；`this` 无改写 |
| 调用点弥散 | posts 注入调用点帧（G-POST-INJECT） | 无——函数值不携带下文（§5.4） |
| 声明处义务 | posts 体内兑现（E-POST-UNPROVEN） | 无（AnonFunExpr 的 posts 只在声明处检查，不进 FunType） |
| 越界 `$n` | E-PARAM-REF + H-PARAM-REF | 越界时 `substParamRefToArg` 原样保留（args.getOrNull 越界回退，CallCheck.kt:501），无专项诊断（待核） |

## 9. 相邻机制

### 9.1 结构体伴生命题

结构体声明携带伴生命题（`StructDecl.props`，Ast.kt:55–64）：`struct Test(n: Nat) <n ≠ 0>`。

- **构造时证明**：位置式/命名式构造前证明 props（字段替换为实参），证不出报 `E-STRUCT-PROP-UNPROVEN`（CallCheck.kt:681 以下；修复 #7：缺省字段以声明默认值替换进命题）；
- **硬约束**：props 禁止引用 `@mut` 字段——`E-STRUCT-MUT-PROP`（Symbols.kt:158 声明位 + CallCheck.kt:1144–1147 防御）；
- **作形参自动注入**：`fun f(test: Test)` 体内等价于前件 `<test.n ≠ 0>`（字段引用替换为 `test.字段`，Checker.kt:360–372）；
- **方法体注入**：self 结构体的 props 以裸字段形态注入（Checker.kt:499–506）；
- **变量构造注入**：`var t = Test(m)` 注入 `t.n = m` 与 props（Checker.kt:561–577）。

### 9.2 约束表（依赖类型方向）

`fun f()<score <= 100>`（constraints，Parser.kt:318–337 只解析登记）在调用点按实参承担，三态判断（CallCheck.kt:929–937）：

$$\frac{\Gamma \vdash \text{goal}}{\text{通过}} \qquad \frac{\Gamma \nvdash \text{goal} \quad \Gamma \vdash \neg\text{goal}}{\texttt{E-CONSTRAINT-VIOLATED}\ (\text{ERROR：已反证})} \qquad \frac{\Gamma \nvdash \text{goal} \quad \Gamma \nvdash \neg\text{goal}}{\texttt{W-CONSTRAINT-UNPROVEN}\ (\text{WARN：值可能运行时才确定})} \quad (\text{G-CONSTRAINT})$$

（goal 经 envSub 实参替换 + `$n` 改写 + `this` 改写。）确凿违反报错，静态证不出降级警告，不误杀未知实参。

## 11. 判断式索引

**帧与弥散**：G-INJECT（注入，⊤ 不入）、G-ALLFACTS（向上可见）、G-BLOCK（块回溢）、G-LAMBDA（lambda 隔离）。

**签名语法**：G-FUNTYPE-CTX（函数类型携带上下文）、G-CONSTRAINT-DISPATCH（约束表分派）。

**上文**：G-PRE（上文验证）、G-PRE-FAIL（E-PRE-UNPROVEN）、G-PRE-IN-BODY（上文注入体帧）、G-SUPPLY-AUTO（自动供给三态）、G-SUPPLY-EXPLICIT（显式供给）、G-EXCLUSION（排除集）。

**下文**：G-POST-CHECK（声明处兑现）、G-POST-FAIL（E-POST-UNPROVEN）、G-DOLLAR-OF（$ 解法）、G-AXIOM-FUN（`@axiom` 豁免）、G-POST-CHECK-ANON（匿名函数义务）。

**弥散**：G-POST-INJECT（下文注入调用点）、G-COMPANION-INJECT（伴生记录）、G-GLOBAL-FACTS（pure/async）。

**函数值上下文**：G-CTX-VALUE（调用点验证）、G-CTX-FAIL（E-CTX-UNPROVEN）、G-CTX-LAMBDA（lambda 体注入）。

**约束表**：G-CONSTRAINT（三态判断）。

## 12. 已知边界与待核

1. **伴生命题 → 下文的推理规则未由证明器实现**：旧文档规定 `f⟨a…⟩ → ∧posts`，但 Prover 无该展开；实现以 G-POST-INJECT 同点直接注入等价覆盖（§6.2）。伴生记录的其他消费路径待核。
2. **E-CTX-UNPROVEN 无行为测试**：函数值上下文路径（checkInlineFunCall）仅有 explain 覆盖（ExplainCoverageTest:45），§8.2 示例按代码路径构造，未经端到端核实。
3. **FunType.context 渲染/解析分隔符不一致**：渲染用分号（Ast.kt:170），源码用逗号（parseAngleList）。
4. **函数值不携带下文**：AnonFunExpr 的 posts 在声明处检查但不进 FunType（Checker.kt:1341–1346），函数值调用的下文弥散缺失——设计边界或遗漏，待核。
5. **函数值上下文中越界 `$n` 无专项诊断**：`substParamRefToArg` 越界回退为原样保留（CallCheck.kt:501），与具名函数的 E-PARAM-REF 不对称。
6. **匿名函数不做约束表分派**（Parser.kt:845 直接 parseAngleList），与具名函数（Parser.kt:279–282）不一致。
7. **多上下文的证明是逐项独立的**：`<p, r>` 中一项失败不短路另一项的检查（各自产生诊断），组合命题需用户显式写合取。

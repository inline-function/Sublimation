## 1. when 三形态总览

凝华的 when 有三种形态，统一在一个判断接口 M-WHEN 下（总纲 §3.9），但各形态的前提条件不同：

| 形态 | 层面 | 语法 | 解析入口 | 运行期行为 |
|---|---|---|---|---|
| 值 when | 表达式 | `when(x) { pat => body }`、`when { cond => body }`、`when(var e = t) { … }` | parseWhen（Parser.kt:1492） | 逐分支匹配/求值 |
| 模板 when | 表达式（脱糖） | `when(t in _) { p => body }` | parseWhen + D-TEMPLATE 脱糖（:1508—1516） | 同无主题 when |
| 命题 when | 语句 | `when[P ∨ Q] { P => {…} }` | parseWhenProp（Parser.kt:720） | 空转（值为 Null，体不在运行期执行） |

三者共用分支分隔符 `=>`（修正案后 `->` 全位非法，lexer 出 ARROW 仅供诊断）。

### 1.1 统一判断接口

$$\frac{\Gamma \vdash e : \tau_s \qquad (\Gamma_i \vdash body_i : \tau_i)_{i=1..n} \qquad \tau_w = \text{join}(\tau_1, \dots, \tau_n) \qquad \Gamma \vdash w\ \text{穷尽?}}{\Gamma \vdash \texttt{when}\ e\ \{ arm_1 \dots arm_n \} : \tau_w} \quad (\text{M-WHEN})$$

其中 `Γ_i` 是第 i 分支帧（含顺序否定，§3.2），穷尽性判定决定 `τ_w` 的具体取值（§4）。定型规则的完整形式见 01 卷 §2.6 T-WHEN-EXH / T-WHEN-UNSEALED。

各形态对 M-WHEN 前提的差异：

- **值 when（有主题）**：`e` 为主题表达式，`arm_i` 含模式 `pat_i` 与可选守卫；`Γ_i` 由 bindPattern 构造。
- **值 when（无主题）**：`e = null`，`arm_i` 含布尔条件 `cond_i`（存 WhenArm.cond），模式为 PatCond 哨兵；`bp_i = PropLogic.fromExpr(cond_i)`（WhenCheck.kt:132—136）。
- **模板 when**：解析层脱糖为无主题 when（§7.1 D-TEMPLATE），语义层按无主题处理。
- **命题 when**：不走 M-WHEN，走独立的 G-WHEN-PROP 判断（§6），运行期空转。

## 2. 模式语法域

模式由 parsePattern（Parser.kt:1556—1654）解析，归纳定义如下：

$$\frac{}{l \in PatLit \quad (l \in \mathbb{Z} \cup Str)} \quad (\text{M-PAT-LIT})$$

$$\frac{\Sigma \vdash C : Ctor \qquad |fields(C)| = n \qquad (p_j \in Pat)_{j=1..n}}{is\ C(p_1, \dots, p_n) \in PatCtor} \quad (\text{M-PAT-CTOR})$$

$$\frac{T \notin Typeclass \qquad x \in Var?}{is\ T\ [as\ x] \in PatIs} \quad (\text{M-PAT-IS})$$

$$\frac{(p_j \in Pat)_{j=1..n} \qquad n \ge 2}{(p_1, \dots, p_n) \in PatTuple} \quad (\text{M-PAT-TUPLE})$$

$$\frac{}{\_ \in PatBind \qquad x \in Var \Rightarrow x \in PatBind} \quad (\text{M-PAT-BIND})$$

$$\frac{}{else \in PatElse} \quad (\text{M-PAT-ELSE})$$

**区间不在模式域**：parsePattern 的 token 分支中无 RANGE / MINUS。值 when 分支位不接受 `0..n` 模式（实测报「期望 DARROW」）。区间仅出现在两个表达式位：模板 when 的分支模式（脱糖为 `in(t, lo..hi)`，Parser.kt:1531）与无主题 when 的分支条件（`n in 0..10`，Parser.kt:1539）。

### 2.1 模式良构判断

$$\frac{\Sigma \vdash C : Ctor \qquad |fields(C)| = |p_1..p_n| \qquad (\Gamma \vdash p_j\ Pat\ \text{对}\ \tau_j)_{j=1..n}}{\Gamma \vdash is\ C(p_1, \dots, p_n)\ Pat\ \text{对}\ \tau_s} \quad (\text{M-PAT-CTOR-WF})$$

$$\frac{T \notin Typeclass \qquad \tau_s \approx T \lor (\tau_s = U_1 | \dots | U_m \land \exists k.\ T \approx U_k)}{\Gamma \vdash is\ T\ [as\ x]\ Pat\ \text{对}\ \tau_s} \quad (\text{M-PAT-IS-WF})$$

$$\frac{\tau_s = (\sigma_1, \dots, \sigma_n) \qquad |p_1..p_k| = n \qquad (\Gamma \vdash p_j\ Pat\ \text{对}\ \sigma_j)_{j=1..n}}{\Gamma \vdash (p_1, \dots, p_k)\ Pat\ \text{对}\ \tau_s} \quad (\text{M-PAT-TUPLE-WF})$$

侧条件：

- 类型类不能作 is 模式（无运行时 tag），违者报 E-TYPE-MISMATCH（WhenCheck.kt:243—244）。
- 元组模式分量数不符或对非元组主题使用，报 E-TYPE-MISMATCH（WhenCheck.kt:259—262）。
- is 类型不在联合变体中，报 E-TYPE-MISMATCH（WhenCheck.kt:249—250）。
- `(p)` 单元素括号退化为子模式 p，不构成 PatTuple（Parser.kt:1614—1621）。

### 2.2 裸名歧义消解

解析层无法区分无参构造子与绑定变量，一律产 `PatCtor(nm, [])`。语义层二次判定（bindPattern，WhenCheck.kt:270—289）：

$$\frac{\Sigma \vdash nm : Ctor}{nm\ \text{是构造子模式}} \quad (\text{M-NAME-CTOR}) \qquad \frac{\Sigma \nvdash nm : Ctor \qquad |args| = 0}{nm\ \text{退化为具名绑定}\ nf \vdash nm := \tau_s} \quad (\text{M-NAME-BIND})$$

$$\frac{\Sigma \nvdash nm : Ctor \qquad |args| > 0}{\Phi \vdash \texttt{E-UNBOUND-NAME}} \quad (\text{M-NAME-ERR})$$

运行期同判据按首字母小写化（isBindName，Evaluator.kt:751—753）：小写且非 true/false/null → 绑定。

### 2.3 构造子解构的括号纪律

带绑定或嵌套的解构必须显式 is。不带 is 的括号模式仅允许空参值比较 `A()`（Parser.kt:1642—1648）。`E::A` 路径形态折叠为复合名 `E::A`，符号层按 `substringAfterLast("::")` 归一化（WhenCheck.kt:205）。

## 3. 分支命题构造与顺序敏感

### 3.1 分支命题生成

每个分支产生一条分支命题 `bp`，并往分支帧 `nf` 注入可用的等式（保持 ground，体内可引用绑定变量）。返回给穷尽析取的命题才做存在封闭（I-14，WhenCheck.kt:340—344）。

$$\frac{}{bp(PatElse) = \top} \quad (\text{M-BP-ELSE})$$

$$\frac{x \neq \_ \Rightarrow nf \vdash x := \tau_s,\ nf += (subj = x)}{bp(PatBind(x)) = \top} \quad (\text{M-BP-BIND})$$

$$\frac{}{bp(PatLit(l)) = (subj = l)} \quad (\text{M-BP-LIT})$$

$$\frac{bind \neq null \Rightarrow nf \vdash bind := T;\quad bind = null \land subj = NameRef(x) \Rightarrow nf \vdash x := T}{bp(PatIs(T)) = (subj : T)} \quad (\text{M-BP-IS})$$

$$\frac{term, \bar{x} = patternTerm(p) \qquad eq = (subj = term) \qquad nf += eq}{bp(PatCtor / PatTuple) = \exists \bar{x}.\ eq} \quad (\text{M-BP-CTOR})$$

其中 PatCtor 的 `term` 是 `C(term_1, …, term_k)`，PatTuple 的 `term` 是 `(term_1, …, term_k)`。`_` 分配新鲜量化名 `__w{n}`（patternTerm :347），否则与覆盖律形状不同构，alphaEq 失配导致误判非穷尽（I-14）。

配套注入事实（WhenCheck.kt:269—315）：

- Cons/SetCons 头部注入 `in(h, subj)`，供 forEach 的上文 `in<h, xs>` 消费（:306—311）。
- 类型测入帧 `(subj : 枚举名)`，供分支体内类型收窄（:303—304）。
- P9 血缘登记（决策 44）：模式绑定的名字登记为 subj 的结构子项 structSub，递归自检查据此放行真实的结构递归（:220—225）。

### 3.2 顺序敏感

when 是顺序敏感的（决策 66）：第 i 分支帧注入前 i−1 个分支命题的否定（WhenCheck.kt:129）。

$$\frac{\Gamma_i = \Gamma, \neg bp_1, \dots, \neg bp_{i-1} \qquad \Gamma_i \vdash body_i : \tau_i}{\text{第 } i \text{ 分支在排除前序匹配的上下文中检查}} \quad (\text{M-SEQ-NEG})$$

示例：`when(p) { (0, 0) => A  (a, b) => B }` 的第二分支帧含 `¬(p = (0, 0))`，可作为前提使用。

顺序否定累积**不参与**穷尽性判定——穷尽目标只取各分支正命题的析取（WhenCheck.kt:164—168）。

### 3.3 守卫在分支命题中的合成

$$\frac{bp_0\ \text{已注入}\ nf \qquad nf \vdash guard : Bool \qquad g_{prop} = PropLogic.fromExpr(guard)}{bp = \begin{cases} g_{prop} & bp_0 = \top \\ bp_0 \land g_{prop} & \text{otherwise} \end{cases}} \quad (\text{M-GUARD-SYNTH})$$

检查期守卫先于求值看到分支命题（nf.inject(bp0)，WhenCheck.kt:147），守卫里可以引用模式绑定的变量。带守卫的分支从绑定式吸收中除名（§4.3，WhenCheck.kt:197）。

## 4. 穷尽性判定

### 4.1 主判据（决策 43）

$$\frac{sawCatchAll \lor branchProps.isEmpty() \lor \Gamma' \vdash* bp_1 \lor \dots \lor bp_n}{when\ \text{穷尽} \qquad \tau_w = \text{join}(\tau_1, \dots, \tau_n)} \quad (\text{M-EXHAUSTIVE})$$

$$\frac{\neg(sawCatchAll \lor branchProps.isEmpty() \lor \Gamma' \vdash* bp_1 \lor \dots \lor bp_n)}{when\ \text{非穷尽} \qquad \tau_w = (未密封)} \quad (\text{M-NON-EXHAUSTIVE})$$

其中 `sawCatchAll` 表示某分支 `bp = ⊤` 且无守卫（WhenCheck.kt:151）；`Γ' = Γ ∪ {cov}`（cov 为覆盖律析取式，若存在）。

快捷通道：`sawCatchAll`（兜底分支恒真且无守卫）或分支表为空时直接判穷尽（WhenCheck.kt:164）。

### 4.2 穷尽性是提示不是要求（决策 66）

判不出穷尽的 when 固定按 `(未密封)` 处理，**不阻断编译**。诊断行为分三种情形：

| 情形 | 诊断 | 值类型 | 依据 |
|---|---|---|---|
| 主题有覆盖律（名义枚举）却覆盖不全 | W-NON-EXHAUSTIVE | (未密封) | WhenCheck.kt:176—177，`cov != null` |
| 无主题 / 模板 when 判不出 | W-NON-EXHAUSTIVE | (未密封) | WhenCheck.kt:176，`e.subject == null` |
| 主题无覆盖律（元组、函数类型等） | 静默退化，不警告 | (未密封) | WhenCheck.kt:176 门控不命中 |

即「没有 W-NON-EXHAUSTIVE」不等于「已穷尽」——元组主题永远静默退化。非密封 when 的值流向函数的非 Null 返回类型时报 E-NON-SEALED-MATCH（Checker.kt:405—407）；作为语句使用（值丢弃）合法。

### 4.3 覆盖律展开（决策 49/64）

按主题的**具体类型**就地深展开（不用全局 ∀，泛型枚举 Optional vs Optional[Nat] 会因类型实参不匹配导致 MP 触发不了，工程规范 I-3）：

$$\frac{\Sigma \vdash \tau_s : Enum \qquad shapes = coverShapes(subj, \tau_s, 3) \qquad shapes \neq \emptyset}{cov = \bigvee_{s \in shapes} (\exists s.vars.\ \bigwedge s.conjs)} \quad (\text{M-COVER-LAW})$$

`cov` 作为额外前提并入 Γ 参与穷尽证明（WhenCheck.kt:161—167）。深展开将内层单字段枚举的 `v = term` 直接代入外层项（I-14），使覆盖形状与 bindPattern 的存在形态同构，靠 alphaEq + 析取子集匹配。

安全阀：深度 COVER_DEPTH = 3、形状数 COVER_MAX_SHAPES = 64，超限返回空 → 保守判非穷尽。健全性方向正确，不会误判穷尽（WhenCheck.kt:5—9、44—47）。

### 4.4 绑定式吸收

构造子分支实参全为裸绑定或通配且无守卫时，在值空间恒覆盖该构造子的全部值（bindingCovered，WhenCheck.kt:193—208）：

$$\frac{\forall j.\ args_j \in \{PatBind\} \cup \{PatCtor(n, []) \mid \Sigma \nvdash n : Ctor\} \qquad guard = null}{C(x_1, \dots, x_k)\ \text{吸收}\ C\ \text{的全部值}} \quad (\text{M-BIND-COVERED})$$

故 `is Some(xs)` + `None` 即穷尽。反之：嵌套模式 `is B(is Leaf(x))` 不吸收（实参不全为绑定）；带字面量 `is Some(0)` 保守判非穷尽；守卫破坏吸收（守卫缩小匹配集，WhenCheck.kt:197）。

此判定仅在覆盖律证明失败后作为补救尝试（WhenCheck.kt:169）。

### 4.5 联合主题密封

联合主题的无守卫 is 分支覆盖全部变体时判穷尽（WhenCheck.kt:171—174）：

$$\frac{\tau_s = U_1 | \dots | U_m \qquad \{T_i \mid arm_i.guard = null \land arm_i.pattern = PatIs(T_i)\} \supseteq \{U_1, \dots, U_m\}}{when\ \text{穷尽}} \quad (\text{M-UNION-SEALED})$$

其中 `⊇` 按 typeLooseEq 逐变体比对。else 分支同时把联合主题反收窄为剩余变体（WhenCheck.kt:139—143，§3.2 已述）。

### 4.6 区间覆盖判定

模板 when 与无主题 when 的分支命题是 `in(t, lo..hi)` 原子，可证性交给线性算术通道（ArithProve）：

$$\frac{\Gamma \vdash t \in (L..H) \qquad l_1 = L \qquad h_n = H \qquad \forall i < n.\ l_{i+1} = h_i + 1}{\Gamma \vdash* \bigvee_{i=1..n} in(t, l_i..h_i)} \quad (\text{M-RANGE-EXHAUST})$$

全域 `(L..H)` 由 Γ 组合而来：Nat 局部/字段自动注入下界 `n ≥ 0`（Checker.kt:600—603），上界来自函数上文或结构体伴生命题。区间有缝或缺端点则落回 M-NON-EXHAUSTIVE。

### 4.7 运行期退化

$$\frac{\text{无任何分支匹配}}{eval(when) = Null \qquad \text{不抛异常}} \quad (\text{M-RT-NULL})$$

解释器固定返回 ScriptValue.Null（Evaluator.kt:723）；JS 生成在分支链尾追加 `return null;`（JsCodeGen.kt:1751）。

## 5. 守卫的运行期语义

$$\frac{matchPattern(pat, subj, armFrame) = true \qquad truthy(eval(guard, armFrame)) = true}{evalArm_i = eval(body_i, armFrame)} \quad (\text{M-GUARD-RT-MATCH})$$

$$\frac{matchPattern = true \qquad truthy(guard) = false}{\text{跳过本分支，不回溯前面分支}} \quad (\text{M-GUARD-RT-SKIP})$$

要点（Evaluator.kt:711—721）：

1. 先匹配、后守卫：守卫在 armFrame 求值，此时模式变量已绑定，守卫可以引用绑定变量。
2. 守卫失败只是跳过本分支，主题值已被消费，不会回到上一分支重试。
3. 守卫是值位：守卫表达式按值表达式检查与求值，用 `!=`、`&` 等值算符，不把命题算符 `∧`/`→` 写进守卫。
4. 代码生成的绑定/守卫次序：`if (cond) { binds; if (guard) return body; }`，必须先绑定再判守卫（JsCodeGen.kt:1740—1746）。

## 6. 命题 when

命题 when 是编译期语句（WhenPropStmt，Ast.kt:284）：检查分支体、产出公共结论注入 Γ；运行期空转为 Null（Evaluator.kt:191；JsCodeGen.kt:796/1514 生成空），分支体永不在运行期执行。

### 6.1 析取前提义务

$$\frac{Q = PropLogic.fromExpr(disjunction) \qquad \neg\exists P \in \Gamma.\ render(P) = render(Q)}{\Phi \vdash \texttt{W-PROP-UNBOUND}} \quad (\text{M-PROP-DISJ})$$

析取式必须在 Γ 中（Checker.kt:670—672），按渲染串全等比对，非证等价。供给方式：`axiom (P ∨ Q)`、上文弥散、∵∴ 链等。

### 6.2 分支证明义务

$$\frac{\Gamma_i = \Gamma, PropLogic.fromExpr(arm_i.condition) \qquad (\Gamma_i \vdash s_j \Longrightarrow \Delta_j)_{s_j \in body_i}}{\text{分支 } i \text{ 检查完成}} \quad (\text{M-PROP-ARM})$$

每支在子帧注入自己那一条析取支（af.inject，Checker.kt:677），分支体的 ∵∴ 语句照常走 E-PREMISE-UNPROVEN / E-CANNOT-PROVE。

### 6.3 公共结论回注

$$\frac{common = \bigcap_{i=1..n} \{render(P) \mid P \in BTSConclusions(body_i)\} \qquad common \neq \emptyset}{\Gamma += \{P \mid render(P) \in common\} \qquad \Phi \vdash \texttt{D-WHEN-PROP}} \quad (\text{M-PROP-COMMON})$$

$$\frac{common = \emptyset}{\Phi \vdash \texttt{W-WHEN-NO-COMMON}} \quad (\text{M-PROP-NO-COMMON})$$

公共性按命题渲染字符串集合交计算（Checker.kt:684—691）：各支结论必须逐字同一个命题才回注，证出等价但不同形不算。仅 BTSStmt（∴）的结论进入候选。

### 6.4 与 03 卷的关系

命题 when 走 03 卷的析取前提机制（03 卷 §3.7）。析取式须在 Γ，否则 W-PROP-UNBOUND。本卷不重复 03 卷的 Frame 弥散规则。

## 7. 脱糖规则

### 7.1 模板 when 脱糖

`when(t in _)` 在解析层脱糖（Parser.kt:1508—1516）：主题是中缀 `in` 调用且右操作数是 `_` 时，`templateBase = t`、主题置空，每个分支模式 `p` 变成分支条件 `in(t, p)`：

$$\frac{\vdash t : \tau}{when(t\ in\ \_)\ \{ p_1 => b_1 \dots p_n => b_n \} \rightsquigarrow when\ \{ in(t,p_1) => b_1 \dots in(t,p_n) => b_n \}} \quad (\text{D-TEMPLATE})$$

要点：

- 模式位 `p` 是表达式（区间 `0..59`、字面量、无名表达式），不是 parsePattern 的模式域。
- `_` 与 `else` 分支一样脱糖为 PatElse 兜底（Parser.kt:1527—1530）。
- 分支体解析挂 stopArrow（Parser.kt:1548），保护下一分支的 `(…)` 模式不被后缀调用吞噬。
- 模板 when 的 else/_ 分支运行期抛 InterpreterError（Evaluator.kt:714—716，cond=null），属已知限制（§10-1）。

### 7.2 ifis 脱糖

$$\frac{cond = e\ is\ P \quad (\text{IsPatExpr 哨兵})}{if (e\ is\ P)\ A\ else\ B \rightsquigarrow when(e)\ \{ is\ P => A\ [\,else => B\]\}} \quad (\text{D-IFIS})$$

哨兵仅在 if 条件解析期放行（ifIsCond，Parser.kt:1052—1056、1404—1407）；组合条件（`a is Some(e) && e > 0`）被解析期拒绝。脱糖复用 when 的全部机制：模式匹配、穷尽性提示、智能转换。无 else 时不补分支，与无 else 的 if 同义。

## 8. if 同构规则

if 与 when 同构（Checker.kt:1198—1259）。以下规则与 01 卷 §2.6 呼应，此处给出模式语义侧的细节。

### 8.1 智能转换

$$\frac{cond = x\ is\ T \qquad x \in Var}{thenFrame = \Gamma[x := T],\ \Gamma += (x : T)} \quad (\text{M-IF-SMARTCAST})$$

条件为 `x is T` 时 then 帧注入 `x : T`（Checker.kt:1206—1214），子帧遮蔽 x 的旧类型。

### 8.2 else 反收窄

$$\frac{cond = x\ is\ T \qquad \Gamma(x) = U_1 | \dots | U_m \qquad rest = \{U_j \mid U_j \not\approx T\} \qquad |rest| < m}{elseFrame = \Gamma[x := \text{if } |rest|=1 \text{ then } rest_1 \text{ else } rest_1 | \dots | rest_k]} \quad (\text{M-IF-NARROW})$$

仅当条件为类型测、目标为名字、原类型为联合且被测类型确为变体时成立（Checker.kt:1235—1246）。

### 8.3 分支类型合并

$$\frac{aD \land bD}{\tau_{if} = Nothing} \quad (\text{M-IF-BOTH-DIV}) \qquad \frac{aD \land \neg bD}{\tau_{if} = \tau_{else}} \quad (\text{M-IF-THEN-DIV})$$

$$\frac{\neg aD \land bD}{\tau_{if} = \tau_{then}} \quad (\text{M-IF-ELSE-DIV}) \qquad \frac{\neg aD \land \neg bD \land \tau_{then} \approx \tau_{else}}{\tau_{if} = unify(\tau_{then}, \tau_{else})} \quad (\text{M-IF-JOIN})$$

$$\frac{elseBlock = null}{\tau_{if} = Null} \quad (\text{M-IF-NO-ELSE})$$

其中 `aD = diverges(thenBlock)`、`bD = diverges(elseBlock)`。Nothing 在此处是底类型的相容（TypeInfer.unify 对 Nothing 返回对方类型），不是子类型推导。两支皆发散 → Nothing；无 else → Null。分支类型不一致且均不发散时报 E-TYPE-MISMATCH（Checker.kt:1252—1253）。

## 9. 解构绑定

### 9.1 元组解构

$$\frac{\tau_s = (\sigma_1, \dots, \sigma_n) \qquad |p_1..p_n| = n \qquad (bindVars(p_j, \sigma_j, nf))_{j=1..n}}{nf \vdash (x_1, \dots, x_n) := (\sigma_1, \dots, \sigma_n)} \quad (\text{M-DESTRUCT-TUPLE})$$

分量递归绑定（bindTupleVars，WhenCheck.kt:369—373）。分量数不符报 E-TYPE-MISMATCH（:259—262）。

### 9.2 构造子解构

$$\frac{\Sigma \vdash C : Ctor \qquad |fields(C)| = n \qquad (bindVars(p_j, fieldTy_j, nf))_{j=1..n}}{nf \vdash C(x_1, \dots, x_n)\ \text{解构绑定}} \quad (\text{M-DESTRUCT-CTOR})$$

字段类型经类型参数代换（ci.fields.map { it.substT(sub) }，WhenCheck.kt:296）。嵌套模式递归绑定（bindVars，:379—408），支持 `Some(Some(y))` 等多层解构。

### 9.3 lambda 解构参数

lambda 参数支持解构 `(a, b) => body`（_langfacts.md §2 G-34）。这与 01 卷 §2.3 的函数类型定型呼应：解构参数的类型由期望函数类型的参数位给出。

### 9.4 模式绑定不走拷贝

$$\frac{matchPattern(pat, subj, armFrame)}{armFrame += x := subj \quad \text{（直接引用匹配值，不拷贝）}} \quad (\text{M-PAT-BIND-DIRECT})$$

模式绑定不走 binderNeedsCopy / bindCopy。所有权/别名纪律在主题值被引入的那一次绑定上已经落实，匹配只是把既有值按字段/位置重新命名，不产生新的所有权转移点。

## 10. 分支位的蕴含加括号（stopArrow 机制）

### 10.1 停止规则

`=>` 成为程序位唯一箭头后，分支位的蕴含消歧靠解析器的停止规则（parseExpr，Parser.kt:1016—1026；parsePostfix :1173）：

$$\frac{stopArrow = true \qquad cur \in \{ARROW, DARROW\}}{parseExpr\ \text{停止}} \quad (\text{M-STOP-ARROW})$$

$$\frac{stopArrow = true \qquad cur = LPAREN \land precededBySpace}{parseExpr / parsePostfix\ \text{停止}} \quad (\text{M-STOP-SPACE-PAREN})$$

### 10.2 挂接范围

| 解析位 | stopArrow | 出处 |
|---|---|---|
| 模板 when 分支模式 | true | Parser.kt:1529 |
| 模板 when 守卫 / 值 when 守卫 | true | :1533、:1543 |
| 无主题 when 分支条件 | true | :1539 |
| 模板 when 分支体 | true | :1548（`templateBase != null`） |
| 值 when 分支体 | false | :1548（`templateBase == null`） |
| 无主题 when 分支体 | false | 同上 |
| 命题 when 分支条件 | false（angle=false，:728） | 体为 parseBlock，不受影响 |

### 10.3 已知缺口

值 when 与无主题 when 的分支体未挂 stopArrow。parsePostfix 的后缀调用分支（Parser.kt:1190）不检查空格，未挂 stopArrow 的分支体会把下一分支起始的空格-括号表达式吞成后缀调用。规避方案：分支体写 `{ … }` 块；或把 `(…)` 起始的分支前置；或后随 else 分支。

## 12. 边界与待核清单

1. **模板 when 的 else/_ 分支运行期抛错**〔实现现状〕：模板 when 的兜底分支 cond 为 null，evalWhen 的无主题路径对 cond=null 直接抛 InterpreterError（Evaluator.kt:714—716）。检查期照常判穷尽，仅运行期失败。规避：末支写覆盖全域的具体区间。
2. **表达式体吞噬下一 `(…)` 分支**〔实现现状〕：值 when 与无主题 when 的分支体未挂 stopArrow（§10.3）。模板 when 已挂，无此问题。
3. **主题绑定作用域分歧**〔待核〕：检查期把 `e` 声明进外层帧（WhenCheck.kt:119 `f.declareVar`），求值期限定在 whenFrame（Evaluator.kt:705—710）。统一方向未定；书写上目前应把主题绑定视为 when 内有效。
4. **元组/结构化主题无覆盖律静默退化**〔实现现状〕：决策 66，`(_, _) => 0` 也不被认作穷尽，要值类型不退化须写 else。
5. **命题 when 的公共性按渲染串**〔实现现状〕：等价但不同形的结论不回注（Checker.kt:684—691）。
6. **模式变量是否需要按字段类型追加 @mut/@ref 视图传播**〔待核〕：源码未体现，当前模式绑定直接共享匹配值。
7. **stopArrow 是否计划挂到值/无主题 when 的分支体**〔待核〕：源码无此变更迹象。
8. **跨模块枚举覆盖律**〔实现现状〕：findVisibleEnum 按可见路径查找（WhenCheck.kt:435—442），跨模块枚举参与覆盖律；多模块同名构造子歧义取第一个命中（文档记限制）。

凝华的 when 共有**三种形态**，分属两个层面：

| 形态 | 层面 | 语法 | 解析入口 | 运行期 |
|---|---|---|---|---|
| 值 when | 值（表达式） | `when(x) { pat => body }`、`when { cond => body }`、`when(var e = t) { … }` | parseWhen（Parser.kt:1492） | 逐分支匹配/求值 |
| 模板 when | 值（脱糖） | `when(t in _) { p => body }` | parseWhen + S-8 脱糖（:1508-1516） | 同无主题 when |
| 命题 when | 命题（语句） | `when[p ∨ q] { p => {…} }` | parseWhenProp（Parser.kt:720） | **空转**（求值为 Null，体不执行） |

三者共用分支分隔符 `=>`（修正案后 `->` 全位非法）；**不是**同一条产生式的三种用法——它们的判断式系统各自独立（§1、§8）。

## 1. when 的三种形态

### 1.1 值 when（W-VAL）

解析（parseWhen，Parser.kt:1492-1554）：主题位有三种取舍——`when(x)`（主题表达式）、`when(var e = t)`（绑定式主题）、`when { … }`（无主题，分支位是布尔条件）；分支形态 `pat => body`、`pat if guard => body`、`_ => body`、`else => body`。

$$rac{dash e : 	au qquad 	ext{各 } pat_i Rightarrow body_i 	ext{ 对 } 	au 	ext{ 合法}}{dash when(e) { pat_1 => body_1 dots pat_n => body_n } : 	au'} quad (	ext{W-VAL})$$

其中 `τ'` 由穷尽性判定决定（§4）。无主题形态把分支位从模式换成条件：

$$rac{Gamma dash cond_i : Bool qquad 	ext{无主题、不绑定}}{dash when { cond_1 => body_1 dots } : 	au'} quad (	ext{W-NOSUBJ})$$

无主题分支在 AST 里以哨兵模式承载（WhenArm.cond + PatCond，Ast.kt:486-515；Parser.kt:1537-1540）——**模式匹配机制不参与**，`PatCond` 在 bindPattern 中恒取 `⊤`（WhenCheck.kt:228）。

绑定式主题（指导§51、Kotlin 风格）：

$$rac{Gamma dash t : 	au qquad Γ' = Γ, e := 	au, (e = t), (e : 	au)}{dash when(var e = t) { … }} quad (	ext{W-SUBJ-BIND})$$

检查期把 `e` 声明进**外层帧** `f`（WhenCheck.kt:118-122），并注入等式与类型测两条命题；求值期则把 `e` 限定在 whenFrame 子帧（Evaluator.kt:705-710）。这一作用域分歧是本会话实测发现的已知差异（§12-3）。

### 1.2 模板 when（W-TEMPLATE）

`when(t in _)` 在解析层脱糖（S-8、D-17，Parser.kt:1508-1516）：主题是中缀 `in` 调用且右操作数是 `_` 时，`templateBase = t`、主题置空，每个分支模式 `p` 变成分支条件 `in(t, p)`：

$$rac{dash t : 	au}{when(t in _) { p_1 => b_1 dots p_n => b_n } ightsquigarrow when { in(t,p_1) => b_1 dots in(t,p_n) => b_n }} quad (	ext{W-TEMPLATE})$$

要点：

- 模式位 `p` 是**表达式**（区间 `0..59`、字面量、无名表达式），不是parsePattern 的模式域——这是区间进入 when 的唯一通道（§2.5）；
- `_` 与 `else` 分支一样脱糖为 PatElse 兜底（Parser.kt:1527-1530）；
- 分支体解析挂 stopArrow（Parser.kt:1548），保护下一分支的 `(…)` 模式不被后缀调用吞噬（§6）；
- 模板 when 的 `_`` 只是脱糖标记，**不存在** `D-RANGE-INFER`「_ 推断为区间」诊断（旧 10-诊断码.md 残留条目；全源码 grep 无此码，实测）。

### 1.3 命题 when（W-PROP）

语句层产生式（Parser.kt:639 分派、720-737 解析）：

```
whenProp ::= 'when' '[' Expr ']' '{' { whenPropArm } '}'
whenPropArm ::= Expr ['=>'] Block          // 分支箭头可选（Parser.kt:729-730）
```

判断式见 §8。此处先记一条**修订性事实**：boring doc/形式化文法.md §6.1 断言「WhenPropStmt 是语法上的死产生式（v3.0）」——该结论系 v4 之前的 `->` 分隔符时期所测。本会话以当前源码实测：`when[p ∨ q] { p => { ∵ p, (p → s) ∴ s } q => { ∵ q, (q → s) ∴ s } }` 在 axiom 供给析取前提后 **check 通过并产出 D-WHEN-PROP**（tmp-when-probe5.subs，实测）。v4 把分支箭头改为 `=>` 后，分支条件解析在 `=>` 前自然终止，旧文档描述的失效模式已不复存在；结论以源码与本会话实测为准（形式化文法.md 该节为过时记载）。

## 2. 模式语法域（parsePattern，Parser.kt:1556-1654）

```
Pattern ::= 'is' Type ['as' IDENT]            PatIs    (:1606-1608)
          | 'is' Ctor '(' Pattern {',' Pattern} ')'   PatCtor（解构，:1588-1605）
          | 'is' EnumPath '::' Ctor ['(' … ')']       PatCtor（复合名，:1563-1585）
          | 'else'                               PatElse  (:1610-1613)
          | '(' Pattern {',' Pattern} ')'         PatTuple (:1615-1622)
          | INT | STR                            PatLit   (:1624-1625)
          | IDENT                                见下
IDENT 分支：'_' → PatBind("_")；'E::A' ['(' ')'] → PatCtor 复合名；
            'A(' ')' → PatCtor 空参（仅值比较）；裸名 → PatCtor(nm, []) ——
            与无参构造子/绑定变量同形，由语义层按符号表判定（:1626-1652）
```

### 2.1 模式的良构判断式

$$rac{findVisibleCtor(C) = ci qquad ci.fields 数 = |p_1..p_n|}{Γ ⊢ is C(p_1, dots, p_n) Pat 	ext{ 对 } τ} quad (	ext{W-PAT-CTOR})$$

$$rac{类型类表无 T qquad τ 与 T 相容（联合主题时 T ∈ variants）}{Γ ⊢ is T [as x] Pat 	ext{ 对 } τ} quad (	ext{W-PAT-IS})$$

类型类不能作 is 模式（无运行时 tag，E-TYPE-MISMATCH，WhenCheck.kt:243-250）。

### 2.2 裸名歧义（W-PAT-NAME）

解析层无法区分「无参构造子」与「绑定变量」——一律产 `PatCtor(nm, [])`，由语义层二次判定：

$$rac{findVisibleCtor(nm) = ci}{nm 	ext{ 是构造子模式}} qquad rac{findVisibleCtor(nm) = null land nm 	ext{ 无实参}}{nm 	ext{ 退化为具名绑定}  (bindPattern :286-289)} quad (	ext{W-PAT-NAME})$$

运行期同判据按首字母小写化（`isBindName`，Evaluator.kt:751-753）：小写且非 true/false/null → 绑定。故 `Cons(_, t)` 的 `t` 是绑定、`Nil` 是构造子，而大写未知名按构造子比较处理。

### 2.3 构造子解构的括号纪律

规则（Parser.kt:1642-1648，用户约定）：**带绑定/嵌套的解构必须显式 is**。`Some(x)` 直接写在分支位会被拒（「以 is 开头的构造子解构」）；不带 is 的括号模式仅允许空参值比较 `A()`。`E::A` 路径形态（v2.1）折叠为复合名 `E::A`，符号层按 `substringAfterLast("::")` 归一化解析（WhenCheck.kt:205、JsCodeGen.kt:1777）。

### 2.4 元组模式（W-PAT-TUPLE）

至少一个逗号才成元组模式，`(p)` 退化为子模式（Parser.kt:1614-1621）；分量数与主题元组元素数不符或对非元组主题使用 → E-TYPE-MISMATCH（WhenCheck.kt:259-262）。

### 2.5 区间：不在模式域（W-NO-RANGE-PAT）

**以源码为准**：parsePattern 的 token 分支里没有 RANGE / MINUS——值 when 的分支位**不接受** `0..n` 模式。本会话实测 `when(n) { 0..9 => 0 else => 1 }` 报「期望DARROW，实际'.. '」（tmp-when-probe2.subl）。区间只出现在两个**表达式位**：

1. 模板 when 的分支模式（脱糖为 `in(t, lo..hi)`，Parser.kt:1531）；
2. 无主题 when 的分支条件（`n in 0..10`，Parser.kt:1539）。

两者的穷尽性走 §4.4 的区间覆盖判定。旧文档把「区间模式」当模式域成员的写法在当前实现中不成立（标 **待核**：是否有计划把区间并入模式域——源码与 _langfacts.md 均无此迹象）。

### 2.6 兜底模式

`else` 与 `_` 同为 PatElse/PatBind 兜底（PatBind("_") 在 bindPattern 恒取 ⊤，WhenCheck.kt:229-234）。注意模板 when 里 `_` 也被归一为 PatElse（Parser.kt:1530）。

## 3. 分支命题与匹配判断式（bindPattern，WhenCheck.kt:211-317）

每个分支产生一条**分支命题** `bp`（指导§63），并往分支帧 `nf` 注入可用的等式（保持 ground，体内引用绑定变量）；returned 给穷尽析取的命题才 ∃ 封闭（I-14）。

$$rac{}{bp(PatElse) = ⊤} quad (	ext{M-ELSE}) qquad rac{}{bp(PatBind(x)) = ⊤ qquad nf ⊢ x := τ land nf += (subj = x)} quad (	ext{M-BIND})$$

$$rac{}{bp(PatLit(l)) = (subj = l)} quad (	ext{M-LIT}) qquad rac{}{bp(PatIs(T)) = (subj : T) qquad nf ⊢ [x := T]} quad (	ext{M-IS})$$

$$rac{term, x̄ = patternTerm(p)}{bp = ∃x̄. (subj = term) qquad nf += (subj = term) 	ext{（ground）}} quad (	ext{M-CTOR / M-TUPLE})$$

其中 PatCtor 的 `term` 是 `C(term_1, …, term_k)`、PatTuple 的 `term` 是 `(term_1, …, term_k)`；`x̄` 收集全部绑定位点（`_` 也分配新鲜量化名 `__w{n}`，否则与覆盖律形状不同构、alphaEq 失配 → 误判非穷尽，I-14，WhenCheck.kt:340-344）。

配套事实（WhenCheck.kt:269-315）：

- **Cons/SetCons 头部注入**：`in(h, subj)`——Cons(h, t) 匹配后头部元素 `h` 属于主题列表，供 forEach 的上文 `in<h, xs>` 消费（:306-311）；
- **类型测入帧**：`(subj : 枚举名)` 供分支体内类型收窄（:303-304）；
- **单射性**（M-INJECTIVE）：`C(a) = C(b) → a = b` 由等式链代换支撑（ArithProve 等式通道），嵌套穷尽判定依赖它；
- **P9 血缘登记**（决策 44）：模式绑定的名字登记为 subj 的结构子项（structSub），递归自检查据此放行真实的结构递归（:220-225）。

### 3.1 顺序否定（W-SEQ-NEG）

when 是**顺序敏感**的（指导§66）：第 i 分支的分支帧注入前 i−1 个分支命题的否定。

$$rac{Γ_i = Γ, ¬bp_1, dots, ¬bp_{i-1}}{Γ_i ⊢ body_i} quad (	ext{W-SEQ-NEG})$$

故 `when(p) { (0, 0) => A (a, b) => B }` 的第二分支里 `¬(p = (0, 0))` 作为前提可用（元组主题的等式否定）。这条否定累积对穷尽性判定**不**参与——穷尽目标只取各分支正命题的析取（WhenCheck.kt:164-168）。

### 3.2 守卫在分支命题中的合成（W-GUARD-PROP）

$$rac{bp_0 	ext{ 已注入 } nf qquad nf ⊢ guard : Bool}{bp = egin{cases} guard & bp_0 = ⊤ \ bp_0 ∧ guard & 	ext{ otherwise} end{cases}} quad (	ext{W-GUARD-PROP})$$

检查期守卫**先于求值**看到分支命题（nf.inject(bp0)，WhenCheck.kt:147）——守卫里可以引用模式绑定的变量。守卫还从穷尽性吸收中**除名**（§4.3）。

## 4. 穷尽性判断（coverage）

### 4.1 主判据（决策 43）

$$rac{Γ ⊢* bp_1 lor bp_2 lor dots lor bp_n quad 	ext{（析取恒真）}}{when 	ext{ 穷尽} qquad τ' = unify(τ_{b_1}, dots, τ_{b_n})} quad (	ext{M-EXHAUSTIVE})$$

$$rac{Γ 
vdash* bp_1 lor dots lor bp_n qquad 	ext{（含 } sawCatchAll 	ext{ 与空分支表两种快捷穷尽）}}{when 	ext{ 非穷尽} qquad τ' = unsealedT 	ext{（仅与 Null 相容）}} quad (	ext{M-NON-EXHAUSTIVE})$$

快捷通道（WhenCheck.kt:164）：`sawCatchAll`（某分支 bp=⊤ 且无守卫）、分支表为空。类型规则：

$$rac{when 	ext{ 穷尽}}{τ_{when} = τ_{b_1} mid dots mid τ_{b_n}} quad (	ext{M-TYPE-SEALED}) qquad rac{when 	ext{ 非穷尽}}{τ_{when} = unsealedT} quad (	ext{M-TYPE-UNSEALED})$$

非密封值流向函数声明的非 Null 返回类型时由 E-NON-SEALED-MATCH 兜住（Checker.kt:401-403）；作为语句使用（值丢弃）合法。

### 4.2 穷尽性是提示，不是要求（决策 66）

判不出穷尽的 when 固定按 Null 处理，**不阻断编译**：

| 情形 | 诊断 | 值类型 |
|---|---|---|
| 主题有覆盖律（名义枚举）却覆盖不全 | `W-NON-EXHAUSTIVE`（WhenCheck.kt:176-177） | unsealedT |
| 无主题 / 模板 when 判不出 | `W-NON-EXHAUSTIVE`（门控含 `e.subject == null`，:176） | unsealedT |
| 主题无覆盖律（元组、函数类型等） | **静默退化，不警告**（:176 门控不命中） | unsealedT |

即「没有 W-NON-EXHAUSTIVE」不等于「已穷尽」——元组主题永远静默（CheckerTest 560-565）。

### 4.3 覆盖律与绑定式吸收

**覆盖律**（决策 49/64）按主题的**具体类型**就地深展开（不用全局 ∀，泛型枚举 Optional vs Optional[Nat] 会失配，工程规范 I-3）：

$$rac{findVisibleEnum(τ) ≠ null qquad shapes = coverShapes(subj, τ, 3)}{cov = igvee_{s ∈ shapes} (∃s.vars. s.conjs)} quad (	ext{M-COVER-LAW})$$

`cov` 作为额外前提并入 Γ 参与穷尽证明（WhenCheck.kt:161-167）。深展开将内层单字段枚举的 `v = term` **直接代入**外层项（I-14），使覆盖形状与 bindPattern 的 ∃ 形态同构，靠 alphaEq + 析取子集匹配（嵌套模式无需 ∃-消去规则）。安全阀：深度 COVER_DEPTH=3、形状数 COVER_MAX_SHAPES=64，超限返回空 → **保守判非穷尽**——健全性方向永远正确，不会误判穷尽（WhenCheck.kt:5-9、44-47）。

**绑定式吸收**（假阳性修复，bindingCovered，WhenCheck.kt:193-208）：构造子分支实参**全为裸绑定/通配且无守卫**时，在值空间恒覆盖该构造子的全部值，与字段类型无关：

$$rac{∀ i. args_i ∈ { PatBind } ∪ { PatCtor(n,[]) mid findVisibleCtor(n) = null } qquad guard = null}{C(x_1, dots, x_k) 	ext{ 吸收 } C 	ext{ 的全部值}} quad (	ext{M-BIND-COVERED})$$

故 `is Some(xs)` + `None` 即穷尽；反之：嵌套模式 `is B(is Leaf(x))` 不吸收（实参不全为绑定），带字面量 `is Some(0)` 保守判非穷尽，**守卫破坏吸收**（守卫缩小匹配集）。

**联合主题密封**（v2.0 和类型）：无守卫 is 分支覆盖联合主题全部变体 → 穷尽（WhenCheck.kt:171-174）；else 分支同时把联合主题反收窄为剩余变体（:139-143）。

### 4.4 区间覆盖判定（模板/无主题 when）

穷尽目标仍是分支命题析取，但分支命题是 `in(t, lo..hi)` 原子；可证性交给**线性算术通道**（ArithProve）：

$$rac{Γ ⊢ t ∈ (L..H) qquad 	ext{各分支区间排序后首尾衔接：} l_1 = L land h_n = H land ∀i<n. l_{i+1} = h_i + 1}{Γ ⊢* igvee_i in(t, l_i..h_i)} quad (	ext{M-RANGE-EXHAUST})$$

全域 `(L..H)` 由 Γ 组合而来，不靠用户手写：`Nat` 局部/字段自动注入下界 `n ≥ 0`（Checker.kt:600-603、495-500），上界来自函数上文（`fun f(n: Nat)<n ≤ 30>`）或结构体伴生命题。本会话实测：

```
fun d(n: Nat)<n ≤ 30>: Str = when {
  n in 0..10 => "a"
  n in 11..20 => "b"
  n in 21..30 => "c"
}
```

run-script 输出 `b` 且**无** W-NON-EXHAUSTIVE（tmp-wl.subs，实测）——三段区间无缝覆盖全域 [0, 30]，纯属算术通道裁决，与模板形态同源（show/解释器/mathproof.subs 的 gradeChar 同款，InterpreterTest.kt:440）。区间有缝或缺端点则落回 M-NON-EXHAUSTIVE（对无主题/模板 when 发警告）。

### 4.5 运行期退化（Null，不抛异常）

$$rac{	ext{无任何分支匹配}}{eval(when) = Null qquad 	ext{不抛异常}} quad (	ext{W-RT-NULL})$$

解释器固定返回 ScriptValue.Null（Evaluator.kt:723）；JS 生成在分支链尾追加 `return null;`（JsCodeGen.kt:1751，注释「穷尽时不可达，语义层已保证」）。

## 5. 守卫的运行期语义

$$rac{matchPattern(pat, subj, armFrame) = true qquad truthy(eval(guard, armFrame)) = true}{evalArm_i := eval(body_i, armFrame)} quad (	ext{W-GUARD-RT})$$

$$rac{matchPattern = true qquad truthy(guard) = false}{跳过本分支（continue），	ext{不回溯前面分支}} quad (	ext{W-GUARD-SKIP})$$

要点（Evaluator.kt:711-721）：

1. **先匹配、后守卫**：守卫在 armFrame 求值，此时模式变量已绑定——守卫可以引用绑定变量（`is Some(v) if v > 0 => v`，实测 first(Some(0))=0 → 守卫失败落到下一分支）；
2. **守卫不改变分支选择的前进方向**：守卫失败只是跳过本分支，主题值已被消费，不会回到上一分支重试；
3. **守卫是值位**：守卫表达式按值表达式检查与求值（examples/模式匹配.subl:29 注释「用 != 前缀调用与 &，不用命题算符」）；
4. **代码生成的绑定/守卫次序**：`if (cond) { binds; if (guard) return body; }`——必须先绑定再判守卫，否则守卫引用不到模式变量（JsCodeGen.kt:1740-1746）；
5. **检查期**：守卫先看到分支命题（§3.2），守卫命题 conjunction 进穷尽析取，同时把该分支从绑定式吸收中除名（§4.3）。

## 6. 分支位的蕴含加括号（stopArrow 机制）

### 6.1 机制

`->` 既被修正案全位非法化、`=>` 成为程序位唯一箭头后，分支位的蕴含消歧靠解析器的停止规则（parseExpr，Parser.kt:1016-1026；parsePostfix :1173）：

$$rac{stopArrow = true qquad cur ∈ {ARROW, DARROW}}{parseExpr 	ext{停止}} quad (	ext{S-ARROW}) qquad rac{stopArrow = true qquad cur = 	ext{'(' 且 precededBySpace}}{parseExpr / parsePostfix 	ext{停止（防后缀调用吞下一分支的 } (dots) 	ext{ 模式）}} quad (	ext{S-SPACE-PAREN})$$

`stopIdents`（Parser.kt:31、1024）是同族机制，但只服务于命题位 if-then-else 的 then/else 停止词，与 when 无关。

### 6.2 挂接范围（以源码为准）

| 解析位 | stopArrow | 出处 |
|---|---|---|
| 模板 when 分支模式 | ✓ | Parser.kt:1529 |
| 模板 when 守卫 / 值 when 守卫 | ✓ | :1533、:1543 |
| 无主题 when 分支条件 | ✓ | :1539 |
| 模板 when 分支体 | ✓ | :1548（`parseBranchBody(stopArrow = templateBase != null)`） |
| **值 when 分支体** | ✗ | :1548 同式——templateBase==null 即 false |
| **无主题 when 分支体** | ✗ | 同上 |
| 命题 when 分支条件 | ✗（parseExpr(angle=false)，:728） | 但体为 parseBlock，不受影响 |

### 6.3 实测缺口：表达式体吞噬下一 `(…)` 分支

因为 parsePostfix 的后缀调用分支（Parser.kt:1190）**不检查空格**，未挂 stopArrow 的分支体会把下一分支起始的空格-括号表达式吞成后缀调用：

- 值 when：`when(p) { (0, 0) => 1 (a, b) => a }` → 报「期望模式，实际'=>'」（tmp-wf.subs，实测）——体 `1` 被解析成调用 `1(a, b)`，下一分支从 `=>` 起始；
- 无主题 when：`when { n > 10 => "a" (n in 0..10) => "b" }` → 报「期望表达式，实际'=>'」（tmp-wh.subs，实测）。

**模板 when 无此问题**（体挂 stopArrow，S-SPACE-PAREN 生效，故 grade 的 `(0..59) => "F" (60..100) => "P"` 连写合法，实测）。规避方案（实测 we：用 `{ … }` 块体即可）：

- 分支体写 `{ … }` 块（parseBlock 有明确 RBRACE 边界）；
- 或把 `(dots)` 起始的分支**前置**（首分支无条件前驱，不受吞噬）；
- 或后随 `else` 分支（PatElse 以关键词起始，不是括号）。

这是当前实现的解析不对称（标 **待核**：是否计划把 stopArrow 一并挂到值/无主题 when 的分支体——源码无此变更迹象）。

## 7. 绑定走拷贝判据

### 7.1 四条规则（修正案）

binderNeedsCopy（Checker.kt:838-846）与脚本模式 Evaluator.bindCopy（Evaluator.kt:112-119）是**同一判据**：

$$rac{}{copy iff ig(target{∈}mut land (¬target{∈}ref lor src pure)ig) lor ig(src{∈}mut land target pureig) lor ig(src{∈}ref land ¬target{∈}refig)} quad (	ext{W-COPY})$$

$$rac{copy = false}{目标与源共享同一对象（别名）} quad (	ext{W-ALIAS})$$

四条款口语化：① 目标 @mut 且（不带 @ref 或源纯）→ 深拷；② 源 @mut 且目标纯 → 深拷；③ 源带 @ref 且目标不带 @ref → 冻结快照；其余（不可变互传、@mut 绑到 @ref、@ref 互别名）共享。

### 7.2 拷贝点与模式绑定的关系

拷贝发生在**引入绑定的位**：VarStmt（Evaluator.kt:166-167）、AssignStmt（:174-175）、声明即表达式 VarExpr（:246）。深拷贝对结构体/列表/Optional/Result 逐字段递归，对**函数闭包一并深拷捕获变量**（deepCopy → ClosureFun.copyCapture + copiedFrame 沿父链，Evaluator.kt:130-158）；JS 侧 `__dc` 对函数**穿透**为既定边界。

模式绑定**不走 bindCopy**：

$$rac{matchPattern(pat, subj, armFrame)}{armFrame += x := subj 	ext{（直接引用匹配值，不拷贝）}} quad (	ext{W-PAT-BIND-DIRECT})$$

主题绑定亦同（evalWhen 声明进 whenFrame 时直接赋主题值，Evaluator.kt:708-710）。所有权/别名纪律在**主题值被引入的那一次绑定**上已经落实——匹配只是把既有值按字段/位置重新命名，不产生新的所有权转移点。若主题本身来自 @mut 绑定，模式变量与主题共享同一对象的语义与 W-ALIAS 一致（标 **待核**：模式变量是否需要按字段类型追加 @mut/@ref 视图传播——源码未体现）。

### 7.3 主题绑定的检查/求值作用域分歧（实测）

检查期把 `e` 声明进外层帧（WhenCheck.kt:119 `f.declareVar`），求值期限定在 whenFrame（Evaluator.kt:705-710）。实测：

```
fun g(n: Nat): Nat {
  when(var e = n) { is Nat => 0 }
  return e        // 检查通过，运行期报「未定义的变量 e」
}
```

check 通过、run-script 抛「未定义的变量『e』」（tmp-when-probe6.subs，实测）——检查器的作用域比解释器宽，属已知分歧（标 **待核**：统一方向未定；书写上目前应把主题绑定视为 when 内有效）。

## 8. 命题 when 的证明义务

命题 when 是**编译期语句**：检查分支体、产出公共结论注入 Γ；运行期空转为 Null（Evaluator.kt:191；JsCodeGen.kt:796/1514 生成空），**分支体永不在运行期执行**。

### 8.1 析取前提义务（W-PROP-DISJ）

$$rac{Γ 中无命题 q 	ext{（按渲染串比对，} PropLogic.render 	ext{）}}{warn W	ext{-}PROP	ext{-}UNBOUND 	ext{（分)}]} quad (	ext{W-PROP-DISJ})$$

`when[p ∨ q]` 的析取式必须**已在 Γ 中**（Checker.kt:660-662，按渲染串全等比对，非证等价）。供给方式：`axiom (p ∨ q)`、上文弥散、∵∴ 链等。

### 8.2 分支证明义务（W-PROP-ARM）

$$rac{Γ_i = Γ, 	ext{析取支}_i qquad body_i ⊢ ∴ q_i}{	ext{分支 } i 	ext{ 证明义务达成}} quad (	ext{W-PROP-ARM})$$

每支在子帧注入**自己那一条析取支**（af.inject，Checker.kt:667），分支体的 ∵∴ 语句照常走 E-PREMISE-UNPROVEN / E-CANNOT-PROVE——即分支条件须在该支假设下**可证**。注意注入的是分支条件 `arm.condition` 这个命题，而不是析取式中的对应支——写 `when[p ∨ q]` 时通常两者同形。

### 8.3 公共结论回注（W-PROP-COMMON）

$$rac{∀ i. q_i 	ext{ 的渲染串集合有交集}}{Γ += igcap_i props(body_i) 	ext{（按渲染串求公共结论）} qquad supplement D	ext{-}WHEN	ext{-}PROP} quad (	ext{W-PROP-COMMON})$$

$$rac{	ext{公共结论为空}}{warn W	ext{-}WHEN	ext{-}NO	ext{-}COMMON 	ext{（警告级，不阻断）}} quad (	ext{W-PROP-NO-COMMON})$$

公共性按 **∏ 命题渲染字符串** 集合交计算（Checker.kt:664-681）：各支结论必须**逐字同一个命题**才回注，证出等价但不同形不算（wiki/03-证明-公理语句axiom.md 的实测先例同此）。分支体中只有 BTSStmt（∴）的结论进入候选。

### 8.4 完整示例（本会话实测 check 通过）

```
fun h(p: Bool, q: Bool): Bool {
  axiom (p ∨ q)          // 供给析取前提，免 W-PROP-UNBOUND
  axiom (p → s)
  axiom (q → s)
  when[p ∨ q] {
    p => { ∵ p, (p → s) ∴ s }
    q => { ∵ q, (q → s) ∴ s }
  }
  return true            // 命题 when 运行期空转，返回值另给
}
```

实测诊断输出（-v）：两支各 `D-BTS: ∵…∴ s 成立`，语句位 `D-WHEN-PROP: 分类讨论得出共同结论：s`，无 W-PROP-UNBOUND / W-WHEN-NO-COMMON（tmp-when-probe5.subs）。若两支各证自己的析取支（`∴ p` / `∴ q`），公共结论为空 → 只发 W-WHEN-NO-COMMON、什么也不注入（wiki/03-证明-证明链.md 实测同款）。

### 8.5 命题 when 的分支位书写注意

分支条件以 parseExpr(angle=false) 解析（无 stopArrow，Parser.kt:728）：v4 `=>` 分隔符下，`p → q => {…}` 的蕴含右操作数止于 `q`，体 `{…}` 正常进 parseBlock（实测 wk：可解析可检查）。唯一残余风险是**蕴含右操作数直接以 `{` 开头**（`p → {…} => …` 会被 lambda 糖吞）——给整个条件加括号即可（`(p → q) => {…}`，实测 wi）。

## 12. 已知限制与实测缺口（本会话验证）

1. **模板 when 的 else/_ 分支运行期抛错**（实测 tmp-when-probe4.subs）：模板 when 的兜底分支 cond 为 null，evalWhen 的无主题路径对 cond=null 直接抛 InterpreterError「无主题 when 的分支必须有 cond」（Evaluator.kt:714-716）。检查期照常判穷尽、**仅运行期失败**。规避：末支写覆盖全域的具体区间（mathproof.subs 的 gradeChar 同款），不用 else。
2. **表达式体吞噬下一 `(…)` 分支**（§6.3，实测）：值 when 与无主题 when 的分支体未挂 stopArrow；模板 when 已挂。
3. **主题绑定作用域分歧**（§7.3，实测）：checker 外层帧 vs 解释器 whenFrame。
4. **元组/结构化主题无覆盖律静默退化**（决策 66，CheckerTest 560-565）：`(_, _) => 0` 也不被认作穷尽，要值类型不退化须写 `else`。
5. **命题 when 的公共性按渲染串**：等价但不同形的结论不回注（Checker.kt:670）。
6. **区间不在模式域**（§2.5，实测）：值 when 分支位写 `0..n` 是语法错。
7. **守卫破坏绑定式吸收**（WhenCheck.kt:197）：带守卫的构造子分支须重新数穷尽性。
8. 形式化文法.md §6.1「命题 when 是死产生式」结论已过时（§1.3 实测推翻）；该文档若修订应以此为准。

## 13. 书写建议

1. 分支分隔符一律 `=>`；分支位要写蕴含就加括号（`(p → q) => …`），把停止语义握在自己手里；
2. 值/无主题 when 的分支体尽量用 `{ … }` 块（提前 return、表达式体吞噬括号分支两便）；括号起始的分支（元组、区间括起）前置或尾随 else；
3. 区间判断放进 `when(n in _)` 或无主题 `when { n in a..b => … }`，全界写进命题（`<n ≤ 100>` 上文 / Nat 下界），让算术通道证覆盖，不要靠 else 兜底——模板 when 的 else 运行期会抛（§12-1）；
4. 穷尽是提示不是要求：枚举主题补全构造子或加 else；元组主题主动写 else；把「没有 W-NON-EXHAUSTIVE」当「已穷尽」是错的；
5. 守卫是值位：用 `!=`、`&` 这类值表达式，不要把 `∧`/`→` 写进守卫；守卫可引用模式绑定变量；
6. 命题 when 运行期空转：只用来推导编译期结论；析取前提用 axiom 供给，各支必须证出**同一个**结论才回注；
7. 模式绑定直接共享匹配值：需要独立副本时在引入主题值的那次 var 绑定上落实 @mut/@ref（拷贝判据 §7.1），别指望匹配位再拷一次。

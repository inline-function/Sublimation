# 第四卷 · 命题与证明

> 本卷规定凝华的命题世界：命题的语法与表示、内建命题、自定义命题、量词、自动证明器的判定规则、手动证明语句、定理函数与策略。
> 本卷的规则必须满足总纲公理三（健全但不完备）与不变量 I-1（健全性）。

## 1. 命题的地位

### 1.1 两个世界

依总纲公理二，凝华区分值世界与命题世界。命题世界的特征：

| 属性 | 命题世界 | 值世界 |
|---|---|---|
| 是否可求值 | 否 | 是 |
| 是否可打印 | 否 | 是 |
| 是否可作为实参 | 否（除命题参数） | 是 |
| 是否进入生成代码 | **否** | 是 |
| 居住位置 | 上下文 Γ | 运行时环境 |
| 判定方式 | 编译期证明 | 运行时求值 |

### 1.2 上下文中的表达式

上下文中可以书写表达式，但这些表达式**不运行，也不能运行**——它们只表示**结构**。

```subl
print(1 + 2)
```

写在上下文中时，它其实是：

```
CallExpr(NameRef("print"), [BinExpr("+", IntLit("1"), IntLit("2"))])
```

即一棵语法树。两个上下文中的表达式相同，当且仅当它们的语法树结构相同。

由此得到**结构相等**的基本事实：

$$\frac{e \text{ 是纯表达式}}{\vdash e = e} \quad (\text{P\_REFL-PURE})$$

```subl
1 + 2 = 1 + 2          // 可证：结构相同
1 + 2 = 2 + 1          // 不可直接证：结构不同，需要定理
```

### 1.3 纯度的影响

不止函数有**纯度**，实际上所有表达式都有纯度。纯的表达式称为**纯表达式**，例如 `1 + 1`；不纯的表达式例如 `print("ok")`。

**如果表达式不纯，则不能通过结构相同认为它们相同**：

$$\frac{e \text{ 含不纯调用}}{e = e \text{ 不可证（除非它被显式注入 } \Gamma\text{）}} \quad (\text{P\_IMPURE-NO-REFL})$$

即：`print("ok") = print("ok")` 不可证，连自反也不承认。

这一规则的实现判据是「表达式是否含 `@impure` 函数的调用」。含有则其一切比较命题（`=`、`==`、`!=`、`≠`、`<`、`>`、`<=`、`≤`、`>=`、`≥`）都只能通过 Γ 中的显式事实匹配，不走结构相等通道。

同理，可变变量只承认自反，不承认它与其他表达式的相等命题（第六卷 §3）。

### 1.4 纯命题

纯函数有**自然命题** `pure<f>`。不止具名函数，lambda 表达式也可以被证明纯，因为函数的名字本身指代的就是函数本身——一个函数类型的变量：

```subl
pure<f>
pure<{ 1 + 1 }>
```

持有 `pure<f>` 的后果：即使 `f` 标注了 `@impure`，在纯作用域调用 `f` 也被放行（第六卷 §2.3）。

## 2. 命题的语法与表示

### 2.1 内建命题

内建命题是编译器内置的命题，它们**涉及类型与命题**，并构成命题世界的逻辑骨架：

| 名称 | 命题 | 表述 | 表示 |
|---|---|---|---|
| 蕴含 | `p → q` | 若 p 则 q | `PImp(p, q)` |
| 等价 | `p ↔ q` | p 当且仅当 q | `PIff(p, q)` |
| 否定 | `¬<p>` | 非 p | `PNot(p)` |
| 合取 | `p ∧ q` | p 且 q | `PAnd(p, q)` |
| 析取 | `p ∨ q` | p 或 q | `POr(p, q)` |
| 为 | `e : T` | e 具有类型 T | `PAtom(":", [e, T])` |
| 真 | `⊤` | 恒真 | `PTop` |
| 假 | `⊥` | 恒假 | `PBot` |
| 全称 | `∀x . p` | 对所有 x，p | `PForall([x], p)` |
| 存在 | `∃x . p` | 存在 x 使 p | `PExists([x], p)` |
| 唯一存在 | `∃!x . p` | 存在唯一 x 使 p | `PExists1([x], p)` |

**「为」命题 `e : T` 是内建命题中特殊的一个**：它把类型世界的归属关系提升为命题。因此类型事实可以作为推理的前提与结论参与证明。

### 2.2 命题的规范化表示

全部命题归约为如下十一形态之一：

```
Prop = PTop
     | PBot
     | PNot   ⟨ p : Prop ⟩
     | PAnd   ⟨ a : Prop, b : Prop ⟩
     | POr    ⟨ a : Prop, b : Prop ⟩
     | PImp   ⟨ a : Prop, b : Prop ⟩
     | PIff   ⟨ a : Prop, b : Prop ⟩
     | PForall  ⟨ names : List<String>, body : Prop ⟩
     | PExists  ⟨ names : List<String>, body : Prop ⟩
     | PExists1 ⟨ names : List<String>, body : Prop ⟩
     | PAtom    ⟨ head : String, terms : List<Expr> ⟩
```

`PAtom` 承载**一切原子命题**：

| 形态 | head | terms |
|---|---|---|
| 零元命题 `p` | `"p"` | `[]` |
| 参数化命题 `valid<7>` | `"valid"` | `[7]` |
| 比较命题 `a = b` | `"="` | `[a, b]` |
| 类型归属 `e : T` | `":"` | `[e, T]` |
| 成员命题 `x ∈ xs` | `"in"` | `[x, xs]` |
| 伴生命题 `f<a, b>` | `"f"` | `[a, b]` |
| 返回值指代 `$` | `"$"` | `[]` |

### 2.3 表达式到命题的转换

```
P-CONV：Expr → Prop
```

转换规则按表达式的形态分派：

$$\frac{}{\text{fromExpr}(\top) = \text{PTop}} \quad (\text{PC-TOP})$$

$$\frac{}{\text{fromExpr}(\bot) = \text{PBot}} \quad (\text{PC-BOT})$$

$$\frac{}{\text{fromExpr}(\$) = \text{PAtom}(\text{"\$"}, [])} \quad (\text{PC-DOLLAR})$$

$$\frac{}{\text{fromExpr}(\$n) = \text{PAtom}(\text{"\$n"}, [])} \quad (\text{PC-PARAMREF})$$

$$\frac{}{\text{fromExpr}(\lnot e) = \text{PNot}(\text{fromExpr}(e))} \quad (\text{PC-NOT})$$

```
fromExpr(a → b) = PImp(fromExpr(a), fromExpr(b))          (PC-IMP)
fromExpr(a ↔ b) = PIff(fromExpr(a), fromExpr(b))          (PC-IFF)
fromExpr(a ∧ b) = PAnd(fromExpr(a), fromExpr(b))          (PC-AND)
fromExpr(a ∨ b) = POr(fromExpr(a), fromExpr(b))           (PC-OR)

fromExpr(a ○ b) = PAtom(○′, [a, b])    ○ ∉ {→, ↔, ∧, ∨}   (PC-BIN)
                 其中 ∈ 归一为 in：○′ = if(○ = ∈) "in" else ○
```

$$\frac{}{\text{fromExpr}(\text{NameRef}(n)) = \text{PAtom}(n, [])} \quad (\text{PC-NAME})$$

```
fromExpr(n<t₁…tₖ>) = PAtom(n, [t₁…tₖ])                    (PC-INST)

fromExpr(⊙(a₁…aₖ)) = PAtom(⊙, [a₁…aₖ])   ⊙ 是符号标识符  (PC-SYMCALL)

fromExpr(f(a₁…aₖ)) = PAtom(f, [a₁…aₖ])                    (PC-CALL)

fromExpr(∀x⃗ . p) = PForall(x⃗, fromExpr(p))               (PC-FORALL)
fromExpr(∃x⃗ . p) = PExists(x⃗, fromExpr(p))               (PC-EXISTS)
fromExpr(∃!x⃗ . p) = PExists1(x⃗, fromExpr(p))             (PC-EXISTS1)
```

$$\frac{}{\text{fromExpr}(e) = \text{PAtom}(\text{"\_\_t\_\_"}, [e]) \quad \text{其他一切表达式}} \quad (\text{PC-OTHER})$$

规则 `PC-BIN` 的意义：二元运算符在命题位被解释为**二元谓词**。因此中缀调用法的脱糖（第二卷 §8.3）与命题解释是自洽的——`a ∈ b` 在值层是 `in(a, b)`，在命题层是 `PAtom("in", [a, b])`，二者同构。

三个结构性哨兵 head 用于容纳无法归类的表达式：

| head | 含义 |
|---|---|
| `__t__` | 任意表达式的命题化（不参与推理） |
| `__call__` | 被调方不是名字的调用表达式 |
| `__inst__` | 实例化目标不是名字的表达式 |

### 2.4 书写形式与归一

命题记号存在 ASCII 与 Unicode 两套拼写，二者在词法层或命题层归一：

| Unicode | ASCII | 归一后 |
|---|---|---|
| `∧` | `&&`、`&` | `∧` |
| `∨` | `\|\|`、`\|` | `∨` |
| `→` | `->` | `→` |
| `↔` | `<->` | `↔` |
| `¬` | `!`、`not` | `¬` |
| `∀` | `forall` | `∀` |
| `∃` | `exists` | `∃` |
| `∃!` | `exists1` | `∃!` |
| `∈` | — | `in` |
| `≤` | — | 与 `<=` 在事实匹配时等价 |
| `≥` | — | 与 `>=` 在事实匹配时等价 |
| `≠` | — | 与 `!=` 在事实匹配时等价 |

**规范风格要求书写 Unicode 形式**，因为 `<=` 是值世界的比较函数（第一卷 §4.8）。在命题位书写 `<=` 不会构成命题比较。

### 2.5 结合性与括号要求

**命题连接词不实现优先级，全部同优先级、左结合**（第二卷 §5.3）。这一事实对命题书写有直接影响：

```subl
n >= 0 ∧ m >= 0          // 被解析为 ((n >= 0) ∧ m) >= 0，不是想要的形态
(n >= 0) ∧ (m >= 0)      // 正确：显式加括号
```

因此规范风格要求：**混用比较记号与逻辑连接词时必须显式加括号。**

### 2.6 命题括号

`<e>` 是命题括号，用于在需要命题的位置包裹表达式：

```subl
def ≠<a, b> ↔ ¬<a = b>
∀x . x ∈ list → p<x>
```

`¬` 之后若直接跟复合表达式，必须用命题括号包裹，否则否定只作用于紧随的原子。

### 2.7 位置盲

命题项的同一性**只认名字与结构，不认源位置**。语法节点携带的位置信息（用于诊断与语言服务）在进入命题世界前必须被剥离：

$$\frac{}{\text{NameRef}(n, \text{pos}_{1}) \text{ 与 } \text{NameRef}(n, \text{pos}_{2}) \text{ 是同一个命题项}} \quad (\text{P-BLIND})$$

若不剥离位置，同一变量在两处出现会被判为两个不同的项，等式推理与事实匹配全部失效。

### 2.8 α-等价

命题比较必须按**绑定变量的出现序**重命名后再比结构：

$$\frac{}{\forall x . p\langle x\rangle \equiv_\alpha \forall y . p\langle y\rangle} \quad (\text{P-ALPHA})$$

理由：穷尽性判定中的覆盖律与分支命题使用的变量名必然不同，字符串比较会误判。

新鲜名字的生成使用 `#` 前缀加计数器（`#0`、`#1`、…）。由于合法标识符不含 `#`，此形式**必然新鲜**。

## 3. 自定义命题

### 3.1 声明

```subl
def =<a, b>
def ≠<a, b> ↔ ¬<a = b>
```

自定义命题的特点：

- 它们通常**只涉及表达式和表达式之间的关系**，不涉及类型与命题；
- **不约束参数的类型**。因此可以书写荒谬的命题：

```subl
1 ∈ 2
"ok" ≥ 0
```

这些命题在语法与类型层均合法，只是无法被构造出证明——除非使用 `unchecked`。

### 3.2 等价式定义

带 `↔` 的定义给出命题的**展开式**：

$$\frac{\Sigma(p) = \text{PropDefDecl}(p, [a_{1} \dots a_{k}], \text{equiv})}{\text{目标 } \text{PAtom}(p, [t_{1} \dots t_{k}]) \text{ 可展开为 } \text{equiv}[a_{i} := t_{i}]} \quad (\text{P-DEF-EXPAND})$$

展开在证明流水线的**第一个通道**执行（§5.1），展开后以展开结果为新目标继续证明。

展开规则：

- 每次只展开**一层**，由证明入口的递归自然驱动多层展开；
- 展开次数上限为 5 层，超限停止；
- 展开必须检测自引用回环（`def p<a> ↔ p<a>` 形态），检测到即停止。

### 3.3 自定义命题与内建命题的界限

当前**不支持**自定义涉及类型或命题的命题。即自定义命题的项只能是表达式，不能写：

```subl
def 是类型<T>          // 不支持
def 是命题<p>          // 不支持
```

需要对类型或命题进行量化时，使用量词的 `#`／`@` 前缀（§4.2）。

## 4. 量词

### 4.1 量词的形态

```
∀x₁ … xₖ . p          全称量词
∃x₁ … xₖ . p          存在量词
∃!x₁ … xₖ . p         唯一存在量词
```

### 4.2 量词变量的维度

量词变量名的前缀标记其**维度**，维度决定实例化时从哪个候选池取值（§7）：

| 前缀 | 维度 | 例子 |
|---|---|---|
| 无 | 表达式维 | `∀x . x ∈ list → p<x>` |
| `@` | 命题维 | `∀@p . p ∨ ¬<p>` |
| `#` | 类型维 | `∀#T . Optional[T] ≠ T` |

`@` 前缀在量词里标记命题参数，以与值参数区分。

### 4.3 函数即全称量词的构造法

**函数本身就是一种全称量词的构造法。**

```subl
fun f(x) : <x ∈ list → p<x>>
```

声明这个函数时，编译器自动注入一个自然命题：

```
∀x . x ∈ list → p<x>
```

推广的规则：

> **函数的参数列表就是它自然全称量词命题的主语，函数的伴生命题就是它自然全称量词命题的谓语。**

$$\frac{\text{f 的签名：}\text{fun } f(x_{1} : \tau_{1}, \dots, x_{k} : \tau_{k}) \langle \text{preps} \rangle : \tau \langle \text{posts} \rangle}{\text{自然命题：}\forall x_{1} \dots x_{k} . (\bigwedge \text{preps}) \to (\bigwedge \text{posts})} \quad (\text{P-FUN-UNIVERSAL})$$

### 4.4 存在量词的构造

存在量词的构造只需找到一个元素，说它有某个命题：

```subl
∃ x = 0 . x : Nat          // 这是一句语句，写在程序里，不是在上下文中写
```

于是证明了：

```
∃ x . x : Nat
```

### 4.5 全称引入（概括规则）

证明目标 `∀x⃗ . p` 时，把绑定名替换为**新鲜常量**后证明 `p`：

$$\frac{\vec{x} \text{ 不出现在 } \Gamma \text{ 的任何事实中} \qquad \vec{c} \text{ 是新鲜常量} \qquad \Gamma \vdash p[\vec{x} := \vec{c}]}{\Gamma \vdash \forall \vec{x} . p} \quad (\text{R-FORALL-INTRO})$$

新鲜常量的形式是 `#vg{深度}_{序号}`。

**关键补充**：新鲜常量在原有闭包的实例化候选之外（闭包按 Γ 中的项收集，看不到 `#vg`）。因此必须以替换后的目标为额外目标**重算闭包**，使 Γ 中的 `∀` 事实能以这些常量为候选实例化。

例：由 `∀n m . n = m` 证 `∀a b . a = b`。先把目标替换为 `#vg0_0 = #vg0_1`，重算闭包时 Γ 中的 `∀n m . n = m` 以这两个常量为候选实例化，产出 `#vg0_0 = #vg0_1`，目标命中事实。

### 4.6 存在消去

$$\frac{\Gamma \vdash \exists x . p \qquad x \text{ 新鲜，不在 } \Gamma \text{ 与结论中出现} \qquad \Gamma, x, p \vdash q \qquad q \text{ 不含 } x}{\Gamma \vdash q} \quad (\text{R-EXISTS-ELIM})$$

存在消去在语言中通过 `∃x . p { … }` 语句实现（§6.5）。

### 4.7 存在引入

$$\frac{\Gamma \vdash p[x := t]}{\Gamma \vdash \exists x . p} \quad (\text{R-EXISTS-INTRO})$$

见证 `t` 从 Γ 的 ground 项中搜索。

### 4.8 唯一存在的分解

```
∃!x . P(x)  ⟺  ∃x . (P(x) ∧ ∀y . (P(y) → y = x))
```

证明时：对 Γ 的每个 ground 项 `c`，证明 `P(c)` 与 `∀y . (P(y) → y = c)`。

## 5. 自动证明

### 5.1 证明通道流水线

证明一个命题义务时，编译器按以下通道**依次尝试，命中即短路**：

| 序 | 通道 | 判定内容 |
|---|---|---|
| 1 | **自定义命题展开** | 按 `def` 定义展开后以展开结果为新目标递归 |
| 2 | **否定常量拆解** | 目标 `¬p` 且 `p` 是常量原子：`p` 假则目标真，`p` 真则目标假 |
| 3 | **蕴含常量拆解** | 目标 `p → q`：`p` 常量假则恒真；`p` 常量真则只需证 `q` |
| 4 | **常量原子真值** | `3 >= 0` 这类可直接判定的常量比较 |
| 5 | **常量类型判定** | 字面量的 `e : T` |
| 6 | **纯度结构相等** | 目标是比较命题且任一侧含不纯调用：**仅查 Γ 中的显式事实** |
| 7 | **类型判定** | `x : T`，匹配 Γ 中注入的类型事实，或构造表达式的结果类型归属 |
| 8 | **常量归约** | 目标含变量但 Γ 有等式事实可归约为常量（`var m = 5` → 目标 `≠<m,0>` 归约为 `≠<5,0>`） |
| 9 | **Real 代数重写** | 等式目标两侧可转为 `Real` → 规范化后结构相等（第三卷 §11.5） |
| 10 | **线性算术** | 整数域的不等式／等式／区间蕴含与析取反证 |
| 11 | **通用证明器** | 饱和闭包 + 目标分解（§5.2、§5.3） |
| 12 | **反证法** | 仅激进模式且挂载 `@classic`：`Γ ∪ {¬goal}` 饱和出 `⊥` |
| 13 | **定理搜索** | 定理空间（跨模块标准库 + 用户 `@theorem`）的后件与目标结构合一 |

**顺序敏感的理由**：类型、常量、算术通道先于通用证明器，用更精确的判定率先定谳，避免被后续宽通道误吞。

通道 10（线性算术）的特殊规则：**只有判定为「成立」才短路**；判定为「不成立」或「形态不支持」都继续走后续通道，以免掐断等式图、等量代换等其他推理。

通道 11 失败且深度耗尽时报 `E-DEEP-SATURATION`。

### 5.2 事实库归一化

进入饱和闭包之前，Γ 中的事实必须归一化：

```
normalizeFacts(ps) = ps
    经 expandIff    把 p ↔ q 拆为 (p → q) 与 (q → p)
    经 flattenAnd   把合取展平为事实列表
    经 stripNN      消去双重否定 ¬¬p → p
    经 blindPos     剥离项的位置信息
```

**等价拆双蕴含**的理由：使 MP 能由 `¬irrational<power>` 推出 `rational<power>` 等（`↔` 本身不是 MP 的载体）。

**合取展平**的理由：使 `p ∧ q` 的两支可以独立参与 MP 与事实匹配。

**双否消去**是直觉主义健全的。

### 5.3 饱和闭包

饱和闭包从 Γ 迭代推出新事实至不动点。

**关键表达式池**的构造：

```
K = groundTerms(termSource) ∪ groundTerms(extraGoals)    去重后固定
```

关键池**一次性收集，此后固定**，不随新增事实扩张。理由：若随事实扩张，复合项会自我增殖（`(1+2)` → `(1+2)+(2+1)` → …），导致笛卡尔爆炸且永不达不动点。

**ground 项的收集**采用后序遍历：内层先入，外层后入。对 `print(1 + 2)`，收集到 `print(1 + 2)`、`1 + 2`、`1`、`2`。它们称为**关键表达式**。

**实例化矩阵预计算**：关键池固定，各 `∀` 量词的候选替换跨轮不变，因此预计算一次。多名字量词的候选是笛卡尔积。

**闭包规则**（每轮依次执行）：

$$\frac{\forall \vec{x} . p \in F \qquad \vec{t} \in K^{n} \qquad p[\vec{x} := \vec{t}] \text{ 的归一化结果} \notin F}{F := F \cup \text{normalize}(p[\vec{x} := \vec{t}])} \quad (\text{R-INST})$$

$$\frac{p \to q \in F \qquad \text{normalize}(p) \text{ 的每一支都} \in F}{F := F \cup \text{normalize}(q)} \quad (\text{R-MP})$$

$$\frac{p \to q \in F \qquad \lnot q \in F}{F := F \cup \text{normalize}(\lnot p)} \quad (\text{R-MT})$$

$$\frac{p \in F \qquad \lnot p \in F \qquad \bot \notin F}{F := F \cup \{\bot\}} \quad (\text{R-CONTRA})$$

`R-MP` 是**前向链接**（modus ponens），`R-MT` 是**拒取式**（modus tollens，经典逻辑健全）。

**去重**：每个「量词 + 候选组合」只实例化一次（以量词名与候选的标签串为键）。

**终止**：

| 模式 | 终止条件 |
|---|---|
| 普通模式 | 轮数达到 `maxRounds = 3`，或本轮无新事实 |
| 激进模式 | 仅「本轮无新事实」（不动点），无轮数上限 |

**额外目标的地位**（健全性关键）：

```
closure(Γ, extraGoals, termSource)
```

`extraGoals` 的项**只贡献实例化候选，不加入事实**。否则目标会平凡可证，破坏健全性。

### 5.4 目标分解

饱和之后，对目标做递归分解。深度预算为 `curBudget`，超出则标记深度耗尽并返回失败。

$$\frac{}{\Gamma \vdash p \qquad \text{当 } \bot \in \Gamma \text{ 且 } p \neq \bot \text{（矛盾爆炸）}} \quad (\text{R-BOT-ELIM})$$

$$\frac{}{\Gamma \vdash p \qquad \text{当 } p \in \Gamma \text{ 且 } p \neq \bot} \quad (\text{R-AXIOM})$$

$$\frac{}{\Gamma \vdash \top} \quad (\text{R-TOP})$$

$$\frac{}{\Gamma \vdash \bot \qquad \text{当且仅当 } \bot \in \Gamma} \quad (\text{R-BOT})$$

$$\frac{\Gamma \vdash p \qquad \Gamma \vdash q}{\Gamma \vdash p \land q} \quad (\text{R-AND})$$

$$\frac{\Gamma \vdash p}{\Gamma \vdash p \lor q} \quad (\text{R-OR-INTRO-L})$$

$$\frac{\Gamma \text{ 含析取式 } f \text{，且 } f \text{ 的每个子项都 } \alpha \text{-等价于目标 } g \text{ 的某个子项}}{\Gamma \vdash g} \quad (\text{R-OR-SUBSET})$$

$$\frac{\Gamma, p \vdash q}{\Gamma \vdash p \to q} \quad (\text{R-IMP-INTRO})$$

$$\frac{\Gamma \vdash p \to q \qquad \Gamma \vdash q \to p}{\Gamma \vdash p \leftrightarrow q} \quad (\text{R-IFF-INTRO})$$

$$\frac{\Gamma \vdash p[x := t] \qquad t \text{ 是 } \Gamma \text{ 的 ground 项} \qquad x \text{ 是单一绑定名}}{\Gamma \vdash \exists x . p} \quad (\text{R-EXISTS})$$

$$\frac{\text{见 §4.5}}{\Gamma \vdash \forall \vec{x} . p} \quad (\text{R-FORALL})$$

$$\frac{\text{见 §4.8}}{\Gamma \vdash \exists! x . p} \quad (\text{R-EXISTS1})$$

$$\frac{\lnot p \in \Gamma \qquad \text{或} \qquad \bot \in \Gamma \qquad \text{或} \qquad p \text{ 形如 } \lnot \lnot q \text{ 且 } \Gamma \vdash q}{\Gamma \vdash \lnot p} \quad (\text{R-NOT})$$

$$\frac{\text{见 §5.5}}{\Gamma \vdash \text{PAtom}(\text{head}, \text{terms})} \quad (\text{R-ATOM})$$

**环剪枝**：同一目标在证明路径上重现即为环（`X → … → X` 只能继续循环），必须剪枝以防震荡。剪枝的判据是目标在 `visited` 集合中已出现。

**析取子集规则 `R-OR-SUBSET` 的方向性**（健全性关键）：

```
(A ∨ B) ⊢ (A ∨ B ∨ C)      有效（子集 ⊆ 超集）
(A ∨ B ∨ C) ⊢ (A ∨ B)      无效，不做
```

若方向反了，缺分支的 `when` 会被误判为穷尽。由此规则可得：覆盖律 `(R ∨ G ∨ B)` 能证出穷尽目标 `(R ∨ G ∨ B)`，但证不出残缺目标 `(R ∨ G)`——恰是部分匹配的 `when` 应当报 `W-NON-EXHAUSTIVE` 的语义。

### 5.5 原子命题的判定

目标为 `PAtom` 时，依次尝试四条通道：

**其一，成员过滤谓词**：覆盖 `list.filter { _ != 0 }` 之类后置 `∀e . e ∈ $ → e ≠ 0` 的证明。比较记号做 ASCII／Unicode 等价（`!=` ↔ `≠`、`<=` ↔ `≤`、`>=` ↔ `≥`、`==` ↔ `=`）。

**其二，事实匹配**：目标与 Γ 中某事实结构同一，或经等量代换后同一。

**其三，等式图可达**：目标是比较命题（`=`、`==`、`<=`、`≤`、`>=`、`≥`）且两项在等式图中可达：

$$\frac{\text{termEq}(t_{1}, t_{2}) \text{ 成立，或 } \text{eqReachable}(\text{eqs}, t_{1}, t_{2})}{\Gamma \vdash t_{1} = t_{2}} \quad (\text{R-EQ-TERM})$$

等式图以 Γ 中全部等式事实为边，双向边即对称性，可达性以广度优先搜索判定，即传递性。**等式推理在目标侧进行，不修改 Γ。**

**其四，类型事实的等式传播**：

$$\frac{e : T \in \Gamma \qquad e = e' \in \Gamma \text{（等式图可达）}}{\Gamma \vdash e' : T} \quad (\text{R-TYPE-EQ-PROP})$$

### 5.6 自动证明的能力边界

**可以自动覆盖**：常见工程场景——自然命题、伴生命题、结构相等、线性算术、区间穷尽、定理链式推导。

**不自动证明**（需手动证明语句或策略）：

| 情形 | 原因 |
|---|---|
| 非线性算术 | 判定过程超出线性整数片段 |
| `∨`／`¬`／`→` 在待证侧引入 | 普通模式不做析取消去 |
| `∃!` 的唯一性（多名字） | 仅支持单绑定名 |
| 多名字量词的完全实例化 | 普通模式的候选是笛卡尔积，规模受限 |
| 实数不等式 | 不在判定片段内 |

**饱和失败**时报 `E-DEEP-SATURATION`，建议拆成小步骤。

### 5.7 关键表达式的收集规则

自动证明沿「关键表达式」工作：

1. 收集代码块中出现的**一切**表达式，**优先内、其次外**；
2. 尽可能通过定理排列组合关键表达式，以及应用策略（莱布尼茨替换、蕴含传播、自反、拆解定义等），产生命题；
3. 命题中出现的表达式**再收集进关键表达式**；
4. 循环，直到超过回合上限仍未证出所需命题，即认为证明失败。

失败的可能原因有三：需要手动证明、证明过于复杂、或命题单纯不可证。

**实例化的组合展开**：设有两个关键表达式 `a`、`b`，以及定理 `∀a b . p<a, b>`，则编译器自动产生四个命题：

|  | `a` | `b` |
|---|---|---|
| **`a`** | `p<a,a>` | `p<a,b>` |
| **`b`** | `p<b,a>` | `p<b,b>` |

## 6. 手动证明语句

手动证明语句用于自动证明器无法覆盖的场景。依总纲公理一，全部手动证明语句都是表达式，固定返回 `Null`。

### 6.1 因为-所以语句

**语法**（第二卷 §4.6）：

```
∵ 形式, 前提₁, 前提₂, … ∴ 结论
```

三部分的角色：

- **形式**：`∵` 之后的第一个命题，即要调用的定理所构造的**全称量词命题**；
- **前提**：其后逗号分隔的命题，编译器用自动证明验证；
- **结论**：`∴` 之后的命题，必须是该定理后件的实例。

**语义**：

$$\frac{\Sigma \text{ 中存在定理函数 } f\text{，其自然命题 } \forall \vec{x} . (A \to B) \text{ 与「形式」匹配} \qquad \Gamma \vdash A[\vec{x} := \vec{t}] \text{ （前提，逐个用自动证明验证）} \qquad \text{「结论」} \equiv_\alpha B[\vec{x} := \vec{t}]}{\Gamma' = \Gamma \cup \{\text{结论}\} \qquad \text{语句值} = \text{null}} \quad (\text{R-BTS})$$

判定流程：

1. 编译器从符号表查找**构造了该形式的定理函数**。查找依据是命题的**形式**而非名字——这正是「因为-所以语句」的价值：不必知道定理名，也不必书写长名字；
2. 逐一验证前提。验证仍走自动证明。前提证不出报 `E-PREMISE-UNPROVEN`；
3. 判断结论是否为该定理的后件实例。不是则报 `E-CANNOT-PROVE`；
4. 一切通过后，结论注入 Γ，语句返回 `Null`。

**全称量词命题的前提与结论**：如果一个全称量词命题的谓词是一个蕴含命题，那么称这个蕴含命题的**前件**为命题的前提，**后件**为命题的结论。

**示例**：

```subl
∵ ∀a b . (a : Rat ∧ b : Rat) → ((a + b) = (b + a)),
  a : Rat, b : Rat
∴ (a + b) = (b + a)
```

对应的定理函数可以是：

```subl
@theorem
fun `commutative law of addition`(a : Rat, b : Rat) : <(a + b) = (b + a)>
```

也可以写成把类型条件放进蕴含前件的形式：

```subl
@theorem
fun `commutative law of addition`(a, b) : <(a : Rat ∧ b : Rat) → (a + b) = (b + a)>
```

两者构造的自然命题都是 `∀a b . (a : Rat ∧ b : Rat) → ((a + b) = (b + a))`，编译器据此认定这是用户想要调用的定理。

**注意**：即使正在手动证明，编译器仍会用自动证明帮助验证前提。前提不能自动证明时，需要用户自行证明。

**兼容简写**：

| 形态 | 语义 |
|---|---|
| `∴ q` | 等价于 `∵ ⊤ ∴ q`：先证 `q`，再注入 `q` |
| `∵ p`（后无逗号也无 `∴`） | 等价于 `∵ ⊤ ∴ p` |

### 6.2 非真即假语句

在经典逻辑中，命题是非真即假的。把 `if` 的圆括号换成方括号，即构成非真即假语句：

```
if[p] { S₁ } else { S₂ }
```

**语义**：

$$\frac{\text{已挂载 @classic} \qquad \Gamma, p \vdash S_{1} \Longrightarrow \Gamma_{1} \qquad \Gamma_{1} \text{ 证出公共结论集 } Q_{1} \qquad \Gamma, \lnot p \vdash S_{2} \Longrightarrow \Gamma_{2} \qquad \Gamma_{2} \text{ 证出公共结论集 } Q_{2} \qquad Q = Q_{1} \cap Q_{2}}{\Gamma' = \Gamma \cup Q \qquad \text{语句值} = \text{null}} \quad (\text{R-IFPROP})$$

两支分别以 `p` 与 `¬p` 入上下文；语句证明**两支共同有的命题**并注入 Γ。

**示例**：

```subl
if[n < 0] {
    // 此处 Γ 含 n < 0
    ∵ ∀n . (n : Nat) → (n ≥ 0),
      n : Nat
    ∴ n ≥ 0
    ∵ ∀n m . (n : Rat ∧ m : Rat) → (n ≥ m ↔ ¬<n < m>),
      n : Rat, 0 : Rat
    ∴ ¬<n < 0>
    ∵ ∀@p . (p ∧ ¬<p>) → ⊥,
      n < 0, ¬<n < 0>
    ∴ ⊥
    // 从矛盾可以证明出所有命题，自然包含 ¬<n < 0>
} else {
    // 此处 Γ 含 ¬(n < 0)
}
// 语句之后 Γ 含 ¬<n < 0>
```

**诊断**：

| 情形 | 诊断 |
|---|---|
| 未挂载 `@classic` | `E-NEED-CLASSIC` |
| 两支无共同结论 | `E-IF-CONCLUSION-MISMATCH` |

**挂载经典逻辑**：文件内任一声明标注 `@classic` 即挂载 `core.classic`。未挂载时语言是**直觉主义**的：`¬¬p → p` 不可推，反证法通道关闭。

该语句固定返回 `Null`。

### 6.3 分类讨论语句

析取式总是有一个命题成立。通过对析取式进行分类讨论，得出无论哪个分支都可以证明出某命题。把 `when` 换成方括号，即构成分类讨论语句：

```
when[p₁ ∨ p₂ ∨ …] {
    p₁ => { S₁ }
    p₂ => { S₂ }
    …
}
```

**语义**：

$$\frac{(p_1 \lor p_2 \lor \dots) \in \Gamma \qquad \forall i.\ \Gamma, p_i \vdash S_i \Longrightarrow \Gamma_i \qquad \Gamma_i \text{ 证出结论集 } Q_i \qquad Q = \bigcap Q_i}{\Gamma' = \Gamma \cup Q \qquad \text{语句值} = \text{null}} \quad (\text{R-WHENPROP})$$

**示例**：

```subl
when[n > 0 ∨ n < 0] {
    n > 0 => {
        ∵ ∀n m . (n : Rat ∧ m : Rat ∧ n > m) → (n ≠ 0),
          n : Rat, 0 : Rat, n > 0
        ∴ n ≠ 0
    }
    n < 0 => {
        ∵ ∀n m . (n : Rat ∧ m : Rat ∧ n < m) → (n ≠ 0),
          n : Rat, 0 : Rat, n < 0
        ∴ n ≠ 0
    }
}
// 语句之后 Γ 含 n ≠ 0
```

各分支中无论哪个部分成立都可以证明出 `n ≠ 0`，故分类讨论语句证明 `n ≠ 0`。

**规则**：

- 方括号内的析取式必须**已在 Γ 中**。不在则报 `W-PROP-UNBOUND`（警告级，不阻断）；
- 分支是「条件 + 语句块」，**没有 `else` 臂**；
- 各支无公共结论报 `W-WHEN-NO-COMMON`（警告级）。

该语句固定返回 `Null`。

### 6.4 存在语句

声明函数以构造一个全称量词，而使用**存在语句**构造一个存在量词：

```
∃n = 0 . n : Nat ∧ n = 0
```

**语义**：

$$\frac{\Gamma \vdash p[x := t] \qquad t \text{ 是见证}}{\Gamma' = \Gamma \cup \{\exists x.\ p\} \qquad \text{语句值} = \text{null}} \quad (\text{R-EXIST-INTRO})$$

上例证明了 `∃n . n : Nat ∧ n = 0`。

见证部分的命题证不出报 `E-QUANT-UNPROVEN`。

**限制**：见证部分目前不支持类型断言混在性质里。应当书写 `∃ x = 0 . x = 0` 这类纯表达式性质，而非把 `x : Nat` 混入。

该语句返回 `Null`。

### 6.5 存在消去语句

```
∃x . p { S }
```

**语义**：

$$\frac{(\exists x.\ p) \in \Gamma \qquad x \text{ 新鲜} \qquad \Gamma, x, p \vdash S \Longrightarrow \Gamma' \qquad \Gamma' \text{ 的结论不含 } x}{\Gamma'' = \Gamma \cup (\Gamma' \text{ 的结论}) \qquad \text{语句值} = \text{null}} \quad (\text{R-EXIST-ELIM})$$

前提不在 Γ 中报 `E-PROP-UNBOUND`。

### 6.6 全称引入语句（局部函数）

块内的 `fun` 声明构成**全称量词引入**：其签名构造的自然命题被登记为**块内局部定理**。

$$\frac{\text{fun f(x : } \tau \text{) <preps> : } \sigma \text{ <posts>} \qquad \text{在块内声明，体非空}}{\text{局部定理表} := \text{局部定理表} \cup \{f \mapsto \forall x.\ (\bigwedge \text{preps}) \to (\bigwedge \text{posts})\} \qquad \text{语句值} = \text{null}} \quad (\text{R-LOCAL-FUN})$$

体为空时报 `E-QUANT-UNPROVEN`。登记成功发 `D-LOCAL-FUN` 补充级诊断。

局部定理的作用域限于所在块及其子块，不向父帧回溢。

### 6.7 策略语句

证明器是一个默认不启用的模块，由编译器或注解处理器提供。它们给出**策略**。调用策略的格式：

```
@策略名[命题]
```

**语义**：

$$\frac{\text{策略 } s \text{ 可用} \qquad s(\text{命题}) \text{ 判定成功}}{\Gamma' = \Gamma \cup \{\text{命题}\} \qquad \text{语句值} = \text{null}} \quad (\text{R-STRATEGY})$$

判定失败报 `E-STRATEGY-FAILED`；成功发 `D-STRATEGY`。

**适用场景**：当遭遇自动证明器的固有局限与目标的特定形态的**交集**时使用策略。例如证明 `(3 * 2 + 6) = 12`：自动证明器只涉及对表达式和定理的排列组合，难以证明这类算术问题，此时使用化简器：

```subl
@simp[(3 * 2 + 6) = 12]
```

编译器会调用化简证明器去证明该命题。

**内建策略**：

| 策略 | 职责 |
|---|---|
| `@simp` | 化简器：算术表达式的规范化与求值 |
| `@subst` | 替换器：等量代换 |

依语言哲学，所有策略语句都返回 `Null`。

### 6.8 后缀式辅助策略

`by` 除语句式外还有**后缀式**（表达式位）：

```
e by [p₁, p₂, …]
```

语义是把人给的中间命题注入 Γ，并返回 `e` 的值：

$$\frac{}{\Gamma' = \Gamma \cup \{p_1, p_2, \dots\} \qquad \text{表达式值} = \text{e 的值}} \quad (\text{R-BY-EXPR})$$

`by` 不经证明器检验，是**辅助策略**：它把大结论拆成小步，由人负责中间命题的正确性。发 `D-BY` 补充级诊断。

### 6.9 公理逃逸

```
axiom p₁, p₂, …
```

**语义**：

$$\frac{}{\Gamma' = \Gamma \cup \{p_1, p_2, \dots\} \qquad \text{语句值} = \text{null}} \quad (\text{R-AXIOM-ESC})$$

不经任何检验。这是凝华唯一的命题逃逸口。擦除后在生成代码中保留 `// axiom: q` 注释以供审计。

### 6.10 unchecked 包裹

```
unchecked <语句>
```

绕过该语句的证明义务、纯度检查与可变性检查。语句内部的纯度上下文被置为不纯。

## 7. 定理函数

### 7.1 定义

某些定理涉及类型或命题参数，编译器在正常模式下无法对其自动调用。此时需要手动调用定理，例如排中律：

```subl
`law of excluded middle`[p]        // p ∨ ¬<p>
```

其声明：

```subl
@theorem
fun `law of excluded middle`[p] : Null <p ∨ ¬<p>>
```

### 7.2 定理函数的性质

`@theorem` 标注表示它是**定理函数**：

| 性质 | 规定 |
|---|---|
| 副作用 | 无 |
| 返回值 | 固定为 `Null` |
| 代码生成 | 编译时被擦除 |
| 参数修改 | 不修改参数 |

**只有 `@theorem` 显式标注的函数才是定理函数。**非 `@theorem` 的函数（即使是纯函数且返回 `Null`）不是定理、不进定理空间，代码照常生成。

### 7.3 定理函数的唯一性约束

**不同名称的定理函数不能构造同一形式的全称量词命题，否则报错。**

理由：定理函数本质上就是一个全称量词命题，**不依靠名字**。两个不同名的定理若构造同一形式的全称命题，则它们在定理空间中是同一个对象，保留两者会造成搜索歧义。

$$\frac{\Sigma \text{ 中已有定理 } f\text{，其自然命题 } \forall \vec{x}.\ q \qquad \text{新定理 } g\ (g \neq f)\text{ 的自然命题 } \forall \vec{y}.\ q'\text{，且 } q \equiv_\alpha q'}{\text{报错：重复定理}} \quad (\text{R-THEOREM-DUP})$$

### 7.4 定理函数的调用

定理函数可以作普通函数调用，其值固定为 `Null`。在上下文推导中，调用定理函数是**空操作**（不再禁止值级调用）。程序风格允许把 `@theorem` 公理像代码一样调用——调用即注入其下文，可驱动后续前件。

**示例：由排中律推广**

排中律定理的伴生命题是 `` `law of excluded middle`<p> ``，规定：

```
∀@p . `law of excluded middle`<p> → (p ∨ ¬<p>)
```

函数的构造本身带来自然全称量词命题：

```
∀@p . `law of excluded middle`<p>
```

组合上面两个命题可得：

```
∀@p . p ∨ ¬<p>
```

### 7.5 定理搜索

**搜索范围**：本模块的定理空间 + 沿可见路径展开的跨模块定理（含 `core.logic` 与 `core.classic` 标准库）。

**命中判据**：定理的后件与目标做**结构合一**。定理的理论参数（如 `@p`）与形参一起构成元变量集，可绑定到目标的对应位置。

**命题元变量的特殊规则**：定理后件里**无参数的裸名原子**（如 `@p`）可以绑定到任意目标命题。

**搜索深度**：默认**两跳**。超限报 `E-THEOREM-SEARCH-DEPTH`。

### 7.6 预置定理库

标准库 `core` 提供两个定理模块：

| 模块 | 内容 | 挂载条件 |
|---|---|---|
| `core.logic` | 等式的自反／对称／传递、莱布尼茨替换、MP、合取／析取／否定／量词规则、区间上下界（`rangeLowerBound`）、`<=` 的自反与传递、自然数非负（`natNonNeg`） | 工程模式隐式挂载 |
| `core.classic` | 排中律（`tertiumNonDatur`）、双否消去、逆否 | 需 `@classic` 挂载 |

`core.logic` 中的定理均已标注 `@theorem`，编译期擦除。

**示例**：

```subl
∵ n ∈ (0..30)
∴ n ≥ 0            // 命中 rangeLowerBound 与 natNonNeg
```

### 7.7 @axiom 函数

标注 `@axiom` 的函数，其**下文签名即公理**，不做自动证明：

```
Γ ⊢ posts 的义务被免除      发 D-AXIOM-POST
```

`@axiom` 与 `@theorem` 的区别：`@theorem` 是「已被接受的真理，供搜索」；`@axiom` 是「本函数的下文无需证明」。

## 8. 算术判定

### 8.1 线性整数算术

自动证明的第 10 通道是线性整数算术判定，覆盖：

| 形态 | 判定方式 |
|---|---|
| 线性等式 `Σcᵢ·vᵢ = C` | 归一化后比对 |
| 线性不等式 `Σcᵢ·vᵢ ≤ C` | 单变量界收紧 + 双变量差分约束传播 |
| 区间成员 `x ∈ (lo..hi)` | 转为两个不等式 |
| 蕴含 `A → B` | `A ∧ ¬B` 的不可满足性判定 |
| 析取反证 | 各支分别判定 |

**判定过程**：

1. 归一化：把约束转为线性形式 `Σ cᵢ·vᵢ ≤ C`；
2. 单变量：收紧绝对界 `[lo, hi]`；
3. 双变量差分：以 Bellman-Ford 传播相对界；
4. 否定蕴含：判定 `Γ ∧ ¬G` 是否不可满足。

**三态返回**：

| 返回 | 含义 | 后续 |
|---|---|---|
| 成立 | 目标在片段内且为真 | 短路，证明成功 |
| 不成立 | 目标在片段内且为假 | **不短路**，继续后续通道 |
| 不支持 | 目标形态不在线性整数片段内 | **不短路**，继续后续通道 |

只有「成立」短路。这一设计避免掐断等式图与等量代换等其他推理。

`when` 的区间穷尽性判定受益于此通道（第七卷 §7）。

### 8.2 判定片段之外

以下形态**不在**线性整数算术的判定片段内：

- 非线性项（`x * y`、`x²`）；
- 实数域不等式；
- 需要归纳的命题。

### 8.3 精确实数代数重写

自动证明的第 9 通道是 `Real` 代数重写，规则见第三卷 §11.5。触发条件：目标是等式（`=` 或 `==`）且两侧均可转为 `Real`。

## 9. 激进证明模式

### 9.1 定位

激进模式是一个可选编译开关，其含义是：

> **我接受编译很慢甚至不停机，请用一切健全手段证出我的命题。**

普通模式追求「完备性 × 可判定性 × 停机性」的平衡，**健全但不完备**。激进模式放弃停机性，换取更强的搜索能力。

开启方式：`compile`／`check` 附加 `--prover=aggressive`。脚本模式不受影响（脚本模式不做命题证明）。

**不支持中间档**：激进模式的语义是「无上限」，中间档会让用户困惑「为什么这次证出、那次证不出」。要么普通，要么激进。

### 9.2 健全性底线（不可违反）

**激进模式是「更彻底的搜索」，不是「更宽松的判定」。**

**允许**：更深、更广、更多策略、更灵活组合、三维池。

**绝不允许**：

- 猜测某命题成立；
- 启发式近似某目标；
- 降级为 `axiom` 语义；
- 接受任何未经证明的前提；
- 从「看起来对」跳到「认为对」。

这条是激进模式的立身之本。一旦破了它，激进模式就成了 `axiom` 的伪装。

### 9.3 所有新项必须有约束来源

构造新项时，新项必须有**约束来源**——类型约束、池约束或合一约束。

**无约束的凭空生成是永动机，不做。**

这条直接决定「不停机」是「有意义的搜索」还是「永动机」。

### 9.4 不停机语义

激进模式下编译器可能在某个证明义务上**永远搜索下去**。这不是缺陷，而是设计选择，用户明确知道并接受。

编译器的责任：

- 显示进度；
- 支持中断；
- **不偷偷放弃**——不会因为「搜太久」自行降级；
- 反模型优先——命题不成立时尽早给出反例。

### 9.5 三维关键池

这是普通模式与激进模式**最本质的区别**。

| 维度 | 内容 |
|---|---|
| **表达式** | 代码中出现的项、字面量、构造子应用、函数调用；Γ 里的 ground 项 |
| **类型** | 代码中出现的类型；Γ 里类型事实 `e : T` 的 `T`；结构体／枚举／类型类名；别名展开结果 |
| **命题** | Γ 里的命题；目标命题；函数前后件；定理后件；分支条件 |

**普通模式的池只有表达式一维。**

**为何需要三维池**——排中律是典型例子：

```
定理：∀P . P ∨ ¬P
```

普通模式：池里只有表达式，`P` 是命题变量，池里没有命题 → 无法实例化 → **排中律永不启用**。

激进模式：池里有命题 → 排中律可以实例化：取 `P := ` 池中某命题 `P₀`，得到 `P₀ ∨ ¬P₀` → **分情况证明可用**。

| 定理 | 需要的维度 | 普通 | 激进 |
|---|---|---|---|
| `∀x . x = x` | 表达式 | 可 | 可 |
| `∀@P . P ∨ ¬P` | 命题 | **不可** | 可 |
| `∀@P . ¬¬P → P` | 命题 | **不可** | 可 |
| `∀#T . Optional[T] ≠ T` | 类型 | **不可** | 可 |

**∀ 实例化按绑定变元的维度取候选**：

```
∀x . P(x)       x 从表达式池取
∀#T . Q(T)      T 从类型池取
∀@P . R(P)      P 从命题池取
∀x, T . S(x,T)  笛卡尔积
```

维度分派的判据：裸原子 → 命题池；`:` 的右端 → 类型池；其余 → 表达式池。

### 9.6 池的构造

池的内容有三个来源：

**其一，类型导向的表达式构造**：给定目标类型 `T`，枚举所有类型为 `T` 的表达式（深度预算 3 至 5 层）——字面量、池中类型为 `T` 的项、构造子应用、函数应用。

**其二，合一反推的类型构造**：从泛型实例化、等式推理、字段访问中提取「被用到的类型」（不是枚举所有名义类型，而是从现有约束反推）。

**其三，目标驱动的命题构造**：反向分解 `R = A ∧ B` 生成子目标 `A`、`B`；假设引入 `R = A → B` 生成假设 `A` 与子目标 `B`；反证 `R = P` 生成假设 `¬P` 与目标 `⊥`。

### 9.7 池的边界

以下内容**不进池**：

| 不进池 | 理由 |
|---|---|
| 无约束的命题枚举 | 命题空间无限深 |
| 无类型约束的表达式枚举 | 爆炸且无意义 |
| 所有名义类型的枚举 | 与搜索目标无关 |
| Cut 自动引入的中间命题 | 需要凭空造中间项，违反 §9.3 |

**「有约束来源」是池的守门人。**

### 9.8 池规模控制

三维池比一维池大得多，必须有规模上限：

| 维度 | 上限 |
|---|---|
| 表达式 | 500 |
| 类型 | 200 |
| 命题 | 200 |
| 组合 | 4096 |

每维度独立计数；构造出的项单独计数；超上限时**优先保留与当前目标相关的项**（按项重叠度排序）。

### 9.9 策略差异对照

| 维度 | 普通模式 | 激进模式 |
|---|---|---|
| 饱和轮数 | `maxRounds = 3` | 无上限，靠不动点判停 |
| 证明深度 | `maxDepth = 6` | 迭代加深：预算 4 → 8 → 16 → … |
| 关键池维度 | 表达式 | 表达式 + 类型 + 命题 |
| 池的构建 | 仅收集 | 收集 + 构造 |
| `∀` 实例化候选 | 表达式池 | 按绑定变元维度取池 |
| `∨` 消去 | 关闭 | 开启（分情况证明） |
| 反证法 | 关闭 | 开启（需 `@classic`） |
| 排中律前向实例化 | 关闭 | 开启（对命题池每个候选注入 `A ∨ ¬A`） |
| 记忆化 | 无 | 正向记忆（只记已证目标） |
| 中断 | 无 | `Ctrl-C` → 中断异常 → 诊断报告 |

**迭代加深的判据**：证明失败且被深度截断时，预算翻倍重试；未被深度截断则认定真不可证，返回失败。

**∨ 消去规则**：

$$\frac{\Gamma \text{ 含 } A \lor B \qquad \text{该析取式未在本路径拆过} \qquad \Gamma, A \vdash \mathit{goal} \qquad \Gamma, B \vdash \mathit{goal}}{\Gamma \vdash \mathit{goal}} \quad (\text{R-OR-ELIM})$$

分支内 `p` 与 `¬p` 并存即该分支已矛盾，任意目标成立（析取三段论 `¬a, a ∨ b ⊢ b` 的落点）。`⊥`-消去在直觉主义亦成立，只是 `∨` 拆分本身只在激进／经典语境提供。

必须记录本路径已拆过的析取式，防止同一析取被反复拆分——这是 `visited` 剪枝之外的第二重终止保证。

**反证法规则**：

$$\frac{\text{@classic 已挂载} \qquad \Gamma \cup \{\lnot \mathit{goal}\} \text{ 饱和出 } \bot}{\Gamma \vdash \mathit{goal}} \quad (\text{R-RAA})$$

经典逻辑独有：直觉主义只得 `¬¬goal`，不得 `goal`。未挂载 `core.classic` 时绝不启用。

**排中律前向实例化**：识别可见定理中后件形状为 `p ∨ ¬p`（`p` 为无参数裸原子）的定理，对命题池每个候选 `A` 注入 `A ∨ ¬A` 进 Γ，配合 `∨` 消去完成分情况证明。仅 `@classic` 挂载时启用。

### 9.10 明确不做的策略

| 策略 | 理由 |
|---|---|
| Cut 自动引入 | 永动机 |
| 引理发现 | 研究级 |
| 不变量推断 | 研究级 |
| 高阶合一 | 一般不可判定 |
| 命题枚举 | 命题空间无限深 |
| 类型全枚举 | 与目标无关 |
| 归纳（结构／数值／强／良基／互归纳） | 健全性依赖良基性判定，风险高 |

### 9.11 可观测性

**输出分工**：

| 内容 | 输出目标 |
|---|---|
| 编译产物 | 标准输出 |
| 进度显示 | **标准错误**（不污染产物） |
| 诊断报告 | 文件 |

**进度格式**：

```
[激进证明] 已证 47 / 待证 62 | 搜索中
  当前目标：main.subl:42:8  `n > 0`
  已尝试：3 条推理链，最深 8 层
  池规模：表达式 128 | 类型 24 | 命题 56
  最近尝试的定理：addComm, mulAssoc, LEM（排中律）
  当前 Γ 相关事实：n : Nat, n ≥ 0
```

池规模必须显示三维——用户看到「命题池 56」才会理解排中律为何启用。

**「已证／待证」的定义**：

分母是**编译过程中产生的所有证明义务**，包含：

- 函数前件与下文；
- `∴`／`∵` 语句的命题；
- 结构体伴生命题；
- 分支穷尽性判定；
- 归纳／反证策略产生的子目标（递归展开后计入）。

**不含**：类型检查、纯语法检查。

**节流**：每 5 秒或每 100 步打一行（任一触发）。可用 `--prove-verbose` 提高频率，`--prove-interval=2s` 自定义（支持 `500ms`／`2s`／`1m`）。

### 9.12 中断与诊断报告

`Ctrl-C` 的处理：

1. 置中断位，搜索循环在下一个检查点抛出中断异常；
2. 打印当前状态；
3. 生成可审计诊断报告；
4. **退出码 130**（SIGINT 标准）。

**报告内容**（写入 `sublimation-prover-dump.md`，可用 `--prove-dump=路径` 指定）：

| 部分 | 内容 |
|---|---|
| 其一 | **卡住的目标**：目标命题、来源位置、**完整的当前 Γ**、已尝试的推理路径 |
| 其二 | **已证的义务**：哪些证出、哪些未轮到 |
| 其三 | **搜索统计**：总步数、每层节点数、三维池规模、定理表命中情况 |
| 其四 | **最接近成功的路径**：从搜索树挑一条展开最深但未完成的路径——供编译器开发者判断「缺哪条规则」 |
| 其五 | **提交问题的模板**：最小复现模板 |

报告的用途：用户可把报告发给编译器开发者。**这是激进模式最有价值的部分**——把「用户卡住」变成「用户收集到诊断信息」。

### 9.13 命令行接口

```
sublimation compile project/                          普通模式（默认）
sublimation compile project/ --prover=aggressive      激进模式
sublimation compile project/ --prover=aggressive --prove-verbose
sublimation compile project/ --prover=aggressive --prove-dump=path/to/report.md
sublimation compile project/ --prover=aggressive --prove-interval=2s
```

### 9.14 验收判据

激进模式的实现必须满足：

| 方面 | 判据 |
|---|---|
| 功能 | 三维池生效（排中律可实例化、涉及类型的定理可实例化）；反证法可证出普通模式证不出的目标；反模型构造能找到反例；中断能生成诊断报告 |
| 健全性 | **所有证出的命题都必须是真的**；不允许猜出来的证明 |
| 可观测性 | 进度显示三维池规模；`Ctrl-C` 能中断并生成报告；报告内容完整可读 |
| 兼容性 | 普通模式行为**完全不变**（测试全绿 + 示例产物逐字节不变）；激进模式只在旗标存在时启用 |
| 不返回 | 激进模式下证不出时不返回（符合设计），但 `Ctrl-C` 必须能中断 |

### 9.15 反模型层

| 策略 | 说明 |
|---|---|
| 反模型构造 | 命题不成立时构造反例模型 |
| 有界模型检验 | 限定论域大小寻找反例 |

**价值**：命题**真的不成立**时，激进模式能提前给出「我找到了反例」——比「永远搜下去」对用户有用得多。

**健全性**：找到反例 ⇒ 命题不成立。不产生假证明。

### 9.16 分层策略清单

激进模式的策略按层组织。所有策略的健全性必须不低于「无风险」。

**饱和层**：见 §9.9。关键约束是「无上限」必须有「不动点判据」——普通模式靠轮数截断，激进模式必须靠「本轮没产生新事实」退出。

**等式层**：

| 策略 | 说明 |
|---|---|
| 递归等量代换到不动点 | 去除浅层代换的限制 |
| Congruence closure | 并查集 + 函数符号一致性 |
| Knuth-Bendix 完成 | 等式转项重写系统 |
| Superposition | 等式 + 归结叠加演算 |

**逻辑层**：反证法、析取消去、蕴含引入完整版、排中律实例化、双重否定消去。

**量词层**：多名字量词全量实例化、E-matching（trigger 匹配 Γ 中项）、`∃` 引入的完整搜索。

**算术层**：

| 策略 | 说明 |
|---|---|
| Presburger 完整判定 | 线性整数算术的完备判定 |
| Cooper 算法／Omega 测试 | Presburger 的经典实现 |
| 线性算术（有理数域） | Simplex／Fourier-Motzkin |
| 非线性算术 | 特定片段可做 |

Presburger 判定是「带有命题的类型」校验的钥匙。

**项／表达式层**：类型导向枚举、重写到正规形、代数简化（`x + 0 = x` 等恒等式）、结合-交换（AC）归一化。

**搜索架构层**：搜索树（广度／深度／最佳优先）、迭代加深、记忆化、证明重用、并行搜索。

## 10. 证明义务

### 10.1 义务的种类

编译过程中产生的证明义务：

| 义务 | 触发点 | 失败诊断 |
|---|---|---|
| 函数下文 | 函数体结束时 Γ 必须蕴含下文 | `E-POST-UNPROVEN` |
| 调用前件 | 调用点上文必须在 Γ 中可证 | `E-PRE-UNPROVEN` |
| 结构体伴生命题 | 构造点上伴生命题必须可证 | `E-STRUCT-PROP-UNPROVEN` |
| 因为-所以的前提 | `∵` 后的前提列表 | `E-PREMISE-UNPROVEN` |
| 因为-所以的结论 | `∴` 后的结论 | `E-CANNOT-PROVE` |
| 存在语句的见证 | `∃x = t . p` 的 `p[x := t]` | `E-QUANT-UNPROVEN` |
| 策略目标 | `@s[q]` 的 `q` | `E-STRATEGY-FAILED` |
| 分支穷尽性 | `when` 的分支命题析取 | `W-NON-EXHAUSTIVE` |
| 函数值上下文 | 调用携带上下文的函数值 | `E-CTX-UNPROVEN` |
| 约束违反 | 类型类约束被反证 | `E-CONSTRAINT-VIOLATED` |

### 10.2 义务的履行原则

**证不出即编译错误**，并列出尝试过的定理与当前 Γ。**绝不悄悄放行。**

依总纲公理三，「证不出」不等于「命题为假」。此时的三条出路：

1. **手动证明语句**（§6）：给出形式、前提、结论，或用分类讨论、非真即假拆解；
2. **策略**（§6.7）：调用命名证明器处理算术等自动证明器的盲区；
3. **`unchecked`**（§6.9、§6.10）：显式逃逸，正确性由用户负责。

### 10.3 函数体是证明义务

函数声明**不是可信公理**：

$$\frac{\text{fun f(…) : } \tau \text{ <posts> \{ body \}}}{\text{检查 body 结束时的 } \Gamma \text{ 必须蕴含 posts}} \quad (\text{义务})$$

逃生门只有 `axiom`。

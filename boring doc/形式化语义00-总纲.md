## 一、本卷的地位与读法

### 1.1 本卷定义什么

本卷是 12 卷形式化语义的**接口层**，不定义任何具体推导规则。它固定四样东西，供十一部分卷共同遵守：

1. **语义域**（§2）：值域 `Val`、类型域 `Ty`、命题域 `Prop`、上下文 `Γ/Δ`、效应与所有权标签；
2. **判断形式总表**（§3）：全套卷册出现的判断式及其读法、对应实现入口；
3. **卷分工索引**（§4）：每卷负责哪一族规则，卷际如何引用；
4. **健全性与不猜测底线**（§5）：跨卷恒成立的不变量。

各分卷的规则凡与本卷接口形状不一致者，以分卷的具体化为准；本卷凡与 `_langfacts.md` 或源码冲突者，以事实表与源码为准（勘误入口见 §7）。

### 1.2 判断式体例

$$\frac{\text{前提}_1 \qquad \text{前提}_2 \qquad \cdots \qquad \text{前提}_n}{\text{结论}} \quad (\text{规则名})$$

横线之上为可同时成立的前提，之下为结论；规则名置于右端括号内，全规范唯一，以卷前缀开头（§6.2）。前提为空时横线上留白，规则为公理式规则。中文一律置于 `\text{...}` 内；逻辑联结词与量词用 Unicode 符号（`∧ ∨ ¬ → ↔ ∀ ∃ ∃! ⊤ ⊥`）——其中命题位的蕴含必须写成 `→`（词法层 `->` 全位非法，lexer 出 ARROW 仅供诊断），程序位的分支与函数体符号必须写成 `=>`（详见各卷代码示例）。

### 1.3 与语言设计公理的关系

根文档确立的三条设计公理——万物皆表达式、值与命题二分、健全但不完备——是本系列的语义基准（旧总纲曾系统展开，此处不重述）。本卷把它们翻译为可检查的接口条款：

- **万物皆表达式** → 语句判断与表达式判断统一为 `⟹`/`⊢` 两族（§3.6、§3.1），语句的值固定为 `Null`；
- **值与命题二分** → 值域 `Val` 与命题域 `Prop` 分立，唯一的桥是分支条件提升（02 卷、03 卷）；
- **健全但不完备** → §5 的 I-1「不猜测」底线：证明器证不出即为诊断，任何模式都不得把「证不出」降级为「成立」。

## 二、语义域

### 2.1 值域 `Val`（求值侧）

值域由解释器 `ScriptValue`（interpreter/.../ScriptValue.kt）给出，跨边界一律**引用语义**（不拷贝；脚本改宿主对象即改宿主对象本体）：

$$v ::= \text{Num}(\mathbb{Z}) \mid \text{Real}(\mathbb{R}) \mid \text{Str} \mid \text{Bool} \mid \text{Null} \mid \text{ListV} \mid \text{Struct} \mid \text{OptionalV} \mid \text{ResultV} \mid \text{Fun} \mid h$$

其中 `Struct = (类型名, 字段表, 可变字段集)`，`OptionalV(v?)` 以内部 `null` 表示 `None`，`ResultV(isOk, v, e)` 分 `Ok/Err` 两态，`Fun` 统一包装宿主函数与脚本闭包（按标识判等，不按结构），`h` 为宿主穿透值（11 卷）。类型映射：`Nat/Int/Rat → Num/Real`、`Str → Str`、`Bool → Bool`、`Null → Null`、`List[T] → ListV`、`Optional[T] → OptionalV`、`Result[T,E] → ResultV`、结构体/宿主注入类型 → `Struct`、函数值 → `Fun`。

### 2.2 类型域 `Ty`（检查侧）

类型域由 `Type` 接口（frontend/.../ast/Ast.kt:136 起）给出：

$$\tau ::= n[\tau^*] \mid (\tau,\dots) \Rightarrow \tau\ \langle \pi,\ \Theta,\ \kappa \rangle \mid (\tau,\dots) \mid \texttt{@mut}\ \tau \mid \texttt{@atomic}\ \tau \mid \tau \mid \tau \mid m.n[\tau^*]$$

- `n[τ*]`：名义类型或类型参数引用（`NamedType`，如 `Nat`、`Optional<Nat>`、`T`）；
- `(τ,…) ⇒ τ ‹π, Θ, κ›`：函数类型（`FunType`），`π` 为纯度串，`Θ` 为理论参数（多态函数类型 `[T](T) => T`），`κ` 为上下文命题列表（`(T)<$1 ∈ xs> => Null`）；零参形态为 `() => U`；
- `(τ,…)`：元组（`TupleType`；`EmptyTuple`/`SingleTuple<T>` 走 `NamedType`）；
- `@mut τ`：唯一所有权可变视图（`MutType`）；`@atomic τ`：原子声明（`AtomicType`，JS 单线程下透明反射到内层类型）；
- `τ | τ`：联合类型（`UnionType`）；
- `m.n[τ*]`：跨模块限定类型（`QualifiedType`，checker 校验存在性与参数可解析性，`Symbols` 折叠为同简单名 `NamedType`——已知限制：不同模块同名类型会合并，见 08 卷）。

`@ref` **不是类型构造子**：它是变量级注解（`"ref" in annotations`，`Frame.refs` 登记）；`@ref @mut T` 即「变量标 `@ref`、类型为 `@mut T`」的共享可变别名（04 卷）。

### 2.3 命题域 `Prop`（证明侧）

命题域由 `Prop`（compiler/.../checker/Prop.kt:10 起）给出，`PAtom` 承载一切原子：

$$P ::= \top \mid \bot \mid \neg P \mid P \land P \mid P \lor P \mid P \to P \mid P \leftrightarrow P \mid \forall \vec{x}.P \mid \exists \vec{x}.P \mid \exists! \vec{x}.P \mid h\langle e_1,\dots,e_n\rangle$$

- 原子 `h⟨e…⟩` 涵盖 0 元命题 `p`、参数化命题 `valid<7>`、比较/等式（`$ == 7` → `PAtom("==",[$,7])`）、两参解糖 `q ○ p = ○<q,p>`；
- 归一化在命题层完成：`∈`→`in`、`<=`↔`≤`、`!=`↔`≠`、`a ↔ b` 拆双蕴含、合取分解、双否消去、位置盲（`blindPos`：同一变量在两处出现必须仍是同一项）；
- `⊤` 不入事实集（`Frame.inject` 丢弃 `PTop`）。

### 2.4 上下文 `Γ` / `Δ`

上下文由作用域帧 `Frame`（compiler/.../checker/Diffusion.kt:11 起）实现：

$$\Gamma = \langle x \mapsto \tau,\ \ \ P\ \text{集},\ \ f \mapsto \text{定理},\ \ \textit{muts}/\textit{refs},\ \ \Sigma,\ \ u,\ \ \Gamma_{\text{parent}} \rangle$$

- `Γ_vars(x) = τ`：变量类型环境（`lookupVar` 沿父链）；
- `facts`：命题事实集（`LinkedHashSet`，去重保序）；`Γ ⊢ P` 的搜索空间 = 本帧 `allFacts()`（沿父链拼接）+ `globalFacts`（跨帧全域事实池，当前承载 `pure<name>`：未标 `@impure` 的函数自动纯，决策 34）；
- `muts/refs`：变量级 `@mut`/`@ref` 登记（`isMut/isRef` 沿父链）；
- `u = uncheckedDepth`：unchecked 深度（非负整数，§3.4 效应闸门开口）；
- `Δ` 在本规范中固定表示**演义后的后件上下文**（语句检查/弥散的输出，03 卷）。

帧链的拓扑规则（03 卷细化）：嵌套帧继承外层；**块事实回溢父帧**（函数体/语句块的弥散），**lambda 帧隔离**（闭包捕获在创建时深拷贝，06/07 卷）。

### 2.5 效应与所有权标签

| 标签 | 集合 | 语义 |
|---|---|---|
| 纯度 `π` | `{pure, impure}` | 检查期的预期/实际效应；默认纯（未标 `@impure` 即纯），纯上下文禁止 impure 调用（04 卷） |
| 异步 | `{async, sync}` | `@async` 函数体内可自由调用挂起函数；sync 体内 async 调用受 async-in-sync 闸（Checker.kt:769 附近） |
| 所有权 `μ` | `{纯, @mut, @ref, @ref @mut}` | 绑定/赋值/字段写的拷贝判据（四条规则，§3.7） |
| 原子 | `@atomic` | 类型层声明，事件循环保证读写原子（04 卷） |

函数值类型也携带纯度（`FunType.purity`）：lambda 体内发生 impure 调用（放行态）时推导该函数值为 `impure`，纯上下文调用它报 `E-IMPURE-CALL`。

### 2.6 四域同框示例

以下为可运行的工程模式片段（顶层只许声明与 `axiom`，执行代码入函数体），标注它触及的四个域：

```subl
axiom validRange                               // Prop：PAtom("validRange",[]) 注入模块级作用域

@mut struct Acc(@mut total: Nat)               // Ty：@mut 字段；所有权标签 μ

fun step(acc: @mut Acc, n: Nat) : Nat {        // Ty：参数持 @mut 视图
  var v : @mut Nat = n                         // K-COPY-2：@mut 目标 ← 纯源 → 深拷贝
  var alias : @ref @mut Acc = acc              // @ref @mut ← @mut：别名共享，不拷贝
  alias.total = alias.total + n                // 字段写：@mut 字段且持 @mut 视图
  v                                            // 尾表达式即块值（万物皆表达式）
}

fun main() {                                   // 工程模式入口
  print(step(Acc(0), 3))
}
```

上文/下文的书写位置（冒号前的 `<p>` 为上文、返回类型后的 `<q>` 为下文）、`$` 返回值指代与 `$n` 第 n 形参的精确语法在 03 卷定义；本示例只演示四个域如何在声明层面交织。

### 3.2 类型判断（01 卷接口）

类型判断以 `T-` 为前缀（01 卷定义完整规则集）。接口示例：

$$\frac{\Gamma_{\textit{vars}}(x) = \tau}{\Gamma \vdash x : \tau} \quad (\text{T-VAR})$$

$$\frac{\Gamma; \pi \vdash f : (\tau_1) \Rightarrow \tau_2 \qquad \Gamma; \pi \vdash e : \tau_1}{\Gamma; \pi \vdash f(e) : \tau_2} \quad (\text{T-APP})$$

实现基线（源码）：检查器取**宽松策略**——推导不出确切类型（`synthetic` 合成类型）时不误报，只对有证据的类型错误报错（Checker.kt 头注）；`synthetic` 类型参与合一/宽松相等时一律放行（TypeInfer.kt `looseEq`）。数值类型 `Nat/Int/Rat` 间在宽松相等下放行（数值升格），但名义类型不得因此合并。

### 3.3 命题可证判断（02 卷接口）

$$\frac{\Gamma \vdash P \to Q \qquad \Gamma \vdash P}{\Gamma \vdash Q} \quad (\text{R-MP})$$

$$\frac{}{\Gamma,\ \texttt{axiom}\ \ P \vdash P} \quad (\text{R-AXIOM})$$

`axiom p1, p2` 语句把命题直接注入当前作用域事实集（`AxiomStmt` 分支：`s.props.forEach { f.inject(...) }`，返回 `Null`）；t30（用户决策「by 只有委托」）后免验证直接供给通道**只剩 axiom 一条**——语句式 `by [q]` 删除为编译期错误 `E-BY-REMOVED`，后缀式 `expr by [q]` 改为**断言**（`Γ ⊢ Qᵢ` 核对，不成则 `E-CANNOT-PROVE`，不注入 Γ）。义务形式：`∵ P₁…Pₙ ∴ Q` 中前提各自先经 `Γ ⊢ Pᵢ`（不成则 `E-PREMISE-UNPROVEN`），再由「定理空间 + 前提」证 Q（不成则 `E-CANNOT-PROVE`）。

### 3.4 效应判断（04 卷接口）

效应判断以 `E-` 为规则前缀（04 卷）。总纲固定两条接口闸（实现已验证）：

$$\frac{\pi = \text{pure} \qquad f\ \text{标注}\ \texttt{@impure}}{\Gamma; \pi \nvdash f(\dots) : \tau} \quad (\text{E-IMPURE-CALL})$$

$$\frac{\Gamma \vdash x : \tau \qquad \neg\ \textit{isMut}(x) \qquad u = 0}{\Gamma \vdash \texttt{x = e}\ \text{拒绝}\ (\texttt{E-IMMUT-ASSIGN})} \quad (\text{E-IMMUT-ASSIGN})$$

`unchecked` 机制是唯一的受控开口：`unchecked <语句>` 使 `u` 自增并强制 `π := impure`（`UncheckedStmt` 分支：`uncheckedDepth++; checkStmt(s.inner, f, pure = false, …); uncheckedDepth--`）；解释器对 inner 直接执行（Evaluator.kt:194 附近），JS 生成侧注 `// unchecked` 后透传（JsCodeGen.kt:822 附近）。凡 `u > 0` 处，纯度/不可变闸门一律放行——这是刻意的开口，不是闸门失效。

### 3.5 求值判断（06 卷接口）

$$\frac{}{\sigma \vdash \langle n\rangle \Downarrow \mathrm{Num}(n)} \quad (\text{V-INT})$$

$$\frac{\sigma \vdash e \Downarrow v \qquad \text{copy}(\mu_{tgt} \leftarrow \mu_{src})}{\sigma \vdash \texttt{var } x : \tau = e \Downarrow \mathrm{Null}} \quad (\text{V-BIND-COPY})$$

求值的帧 `σ` 为 `ScriptFrame`（vars/muts/refs/functions 沿父链）；闭包捕获在 lambda 创建时**深拷贝**（`ClosureFun.copyCapture` 沿父链逐值拷；JS 侧 `__dc` 对函数**穿透**为既定边界——07 卷）。错误路径（panic / unwrapOr）与宿主函数调用见 06/11 卷。

### 3.6 语句与弥散判断（03 卷接口）

$$\frac{\Gamma; \pi; \phi \vdash s_1 \Longrightarrow \Delta_1 \qquad \Delta_1; \pi; \phi \vdash s_2 \Longrightarrow \Delta_2}{\Gamma; \pi; \phi \vdash s_1; s_2 \Longrightarrow \Delta_2} \quad (\text{G-SEQ})$$

弥散（diffusion）的核心接口：下文命题 `<$ = 7>` 在体内兑现后**回溢父帧**，后续语句可消费；分支帧的公共结论按结构相等取交后注入块外（`if[p]` 排中律分支即此机制：两支各注 `p`/`¬p`，取交集为块外结论，交集为空则报 `E-IF-CONCLUSION-MISMATCH`）。

### 3.7 拷贝判断（04 卷接口）

四条规则（编译期 `binderNeedsCopy` 与解释器 `bindCopy` **同一谓词**、同一判据；Evaluator.kt:112 与 Checker.kt 私有函数同注）：

$$\frac{\mu_{tgt} \ni \texttt{@mut}\ \land (\mu_{tgt} \not\ni \texttt{@ref}\ \lor \mu_{src} = \text{纯})}{\text{copy}(\mu_{tgt} \leftarrow \mu_{src})} \quad (\text{K-COPY-1/2})$$

$$\frac{\mu_{src} \ni \texttt{@mut}\ \land \mu_{tgt} = \text{纯}}{\text{copy}(\mu_{tgt} \leftarrow \mu_{src})} \quad (\text{K-COPY-3}) \qquad \frac{\mu_{src} \ni \texttt{@ref}\ \land \mu_{tgt} \not\ni \texttt{@ref}}{\text{copy}(\mu_{tgt} \leftarrow \mu_{src})} \quad (\text{K-COPY-4})$$

例：`@mut T ← T` 深拷；`@mut T ← @mut T` 深拷（每个 @mut 绑定持独立对象）；`@ref @mut T ← @mut T` 别名共享（`b.n = 1` 后 `a.n` 亦变）；`@ref T ← T` 共享只读；`T ← @ref T` 深拷。

### 3.8 诊断判断（09 卷接口）

诊断是三族命名空间（E- 错误 / W- 警告 / D- 提示）：

$$\frac{\Gamma \nvdash P \qquad P\ \text{为}\ \because\text{-结论}\ \qquad \text{前提已证}}{\Phi \vdash \text{prog} \Rightarrow \texttt{E-CANNOT-PROVE}\ @\ \text{pos}} \quad (\text{N-PROVE})$$

每条诊断携带位置（`行:列`，从 1 计）；带位置诊断输出时附源码行文本、行号与指向列的上箭头。全量码表（约 100 条）见 09 卷；本系列已确认的关键码：`E-IMMUT-ASSIGN`、`E-CANNOT-PROVE`、`E-PREMISE-UNPROVEN`、`W-PROP-UNBOUND`、`E-QUANT-UNPROVEN`、`E-IF-CONCLUSION-MISMATCH`、`E-MAIN-PARAMS`、`E-RETURN-OUTSIDE`、`E-NOT-MUT`、`E-IMPURE-CALL`、`D-DEEP-COPY`、`D-BTS`、`D-BY`、`D-NAT-PROP` 等。

### 3.9 模式匹配判断（05 卷接口）

when 有三态（值 when / 模板 when / 命题 when），统一在一个判断下：

$$\frac{\Gamma \vdash e : \tau \qquad (\Gamma, \overline{x_i : \tau_i} \vdash \textit{body}_i : \tau_w)_i \qquad \Gamma \vdash w\ \text{穷尽}}{\Gamma \vdash \texttt{when}\ \ e\ \{\dots\} : \tau_w} \quad (\text{M-WHEN})$$

穷尽性判定（`WhenCheck.kt`）依赖枚举覆盖律展开（`enumCoverageDisj`）、区间模板 `when(t in _)` 与守卫补全；命题 when `when[p ∨ q]` 走 03 卷的析取前提机制（`WhenPropStmt`：析取式须在 Γ，否则 `W-PROP-UNBOUND`）。分支位的蕴含须加括号（stopArrow 机制，parser 层）。

### 3.10 代码生成判断（07 卷接口）

$$\frac{\Sigma; \Gamma \vdash \textit{decl} \Rightarrow \textit{js}_1 \qquad \Sigma; \Gamma \vdash \textit{prog} \Rightarrow \textit{js}_2}{\Sigma; \Gamma \vdash \textit{decl};\textit{prog} \Rightarrow \textit{js}_1\ \text{拼接}\ \textit{js}_2} \quad (\text{J-SEQ})$$

关键边界：命题以断言形态落地（证明本身不保留）；定理函数与证明语句整体擦除（I-6）；`__dc` 深拷对函数穿透为既定边界；运行时（Channel/Mutex/Flow/atomic/`__range`）按 checker 置位的 used 标志按需注入。

### 3.11 模块判断（08 卷接口）

$$\frac{\text{目录树} \rightsquigarrow \Sigma \qquad \Sigma \vdash \text{可见路径集合}}{\Sigma \vdash \text{tree} \Rightarrow \text{units}} \quad (\text{X-TREE})$$

目录即模块（根 = 扫全树）；符号检查分三阶段——A 符号收集、B 类型可解析性与 impl 完整性、C 语义检查——跨模块名字解析要求全树符号先齐备（08 卷）。`QualifiedType` 折叠为同简单名 `NamedType` 是已知限制（跨模块同名类型合并）。

### 3.12 注解处理判断（10 卷接口）

$$\frac{\Sigma \vdash \textit{ast}_i \looparrowright \textit{ast}_{i+1} \qquad \textit{ast}_{i+1} \neq \textit{ast}_i}{\Sigma \vdash \textit{ast}_0 \looparrowright^{*} \textit{ast}_n\ (\text{收敛})} \quad (\text{H-FIXPOINT})$$

处理器多轮变换至收敛，运行在符号收集之后、语义检查之前；其输出是「待合法化的新代码」，必须整体过 C 阶段（I-3）——处理器因此无法绕过语言设计。

### 3.13 宿主绑定判断（11 卷接口）

$$\frac{h \in \textit{hostFunctions} \cup \textit{hostStructs}}{\sigma \vdash_{\text{host}} h \mapsto v \quad \text{（值跨边界引用语义，不拷贝）}} \quad (\text{B-BIND})$$

脚本模式管线：词法 → 语法（scriptMode）→〔可选〕全局类型推导（`<infer>` 占位替换）→ 语义检查 → 解释求值；`.subs` 每文件独立执行（互不共享、无需 main）。

## 五、健全性与不猜测底线

以下不变量对所有实现、所有编译模式（含激进证明模式）恒成立；任何违反即为缺陷。

**I-1（健全即不猜测）。** 若编译成功，则每个被接受的命题义务都在规范定义的推理系统内可证。证明器不得猜测命题成立、不得启发式近似目标、不得接受未经证明的前提。实现基线：多路 `return` 的 `$` 归一取保守 `null` 让后件核对显式失败——源码原注「不猜测——猜测会产生『看似通过实则错误』的证明」（Diffusion.kt `dollarOf`）；普通模式证明器轮次有界（`Prover(maxRounds = 3, …)`），仅激进模式放开（`Int.MAX_VALUE`）。

**I-2（宽松不误报，但闸不绕过）。** 推导不出确切类型（`synthetic`）时只放宽、不误报（Checker 头注「宽松策略」）；但 §3.4 的纯度/不可变闸门除 `unchecked` 显式开口（`u > 0`）外不得以任何「容错」名义放行。

**I-3（检查完整性）。** 进入代码生成的全部 AST——用户书写或注解处理器产生——都必须完整通过语义检查；注解处理器必须运行在符号收集之后、语义检查之前（10 卷），处理器产出按「待合法化的新代码」送入检查器。

**I-4（不可变默认）。** 变量、字段、参数默认不可变；可变性必须在类型层（`@mut T`）或变量层（`@ref`/`@mut` 注解）显式可见。赋值闸 (E-IMMUT-ASSIGN) 仅当 `¬isMut(lhs) ∧ u = 0` 触发（Checker.kt:612 附近）。

**I-5（纯度守恒）。** 纯上下文内不得出现 impure 调用或不可变闸违反；lambda 捕获外层可变变量的写入推导该 lambda 为 impure（`curLambdaImpure`）；闭包捕获在创建时深拷。

**I-6（擦除性）。** 类型、命题、理论参数、定理函数、证明语句在代码生成阶段完全擦除，不产生运行时表示；唯一例外是类型类字典（运行时对象，承载方法分派）。`axiom` 擦除后在生成代码保留一行注释供人工审计（形如 `// axiom: q`）。

**I-7（普通模式稳定性）。** 激进模式（CLI 标志）不得改变普通模式的任何行为：同一源文本不加旗标时，诊断与产物必须与开启前完全一致（`aggressive` 默认 `false`，普通模式所有激进分支全部关闭，Checker 构造器注）。

**I-8（诊断确定性）。** 同一源文本在同一编译模式下，诊断序列（顺序与内容）必须一致。

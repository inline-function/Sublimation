# 第一卷 · 词法

> 本卷规定凝华源文本如何被切分为词法单元（Token）。本卷的规则是确定性的：同一源文本必须产生同一 Token 序列。

---

## 1. 源文本与字符分类

### 1.1 源文本

一个**源文本**（source text）是 Unicode 码元的有限序列。源文件的扩展名规定如下：

| 扩展名 | 用途 |
|---|---|
| `.subl` | 工程模式源文件 |
| `.subs` | 脚本模式源文件、注解处理器脚本 |

扩展名不参与词法与语法，仅供编译管线选择处理模式。

### 1.2 字符分类

词法分析器按下表对单个字符分类。分类判定按表中**自上而下**的顺序进行，首个命中的类别生效。

| 序 | 类别 | 判据 | 处理 |
|---|---|---|---|
| 1 | 字节序标记 | `U+FEFF` | 平凡元素，跳过 |
| 2 | 空白 | 空格、`\t`、`\r`、`\n` | 平凡元素，跳过 |
| 3 | 十进制数字 | `'0'..'9'` | 数值字面量起始 |
| 4 | 双引号 | `'"'` | 字符串字面量起始 |
| 5 | 反引号 | `` '`' `` | 反引号标识符起始 |
| 6 | 因为符号 | `∵` 或 `∴` | 固定单元 `BECAUSE`／`THEREFORE` |
| 7 | 标识符起始 | `'_'` 或 `isLetter(c)` | 普通标识符 |
| 8 | 符号标识符起始 | `code(c) > 127` 且非空白、非字母数字、且不属于逻辑单元素集 | 符号标识符 |
| 9 | 多字符单元起始 | 见 §5 | 按优先匹配表处理 |
| 10 | 单字符单元 | 见 §4 单字符表 | 固定单元 |
| 11 | 其他 | — | 词法错误 `E-LEX` |

其中 `isLetter(c)` 与 `isLetterOrDigit(c)` 采用 Unicode 字母分类，因而**中文、希腊字母等均可作为标识符字符**。

### 1.3 逻辑单元素集

以下九个字符是**固定单元**，不得并入符号标识符，无论其前后是何字符：

```
∀   ∃   ∧   ∨   ¬   →   ↔   ⊤   ⊥
```

此集合记为 `LogicalSingletons`。其作用见 §7.3。

### 1.4 全角标点集

以下字符在被拒识时必须给出「请换成英文半角符号」的附加提示：

```
（ ） 【 】 ＜ ＞ ＝ ， ； ： ＂ ＇ ！ ＆ ｜
```

## 2. 词法单元

### 2.1 单元结构

一个词法单元是一个五元组：

```
Token = ⟨kind, text, line, col, precededBySpace⟩
```

| 分量 | 类型 | 含义 |
|---|---|---|
| `kind` | 单元种类 | §4 定义的枚举值 |
| `text` | 字符串 | 该单元的**规范文本**。多数情况下等于源文本片段，但存在归一化例外（见 §2.2） |
| `line` | 自然数 ≥ 1 | 单元起始行号 |
| `col` | 自然数 ≥ 1 | 单元起始列号 |
| `precededBySpace` | 布尔 | 该单元之前是否存在被跳过的平凡元素（见 §9） |

行号与列号均以 1 为起点。列号按 Unicode 码元计数，不按显示宽度计数。

### 2.2 文本归一化

以下两种情形中，`text` 与源文本片段不一致：

| 源文本 | kind | text |
|---|---|---|
| `&&` | `LAND` | `∧` |
| `\|\|` | `LOR` | `∨` |

归一化必须在词法层完成。其后果是：语法层、命题层、代码生成层对 `∧`／`&&` 不作区分，二者是同一条通道。

除上表外，任何单元的 `text` 必须逐字符等于其源文本片段。

### 2.3 终止单元

Token 序列的末尾必须追加一个终止单元：

```
⟨EOF, "<eof>", line, col, true⟩
```

其中 `line`、`col` 为源文本结束位置的行列号。终止单元的 `precededBySpace` 恒为 `true`。

---

## 3. 平凡元素

**平凡元素**（trivial element）是不产生 Token 的源文本片段，包括空白、字节序标记与注释。

### 3.1 注释

凝华只有一种注释：

```
Comment → '//' { 任意字符 除换行 }
```

`//` 之后至行尾（不含行尾换行符）的全部内容被跳过。

**凝华不支持块注释。**`/* … */` 不是注释：`/` 被切分为 `SLASH`，`*` 被切分为 `STAR`，后续内容按正常源文本处理，通常导致语法错误。

注释不嵌套。

### 3.2 换行的地位

换行是空白，**不是语句终止符**。语句之间的分隔由语法层决定（见第二卷 §3.2）。分号 `;` 是可选的语句分隔符。

### 3.3 跳过的副作用

跳过平凡元素时若至少跳过一个字符，则**下一个** Token 的 `precededBySpace` 为 `true`。注释计入此判定：

```subl
a//注释
<b
```

上例中 `<` 的 `precededBySpace` 为 `true`（注释被跳过），因而 `<` 是比较中缀而非实例化起始。此规则见 §9。

## 4. Token 种类全集

单元种类共 **70** 种，按功能分为七组。

### 4.1 字面量与标识符（5 种）

| kind | 含义 | text 形态 |
|---|---|---|
| `INT` | 整数字面量 | `[0-9]+` |
| `FLOAT` | 浮点字面量 | `[0-9]+ '.' [0-9]+` |
| `STR` | 字符串字面量 | 已去引号、已解转义的内容 |
| `IDENT` | 标识符 | 普通标识符、反引号标识符、或未被识别为关键字的字母串 |
| `SYMBOL` | 符号标识符 | 一个或多个符号字符的连续序列，如 `∈`、`≤`、`⊆`、`○` |

### 4.2 硬关键字（16 种）

| kind | 拼写 |
|---|---|
| `FUN` | `fun` |
| `CLASS` | `class` |
| `STRUCT` | `struct` |
| `ENUM` | `enum` |
| `VAR` | `var` |
| `IMPL` | `impl` |
| `FOR` | `for` |
| `IF` | `if` |
| `ELSE` | `else` |
| `UNCHECKED` | `unchecked` |
| `WHEN` | `when` |
| `IS` | `is` |
| `BY` | `by` |
| `TYPE` | `type` |
| `RET` | `return` |
| `DEF` | `def` |

硬关键字的规则见 §8。

### 4.3 标点（9 种）

| kind | 拼写 | 用途 |
|---|---|---|
| `LPAREN` | `(` | 圆括号起始 |
| `RPAREN` | `)` | 圆括号结束 |
| `LBRACKET` | `[` | 方括号起始（类型实参、策略、公理） |
| `RBRACKET` | `]` | 方括号结束 |
| `LBRACE` | `{` | 花括号起始（块、lambda、类型类体） |
| `RBRACE` | `}` | 花括号结束 |
| `COMMA` | `,` | 分隔符 |
| `SEMI` | `;` | 可选语句分隔符 |
| `COLON` | `:` | 类型标注、命题「为」 |
| `COLON2` | `::` | 限定名分隔（枚举成员、跨模块引用） |
| `DOT` | `.` | 字段访问、量词变量列表终止符 |
| `AT` | `@` | 注解前缀、命题参数标记 |
| `BACKSLASH` | `\` | 保留单元，当前语法不使用 |
| `DOLLAR` | `$` 或 `$n` | 返回值指代、参数引用 |
| `HASH` | `#` | 类型参数标记（量词中） |

本组共 15 个 kind（`COLON2`、`DOT`、`AT`、`BACKSLASH`、`DOLLAR`、`HASH` 均为独立单元）。

### 4.4 算术、比较与赋值（12 种）

| kind | 拼写 | 说明 |
|---|---|---|
| `PLUS` | `+` | 加 |
| `MINUS` | `-` | 减；亦为一元负号 |
| `STAR` | `*` | 乘 |
| `SLASH` | `/` | 除 |
| `PERCENT` | `%` | 取余 |
| `POW` | `^` | 幂 |
| `ASSIGN` | `=` | 赋值、默认值、命名实参 |
| `EQ` | `==` | 值世界的相等判断 |
| `NEQ` | `!=` | 值世界的不等判断 |
| `LE` | `<=` | 值世界的小于等于 |
| `GE` | `>=` | 值世界的大于等于 |
| `RANGE` | `..` | 区间构造 |

### 4.5 箭头与逻辑（6 种）

| kind | 拼写 | 说明 |
|---|---|---|
| `ARROW` | `->` | 蕴含（值层）；lambda 分隔符的兼容写法 |
| `DARROW` | `=>` | 函数类型箭头；lambda 与 `when` 分支的分隔符 |
| `IFF` | `<->` | 等价（值层拼写） |
| `AMP` | `&` | 单与（值层逻辑与） |
| `PIPE` | `\|` | 单或（值层逻辑或） |
| `BANG` | `!` | 一元否定（值层） |

### 4.6 Unicode 逻辑与数学（10 种）

| kind | 拼写 | 说明 |
|---|---|---|
| `FORALL` | `∀` | 全称量词 |
| `EXISTS` | `∃` | 存在量词 |
| `EXISTS1` | `∃!` | 唯一存在量词 |
| `LAND` | `∧` | 合取（亦由 `&&` 归一而来） |
| `LOR` | `∨` | 析取（亦由 `\|\|` 归一而来） |
| `LNOT` | `¬` | 否定 |
| `IMPLIES` | `→` | 蕴含 |
| `EQUIV` | `↔` | 等价 |
| `TOP` | `⊤` | 真 |
| `BOT` | `⊥` | 假 |

### 4.7 证明记号、尖括号与终止（5 种）

| kind | 拼写 | 说明 |
|---|---|---|
| `BECAUSE` | `∵` | 因为（手动证明语句起始） |
| `THEREFORE` | `∴` | 所以（手动证明语句结论） |
| `LT` | `<` | 小于；亦为实例化与上下文列表的起始 |
| `GT` | `>` | 大于；亦为实例化与上下文列表的结束 |
| `EOF` | — | 终止单元 |

### 4.8 关于 `≤` `≥` `≠` `∈`

`≤`、`≥`、`≠`、`∈` **不是**独立的 Token 种类。它们不属于 `LogicalSingletons`，因而被 §7.3 的符号标识符规则收入，切分为 `SYMBOL` 单元。

这一事实是凝华「值与命题二分」（总纲公理二）在词法层的体现：

| 写法 | kind | 归属世界 |
|---|---|---|
| `<=` | `LE` | 值世界（比较函数，代码生成层有对应实现） |
| `≤` | `SYMBOL` | 命题世界（自定义或内建命题记号） |
| `!=` | `NEQ` | 值世界 |
| `≠` | `SYMBOL` | 命题世界 |
| `>=` | `GE` | 值世界 |
| `≥` | `SYMBOL` | 命题世界 |

因此命题必须书写 Unicode 形式。书写 `x <= 0` 于命题位不会构成命题比较，而是构成值世界的比较函数调用。

## 5. 多字符单元的优先匹配

当当前字符可开启多个单元时，按下表**自上而下**的顺序判定，首个命中的规则生效。表中「后继」指紧随其后的字符。

| 序 | 当前字符 | 后继 | 产出 |
|---|---|---|---|
| 1 | `<` | `->` | `IFF`，text `<->` |
| 2 | `=` | `>` | `DARROW`，text `=>` |
| 3 | `=` | `=` | `EQ`，text `==` |
| 4 | `!` | `=` | `NEQ`，text `!=` |
| 5 | `<` | `=` | `LE`，text `<=` |
| 6 | `>` | `=` | `GE`，text `>=` |
| 7 | `-` | `>` | `ARROW`，text `->` |
| 8 | `∃` | `!` | `EXISTS1`，text `∃!` |
| 9 | `.` | `.` | `RANGE`，text `..` |
| 10 | `:` | `:` | `COLON2`，text `::` |
| 11 | `&` | `&` | `LAND`，text `∧`（归一化） |
| 12 | `\|` | `\|` | `LOR`，text `∨`（归一化） |

匹配为**贪婪**：一旦命中，消费全部参与字符。未命中任何规则时，进入 §4 的单字符判定。

### 5.1 优先匹配的推论

由上表可直接推出以下切分结果：

| 源文本 | Token 序列 |
|---|---|
| `->` | `ARROW` |
| `->>` | `ARROW` `GT` |
| `=>` | `DARROW` |
| `==>` | `EQ` `GT` |
| `<->` | `IFF` |
| `<<->` | `LT` `IFF` |
| `..` | `RANGE` |
| `...` | `RANGE` `DOT` |
| `::` | `COLON2` |
| `:::` | `COLON2` `COLON` |
| `∃!` | `EXISTS1` |
| `∃!x` | `EXISTS1` `IDENT(x)` |

### 5.2 `$n` 的粘连

`$` 之后若紧跟十进制数字，则贪婪读取全部连续数字，产出**单个** `DOLLAR` 单元，其 text 包含 `$` 与全部数字：

```
'$' [0-9]+   →   ⟨DOLLAR, "$" 数字串⟩
```

例：`$1` → `⟨DOLLAR, "$1"⟩`；`$12` → `⟨DOLLAR, "$12"⟩`；单独的 `$` → `⟨DOLLAR, "$"⟩`；`$ x` → `⟨DOLLAR, "$"⟩` `⟨IDENT, "x"⟩`。

## 6. 字面量

### 6.1 整数字面量

```
IntLit → [0-9]+
```

规则：

- 贪婪读取连续十进制数字；
- **不支持**进制前缀（无 `0x`、`0b`、`0o`）；
- **不支持**数字分隔符（`1_000` 切分为 `INT(1)` 与 `IDENT(_000)`）；
- **不支持**正号前缀（`+1` 是 `PLUS` 与 `INT(1)` 两个单元，由语法层组合）；
- **不支持**科学计数法（`1e5` 切分为 `INT(1)` 与 `IDENT(e5)`）。

负数的表示：`-1` 切分为 `MINUS` 与 `INT(1)`，一元负号在语法层构造 `UniExpr("-", IntLit(1))`。因此**不存在负的整数字面量单元**。

### 6.2 浮点字面量

```
FloatLit → [0-9]+ '.' [0-9]+
```

小数点之后必须至少有一位数字。判定顺序为：先贪婪读取整数部分，再检查后继是否为 `.` 且 `.` 之后是否为数字；两者皆满足时继续读取小数部分并产出 `FLOAT`，否则回退为 `INT`（`.` 留待下一次切分）。

推论：

| 源文本 | Token 序列 |
|---|---|
| `1.0` | `FLOAT("1.0")` |
| `1.` | `INT("1")` `DOT` |
| `1.x` | `INT("1")` `DOT` `IDENT("x")` |
| `1.0.0` | `FLOAT("1.0")` `DOT` `INT("0")` |
| `.5` | `DOT` `INT("5")` |

浮点字面量的类型语义见第三卷；其精度语义见第四卷 §8（`Rat` 为实现层浮点，`Real` 为精确符号值）。

### 6.3 字符串字面量

```
StrLit → '"' { StrChar } '"'
StrChar → 任意字符 除 '"' 除 '\'
        | Escape
Escape → '\' ( 'n' | 't' | 'r' | '"' | '\\' | Other )
```

转义序列的解释：

| 序列 | 值 |
|---|---|
| `\n` | 换行 `U+000A` |
| `\t` | 制表 `U+0009` |
| `\r` | 回车 `U+000D` |
| `\"` | 双引号 |
| `\\` | 反斜杠 |
| `\X`（其他任意 X） | X 本身 |

规则：

- `STR` 单元的 `text` 是**已去引号、已解转义**的内容；
- 字符串必须闭合。源文本结束时仍未遇右引号，报 `E-LEX`（消息「字符串未闭合」），位置为**开引号**处；
- 反斜杠后若为源文本末尾，同样报 `E-LEX`；
- 换行符可以直接出现在字符串内（未转义的 `\n` 字符被视为普通字符）；
- **不存在单引号字符字面量**。`'a'` 中的 `'` 是未识别字符，报 `E-LEX`；
- 字符串插值（`$name`、`${expr}`）**不在词法层处理**：插值内容作为字符串的普通字符进入 `text`，由语法层重新切分与解析（见第二卷 §7.10）。

### 6.4 字面量与标识符的边界

数值起始字符优先于一切标识符规则。因此 `123abc` 切分为 `INT("123")` 与 `IDENT("abc")`，而非一个单元。

## 7. 标识符

凝华有三类标识符。

### 7.1 普通标识符

```
Ident → IdentStart { IdentCont }
IdentStart → '_' | 任意 Unicode 字母
IdentCont → '_' | 任意 Unicode 字母 | 任意 Unicode 数字
```

贪婪读取。读取完成后查关键字表（§8）：命中则产出对应关键字 kind，否则产出 `IDENT`。

**凝华标识符支持中文与其他 Unicode 字母。**`函数名`、`变量`、`α`、`β` 均为合法标识符。

### 7.2 反引号标识符

```
BacktickIdent → '`' { 任意字符 除 '`' 除换行 } '`'
```

规则：

- 反引号内的内容可以是任意字符，包括空格、运算符字符、关键字拼写、数字起始串；
- **不得**包含换行（`\n` 或 `\r`），违反则报 `E-LEX`（消息「反引号标识符不能跨行」）；
- 必须闭合，源文本结束时未闭合报 `E-LEX`（消息「反引号标识符未闭合」）；
- 产出 kind 恒为 `IDENT`，**不查关键字表**。因而 `` `when` `` 是普通标识符，可与关键字 `when` 并存；
- `text` 不含反引号本身。

反引号标识符的典型用途是容纳含空格的定理名，例如 `` `law of excluded middle` ``。

### 7.3 符号标识符

```
SymbolIdent → SymbolChar+
SymbolChar → c  使得  code(c) > 127
                且  ¬isWhitespace(c)
                且  ¬isLetterOrDigit(c)
                且  c ∉ LogicalSingletons
```

贪婪读取连续的 `SymbolChar`，产出单个 `SYMBOL` 单元。

规则与推论：

- `∈`、`≤`、`≥`、`≠`、`⊆`、`○`、`∘`、`∩`、`∪` 均为合法符号标识符；
- `∵`、`∴` 满足 `SymbolChar` 判据，但被 §1.2 序 6 提前拦截，恒为 `BECAUSE`／`THEREFORE`，**不得**作为符号标识符的一部分；
- `LogicalSingletons` 中的九个字符既不能开启符号标识符，也会终止正在读取的符号标识符。因此 `∈∧` 切分为 `SYMBOL("∈")` 与 `LAND`；
- 连续的非逻辑符号字符会被合并为**一个**单元。`≠∈` 切分为 `SYMBOL("≠∈")`。书写自定义命题记号时应当注意此贪婪性；
- 符号标识符不参与关键字判定。

符号标识符在语法层作为**自定义中缀运算符**使用（第二卷 §5.4），在命题层作为**命题头**使用（第四卷 §2）。

## 8. 关键字

### 8.1 硬关键字表

关键字表是如下有限映射：

```
fun → FUN          class → CLASS       struct → STRUCT
enum → ENUM        var → VAR           impl → IMPL
for → FOR          if → IF             else → ELSE
unchecked → UNCHECKED   when → WHEN    is → IS
by → BY            type → TYPE         return → RET
def → DEF
```

共 16 项。

### 8.2 硬关键字的效力

硬关键字是**保留字**：它们在任何位置都被切分为对应 kind，不得作为普通标识符使用。若需要一个与关键字同拼写的名字，必须使用反引号标识符（§7.2）。

### 8.3 非关键字

以下拼写**不是**关键字，而是普通 `IDENT`；它们在特定语法位置由语法层按文本识别（见第二卷）：

| 拼写 | 语法层识别位置 |
|---|---|
| `in` | 中缀成员判断位；类型类约束位 |
| `then` | 命题位 `if … then … else …` |
| `as` | 模式 `is T as x` 的绑定名之前 |
| `axiom` | `unchecked.axiom[…]` 的成员位 |
| `not` | 一元否定（等价于 `¬`） |
| `forall` | 量词位，归一为 `∀` |
| `exists` | 量词位，归一为 `∃` |
| `exists1` | 量词位，归一为 `∃!` |
| `self` | impl 方法体内的接收者名 |
| `的内部值` | 后缀选择子 |

`in` 的地位需要特别说明：它是**去关键字化**的名字。凝华把 `a in b` 定义为普通的中缀函数调用 `in(a, b)`（第二卷 §7.4），`in` 因此与用户自定义的任何双参函数没有区别，不必占用保留字。

## 9. 邻接标记

### 9.1 定义

`precededBySpace` 是凝华消歧机制的基础。其定义：

> Token `t` 的 `precededBySpace` 为 `true`，当且仅当在 `t` 之前、上一个 Token 之后，词法分析器跳过了**至少一个**平凡元素字符。

平凡元素包括空白与注释（§3）。因此：

```subl
f<T>     // `<` 的 precededBySpace = false
f < T    // `<` 的 precededBySpace = true
f/*不支持*/<T   // 块注释非法，此处不成立
f//注释
<T       // `<` 的 precededBySpace = true
```

### 9.2 邻接规则

`<` 与 `>` 是重载最严重的两个字符。凝华以邻接标记消歧：

| 形态 | 邻接 | 语义 |
|---|---|---|
| `f<T>` | `<` 紧贴 `f` | 实例化：向 `f` 提供类型实参或命题供给 |
| `f(a)<p>` | `<` 紧贴 `)` | 上下文列表：函数的上文／下文 |
| `a < b` | `<` 前后有空格 | 值世界中缀比较 |
| `a > b` | `>` 前后有空格 | 值世界中缀比较 |

词法层**只记录**邻接事实，不作任何消歧判定；消歧由语法层依第二卷 §5 的规则执行。

### 9.3 词法层的职责边界

词法分析器不得：

- 合并或拆分 Token 以适配语法期望；
- 依据上下文改变某个 Token 的 kind；
- 对 `precededBySpace` 作语义解释。

## 10. 词法分析判断式

### 10.1 整体判断

```
⊢ src ⇒ toks
```

读作：源文本 `src` 词法分析得到 Token 序列 `toks`（末尾含 `EOF`）。

### 10.2 规则

```
──────────────────────────────  (L-EMPTY)
⊢ ε ⇒ [⟨EOF, "<eof>", 1, 1, true⟩]


src = w · rest    ⊢ w 是平凡元素    ⊢ rest ⇒ toks    跳过了至少一个字符
──────────────────────────────────────────────────────────────────────  (L-TRIVIAL)
⊢ src ⇒ toks 且 toks 首元素的 precededBySpace 置为 true


src = t · rest    ⊢ t 依 §5→§6→§7→§4 顺序切分为单元 u    ⊢ rest ⇒ toks
──────────────────────────────────────────────────────────────────────  (L-TOKEN)
⊢ src ⇒ ⟨u.kind, u.text, line, col, precededBySpace⟩ :: toks


⊢ src 的首字符不属于任何合法单元起始
──────────────────────────────────────  (L-FAIL)
⊢ src ⇒ E-LEX
```

规则 `L-TOKEN` 中的判定顺序必须严格执行：**多字符优先匹配（§5）先于字面量（§6）先于标识符（§7）先于单字符（§4）**。但 `§1.2` 的字符分类给出了更前置的拦截：数字、双引号、反引号、`∵`/`∴`、标识符起始、符号起始六类在进入多字符匹配表之前即已分流。完整的判定顺序为：

```
1. 数字起始        → readInt（§6.1、§6.2）
2. 双引号          → readString（§6.3）
3. 反引号          → readBacktickIdent（§7.2）
4. ∵ / ∴           → BECAUSE / THEREFORE
5. '_' 或字母      → readIdent（§7.1，含关键字判定）
6. 符号起始        → readSymbol（§7.3）
7. 多字符匹配表    → §5
8. 单字符表        → §4
9. 其他            → E-LEX
```

## 11. 词法错误

词法错误一律使用诊断码 `E-LEX`，等级为**错误**，阻断编译。

| 场景 | 消息形态 |
|---|---|
| 未识别字符 | `这个字符 'X' 语言不认识` |
| 未识别的全角标点 | `这个字符 '（' 语言不认识（这是中文全角符号，请换成英文半角符号）` |
| 字符串未闭合 | `字符串未闭合` |
| 反引号标识符未闭合 | `反引号标识符未闭合` |
| 反引号标识符跨行 | `反引号标识符不能跨行` |

错误消息必须携带 `文件名:行:列` 前缀。词法错误是**致命错误**：一旦抛出，词法分析立即终止，不产出部分 Token 序列，语法分析不启动。

## 12. 与语法层的接口

词法分析向语法层交付一个完整的 `List<Token>`。语法层可以：

- 向前查看任意多个 Token（无限制回溯）；
- 读取每个 Token 的 `precededBySpace`；
- 依据 `kind` 与 `text` 双重条件判定（例如中缀 `in` 需 `kind == IDENT && text == "in"`）。

语法层不得要求词法层重新切分，也不得自行合并相邻 Token。唯一的例外是字符串插值：语法层取出 `STR` 单元的 `text`，对其中的插值片段**重新调用词法分析器**（见第二卷 §7.10）。

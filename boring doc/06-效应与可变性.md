# 第六卷 · 效应与可变性

> 本卷规定凝华的纯度系统、停机证明、可变性系统、引用别名与深拷贝、原子性、异步效应。
> 设计目标：用户不承担很大的心智负担，同时程序里不出现满天飞的副作用与可变变量。语言的取向是**用不可变的东西与纯函数构造程序**。

---

## 1. 基本纪律

凝华的默认状态：

| 维度 | 默认 | 改变方式 |
|---|---|---|
| 变量可变性 | **不可变** | `@mut` 注解 |
| 函数纯度 | **纯** | `@impure` 注解 |
| 结构体字段 | **不可变** | `@mut` 注解（结构体本身也须 `@mut`） |
| 函数异步性 | **同步** | `@async` 注解 |
| 值语义 | **拷贝** | `@ref` 注解（别名） |

这一纪律的表述是：**默认纯、不可变；副作用与可变性必须显式标注。**

逃逸口是 `unchecked`（第二卷 §4.12）：不方便标注时用它显式逃逸，从那一刻起正确性由用户负责。

## 2. 纯度

### 2.1 纯函数的默认地位

函数在没有标注 `@impure` 的时候，默认就是**纯函数**。

纯函数有它的自然命题 `pure<f>`。若不纯函数证明了该命题，则认为是纯函数。

```
"impure" ∉ f.annotations
────────────────────────────────────────  (E-PURE-FACT)
全局事实集 := 全局事实集 ∪ {pure<f>}
```

### 2.2 纯函数的三项要求

纯函数必须做到如下三个要求：

```
① 体内不能有不纯的表达式
② 不能修改外部捕获的可变变量
③ 必须证明自己停机
```

标注 `@impure` 时，解除上述限制。

### 2.3 纯度检查规则

**其一，纯作用域调用不纯函数**：

```
当前作用域 pure = true     被调函数 g 的 "impure" ∈ g.annotations     pure<g> ∉ Γ
────────────────────────────────────────  (E-IMPURE-CALL)
报错 E-IMPURE-CALL
```

**放行条件**：Γ 中含有 `pure<g>` 时，即使在纯作用域调用不纯的 `g` 也放行：

```subl
@impure fun side() : Null {}

fun pureCaller() <pure<side>> : Null {
    side()          // 上下文持有 pure<side> ⇒ 放行
}

@impure
fun main() {
    unchecked.axiom[pure<side>]     // @impure 函数不自动注册 pure，前件需显式供给
    pureCaller()
}
```

**其二，lambda 修改外部捕获的可变变量**：

```
lambda 体内对外部捕获的可变变量赋值
────────────────────────────────────────  (E-LAMBDA-IMPURE)
该 lambda 判定为不纯，其函数类型的 purity = "impure"
```

**其三，纯度随函数值传递**：函数类型的 `purity` 字段承载纯度信息。`@impure` 函数类型的实参，其传入的函数值必须也是不纯的（或至少允许不纯）：

```subl
fun runIt(f : @impure () => Null) : Null = f()
runIt({ print("x") })        // 合法：期望类型允许不纯
```

### 2.4 纯度与相等命题

**不纯函数的调用是不纯表达式，不承认不纯表达式的相等命题，包括自反。**

```
e 含不纯调用
────────────────────────────────────────  (E-IMPURE-NO-EQ)
e = e 不可证        e₁ = e₂ 不可证（除非显式注入 Γ）
```

详见第四卷 §1.3。

### 2.5 纯度与上下文的关系

```
函数的参数类型可变时，函数必须标注 @impure
────────────────────────────────────────  (E-IMPURE-REQUIRED)
形参类型含 MutType 且 "impure" ∉ annotations ⇒ 报错 E-IMPURE-REQUIRED
```

理由：可变参数意味着函数可能修改传入的可变状态，这是副作用。

### 2.6 纯度与命题世界

**上下文（命题、`∴`、守卫）中的表达式必须纯。**证明系统不处理副作用。

不纯表达式在命题世界中的地位见第四卷 §1.3：连自反都不承认。

方法调用与字典分发在无法确定被调符号时，**保守视为不纯**——匹配「不上价值的调用不参与」的原则。

## 3. 停机证明

### 3.1 要求

纯函数**必须证明自己停机**（§2.2 要求 ③）。

### 3.2 递归停机证明的两条路

关于递归的停机证明有两条：

**其一，结构递归**：证明每次递归的时候，递归的函数参数是原先的**子结构**，并且在递归到空结构时停止。

```subl
fun len(xs : List[Nat]) : Nat = when(xs) {
    Nil          => 0
    is Cons(h, t) => 1 + len(t)      // t 是 xs 的子结构
}
```

**其二，数值递归**：证明每次递归的时候，递归的函数参数**向着某个数值靠拢**，并且在递归到那个数值的时候停止。

```subl
fun fact(n : Nat) : Nat = if (n <= 1) { 1 } else { n * fact(n - 1) }    // n - 1 向 0 靠拢
```

### 3.3 判定规则

```
纯函数 f 的自递归调用 f(a₁…aₖ)
∀i. aᵢ 既不是形参的语法子项，也不是形参的数值递减
────────────────────────────────────────  (E-NON-STRUCTURAL-REC)
报错 E-NON-STRUCTURAL-REC
```

**语法子项的判定**：变量实参沿「子结构血缘链」向上追溯（例如 `when` 解构出的 `t` 追溯到 `xs`），若到达某个形参则认定为语法子项。**形参自身不算子项**（`f(n)` 中的 `n` 不是 `n` 的子项）。

**数值递减的判定**：只认两种形态，其中 `p` 是当前函数的形参名、`k` 是非零常量：

```
p - k     （k > 0，向下递减）
p + k     （k < 0，向上递增）
```

**检查范围**：仅检查**纯函数的自递归**（被调名等于当前函数名）。**互递归不检查。**

**豁免**：`@impure` 标注或处于 `unchecked` 内时跳过检查。

### 3.4 停机失败的处理

**编译模式**：报 `E-NON-STRUCTURAL-REC`，阻断编译。

**脚本模式（开启全局类型推导）**：不报错，而是**降级为 `@impure`**：

```
自递归且实参不递减
────────────────────────────────────────  (E-AUTO-IMPURE)
自动标注 @impure      发 D-AUTO-IMPURE 补充级诊断
```

含义：把「未证明停机」当作一个**效应来源**，并入效应推断引擎。

```subl
fun rec() = rec()          // 未证停机 → 自动标 @impure
fun g() { rec() }          // g 也 impure（效应传播）
```

决策理由：脚本短，用户自己承担「这个函数可能不停」的风险；报错会破坏脚本的书写体验。**降级而非报错**，且效应传播与「体内调 `print`」是同一种源，走同一传播机制。

## 4. 变量

### 4.1 默认不可变

变量默认是不可变的，除非注解 `@mut`。

```subl
var n = 0               // 不可变
// n = 1                // 报错 E-IMMUT-ASSIGN

@mut var m = 0
m = m + 1               // 合法
```

### 4.2 赋值检查

```
赋值 x = e
x 未标注 @mut（且不在 unchecked 内）
────────────────────────────────────────  (E-IMMUT-ASSIGN)
报错 E-IMMUT-ASSIGN
```

赋值目标必须是变量名或字段访问链，否则报 `E-ASSIGN-TARGET`。

### 4.3 可变变量与相等命题

**可变变量除了自反外，不承认它与其他表达式的相等命题。**

```
x 标注 @mut
────────────────────────────────────────  (E-MUT-NO-EQ)
不注入 x = e        仅保留 x = x（自反）
```

理由：可变变量的值会变，绑定等式保不住。

### 4.4 建议做法

如果确实想让可变变量配合上下文系统，建议直接写一个新的不可变变量赋值它，或者用 `let` 类函数。**证明不可变的最好办法，就是让编译器看见你亲自把可变性割掉。**

## 5. 可变结构体

### 5.1 两级标注

**为结构体标注 `@mut`，表示允许结构体声明可变属性。结构体的属性可以注解 `@mut`，此时结构体的属性可变。**

```subl
@mut
struct T(@mut n : Nat)
```

两个 `@mut` 缺一不可：

| 标注 | 作用 |
|---|---|
| `@mut struct` | 允许该结构体声明可变字段 |
| `@mut` 字段 | 该字段可变 |

### 5.2 可变视图

修改结构体的可变属性，需要**变量持有的结构体类型可变**。在结构体类型前面加上 `@mut` 表示变量的结构体可变——这称为**可变视图**。

```subl
var a : @mut T = T(0)
var b : T = T(0)
a.n = 1                // 正常：可变视图 + 可变字段
//b.n = 1              // 编译不通过：不可变视图没有修改权
```

### 5.3 字段写入检查

```
赋值 r.field = e
────────────────────────────────────────  (E-FIELD-WRITE)
必须同时满足：
  ① field 标注了 @mut
  ② r 持有的类型是 MutType（可变视图）
违反 ① 或 ② 均报 E-NOT-MUT
```

### 5.4 可变结构体的判定

```
"struct" 的 annotations 含 "mut"，或其任一字段含 "mut"
────────────────────────────────────────  (E-MUT-STRUCT)
该结构体类型判定为可变结构体类型
```

可变结构体类型的变量绑定**不注入字段等式**（第五卷 §4.2）。

### 5.5 伴生命题与可变字段的冲突

```
结构体的伴生命题引用了标注 @mut 的字段
────────────────────────────────────────  (E-STRUCT-MUT-PROP)
报错 E-STRUCT-MUT-PROP
```

理由：伴生命题在构造时证明、在参数位注入，而可变字段的值会变，命题保不住。

## 6. 可变类型与拷贝

### 6.1 类型层的可变性

**为类型类注解 `@mut`，表示允许类型类声明可变函数。类型类的函数可以注解 `@mut`，即可变函数，这表示这个函数只能在类型可变的时候调用，可变函数可以修改实现时结构体的可变属性。**

```subl
@mut
class T {
    @mut
    fun add(n : Nat)
}
```

**类型可以注解 `@mut`，这表示类型是可变类型。**

### 6.2 可变函数的调用条件

```
调用 m 的方法 f，f 标注 @mut
────────────────────────────────────────  (E-MUT-METHOD)
接收者必须持有 @mut 视图，否则报 E-NOT-MUT
```

### 6.3 隐式转换与深拷贝

**可变类型与不可变类型之间的类型转换是隐式的，并且会触发深拷贝。可变类型转可变类型也会发生深拷贝。**

```subl
var a : @mut T = T(0)
var b : T = a
a.n = 1
print(b.n)              // 此时仍然是 0
```

```subl
var a : T = T(0)
var b : @mut T = a
b.n = 1
print(a.n)              // 此时仍然是 0
```

```subl
var a : @mut T = T(0)
var b : @mut T = a
b.n = 1
print(a.n)              // 此时仍然是 0
```

三个例子的共同点：**只要涉及 `@mut` 视图的绑定，默认拷贝。**

### 6.4 引用别名 @ref

**对于可变类型变量，如果明确想分享同一个对象，需要为变量标注 `@ref`。**

```subl
@ref var a : @mut T = T(0)
@ref var b : @mut T = a
b.n = 1
print(a.n)              // 此时是 1
```

**可变引用传给不可变引用**：修改可变引用的结构体，不可变引用会观察到结构体变化，只是不可变引用没有对结构体的修改权而已，并且引用是别名语义。

```subl
@ref var a : @mut T = T(0)
@ref var b : T = a
a.n = 1
print(b.n)              // 此时是 1
```

### 6.5 引用与非引用互传

**当引用变量和非引用变量互传时，会触发深拷贝。**

```subl
@ref var a : @mut T = T(0)
var b : @mut T = a
a.n = 1
print(b.n)              // 此时是 0
```

```subl
var a : @mut T = T(0)
@ref var b : @mut T = a
a.n = 1
print(b.n)              // 此时是 0
```

### 6.6 拷贝规则汇总

```
判定「绑定 x = e 是否触发深拷贝」：
────────────────────────────────────────  (E-DEEP-COPY)
需要拷贝 ⟺ (源或目标任一侧持有 @mut 视图，或任一侧是 @ref)
           ∧ ¬(源与目标双侧均为 @ref)
```

一句话规则：**只要涉及 `@mut` 视图或 `@ref` 的绑定，默认拷贝；只有双侧都是 `@ref` 才是别名。**

| 源 | 目标 | 结果 |
|---|---|---|
| `@mut T` | `T` | 深拷贝 |
| `T` | `@mut T` | 深拷贝 |
| `@mut T` | `@mut T` | 深拷贝 |
| `@ref @mut T` | `@ref @mut T` | **别名共享** |
| `@ref @mut T` | `@ref T` | **别名共享**（不可变引用可观察修改） |
| `@ref @mut T` | `@mut T` | 深拷贝 |
| `@mut T` | `@ref @mut T` | 深拷贝 |

深拷贝点必须发 `D-DEEP-COPY` 补充级诊断。

### 6.7 深拷贝的语义

深拷贝是**递归**的：结构体的字段、列表的元素、`Optional` 与 `Result` 的载荷都递归复制。

**对函数深拷贝时，深拷贝函数闭包捕获的变量。**

### 6.8 上下文对引用的态度

上下文对于引用变量的态度与可变变量一致：**`@ref` 变量的绑定等式一律不注入 Γ**（第五卷 §4.2）。

## 7. 原子性

### 7.1 定义

原子操作是不可分割的最小操作。为支持原子操作的类型标注 `@atomic` 表示对这个类型的读写是原子的。

```subl
@mut var counter : @atomic Nat = 0
counter = counter + 1
```

### 7.2 适用范围

目前自然数、整数、有理数、字符串等都可以标注原子性注解；容器类型也可以标注原子性注解。

### 7.3 透明性

`@atomic` 修饰**类型**，是**透明标记**：

```
────────────────────────────────────────  (E-ATOMIC-TRANSPARENT)
@atomic τ ≡ τ
```

运行时无额外包装，不改变类型本身。

### 7.4 与可变性的关系

`@atomic` **只是原子性标记**：变量仍需 `@mut` 才能赋值。`@atomic` 不含可变性。

```subl
var x : @atomic Nat = 0
// x = 1              // 报错 E-IMMUT-ASSIGN：@atomic 不带来可变性
```

### 7.5 与不可变性的关系

`@atomic` **不破坏不可变性**。在单线程的实现目标下按值读写，原子性注解不引入共享可变状态。

## 8. 异步效应

### 8.1 异步函数

标注 `@async` 的函数是**异步函数**。

**只有异步函数可以调用异步函数。**与 JavaScript 的区别是：**没有 `await` 关键词，调用异步函数自动 `await`。**

```subl
@async
fun worker(name : Str) : Null {
    print("worker " + name)
}

@impure
fun main() {
    worker("a")              // 异步调用，自动 await（不需要写 await）
}
```

```
非 @async 上下文调用 @async 函数
────────────────────────────────────────  (E-NEED-ASYNC)
报错 E-NEED-ASYNC
```

自动 `await` 发 `D-AUTO-AWAIT` 补充级诊断。

**天然异步的上下文**：

- `main()` 天然是 async 上下文；
- `Task { … }` 的体天然 async。

需要副作用的异步函数同时标 `@impure @async`。

### 8.2 异步传染

```
g 标注 @async     f 体内调用 g     f 未标注 @async
────────────────────────────────────────  (E-ASYNC-INFECT)
报错 E-NEED-ASYNC（f 必须标注 @async）
```

### 8.3 任务 Task

```subl
var t = Task {                // 创建任务（此时不启动）
    print("child task")
}
t.start()                     // 启动（不阻塞）
t.join()                      // 挂起直到完成，取返回值
print(toStr(t.isAlive()))     // 是否仍在运行
```

规则：

- `Task { … }` 是**块表达式**（不是 lambda），体天然 async；
- Task 的方法集是 `{start, join, isAlive}`；
- `join()` 前必须先 `start()`，否则报 `E-NOT-STARTED`；
- 在同步上下文调 `join()` 报 `E-NEED-ASYNC`；
- Task 体可以有返回值：`var t = Task { 42 }`，`t.join()` 拿到 42。

### 8.4 通道 Channel

`Channel` 是一类协调异步发送与处理数据的类型。

```subl
var ch : Channel[Nat] = Channel<Nat>(2)     // 有缓冲通道，容量 2
ch.send(1)                                 // 缓冲满时发送方挂起
ch.send(2)
var v : Nat = ch.receive()                 // 缓冲空时接收方挂起
ch.close()                                 // 关闭
print(toStr(ch.isClosed()))                // true
```

规则：

- **创建通道时可以选择缓冲模式，默认值是无缓冲**（容量 0）。无缓冲通道的发送与接收必须配对，否则挂起等待；
- **通过 `send` 将数据放入通道。如果通道已满，发送方会等待，直到有空间**；
- **通过 `receive()` 从通道取出数据。如果通道为空，接收方协程会等待，直到有数据到达**；
- FIFO 保序：先发送先接收；
- 方法集是 `{send, receive, close, isClosed}`；
- `close()` 之后的 `send`／`receive` 报 `E-CHANNEL-CLOSED`；
- 创建 `Channel` 时缺类型参数报 `E-TYPE-MISSING`。

**书写约定**：类型标注写 `Channel[Nat]`（类型位用方括号），创建调用写 `Channel<Nat>(容量)`（调用位类型实参用尖括号）。

**接收的智能转换**：本地未关闭通道的 `receive()` 智能转换为 `T`（直接拿到解包值）；通道来自参数或已关闭时返回 `Optional[T]`，要用 `when` 解包：

```subl
@impure @async
fun consume(ch : Channel[Nat]) : Null {
    var x = ch.receive()          // 参数位 → Optional[Nat]（保守）
    when (x) {
        is Some(v) => print("val=" + toStr(v))
        None       => print("closed")
    }
}
```

### 8.5 锁 Mutex

为了防止异步情况下的数据竞争，提供了 `Mutex` 类型以用于管理异步数据修改。

它提供 `lock()`、`unlock()`、`withLock(f : @impure () => Null)` 等函数。

```subl
@mut struct Counter(@mut n : Nat)

@impure @async
fun bump(m : Mutex, c : @mut Counter) : Null {
    m.withLock(fun() {
        c.n = c.n + 1                    // 临界区，退出即解锁
    })
}

@impure
fun main() {
    var m = Mutex()
    var c : @mut Counter = Counter(0)
    var t = Task { bump(m, c) }
    t.start()
    t.join()
}
```

规则：

- `Mutex()` 创建（无类型参数）；
- `lock()`／`unlock()` 是底层加解锁，一般直接用 `withLock(f)`；
- `withLock` 的参数类型是 `@impure () => Null`——传 lambda 或匿名函数皆可，纯度随函数值传递；
- `lock`／`unlock`／`withLock` 本身是**挂起操作**，需要异步上下文。

### 8.6 流 Flow

`Flow` 是惰性冷流，提供很多用于组合的函数，比方说 `map` 之类的。

在内使用 `emit(1)` 发送数据，在外使用 `collect` 消费数据。

```subl
var fl = Flow {
    emit(1)                              // emit 只能在 Flow 体内
    emit(2)
    emit(3)
}

fl.collect(fun(x : Nat) {                 // 消费每个发射值
    print("flow " + toStr(x))
})

var doubled = fl.map({ x => x * 2 })     // 派生冷流（不立即执行）
doubled.collect(fun(x : Nat) {
    print("doubled " + toStr(x))
})
```

规则：

- 创建语法 `Flow { emit(v); … }`（块表达式，体为异步生成器）；
- `map(f)` 派生新冷流；`collect(f)` 消费；
- **`emit(v)` 仅在 Flow 体内合法**，否则报错；
- 方法集是 `{collect, map}`；
- **惰性**：`collect` 时才执行生成器体。

### 8.7 异步内建工具

`core.async` 提供内建工具函数（`@root`，编译器内建实现，全部 `@impure @async`）：

| 函数 | 语义 |
|---|---|
| `delay(ms)` | 显式延时（毫秒），`sleep` 的语义包装 |
| `runBoth(f, g)` | 先启动 `f`（不阻塞），主路径继续 `g`，join 等 `f` 收尾 |
| `runSeq(f, g)` | 先做完 `f` 再做 `g`（串行语义） |
| `collectToList(fl)` | 收集为列表（发送序保持） |
| `collectCount(fl)` | 计数 |
| `collectAll(fl, p)` | 谓词全称判定（短路） |
| `withMutex(m, f)` | 等价于 `m.withLock(f)` |
| `bumpCounter(m, c)` | 计数器的读-改-写复合操作 |
| `bumpPair(m₁, m₂, c₁, c₂)` | 双计数器的复合操作 |
| `channelFromList(xs)` | 建通道并发完即关 |
| `sendAll(ch, xs)` | 逐一发送 |
| `channelDrain(ch)` | 收到关闭为止（FIFO） |
| `channelPipe(src, dst)` | `src` 收一个往 `dst` 发一个，`src` 关则关 `dst` |

### 8.8 异步的实现约束

受限于 JavaScript 的编译目标，异步并不能做得很复杂——不过本来也不需要做得很复杂。

**脚本模式与异步**：脚本模式是同步解释，异步引入挂起-恢复语义，与线性执行模型冲突，因此脚本模式**移除所有异步特性**（`@async`／`Task`／`Channel`／`Mutex`）。脚本的顶层就是入口，不存在异步上下文；在脚本中调用异步函数会因缺少异步上下文而报 `E-NEED-ASYNC`。

## 9. 效应推断（脚本模式）

### 9.1 定位

效应推断是脚本模式全局类型推导的一部分（第九卷 §6），默认关闭。编译模式下效应必须显式标注。

### 9.2 传播规则

```subl
class B { fun f() }
impl B for A { fun f() = print(n + 1) }
//                ↑ impure
```

推演：

1. impl 体内调 `print`（impure）；
2. 推 `impl B for A.f` 为 **impure**；
3. **向上传播**到 `class B.f`——`B.f` 的效应 = 所有 impl 效应的 **join**；
4. 于是 `class B { @impure fun f() }`；
5. **继续向上**：`B.f` 的调用点，其所在函数的效应也 join 上 impure。

### 9.3 效应推断是标记传播，不是约束求解

| 维度 | 类型推断 | 效应推断 |
|---|---|---|
| 约束形式 | `T : Num` | `f : impure` |
| 求解 | 合一 | **join** |
| 冲突 | 有（冲突报错） | **无冲突**（join 恒存在） |
| 传播方向 | 使用点 → 声明 | 实现 → 接口 |

### 9.4 多 impl 的 join

```subl
impl B for A1 { fun f() = 1 }             // pure
impl B for A2 { fun f() = print("x") }    // impure
// B.f 效应 = pure ⊔ impure = impure
```

**所有调用点按 impure 处理**（牺牲 `A1` 的纯度优势，保证健全）。

### 9.5 传播顺序

与类型推断一致，走强连通分量的拓扑序。效应传播**无环**（join 单调），迭代三轮足够。

**`pure<f>` 命题的注册时机**：在效应推断**完成之后**。推为 pure → 注册 `pure<f>`；推为 impure → 不注册。

### 9.6 效应源

| 源 | 判定 |
|---|---|
| 体内调用非纯符号 | 内建不纯函数、标准库 `@impure` 函数、已推为 impure 的脚本函数 |
| 停机检查失败 | 自递归且实参不递减（§3.4） |
| 修改捕获的可变变量 | lambda 体内赋值外部可变变量 |

### 9.7 边界

不做**效应多态**（形如 `fun map[ε](f : T => U with ε)`）。类型类接口只需一个**上界**（具体效应值），不需要接受任意效应参数。

────────────────────────────────────────  (E-IMPURE-REQUIRED)    @mut 形参须 @impure

## 11. 效应层的诊断

| 码 | 等级 | 触发条件 |
|---|---|---|
| `E-IMPURE-CALL` | 错误 | 纯函数里调了有副作用的函数 |
| `E-IMPURE-REQUIRED` | 错误 | 参数带 `@mut T`，函数必须标 `@impure` |
| `E-IMMUT-ASSIGN` | 错误 | 给不可变变量赋值 |
| `E-ASSIGN-TARGET` | 错误 | 赋值目标不是变量或字段链 |
| `E-NOT-MUT` | 错误 | 修改字段需要可变视图；可变方法缺 `@mut` 视图 |
| `E-STRUCT-MUT-PROP` | 错误 | 结构体伴生命题引用 `@mut` 字段 |
| `E-NON-STRUCTURAL-REC` | 错误 | 纯函数递归停止性存疑（参数没有在变小） |
| `E-NEED-ASYNC` | 错误 | 非 `@async` 上下文调用 `@async` 函数 |
| `E-NOT-STARTED` | 错误 | Task 未 `start` 就 `join` |
| `E-CHANNEL-CLOSED` | 错误 | 已关闭通道的 `send`／`receive` |
| `E-TYPE-MISSING` | 错误 | Channel 创建缺类型参数 |
| `D-DEEP-COPY` | 补充 | 绑定／赋值涉及 `@mut` 类型时发生了深拷贝 |
| `D-AUTO-IMPURE` | 补充 | 全局类型推导自动标注 `@impure`（停机失败降级） |
| `D-AUTO-AWAIT` | 补充 | 异步调用自动 await |

---

## 12. 建议

- 优先写**纯 + 不可变**代码（函数式风格），少用 `@mut`／`@ref`；
- 把可变性「割掉」：需要新值时，写一个新的不可变变量；
- 证明命题时尽量用不可变值——可变变量与 `@ref` 的等式命题在上下文里不成立；
- 真需要就地修改（计数器、缓存、共享状态），用 `@mut struct` + `@mut` 视图 + 必要时 `@ref` 别名，**把可变性关进最小的笼子**；
- `unchecked` 是手术刀不是瑞士军刀：逃逸过的代码不再受编译器保护，确认不了行为时宁可改标注。

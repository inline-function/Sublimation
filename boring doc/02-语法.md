# 第二卷 · 语法

> 本卷规定凝华源文本的抽象语法结构、文法产生式、表达式解析规则与脱糖规则。
> 词法单元的种类与切分见第一卷。

---

## 1. 抽象语法

### 1.1 语法树的组织

一个源文件的语法树是 `FileAst`，它由**条目**（Entry）序列构成。条目分两类：

```
FileAst   = ⟨ entries : List<Entry> ⟩
Entry     = DeclEntry ⟨ decl : Decl ⟩
          | StmtEntry ⟨ stmt : Stmt ⟩
```

`StmtEntry` 仅在脚本模式合法（§9.1）。工程模式的顶层只允许 `DeclEntry`。

### 1.2 位置信息

每个语法节点携带一个**位置**字符串，形如 `行:列`。位置用于诊断输出。节点的位置是其**首个 Token** 的位置。

### 1.3 节点总览

抽象语法分为六个范畴：

| 范畴 | 成员数 | 定义处 |
|---|---|---|
| 类型 `Type` | 7 | §2 |
| 理论参数 `TheoryParam` | 2 | §3.1 |
| 声明 `Decl` | 7 | §3 |
| 语句 `Stmt` | 15 | §4 |
| 表达式 `Expr` | 28 | §5 |
| 模式 `Pattern` | 7 | §6 |

## 2. 类型语法

### 2.1 类型种类

```
Type = NamedType      ⟨ name : String,  args : List<Type> ⟩
     | FunType        ⟨ params : List<Type>,  ret : Type,  purity : String,
                        theory : List<TypeParam>,  context : List<Expr>? ⟩
     | TupleType      ⟨ items : List<Type> ⟩
     | MutType        ⟨ inner : Type ⟩
     | AtomicType     ⟨ inner : Type ⟩
     | UnionType      ⟨ variants : List<Type> ⟩
     | QualifiedType  ⟨ module : List<String>,  name : String,  args : List<Type> ⟩
```

各种类的语义见第三卷。本节只规定其书写形式。

### 2.2 产生式

```
Type            → '@mut' Type                                   ⟶ MutType
                | '@atomic' Type                                ⟶ AtomicType
                | '@impure' FunType                             ⟶ FunType(purity = "impure")
                | '[' TypeParamList ']' FunOrTupleType          ⟶ 多态函数类型
                | FunOrTupleType
                | NamedType
                | Type '|' Type { '|' Type }                    ⟶ UnionType

FunOrTupleType  → '(' [ TypeList ] ')' [ Context ] '=>' Type    ⟶ FunType
                | '(' [ TypeList ] ')'                          ⟶ TupleType

Context         → '<' ExprList '>'

NamedType       → NameSegment { '.' NameSegment } [ '[' TypeList ']' ]
                  单段 ⟶ NamedType     多段 ⟶ QualifiedType

TypeList        → Type { ',' Type } [ ',' ]
TypeParamList   → TypeParam { ',' TypeParam } [ ',' ]
TypeParam       → Name [ '[' '_' { ',' '_' } ']' ]
```

### 2.3 书写约定

**类型实参用方括号 `[]`，函数调用的类型实参用尖括号 `<>`。** 两套括号职责分明：

```subl
var xs : List[Nat] = listOf(1, 2)      // 类型位：[]
var ch : Channel[Nat] = Channel<Nat>(2) // 类型位 []，调用位 <>
var o  : Box[Nat] = Some(9)             // 泛型头别名，类型位 []
```

尖括号 `<>` 在调用位兼任三种职责：类型实参、命题供给、命题项。三者的区分由被调函数的签名决定（第五卷 §6）。

### 2.4 函数类型

函数类型的完整形式：

```
'(' [参数类型…] ')' [ '<' 上下文 '>' ] '=>' 返回类型
```

纯度标注 `@impure` 置于最前：

```subl
(A) => B                    // 纯函数类型
@impure (A) => B            // 不纯函数类型
[T](T) => T                 // 多态函数类型
(Nat) <n > 0> => Null       // 携带上下文的函数类型
```

多态函数类型的理论参数表 `[T]` 位于参数表之前。

### 2.5 元组类型与单元类型

```subl
()             // 空元组类型（Null 的别名语义，见第三卷）
(Nat)          // 单元组类型
(Nat, Str)     // 二元组类型
```

单元素的 `()` 括号不构成元组，而是分组或空元组，由语法层依上下文判定。

### 2.6 联合类型

```subl
Nat | Str              // 二元联合
Nat | Str | Bool       // 多元联合
```

联合类型主要用于模式匹配的穷尽性结论（第七卷 §6）。

### 2.7 推导占位类型

脚本模式下省略类型标注时，语法层填入占位类型 `InferMarker`，其规范文本为 `<infer>`。`InferMarker` 由全局类型推导阶段替换为真实类型（第九卷 §6），**语义检查器永不遇见它**。

## 3. 声明

### 3.1 理论参数

```
TheoryParams    → '[' TheoryParam { ',' TheoryParam } [ ',' ] ']'
TheoryParam     → '@' Name                                    ⟶ PropParam(name)
                | Name [ '[' '_' { ',' '_' } ']' ] [ ':' Constraint ]
                                                              ⟶ TypeParam(name, arity, constraint)
```

理论参数分两类：

- **类型参数** `TypeParam`：以大写字母书写（约定，非强制）。`arity` 是其后 `_` 占位符的个数：`T` 的 arity 为 0，`F[_]` 的 arity 为 1，`G[_, _]` 的 arity 为 2。arity > 0 的类型参数称为**kind 形参**，用于高阶类型（第三卷 §7）。
- **命题参数** `PropParam`：以 `@` 前缀书写，小写字母命名（约定）。其全称量词形式写作 `∀@p`。

携带命题参数的函数称为**超越函数**。

### 3.2 函数声明

```
FunDecl → { Annotation } 'fun' Name [ TheoryParams ] [ Params ]
          [ Constraints ] [ PreContext ]
          [ ':' [ Type ] [ PostContext ] ]
          [ Body ]

Params      → '(' [ Param { ',' Param } [ ',' ] ] ')'
Param       → { '@' Name } ( Destruct | Name ) [ ':' Type ] [ '=' Expr ]
Destruct    → '(' Name { ',' Name } [ ',' ] ')'
Constraints → '<' ConstraintItem { ',' ConstraintItem } [ ',' ] '>'
ConstraintItem → Name Op Expr          Op ∈ { '<=', '>=', '==', '!=' } 或 IDENT 'in'
PreContext  → '<' ExprList '>'
PostContext → '<' ExprList '>'
Body        → '=' Expr  |  BlockExpr          二者互斥
```

`FunDecl` 的节点字段：

```
FunDecl ⟨ name, annotations, theory, params, preps, retType, posts, body, constraints, pos ⟩
```

其中 `preps` 是上文（前置命题列表），`posts` 是下文（后置命题列表），`constraints` 是类型类约束列表。

**完整签名的读法**：

```
fun 函数名[理论参数](实际参数)<上文> : 返回类型<下文>
```

- 理论参数：类型参数与命题参数；
- 实际参数：表达式层面的形参；
- 上文：调用该函数**之前**必须在 $\Gamma$ 中成立的命题；
- 下文：调用该函数**之后**注入 $\Gamma$ 的命题。

示例：

```subl
fun f(x : Nat) <x > 0> : Nat <$ >= 0> = x + 1
```

**函数体两种形态互斥。**同时书写 `= {` 是语法错误：

```subl
fun f() : Nat = { 1 }     // 错误：表达式体不带花括号，块体不带等号
fun f() : Nat = 1         // 正确：表达式体
fun f() : Nat { return 1 } // 正确：块体
```

**返回类型可省略。**省略时由推导填充（表达式体取体类型；块体取全部 `return` 的共同类型）。

**形参不允许默认值**，违反报 `E-DEFAULT-PARAM`。只有结构体字段允许默认值。

**变长形参**：形参标注 `@list` 时采用 Kotlin vararg 语义——形参声明**元素类型** `T`，函数体内该形参的类型是 `List[T]`，调用端的剩余位置实参自动打包：

```subl
fun sum(@list xs : Nat) : Nat = sumList(xs)
sum(1, 2, 3)      // xs 在体内是 List[Nat]
```

### 3.3 结构体声明

```
StructDecl → { Annotation } 'struct' Name [ TheoryParams ]
             [ '(' [ Param { ',' Param } [ ',' ] ] ')' ]
             [ '<' ExprList '>' ]
```

节点字段：`StructDecl ⟨ name, theory, fields, annotations, props, pos ⟩`，其中 `props` 是**伴生命题**列表。

规则：

- 结构体的成员表**必须**是圆括号参数列表。书写大括号体是语法错误；
- 无字段的结构体可省略括号：`struct Unit`；
- 字段**允许**默认值：`struct Item(count : Nat = 1)`；
- 字段可携带注解：`struct T(@mut n : Nat)`；
- 尾随的 `<…>` 是伴生命题，在构造该结构体时必须被证明（第五卷 §5.4）。

示例：

```subl
struct User(name : Str, age : Nat)
struct PosPoint(x : Nat, y : Nat) <x > 0, y > 0>
struct Item(count : Nat = 1)
```

### 3.4 枚举声明

```
EnumDecl → { Annotation } 'enum' Name [ TheoryParams ]
           [ '{' { Ctor } '}' ]
Ctor     → Name [ '(' Type { ',' Type } [ ',' ] ')' ] [ ',' | ';' ]
```

节点字段：`EnumDecl ⟨ name, theory, ctors, pos ⟩`，`Ctor ⟨ name, fields : List<Type> ⟩`。

规则：

- 构造子的字段是**类型列表**而非参数列表（字段无名，按位置访问）；
- 构造子之间以 `,` 或 `;` 分隔，最后一个可省略；
- 无构造子的枚举可省略花括号：`enum Empty`；
- 带字段的构造子即代数数据类型：`enum Result[T, E] { Ok(T), Err(E) }`；
- 零参构造子书写时可带空括号 `None()`，也可省略 `None`。二者在值层等价，在模式层的差别见 §6.3。

### 3.5 类型类声明

```
ClassDecl → { Annotation } 'class' Name [ TheoryParams ]
            [ ':' ParentType { ',' ParentType } ]
            [ '{' { { Annotation } FunDecl } '}' ]
```

节点字段：`ClassDecl ⟨ name, theory, annotations, members, parents, pos ⟩`。

规则：

- 类型类以 `class` 关键字声明（凝华的 `class` **不是**面向对象语言的类，而是 Haskell 意义下的 typeclass）；
- `parents` 是父类型类列表，支持子类型类继承：`class Monad[F[_]] : Functor[F[_]]`；
- 成员是**签名级** `FunDecl`，可以只有签名（此时是抽象方法），也可以带函数体（此时是默认实现）；
- 成员可携带注解，其中 `@mut` 表示可变方法，`@new` 表示这不是实现类方法集的函数；
- 无成员的类型类可省略花括号。

### 3.6 impl 声明

```
ImplDecl → 'impl' Type [ 'for' Type ] [ 'by' Name ] '{' { { Annotation } FunDecl } '}'
```

节点字段：`ImplDecl ⟨ trait : Type?, self : Type, members, delegate : String?, pos ⟩`。

三种形态：

**其一，实现类型类**（`trait` 与 `self` 均非空）：

```subl
impl Show for User {
    fun show() : Str = self.name
}
```

**其二，扩展方法**（无 `for`，`trait` 为空）：

```subl
impl User {
    fun isAdult() : Bool = self.age >= 18
}
```

成员脱糖为带 `self` 首参的**自由函数**（§8.8），后续链路零感知。

**其三，委托实现**（`by`）：

```subl
impl Show for Wrapper by inner { … }
```

`delegate` 是被委托的字段名；字段不存在报 `E-BY-UNBOUND`。

**高阶类型简写**：`impl Functor[List]` 等价于 `impl Functor for List[a]`。其中 `Functor` 必须是本文件已声明的类型类名；`List` 的 kind 占位 `a` 自动补齐；`self` 中的大写零实参名（如 `Result[_, E]` 的 `E`）被收集并并入各成员的理论参数尾部。

### 3.7 类型别名声明

```
TypeAliasDecl → 'type' Name [ TheoryParams ] '=' Type
```

节点字段：`TypeAliasDecl ⟨ name, theory, target, pos ⟩`。

```subl
type MyNat = Nat                        // 简单别名
type NatOpt = Optional[Nat]             // 容器别名
type Box[a] = Optional[a]               // 泛型头别名
type Dict[k, v] = Map[k, v]             // 多参数泛型头
type Pred = (Nat) => Bool               // 函数类型别名
type PairT = (Nat, Str)                 // 元组类型别名
```

别名是**纯类型层设施**：编译期展开，不生成任何运行时代码。泛型头的参数按位置逐位代入（第三卷 §8）。

### 3.8 命题定义声明

```
PropDefDecl → 'def' DefName [ '<' Name { ',' Name } '>' ]
              [ '↔' | '<=>' ] [ '<' Expr '>' | Expr ]
```

节点字段：`PropDefDecl ⟨ name, params : List<String>, equiv : Expr?, pos ⟩`。

`DefName` 可以是标识符、符号标识符、或以下任一运算符 Token：

```
'='  'in'  '+'  '-'  '*'  '/'  '%'  '=='  '!='  '<='  '>='
'&'  '|'  '->'  '<->'  '<'  '>'
```

示例：

```subl
def =<a, b>                       // 声明二元谓词 =
def ≠<a, b> ↔ ¬<a = b>            // 带等价式的定义
```

带等价式的定义在证明时按定义展开（第四卷 §5.1）。

规则：

- 自定义命题**不约束参数的类型**。因此 `1 ∈ 2`、`"ok" ≥ 0` 这类荒谬命题在语法与类型层均合法，只是无法被证明（除非经由 `unchecked`）；
- 自定义命题的项**只能是表达式**。当前不支持像内建命题那样对类型与命题进行量化。

### 3.9 注解

```
Annotation → '@' Name
```

注解在抽象语法树中以**名字字符串列表**表示（`annotations : List<String>`），不带参数。注解是通用容器：所有可注解的节点（函数、结构体、类型类、枚举、变量声明、形参、字段）都携带该列表。

**内建注解**是编译器额外认识的名字：

| 注解 | 挂载位置 | 编译器行为 |
|---|---|---|
| `@mut` | var／param／field／struct／class | 可变性检查（第六卷） |
| `@ref` | var | 引用别名语义（第六卷 §6） |
| `@impure` | fun／函数类型 | 纯度检查（第六卷 §2） |
| `@async` | fun | 异步传染（第六卷 §8） |
| `@atomic` | 类型 | 原子性标记（第六卷 §7） |
| `@root` | fun | 内建白名单检查，代码生成层特判 |
| `@host` | fun | 宿主 API 声明（第九卷 §5） |
| `@theorem` | fun | 登记为定理函数（第四卷 §7） |
| `@axiom` | fun | 下文签名即公理，不做自动证明 |
| `@classic` | decl | 挂载 `core.classic`，启用经典逻辑 |
| `@new` | impl 成员 | 声明这不是实现类方法集的函数 |
| `@list` | param | 变长实参（§3.2） |
| `@allMut` | struct | 由注解处理器改写为 `@mut`（第八卷 §5） |

**用户自定义注解**（如 `@MyCheck`）编译器不认识，原样透传，由注解处理器读取。

注解名不得由用户自行定义命名空间：注解名的空间由宿主与标准库提供，用户只使用。

## 4. 语句

### 4.1 语句种类

```
Stmt → VarStmt         ⟨ name, annotations, type : Type?, value : Expr, destruct : List<String>?, pos ⟩
     | AssignStmt      ⟨ target : Expr, value : Expr, pos ⟩
     | ExprStmt        ⟨ expr : Expr, pos ⟩
     | ReturnStmt      ⟨ expr : Expr?, label : String?, pos ⟩
     | FunStmt         ⟨ fn : FunDecl, pos ⟩
     | BTSStmt         ⟨ form : Expr, premises : List<Expr>, conclusion : Expr, pos ⟩
     | IfPropStmt      ⟨ prop : Expr, thenStmts : List<Stmt>, elseStmts : List<Stmt>, pos ⟩
     | WhenPropStmt    ⟨ disjunction : Expr, arms : List<WhenPropArm>, pos ⟩
     | StrategyStmt    ⟨ strategy : String, goal : Expr, pos ⟩
     | ExistIntroStmt  ⟨ names : List<String>, witnesses : List<Expr>, prop : Expr, pos ⟩
     | ExistsElimStmt  ⟨ name : String, prop : Expr, body : List<Stmt>, pos ⟩
     | ByStmt          ⟨ props : List<Expr>, pos ⟩
     | AxiomStmt       ⟨ props : List<Expr>, pos ⟩
     | UncheckedStmt   ⟨ inner : Stmt, pos ⟩
```

辅助节点：`WhenPropArm ⟨ condition : Expr, body : List<Stmt>, pos ⟩`。

依总纲公理一，全部语句都是表达式：它们在值层的类型是 `Null`（`ReturnStmt` 的类型是 `Nothing`）。

### 4.2 产生式

```
Stmt → ExistsStmt | FunStmt | IfPropStmt | WhenPropStmt | ThereforeStmt
     | BTSStmt | UncheckedStmt | ReturnStmt | ByStmt | StrategyStmt
     | VarStmt | AssignStmt | ExprStmt

VarStmt      → { Annotation } 'var' [ Destruct ] Name [ ':' Type ] '=' Expr
AssignStmt   → PostfixExpr '=' Expr          左值仅限 NameRef 与 FieldExpr
ExprStmt     → Expr
ReturnStmt   → 'return' [ '@' Name ] [ Expr ]
FunStmt      → 'fun' { Annotation } FunDecl
```

### 4.3 变量声明

```subl
var n = 0                        // 不可变，类型由初值推导
var x : Int = -3                 // 显式标注
@mut var m = 0                   // 可变
@ref var a : @mut T = T(0)       // 引用别名
var (p, q) = pair                // 元组解构
```

规则：

- **变量默认不可变**。可变性必须由 `@mut` 显式标注；
- 类型标注可省略，省略时由初值类型推导，并发 `D-TYPE-INFERRED` 补充级诊断；
- 解构形式要求初值是元组，且分量数一致，否则报 `E-TUPLE-DESTRUCT`／`E-TUPLE-ARITY`。

### 4.4 赋值

赋值目标只能是变量名或字段访问链：

```subl
m = m + 1          // 变量赋值
a.n = 1            // 字段赋值
a.b.c = 1          // 嵌套字段赋值
```

其他形态（如对函数调用结果赋值）报 `E-ASSIGN-TARGET`。给不可变变量赋值报 `E-IMMUT-ASSIGN`。

### 4.5 return

```
ReturnStmt → 'return' [ '@' Name ] [ Expr ]
```

规则：

- `return` **仅在函数体块的顶层语句位合法**。lambda 与嵌套块内使用报 `E-RETURN-OUTSIDE`——它们在代码生成层是立即执行函数，`return` 无法逃出；
- 裸 `return`（无表达式）等价于 `return null`，用于返回类型为 `Null` 的函数；
- `@' Name` 是标签，用于指定返回的目标函数（多层嵌套时）；
- `return` 的类型是 `Nothing`，其后同层的语句报 `W-UNREACHABLE`。

### 4.6 因为-所以语句

因为-所以语句的形式严格规定如下：

```
BTSStmt → '∵' Form { ',' Premise } '∴' Conclusion
Form        → Expr
Premise     → Expr
Conclusion  → Expr
```

三部分的角色：

- `∵` 之后的**第一个**命题是**形式**（form）——即要调用的定理所构造的全称量词命题；
- 其后由逗号分隔的命题是**前提**（premises）——编译器用自动证明验证它们；
- `∴` 之后是**结论**（conclusion）——必须是该定理后件的实例。

示例：

```subl
∵ ∀a b . (a : Rat ∧ b : Rat) → ((a + b) = (b + a)),
  a : Rat, b : Rat
∴ (a + b) = (b + a)
```

语义规则（第四卷 §6.1 给出完整判定）：

1. 编译器从符号表查找构造了 `form` 这一形式的**定理函数**；
2. 逐一验证 `premises` 在当前 $\Gamma$ 下可证。验证仍走自动证明；前提证不出报 `E-PREMISE-UNPROVEN`；
3. 判断 `conclusion` 是否为该定理的后件实例。不是则报 `E-CANNOT-PROVE`；
4. 一切通过后，`conclusion` 被注入 $\Gamma$。

该语句固定返回 `Null`。

**兼容简写**：

| 形态 | 脱糖为 |
|---|---|
| `∴ q` | `BTSStmt(⊤, [], q)` |
| `∵ p`（后无逗号也无 `∴`） | `BTSStmt(⊤, [], p)` |

### 4.7 非真即假语句

```
IfPropStmt → 'if' '[' Expr ']' BlockExpr [ 'else' BlockExpr ]
```

把 `if` 的圆括号换成方括号，即构成命题层的非真即假语句（分类讨论的特例，二分）：

```subl
if[n < 0] {
    // 此处 Γ 含 n < 0
    ∴ ¬<n < 0>
} else {
    // 此处 Γ 含 ¬(n < 0)
    ∴ ¬<n < 0>
}
// 语句之后 Γ 含 ¬<n < 0>
```

两支分别以 $p$ 与 $\lnot p$ 入上下文；语句证明**两支共同的结论**并注入 $\Gamma$。使用经典逻辑规则（排中律、反证）需要先挂载 `@classic`，否则报 `E-NEED-CLASSIC`。两支无共同结论报 `E-IF-CONCLUSION-MISMATCH`。该语句固定返回 `Null`。

### 4.8 分类讨论语句

```
WhenPropStmt → 'when' '[' Expr ']' '{' { WhenPropArm } '}'
WhenPropArm  → Expr [ '=>' ] BlockExpr [ ',' ]
```

把 `when` 的圆括号换成方括号，即构成命题层的分类讨论语句：

```subl
when[n > 0 ∨ n < 0] {
    n > 0 => { ∴ n ≠ 0 }
    n < 0 => { ∴ n ≠ 0 }
}
// 语句之后 Γ 含 n ≠ 0
```

规则：

- 方括号内必须是一个**析取式**，且该析取式必须已在 $\Gamma$ 中。不在则报 `W-PROP-UNBOUND`；
- 分支是「条件 + 语句块」，**没有 `else` 臂**；
- 各支分别假设一个析取支；语句证明**各支共同的结论**并注入 $\Gamma$；
- 无共同结论报 `W-WHEN-NO-COMMON`；
- 该语句固定返回 `Null`。

### 4.9 存在语句

存在语句有两种形态。

**存在引入**：

```
ExistIntroStmt → '∃' Name '=' Expr { ',' Name '=' Expr } '.' Expr
```

```subl
∃ x = 0 . x : Nat ∧ x = 0
```

给出见证，证明替换后的性质，从而注入 `∃ x . (x : Nat ∧ x = 0)`。见证部分的命题证不出报 `E-QUANT-UNPROVEN`。

**存在消去**：

```
ExistsElimStmt → '∃' Name '.' Expr [ BlockExpr ]
```

从 $\Gamma$ 中已有的存在命题取出一个新鲜名字，在块内使用。前提不在 $\Gamma$ 中报 `E-PROP-UNBOUND`。

两种语句均固定返回 `Null`。

### 4.10 策略语句

```
StrategyStmt → '@' Name '[' Expr ']'
```

```subl
@simp[(3 * 2 + 6) = 12]
```

调用命名证明器（策略）证明该命题。策略由编译器或注解处理器提供，默认不启用。证明失败报 `E-STRATEGY-FAILED`。该语句固定返回 `Null`。

### 4.11 公理语句与辅助策略

```
AxiomStmt → 'unchecked' '.' 'axiom' '[' Expr { ',' Expr } ']'
ByStmt    → 'by' '[' Expr { ',' Expr } ']'
```

```subl
axiom ∀n . tagged<n>      // 无条件注入公理
by [中间命题]                         // 注入人给的中间命题
```

`axiom …` 是**命题逃逸**：直接把命题塞入 $\Gamma$，不经证明器检验。`by […]` 是辅助策略，同样直接注入，用于把大结论拆成小步。

`by` 另有**后缀式**（表达式位）：`e by [p₁, p₂]`，见 §5.4。

### 4.12 unchecked 语句

```
UncheckedStmt → 'unchecked' Stmt
```

包裹单条语句，绕过该语句的纯度、可变性与证明义务检查：

```subl
unchecked frozen = frozen + 1     // 绕过 E-IMMUT-ASSIGN
unchecked print(get7())           // 绕过纯度检查
var v = unchecked 1               // 表达式位的 unchecked
```

`unchecked` 是凝华唯一的逃逸口。逃逸过的代码不再受编译器保护，正确性由用户负责。

### 4.13 局部函数声明

```
FunStmt → 'fun' { Annotation } FunDecl
```

函数可以声明在块内。局部函数声明构成一个**全称量词引入**：其签名所构造的自然命题被登记为块内局部定理（第四卷 §6.6）。

### 4.14 语句分隔

语句之间以**换行**或**分号**分隔。分号是可选的；语法层在语句边界处跳过任意多个分号。

两条语句黏连而无分隔是语法错误：

```subl
a = 1 b = 2      // 错误：两条语句要换行或分号分隔
a = 1; b = 2     // 正确
```

## 5. 表达式

### 5.1 表达式种类

```
Expr = IntLit          ⟨ value : String, pos ⟩
     | FloatLit        ⟨ value : String, pos ⟩
     | StrLit          ⟨ value : String, pos ⟩
     | NameRef         ⟨ name : String, pos ⟩
     | ReturnSym       ⟨ pos ⟩                        // '$'
     | ParamRefExpr    ⟨ index : Int, pos ⟩           // '$n'
     | TopExpr         ⟨ pos ⟩                        // '⊤'
     | BotExpr         ⟨ pos ⟩                        // '⊥'
     | BinExpr         ⟨ op : String, left : Expr, right : Expr, pos ⟩
     | UniExpr         ⟨ op : String, operand : Expr, pos ⟩
     | CallExpr        ⟨ callee : Expr, args : List<Expr>,
                        namedArgs : Map<String, Expr>, pos ⟩
     | SymbolCallExpr  ⟨ op : String, args : List<Expr>, pos ⟩
     | FieldExpr       ⟨ target : Expr, name : String, pos ⟩
     | FunRefExpr      ⟨ target : Expr, name : String, pos ⟩
     | InstExpr        ⟨ target : Expr, terms : List<Expr>, pos ⟩
     | LambdaExpr      ⟨ params : List<String>, body : Expr, pos ⟩
     | AnonFunExpr     ⟨ name, theory, params, preps, retType, posts, body, pos ⟩
     | BlockExpr       ⟨ stmts : List<Stmt>, pos ⟩     派生：tailExpr : Expr?
     | TupleExpr       ⟨ items : List<Expr>, pos ⟩
     | StructCtorExpr  ⟨ struct : String, assigns : List<Pair<String, Expr>>, pos ⟩
     | IfExpr          ⟨ cond : Expr, thenBlock : BlockExpr,
                        elseBlock : BlockExpr?, pos ⟩
     | WhenExpr        ⟨ subject : Expr?, subjectBinding : String?,
                        arms : List<WhenArm>, pos ⟩
     | QuantExpr       ⟨ q : String, names : List<String>, body : Expr, pos ⟩
     | TypeTestExpr    ⟨ target : Expr, type : Type, pos ⟩
     | IsPatExpr       ⟨ target : Expr, pat : Pattern, pos ⟩
     | TaskExpr        ⟨ body : BlockExpr, pos ⟩
     | FlowExpr        ⟨ body : BlockExpr, pos ⟩
     | VarExpr         ⟨ name, annotations, type : Type?, value : Expr, pos ⟩
     | ByExpr          ⟨ target : Expr, props : List<Expr>, pos ⟩
```

辅助节点：`WhenArm ⟨ pattern : Pattern, guard : Expr?, cond : Expr?, body : Expr, pos ⟩`。

`WhenArm` 的 `pattern` 与 `cond` 互斥使用：有主题的 `when` 用 `pattern`（可带 `guard`），无主题的 `when` 用 `cond`。

### 5.2 表达式种类数

共 28 种。

### 5.3 核心设计：不实现运算符优先级

**凝华刻意不实现运算符优先级。**全部中缀运算符具有相同优先级，且一律**左结合**。

这一决定的后果是：

```subl
1 + 2 * 3        // 解析为 (1 + 2) * 3 = 9，而非 7
```

为避免歧义，编译器在检测到「右侧运算符的算术优先级高于左侧已存运算符」的形态时，发出 `H-ARITH-PRECEDENCE` 提示，建议用户加括号。**该提示不改变解析结果**，优先级表仅用于生成提示：

| 运算符 | 提示用优先级 |
|---|---|
| `^` | 3 |
| `*` `/` `%` | 2 |
| `+` `-` | 1 |
| 其他 | 0 |

因此凝华代码的规范风格是：**混合不同算术运算符时必须显式加括号。**

### 5.4 表达式解析规则

```
Expr → Unary { InfixTail }
```

`Unary` 先解析，随后进入一个循环，每轮消费一个中缀构造并把右侧作为 `Unary` 解析。循环中各分支的判定顺序**是文法的一部分**，如下表。表中「条件」列的判定按行序进行，首个命中者生效。

| 序 | 形态 | 条件 | 产出 |
|---|---|---|---|
| 1 | 停止词 | `then`／`else` 作为 `IDENT` 出现在命题位 | 终止循环 |
| 2 | 箭头停止 | `->`／`=>`；或 `when` 守卫中带空格的 `(` | 终止循环 |
| 3 | `by` | `BY` 单元后跟 `[` | `ByExpr(left, props)` |
| 4 | `>` | `GT` **前后有空格**且其后有操作数，且处于上下文列表内 | `BinExpr(">", left, right)` |
| 5 | `<` | `LT` **前后有空格** | `BinExpr("<", left, right)` |
| 6 | `is` | `IS` 单元，同行 | `TypeTestExpr` 或 `IsPatExpr`（见 §5.7） |
| 7 | `..` | `RANGE` 单元 | `BinExpr("..", left, right)` |
| 8 | `in` | `IDENT` 且文本为 `in` | `CallExpr(NameRef("in"), [left, rangeOperand])` |
| 9 | 内建运算符 | 属于 `BinOps` 集合 | `BinExpr(op, left, right)` |
| 10 | 符号标识符 | `SYMBOL` **前后有空格** | `BinExpr(text, left, right)` |
| 11 | `的内部值` | `IDENT` 且文本为 `的内部值` | `CallExpr(NameRef("的内部值"), [left])` |
| 12 | 标识符中缀 | `IDENT`，**前后均有空格**，且与前一个 Token 同行 | `CallExpr(NameRef(text), [left, right])` |

其中：

```
BinOps = { +, -, *, /, %, ^, =, :, <=, >=, &, |, ->, <->, ==, !=, ∧, ∨, →, ↔ }

RangeOperand → Unary [ '..' Unary ]
```

序 8 的右操作数可以吞下一个区间：`x in 0..10` 解析为 `in(x, (0..10))`。

### 5.5 一元表达式

```
Unary → '-' Unary                                   ⟶ UniExpr("-")
      | '!' Unary                                   ⟶ UniExpr("!")
      | '¬' Unary                                   ⟶ UniExpr("¬")
      | 'not' Unary                                 ⟶ UniExpr("¬")
      | '<' ExprList '>'                            ⟶ 命题括号
      | Postfix
```

**命题括号** `<e>` 用于在表达式位书写命题，主要出现在 `def` 的等价右式与量词体中：

```subl
def ≠<a, b> ↔ ¬<a = b>
```

`¬` 与 `!` 在值层与命题层的解释不同：`!` 是值世界的布尔取反，`¬` 是命题世界的否定（第四卷 §2）。

### 5.6 后缀表达式

```
Postfix → Primary { PostfixOp }

PostfixOp → '::' Name                     限定名／枚举成员
          | '.' Name                      字段访问（要求 '.' 无前导空格，或位于行首）
          | '(' Args ')'                  调用
          | '<' ExprList '>'              实例化（要求 '<' 紧贴，无前导空格）
          | '{' Lambda '}'                尾随 lambda
          | '{' Block '}'                 Task／Flow 体
```

**邻接规则在此处生效**：

| 形态 | 解释 |
|---|---|
| `f<T>` | 实例化（`<` 紧贴） |
| `f < T` | 比较（`<` 前后有空格） |
| `f(a)<p>` | 上下文列表（`<` 紧贴 `)`） |

`Task { … }` 与 `Flow { … }` 的花括号是**块表达式**而非 lambda，且仅在被调名为 `Task`／`Flow` 时触发。

### 5.7 基本表达式

```
Primary → INT | FLOAT | STR
        | '$'                                   ⟶ ReturnSym
        | '$n'                                  ⟶ ParamRefExpr(n)
        | '⊤'                                   ⟶ TopExpr
        | '⊥'                                   ⟶ BotExpr
        | '(' Expr ')'                          ⟶ 分组
        | '(' Expr ',' { Expr } ')'             ⟶ TupleExpr
        | '{' Lambda '}'                        ⟶ LambdaExpr
        | 'var' …                               ⟶ VarExpr
        | { '@' Name } 'var' …                  ⟶ VarExpr（带注解）
        | 'fun' …                               ⟶ AnonFunExpr
        | 'if' …                                ⟶ IfExpr
        | 'when' …                              ⟶ WhenExpr
        | Quantifier                            ⟶ QuantExpr
        | IDENT | SYMBOL                        ⟶ NameRef
        | SymbolCallStart '(' Args ')'          ⟶ SymbolCallExpr
        | OpPrefix '(' Args ')'                 ⟶ CallExpr(NameRef(op), args)
```

其中：

```
SymbolCallStart = { '<', '>', '==', '!=', '<=', '>=' }
OpPrefix        = { '+', '*', '/', '%', '&', '|', '->', '<->' }
```

后两条支持**前缀调用**形式，用于把运算符当普通函数使用：

```subl
+(1, 2)             // 等价于 1 + 2
<(a, b)             // 等价于 a < b
!=(m, 0)            // 守卫位推荐写法
```

### 5.8 量词

```
Quantifier → QuantKind QuantNames '.' Expr
QuantKind  → '∀' | '∃' | '∃!' | 'forall' | 'exists' | 'exists1'
QuantNames → { [ '@' | '#' ] Name [ ',' ] }+
```

量词变量名前缀标记其**维度**：

| 前缀 | 含义 |
|---|---|
| 无 | 值参数（表达式维） |
| `@` | 命题参数（命题维） |
| `#` | 类型参数（类型维） |

```subl
∀ x . x ∈ list → p<x>          // 值量化
∀@p . p ∨ ¬<p>                 // 命题量化（排中律）
∀#T . Optional[T] ≠ T          // 类型量化
∃ x . x : Nat ∧ x = 0
∃! x . p<x>                    // 唯一存在
```

ASCII 别名 `forall`／`exists`／`exists1` 在语法层归一为 Unicode 形式。

`.` 是量词变量列表的终止符，其后是量词体。

### 5.9 if 表达式

两种形态：

```
IfExpr → 'if' '(' Expr ')' Branch [ 'else' Branch ]        值层 if
       | 'if' Expr 'then' Expr 'else' Expr                  命题位数学风 if
Branch → BlockExpr | Expr                                    裸表达式自动包装为块
```

值层 `if` 的分支可以是裸表达式，语法层自动包装为 `BlockExpr`。

`then` 不是关键字，是普通 `IDENT`，仅在命题位按文本识别。

### 5.10 when 表达式

```
WhenExpr → 'when' [ '(' Subject ')' ] '{' { WhenArm } '}'

Subject → Expr
        | 'var' Name '=' Expr                    绑定式主题
        | Expr 'in' '_'                          区间模板主题

WhenArm → Pattern [ 'if' Guard ] '=>' Body       有主题
        | Expr '=>' Body                         无主题（条件臂）
        | 'else' '=>' Body                       兜底臂
```

**分支分隔符是 `=>`。**`->` 在 `when` 臂位置不被接受（它在凝华中是蕴含运算符，与分支分隔彻底解耦）。

分支体有两种写法：单表达式（`=> expr`）或语句块（`=> { … }`）。

```subl
when (n) {
    0            => print("零")
    m if m > 10  => print("大")
    else         => print("其他")
}

when {                                    // 无主题条件链
    n < 0  => print("负")
    n == 0 => print("零")
    n > 0  => print("正")
}

when(n in _) {                            // 区间模板
    (0 .. 10)  => print(1)
    (11 .. 20) => print(2)
}

when(var x = f()) {                       // 绑定式主题
    is Some(v) => print(v)
    else => print("空")
}
```

区间模板的语义与穷尽性判定见第七卷 §7。

### 5.11 lambda

```
Lambda → '{' [ ParamList ] ( '=>' | '->' ) LambdaBody '}'     显式参数
       | '{' LambdaBody '}'                                   隐式单参
ParamList → ( Name | '(' Name { ',' Name } ')' ) { ',' … }
LambdaBody → { Stmt } [ Expr ]
```

**lambda 的分隔符 `=>` 与 `->` 均被接受**（与 `when` 臂不同）。规范风格统一使用 `=>`，以避免与蕴含 `->` 混读。

**隐式单参**：lambda 只有一个参数时可以省略参数表，用 `_` 指代：

```subl
var lambda : (Nat) => Nat = { _ + 1 }
xs.map { _ + 1 }
```

`LambdaBody` 是语句序列，末尾的表达式语句退化为 lambda 的值。

### 5.12 匿名函数

```
AnonFunExpr → 'fun' [ '_' ] [ TheoryParams ] [ Params ]
              [ PreContext ] [ ':' Type ] [ PostContext ] [ Body ]
```

匿名函数与具名函数声明的区别仅在于可以没有名字。它可以携带完整的理论参数、上下文与返回类型：

```subl
fun(x : Nat) { print(x) }
fun[T](x : T) : T = x
fun() : Null <p> { axiom p }
```

`fun _` 形式用于显式表示「无名的单参函数」。

### 5.13 实参列表

```
Args → '(' [ Arg { ',' Arg } [ ',' ] ] ')'
Arg  → IDENT '=' Expr            命名实参
     | Expr                      位置实参
```

**命名实参**以 `IDENT` 后紧跟 `ASSIGN`（单等号 `=`）识别；这与命题等价的 `EQ`（双等号 `==`）区分开。

```subl
o.f(b = 1, a = 2)          // 指名调用法
Point(x = 1, y = 2)        // 命名字段构造
```

命名实参**只支持用 `fun` 声明的函数**与结构体构造。类型类字典方法不支持命名实参，违反报 `E-NAMED-ARG`。

尾随逗号在实参列表、参数列表、类型实参列表中均被允许。

## 6. 模式

### 6.1 模式种类

```
Pattern = PatLit   ⟨ value : Expr, pos ⟩
        | PatCtor  ⟨ name : String, args : List<Pattern>, pos ⟩
        | PatTuple ⟨ items : List<Pattern>, pos ⟩
        | PatIs    ⟨ type : Type, bind : String?, pos ⟩
        | PatBind  ⟨ name : String, pos ⟩
        | PatElse  ⟨ pos ⟩
        | PatCond  ⟨ pos ⟩              无主题 when 的条件占位
```

### 6.2 产生式

```
Pattern → 'is' Type [ 'as' Name ]                       ⟶ PatIs
        | 'is' Name '::' Name [ '(' PatternList ')' ]   ⟶ PatCtor（限定名）
        | 'is' Name '(' PatternList ')'                 ⟶ PatCtor
        | 'else'                                        ⟶ PatElse
        | '(' Pattern { ',' Pattern }+ ')'              ⟶ PatTuple
        | '(' Pattern ')'                               ⟶ 退化为子模式
        | INT                                           ⟶ PatLit(IntLit)
        | STR                                           ⟶ PatLit(StrLit)
        | '_'                                           ⟶ PatBind("_")
        | Name '::' Name [ '(' ')' ]                    ⟶ PatCtor（限定名，空参）
        | Name '(' ')'                                  ⟶ PatCtor（空参值比较）
        | Name                                          ⟶ PatCtor（无参；语义层判定为绑定或构造子）

PatternList → Pattern { ',' Pattern } [ ',' ]
```

### 6.3 关键规则

**解构必须显式书写 `is`。**带绑定或嵌套的模式必须写 `is`：

```subl
when (o) {
    is Some(v) => print(v)     // 正确
    Some(v)    => print(v)     // 错误：不带 is 时 Some(v) 不是合法模式
    None       => print("空")  // 正确：无参名只允许值比较形态
}
```

不带 `is` 的裸名 `Name` 有两种可能解释：变量绑定或零参构造子。判定在语义层依名字的首字母大小写与符号表进行。

**嵌套解构**：

```subl
when (result) {
    is Ok(is Some(v)) => print(v)      // 两层构造子
    is Ok(None)       => print("空")
    is Err(e)         => print("错: " + e)
}
```

**`as` 绑定**：

```subl
when (o) {
    is Optional[Nat] as x => print(x)   // 类型分支并绑定整体
}
```

`as` 不是关键字，仅在模式位按文本识别。

**结构体解构**：

```subl
struct T(a : Nat, b : Nat)
when (o) {
    is T(a, b) => print(a)
    else       => print("?")
}
```

**限定名模式**：跨枚举的同名构造子用 `枚举::构造子` 消歧：

```subl
when (c) {
    is Color::Red => …
    is Other::Red => …
}
```

**元组模式**：

```subl
fun firstOf(p : (Nat, Nat)) : Nat = when(p) {
    (a, b) => a
    else   => 0
}
```

### 6.4 模式的语义

模式匹配与上下文系统的融合规则（分支命题、穷尽性、后分支继承前分支的否定）见第七卷。

## 7. 调用法

凝华提供五种调用法。它们都是**语法糖**，在解析期或语义期脱糖为基本形态。

### 7.1 中缀调用法

对于双参函数，或有单参的类型类函数，可以使用中缀调用法：

```subl
1 + 2          // 等于 +(1, 2)，也等于 1.+(2)
xs append ys   // 等于 append(xs, ys)
a ∈ b          // 等于 ∈(a, b)
```

内建运算符走 `BinExpr`，标识符与符号标识符走 `CallExpr`（§5.4 序 10、12）。

标识符中缀要求**前后均有空格且同行**，以与函数调用区分：

```subl
xs append ys    // 中缀调用
xs append(ys)   // 普通调用
```

### 7.2 扩展调用法

任意有参函数的首参可以移动到接收者位置：

```subl
o.f(1, 2, 3)     // 等于 f(o, 1, 2, 3)
size(xs)         // 自由函数
xs.size()        // 扩展调用法（等价）
```

解析时若与类型类方法冲突，**优先类型类**。完整的方法糖解析顺序：

1. 同名自由函数／扩展方法，且首形参类型匹配接收者（优先）；
2. 类型类字典里的方法（按接收者类型解析实例）；
3. 结构体自身的字段（字段访问）。

### 7.3 尾随调用法

如果函数的尾参是函数类型，则匿名函数可以写在参数括号之外：

```subl
list.map { e => e + 1 }              // 等于 list.map({ e => e + 1 })
xs.fold(0) { acc, x => acc + x }     // 等于 xs.fold(0, { acc, x => acc + x })
```

脱糖发生在解析期：尾随 lambda 被追加为 `CallExpr` 的最后一个位置实参，并发 `D-TRAILING` 补充级诊断。

### 7.4 安全调用法

对 `T?`（即 `Optional[T]`）类型使用 `?.` 表示：若为 `None` 则返回 `None`：

```subl
o?.f()         // if(o is Some(o)) o.f() else None
```

等价的展开形式：

```subl
if (o is Some(v)) v.f() else None
```

### 7.5 指名调用法

只支持用 `fun` 声明的函数，按名字传入参数：

```subl
o.f(b = 1, a = 2)      // 若签名是 f(a, b)，则等于 o.f(2, 1)
```

### 7.6 安全替换函数

```subl
fun ?:[T](a : T?, b : T) : T =
    if (a == None) b else a
```

`a ?: b` 是它的中缀形态。

### 7.7 安全转换运算符

`as` 是内建关键词：

```subl
o as T
```

若 `o` 是 `T` 的实例则转换成功，否则返回 `None`。

## 8. 脱糖规则

脱糖（desugaring）是把语法糖改写为基本形态的过程。本节列出全部脱糖规则。每条规则标注其发生阶段：**解析期**（在语法分析中直接产出基本形态）或**语义期**（在语义检查中改写）。

### 8.1 `T?` → `Optional[T]`　【解析期】

```
D-NULLABLE：τ? ⟶ Optional[τ]
```

可空类型语法糖可以嵌套：`T??` ⟶ `Optional[Optional[T]]`。

### 8.2 尾随 lambda　【解析期】

```
D-TRAILING-LAMBDA：f(a) { λ } ⟶ f(a, λ)
                   f { λ }    ⟶ f(λ)
```

### 8.3 中缀调用　【解析期】

```
D-INFIX-OP：  a ○ b   ⟶ BinExpr("○", a, b)        ○ ∈ BinOps
D-INFIX-SYM： a ⊙ b   ⟶ BinExpr("⊙", a, b)        ⊙ 是 SYMBOL 且前后有空格
D-INFIX-ID：  a f b   ⟶ CallExpr(NameRef("f"), [a, b])   f 是 IDENT 且前后有空格、同行
D-INFIX-IN：  a in b  ⟶ CallExpr(NameRef("in"), [a, b])
D-INNER：      e 的内部值 ⟶ CallExpr(NameRef("的内部值"), [e])
```

### 8.4 逻辑运算符归一　【词法期】

```
D-LOGIC-NORM：a && b ⟶ a ∧ b
              a || b ⟶ a ∨ b
```

归一发生在词法层的 `text` 字段（第一卷 §2.2），因此后续全链路统一处理。

### 8.5 量词别名归一　【解析期】

```
D-QUANT-NORM：forall ⟶ ∀     exists ⟶ ∃     exists1 ⟶ ∃!
```

### 8.6 if-is 解构　【解析期】

```
D-IFIS：if (e is pat) A else B ⟶ when (e) { is pat => A ; else => B }
```

条件解析期间置 `ifIsCond` 标记，使 `is Ctor(…)` 产出 `IsPatExpr` 哨兵；`if` 解析器检测到哨兵后整体脱糖为 `WhenExpr`。

**限制**：条件必须是单独的模式判断。组合条件不被接受：

```subl
if (o is Some(e) && e > 0)     // 错误：绑定的 e 也没有作用域
```

组合条件请改用 `when` 分支守卫。

### 8.7 区间模板 when　【解析期】

```
D-WHEN-TEMPLATE：when (t in _) { p₁ => b₁ ; … ; pₙ => bₙ }
                 ⟶ when { t in p₁ => b₁ ; … ; t in pₙ => bₙ }
```

主题 `CallExpr("in", [t, _])` 被识别后，`subject` 置空，`templateBase` 记为 `t`；每个分支的模式 `pᵢ` 被包成 `cond = CallExpr("in", [t, pᵢ])`，`pattern` 用 `PatCond` 哨兵占位。`_` 与 `else` 均映射为 `PatElse`。

### 8.8 无类型类 impl 展开　【解析期】

```
D-EXT-IMPL：impl T { fun m(params) body ; … }
            ⟶ fun m(self : T, params) body ; …
```

成员脱糖为带 `self` 首参的自由函数声明。`self` 类型中的 kind 占位（零实参小写裸名）被提升为成员的理论参数。这是 AST 级展开，后续链路零感知。

### 8.9 高阶类型 impl 简写　【解析期】

```
D-HKT-IMPL：impl Functor[List] ⟶ impl Functor for List[a]
```

`Functor` 必须是本文件已声明的类型类名。`List` 零实参时补 kind 占位 `a`；`self` 中的大写零实参名（如 `Result[_, E]` 的 `E`）被收集为简写变量，并入各成员的理论参数尾部。

### 8.10 字符串插值　【解析期】

```
D-INTERP："prefix$name suffix"  ⟶ concat("prefix", concat(toStr(name), " suffix"))
          "a${expr}b"           ⟶ concat("a", concat(toStr(expr), "b"))
```

字符串被拆分为 `StrLit` 段与 `CallExpr(NameRef("toStr"), [expr])` 段，组装为 `concat` 链。`${}` 内的表达式通过**子解析器重新词法分析**后解析。

```subl
"Hello, $name"
"sum=${x + y}"
```

### 8.11 因为-所以简写　【解析期】

```
D-BTS-BARE：∴ q   ⟶ BTSStmt(⊤, [], q)
D-BTS-ONLY：∵ p   ⟶ BTSStmt(⊤, [], p)      （p 后无逗号也无 ∴）
```

### 8.12 参数引用　【语义期】

```
D-PARAM-REF：$n 在函数的上文／下文中 ⟶ 第 n 个形参的名字
D-RETURN：   $  在函数的下文中 ⟶ 函数体的末表达式
             $  在调用点注入的命题中 ⟶ 调用表达式本身
D-THIS：     this 在函数签名中 ⟶ 函数名
D-SELF：     self 在 impl 方法签名中 ⟶ 接收者表达式
```

`$n` 在**函数体内**使用是错误，报 `E-PARAM-REF-IN-BODY`；`n` 越界报 `E-PARAM-REF`。语义期改写会发 `H-PARAM-REF` 提示，建议直接使用参数名。

### 8.13 零参构造子　【语义期】

```
D-ZERO-CTOR：None（作值引用时） ⟶ None()
```

### 8.14 命题记号归一　【语义期】

```
D-PROP-NORM：∈ ⟶ in        ≠ ⟶ !=        ≤ ⟶ <=        ≥ ⟶ >=
```

归一只发生在**命题比较**层面（用于事实匹配），不改变书写形式。值层的 `<=` 与命题层的 $\le$ 仍是两个不同世界的构造（第一卷 §4.8）。

## 9. 解析模式

### 9.1 脚本模式（scriptMode）

脚本模式放宽以下限制：

- **顶层允许语句**：`Entry` 可以是 `StmtEntry`。工程模式下顶层语句是语法错误；
- **注解后回退**：`@` 之后若不是 `fun`／`struct`／`class`，脚本模式回退到语句解析；工程模式直接报错。

脚本模式的其余语法与工程模式完全一致。

### 9.2 无类型模式（allowUntyped）

该开关仅在脚本模式下可开启，放宽一项限制：

- **形参类型可省略**：省略时填入 `InferMarker` 占位类型。

工程模式下形参必须标注类型，省略是语法错误。

`var` 声明的类型标注在**两种模式下都是可选的**（与该开关无关）。

## 10. 语法分析判断式

$$\vdash\ \text{toks} \Rightarrow \text{ast}$$

读作：Token 序列 `toks` 语法分析得到抽象语法树 `ast`。

凝华的语法分析器是**手写递归下降**，具有无限制向前查看能力（可读取 Token 序列的任意位置）。因此本文的产生式应理解为**判定规则**而非严格的 LL(k) 文法：当产生式存在歧义时，以 §5.4 的分支顺序与 §9 的邻接规则为最终裁决。

语法错误一律使用诊断码 `E-PARSE`，等级为**错误**，阻断编译。语法错误是致命错误：抛出后立即终止，不产出部分语法树。

## 11. 完整示例

以下程序覆盖了本卷规定的主要构造：

```subl
type NatOpt = Optional[Nat]
type Box[a] = Optional[a]

def ≠<a, b> ↔ ¬<a = b>

struct PosPoint(x : Nat, y : Nat) <x > 0, y > 0>

enum Color { Red(), Green(), Blue() }

class Show {
    fun show() : Str
}

impl Show for PosPoint {
    fun show() : Str = "($x, $y)"
}

@theorem
fun leqRefl[a] : Null <a <= a>

fun capped(score : Nat) <score ≤ 100> : Nat <$ ≥ 0> = score

fun grade(n : Nat) <n ∈ (0..30)> : Str =
    when(n in _) {
        (0 .. 10)  => "低"
        (11 .. 20) => "中"
        (21 .. 30) => "高"
    }

@impure
fun main() {
    @mut var counter = 0
    counter = counter + 1

    var p = PosPoint(1, 2)
    print(p.show())

    ∵ ∀a . (a : Nat) → (a ≥ 0),
      counter : Nat
    ∴ counter ≥ 0

    when (counter) {
        0            => print("零")
        m if m > 10  => print("大")
        else         => print("其他")
    }

    var xs = listOf(1, 2, 3)
    print(toStr(xs.map { x => x + 1 }.size()))
}
```

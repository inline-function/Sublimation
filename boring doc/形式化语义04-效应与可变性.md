### 0.1 本卷定义什么

本卷形式化凝华基础方言的四个效应维度及其交互：

## 一、纯度判断系统

### 1.1 pure<f> 命题注册

命名函数默认纯（决策 34）：符号收集完成后一次性注册（`checkFile` 调 `registerPureFacts`，Symbols.kt:16），使互相调用的函数无论声明顺序都能查到对方的纯度。

$$\frac{f \in \Sigma_{\textit{funs}} \qquad \text{"impure"} \notin \textit{anns}(f) \qquad \textit{body}(f) \ne \bot}{\Gamma_g := \Gamma_g \cup \{\text{pure}\langle f\rangle\}} \quad (\text{E-PURE-FACT})$$

良构前提：`f` 已在符号表中登记；`anns(f)` 取用户注解或内建表裁决结果（见下）。对无体的 `@root` 内建声明，纯度由内建表裁决（否则用户写 `@root fun readFile(...)` 不带 `@impure` 会被误注册）：

$$\frac{\textit{body}(f) = \bot \qquad B = \textit{builtinimpure}(f) \lor \textit{builtinPure}(f) \lor \textit{builtinAndroid}(f) \qquad B \ne \bot}{\textit{anns}_{\textit{裁决}}(f) := \textit{anns}(B) \qquad \text{E-PURE-FACT 用 anns}_{\textit{裁决}}\text{ 重新适用}} \quad (\text{E-PURE-ROOT})$$

〔实现现状〕`impl` 方法按方法名注册（Symbols.kt:50–52）：

$$\frac{m \in \Sigma_{\textit{methods}} \qquad \exists e \in \textit{entries}(m).\ \text{"impure"} \notin \textit{anns}(e.\textit{fn})}{\Gamma_g += \text{pure}\langle m\rangle} \quad (\text{E-PURE-METHOD})$$

〔实现现状〕跨模块可见模块的 `pure<f>` 按裸名注册，但同名在任一可见模块有 `@impure` 定义时整名不注册（Symbols.kt:33–47）：

$$\frac{n \in \textit{visibleNames} \qquad \forall p \in \textit{visible}.\ \forall g \in \Sigma_{\textit{funs}}(p).\ n = \textit{name}(g) \Rightarrow \text{"impure"} \notin \textit{anns}(g)}{\Gamma_g += \text{pure}\langle n\rangle} \quad (\text{E-PURE-XMOD})$$

E-PURE-FACT/XMOD/METHOD 注册的是可证事实；`axiom pure<f>` 语句或函数上下文 `<pure<f>>` 也可手工向 Γ 补入同名事实（见 §1.3 放行通道）。

### 1.2 @impure 声明与强制条款

`@impure` 是函数级注解，解除纯函数的全部义务（体内不纯表达式、不改外部捕获、停机性）。唯一强制标注的条款在声明期：

$$\frac{\textit{body}(f) \ne \bot \qquad \text{"impure"} \notin \textit{anns}(f) \qquad \exists p \in \textit{params}(f).\ \textit{expand}(\textit{type}(p)) \in \text{MutType}}{\text{报错 E-IMPURE-REQUIRED}} \quad (\text{E-IMPURE-REQUIRED})$$

良构前提：`f` 有体（`checkFun` 只在有体时被调用，Checker.kt:293–297）；`expand` 展开类型别名后判定（`syms.expand`）；`@ref` 不能写在类型位（Parser 类型位注解只支持 `@mut`/`@atomic`/`@impure`），可变形参语义一律走 `@mut T`。无体的 `@root` 声明可带 `@mut` 形参而不触发本条款（由 `body(f) ≠ ⊥` 前提保证）。

`@impure` 也可出现在类型位修饰函数类型（Parser 类型位注解）：`f: @impure (A) => Null` 把纯度记进 `FunType.purity`，这是函数值纯度随类型传递的入口（§1.4）。

### 1.3 纯作用域调用闸与 pure<f> 放行

纯函数体内调用 `@impure` 函数时：

$$\frac{\text{"impure"} \in \textit{anns}(g) \qquad \pi = \text{pure} \qquad \Gamma \nvdash \text{pure}\langle g\rangle}{\text{报错 E-IMPURE-CALL}} \quad (\text{E-IMPURE-CALL})$$

良构前提：`g` 已解析为具名函数；`Γ ⊢ pure<g>` 搜索 `f.allFacts()` 的 MP 闭包（含 Γ_g）。放行条款（决策 54）：

$$\frac{\text{"impure"} \in \textit{anns}(g) \qquad \Gamma \vdash \text{pure}\langle g\rangle}{\text{调用 } g() \text{ 在纯作用域放行}} \quad (\text{E-DISCHARGE-PURE})$$

`pure` 的来源有三条路径：E-PURE-FACT/XMOD/METHOD 自动注册、`axiom pure<f>` 语句注入、函数上下文 `<pure<f>>`（上文，调用方须供给）。方法路径的纯度原子统一按方法名查询（与 E-PURE-METHOD 对齐）。

可运行示例：

```subl
@impure fun side(): Null {}

fun viaAxiom(): Null {
    axiom pure<side>
    side()
}

fun viaContext() <pure<side>> : Null {
    side()
}
```

### 1.4 lambda 纯度推导

lambda 与匿名函数在检查时进入独立的纯度跟踪：进入时 `λ_impure` 复位为 ⊥、`depth_λ` 加一，体检查结束后取终值为该 λ 的纯度，并恢复外层标记（Checker.kt:1110–1171）。三个不纯源：

$$\frac{\textit{depth}_\lambda > 0 \qquad s \equiv x = e \qquad x \notin \textit{vars}(f_{\textit{当前帧}}) \qquad \textit{isMut}(x)}{\lambda_{\textit{impure}} := \top} \quad (\text{E-LAMBDA-ASSIGN})$$

$$\frac{\textit{depth}_\lambda > 0 \qquad e \equiv \text{NameRef}(x) \qquad x \notin \textit{vars}(f_{\textit{当前帧}}) \qquad \textit{isMut}(x)}{\lambda_{\textit{impure}} := \top} \quad (\text{E-LAMBDA-READ})$$

$$\frac{\text{"impure"} \in \textit{anns}(g) \qquad \textit{depth}_\lambda > 0}{\lambda_{\textit{impure}} := \top} \quad (\text{E-LAMBDA-CALL})$$

良构前提：E-LAMBDA-ASSIGN 的 `x` 是赋值目标 NameRef（Checker.kt:625）；E-LAMBDA-READ 的 `x` 是表达式中的 NameRef（Checker.kt:943）；E-LAMBDA-CALL 在 CallCheck.kt:754 触发，无 `u` 条件。三规则的结论与 `π` 实参无关——这是 §4.3 不变量 U1 的来源。

λ 检查结束时的回填：

$$\frac{\lambda_{\textit{impure}} \text{ 为体检查终值}}{\textit{type}(\lambda) = \text{FunType}(\vec{\sigma},\ \tau,\ \textit{purity} = \begin{cases}\text{"impure"} & \lambda_{\textit{impure}} = \top \\ \text{""} & \lambda_{\textit{impure}} = \bot\end{cases})} \quad (\text{E-LAMBDA-TYPE})$$

$$\frac{\lambda_{\textit{impure}} = \bot}{\Gamma += \text{pure}\langle \lambda \rangle} \quad (\text{E-LAMBDA-PURE})$$

**函数值闸**。λ 带 `purity="impure"` 传作值时，其调用在纯上下文受第二道闸（CallCheck.kt:479–487）：

$$\frac{\textit{type}(v) = \text{FunType}(\_,\ \_,\ \text{"impure"}) \qquad \pi = \text{pure} \qquad u = 0 \qquad \neg\textit{borrowed}(v)}{\text{报错 E-IMPURE-CALL}} \quad (\text{E-IMPURE-CALL-VAL})$$

$$\frac{\textit{callee} \equiv \text{本函数某形参名} \qquad \text{该形参类型} = \text{FunType}(\_,\ \_,\ \text{"impure"})}{\textit{borrowed} := \top \qquad \text{E-IMPURE-CALL-VAL 不适用}} \quad (\text{E-BORROWED})$$

E-BORROWED 是借用效应：HKT 标准库的 `forEach(f : @impure (A) => Null)` 把 impure 函数值声明为形参，形参即显式效应能力（能传出 impure λ 的调用方本身必非纯）。

**边界 B1**〔待核〕：字段写不进 λ 不纯标记——E-LAMBDA-ASSIGN 只匹配赋值目标为 NameRef 的赋值（Checker.kt:619–627），目标为 FieldExpr 时走 `checkMutFieldWrite`（:628/:886–899），后者不置 `λ_impure`。故 `@mut var x = Box(0); var inc = { => x.n = 1 }; inc()` 在纯函数内通过检查。这与「修改外部可变状态即不纯」的字面表述存在缺口，是否为设计意图待核。

### 1.5 纯度与 Γ 的交互

纯度判断影响 Γ 的两项注入策略：

- **绑定等式注入**只用 `isPureValue`（Checker.kt:839–853）：字面量、NameRef、纯中缀表达式、被调函数非 impure 的调用；`@impure` 函数结果不确定，不注入；
- **结构相等豁免**：`containsImpureCall` 判定表达式是否含 `@impure` 调用；命中则该表达式不参与结构相等/自反。

### 1.6 停机闸

纯函数自递归须经停机性检查（决策 44/9）：

$$\frac{\neg\textit{isMethodPath} \qquad \text{"impure"} \notin \textit{anns}(f) \qquad u = 0 \qquad g \equiv f \qquad \neg\exists a \in \textit{args}(g).\ \textit{structuralArg}(a) \lor \textit{numericDescent}(a)}{\text{报错 E-NON-STRUCTURAL-REC}} \quad (\text{E-NON-STRUCTURAL-REC})$$

良构前提：`structuralArg(a)` 指 `a` 是某形参的语法子项；`numericDescent(a)` 指数值实参严格向 0 靠拢；全参数都不递减才算违规；`@impure` 函数与方法路径不受约束。闸门与 `u` 的交互见 §4.2。

## 二、@mut/@ref 视图与别名

### 2.1 四种所有权

变量级所有权 μ 由类型层 `@mut T`（MutType）与变量层注解 `@mut var`/`@ref var` 组合而成：

| μ | 写法 | 语义 |
|---|---|---|
| 纯 | `var x : T` | 不可变值，无特殊视图 |
| @mut | `var x : @mut T` 或 `@mut var x : T` | 唯一所有权可变视图 |
| @ref | `@ref var x : T` | 共享只读别名（变量级注解，不是类型构造子） |
| @ref @mut | `@ref var x : @mut T` | 共享可变别名 |

〔实现现状〕`@ref` 不是类型构造子：Parser 类型位不识别 `@ref`，它是变量声明注解，由 Checker 登记进 `Frame.refs`（Diffusion.kt:29–30）。`@ref @mut T` 的组合语义 = `@ref` 变量持有 `@mut T` 类型。

视图三公理 M-1/M-2/M-3 与 compatibleView（CV-MUT-DOWN/CV-MUT-UP）的定义见 01 卷 §3.1，本卷不重复。以下仅给出效应侧的字段写与可变方法调用规则。

### 2.2 字段写规则

$$\frac{\Delta(r) = \tau_r \qquad (\tau_r \in \text{MutType} \lor \mu(r)) \qquad \Sigma(S) = \text{struct} \qquad f \text{ 是 } S \text{ 的 @mut 字段}}{\Gamma; \pi \vdash r.f = e : \tau_e} \quad (\text{E-FIELD-WRITE})$$

两个前提各自失败都报 E-NOT-MUT（Checker.kt:897/899）：字段须是 @mut 字段，且接收者须持有 @mut 视图（类型为 MutType 或变量在 M 集中）。@atomic 字段写以 AtomicType 内层同判（Checker.kt:890：`rcvType is AtomicType` 时取 `inner`）。

### 2.3 可变方法调用

$$\frac{\text{"mut"} \in \textit{anns}(m) \qquad \tau_{\textit{self}} \notin \text{MutType}}{\text{报错 E-NOT-MUT}} \quad (\text{E-MUT-METHOD-VIEW})$$

良构前提：`m` 是被调方法；`τ_self` 是接收者类型（CallCheck.kt:392–394）。可变方法只能由持有 @mut 视图的接收者调用。

### 2.4 @mut 版本前进与 Γ 等式注入

可变变量的值可随时被赋新，因此以它为轴的等式命题在注入后即可能失效。凝华的处理是源头不注入（决策 35）：

$$\frac{\textit{isPureValue}(e) \qquad \neg\mu(x) \qquad \neg\rho(x) \qquad \neg\textit{refsMut}(e, f) \qquad \neg\textit{isMutStructType}(\tau_x)}{\Gamma += (x = e)} \quad (\text{E-INJ-EQ})$$

$$\frac{\textit{isPureValue}(e) \lor \mu(x)}{\Gamma += (x : T)} \quad (\text{E-INJ-TYPE})$$

良构前提：`isPureValue` 定义见 Checker.kt:839–853；`refsMut` 递归检查表达式是否引用 @mut/@ref 变量（:909–918）；`isMutStructType` 检查类型是否为可变结构体（:903–907）。不注入等式的情形：@mut 变量、@ref 变量、初值引用 @mut 变量、可变结构体类型、初值含 @impure 调用。

## 三、深拷贝四规则

### 3.1 统一谓词

绑定与赋值共享同一个拷贝谓词——编译期 `Checker.binderNeedsCopy`（:865–873）与脚本期 `Evaluator.bindCopy`（:112–118）逐字同构。先抽取合并标记：

- `mut♯_t = (τ_t ∈ MutType) ∨ μ(x)`，`mut♯_s` 同理；
- `pure_t = ¬ρ_t ∧ ¬mut♯_t`，`pure_s` 同理。

定义见 01 卷 §4.1/§4.2，本卷直接引用其规则名 COPY-①②/COPY-③/COPY-④/COPY-SHARE。以下为完整判定矩阵（01 卷 §4.3 的同口径展开）：

| # | 目标 | 源 | mut♯_t | ρ_t | mut♯_s | ρ_s | 判定 | 主条款 |
|---|---|---|---|---|---|---|---|---|
| 1 | T | T | ⊥ | ⊥ | ⊥ | ⊥ | 共享 | — |
| 2 | T | @ref T | ⊥ | ⊥ | ⊥ | ⊤ | 拷贝 | ④ |
| 3 | T | @mut T | ⊥ | ⊥ | ⊤ | ⊥ | 拷贝 | ③ |
| 4 | T | @ref @mut T | ⊥ | ⊥ | ⊤ | ⊤ | 拷贝 | ③ |
| 5 | @ref T | T | ⊥ | ⊤ | ⊥ | ⊥ | 共享 | — |
| 6 | @ref T | @ref T | ⊥ | ⊤ | ⊥ | ⊤ | 共享 | — |
| 7 | @ref T | @mut T | ⊥ | ⊤ | ⊤ | ⊥ | 共享 | — |
| 8 | @ref T | @ref @mut T | ⊥ | ⊤ | ⊤ | ⊤ | 共享 | — |
| 9 | @mut T | T | ⊤ | ⊥ | ⊥ | ⊥ | 拷贝 | ① |
| 10 | @mut T | @ref T | ⊤ | ⊥ | ⊥ | ⊤ | 拷贝 | ① |
| 11 | @mut T | @mut T | ⊤ | ⊥ | ⊤ | ⊥ | 拷贝 | ② |
| 12 | @mut T | @ref @mut T | ⊤ | ⊥ | ⊤ | ⊤ | 拷贝 | ② |

| 14 | @ref @mut T | @ref T | ⊤ | ⊤ | ⊥ | ⊤ | 共享 | — |
| 15 | @ref @mut T | @mut T | ⊤ | ⊤ | ⊤ | ⊥ | 共享 | — |
| 16 | @ref @mut T | @ref @mut T | ⊤ | ⊤ | ⊤ | ⊤ | 共享 | — |

自然语读法（Checker.kt:858–863 注释）：
1. 目标含 @mut 且（不带 @ref 或源纯）→ 拷贝；
2. 目标带 @mut 且不带 @ref → 拷贝（每个 @mut 绑定持独立对象）；
3. 源含 @mut 且目标纯 → 拷贝（割除可变性）；
4. 源带 @ref 且目标不带 @ref → 拷贝（冻结引用快照）。

其余共享同一对象，不拷贝。

### 3.2 维度的来源与限制

- `mut♯_t` 有两个来源：变量注解 `@mut var x`（`f.declareMut`，Checker.kt:582–583）与类型位 `var x : @mut T`（`tgt is MutType`，:866）。两者授予的权能不同：变量注解同时授予名字重赋权（`x = …` 合法），类型位只建立可变视图（可写 @mut 字段，但 `x = …` 仍报 E-IMMUT-ASSIGN，因为 `f.isMut` 只看注解集中的名字，:622）。
- `ρ_t` 只能来自变量注解 `@ref var`（`@ref` 不能出现在类型位）。
- `mut♯_s`/`ρ_s` 取自源变量的同名标志，因此完整判定要求源表达式是 NameRef（Checker.kt:633–638、Evaluator.kt:121–126 都先判 `e is NameRef`）。源为字面量/构造/调用时 `mut♯_s = ρ_s = ⊥`，条款 ①② 仍可触发拷贝。

### 3.3 深拷的静态留痕与代码生成

每次拷贝发 D-DEEP-COPY 补充级诊断并在 `deepCopyHits` 留痕（Checker.kt:637–638），代码生成层以 `__dc` 包裹（JsCodeGen.kt:822–823）。`__dc` 助手仅在有深拷/视图变异留痕时注入（:331）。

**边界 B2**〔待核〕：留痕只在源为 NameRef 时发生；源为构造/调用等表达式时，C-COPY 谓词仍在脚本模式 `bindCopy` 生效，但 JS 侧不包 `__dc`。两模式在函数值捕获上的既定差异（§3.4）之外的差异面待系统实测。

### 3.4 闭包捕获深拷贝

函数值遇到拷贝边界时，其闭包捕获一并深拷：

$$\frac{\text{copy}(\mu_{tgt} \leftarrow \mu_{src}) = \top \qquad v = \text{Fun}(\varphi) \qquad \varphi \in \text{ClosureFun}}{\text{value}(x) := \varphi.\text{copyCapture}()} \quad (\text{K-FUN-COPY})$$

〔实现现状〕解释器侧 `copiedFrame` 沿父链收集所有帧（外层优先、内层同名覆盖），逐值 deepCopy 后装入新帧（Evaluator.kt:130–143）。deepCopy 对 Struct/ListV/OptionalV/ResultV 递归逐字段拷贝（:145–158）。

JS 侧 `__dc` 对函数穿透为既定边界（`typeof v !== "object"` 使函数直接透传，JsCodeGen.kt:329–330 注释明示）：

| 场景 | 解释器（脚本模式） | JS（编译模式） |
|---|---|---|
| 结构体/列表的拷贝边界 | 逐字段递归深拷 | `__dc` 逐字段递归深拷 |
| 函数值的拷贝边界 | K-FUN-COPY：捕获帧冻结 | 函数透传，捕获环境共享 |

**已知缺陷**〔待核〕：`copiedFrame` 对捕获帧中的函数值自身无终止处理，实测 `@mut var g = f`（`f` 与 `g` 同帧）导致解释器堆栈溢出（Evaluator.kt:130–143/:156 递归）。FUN-COPY 需加记忆化或透传豁免。编译模式不受影响。

可运行示例：

```subs
@mut var x = 0
var f = { => x }          // 捕获活帧：f() 随 x 变
@mut var g = f            // K-COPY 行 11（@mut 目标恒拷）→ K-FUN-COPY 冻结
x = 1
print(f())                // 活捕获：1
print(g())                // 冻结捕获：0
```

## 四、unchecked 豁免

### 4.1 语法与进入判断式

`unchecked <语句>`（Parser parseUnchecked）包住一条语句。静态语义：

$$\frac{s \equiv \texttt{unchecked}\ t \qquad u := u + 1 \qquad \textit{checkStmt}(t,\ f,\ \pi = \text{impure}) \qquad u := u - 1}{\Gamma; \pi \vdash s : \text{Null}} \quad (\text{E-UNCHECKED})$$

良构前提：`u ≥ 0` 恒成立（初始为 0，进出配对）。两个直接后果：(i) 块内所有子表达式/子语句的 `π` 实参被强制为 impure（Checker.kt:779 及 :789/:1105/:1146 等处 `if (u > 0) false else pure`）；(ii) 诊断闸中显式带 `u` 条件者被关闭。

**定性**：`unchecked` 是刻意的受控开口，不是闸门失效。它关掉的是诊断报告，效应系统的内部标记（如 `λ_impure`）照常运作（见 §4.3 U1）。`unchecked.axiom[…]` 与 `unchecked.<其它>` 均报错（Parser 层拦截）。

### 4.2 uncheckedDepth 闸门表

「关」= `unchecked` 包住时不报该诊断；「开」= 仍然报告。

| # | 闸门/诊断 | 平时判定 | unchecked 内 | 出处 |
|---|---|---|---|---|
| 1 | E-IMMUT-ASSIGN | `¬μ(x) ∧ u = 0` | 关 | Checker.kt:622 |
| 2 | E-IMPURE-CALL（具名） | `"impure" ∈ anns(g) ∧ π = pure`；块内 π 强制 impure | 关 | CallCheck.kt:755 + :779 |
| 3 | E-IMPURE-CALL-VAL | `purity="impure" ∧ π = pure ∧ u = 0 ∧ ¬borrowed` | 关 | CallCheck.kt:485 |
| 4 | E-NON-STRUCTURAL-REC | `¬impure ∧ u = 0 ∧ 自递归 ∧ 无递减实参` | 关 | CallCheck.kt:747 |
| 5 | E-NEED-ASYNC（函数调用） | `"async" ∈ anns(g) ∧ ¬curAsync ∧ u = 0` | 关 | CallCheck.kt:769 |
| 6 | E-NEED-ASYNC（挂起方法） | 只看 curAsync，不看 u | **开** | CallCheck.kt:233/:248/:253/:273/:278/:285/:299 |
| 7 | E-NOT-STARTED / E-CHANNEL-CLOSED | 顺序性比对，不看 u | 开 | CallCheck.kt:230–231/:245–246 |
| 8 | 类型族诊断 | 与 u 无关 | 开 | 全局 |
| 9 | E-IMPURE-REQUIRED | 声明期 checkFun，语句位逃逸口不可达 | 开（无法逃逸） | Checker.kt:296 |

〔待核〕闸 6 的设计意图：挂起方法的 E-NEED-ASYNC 不经 `u`，`unchecked` 放行函数调用形态但放不住方法形态；是否应统一待核。

### 4.3 三条不变量

$$\frac{\text{"impure"} \in \textit{anns}(g) \qquad \textit{depth}_\lambda > 0}{\lambda_{\textit{impure}} := \top} \quad (\text{U1})$$

U1（E-LAMBDA-CALL 无 `u` 条件，CallCheck.kt:754）：`unchecked` 关掉诊断，λ 纯度标记照常置位。`unchecked side()` 写在 λ 内时调用仍被记录为不纯，该 λ 的类型仍带 `purity="impure"`。

$$\frac{u > 0 \Rightarrow \pi := \text{impure} \qquad u \text{ 归零后恢复外层}}{\text{纯度降级单向、局部}} \quad (\text{U2})$$

U2：`unchecked` 块内一律按非纯检查，离开块后 `u` 归零，外层 `π` 完好。

$$\frac{s \equiv \texttt{unchecked}\ t \qquad \text{运行期}}{\textit{eval}(s) = \textit{eval}(t) \qquad \text{JS: // unchecked 注释 + 透传}} \quad (\text{U3})$$

U3：`unchecked` 是纯静态检查指令——解释器直接执行 inner（Evaluator.kt:196），JS 生成只追加注释后照常生成（JsCodeGen.kt:822 附近）。零运行时开销。

## 五、@atomic 与异步

### 5.1 @atomic

`@atomic τ` 是类型层声明（AtomicType），事件循环保证读写原子。JS 单线程下透明反射到内层类型：

$$\frac{}{\text{AtomicType}(\tau) \equiv \tau} \quad (\text{EQ-ATOMIC})$$

〔实现现状〕typeEq 的 EQ-ATOMIC 分支（Types.kt:333–335）使 AtomicType 与内层类型严格相等。字段写时 AtomicType 内层同判（Checker.kt:890）。

### 5.2 async 效应标签

$$\frac{\text{"async"} \in \textit{anns}(f)}{\Gamma_g += \text{async}\langle f\rangle} \quad (\text{E-ASYNC-FACT})$$

E-ASYNC-FACT 与 E-PURE-FACT 同期注册（Symbols.kt:28）。`async<f>` 是传播事实，不是放行通道：同步上下文调用 @async 函数仍报错。

### 5.3 async-in-sync 闸

$$\frac{\text{"async"} \in \textit{anns}(g) \qquad \alpha_a = \text{sync} \qquad u = 0}{\text{报错 E-NEED-ASYNC}} \quad (\text{E-NEED-ASYNC})$$

$$\frac{\text{"async"} \in \textit{anns}(f) \lor \textit{name}(f) = \text{"main"}}{\alpha_a(f) := \text{async}} \quad (\text{E-ASYNC-CTX})$$

良构前提：E-ASYNC-CTX 在 checkFun 设置（Checker.kt:316 附近）；`main` 天然 async。@async 函数体内对 @async 函数的合法调用是挂起点：

$$\frac{\text{"async"} \in \textit{anns}(g) \qquad \alpha_a = \text{async}}{\textit{asyncAwaitHits}(g()) := \top \qquad \text{D-AUTO-AWAIT}} \quad (\text{E-SUSPEND-POINT})$$

### 5.4 挂起操作闸门表

除函数调用形态外，标准库的对象方法也挂起，全部只认 `α_a`（不经 `u`，见 §4.2 闸 6）：

| 操作 | 接收者类型 | 挂起点 | 同步上下文 | 出处 |
|---|---|---|---|---|
| `t.start()` / `t.isAlive()` | Task[T] | 否 | 合法 | CallCheck.kt:226–227 |
| `t.join()` | Task[T] | 是 | E-NEED-ASYNC | :228–234 |
| `ch.send(v)` | Channel[T] | 是 | E-NEED-ASYNC | :243–249 |
| `ch.receive()` | Channel[T] | 是 | E-NEED-ASYNC | :251–259 |
| `ch.close()` / `ch.isClosed()` | Channel[T] | 否 | 合法 | :261–262 |
| `m.lock()` / `m.unlock()` / `m.withLock(f)` | Mutex | 是 | E-NEED-ASYNC | :271–286 |
| `fl.collect(f)` | Flow[T] | 是 | E-NEED-ASYNC | :296–300 |
| `fl.map(f)` | Flow[T] | 否 | 合法 | :302–307 |

〔待核〕core 下 async/mutex/flow 标准库的完整签名（Task 冷流、runBoth/runSeq、withMutex、collectAll）若源码不足以坐实则需逐函数核实。

### 5.5 与纯度的复合

`@async` 与 `@impure` 独立标注、独立闸门。四象限组合都合法，诊断各报各的。

### 6.2 最小可运行对照

```subl
@mut struct Box(@mut n: Nat)

@impure fun side(): Null {}

@async fun tick(): Nat = 1

@impure fun main(): Null {
    var src : Box = Box(0)
    var dst : @mut Box = src       // COPY-①：深拷（D-DEEP-COPY）
    dst.n = 2
    print(src.n)                   // 0：版本前进不影响源
    @mut var a : @mut Box = Box(1)
    @ref var b : @mut Box = a      // 行 15：别名共享
    b.n = 5
    print(a.n)                     // 5
    axiom pure<side>               // E-DISCHARGE-PURE
    side()
    print(tick())                  // main 天然 async：挂起点
    return null
}
```

## 七、边界与待核清单

1. **边界 B1**〔待核〕：λ 内对捕获 @mut 结构体做字段写（`x.n = 1`）不置 `λ_impure`（Checker.kt:628 走 FieldExpr 分支）；与「修改外部可变状态即不纯」的字面表述存在缺口，是否为设计意图待核。
2. **缺陷**〔待核〕：捕获帧含函数值自身/互引用时 `copiedFrame` 无限递归（实测 `@mut var g = f` 堆栈溢出）；K-FUN-COPY 需加记忆化或透传豁免。编译模式不受影响。
3. **闸 6 设计意图**〔待核〕：挂起方法的 E-NEED-ASYNC 不经 `u`（CallCheck.kt:233 等），`unchecked` 放行函数调用形态但放不住方法形态；是否应统一待核。
4. **边界 B2**〔待核〕：深拷静态留痕只覆盖 NameRef 源（Checker.kt:633–638），非 NameRef 源的拷贝只在解释器 `bindCopy` 生效、JS 侧不包 `__dc`；两模式在函数值捕获上的既定差异（§3.4）之外的差异面待系统实测。
5. **标准库签名**〔待核〕：core 下 async/mutex/flow 各 `.subl` 的完整签名（Task/runBoth/runSeq/withMutex/collectAll）需逐函数核实。
6. **行号漂移**：本文引用的 file:line 以当前工作树为准，重构后需按函数名（`binderNeedsCopy`、`registerPureFacts`、`checkCall`、`bindCopy`、`copiedFrame`、`dcWrap`、`checkMutFieldWrite`）重定位。

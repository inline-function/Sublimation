## 〇、地位、范围与记号

### 0.1 本卷定义什么

本卷将「效应」形式化为三个**互相独立但共用逃逸口**的判断维度，并给出每个维度的判断式、它们与上下文 Γ 的交互、以及编译期/运行期两套实现（Checker 与 Evaluator/JsCodeGen）的同一性边界：

1. **纯度**（§1）：函数是否可含副作用。载体是 `@impure` 注解、`pure<f>` 命题与 `FunType.purity` 字段；
2. **可变性**（§2–§3）：绑定是否产生新对象。载体是 `@mut`/`@ref` 标注与四条拷贝规则构成的谓词；
3. **异步**（§5）：调用是否挂起。载体是 `@async` 注解与 `curFunAsync` 状态。

统一的逃逸口是 `unchecked`（§4）：它关掉一**部分**闸门，但不是全部——§4.2 的闸门表是本卷最实用的产出。

**不在本卷范围**：类型系统的可变性形态（`@mut T`/`@ref T`/`@atomic T` 的类型层规则，见 03 卷）、命题证明本身（02 卷）、上下文系统的扩散机制（05 卷）、Async 运行时（Channel/Mutex/Flow 的值的语义，09 卷）。本卷只引用这些系统暴露给效应判断的接口。

## 一、纯度判断系统

### 1.1 pure<f> 命题注册

纯度的静态事实在符号收集完成后一次性注册（`checkFile` 调 `registerPureFacts`，Checker.kt:199），使互相调用的函数无论声明顺序都能查到对方的纯度。命名函数默认纯（决策 34）：

$$\frac{f \in \text{syms.funs} \qquad \text{"impure"} \notin \text{anns}(f)}{\Gamma_g := \Gamma_g \cup \{\text{pure}\langle f\rangle\}} \quad (\text{E-PURE-FACT})$$

对无体的 `@root` 内建声明，用户注解不作数，纯度由**内建表**裁决（否则用户写 `@root fun readFile(...)` 不带 `@impure` 就会被误注册出错误证明）：

$$\frac{f.\text{body} = \bot \qquad B = \text{builtinimpure}(f) \lor \text{builtinPure}(f) \lor \text{builtinAndroid}(f) \qquad B \neq \bot}{\text{anns}_{\text{裁决}}(f) := \text{anns}(B) \qquad \text{E-PURE-FACT 用 anns}_{\text{裁决}}\text{ 重新适用}} \quad (\text{E-PURE-ROOT})$$

`impl` 方法按**方法名**（不是全限定签名）注册——方法路径的纯度闸与此同名注册对齐（O2）：

$$\frac{m \in \text{syms.methods} \qquad \exists e \in \text{entries}(m).\ \text{"impure"} \notin \text{anns}(e.\text{fn})}{\Gamma_g += \text{pure}\langle m\rangle} \quad (\text{E-PURE-METHOD})$$

跨模块（P0 补全）：可见模块的 `pure<f>` 一并按**裸名**注册，但同名只要在任一可见模块有 `@impure` 定义，整个名字都不注册（调用解析无法区分同名异模块，否则对 impure 版本的裸名调用会被同名 pure 事实错误放行）：

$$\frac{n \in \text{visibleNames} \qquad \forall p \in \text{visible}.\ \forall g \in \text{funs}(p).\ n = \text{name}(g) \Rightarrow \text{"impure"} \notin \text{anns}(g)}{\Gamma_g += \text{pure}\langle n\rangle} \quad (\text{E-PURE-XMOD})$$

注意 E-PURE-FACT/XMOD/METHOD 注册的是**可证事实**，任何 `axiom pure<f>` 语句或函数上下文 `<pure<f>>` 也能手工向 Γ 补入同名事实——这就是 §1.3 的放行通道。

### 1.2 @impure 声明与强制条款

`@impure` 是函数级注解，标注后解除纯函数的全部三项义务（体内不纯表达式、不改外部捕获、停机性）。唯一**强制**标注的条款在声明期：参数类型含 `@mut` 的函数必须标 `@impure`：

$$\frac{f.\text{body} \neq \bot \qquad \text{"impure"} \notin \text{anns}(f) \qquad \exists p \in \text{params}(f).\ \text{expand}(\text{type}(p)) = \text{@mut}\ T}{\text{报错 E-IMPURE-REQUIRED}} \quad (\text{E-IMPURE-REQUIRED})$$

- 判定只认 `MutType`（`syms.expand` 展开别名后），`@ref` 不能写在类型位（Parser.kt:521：类型位注解只支持 `@mut`/`@atomic`/`@impure`），可变形参语义一律走 `@mut T`；
- 条件中的 `f.body ≠ ⊥` 是实现事实：`checkFun` 只在有体时被调用（Checker.kt:217/:222/:229），故无体的 `@root` 声明可带 `@mut` 形参而不触发本条款（实测确认，见 wiki 04 旁证）。
- `@impure` 也可出现在**类型位**修饰函数类型（Parser.kt:513–521）：`f: @impure (A) => Null` 把纯度记进 `FunType.purity`（Ast.kt:156），这是函数值纯度随类型传递的入口（§1.4）。

### 1.3 纯作用域调用闸与 pure<f> 放行

纯函数体内调用 `@impure` 函数（含内建 `print`/`rand`/`sleep` 等，由 builtinimpure 表供应）时：

$$\frac{\text{"impure"} \in \text{anns}(g) \qquad \text{pure}(\text{ctx}) \qquad \Gamma \nvdash \text{pure}\langle g\rangle}{\text{报错 E-IMPURE-CALL}} \quad (\text{E-IMPURE-CALL})$$

放行条款（决策 54：`pure` 是「单参命题、可改变代码行为」的上下文事实）：

$$\frac{\text{"impure"} \in \text{anns}(g) \qquad \Gamma \vdash \text{pure}\langle g\rangle}{\text{调用 } g() \text{ 在纯作用域放行（无 E-IMPURE-CALL）}} \quad (\text{DISCHARGE-PURE})$$

- 方法路径（`x.f()`、自由式）的纯度原子统一按**方法名**注册与查询（与 E-PURE-METHOD 同名注册对齐）；
- `pure` 的来源有三条路径：E-PURE-FACT/XMOD/METHOD 的自动注册、`axiom pure<f>` 语句注入、函数上下文 `<pure<f>>`（上文，调用方须供给）。

可运行示例（三种放行形态对照，均实测通过）：

```subl
@impure fun side(): Null {}

// 形态一：axiom 语句注入
fun viaAxiom(): Null {
    axiom pure<side>
    side()
}

// 形态二：函数上下文（上文）供给
fun viaContext() <pure<side>> : Null {
    side()
}
```

### 1.4 lambda 纯度推导（lambda purity）

lambda 与匿名函数（统称 λ）在检查时进入独立的纯度跟踪：进入 λ 时把 `λ_impure` 复位为 ⊥、`depth_λ` 加一，体检查结束后取终值为该 λ 的纯度，并恢复外层标记（Checker.kt:1083–1139 / 1312–1340）。三个不纯源：

$$\frac{\text{depth}_\lambda > 0 \qquad s \equiv x = e \ (\text{NameRef 赋值}) \qquad x \notin \text{vars}(f_{\text{当前帧}}) \qquad \text{isMut}(x)}{\lambda_{\text{impure}} := \top} \quad (\text{L-IMPURE-ASSIGN})$$

$$\frac{\text{depth}_\lambda > 0 \qquad \text{表达式含 NameRef } x \qquad x \notin \text{vars}(f_{\text{当前帧}}) \qquad \text{isMut}(x)}{\lambda_{\text{impure}} := \top} \quad (\text{L-IMPURE-READ})$$

$$\frac{\text{"impure"} \in \text{anns}(g) \qquad \text{depth}_\lambda > 0}{\lambda_{\text{impure}} := \top} \quad (\text{L-IMPURE-CALL})$$

- L-IMPURE-ASSIGN/READ 的判据相同：`x` 不在当前帧声明（即捕获自外层）且沿父链 `isMut` 成立；读取与写入同等处理（可变状态读取即隐式状态依赖）。
- 三规则的**结论与 `pure` 实参无关**——这是 §4.3 不变量 U1 的来源：`unchecked` 包住的 impure 调用不报 E-IMPURE-CALL，但仍然污染所在 λ 的纯度标记（CallCheck.kt:754/:480 无 `depth_uc` 条件）。

λ 检查结束时的回填：

$$\frac{\lambda_{\text{impure}} \in \{\top, \bot\} \text{ 为体检查终值}}{\text{type}(\lambda) = \text{FunType}(\text{形参类型},\ \text{体类型},\ \text{purity} = \begin{cases}\text{"impure"} & \lambda_{\text{impure}} = \top \\ \text{""} & \lambda_{\text{impure}} = \bot\end{cases})} \quad (\text{L-TYPE})$$

$$\frac{\lambda_{\text{impure}} = \bot}{\Gamma += \text{pure}\langle \lambda \text{ 字面量}\rangle} \quad (\text{L-PURE-FACT})$$

L-PURE-FACT 使 `fun need() <pure<{1 + 1}>> : Null` 的前件可被一个纯 lambda 字面量自动满足（实测通过）。

**函数值闸**。λ 一旦带 `purity="impure"` 传作值，其调用在纯上下文受第二道闸（CallCheck.kt:479–487）：

$$\frac{\text{type}(v) = \text{FunType}(\_,\ \_,\ \text{"impure"}) \qquad \text{pure}(\text{ctx}) \qquad \text{depth}_{\text{uc}} = 0 \qquad \neg\text{borrowed}(v)}{\text{报错 E-IMPURE-CALL（函数值）}} \quad (\text{E-IMPURE-CALL-VAL})$$

$$\frac{\text{callee} \equiv \text{本函数某形参名} \qquad \text{该形参声明类型} = \text{FunType}(\_,\ \_,\ \text{"impure"})}{\text{borrowed} := \top \qquad \text{E-IMPURE-CALL-VAL 不适用}} \quad (\text{BORROWED})$$

BORROWED 是「借用效应」：HKT 标准库的 `forEach(f : @impure (A) => Null)` 之类把 impure 函数值声明为形参，形参即显式效应能力（能传出 impure λ 的调用方本身必非纯，纯洁性不破）。

实测示例（两种极性）：

```subl
fun f(): Null {
    @mut var x = 0
    var inc = fun() { x = 1 }      // L-IMPURE-ASSIGN ⇒ inc : impure () => Null
    inc()                          // E-IMPURE-CALL（函数值）
    return null
}
```

```subl
fun g(): Null {
    @mut var x = 0
    var inc = fun() { x }          // L-IMPURE-READ ⇒ g : impure () => Nat
    inc()                          // E-IMPURE-CALL（函数值）
    return null
}
```

**边界 B1（实测确认）**：字段写不进 λ 不纯标记——L-IMPURE-ASSIGN 的语句形态只匹配赋值目标为 NameRef 的赋值（Checker.kt:609–617），目标为 `FieldExpr` 时走 `checkMutFieldWrite`（Checker.kt:618/:859–873），后者不置 `λ_impure`。故 `@mut var x = Box(0); var inc = fun() { x.n = 1 }; inc()` 在纯函数内**通过**检查（λ 不被标记，函数值闸不触发）。这与「修改外部可变状态即不纯」的字面表述有缺口：是否为设计意图**待核**，本文按代码事实记录。

### 1.5 纯度与 Γ 的交互

纯度判断直接影响 Γ 的两项注入策略（§2.3 的同源规则）：

- **绑定等式注入**只用 `isPureValue`（Checker.kt:812–824）：字面量、NameRef、纯中缀表达式、以及**被调函数非 impure 的调用**（P4：`var x = f(5)` 需注入 `x = f(5)` 供等式推理；`@impure` 函数结果不确定，不注入）；
- **结构相等豁免**：`containsImpureCall`（Diffusion.kt:144–167）判定表达式是否含 `@impure` 调用；命中则该表达式不参与结构相等/自反（Diffusion.kt:307–309）。故 `∵ print("a") = print("a")` 不可证（含自反在内）。

### 1.6 停机闸（效应完整性的第三支柱）

纯函数自递归必须经停机性检查（决策 44/9；闸门与 `depth_uc` 的交互见 §4.2）：

$$\frac{\neg\text{isMethodPath} \qquad \text{"impure"} \notin \text{anns}(f) \qquad \text{depth}_{\text{uc}} = 0 \qquad g \equiv f \text{（自递归）} \qquad \neg\exists a \in \text{args}(g).\ \text{structuralArg}(a) \lor \text{numericDescent}(a)}{\text{报错 E-NON-STRUCTURAL-REC}} \quad (\text{E-NON-STRUCTURAL-REC})$$

- `structuralArg(a)`：`a` 是某形参的**语法子项**（如 `t` 的子结构、`xs.tail()` 之形态）；`numericDescent(a)`：数值实参严格向 0 靠拢（`n - 1` 可，`n + 1` 不可）；
- 全参数都不递减才算违规（`map(f, t)` 允许 `f` 原样透传，停止性由递减者保证）；`@impure` 函数与方法路径（字典分发）不受约束。

## 二、可变拷贝四规则

### 2.1 统一谓词（binder 判断式）

绑定与赋值共享同一个拷贝谓词——编译期 `Checker.binderNeedsCopy`（Checker.kt:838–846）与脚本期 `Evaluator.bindCopy`（Evaluator.kt:112–119）逐字同构。先抽取四布尔：

$$\frac{\begin{aligned} m_t &= \text{"mut"} \in \text{anns}(x) \ \lor\ \text{type}(x) = \text{@mut}\ T \\ r_t &= \text{"ref"} \in \text{anns}(x) \\ m_s &= \text{"mut"} \in \text{anns}(e) \ \lor\ \text{type}(e) = \text{@mut}\ T \qquad (e \equiv \text{NameRef}) \\ r_s &= \text{"ref"} \in \text{anns}(e) \qquad (e \equiv \text{NameRef}) \end{aligned}}{\text{copy}(x \leftarrow e) \iff \underbrace{(m_t \land (\neg r_t \lor (\neg m_s \land \neg r_s)))}_{\text{条款 ①②}} \ \lor\ \underbrace{(m_s \land \neg m_t \land \neg r_t)}_{\text{条款 ③}} \ \lor\ \underbrace{(r_s \land \neg r_t)}_{\text{条款 ④}}} \quad (\text{C-COPY})$$

四条款与契约文字一一对应：

| 条款 | 谓词部分 | 自然语言 |
|---|---|---|
| ① | `m_t ∧ (¬r_t ∨ 源纯)` | 目标含 @mut 且（不带 @ref 或源纯）→ 拷贝 |
| ② | 同上（`m_t` 恒拷的兜底） | 每个 @mut 绑定持独立对象 |
| ③ | `m_s ∧ 目标纯` | 源含 @mut 且目标纯 → 拷贝（割除可变性） |
| ④ | `r_s ∧ ¬r_t` | 源带 @ref 且目标不带 @ref → 拷贝（冻结引用快照） |

其中「源纯」= `¬m_s ∧ ¬r_s`，「目标纯」= `¬m_t ∧ ¬r_t`。其余情形（不可变值互传、可变值绑入 @ref、引用互相别名）**共享同一对象，不拷贝**。

**维度的来源与限制**：

- `m_t` 有两个来源：变量注解 `@mut var x`（`f.declareMut`，Checker.kt:582–583）与类型位 `var x : @mut T`（`tgt is MutType`，Checker.kt:839）；脚本模式同法（Evaluator.kt:164）。**注意两者授予的权能不同**：变量注解同时授予名字重赋权（`x = …` 合法），类型位只建立可变视图（可写 `@mut` 字段，但 `x = …` 仍报 E-IMMUT-ASSIGN——因为 `f.isMut` 只看注解集中的名字，Checker.kt:612；实测确认：`var a : @mut Box = Box(0); a = Box(1)` 报 E-IMMUT-ASSIGN）。
- `r_t` 只能来自变量注解 `@ref var`（`@ref` 不能出现在类型位，Parser.kt:521）；`@ref var b : @mut T = a` 是「共享可变别名」的实际写法（类型位贡献 `m_t`，注解贡献 `r_t`）。
- `m_s`/`r_s` 取自**源变量**的同名标志，因此 C-COPY 的完整判定要求源表达式是 NameRef（Checker.kt:587/:626/:1299、Evaluator.kt:121–126 都先判 `e is NameRef`）。源为字面量/构造/调用时 `m_s = r_s = ⊥`，条款 ①②仍可触发拷贝。

### 2.2 完整矩阵与证明

对 `(m_t, r_t, m_s, r_s)` 的 16 种组合穷举（目标/源以「标注形态」示意，`T` 为任意非视图类型）：

| # | 目标 | 源 | `(m_t,r_t,m_s,r_s)` | 判定 | 主条款 | 可观察后果 |
|---|---|---|---|---|---|---|
| 1 | `T` | `T` | 0 0 0 0 | 共享 | — | 不可变值互传 |
| 2 | `T` | `@ref T` | 0 0 0 1 | **拷贝** | ④ | 冻结引用快照 |
| 3 | `T` | `@mut T` | 0 0 1 0 | **拷贝** | ③ | 割除可变性 |
| 4 | `T` | `@ref @mut T` | 0 0 1 1 | **拷贝** | ③ | 割除可变性 |
| 5 | `@ref T` | `T` | 0 1 0 0 | 共享 | — | 建立只读视图 |

| 7 | `@ref T` | `@mut T` | 0 1 1 0 | 共享 | — | 只读视图可见源变更（陷阱见 §2.5） |
| 8 | `@ref T` | `@ref @mut T` | 0 1 1 1 | 共享 | — | 同上 |

| 11 | `@mut T` | `@mut T` | 1 0 1 0 | **拷贝** | ② | 每个 @mut 绑定独立对象 |
| 12 | `@mut T` | `@ref @mut T` | 1 0 1 1 | **拷贝** | ② | 同上 |
| 13 | `@ref @mut T` | `T` | 1 1 0 0 | **拷贝** | ①（源纯） | 别名建立须快照 |
| 14 | `@ref @mut T` | `@ref T` | 1 1 0 1 | 共享 | — | 别名 |
| 15 | `@ref @mut T` | `@mut T` | 1 1 1 0 | 共享 | — | **别名共享**：`b.n = 1` 后 `a.n` 亦变 |
| 16 | `@ref @mut T` | `@ref @mut T` | 1 1 1 1 | 共享 | — | 别名 |

**合成定理**（矩阵与 C-COPY 谓词一致）。按目标列分三段证明，每段把谓词化简：

$$\frac{m_t = \bot}{\text{copy} \iff (m_s \lor r_s)} \quad (\text{行 1–4：目标纯})$$

*证明*：`m_t = ⊥` 使析取式第一项为 ⊥；第三项 `r_s ∧ ¬r_t` 中 `¬r_t` 恒真故化简为 `r_s`；第二项 `m_s ∧ ¬m_t ∧ ¬r_t` 化简为 `m_s ∧ ¬r_t`。当 `r_t = ⊥` 时两项合并即 `m_s ∨ r_s`（行 1–4 的 `r_t` 只为 ⊥：类型位 @mut + 注解 @ref 的组合在目标为纯时不可能）。∎ 与 _langfacts §6 的 `T ← @ref T` 深拷、`T ← @mut T` 深拷一致。

$$\frac{m_t = \top \qquad r_t = \bot}{\text{copy} = \top \ (\text{恒拷})} \quad (\text{行 9–12：@mut 无 @ref})$$

*证明*：第一项中 `m_t = ⊤` 且 `¬r_t = ⊤`，故 `m_t ∧ (¬r_t ∨ 源纯) = ⊤`，整个析取为 ⊤，与源无关。∎ 与 _langfacts §6 的 `@mut T ← T` 深拷、`@mut T ← @mut T` 深拷一致（两个 @mut 绑定互为独立副本，即「@mut 版本前进」的物基础，见 §2.3）。

$$\frac{m_t = \top \qquad r_t = \top}{\text{copy} \iff (\neg m_s \land \neg r_s)} \quad (\text{行 13–16：@ref @mut 目标})$$

*证明*：第一项 `m_t ∧ (¬r_t ∨ 源纯)` 中 `¬r_t = ⊥`，化简为 `m_t ∧ 源纯 = 源纯`；第二项 `m_s ∧ ¬m_t` 为 ⊥（`m_t = ⊤`）；第三项 `r_s ∧ ¬r_t` 为 ⊥（`r_t = ⊤`）。故 copy ⟺ 源纯（行 13 源纯为 ⊤ → 拷贝；行 14–16 源非纯 → 共享/别名）。∎ 与 _langfacts §6 的 `@ref @mut T ← @mut T` 别名一致。

**充分性**（谓词 ⇒ 矩阵）由三段分删穷举覆盖全部 16 格得出；**必要性**（矩阵 ⇒ 谓词）同一张表逐行回代即得。两实现（Checker.binderNeedsCopy / Evaluator.bindCopy）逐字共享该谓词，故矩阵在编译模式与脚本模式同时成立；两模式对 `m_t` 的取值口径（注解 ∨ 类型位）亦一致。

### 2.3 @mut 版本前进与 Γ 等式注入

可变变量的值可随时被赋新（版本前进），因此**任何**以它为轴的等式命题在注入后即可能失效。凝华的处理是「源头不注入」（决策 35、root doc 第 9 行）：`@mut` 变量仅保有自反相等（`x = x`），非自反等式论据（`x = 初值`）忽略不注入；初值引用 @mut 变量时（`refsMut`）同样不注入；`@ref` 变量态度与 @mut 一致（值可经别名变更）。

$$\frac{\text{isPureValue}(e) \qquad \text{"mut"} \notin \text{anns}(x) \qquad \text{"ref"} \notin \text{anns}(x) \qquad \neg\text{refsMut}(e, f) \qquad \neg\text{isMutStructType}(T)}{\Gamma += (x = e)} \quad (\text{INJ-EQ})$$

$$\frac{\text{isPureValue}(e) \ \lor\ \text{"mut"} \in \text{anns}(x)}{\Gamma += (x : T)} \quad (\text{INJ-TYPE})$$

不注入（或仅注入类型事实）的情形汇总：

| 情形 | 注入的命题 | 依据 |
|---|---|---|
| 不可变 `x` ← 纯值 | `x = e` 与 `x : T` | INJ-EQ / INJ-TYPE |
| `@mut var x` ← 任意 | 仅 `x : T` | 决策 35（仅自反相等） |
| 不可变 `x` ← `@mut` 变量 | 仅 `x : T`（等式不可靠） | `refsMut` 否决 |
| `@ref var x` ← 任意 | 仅 `x : T` | 引用与 @mut 同态度 |
| `x` 的类型为可变结构体（`@mut struct` 或含 @mut 字段） | 不注入 `x = e` | `isMutStructType`：字段可经 @mut 视图变更 |
| 初值含 `@impure` 调用 | 不注入 `x = e` | §1.5 `isPureValue` |

「版本前进」与拷贝矩阵的关系：条款 ②（`@mut` 目标恒拷）保证每个 @mut 绑定持有独立对象，因此「前进」只改自己；而「不注入等式」保证 Γ 不持有任何会被前进打断的等式。两条规则合起来把可变性对命题世界的污染降到零——Γ 里只剩 `x : T` 这类不会失效的类型事实。

实测示例（等式注入与否的判别）：

```subl
@impure fun main(): Null {
    var y = 0
    var z = y
    // ∵ z = y          // 可证：INJ-EQ 生效
    @mut var x = 0
    var w = x
    // ∵ w = x          // E-CANNOT-PROVE：初值引用 @mut 变量，等式未注入
    // ∵ x = x          // 可证：@mut 变量仅自反
    return null
}
```

### 2.4 深拷的静态留痕与代码生成

- **留痕**：C-COPY 命中且源为 NameRef 时，编译器在 `deepCopyHits` 记录该语句（Checker.kt:587/:626/:1299）并发 `D-DEEP-COPY` 提示（:589/:628）；`@view` 结构体的字段赋值由 codegen 预扫描追加留痕（JsCodeGen.kt:307/:448/:1577–1580）。
- **生成**：`deepCopyHits` 非空或视图变异预扫描命中时，JS 输出注入 `__dc` 助手（JsCodeGen.kt:324–332），绑定/赋值的初值包一层 `__dc(...)`（`dcWrap` :790–791；生成处 :801/:805/:817）。
- **边界 B2（代码直读）**：留痕只在**源为 NameRef** 时发生；源为构造/调用等表达式时，C-COPY 谓词仍在脚本模式 `bindCopy` 生效，但 JS 侧不包 `__dc`（编译模式的拷贝只随留痕落地）。对`@mut` 目标二者皆拷（对象为新建，无观察差）；对纯目标共享的情形两模式一致。跨模式差异面**待核**。

### 2.5 陷阱速查（矩阵的实践后果）

1. **行 7 的只读视图不冻结**：`@ref T ← @mut T` 共享同一对象，「只读」是**编译期不让你写**，不是运行时快照——源继续变更，引用全部看见。要快照请走行 3（去掉 `@ref`）。
2. **行 15 是唯一的别名通道**：`@ref @mut T ← @mut T` 不拷贝，`b.n = 1` 后 `a.n` 亦变；这是有意的共享可变设计，须显式写两个标注。
3. **类型位 @mut ≠ @mut var**：`var a : @mut T` 建视图（可改 @mut 字段）但**不能**重新赋值 `a = …`（E-IMMUT-ASSIGN）；重赋权只用 `@mut var`（§2.1）。

## 三、闭包捕获深拷贝

### 3.1 解释器侧判断式

函数值遇到 C-COPY 拷贝边界时，其闭包捕获一并深拷（修正案条款；Evaluator.kt:156 的 `ScriptValue.Fun` 分支）：

$$\frac{\text{C-COPY}(x \leftarrow e) = \top \qquad \text{value}(e) = \text{Fun}(\varphi) \qquad \varphi \in \text{ClosureFun}}{\text{value}(x) := \varphi.\text{copyCapture}() = \text{eval}\lambda(\text{expr}(\varphi),\ \text{copiedFrame}(\text{frame}(\varphi)))} \quad (\text{FUN-COPY})$$

$$\frac{\text{copiedFrame}(f):\ \text{沿父链收集所有帧（外层优先、内层同名覆盖）} \qquad \forall n \in \text{localNames}(f^*).\ \text{out}(n) := \text{deepCopy}(\text{lookup}(n))}{\text{out 为新帧，保留原 mut/ref 标注}} \quad (\text{FRAME-COPY})$$

即：深拷不是把闭包对象本身复制一份，而是**用一份逐值深拷过的捕获帧重新求值 λ 体**，得到一个冻结在拷贝时刻的闭包。深拷对结构体/列表/Optional/Result 递归逐字段拷贝（`ScriptValue.Struct` 的 `mutableFields` 类型元数据只读共享，Evaluator.kt:145–158）。

### 3.2 JS 侧 `__dc` 的既定边界

```js
const __dc = (v) => {
  if (v === null || typeof v !== "object") return v;   // 原始值透传
  if (Array.isArray(v)) return v.map(__dc);
  const o = {};
  for (const k in v) o[k] = __dc(v[k]);                 // 对象逐字段递归
  return o;
};
```

（JsCodeGen.kt:325–331，仅在有深拷/视图变异留痕时注入）

**函数值早退**：`typeof v !== "object"` 使函数直接透传——JS 闭包不透明，无法从外面拷其捕获环境。这是**既定边界**：修正案要求的「深拷贝闭包捕获变量」只在解释器侧（FUN-COPY）实现，编译模式不模拟（JsCodeGen.kt:322–323 注释明示）。两模式语义差如下：

| 场景 | 解释器（脚本模式） | JS（编译模式） |
|---|---|---|
| 值为结构体/列表的拷贝边界 | 逐字段递归深拷 | `__dc` 逐字段递归深拷 |
| 值为函数的拷贝边界 | FUN-COPY：捕获帧一并冻结 | 函数透传，捕获环境共享 |

### 3.3 触发时机：捕获在创建、冻结在边界

λ 创建时捕获的是**活帧**（`evalLambda` 的 `call` 用 `ScriptFrame(frame)` 直接求值，Evaluator.kt:846–851），因此「闭包捕获在 lambda 创建时深拷」的表述应精确为：**当函数值穿过 C-COPY 拷贝边界时，其捕获帧被快照**。未过边界的闭包持续看见外部变更。

```subs
@mut var x = 0
var f = { => x }          // 捕获活帧：f() 随 x 变
@mut var g = f            // C-COPY 行 11（@mut 目标恒拷）→ FUN-COPY 冻结
x = 1
print(f())                // 活捕获：1
print(g())                // 冻结捕获：0
```

（语义经代码直读 Evaluator.kt:838–854 与 :112–119；本例的完整脚本运行见 §3.4 的缺陷注记——实测须避开自引用捕获帧）

### 3.4 已知缺陷（实测发现，**待核**）

`copiedFrame` 对捕获帧中的**函数值自身**无终止处理：`deepCopy(Fun)` → `copyCapture` → `copiedFrame` → 该帧含原函数值 → `deepCopy(Fun)` → …… 实测 `@mut var g = f`（`f` 与 `g` 同帧）导致解释器堆栈溢出（Evaluator.kt:130-143/:156/:845 递归）。这是实现缺陷而非语言语义：形式上 FUN-COPY 应对已访问的函数值做记忆化（memo）或对非 ClosureFun 透传。编译模式不受影响（`__dc` 函数早退）。

## 四、unchecked 穿透语义

### 4.1 语法与进入判断式

`unchecked <语句>`（Parser.kt:796–803；`unchecked.axiom[p]` 已废除，点号形态一律报错）包住**一条**语句——该语句是块时整块受益。静态语义：

$$\frac{s \equiv \text{unchecked}\ t \qquad \text{depth}_{\text{uc}} := \text{depth}_{\text{uc}} + 1 \qquad \text{checkStmt}(t,\ f,\ \text{pure} = \bot)}{\text{检查完成后}\ \text{depth}_{\text{uc}} := \text{depth}_{\text{uc}} - 1} \quad (\text{UNCHECKED})$$

两个直接后果：(i) 块内所有子表达式/子语句的 `pure` 实参被强制为 `⊥`（Checker.kt:777/:790/:798/:1078/:1119/:1158/:1165/:1174 八处的 `if (depth_uc > 0) false else pure`）；(ii) 诊断闸中显式带 `depth_uc` 条件者被关闭。`uncheckedDepth` 是**机制实现细节**（语言 surface 只有 `unchecked` 关键字），嵌套 `unchecked` 逐层叠加、离开逐层还原。

### 4.2 uncheckedDepth 闸门表

「关」= `unchecked` 包住时不报该诊断；「开」= 仍然报告。

| # | 闸门/诊断 | 平时常的判定 | unchecked 内 | 出处 |
|---|---|---|---|---|
| 1 | E-IMMUT-ASSIGN（给不可变名字赋值） | `¬isMut(x) ∧ depth_uc = 0` | **关** | Checker.kt:612 |
| 2 | E-IMPURE-CALL（具名 @impure 函数） | `"impure" ∈ anns(g) ∧ pure(ctx)`；块内 pure 强制 ⊥ | **关** | CallCheck.kt:755 + :767 |
| 3 | E-IMPURE-CALL（impure 函数值） | `purity="impure" ∧ pure ∧ depth_uc = 0 ∧ ¬borrowed` | **关** | CallCheck.kt:485 |
| 4 | E-NON-STRUCTURAL-REC（纯函数停机） | `¬impure ∧ depth_uc = 0 ∧ 自递归 ∧ 无递减实参` | **关** | CallCheck.kt:747 |
| 5 | E-NEED-ASYNC（调用 @async 函数） | `"async" ∈ anns(g) ∧ ¬curAsync ∧ depth_uc = 0` | **关** | CallCheck.kt:769 |
| 6 | E-NEED-ASYNC（挂起方法：t.join/ch.send/ch.receive/m.lock/m.unlock/m.withLock/fl.collect） | 只看 `curAsync`，**不看** `depth_uc` | **开** | CallCheck.kt:233/:248/:253/:273/:278/:285/:299 |
| 7 | E-NOT-STARTED（未 start 就 join）/ E-CHANNEL-CLOSED（close 后 send） | 顺序性比对，不看 `depth_uc` | **开** | CallCheck.kt:230–231/:245–246 |
| 8 | 类型族诊断（E-TYPE-MISMATCH / E-ARITY / E-UNBOUND-NAME / E-RETURN-* …） | 与 `depth_uc` 无关 | **开** | 全局 |
| 9 | E-IMPURE-REQUIRED（@mut 形参须 @impure） | 声明期 `checkFun`，语句位逃逸口不可达 | **开**（无法逃逸） | Checker.kt:294 |
| 10 | 纯度事实注册 / `pure<f>` 放行 | 注册期与 `depth_uc` 无关 | **开**（独立通道） | Symbols.kt:16–53 |

实测对照（均经 `check` 验证）：

```subl
@impure fun side(): Null {}
@async fun tick(): Nat = 1

fun f(): Null {
    unchecked side()      // 闸 2 关：通过
    unchecked tick()      // 闸 5 关：通过
    return null
}

fun g(): Null {
    side()                // 闸 2 开：E-IMPURE-CALL
    tick()                // 闸 5 开：E-NEED-ASYNC
    return null
}
```

第 6 行是**最容易被误用的一条**：`unchecked` 放行的是**函数调用形态**的 async 闸（`tick()`），挂起**方法形态**（`t.join()`、`ch.send(x)`、`m.lock()`、`fl.collect(f)`）的判定只认 `curAsync`——同步函数里写 `unchecked t.join()` 仍报 E-NEED-ASYNC（代码直读 CallCheck.kt:232–233；是否为有意设计**待核**）。

### 4.3 三条不变量

$$\frac{\text{"impure"} \in \text{anns}(g) \qquad \text{depth}_\lambda > 0}{\lambda_{\text{impure}} := \top} \quad (\text{U1：unchecked 不是效应消除器})$$

U1（L-IMPURE-CALL 的判定无 `depth_uc` 条件，CallCheck.kt:754/:480）：`unchecked` 关掉的是**诊断**，λ 的纯度标记照常置位。因此 `unchecked side()` 写在 λ 内时调用仍被记录为不纯，该 λ 的类型仍带 `purity="impure"`，出 λ 后仍受函数值闸约束。效应系统记住一切，编译器只是不罚。

$$\frac{\text{depth}_{\text{uc}} > 0 \Rightarrow \text{pure} := \bot \qquad \text{depth}_{\text{uc}}\text{ 归零后恢复外层}}{\text{纯度降级单向、局部}} \quad (\text{U2：单向局部传染})$$

U2：`unchecked` 块内一律按非纯检查（没有「块内再纯回去」的通道），但离开块后 `depth_uc` 归零，外层的 `pure` 完好——一块的逃逸不污染整个函数的纯度身份。

$$\frac{s \equiv \text{unchecked}\ t \qquad \text{运行期}}{\text{eval}(s) = \text{eval}(t) \qquad \text{JS 输出为 `// unchecked` 注释 + 透传}} \quad (\text{U3：运行时透明})$$

U3：`unchecked` 是纯静态检查指令——解释器直接执行 inner（Evaluator.kt:194），JS 生成只追加可 grep 审计的注释后照常生成（JsCodeGen.kt:822）。零运行时开销、零运行时语义。

## 五、async 效应标签与 async-in-sync 闸

### 5.1 async<f> 的注册与语义

$$\frac{\text{"async"} \in \text{anns}(f)}{\Gamma_g += \text{async}\langle f\rangle} \quad (\text{ASYNC-FACT})$$

ASYNC-FACT 与 E-PURE-FACT 同期注册（Symbols.kt:28，@root 无体声明同样走 E-PURE-ROOT 的内建表裁决）。**`async<f>` 是传播事实，不是放行通道**：它标记「f 是关键子函数」，供推理与诊断引用；同步上下文调用 @async 函数仍然报错（CallCheck.kt:765–766 注释明示）。要放行只有两条路：给调用方加 `@async`，或 `unchecked`（§4.2 闸 5）。

### 5.2 async-in-sync 闸与异步上下文

$$\frac{\text{"async"} \in \text{anns}(g) \qquad \neg\text{curAsync} \qquad \text{depth}_{\text{uc}} = 0}{\text{报错 E-NEED-ASYNC}} \quad (\text{E-NEED-ASYNC})$$

$$\frac{\text{"async"} \in \text{anns}(f) \ \lor\ \text{name}(f) = \text{"main"}}{\text{curAsync}(f) := \top} \quad (\text{ASYNC-CTX})$$

ASYNC-CTX（Checker.kt:316）：`main` 天然 `@async`——无需注解即可调用 async 函数并接受挂起点。函数体内对 @async 函数的合法调用是**挂起点**：

$$\frac{\text{"async"} \in \text{anns}(g) \qquad \text{curAsync}}{\text{asyncAwaitHits}(g()) := \top \qquad \text{D-AUTO-AWAIT（codegen 自动插入 await，无需 await 关键字）}} \quad (\text{SUSPEND-POINT})$$

### 5.3 挂起操作闸门表

除函数调用形态外，标准库的对象方法也挂起，全部只认 `curAsync`（不经 `depth_uc`，见 §4.2 闸 6）：

| 操作 | 接收者类型 | 挂起点 | 同步上下文 | 出处 |
|---|---|---|---|---|
| `t.start()` / `t.isAlive()` | `Task[T]` | 否（start 登记） | 合法 | CallCheck.kt:226–227 |
| `t.join()` | `Task[T]` | 是（await） | E-NEED-ASYNC（未 start 另报 E-NOT-STARTED） | :228–234 |
| `ch.send(v)` | `Channel[T]` | 是 | E-NEED-ASYNC（close 后另报 E-CHANNEL-CLOSED） | :243–249 |
| `ch.receive()` | `Channel[T]` | 是 | E-NEED-ASYNC | :251–259 |
| `ch.close()` / `ch.isClosed()` | `Channel[T]` | 否 | 合法 | :261–262 |
| `m.lock()` / `m.unlock()` / `m.withLock(f)` | `Mutex` | 是 | E-NEED-ASYNC | :271–286 |

| `sleep`/`readFile`/`writeFile`/`readLine`/`readDir`/`appendFile`/`delay`/`runBoth`/`runSeq`/`collectAll`/`withMutex`... | 内建 | 是（`@async @impure`，builtinimpure 表） | E-NEED-ASYNC（兼闸 2） | Types.kt:56–141 |

### 5.4 与纯度的复合

`@async` 与 `@impure` 独立标注、独立闸门：`@async fun fetch(): Nat = 1` 是**纯**异步函数（注册 `pure<fetch>` 与 `async<fetch>`），在纯函数内调用它放行纯度闸、但触发 async 闸；反之 `@impure @async fun consume(ch: Channel[Nat]): Null`（ModuleE2ETest.kt:571 形态）两闸都要过。四象限组合都合法，诊断各报各的。

| 诊断码 | 级别 | 触发条件 | 修复建议 |
|---|---|---|---|

### 6.3 最小可运行对照（全部经 `check` 实测）

```subl
// 合法：四规则 + 纯度放行 + 天然 async 全部就位
@mut struct Box(@mut n: Nat)

@impure fun side(): Null {}

@async fun tick(): Nat = 1

@impure fun main(): Null {
    var src : Box = Box(0)
    var dst : @mut Box = src       // C-COPY 行 9：深拷（D-DEEP-COPY）
    dst.n = 2
    print(src.n)                   // 0：版本前进不影响源
    @mut var a : @mut Box = Box(1)
    @ref var b : @mut Box = a      // C-COPY 行 15：别名共享
    b.n = 5
    print(a.n)                     // 5
    axiom pure<side>               // DISCHARGE-PURE
    side()
    print(tick())                  // main 天然 async：挂起点
    return null
}
```

## 七、待核清单

1. **边界 B1**：λ 内对捕获 @mut 结构体做**字段写**（`x.n = 1`）不置 `λ_impure`（Checker.kt:618 走 FieldExpr 分支）；与「修改外部可变状态即不纯」的字面表述存在缺口，是否为设计意图待核。
2. **缺陷（§3.4）**：捕获帧含函数值自身/互引用时 `copiedFrame` 无限递归（实测 `@mut var g = f` 堆栈溢出）；FUN-COPY 需加记忆化或透传豁免。编译模式不受影响。
3. **闸 6 的设计意图**：挂起方法的 E-NEED-ASYNC 不经 `uncheckedDepth`（CallCheck.kt:233 等），`unchecked` 放行函数调用形态但放不住方法形态；是否应统一待核。
4. **边界 B2**：深拷静态留痕只覆盖 NameRef 源（Checker.kt:587/:626/:1299），非 NameRef 源的拷贝只在解释器 `bindCopy` 生效、JS 侧不包 `__dc`；两模式在函数值捕获上的既定差异（§3.2）之外的差异面待系统实测。
5. **行号漂移**：本文引用的 file:line 以当前工作树为准，重构后需按函数名（`binderNeedsCopy`、`registerPureFacts`、`checkCall`、`bindCopy`、`copiedFrame`、`dcWrap`）重定位。

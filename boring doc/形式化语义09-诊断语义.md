# 形式化语义 · 第 09 卷 · 诊断语义

## 一、本卷地位与判断系统

### 1.1 主判断

本卷兑现总纲 §3.8 的诊断接口。主判断为：

$$\Phi \vdash \textit{prog} \Rightarrow \delta^*$$

读法：在诊断收集环境 $\Phi$（实现为 `DiagBag`，Diag.kt:35）下，程序 $\textit{prog}$ 产生有序诊断序列 $\delta^*$。围绕该判断派生四族子判断：

| 子判断 | 读法 | 定义节 |
|---|---|---|
| $\Phi \Rightarrow \delta$ | 单条诊断的产生 | §三 |
| $\textit{render}(\delta, \textit{src}) = \sigma$ | 诊断的输出形态 | §四 |
| $\textit{report}(\Phi, v) = \sigma^*$ | 报告闸门（过滤、去重、保序） | §五 |
| $\textit{EXPLAIN}[c] \mapsto t$ | 码的查表解释 | §七 |

诊断判定不参与类型、命题、效应的推导结果（那些是 01–05 卷的判断），只观察它们失败的位置并落袋。本卷全部规则都是 Observable 性质：规则左端引用他卷判断的失败（如 $\Gamma \nvdash P$），右端产出一条 $\delta$。

### 1.2 诊断元组

$$\delta = (\textit{sev},\ c,\ \textit{pos},\ m,\ \textit{mp})$$

- $\textit{sev} \in \{\text{ERROR}, \text{WARN}, \text{HINT}, \text{SUPPLEMENT}\}$（Diag.kt:4 四级枚举）；
- $c$：诊断码，形如 `E-IMMUT-ASSIGN`（码族字母 + 连字符大写词组，总纲 §6.3）；
- $\textit{pos}$：位置串 `"行:列"`（从 1 计），空串表示无位置（Diag.kt:9）；
- $m$：人话消息（含义 + 修复导向，不含内部决策编号）；
- $\textit{mp}$：归属模块路径 `modulePath`，根模块为 `""`，core 标准库模块为 `"core/..."`（Diag.kt:11；ModuleTree.kt:14/22）。

### 1.3 命名空间裁决

总纲 §7 待核 6 登记：效应规则前缀 `E-`（04 卷）与诊断码族 `E-`（本卷）同名异义。本卷正式规定：

1. **位置区分**：诊断码只作为对象出现——在判断式结论中以码字面量出现（如 `E-CANNOT-PROVE@pos`）、在码表中、在 `explain` 实参中；判断式规则名只出现在横线右端 `(\text{规则名})` 括号内。规则名一律不写成 `E-` 开头的诊断码形态。
2. **本卷规则名一律 `N-` 前缀**（总纲 §6.2 已分配）：`N-EMIT`、`N-RENDER`、`N-DEDUPE` 等。
3. **脱糖规则 `D-`（如 D-5）与补充级码族 `D-`（如 D-BTS）同名异义**：脱糖规则的 `D-` 后接短数字或短名且只在脱糖判断式右端出现；诊断码的 `D-` 后接连字符大写词组且只作为对象出现。
4. 禁止任何规则名与诊断码字面量完全同形地出现在同一位置上下文中；行文中指称码族时一律写「E 族 / W 族 / D 族 / H 族」，不写「E 规则」。

### 1.4 与他卷接口

- 02 卷证明失败（$\Gamma \nvdash$ 各形态）→ §九命题族码；
- 04 卷效应/可变性闸门违反 → §九效应族码；
- 08 卷模块树校验失败 → §九模块族码；
- 10 卷注解处理诊断按严重级映射进同一 $\Phi$（Main.kt:295/:360 回调），编译后阶段诊断只报告不阻断（Main.kt:299/:364）。

## 二、Severity 四级与码族语义

### 2.1 四级枚举

Diag.kt:4 定义四级枚举 `Severity { ERROR, WARN, HINT, SUPPLEMENT }`。各级渲染标签由 Diag.kt:14–16 固定：

| Severity | 渲染标签 | 规范码族 | 阻断编译 | 默认输出 |
|---|---|---|---|---|
| `ERROR` | `[错误]` | `E-` | 是 | 是 |
| `WARN` | `[警告]` | `W-` | 否 | 是 |
| `HINT` | `[提示]` | `H-` | 否 | 是 |
| `SUPPLEMENT` | `[补充]` | `D-` | 否 | 否（仅 `-v`） |

第四级 `SUPPLEMENT` 对应码族字母 `D-`（非 `S-`），这是历史命名约定：`D` 取自 "Diagnostic supplement" 而非 "Debug"。总纲 §3.8 提到的「Severity 四级」即此四级枚举，不存在第五级。

### 2.2 实测计数

对 Main.kt:75–183 的 `EXPLAIN` 表全量抽取（本卷写作时实测）：

$$|\textit{EXPLAIN}| = 107 \qquad |E| = 72 \qquad |W| = 10 \qquad |D| = 18 \qquad |H| = 7$$

源码中存在 6 个有发出点但未收录进 EXPLAIN 表的码（§九标注 `⚠`）；EXPLAIN 表中有 4 个无生产发出点的码（§九标注 `✶`）。合计源码实际发出的唯一码数为 109。总纲 §7.2「约 100 条，待 09 卷定稿」由本卷定稿为精确数 107（EXPLAIN 表）/ 109（含仅源码码）。

### 2.3 码族语义判断式

**E 族 —— 阻断**。语言规范前提被违反；对应他卷判断的失败被断言：

$$\frac{\delta = (\text{ERROR},\ c,\ \textit{pos},\ m,\ \_) \in \Phi}{\textit{hasError}(\Phi) = \top \qquad \text{exit} = 1 \qquad \text{compile 拒绝生成 JS}} \quad (\text{N-FAM-E})$$

实现：`hasError = all.any { it.severity == Severity.ERROR }`（Diag.kt:45）；阻断点在 Main.kt:272（目录 check）、:320（单文件 check）、:338（单文件 compile）。

**W 族 —— 证不出但不敢断言**。程序良构，编译器证不出安全性或用户意图，不敢断言其为错误：

$$\frac{\text{程序良构} \qquad \text{编译器对性质 } P \text{ 既证不出 } \top \text{ 也证不出 } \bot \qquad \neg\,\textit{typeOk}\text{-级失败}}{\Phi \Rightarrow (\text{WARN},\ \texttt{W-}\dots,\ \textit{pos},\ m)} \quad (\text{N-FAM-W})$$

典型：`W-CONSTRAINT-UNPROVEN`（实参是运行时变量，约束表条件证不出，CallCheck.kt:935）、`W-NON-EXHAUSTIVE`（分支可能没走完，WhenCheck.kt:177）。这与总纲 I-1（健全即不猜测）同源：证不出 ≠ 错误，故 W 族给「证不出」一个不阻断的出口。

**D 族 —— 确认性回声，默认隐藏**。编译器替用户做了一次隐式决定，留下可审计痕迹：

$$\frac{\text{编译器完成隐式决定 } a \in \{\text{脱糖, 类型推导, 深拷贝, 命题注入, 效应降级}\}}{\Phi \Rightarrow (\text{SUPPLEMENT},\ \texttt{D-}\dots,\ \textit{pos},\ m) \qquad \neg\,\textit{hasError}\ \text{不受影响}} \quad (\text{N-FAM-D})$$

默认不输出（N-GATE-V）；发射端一律走 `bag.supplement`（Diag.kt:42），严重级恒为 SUPPLEMENT。

**H 族 —— 教学提示**。程序正确，但存在更佳写法或易误读点：

$$\frac{\text{程序正确} \qquad \exists\ \text{更可读/更安全的等价写法}}{\Phi \Rightarrow (\text{HINT},\ \texttt{H-}\dots,\ \textit{pos},\ m) \qquad \text{不阻断} \qquad \text{默认输出}} \quad (\text{N-FAM-H})$$

典型：`H-ARITH-PRECEDENCE`（语言无运算符优先级，Parser.kt:1091 hints 通道）、`H-FIELD-SHADOW`（Checker.kt:355）、`H-AMBIGUOUS-CTOR`（Symbols.kt:136）。

### 2.4 阻断性由严重级决定（N-SEV-BLOCK）

$$\frac{}{\textit{hasError}(\Phi) \iff \exists \delta \in \Phi.\ \textit{sev}(\delta) = \text{ERROR}} \quad (\text{N-SEV-BLOCK})$$

码族字母是命名约定，阻断性由发射端选择的严重级决定。源码中存在以 `bag.warn(...)` 发射 `E-` 前缀码的位点，它们不阻断：

| 码 | 发射位 | 实际严重级 |
|---|---|---|
| `E-PROP-UNBOUND` | Checker.kt:752、CallCheck.kt:907/:914 | WARN |
| `E-QUANT-UNPROVEN` | Checker.kt:764 | WARN |
| `E-THEOREM-SEARCH-DEPTH` | Diffusion.kt:348 | WARN |
| `E-NEED-CLASSIC` | Checker.kt:714 | WARN |

反向（`W-` 码以 ERROR 发射）当前全库未发现。读诊断时必须以严重级标签 `[错误]/[警告]` 判阻断性，不能以码族字母猜。

## 三、诊断的产生与归并

### 3.1 单条诊断产生

$$\frac{\text{核对位 } \textit{chk} \text{ 判定规则 } r \text{ 被违反} \qquad (\textit{sev}_r, c_r) \text{ 为 } r \text{ 的规范严重级与码} \qquad \textit{pos} = \text{违反点 行:列}}{\Phi \vdash \textit{chk} \Rightarrow \delta(\textit{sev}_r,\ c_r,\ \textit{pos},\ m,\ \textit{mp})} \quad (\text{N-EMIT})$$

四个入口（Diag.kt:39–42）：`error / warn / hint / supplement`，分别固定严重级；`modulePath` 由 `DiagBag.modulePath` 自动携带。

### 3.2 归并

$$\frac{\Phi_1, \dots, \Phi_n \text{ 为各模块的袋}}{\Phi = \Phi_1 \cup \dots \cup \Phi_n \qquad \text{（保序拼接）}} \quad (\text{N-ABSORB})$$

实现：`absorb(other)` 直追加 `other.all`（Diag.kt:48）；目录模式在 MultiModule.runPhases（MultiModule.kt:141）把每个 Checker 的袋并入总袋。

### 3.3 解析层失败：异常通道

词法/语法失败在 CLI check/compile 路径上以异常上抛，被 main 的 `catch (e: RuntimeException)`（Main.kt:383–386）兜住，输出 `[错误] <消息>`、退出码 1，不携带诊断码：

$$\frac{\text{解析失败}}{\text{抛 } \texttt{ParseFailure} \qquad \text{exit} = 1 \qquad \delta^* = \epsilon} \quad (\text{N-PARSE-EXN})$$

`E-LEX` / `E-PARSE` / `E-CHECK` 三码的发射端在 language-service（LspAnalysis.kt:361/:377/:464）；CLI 路径上它们只存在于 EXPLAIN 表中可查。`E-PARSE` 另有一处 checker 内部兜底（Checker.kt:979，IsPatExpr 残留节点）。

## 四、渲染形态

### 4.1 基本形态

$$\frac{\delta = (\textit{sev},\ c,\ \textit{pos},\ m,\ \_)}{\textit{render}(\delta) = \text{[标签][}\textit{pos}\text{] } c\text{: } m} \quad (\text{N-RENDER})$$

标签：ERROR→`[错误]`、WARN→`[警告]`、HINT→`[提示]`、SUPPLEMENT→`[补充]`（Diag.kt:14–16）；$\textit{pos}$ 为空串时 `[$pos]` 段省略（Diag.kt:17）。

### 4.2 源码片段上下文

$$\frac{\textit{source} \neq \text{null} \qquad \textit{pos} = \text{"}l\text{:}k\text{"} \qquad 1 \leq l \leq |\textit{source}|}{\textit{render}(\delta, \textit{source}) = \text{基本形态} \;+\; \begin{array}{l}\text{右对齐 } l \text{ | 源第 } l \text{ 行}\\ \text{对齐空格 | } (k-1) \text{ 个空格加 } \hat{}\ \end{array}} \quad (\text{N-SNIPPET})$$

实现（Diag.kt:19–32）：$k-1$ 以 `coerceIn(0, text.length)` 夹逼、箭头只画一个 `^`；行号右对齐宽度取 $|source|$ 行数的十进制位数。以下情形不追加片段：`source == null`、`pos` 为空、`pos` 不匹配 `(\d+):(\d+)`、行号越界。

### 4.3 输出通道

| 内容 | 通道 | 位点（Main.kt） |
|---|---|---|
| check 诊断报告（单文件/目录） | stdout | :319 / :271 |
| compile 诊断报告 | stderr | :337 |
| 收尾失败行 `[错误] 语义检查未通过` | stderr | :273 / :320 / :338 |
| JS 产物 | stdout（无 `-o`）或 `-o` 文件 | :288 / :350–352 |
| 编译后处理器报告 | stdout；其错误行走 stderr | :298–299 / :362–364 |
| 脚本 inferNotes | stdout | :409 / :421 |
| explain 命中/未命中 | stdout / stderr | :197 / :194 |

check 与 compile 对诊断报告的通道选择相反：check 走 stdout 使脚本能分离诊断与产物，compile 走 stderr 使 stdout 只剩 JS。目录模式（Main.kt:270）调 `report(includeSupplement = verbose)` 不带 source——目录模式无源码片段上下文，单文件模式才带。

## 五、三道报告闸门

报告是三道闸的复合，顺序为「过滤 → 归属过滤 → 去重」，袋内序列保序。三道闸各自职责独立、互不替代：第一道控制可见性级别、第二道控制模块噪声、第三道控制重查冗余。

### 5.1 第一道：`-v` 补充级闸门

$$\frac{\neg\,\textit{verbose}}{\{\delta \mid \textit{sev}(\delta) = \text{SUPPLEMENT}\} \notin \textit{report}} \qquad \frac{\textit{verbose}}{\textit{report} = \Phi\ \text{（全族保留）}} \quad (\text{N-GATE-V})$$

实现：`report(includeSupplement)`（Diag.kt:64–66）；`verbose = args.contains("-v")`（Main.kt:201）——全局旗标，对 check/compile、单文件/目录模式一致生效。过滤只作用于输出，不作用于 `hasError`（N-SEV-BLOCK）：即使补充级被隐藏，阻断行为不变。

### 5.2 第二道：多模块归属过滤

$$\frac{\textit{sev}(\delta) = \text{SUPPLEMENT} \qquad \delta.\textit{mp} \neq \text{""}}{\delta \notin \textit{report}} \quad (\text{N-GATE-DROP})$$

实现：`dropSupplementsOutside(rootPath)`（Diag.kt:51–53），唯一调用点是 `MultiModule.runPhases` 的 `bag.dropSupplementsOutside("")`（MultiModule.kt:143）。根模块 `modulePath = ""`（ModuleTree.kt:14），故即便 `-v` 也看不到 core 标准库等挂载模块自身的补充级诊断——这是有意设计。该闸只在目录模式存在：单文件 check/compile 从不调用本闸。

### 5.3 第三道：dedupe 三元组去重

$$\frac{\exists \delta' \in \Phi_{\text{已见}}.\ (\textit{code}, \textit{pos}, m) = (\textit{code}', \textit{pos}', m')}{\delta \text{ 被丢弃（保留首发）}} \qquad \frac{(\textit{pos} \neq \textit{pos}' \lor m \neq m')}{\delta, \delta' \text{ 均保留}} \quad (\text{N-DEDUPE})$$

实现：`dedupe()`（Diag.kt:56–61）以 `Triple(code, pos, message)` 为键，使用 `HashSet` 记录已见三元组、`ArrayList` 保序输出。两个触发点（都是重查场景）：

1. **类型推导定点反推**：泛型调用的 lambda 实参在 ≤8 轮迭代环里重复检查，循环后 `if (rounds > 1) d.dedupe()` 收敛（CallCheck.kt:804 注、:837）；
2. **注解处理器改写后重查**：处理器改动 AST → 阶段 A/B/C 全部重跑，`if (checked) bag.dedupe() else checked = true`（MultiModule.kt:113）。

推论：两处同种错误互不吸收（位置不同即不同键）。

### 5.4 序

$$\frac{}{\textit{report}\text{ 的序} = \Phi\text{ 的袋内插入序（过滤与去重均不重排）}} \quad (\text{N-ORDER})$$

无任何按严重级或码排序的步骤；补充级「排在最后」只是袋内插入顺序的涌现。

## 六、脚本模式 inferNotes 旁路

### 6.1 旁路判断式

脚本模式（`run-script`，含 `--global-inference`）有一条绕过 $\Phi$ 的直通通道：全局类型推导（GlobalInference）的产物不进 DiagBag，而由解释器暴露为 `inferNotes`（Interpreter.kt:33–34；元素为 `InferNote(severity, code, pos, message)`，GlobalInference.kt:29）：

$$\frac{n \in \textit{interp.inferNotes}}{\text{stdout}:\ \text{[提示] [}n.c\text{] } n.m \qquad \text{不经 } \Phi\text{、不经 render、不受 -v 闸、不受 dropSupplementsOutside、不经 dedupe}} \quad (\text{N-NOTE-BYPASS})$$

实现：Main.kt:409/:421 的 `interp.inferNotes.forEach { n -> println("[提示] [" + n.code + "] " + n.message) }`。标签硬编码为 `[提示]`（与 $n.\textit{sev}$ 无关）；不打印位置与源码片段；只要跑了推导就一定打印。

### 6.2 与标准映射的偏差

- `D-AUTO-IMPURE`：GlobalInference.kt:670 以 `severity = "SUPPLEMENT"` 发射，经本通道打印为 `[提示] [D-AUTO-IMPURE] …`——码族字母 `D`（规范对应 `[补充]`）与渲染标签 `[提示]` 双重偏差，且不受 `-v` 控制；
- `E-TYPE-CONFLICT`：推导冲突（GlobalInference.kt:332/:349/:390）在推导期即抛 `InterpreterError`，被 main 的 RuntimeException 兜底（Main.kt:383–386）→ 退出码 1。它永不作为 $\delta$ 出现在 check/compile 的袋里。

$$\frac{n.\textit{sev} = \text{"ERROR"} \qquad n \in \textit{inferNotes}}{\text{抛 } \texttt{InterpreterError} \qquad \text{exit} = 1} \quad (\text{N-INFER-ERR})$$

## 七、explain 查表语义

### 7.1 判断式

`explain <CODE>` 是纯查表：不读源码、不跑管线。

$$\frac{\textit{EXPLAIN}[\textit{upper}(c)] = t}{\text{stdout}:\ \text{"}c\text{ — } t\text{"} \qquad \text{exit} = 0} \quad (\text{N-EXPLAIN-HIT})$$

$$\frac{\textit{upper}(c) \notin \textit{keys}(\textit{EXPLAIN})}{\text{stderr}:\ \text{[错误] 未收录诊断码 } c\text{（现有：}\textit{sorted}(\textit{keys})\text{ 列表）} \qquad \text{exit} = 2} \quad (\text{N-EXPLAIN-MISS})$$

实现：Main.kt:189–198；入参先 `uppercase()`（:191），故终端敲小写也命中；无模糊匹配、无前缀补全。命中后 `println` 再 `return`（:197–198），退出码 0；失败退出码 2（:195），且把全部已收录码按字典序列出。

### 7.2 表项文本约定

EXPLAIN 表项是固定两段式：**含义句**（以「。——」分隔）+ **修复建议**。部分表项仍带「错误：/警告：/补充：/提示：」前缀（如 :137/:136/:133/:96），是历史写作遗迹，与实际严重级无绑定关系。

### 7.3 覆盖不变量

$$\frac{}{\textit{keys}(\textit{EXPLAIN}) = \textit{knownCodes}\ (\text{双向同步，由 ExplainCoverageTest 强制})} \quad (\text{N-COVERAGE})$$

`ExplainCoverageTest` 断言 `EXPLAIN.keys.toSortedSet() == knownCodes`。注意两点：

1. `knownCodes` 是人工维护清单，不变量是「表与清单一致」，不是「表与发射点一致」；
2. **表收录 ⇏ 现役发射**。实测四类失配详见 §九各表标注。

## 八、退出码契约

$$\frac{\neg\,\textit{hasError}(\Phi) \qquad \text{无异常抛出}}{\text{exit} = 0} \quad (\text{N-EXIT-OK})$$

$$\frac{\textit{hasError}(\Phi)}{\text{stderr}:\ \text{[错误] 语义检查未通过} \qquad \text{exit} = 1} \quad (\text{N-EXIT-ERR})$$

$$\frac{\text{用法/前置契约被违反}}{\text{stderr}:\ \text{USAGE 或 [错误] 说明} \qquad \text{exit} = 2} \quad (\text{N-EXIT-USAGE})$$

$$\frac{\textit{aggressive} \qquad \text{Ctrl-C} \qquad \text{ProverInterrupted}}{\textit{dumpPath}\text{ 写报告} \qquad \text{stderr}:\ \text{[激进证明] 已中断} \qquad \texttt{Runtime.halt}(130)} \quad (\text{N-EXIT-INT})$$

| 退出码 | 语义 | 触发位点（Main.kt） |
|---|---|---|
| 0 | 成功 | check 通过（:321/:277）、compile 产出（:288/:351）、explain 命中（:198）、脚本跑完（:429） |
| 1 | 编译/执行失败 | hasError（:273/:320/:338）；处理器装载失败（:266）；RuntimeException（:383–386）；脚本无目标（:427） |
| 2 | 用法/契约错误 | 空参数（:186）；explain 缺码/未收录（:190/:195）；缺子命令参数（:200）；-p 缺路径（:221/:223）；-A 缺值（:236）；文件不存在（:254）；目录接错子命令（:258）；未知子命令（:374）；run-script 无目标（:394）或路径不存在（:401） |
| 130 | 激进证明被中断 | ProverInterrupted 兜底（:376–382）→ halt(130) |

三条操作契约：

1. **halt 而非 exitProcess**：130 路径用 `Runtime.getRuntime().halt(130)`（Main.kt:382）绕过其余 shutdown 处理立即退出；
2. **1 与 2 的区分是给 CI 用的**：编译失败（源码问题）与命令用错（契约问题）必须可程序化区分；
3. **退出码只看 ERROR 级**：W/D/H 任意多条都不改变退出码；`hasError` 在报告过滤之前计算。

## 十、确定性与健全性条款

1. **N-DET（确定性，总纲 I-8 落地）**：同一源文本、同一编译模式、同一旗标集，$\delta^*$ 的内容与顺序都确定。依据：袋为 `ArrayList` 保序插入（Diag.kt:36）、报告只过滤不重排（N-ORDER）、dedupe 用 `HashSet` 记录已见 + `ArrayList` 保序输出保留首发（Diag.kt:56–61，确定性不受重查次数影响）、dropSupplementsOutside 用 `removeAll` 不重排（Diag.kt:51–53）。唯一非确定的已知来源是激进模式的搜索调度（受中断时机影响），但那只在 Ctrl-C 时显现为 exit 130 + dump 报告。
2. **N-NOHIDE**：ERROR 级诊断不受任何闸门隐藏——`-v` 闸只过滤 SUPPLEMENT（N-GATE-V）、dropSupplementsOutside 只作用于 SUPPLEMENT（N-GATE-DROP）、dedupe 只吸收三元组全同者（N-DEDUPE）。
3. **N-SOUND-EXIT**：exit 0 ⟹ 无 ERROR 级诊断（N-EXIT-OK/N-SEV-BLOCK 的逆否）；exit 1 时 stderr 必有可定位的原因。
4. **N-D-NONBLOCK**：D 族恒不阻断（发射端固定 SUPPLEMENT，N-FAM-D）。
5. **N-EXPLAIN-CONTRACT**：每个规范码在 EXPLAIN 中恰有一条解释（N-COVERAGE 双向同步）；`explain` 是纯查表，不得有副作用。
6. **N-CHANNEL**：诊断有且仅有三条落盘通路——$\Phi$ 袋（check/compile，过 render 与全部闸门）、脚本 inferNotes 旁路（§六，无闸门无渲染）、解析/运行时异常通道（§3.3、N-INFER-ERR，无码）。

# 第七卷 · 模式匹配

> 本语言的模式匹配融入了上下文系统，因此值得单开一卷。
> 本卷规定 `when` 表达式的形态、模式种类、分支命题、守卫、顺序与穷尽性判定、解构、区间模板。

---

## 1. when 表达式

### 1.1 四种形态

```
WhenExpr → 'when' '(' Subject ')' '{' { WhenArm } '}'      有主题
         | 'when' '{' { WhenArm } '}'                        无主题（条件链）
         | 'when' '(' 'var' Name '=' Expr ')' '{' … '}'      绑定式主题
         | 'when' '(' Expr 'in' '_' ')' '{' … '}'            区间模板
```

**分支分隔符是 `=>`。**

分支体有两种写法：单表达式（`=> expr`）或语句块（`=> { … }`）。

### 1.2 有主题 when

```subl
when (n) {
    0            => print("零")
    m if m > 10  => print("大数")
    else         => print("其他")
}
```

主题被逐一与各分支的模式匹配。

### 1.3 无主题 when

不写主题的条件链，按条件真值依次判定：

```subl
when {
    n < 0  => print("负")
    n == 0 => print("零")
    n > 0  => print("正")
}
```

无主题 `when` 的分支用 `cond` 承载条件表达式，`pattern` 位为条件占位哨兵。

### 1.4 绑定式主题

```subl
when (var x = f()) {
    is Some(v) => print(v)
    else       => print("空")
}
```

主题只求值一次并绑定到名字，各分支可同时使用该名字与解构出的绑定。

### 1.5 区间模板

```subl
when(n in _) {
    (0 .. 10)  => print(1)
    (11 .. 20) => print(2)
    (21 .. 30) => print(3)
}
```

见 §7。

## 2. 模式种类

### 2.1 模式的定义

```
Pattern = PatLit   ⟨ value : Expr ⟩              字面量模式
        | PatCtor  ⟨ name, args : List<Pattern> ⟩ 构造子模式（含解构）
        | PatTuple ⟨ items : List<Pattern> ⟩      元组模式
        | PatIs    ⟨ type : Type, bind : String? ⟩ 类型模式（可绑定）
        | PatBind  ⟨ name ⟩                       变量绑定模式（含通配 _）
        | PatElse                                 兜底模式
        | PatCond                                 无主题 when 的条件占位
```

### 2.2 表达式分支

**表达式分支用于判断模式匹配的判断主体是不是相等于分支的表达式。**

```subl
when(1) {
    1 =>
    2 =>
    3 =>
    else =>
}
```

**表达式分支的分支命题是判断主体与分支的表达式的相等命题**（比方说这里第一个分支的分支命题是 `1 = 1`）。

```
主题是 s，分支模式是字面量或无参构造子 ℓ
────────────────────────────────────────  (M-BRANCH-EQ)
分支命题 = (s = ℓ)
```

### 2.3 类型分支

**类型分支用于判断模式匹配的判断主体是不是某个类型。**

```subl
when(1) {
    is Nat =>
    is Int =>
    is Rat =>
    else =>
}
```

**类型分支的分支命题是判断主体与分支的类型的为命题**（比方说这里第一个分支的分支命题是 `1 : Nat`）。

```
主题是 s，分支模式是 is T
────────────────────────────────────────  (M-BRANCH-TYPE)
分支命题 = (s : T)
```

### 2.4 守卫

**在分支中可以加入 `if` 子句附加逻辑判断。**

```subl
when(n) {
    is Nat if n > 10 =>
    is Nat =>
    else =>
}
```

**第一个分支的分支命题是 `n : Nat` 和 `n > 10` 的合取。**

```
分支模式 p，守卫 g
────────────────────────────────────────  (M-GUARD)
分支命题 = p 的分支命题 ∧ g
```

**守卫位是值层的**，不要用命题算符 `∧`／`∨`。多条件组合用 `&`（代码生成为 JavaScript 的 `&&`），比较写成前缀调用：

```subl
when (n) {
    0 => print("zero")
    m if !=(m, 0) & !=(m, 1) => print("many")     // 前缀调用 + &
    else => print("small")
}
```

### 2.5 变量绑定模式

```subl
when (n) {
    m if m > 10 => print("大")     // m 绑定主题，作用域在分支内
    else => print("其他")
}
```

```
分支模式是 PatBind(x)，x ≠ "_"
────────────────────────────────────────  (M-BIND)
分支命题 = ⊤      分支帧内注入 x = 主题、x : 主题类型
```

通配 `_` 是 `PatBind("_")`，不注入任何绑定。

### 2.6 构造子模式与解构

**模式匹配的 `is` 判断枚举或者结构体的时候可以对它解构。**

```subl
when(o) {
    is Optional::Some(o) =>
    is Optional::None =>
}
```

这里对 `Some` 解构；还可以对结构体解构：

```subl
struct T(a : Nat, b : Nat)
when(o) {
    is T(a, b) =>
    else =>
}
```

```
分支模式是 is C(p₁…pₖ)，主题是 s
────────────────────────────────────────  (M-CTOR)
分支命题 = (s = C(x₁…xₖ))，其中 xᵢ 是 pᵢ 绑定的新鲜名
分支帧内：按 pᵢ 递归注入各分量的绑定与命题
```

**嵌套解构**：

```subl
when (result) {
    is Ok(is Some(v)) => print(v)        // 两层构造子同时解构
    is Ok(None)       => print("空")
    is Err(e)         => print("错: " + e)
}
```

**解构必须显式书写 `is`**（第二卷 §6.3）：

```subl
when (o) {
    is Some(v) => print(v)     // 正确
    Some(v)    => print(v)     // 错误：不带 is 时只允许无参值比较形态
    None       => print("空")  // 正确
}
```

### 2.7 限定名模式

跨枚举的同名构造子用 `枚举::构造子` 消歧：

```subl
when (c) {
    is Color::Red => …
    is Other::Red => …
}
```

多枚举存在同名构造子且有歧义时发 `H-AMBIGUOUS-CTOR` 提示。

### 2.8 as 绑定

```subl
when (o) {
    is Optional[Nat] as x => print(x)     // 类型分支并绑定整体
}
```

```
分支模式是 is T as x
────────────────────────────────────────  (M-IS-AS)
分支命题 = (s : T)      分支帧内注入 x = s、x : T
```

### 2.9 元组模式

```subl
fun firstOf(p : (Nat, Nat)) : Nat = when(p) {
    (a, b) => a
    else   => 0
}
```

```
分支模式是 (p₁…pₖ)，主题是 s
────────────────────────────────────────  (M-TUPLE)
分支命题 = ⊤      分支帧内按分量注入绑定
```

### 2.10 兜底模式

```
分支模式是 else（或 _ 位于末位）
────────────────────────────────────────  (M-ELSE)
分支命题 = ⊤
```

### 2.11 ifis 智能解构

类似于 Rust 的 `if let`，在类型判断中对对象进行解构：

```subl
if(str is Some(str))
    print(str)
else
    print("null")
```

它脱糖为 `when`（第二卷 §8.6）：

```
if (e is pat) A else B  ⟶  when (e) { is pat => A ; else => B }
```

因此穷尽性提示、分支命题与智能转换规则**全部复用**。

```subl
fun describe(o : Optional[Nat]) : Nat =
    if (o is Some(e)) e else 0      // 匹配 Some 则进入分支，e 绑定内部值

fun first(o : Optional[Nat]) : Nat {
    if (o is Some(e)) { return e }  // 提前 return 照常退出函数
    return 0
}
```

规则：

- 模式与 `when` 分支**完全同构**：构造子解构、结构体解构、限定路径、嵌套、通配 `_`、`as` 绑定都能用；
- 不带 `else` 时与普通无 `else` 的 `if` 同义（值退化）；枚举主题会按既有规则给 `W-NON-EXHAUSTIVE` 提示；
- **条件必须是单独的模式判断**：`if (o is Some(e) && e > 0)` 不被接受（绑定的 `e` 也没有作用域），组合条件请改用 `when` 分支守卫；
- 普通布尔条件 `if (c)`、类型测 `if (x is Nat)`（分支内智能转换）不受影响。

## 3. 分支帧

### 3.1 分支帧的创建

```
每个 when 分支创建独立子帧 F′ = Frame(F)
────────────────────────────────────────  (M-BRANCH-FRAME)
分支帧内注入：模式绑定的变量、分支命题
分支帧的事实不回溢到父帧
```

分支内的事实不外泄的理由见第五卷 §3.5：分支命题只在该分支条件下成立。

### 3.2 智能转换

类型分支在分支内产生**智能转换**：

```
分支命题含 s : T
────────────────────────────────────────  (M-SMART-CAST)
分支内 s 的类型按 T 对待
```

## 4. 顺序与穷尽性

### 4.1 顺序语义

**模式匹配是顺序的，因此后面的分支有前面的分支的命题的否定。**

```
分支序列 b₁, b₂, …, bₙ，其分支命题分别为 p₁, p₂, …, pₙ
────────────────────────────────────────  (M-ORDER)
bᵢ 的分支帧内额外注入：¬p₁, ¬p₂, …, ¬pᵢ₋₁
```

**示例**：

```subl
when(n) {
    is Nat if n > 10 => …      // 分支命题：n : Nat ∧ n > 10
    is Nat => …                // 分支命题：n : Nat，且已知 ¬(n : Nat ∧ n > 10)
    else => …                  // 已知前两者的否定
}
```

第二个分支内因此可以推出 `n ≤ 10`（在 `n : Nat` 的前提下）。

### 4.2 穷尽性判据

**如果可以证明模式匹配所有分支的析取命题，那么认为模式匹配是穷尽的**：

```
Γ ⊢ p₁ ∨ p₂ ∨ … ∨ pₙ
────────────────────────────────────────  (M-EXHAUSTIVE)
when 穷尽      返回类型 = 所有分支的联合类型
```

**如果没有证明，则认为模式匹配没有穷尽，此时固定返回 `Null`**：

```
Γ ⊬ p₁ ∨ p₂ ∨ … ∨ pₙ
────────────────────────────────────────  (M-NON-EXHAUSTIVE)
when 非穷尽      返回类型 = (未密封)，仅与 Null 相容
```

判据是分支命题的**析取**在 Γ 里可证恒真——**不是合取**。

### 4.3 穷尽性是提示不是要求

凝华的穷尽性是**提示**而非强制：

| 情形 | 诊断 | 值类型 |
|---|---|---|
| 判不出穷尽，主题无覆盖律 | 无 | `(未密封)` |
| 有覆盖律但覆盖不全 | `W-NON-EXHAUSTIVE` | `(未密封)` |
| 非密封值流向非 `Null` 上下文 | `E-NON-SEALED-MATCH` | — |

```subl
// 错误：返回值来自非穷尽 when（值可能为 Null）
fun name(c : Color) : Str = when(c) {
    Red => "红"
}

// 正确：枚举三构造子补齐
fun name(c : Color) : Str = when(c) {
    Red   => "红"
    Green => "绿"
    Blue  => "蓝"
}
```

### 4.4 覆盖律

**覆盖律**是枚举的穷尽析取。它按 `when` 主题的**具体类型就地生成**，不用全局 `∀`——因为泛型枚举（`Optional` 与 `Optional[Nat]`）会失配。

```
主题类型是 E[τ⃗]，E 的构造子为 C₁…Cₖ
────────────────────────────────────────  (M-COVER)
覆盖律 = C₁(x⃗₁) ∨ C₂(x⃗₂) ∨ … ∨ Cₖ(x⃗ₖ)     变量就地新鲜生成
```

**覆盖律的递归深展开**：内层形状给单等式 `v = term` 时代入外层，与分支命题的 `∃` 形态同构。

### 4.5 析取子集规则的方向

穷尽性判定依赖第四卷 §5.4 的析取子集规则：

```
(A ∨ B) ⊢ (A ∨ B ∨ C)      有效
(A ∨ B ∨ C) ⊢ (A ∨ B)      无效
```

由此：覆盖律 `(R ∨ G ∨ B)` 能证出穷尽目标 `(R ∨ G ∨ B)`，但证不出残缺目标 `(R ∨ G)`——恰是部分匹配的 `when` 应当报 `W-NON-EXHAUSTIVE` 的语义。**方向反了会让缺分支的 when 误判穷尽。**

### 4.6 构造子单射

```
C<a> = C<b> → a = b
────────────────────────────────────────  (M-INJECTIVE)
用于嵌套穷尽性判定
```

### 4.7 α-等价在穷尽性中的作用

覆盖律与分支命题使用的变量名必然不同，因此命题比较**必须**按 α-等价进行（第四卷 §2.8），不能退回字符串比较。

## 5. when 的类型

### 5.1 穷尽时

```
when 穷尽，各分支类型依次为 τ₁…τₙ
────────────────────────────────────────  (M-TYPE-SEALED)
when 的类型 = τ₁ | τ₂ | … | τₙ        （联合类型）
```

若各分支类型相同，联合退化为该类型。

### 5.2 非穷尽时

```
when 非穷尽
────────────────────────────────────────  (M-TYPE-UNSEALED)
when 的类型 = (未密封)      仅与 Null 相容
```

### 5.3 分支提前 return

分支块里提前 `return` 要求 `when` 处于**语句位**（不能是变量初值、实参等值位）。作为块尾表达式时还需补 `else` 兜底且全分支 `return`——`when` 判作**发散**才按语句流处理；位于语句中间则无此限制：

```subl
fun classify(n : Nat) : Nat {
    when {
        n < 0 => { return 0 }
        else  => { return n }
    }
}
```

**发散判定**：`when` 的所有分支均以 `return` 收尾时，`when` 判为发散，其类型是 `Nothing`。

## 6. 命题层的分类讨论

值层 `when` 之外还有一条**命题层**语句：`when[p ∨ q] { … }`，即分类讨论语句。其完整语义见第四卷 §6.3。

```subl
unchecked.axiom[n ≤ 10 ∨ n > 10]        // 先把析取式注入 Γ
when[n ≤ 10 ∨ n > 10] {
    n ≤ 10 => { ∴ n ≥ 0 }
    n > 10 => { ∴ n ≥ 0 }
}
∴ n ≥ 0                                  // 两支共同结论，注入 Γ
```

与值层 `when` 的区别：

| 维度 | 值层 `when(e)` | 命题层 `when[p ∨ q]` |
|---|---|---|
| 括号 | 圆括号 | **方括号** |
| 内容 | 值表达式 | 析取命题 |
| 分支 | 模式 + 表达式体 | 命题条件 + **语句块** |
| `else` 臂 | 允许 | **没有** |
| 产出 | 值（联合类型或 `Null`） | `Null`，且注入公共结论 |
| 使用场景 | 值层程序 | 手动证明 |

## 7. 区间模板

### 7.1 形态

在判断框内的 `_` 会被替换为分支主体：

```subl
when(n in _) {
    0 ..10 -> print(1)
    11..20 -> print(2)
    21..30 -> print(3)
}
```

等同于：

```subl
when {
    n in (0 ..10) -> print(1)
    n in (11..20) -> print(2)
    n in (21..30) -> print(3)
}
```

（分支分隔符按本规范统一书写为 `=>`。）

### 7.2 全域推断

区间模板的穷尽性判定的关键在于**全域**的确定。编译器从 Γ 中组合出全域：

```
Γ 含 n ≤ hi（来自函数上文或结构体伴生命题）
Γ 含 n ≥ lo（来自 Nat 的自然命题，或显式事实）
────────────────────────────────────────  (M-RANGE-DOMAIN)
全域 = (lo .. hi)
```

**示例**：

```subl
fun grade(score : Nat) <score ≤ 100> : Str =
    when(score in _) {                        // _ = 从上下文推断区间
        (0 .. 59)   => "不及格"
        (60 .. 79)  => "及格"
        (80 .. 100) => "优秀"
    }
```

编译器从上下文的 `score ≤ 100` 与 `Nat` 自带的 `score ≥ 0` 组合出全域 `(0..100)`，再收集每个分支的端点（0, 59, 60, 79, 80, 100），排序后检查相邻衔接。分支覆盖了全域，**无需 `else` 也不需要自己写边界检查**。

### 7.3 端点衔接判定

```
分支区间依次为 (l₁..h₁), (l₂..h₂), …, (lₙ..hₙ)，排序后
全域为 (L..H)
────────────────────────────────────────  (M-RANGE-EXHAUST)
穷尽 ⟺ l₁ = L  ∧  hₙ = H  ∧  ∀i < n. lᵢ₊₁ = hᵢ + 1
```

即：首端点对齐全域下界、末端点对齐全域上界、相邻区间无缝衔接。

区间有缝时报 `W-NON-EXHAUSTIVE`：

```
分支区间 (0..10)(11..20) 中间有缝（10 和 11 之间）→ 检查端点衔接
```

### 7.4 上界必须写进命题

**全域上界要写进命题**（`<score ≤ 100>`），用 Unicode `≤`；**命题算符不接受 `<=`**（第一卷 §4.8）。

```subl
fun demo(n : Nat) <n ∈ (0..30)> : Nat {
    @mut var r = 0
    when(n in _) {                 // 编译器证明这三个区间覆盖 (0..30)
        (0 .. 10)  => { r = 1 }
        (11 .. 20) => { r = 2 }
        (21 .. 30) => { r = 3 }
    }
    return r
}
```

`n ∈ (0..30)` 形态的上文同样可以确定全域。

### 7.5 无主题区间 when

无主题 `when` 的区间穷尽判定与模板形态**同源**，前提同样是 Γ 里有全域上下文（函数上文或结构体伴生命题）：

```subl
fun grade2(score : Nat) <score ≤ 100> : Str = when {
    score in (0 .. 59)  => "不及格"
    score in (60 .. 79) => "及格"
    score in (80 .. 100) => "优秀"
}
```

结构体字段同理——伴生命题建域，impl 方法里直接写无主题区间 `when`：

```subl
struct Student(name : Str, score : Nat) <score ≤ 100>

class Gradable { fun grade() : Grade }
impl Gradable for Student {
    fun grade() : Grade = when {
        score in (90..100) => Grade::A
        score in (80..89)  => Grade::B
        score in (60..79)  => Grade::C
        score in (0..59)   => Grade::D
    }
}
```

### 7.6 区间穷尽的证明通道

区间的穷尽性由**线性算术通道**判定（第四卷 §8.1）：编译器收集关键表达式（如 0, 10, 11, 20, 21, 30）并应用定理自动证明，无需手工补丁。

### 7.7 区间推断的诊断

`_` 被推断为具体区间时发 `D-RANGE-INFER` 补充级诊断：

```
D-RANGE-INFER: `when(n in _)` 的 _ 推断为区间 (0..30)
```

## 8. 成员判断 in

### 8.1 语法

`in` 是中缀函数（第二卷 §8.3）：

```subl
a in b          ⟶ in(a, b)
x in 0..10      ⟶ in(x, (0..10))
x in r          ⟶ in(x, r)      r : Range[T]
```

### 8.2 类型规则

```
Γ ⊢ x : τ     Γ ⊢ r : Range[τ]
────────────────────────────────────────  (M-IN)
Γ ⊢ x in r : Bool
```

`in` 的右操作数必须是区间字面量 `lo..hi` 或 `Range[T]` 值，否则报 `E-TYPE-MISMATCH`。

### 8.3 成员命题

`x ∈ xs` 是**集合成员命题**，其中 `xs` 是容器（列表、集合等）。它由自定义命题声明（第四卷 §3.1）：

```subl
def ∈<a, b>
```

成员命题参与全称量词的推理，这是上下文系统的核心用法之一：

```subl
∀ x . x ∈ list → p<x>
```

成员命题的证明由**成员过滤谓词通道**承担（第四卷 §5.5），覆盖如下形态：

```subl
list.filter { _ != 0 }        // 后置命题 ∀e . e ∈ $ → e ≠ 0
```

比较记号在该通道做 ASCII 与 Unicode 等价（`!=` ↔ `≠`、`<=` ↔ `≤`、`>=` ↔ `≥`、`==` ↔ `=`）。

### 8.4 常量区间成员

```
n、lo、hi 均为整数字面量
────────────────────────────────────────  (M-IN-CONST)
⊢ n ∈ (lo..hi)  当且仅当  lo ≤ n ≤ hi
```

## 10. 模式匹配的诊断

| 码 | 等级 | 触发条件 |
|---|---|---|
| `W-NON-EXHAUSTIVE` | 警告 | `when` 非穷尽（缺 `else` 或覆盖不全），作为表达式时值类型退化为 `Null` |
| `E-NON-SEALED-MATCH` | 错误 | 非密封 `when` 的值流向了非 `Null` 上下文 |
| `E-TYPE-MISMATCH` | 错误 | 分支体类型与预期不符；`in` 右侧不是区间或 `Range[T]` |
| `H-AMBIGUOUS-CTOR` | 提示 | 跨枚举同名构造子歧义 |
| `D-RANGE-INFER` | 补充 | `when(n in _)` 的 `_` 推断为具体区间 |

## 11. 书写建议

- `when` 应尽量穷尽所有可能值；把穷尽性交给编译器；
- 区间判断放进 `when(n in _)`，让编译器自动证明覆盖，全界写进命题 `≤`；
- 前置条件放类型里（函数上文、结构体伴生命题），不作运行时防御检查；
- `Optional` 不裸用 `if`／`else`——用 `when` 解构或链式方法；
- 守卫位是值层，用 `&` 与 `|`，不用 `∧` 与 `∨`；
- 分支与 lambda 的分隔符一律用 `=>`。

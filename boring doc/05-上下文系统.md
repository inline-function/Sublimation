# 第五卷 · 上下文系统

> 上下文系统是凝华的核心机制。本卷规定上下文的构成、作用域与弥散规则、自然命题的注入、函数的上文与下文、伴生命题、内联标识与供给机制。
> 命题本身的表示与证明算法见第四卷。

---

## 1. 上下文的地位

### 1.1 定义

**上下文系统**把命题作为独立存在，弥散在作用域中。函数的**上文**与**下文**描述「调用前空气里必须有什么、调用后空气里会多出什么」。

上下文**不是**参数，**不是**值。它不参与运行时，不进入生成代码，也不能被程序读取。

### 1.2 Γ 的构成

上下文记为 `Γ`，是一个二元组：

```
Γ = ⟨V, F⟩
```

| 分量 | 名称 | 内容 |
|---|---|---|
| `V` | 变量类型环境 | 从变量名到类型的有限映射 |
| `F` | 命题事实集 | 命题的有限集合（去重，保持注入顺序） |

`F` 中的条目形态：

| 形态 | 例子 | 来源 |
|---|---|---|
| 类型归属 `e : τ` | `n : Nat` | 自然命题注入 |
| 等式 `e₁ = e₂` | `n = 0` | 变量声明、字段构造 |
| 谓词原子 | `n ≥ 0`、`tagged<7>` | 自然命题、定理、公理 |
| 命题绑定 | `p`（零元） | 命题参数供给 |
| 伴生记录 | `f<a, b>` | 函数调用 |

### 1.3 弥散

**弥散**（diffusion）是命题在作用域中流动的机制。命题像气体一样：在作用域内产生后向可见范围扩散，不需要显式传递。

事实的三个来源：

1. **显式注入**：`axiom …`、`by […]`、`var` 声明；
2. **函数下文**：调用成功后注入；
3. **分支条件**：`if`／`when` 的分支条件在分支内成为事实。

**`if`／`when` 是值世界通往命题世界的唯一桥梁。**

### 1.4 上下文驱动行为

命题不只是供传参使用，它还能改变编译行为：

| 事实 | 驱动的编译行为 |
|---|---|
| `e : Nat` | 智能转换：`e` 在该作用域内按 `Nat` 对待 |
| `pure<f>` | 放行纯作用域对 `f` 的调用（第六卷 §2.3） |
| `T : Show` | 类型类约束的字典解析 |
| `n ∈ (0..30)` | 区间穷尽性的全域推断（第七卷 §7） |

## 2. 帧

### 2.1 帧的定义

上下文按作用域嵌套组织为**帧**（frame）。一个帧携带：

```
Frame = ⟨
    parent          : Frame?                       父帧
    vars            : Map<String, Type>            变量类型环境（有序）
    facts           : Set<Prop>                    Γ 命题事实（去重，保序）
    localTheorems   : Map<String, FunDecl>         块内局部定理表
    muts            : Set<String>                  可变变量名集
    refs            : Set<String>                  引用别名变量名集
    children        : List<Frame>                  子帧列表
    used            : Set<String>                  已使用变量名集
    audited         : Map<String, String>          未使用审计目标（名 → 声明位置）
⟩
```

帧构造时自动注册为父帧的子帧。

### 2.2 事实的可见性方向

```
allFacts(F) = allFacts(F.parent) ++ F.facts        （F.parent 为空时为空列表）
```

**方向是自下而上**：子帧读取父链的全部事实，父帧**不**主动读取子帧的事实。

事实集使用去重且保插入序的集合结构，使事实成员判定为常数时间。

### 2.3 变量查找

```
lookupVar(F, n) = F.vars[n]  若存在
                = lookupVar(F.parent, n)  否则
                = 未绑定  若父链耗尽
```

未绑定的名字报 `E-UNBOUND-NAME`。

### 2.4 可变性与引用标记

```
isMut(F, n) = n ∈ F.muts ∨ isMut(F.parent, n)
isRef(F, n) = n ∈ F.refs ∨ isRef(F.parent, n)
```

二者沿父链判定，因此外层声明的可变性在内层可见。

### 2.5 使用标记的上溢

```
markUsed(F, n)：n ∈ F.used，且 markUsed(F.parent, n)
```

使用标记**沿父链上溢**：子作用域用到即算外层用过。这是未使用审计（`W-UNUSED`）的判据基础。

### 2.6 注入操作

```
────────────────────────────────────────  (G-INJECT)
inject(F, p) = F.facts ∪ {p}      当 p ≠ ⊤
             = F.facts            当 p = ⊤
```

**`⊤` 不被注入**：恒真命题没有信息量，注入它只会膨胀事实集。

### 2.7 未使用审计

带非空位置信息的声明进入审计目标集；`when` 的模式绑定、lambda 形参等传空位置，跳过审计。审计范围是本帧及其**整棵子树**：

```
auditedDecls(F) = ⋃ { f.audited | f ∈ subtree(F) }
```

审计目标未被 `markUsed` 标记时报 `W-UNUSED`。

## 3. 作用域

### 3.1 作用域创建点

| 创建点 | 父帧 | 事实回溢 |
|---|---|---|
| 函数体 | 无（独立顶层帧） | 不适用 |
| 块表达式 `{ … }` | 当前帧 | **回溢** |
| lambda | 当前帧 | **不回溢**（隔离） |
| `when` 分支 | 当前帧 | 不回溢 |
| `if` 分支 | 当前帧 | 不回溢 |
| 模块 | 独立的检查器实例 | 通过可见路径与全局符号表交互 |

### 3.2 函数体帧

```
检查 fun f(…) { body } 时
────────────────────────────────────────  (G-FUN-FRAME)
创建 F₀ = Frame(null)，作为 body 的顶层帧
```

函数体帧没有父帧。这一设计的后果：**函数体看不见调用点的任何事实**。函数所需的一切前提必须通过上文（`preps`）显式声明——这正是上下文系统的核心纪律。

### 3.3 块帧与事实回溢

```
F 是当前帧
────────────────────────────────────────  (G-BLOCK)
创建 F′ = Frame(F)，在其中检查块内语句
块检查结束后：∀p ∈ F′.facts，inject(F, p)
```

**块内产生的事实回溢到父帧。**这就是「弥散」的字面含义：块内证明的东西，出了块仍然可用。

```subl
fun f(n : Nat) : Null {
    {
        ∴ n ≥ 0            // 块内注入 n ≥ 0
    }
    ∴ n ≥ 0                // 块外仍可证：事实已回溢
}
```

回溢的时机是**块的语句全部检查完毕之后、尾表达式检查之前**。因此尾表达式可以看到块内语句产生的事实。

### 3.4 lambda 帧的隔离

```
F 是当前帧
────────────────────────────────────────  (G-LAMBDA)
创建 F′ = Frame(F)，在其中检查 lambda 体
体检查结束后：F′.facts 不回溢
```

lambda 帧**隔离**：其内部产生的事实不外泄。理由：lambda 是值，其求值时机与次数不受定义点控制；若允许事实外泄，则「lambda 体内证明的命题」会被当作定义点的事实使用，破坏健全性。

**唯一的例外**：纯 lambda 的纯度命题注入**外层帧**：

```
lambda 体内无不纯调用
────────────────────────────────────────  (G-LAMBDA-PURE)
inject(F, pure<λ>)        λ 是 lambda 表达式本身
```

这使 `pure<{ 1 + 1 }>` 可被证明（第四卷 §1.4）。

lambda 帧可以**读取**父链的事实（`allFacts` 方向向上），只是不向外**写**。

### 3.5 分支帧

`if` 与 `when` 的每个分支创建独立子帧，分支内的事实**不回溢**。理由：分支事实只在该分支条件下成立，出了分支条件不再保证。

分支的**共同结论**通过命题层语句（第四卷 §6.2、§6.3）提取并注入外层，这是分支信息外泄的唯一合法通道。

### 3.6 局部定理的作用域

块内的 `fun` 声明登记为**局部定理**（第四卷 §6.6）：

```
localTheorems(F′) 在 F′ 及其子帧可见
```

局部定理不随事实回溢到父帧——它是定理表的条目，不是事实集的条目。

## 4. 自然命题

**自然命题**是编译器自动规定与赋予的命题，用户不需要手写。

### 4.1 注入规则全集

下表列出全部注入点。每条规则的形式是「触发点 → 注入的命题」。

**函数签名层**：

| 触发点 | 注入命题 |
|---|---|
| 形参声明 `x : τ` | `x : τ` |
| 形参类型为 `Nat` | `x ≥ 0` |
| 形参类型为携带伴生命题的结构体 | 伴生命题，其中字段引用替换为 `x.字段` 形态 |
| 函数上文 `<preps>` | `preps`，经 `$n`／`this` 内联改写后注入 |
| 方法体的 `self` | `self : SelfType` |
| impl 方法体内的字段裸名 | `字段名 = self.字段名` |
| impl 方法体内的字段类型 | `字段名 : 字段类型` |
| 字段类型为 `Nat` | `字段名 ≥ 0` |
| 结构体的伴生命题（方法体内） | 伴生命题，字段以裸名形态出现 |

**变量声明层**：

| 触发点 | 注入命题 |
|---|---|
| `var x = e`，`e` 是纯值，`x` 非可变、非引用、非可变结构体类型 | `x = e` |
| `var x : τ = e` | `x : τ` |
| `var x = e` 且 `τ = Nat` | `x ≥ 0` |
| `var x = S(a₁…aₖ)`（结构体构造） | `x.字段ᵢ = aᵢ`（逐个），以及 `S` 的伴生命题 |
| `@mut var x = e` | **不注入** `x = e`（仅保留自反） |
| `@ref var x = e` | **不注入** `x = e` |

**表达式层**：

| 触发点 | 注入命题 |
|---|---|
| 整数字面量 `n` | `n ≥ 0` |
| 纯 lambda | `pure<λ>` |
| lambda 的函数类型携带上下文 `<C>` | `C` 注入 lambda 体帧 |

**调用层**：

| 触发点 | 注入命题 |
|---|---|
| 调用 `f(a₁…aₖ)` 成功 | 伴生记录 `PAtom(f, [a₁…aₖ])` |
| 调用 `f(a₁…aₖ)` 成功且 `f` 有下文 | `f` 的各下文，经 `$` → 调用表达式、`$n` → 实参、`this` → 函数名替换后注入调用点帧 |

**符号收集层**（全局）：

| 触发点 | 注入位置 |
|---|---|
| 函数未标注 `@impure` | 全局事实集注入 `pure<f>` |
| 函数标注 `@async` | 全局事实集注入 `async<f>` |

### 4.2 变量声明的注入条件

`var x = e` 注入等式 `x = e` 的条件必须全部满足：

```
e 是纯表达式（不含 @impure 调用）
x 未标注 @mut
x 未标注 @ref
x 的类型不是可变结构体类型
────────────────────────────────────────  (G-VAR-EQ)
inject(F, x = e)
```

任一条件不满足则**不注入等式**。理由见第四卷 §1.3 与第六卷 §3：可变值与不纯表达式的等式保不住。

### 4.3 自然数非负

每个 `Nat` 类型的实体恒有自然命题 `≥ 0`：

```
τ = Nat     x : τ
────────────────────────────────────────  (G-NAT-NONNEG)
inject(F, x ≥ 0)
```

适用于形参、变量、字段、整数字面量。注入时发 `D-NAT-PROP` 补充级诊断。

### 4.4 示例

```subl
var n = 0
```

编译器为当前上下文自动注入：

```
n : Nat
n = 0
n ≥ 0
```

```subl
fun demo(n : Nat, m : Nat) : Null {
    ∴ n ≥ 0          // 自然命题：Nat 形参自动有 n ≥ 0
    ∴ m ≥ 0
}
```

### 4.5 结构体伴生命题

不仅函数可以携带命题，结构体也可以携带它的**伴生命题**：

```subl
struct A(n : Nat) <n > 0>
```

**构造时必须证明**：

```
Γ ⊢ (n > 0)[n := e]
────────────────────────────────────────  (G-STRUCT-PROP)
Γ ⊢ A(e) : A        并注入 A 的伴生命题（字段替换为实参）
```

需要证明 `A(1).n > 0` 才能构造 `A(1)`。证不出报 `E-STRUCT-PROP-UNPROVEN`。

**结构体作为函数参数时自动注入伴生命题**：

```subl
fun f(a : A) {
    // 此处 Γ 含 a.n > 0
}
```

### 4.6 区间事实

数学记号区间注入的事实可以驱动推理：

```subl
axiom n ∈ (0..30)     // 把区间事实注入 Γ
∴ n ≥ 0                          // 命中定理 rangeLowerBound
```

常量区间成员判定是自动证明的独立通道：

```
n、lo、hi 均为整数字面量
────────────────────────────────────────  (G-RANGE-CONST)
⊢ n ∈ (lo..hi)  当且仅当  lo ≤ n ≤ hi
```

## 5. 函数的上文与下文

### 5.1 签名形态

```
fun 函数名[理论参数](实际参数)<上文> : 返回类型<下文>
```

| 部分 | 名称 | 语义 |
|---|---|---|
| `[理论参数]` | 理论参数 | 类型参数与理论命题参数 |
| `(实际参数)` | 实际参数 | 表达式层面的形参 |
| `<上文>` | 上文（前置，`preps`） | 函数调用**需要的**命题 |
| `<下文>` | 下文（后置，`posts`） | 函数调用后**为后面注入的**命题 |

**上文一般不显式传入，但允许。**

### 5.2 理论参数

理论参数分两类：

- **类型参数**：用单大写字母表示（`T`）；
- **理论命题参数**：用小写字母表示（如 `p`）；其全称量词写作 `∀@p`（`@` 前缀在量词里标记命题参数，以与值参数区分）。

具有理论命题参数的函数叫**超越函数**。

### 5.3 调用形态

```subl
f[Nat, p](91, "abc")<a = 0>
```

对于非超越函数，类型参数和上文参数**一般不需要写出来**，编译器会自动推导：

- 编译器自动推理函数的类型参数；
- 同时自动为函数注入当前上下文中它需要的上文。

**需要显式标注的三种情况**：

1. 是超越函数；
2. 无法推导类型参数；
3. 无法自动注入上文。

### 5.4 上文的检查

```
调用点：f(a₁…aₖ)     f 的上文为 [p₁…pₘ]
────────────────────────────────────────  (G-PRE)
① 对每个 pⱼ 执行内联改写（§7）：$n → 形参名，this → 函数名
② 代入命题参数绑定、类型替换、实参环境
③ 要求 Γ ⊢ pⱼ[aᵢ/xᵢ]
```

任一条上文证不出报 `E-PRE-UNPROVEN`。

### 5.5 下文的注入

```
调用点：e = f(a₁…aₖ)     f 的下文为 [q₁…qₙ]     上文检查已通过
────────────────────────────────────────  (G-POST-INJECT)
∀i. inject(F, qᵢ[$ := e, $n := aₙ, this := f])
```

**下文在调用点直接注入，不经验证**——下文是被调函数的**保证**，不是调用点的义务。

### 5.6 下文的验证

下文的验证发生在**函数声明处**：

```
fun f(…) : τ <posts> { body }
────────────────────────────────────────  (G-POST-CHECK)
检查 body 结束时的帧 F′，要求 F′.allFacts() ⊢ postⱼ（经内联改写）
```

证不出报 `E-POST-UNPROVEN`。

这就是「**函数体是证明义务**」：函数声明不是可信公理，体结束时 Γ 必须蕴含下文。逃生门只有 `axiom`。

### 5.7 @axiom 函数

标注 `@axiom` 的函数，其**下文签名即公理**，不做自动证明：

```
"axiom" ∈ f.annotations
────────────────────────────────────────  (G-AXIOM-FUN)
免除 f 的下文验证义务      发 D-AXIOM-POST
```

### 5.8 函数值的上下文

函数**类型**也可以携带上下文：

```
FunType(params, ret, purity, theory, context)
```

书写形式：

```subl
(Nat) <n > 0> => Null
```

调用携带上下文的函数值时，上下文命题必须可证，否则报 `E-CTX-UNPROVEN`。lambda 的期望类型携带上下文时，上下文命题注入 lambda 体帧。

## 6. 伴生命题

### 6.1 定义

在上下文中，函数会自动生成一个**同名命题**，这个命题是函数的**伴生命题**。

**规定：从伴生命题可以推出函数的下文。**

```subl
fun f() : <p>
```

函数 `f` 的伴生命题是 `f<>`，规定 `f<> → p`。

### 6.2 三个身份

| 对象 | 名称 | 作用 |
|---|---|---|
| `f` | 函数的本体 | `f` 是个表达式，上例中 `f` 的类型是 `() => <p>` |
| `f()` | 函数的调用返回值 | `f()` 是函数的返回值，也是表达式，上例中是 `Null` |
| `f<>` | 函数的伴生命题 | `f<>` 是一个命题，规定 `f<> → p` |

`f(91, "abc")` 的伴生命题是 `f<91, "abc">`。

### 6.3 伴生命题的推理规则

```
────────────────────────────────────────  (G-COMPANION)
f<a₁…aₖ> → (⋀ posts[f])
```

其中 `posts[f]` 是 `f` 的下文列表，经内联改写（实参代入）。

### 6.4 伴生命题的用途

伴生命题有两个用途：

**其一，推出下文。**调用 `f` 后，即使下文注入机制不适用（例如 `f` 是超越函数、或调用发生在命题位），也可以由伴生记录推出下文。

**其二，证明「参数被调用过」。**`f<a>` 本身是一个关于调用行为的事实，可以作为推理的前提。

### 6.5 伴生记录的注入

```
调用 f(a₁…aₖ) 成功
────────────────────────────────────────  (G-COMPANION-INJECT)
inject(F, PAtom(f, [a₁…aₖ]))
```

伴生记录与下文注入在同一点发生。

### 6.6 伴生命题与定理搜索

定理函数的伴生命题是定理搜索的入口。例如排中律：

```subl
@theorem
fun `law of excluded middle`[p] : Null <p ∨ ¬<p>>
```

其伴生命题 `` `law of excluded middle`<p> `` 满足：

```
∀@p . `law of excluded middle`<p> → (p ∨ ¬<p>)
```

与其自然全称命题组合即得 `∀@p . p ∨ ¬<p>`（第四卷 §7.4）。

## 7. 内联标识

### 7.1 内联标识的种类

常见的内联标识：

| 标识 | 指代 | 出现位置 |
|---|---|---|
| 参数名称 | 形参本身 | 上文、下文 |
| `$n` | 第 `n` 个形参（从 1 计数） | 上文、下文 |
| `$` | 函数返回值 | 下文 |
| `this` | 函数本体 | 上文、下文 |
| `self` | 结构体本体 | impl 方法的上文、下文 |
| 结构体的属性名称 | 字段 | impl 方法的上文、下文、伴生命题 |

### 7.2 `$n` 的改写

```
$n 出现在具名函数的上文或下文中
────────────────────────────────────────  (G-DOLLAR-N)
声明期统一改写为第 n 个形参的名字      发 H-PARAM-REF 提示
```

限制：

- `n` 越界报 `E-PARAM-REF`；
- `$n` 在**函数体内**使用是错误，报 `E-PARAM-REF-IN-BODY`。

### 7.3 `$` 的解法

`$` 指代函数返回值。其解法按优先级：

```
① 块里有唯一一处带值的显式 return e    →  $ := e
② 否则取尾表达式                        →  $ := 尾表达式
③ 都没有                                →  $ := null
```

**多路 return 的处理**（`if`／`else` 各返回一个）无法归一为单一项，此时保守取 `null`，让后件核对**显式失败**——**不猜测**。猜测会产生「看似通过实则错误」的证明。

在**调用点**注入下文时，`$` 替换为调用表达式本身：

```
调用 e = f(a)，f 的下文含 $ ≥ 0
────────────────────────────────────────  (G-DOLLAR-CALL)
注入 f(a) ≥ 0
```

在**函数体内**，`$` 等价于末表达式。

### 7.4 `this` 的改写

```
this 出现在函数签名（上文／下文）中
────────────────────────────────────────  (G-THIS)
改写为函数名
```

### 7.5 `self` 的内联

`self` 指代结构体本体。在 impl 方法中：

```subl
impl F for A {
    fun f() : <p<self>> { … }
}
```

此时有一个类型为 `A` 的变量 `a`：

```subl
a.f()        // 证明命题 p<a>，这里 self 被内联成 a 了
```

```
调用点 r.f()，f 的下文含 self
────────────────────────────────────────  (G-SELF)
注入时 self := r
```

### 7.6 字段裸名

impl 方法体内可以裸用字段名（`name` ≡ `self.name`）。相应地，方法体帧注入：

```
inject(F, 字段名 = self.字段名)
inject(F, 字段名 : 字段类型)
```

因此伴生命题中的字段引用在方法体内以裸名形态出现，在调用点则以 `接收者.字段名` 形态出现。二者的对应由 §7.5 的 `self` 内联保证。

形参可以遮蔽字段，此时发 `H-FIELD-SHADOW` 提示。

### 7.7 内联改写的执行时机

| 标识 | 改写时机 |
|---|---|
| `$n` | 声明期（函数声明被检查时） |
| `this` | 声明期 |
| `$` | 声明期解为末表达式；调用点解为调用表达式 |
| `self` | 调用点 |
| 字段裸名 | 方法体检查时注入等式事实 |

## 8. 供给

### 8.1 供给的定义

**供给**（supply）是调用点向上文与命题参数提供证据的机制。有两种形态。

### 8.2 自动供给

从 Γ 中检索匹配的命题：

```
Γ 中存在唯一候选 p，且 p 与所需命题匹配
────────────────────────────────────────  (G-SUPPLY-AUTO)
供给成功

Γ 中无候选
────────────────────────────────────────  (G-SUPPLY-UNBOUND)
E-PROP-UNBOUND

Γ 中有多个候选且无法区分
────────────────────────────────────────  (G-SUPPLY-AMBIG)
E-PROP-AMBIGUOUS
```

**自动供给只考虑零元候选**（无参数的裸命题原子）。以下结构性原子**被排除**在候选之外：

```
排除集 = { =, ==, !=, <, >, <=, >=, $, :, __call__, __inst__, __t__ }
```

理由：等式与类型事实是推理的材料，不是可「供给」的弥散命题。

**全称命题的自动实例化**：若上下文里有 `∀n . tagged<n>`，需要 `tagged<7>` 时编译器自动合一供给。

### 8.3 显式供给

用尖括号显式提供：

```subl
fun witness[@q]<q> : Null {}

witness<tagged<7>>()        // 把命题 tagged<7> 供给给 @q
```

尖括号 `<>` 在调用位兼任三种职责：类型实参、命题供给、命题项。区分依据是被调函数的签名中对应位置的理论参数种类。

### 8.4 超越函数

带理论命题参数的函数是超越函数，编译器**无法自动推断**其命题参数，调用点必须显式供给。

## 9. 关键表达式池

### 9.1 定义

自动证明器沿**关键表达式**工作。关键表达式池 `K` 的构造规则见第四卷 §5.7。本节规定其在上下文系统中的地位。

### 9.2 收集范围

```
K = groundTerms(F.allFacts()) ∪ groundTerms(目标)
```

`groundTerms` 对命题做后序遍历，收集全部子表达式：**优先内、其次外**。

对 `print(1 + 2)`，收集到：

```
print(1 + 2),  1 + 2,  1,  2
```

### 9.3 池的固定性

关键池**一次性收集，此后固定**，不随新增事实扩张。

理由：若随事实扩张，复合项会自我增殖（`(1+2)` → `(1+2)+(2+1)` → …），导致笛卡尔爆炸且永不达不动点。

### 9.4 目标项的地位

```
closure(Γ, extraGoals, termSource)
```

`extraGoals`（目标命题）的项**只贡献实例化候选，不作为事实加入 Γ**。

否则目标会平凡可证，破坏健全性。这是第四卷不变量 I-1 的关键保障之一。

### 9.5 纯度对池的影响

含不纯调用的表达式**仍在池中**（它们是关键表达式），但其**比较命题不走结构相等通道**（第四卷 §1.3）。池的成员资格与推理资格是两个独立的问题。

## 10. 上下文与可变性的边界

### 10.1 基本态度

上下文系统对引用变量与可变变量的态度一致：**都是半死不活的**。不可判定的特性不进上下文系统——上下文系统是给函数式风格用的。

### 10.2 不注入的情形

| 实体 | 不注入的事实 | 保留的事实 |
|---|---|---|
| `@mut var x = e` | `x = e` | `x : τ`、自反 `x = x` |
| `@ref var x = e` | `x = e` | `x : τ` |
| 可变结构体类型的变量 | 字段等式 | 类型归属 |
| 含不纯调用的表达式 | 一切比较命题（含自反） | 显式注入的事实 |

理由：可变变量的值会变，绑定等式保不住；不纯表达式的值不确定，结构相等没有意义。

### 10.3 建议的做法

若真的想让可变变量配合上下文系统，建议：

- 直接写一个新的不可变变量赋值它；
- 或使用 `let` 类函数。

**证明不可变的最好办法，就是让编译器看见你亲自把可变性割掉**：

```subl
@mut var m = 5
m = m + 1
var snapshot = m        // 冻结：snapshot 是不可变的，其等式可注入
∴ snapshot = 6
```

详细规则见第六卷。

# 标准库总览（core/）
卷：工程 · 主题域：标准库 core/ 的目录布局、模块形态（目录即模块）与引用方式（mount 挂载 / 脚本自足）
事实来源：_facts/_langfacts.md + core/ 实际目录树与全部 .settings 内容（本会话抽取）+ 抽读 core/logic/logic.subl、core/collection/list.subl、core/async/async.subl 等头部；模块机制引自 compiler/src/main/kotlin/sugared/functor/checker/ModuleTree.kt

> **路径勘误**（相对本系列早期条目）：Result 与 typeclass **不在** core/logic 下，而在 **core/collection**；mutex / flow 也不是 core 下的独立模块，而在 **core/async** 内。本文一律以 core/ 实际目录为准。

## 语法

### 目录布局（事实清单）

core/ 是"包目录"：只含子包目录、不含直接的 .subl 文件。每个子目录是一个模块，内有一个与目录同名的 `.settings` 文件与若干 `.subl` 源文件：

| 模块 | .subl 文件 | .settings 声明的挂载 | 内容（据文件头注释） |
|---|---|---|---|
| core/collection | list / map / optional / result / set / tuple / typeclass | 无（叶子） | List/Optional/Result/Set/Map/Tuple + 类型类 Functor/Foldable/Monad，同模块互见 |
| core/math | math | 无（叶子） | Nat 算术工具（gcd/lcm）+ Math 系 @root 内建（mathMin/mathSin…）+ sqrt |
| core/logic | logic | mount core.math | 命题演算/等式推理/量词 @theorem 定理（refl/sym/trans/modus ponens…） |
| core/classic | classic | mount core.logic | 经典逻辑定理（tertiumNonDatur/doubleNegation/contraposition），声明带 @classic |
| core/async | async / channel / flow / mutex / task | mount core.collection | 异步内建运行时层：Task/Flow/Mutex/Channel + runBoth/runSeq/delay 等 |
| core/io | io | mount core.collection | IO 内建声明（readFile/writeFile/readLine 返回 Result，决策 81） |
| core/json | json | mount core.collection | JSON 内建声明（Optional/List） |
| core/net | net | mount core.collection | 网络内建**占位**（叶子声明） |
| core/real | real | mount core.collection | Rat 浮点内建（toRat/abs/floor/pow/parseRat…） |
| core/regex | regex | mount core.collection | 正则内建占位（List/Optional） |
| core/string | string | mount core.collection | 字符串内建（strSplit 返回 List[Str]） |
| core/number | num | 无 | 数值类型类（Num 标记约束） |
| core/random | random | 无（叶子） | 随机数内建声明 |
| core/time | time | 无（叶子） | 时间内建声明 |
| core/encoding | encoding | 无（叶子） | 编码内建**占位** |

依赖图（由 .settings 实际挂载关系汇总）：`math ← logic ← classic`，`collection ← {async, io, json, net, real, regex, string}`，其余为叶子。

### settings 文件语法

```
# <模块名>.settings（模块名 = 目录名；根模块无 settings，P0 限制）
# 逐行一条指令，只支持 mount；忽略空行与 # 注释
mount <从根起的路径> [as <别名>]
```

路径两种等价写法：斜杠形 `mount core/math` 与点分完整包名形 `mount core.math`（ModuleTree.kt:139 归一化）。

### 引用方式

- **工程模式（.subl 工程）**：语言**没有源码级 import 语句**（Parser.kt 中无 import 语法；旧文档把 import 列为语句种类，与实现不符，**待核**）。跨模块引用一律通过 settings 的 mount：挂载后可用裸名（`gcd(48, 18)`）或限定名（`core.math.gcd(48, 18)`、`math.gcd(...)`）。
- **脚本模式（.subs）**：单文件自足，顶层语句直接执行，无 main 入口，不写 mount。

## 语义

### 目录即模块

每个目录（含根 `/`）是一个模块；同模块内所有 .subl 文件**共享一个 Symbols**——core/collection 的 7 个 .subl 互相直接可见，list.subl 直接用 typeclass 声明的 Functor，optional.subl 直接引用 result 的 Result，无需任何挂载声明。

### 挂载语义（ModuleTree.kt）

- **传递闭包（"收编即全收"）**：挂载 T 则 T 自身挂载的一切也一并可达。core/classic 挂 core.logic，logic 挂 core.math → classic 内裸名 gcd 可用。
- **只向下流淌**：祖先的挂载对后代可见；后代的挂载对祖先不可见；**兄弟模块互不可见**（M3 约束）。
- **完整包名展开**：`mount core.math` 时前缀包 core 也被隐式挂载（本地名未被占用时），故 `core.math.gcd(...)` 与 `math.gcd(...)` 等价。
- **core 隐式挂载（决策 78，用户拍板 B）**：凡 core 包形态的 <根>/core/（或 <根>/test/core/ 嫁接）会被注入到**所有非 core 自身**的模块——自动追加 `mount core` 及全部子包。因此用户工程里 `List/Ok/Err/size/filter` 等裸名默认可用（Kotlin 默认导入语义）；本地同名子目录/别名优先，仅跳过对应子包。
- **挂载图校验**：链成环 → E-CIRCULAR-MOUNT；settings 语法错 → E-PARSE-SETTINGS；挂载目标不存在 → E-UNBOUND-NAME；本地名与挂载名冲突 → E-DUP-DECL。

### 模块边界（修正先前条目的认知）

- **core/logic 是纯定理模块**：只含 @theorem 无体函数（签名即定理，编译期擦除为 Null），供 ∴ 与证明位做结构合一搜索；**容器与类型类全在 core/collection**。
- **core/classic 是逻辑层**：依赖 logic；注意其"挂载经典逻辑"的机制是 **@classic 注解**——任一声明标注 @classic 即置 classicMounted，使排中律等前置可用（Symbols.kt:187 / Diffusion.kt:255），不是仅靠 mount 生效。
- **core/async 是异步统一模块**：Task（内建语法 `Task { … }`，start/join/isAlive）、Flow（`Flow { emit(v); … }` 冷流，collect/map，emit 仅 Flow 体内合法，codegen 译为 yield）、Mutex（`Mutex()` + withLock）、Channel（`Channel[T](n)` 有缓冲通道，send/receive/close，FIFO）。异步内建均 @impure @async @root，调用点由 codegen 编译期特判翻译。
- **JS 侧名字**：模块路径 mangle 为前缀，如 core/collection 的 size → `core_collection__size`；根模块符号无前缀。

### 脚本模式语义

每个 .subs 文件由解释器独立执行（parse → 注入 @host 声明 → Checker → Evaluator）：顶层语句直接运行、无需 main；**多个脚本互不共享声明、互不可见**；core/ 全树 .subl 由运行时作为 stdlib 预relude 注入（Interpreter 的 stdlibDir，默认工作目录下的 core/），宿主函数表提供脚本态内建——脚本**不需要也不支持** mount。

## 示例

工程目录结构：

```
myapp/
  myapp.settings
  main.subl
```

myapp.settings（core 已被隐式挂载，下面两行是显式示例）：

```
mount core.math
mount core.async as a
```

main.subl——裸名 / 限定名并用：

```
fun main(): Null {
    var xs: List[Nat] = range(1, 6)
    print(size(xs))
    print(gcd(48, 18))
    print(core.math.sqrt(16.0))
    var ys: List[Nat] = map(xs) { x => x * 2 }
    print(size(ys))
    return
}
```

core.collection 的类型类与错误容器（标准用法；修正文法 => / →）：

```
// 类型类方法糖与自由式同路由：xs.map(f) 等价 map(xs, f)
var doubled: List[Nat] = listOf(1, 2, 3).map { x => x + 1 }

// Optional：空安全容器（Some/None），when 解构取值
var m: Optional[Nat] = parseRat("x")
var v: Rat = when(m) {
    is Some(r) => r
    None => 0.0
}

// Result：Ok/Err；二阶类型 (T, E) 无 Functor 实例——走 mapOk/mapErr/flatMapOk
var ok: Result[Nat, Str] = Ok(7)
var s: Result[Str, Str] = mapOk(ok) { n => toStr(n) }
print(unwrapOr(s, "(err)"))
```

core.async 的任务与冷流（异步内建在同步上下文需 unchecked 放行）：

```
fun main(): Null {
    unchecked runBoth({ => print("先启") }, { => print("主路径") })
    var fl = Flow {
        emit(1)
        emit(2)
    }
    unchecked collectToList(fl)
    return
}
```

脚本模式单文件自足（hello.subs，直接 `run-script hello.subs`）：

```
var xs = listOf(1, 2, 3)
print(size(xs))
print(unwrapOr(parseRat("2.5"), 0.0))
print(sqrt(9.0))
```

## 陷阱

1. **路径记忆坑**：Result/typeclass 在 core/collection 而非 core/logic；mutex/flow/task/channel 在 core/async 而非 core 顶层。langfacts 旧一句"core/：logic（list/set/map/optional/result/typeclass/real…）"是错误残留，已被实际目录推翻（本文修正）。
2. **core/number 的 settings 名不合规**：目录是 number，文件却是 num.settings / num.subl；按"settings 名 = 目录名"约定（ModuleTree.kt:15）该 settings 实际不会被加载（其内容本就无挂载，暂无影响）——**待核**是否刻意。
3. **没有 import 语句**：旧文法陈述把 import 列为语句种类，但当前 Parser 无此语法；在 .subl 里写 import 会按表达式/调用解析报错。跨模块一律用 .settings 挂载。
4. **根模块无 settings**：想把根级 .subl 与 core 的挂载关系写到根 settings 是行不通的（P0 限制）；且 core 本来就隐式挂载。
5. **兄弟模块互不可见、挂载不向上流淌**：a 与 b 同级，a mount 了 lib，b 里看不到 lib；b 挂的 lib 也漏不到 a。需要共享就提到共同祖先挂载，或各自声明。
6. **不要写环形挂载**：A 挂 B、B 挂 A 直接 E-CIRCULAR-MOUNT；core 自身与子包不被注入隐式自挂正是为此。
7. **同名覆盖**：隐式/传递挂载按目录名注入，本地子目录名优先——自己模块下有 math/ 子目录时，挂载的 core.math 会被跳过，裸名 math 解析到自己的子目录。
8. **Result 不走类型类**：Result[T, E] 是二阶类型，Functor/Foldable 的 F[_] 一阶 kind 套不上——用 mapOk/flatMapOk/mapErr，别找 Result 的 Functor 实例。Set 有 Functor 实例（typeclass.subl 头注），Optional 三类型类实例齐全。
9. **异步内建受上下文闸门**：Task.join 在同步上下文报 E-NEED-ASYNC；未 start 就 join 报 E-NOT-STARTED；runBoth/collectToList 等 @impure @async 在纯函数里调用需 unchecked 放行。
10. **脚本之间不共享**：把公共函数放进 a.subs 指望 b.subs 调用会失败（每个 .subs 独立注入、互不可见）；公共代码请用工程模式（目录即模块，共享 Symbols）。
11. **宿主/编译差异**：real 包注释明确 sqrt 仅脚本模式可用（宿主函数表注入 @host 声明，编译模式尚未落地 JS 特判）——同一段代码在 run-script 与 compile 下行为可能不同，跨模式前对齐内建覆盖面（**待核**其余 @root 的模式差异）。
12. **io/net/encoding/regex 是占位/声明式模块**：.subl 里多为 @root 签名（签名即文档，调用点特判翻译），别期待里面有 Kotlin 式的完整实现体。

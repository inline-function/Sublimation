# 03 · 证明 —— by（断言）

> **一句话**：t30（用户决定「by 只有委托的意思」）之后，命题位的 by 只剩下**后缀断言式**「expr by [q]」——值与类型同 expr，同时声明「q 在此位成立」；编译器把它当**证明义务**（proveOrDeep 核对，证不出报 E-CANNOT-PROVE），**不再免验证注入 Γ**。要无条件信任的命题请用 **axiom 语句**。

## t30 变更速览（旧语义已废除）

| 形态 | 旧语义（已废除） | 新语义（t30） |
|---|---|---|
| 语句式 ``by [q₁, q₂]`` | 命题直接注入 Γ，免验证，发 D-BY | **编译期错误 E-BY-REMOVED**（Parser 仍解析以便给带迁移指引的诊断）；改用 ``axiom q`` 语句（顶层/函数内通用） |
| 后缀式 ``expr by [q]`` | props 注入 Γ，免验证 | **断言**：值/类型 = expr 的值/类型；props 延迟到包围语句/绑定完成后经 proveOrDeep 核对，证不出报 E-CANNOT-PROVE，**不注入 Γ** |
| ``impl C for T by field`` | 委托语法糖 | **不变**（v3.0 特性 2，ImplCheck.kt）——这是 by 现在的**主语义** |

废除的动机：旧 by 与 axiom 同构（都 ``f.inject`` 免验证入 Γ），等于在 axiom 之外开了第二条逃逸口（boring doc/形式化语义02 §「直接供给通道」）；用户决定收口——**免验证供给只留 axiom 一个入口**，by 语义统一为「委托」（impl 位）与「断言」（表达式位）。

## 语法

```subl
expr by [q]                     // 后缀断言式：断言 q 成立，表达式值 = expr 的值
f(x) + 1 by [q1, q2]            // 目标可为任意表达式（左结合先并 f(x)+1）
```

```subl
by [q]                          // ✗ 语句式已移除（E-BY-REMOVED）；迁移：axiom q
```

**词法**：「by」 是保留关键字（Lexer.kt:43 「"by" to Kind.BY」），不能当变量名用。

**两种入口**：

| 形态 | 解析入口 | AST |
|---|---|---|
| 语句式（已移除，仍解析） | parseStmt 见 BY 即 「pos++; ByStmt(parseBracketList())」（Parser.kt:652） | ByStmt(props)（Ast.kt:259）——Checker 报 E-BY-REMOVED |
| 后缀式 | parseExpr 中缀循环：「if (t.kind == Kind.BY) { pos++; left = ByExpr(left, parseBracketList()); continue }」（Parser.kt:1027） | ByExpr(target, props)（Ast.kt:436） |

**命题列表文法**（parseBracketList，Parser.kt:1657-1673，与 axiom 语句共用）：

```ebnf
G-30  中缀位  ::= ... | "by" "[" 命题列表 "]"                 /* e by [q] 后缀断言 */
```

- 每条命题按完整表达式解析：比较 「k > 0」、蕴含 「p → q」、量词 「∀n. valid<n>」 皆可
- 尾随逗号仅在随后的 「)」/「]」/「}」 前允许（Parser.kt:1665）
- 空列表 「by []」 合法（0 条断言，纯语法噪音）

**优先级**：表达式层全左结合，「by」 是普通中缀位：

- 「1 + 2 by [q]」 ≡ 「(1 + 2) by [q]」（by 接整个左操作数）
- 「a by [q] + 2」 ≡ 「(a by [q]) + 2」
- 需要别的结合顺序一律加括号

**同名异物**：「impl C for T by field」 里的 「by」 是**委托语法糖**（v3.0 特性 2，ImplCheck.kt:36/296），要求 by 后跟字段名（IDENT），与命题位毫无关系；两条解析路径互不干扰（委托 Parser.kt:969-978 vs 后缀 :1027）。

## 语义：断言（证明义务）

后缀式检查（Checker.kt，ByExpr 分支 + checkStmt 包裹的 flushByAsserts）：

```kotlin
is ByExpr -> {
    val t = checkExpr(e.target, f, pure)          // ① 先查目标，得类型 t（类型透明）
    if (e.props.isNotEmpty()) pendingByAsserts += e.props to e.pos   // ② 挂入待核队列
    t                                            // ③ 表达式类型 = 目标类型
}
// checkStmt(...){ checkStmtInner(...); flushByAsserts(f) }——语句检查完（名字绑定、
// 自然命题/等式注入就绪）后，逐条 proveOrDeep(f.allFacts(), q) 核对：
//   证不出 → d.error("E-CANNOT-PROVE", ..., "by 断言 ... 证不出 ... 请改用 axiom 语句")
```

判断式（与 boring doc/形式化语义02 同义）：

$$\frac{\Gamma \vdash q_1 \quad \cdots \quad \Gamma \vdash q_n}{\Gamma \vdash \text{expr by } [q_1,\dots,q_n] : T} \quad (\text{R-BY-ASSERT})$$

- **核对延迟到绑定之后**：队列在包围语句/函数体检查完成时统一清空（flushByAsserts，checkStmt 末尾与 checkFun 体检查后）。设计目的：让 ``var r = e by [断言 r]`` 里被声明的 r 在核对时已可见
- **断言不注入 Γ**：能证出的命题本就由 Γ 可推，无需注入；「不信任、要断言」与「信任、要公理」从此是两套机制（by vs axiom）
- **没有 D-BY 留痕了**：旧补充级诊断 D-BY 随免验证注入一并删除（explain 表与诊断参考已同步）
- 平凡命题：「by [⊤]」 的断言平凡可证，等价空操作
- 纯度：「containsImpureCall」 只遍历 ByExpr 的 target（Diffusion.kt:159）——props 属证明层、求值期擦除，不参与纯性判定

### 与 axiom、∴ 的分工（t30 后）

| 机制 | 语法 | 语义 | 失败诊断 |
|---|---|---|---|
| **by 后缀断言** | 「e by [q]」 | 义务：q 须由当前 Γ 证出；值 = e | E-CANNOT-PROVE |
| **axiom 语句** | 「axiom p1, p2」 | 免验证注入 Γ（**唯一逃逸口**）；顶层/函数内通用 | 不验证（信仰式供给，作者负责） |
| ∵∴ 链 | 「∵ form, p ∴ q」 | 义务：前提与结论都要证出，通过后结论注入 Γ | E-PREMISE-UNPROVEN / E-CANNOT-PROVE |
| 裸 ∴ | 「∴ q」 | 义务：验证 q 已证（不注入新事实） | E-CANNOT-PROVE |
| 策略语句 | 「@simp[…]」「@subst[…]」 | 调用证明器去**证**目标 | E-STRATEGY-FAILED |
| unchecked | 「unchecked <语句>」 | 逃逸纯度/可变性闸门，与命题无关 | —— |

「by 断言」与「裸 ∴」同为义务、同走 proveOrDeep；区别只在位形——by 用在**表达式位**（可贴在产生值的表达式上、随绑定一起核对），∴ 用在**语句位**。

### 作用域（帧语义）

- 断言核对用的是**包围语句所在帧** Γ（flushByAsserts 的 f）：函数体内的断言不外泄到调用者（义务本就不产生事实）
- lambda 体里的后缀断言在包围语句的帧核对（lambda 帧隔离，帧内事实不参与）
- 工程模式（.subl）顶层只放行声明：顶层「by [q]」语句式本就报「期望顶层只能写声明」；后缀断言式只能出现在表达式位（如 fun 体）

### 求值与代码生成：运行期零成本

- 解释器：ByExpr → 只求值 target（Evaluator.kt:250），props 完全不参与运行时
- JS 生成：ByExpr → **只留目标值**（JsCodeGen.kt:930「by 后缀擦除」）——断言是编译期义务，运行期擦除得干干净净
- 旧的「// by: q」审计注释随语句式 ByStmt 一并删除（JsCodeGen 的 ByStmt 分支已移除）；要可 grep 审计的命题留痕请用 axiom 语句（产物留 「// axiom: q」）

## 示例

例 1 — 可证断言通过（算术通道）：

```subl
fun main() {
    var x = 1 by [1 == 1]      // 断言恒等式：算术通道可证 → 通过
    print(x)                   // 打印 1
}
```

例 2 — 断言不注入 Γ（与旧语义的本质区别）：

```subl
fun main() {
    var x = 1 by [1 == 1]
    ∴ p                         // ✗ E-CANNOT-PROVE：断言不供给事实，p 仍无依据
}
```

旧语义里 ``by [p]`` 会让 ``∴ p`` 直通——那条「证不出就塞进去」的捷径正是 t30 要废除的。

例 3 — 证不出的断言报错：

```subl
fun main() {
    var r = double(3) by [r == 6]   // ✗ E-CANNOT-PROVE（若 double 的结果等式推不出）
}
```

健全性代价（t30 预期）：VarStmt 不注入初值等式事实，``r = double(3)`` 这条等式不在 Γ，证不出 r == 6。三个出路，按场景选：
- 信它能证、只是自动证明器不够强 → ``var r = double(3)`` 后写 ``axiom r == 6``（免验证供给，作者背书）
- 事实本就在 Γ（算术通道、自然命题、上文弥散）→ 断言照常通过
- 断言只是文档性质 → 删掉（或用注释）

例 4 — 自引用自然命题（延迟核对的用武之地）：

```subl
fun main() {
    var r: Nat = 1 by [r >= 0]  // ✓ r 声明后注入 Nat 自然命题 r ≥ 0，断言可证
}
```

例 5 — 语句式的迁移：

```subl
// ✗ 旧写法（E-BY-REMOVED）
fun f(): Null { by [p] }

// ✓ 迁移：供给公理
fun f(): Null { axiom p }

// ✓ 迁移：断言已证事实
fun f(): Null { ∵ q ∴ p }
```

## 陷阱

**解析类（by 会被“吸走”）**

- ⚠️ **换行吞 by**：换行不是 token（_langfacts §1），「by」 在表达式层是中缀位：
  - 「var x = 5」 换行 「by [q]」 解析为 「var x = 5 by [q]」——断言附着在后缀上（不再有独立语句式）
  - 「axiom p」 换行 「by [q]」 解析为 「axiom (p by [q])」——by 消失进 axiom 的 prop（tag 函数渲染为 「?」）
  - 对策：用 「;」 显断句
- ⚠️ **工程模式顶层禁 by**：「by [q]」 属执行语句，顶层报「期望顶层只能写声明」；脚本模式（.subs）顶层照常（随后由 Checker 报 E-BY-REMOVED）
- ⚠️ 「by」 是硬关键字：「var by = 1」 直接 parse 失败

**语义类**

- ⚠️ **断言不是供给**：by 断言证不出就报错，不会「平掉」任何 E-POST-UNPROVEN/E-PRE-UNPROVEN；要信仰式供给只有 axiom 一个入口
- ⚠️ **props 里的名字不做解析**：「by [r2 == 6]」 中 「r2」 从未定义不单独报警——证不出时以 E-CANNOT-PROVE 体现（断言证不出即失败，错名字也走这条路径）
- ⚠️ **绑定等式的代价**：``var r = 5 by [r == 5]`` 证不出（VarStmt 不注入初值等式）；要么 ``axiom r == 5``，要么断言能由自然命题/算术通道证出的形式
- ⚠️ 后缀断言在 JS 产物里**无留痕**（运行期擦除）；需要可 grep 的命题审计用 axiom 语句

**机制混淆类**

- ❌ 「impl C for T by field」 的 「by」 是委托语法糖（跟字段名），与命题位无关（ImplCheck.kt）
- ⚠️ by 与 axiom 的区别是**信任级别**：axiom = 信任（免验证入 Γ）；by 断言 = 验证（须证出，不入 Γ）
- t30 后「by 只有委托的意思」严格化讨论：命题位的 by 若按字面单义应整体删除；实施取实用折中——保留后缀式作为**断言**（表达式位的证明义务，此前语言空缺），文档如实称其为「断言」而非委托。若用户坚持字面单义，后缀式也可一并删除（Parser 的 ByExpr 分支与 Checker 队列整体移除即可）

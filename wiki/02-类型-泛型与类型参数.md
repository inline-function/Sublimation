# 泛型与类型参数

> 卷：02-类型 · 主题域：泛型（[T] 方括号参数、泛型 fun/struct/enum、实例化、角表）
> 事实来源：_langfacts.md §2/§3/§5；源码 Parser.kt、Ast.kt、Checker.kt、Symbols.kt、TypeInfer.kt、CallCheck.kt、JsCodeGen.kt；core 标准库 collection/optional.subl、collection/typeclass.subl、collection/list.subl（行号为近似定位）

泛型把「类型参数」写进声明的**理论头**（theory）——名字与参数表之间的方括号 `[...]`。凝华的括号分工是本条目的核心线索：**类型位（标注、嵌套应用）用方括号 `[]`，调用位（实例化、供给）用角表 `<>`**。两套括号各自独立解析，互不歧义（Parser.kt:550-552）。

## 语法

### 声明位的方括号

所有可携带理论头的声明（fun / struct / enum / class / type）与两种值形态（匿名函数、多态函数类型）：

```subl
fun id[T](x: T): T = x                        // 泛型函数：头在名字后、参数表前
struct Pair[A, B](first: A, second: B)        // 泛型结构体
enum List[T] { Nil(), Cons(T, List[T]) }      // 泛型枚举（构造子字段可引用 T 与 List[T]）
class Show[T] { fun show(x: T): Str }         // 泛型类型类（成员可为抽象签名）
type Box[a] = Optional[a]                     // 泛型类型别名
fun _[T](a: T): T = a                         // 匿名泛型函数（名省略或写 _，不可被引用）
[T](T) => T                                   // 多态函数类型：[T] 是绑定者，只能修饰函数类型
```

方括号内是**理论参数表**（Ast.kt:95-103），三种形态：

| 形态 | 语法 | AST | 说明 |
|---|---|---|---|
| 类型参数 | `T` / `T: Show` | TypeParam(name, constraint, arity) | 可带类型类约束（约束名是字符串） |
| 命题参数 | `@p` | PropParam(name) | 命题层的形参（见[命题](03-证明-命题.md)） |
| 高阶类型 | `F[_]` / `F[_, _]` | TypeParam(name, null, arity) | arity = 占位 `_` 的个数 |

```subl
fun render[T: Show](x: T): Str = x.show()     // 约束泛型：体内 x.show() 走约束字典槽
fun witness[@q]<q>: Null { }                  // 命题参数 @q 配上文 <q>
class Functor[F[_]] {
    fun map[A, B](fa: F[A], f: (A) => B): F[B]
}
```

细节：

- 尾随逗号合法：`fun f[A, B,](x: A): B`（Parser.kt:371-375）
- 多态函数类型前缀只服务函数类型：`[T](T, T)`（元组带理论头）是**语法错误**，不静默回退（Parser.kt:499-501）
- 泛型函数的声明位角表（`<...>`）另有职责：上文命题 `fun f<p>(...)`、后置下文 `fun f(): T <q>`、约束形参表 `fun f<score <= 100>`（v3.0，Parser.kt:276-316）——都不是类型参数

### 类型位与调用位的括号约定

| 位置 | 括号 | 例 |
|---|---|---|
| 声明头（引入参数） | `[]` | `fun f[T]`、`struct Pair[A, B]`、`type Box[a]` |
| 类型位（代入实参） | `[]` | `List[Nat]`、`Optional[Optional[Nat]]`、`core.Point` |
| 调用位（实例化/供给） | `<>` | `id<Nat>(7)`、`mapEmpty<Str, Nat>()`、`Channel<Nat>(2)` |

调用位的角表**紧贴被修饰名**（`<` 前无空格）才作后缀实例化（Parser.kt:1201-1205）；同一角表还兼任命题上下文与显式供给（`<q>`），由调用点按参数种类分派（CallCheck.kt:789-919）。

### 结构体的两套括号

```subl
struct Test(n: Nat) <n ≠ 0>                   // 声明位 <...> 是伴生命题（构造时证明），不是类型参数
@mut struct Pair[A, B](@mut first: A, second: B)
```

## 语义

### 实例化：显式优先，实参反推导后

$$\frac{f[T](x: T): T \qquad \text{调用 } f(e) \qquad \tau = \text{typeOf}(e)}{T := \tau,\ \Gamma \vdash f(e) : \tau} \quad (\text{T-INST})$$

实例化发生在**调用点**，两条通道（CallCheck.kt:785-836）：

1. **显式角表**：`f<Nat>(e)` 按声明顺序绑定理论参数，且**优先且不覆盖**——已绑定位之后不再被实参反推改写。若实参与显式实例化冲突（`id<Nat>("a")`），实参 Str 与实例化后的形参 Nat 在参数核对处报 E-TYPE-MISMATCH。
2. **实参反推**：形参类型与实参类型做结构化合一 `unifyInto`（TypeInfer.kt:18-70）——变量绑定、occurs check（拒绝 `T → Optional<T]` 的无限类型）、NamedType 逐实参 / FunType 参数+返回 / TupleType 逐项递归、已绑定位做一致性校验。

- **lambda 返回类型的反推走迭代定点**（上限 8 轮）：`map` 的 `U` 只能由 lambda 体推出；`compose` 那样的链式依赖需多轮才能依次解出（CallCheck.kt:801-836）
- **返回类型按替换表实例化**：`(fn.retType ?: …).substT(tsub)`——`fun pair[T](x: T, y: T): (T, T)` 调 `pair(1, 2)` 得 `(Nat, Nat)`
- **形参位若仍是未解出的裸类型变量**，接受任意类型实参（CallCheck.kt:875-882）——这是宽松放行，不是子类型多态

### 构造：由字段实参逐位反推

泛型 struct/enum 的构造调用**不靠角表，而由字段实参推断**（CallCheck.kt:631-687）：

- `Pair(1, "a")` → 逐字段 `extractTpBinding` 解出 `Pair[Nat, Str]`（CheckerTest「HKT2 struct 泛型构造推断实参」）
- `Cons(1, Cons(2, Nil()))` → `List[Nat]`（含 `Cons(T, List[T])` 这类嵌套类型的深位反推）
- 解不出的参数留 synthetic 占位返回（`namedT(name, tps.map { inferred[it] ?: syntheticT(…) })`），如无实参可推的 `emptyList()` 返回 `List[<未解出 T>]`
- 方法体内字段类型按 self 的实参代入：`Pair[Nat, Str]` 的 `first` 在 impl 体内是 `Nat` 而非 `A`（Checker.kt:487-488）

### 约束 = 字典传递（非单态化）

`fun render[T: Show](x: T): Str = x.show()`：

- 声明方生成隐藏首参 `d_Show_T`（JsCodeGen.kt:705-708），调用方按 `tsub[T]` 解出的具体类型解析实例字典、插入实参（CallCheck.kt:944-958）
- `Any` 是自动类型类：约束恒满足、**零字典不设槽**（v2.1）
- 约束解析失败 → E-NO-INSTANCE；运行时才能确定 → W-CONSTRAINT-UNPROVEN；已被反证 → E-CONSTRAINT-VIOLATED
- 类型参数在自递归调用点仍未具体化时，递归调用**透传当前约束槽**而非现场解析（CallCheck.kt:953-957）

### 泛型擦除

理论参数在代码生成期**完全擦除**：`id<Nat>(7)` 生成 `id(7)`（JsCodeGen.kt:897：`InstExpr → expr(e.target)`），类型实参不进运行时。脚本模式的宿主接口中，`[T](T) => T` 与 `(Nat) => Nat` 是同一个接口，区别只在编译期元数据。擦除后唯一残留的泛型痕迹是约束字典槽。解释器（Evaluator）对泛型函数同样按值执行，不做特化。

### 类型别名：按位置逐位代入

`type Box[a] = Optional[a]`：泛型头按**位置**逐位代入（`Box[Nat]` → `Optional[Nat]`），展开是纯编译期的；别名与目标类型在类型检查中完全互通；与既有 struct/enum/class/基类型重名 → E-DUP-DECL（Symbols.kt:293-300）。v1 右值仅支持具名/应用类型（Ast.kt:73-82）。

### 高阶类型（HKT）

- 类型类声明 `class Functor[F[_]]`，成员签名里 `F[A]` 是 kind 应用
- 实例声明 `impl Functor for List[a]`：self 位的零实参小写名（`a`）是**隐式类型变量**；`impl Functor for Result[_, E]` 中 `_` 是 kind 应用槽、`E` 是成员可引用的隐式变量（Parser.kt:956-993）
- kind 合一：`F[A] ~ List[Nat]` 绑 `F := List`、`A := Nat`（TypeInfer.kt:49-68）
- kind 形参**只能以应用形态出现**：裸用 `F` 报 E-KIND-MISMATCH；实参数不符报 E-KIND-MISMATCH；实参自身是另一个构造子形参（`F[G[A]]`）报 E-NON-PATTERN-HKT（Symbols.kt:349-366）

### 命题参数

`[@q]` 是命题形参：调用时自动匹配作用域中唯一的 0 元命题事实；无候选报 E-PROP-UNBOUND（W 族）、多候选报 E-PROP-AMBIGUOUS；可角表显式供给 `w<torch>()`。方括号里 `T` 与 `@p` 同表共存但语义正交（CallCheck.kt:898-919）。详见[命题](03-证明-命题.md)。

## 示例

自包含的工程模式程序（顶层只允许声明，执行代码进 `fun main()`）：

```subl
// ---------- 泛型函数：实参反推 + 显式实例化 ----------
fun id[T](x: T): T = x

// ---------- 泛型枚举（core/collection/list.subl 同构） ----------
enum List[T] {
    Nil()
    Cons(T, List[T])
}

fun size[T](xs: List[T]): Nat = when(xs) {
    Nil => 0
    is Cons(_, t) => size(t) + 1
}

// ---------- 泛型结构体：字段实参反推 ----------
struct Pair[A, B](first: A, second: B)

fun fst[A, B](p: Pair[A, B]): A = p.first

// ---------- 泛型类型别名：按位置代入 ----------
type NatPair[B] = Pair[Nat, B]

// ---------- 约束泛型：字典传递 ----------
class Show[T] { fun show(x: T): Str }

impl Show for Nat {
    fun show(x: Nat): Str = toStr(x)
}

fun render[T: Show](x: T): Str = x.show()

// ---------- 命题参数（独立 axiom 语句，修正案后形态） ----------
axiom torch

fun witness[@q]<q>: Null { }

@impure fun main() {
    var xs = Cons(1, Cons(2, Nil()))        // List[Nat]：由构造子字段实参反推
    print(size(xs))                          // 2

    print(id("hi"))                          // T := Str（实参反推）
    print(id<Nat>(7))                        // T := Nat（显式角表实例化）

    var p = Pair(1, "a")                     // Pair[Nat, Str]：字段实参反推
    print(fst(p))                            // 1

    print(render(7))                         // 约束 Show：调用点插入 d_Show_Nat

    var f: [T](T) => T = {x => x}            // 多态函数类型：lambda 继承 theory
    print(f(3))                              // 3（实参合一反推）
    print(f("a"))                            // a

    var g = fun _[T](a: T): T = a            // 匿名泛型函数
    print(g<Nat>(9))                         // 9（函数值显式实例化）

    var q: NatPair[Str] = Pair(0, "z")       // 别名展开为 Pair[Nat, Str]
    print(q.second)                          // z

    witness<torch>()                         // 命题参数：显式供给
    witness()                                // 自动匹配唯一 0 元命题 torch
}
```

## 陷阱

**括号用错位置**（最常见的错误）：

```subl
// ❌ 非法：调用位误用 []（后缀解析不消费 [，f[Nat](7) 解析失败）
id[Nat](7)

// ❌ 非法：类型位误用 <>——<...> 在类型位是命题括号/函数类型上下文，不是类型应用
var bad: List<Nat> = Nil()         // ❌ 类型位应写作 List[Nat]

// ✅ 正确：类型位用 []，调用位用 <>
var xs: List[Nat] = Nil()
var n = id<Nat>(7)
```
口诀：**声明头与类型位都用 `[]`，只有调用位用 `<>`**。

**箭头家族**（详见[箭头家族](01-基础-箭头家族.md)）：

```subl
// ❌ 非法：函数类型/lambda 用 ->（修正案后 -> 全位非法，仅供诊断）
fun f(x: Nat) -> Nat { }
var g: (T) -> T = {x => x}

// ✅ 正确：程序位一律 =>
fun f(x: Nat): Nat = x
var g: [T](T) => T = {x => x}
```

**实例化的坑**：

- `id<Nat>("a")` → **E-TYPE-MISMATCH**：显式实例化优先绑定且不被反推覆盖，实参 Str 与已实例化形参 Nat 冲突（CheckerTest「显式实例化与实参不符报错」）
- 显式个数不符：多态**函数值**调用报「函数类型 … 有 N 个类型参数，显式给了 M 个」（CallCheck.kt:451-454）；普通具名函数路径多出的角表项被静默忽略（CallCheck.kt:789-794），两者宽严不同
- `f <Nat>(7)`（`<` 前带空格）：不再作后缀实例化，而被解析为比较中缀 `f < Nat`（Parser.kt:1201-1205 的 `!t.precededBySpace` 条件）
- **类型参数解不出会残留**：`fun emptyList[T](): List[T] = Nil()` 直接调用 `emptyList()` 时 T 无实参可推，返回类型残留占位（`List[<未解出 T>]`）；标注侧 `var xs: List[Nat] = emptyList()` 以标注类型兜底（Checker.kt:547-554：标注类型即变量类型，只对初值做兼容性 unify）。需要具体返回类型时显式写 `emptyList<Nat>()`——显式角表先进 tsub（CallCheck.kt:789-794）、返回类型再按替换表实例化（CallCheck.kt:959），得 `List[Nat]`
- `Pair<Nat, Str>(1, "a")` 这类**构造带角表**：解析层接受为 InstExpr（parsePostfix 通用后缀），但 checkStructCall 仅按字段实参推断、未见消费角表类型实参——角表是否对构造生效**待核**

**HKT 的坑**：

- kind 形参裸用 `fun f[T](x: F)` → **E-KIND-MISMATCH**（必须写 `F[A]` 应用形态）
- 实参数不符（`F[_]` 配 `F[A, B]`）→ E-KIND-MISMATCH
- 构造子形参嵌套（`F[G[A]]`）→ **E-NON-PATTERN-HKT**
- `[T](T, T)`（多态前缀接元组）→ **语法错误**：理论前缀仅服务函数类型

**形态混淆**：

- `struct Box[T] { }` → **解析报错**：struct 体是圆括号参数列表，不是花括号（Parser.kt:898-899 给出改写指引）
- `fun f<score <= 100>`（v3.0 约束形参表）与上文命题 `fun f<p>` 同形：解析器按「尖括内首项为 IDENT 且后随带空格的比较/in 运算」分派（Parser.kt:309-316）；LT/GT 作比较符被排除以避免歧义
- 命题参数 `[@q]` 与类型参数 `[T]` 同处方括号：`w<torch>()` 供给的是命题事实，`id<Nat>(7)` 供给的是类型——两者共用角表通道但语义正交，混写不互通

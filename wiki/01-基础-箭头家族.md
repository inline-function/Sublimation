# 箭头家族

> wiki/01-基础-箭头家族 · 事实来源：Lexer.kt、Parser.kt binops/stopArrow 机制（修正案提交 9beb63b）

语言里一切「箭头形」记号分属两个互不相通的通道——**程序位**与**命题位**。

## 语法

| 记号 | 通道 | 出现位置 |
|---|---|---|
| `=>` | 程序位 | lambda 参数表后；when 分支 `模式 => 体`；函数类型 `(T) => U`、零参 `() => Null` |
| `→` | 命题位 | 蕴含中缀（`<p → q>`、`axiom ∀ e. e ∈ xs → (e ≠ 0)`、`∵ p ∴ q` 链中） |
| `<->` 或 `↔` | 命题位 | 等价（IFF/EQUIV 同义，ASCII 与 Unicode 等价归一） |
| `..` | 程序位 | 区间中缀（`0..10`） |
| `->` | **非法** | 任何位置（词法器仍将其 lex 为 ARROW token，纯粹是为了报错定位：诊断会指向那个 `->`） |

### 两通道互不可达

- `=>`（DARROW）**不是中缀算符**：binops 集合里没有它，任何 `a => b` 的写法都会在 `=>` 处中断表达式
- `→`（IMPLIES）**只在中缀**：lambda 参数表、when 分支位、函数类型位都不可能接受它
- 零参 lambda 的 `=>` 是参数表为空的特例：`{ => 7 }`——参数列表可以整个省略，箭头保留

## 语义

为什么要分两通道：蕴含是**命题层的逻辑算符**（参与 Γ 闭包、MP 推理、归一化），箭头是**程序层的结构分隔符**（分隔参数与体、模式与分支、参数与返回类型）。混用会让 `p -> q` 在命题和分支两个位置产生歧义，所以修正案统一为：程序位一律 `=>`，命题位一律 `→`（Unicode）。等价同理用 `<->`/`↔` 而非任何 ASCII 箭头组合。

### when 分支位的蕴含加括号

分支条件用 `parseExpr` 解析时会把后续的中缀一路吃掉。若条件里想写蕴含，必须括起来：

```subl
when[p ∨ ¬q] { (p → q) => { ∴ q } }   // 加括号
```

## 示例

```subl
// 程序位 =>
var add = { x, y => x + y }                  // lambda
var double : (Nat) => Nat = { x => x * 2 }   // 函数类型 + 零形参 lambda
when(x) { is Cons(h, t) => h + size(t)     // when 分支
         Nil => 0 }

// 命题位 →
fun modusPonens[p, q]: Null <p ∧ (p → q)> { }
@impure fun main() {
    axiom ∀ e. e ∈ xs → (e ≠ 0)
    ∵ is Some(7) ∴ true
}
```

## 陷阱

- **`->` 非法**：`p -> q`、`{ x -> x }`、`(T) -> T` 全都不解析；诊断指向 `->` 本身
- **when 分支位的蕴含忘记加括号**：`when[p ∨ q] { p → q => … }` 中 `→` 会被当条件的一部分继续消费，报「期望…」类错
- **零参 lambda 容易漏箭头**：`{ 7 }` 是「隐式单参体」（`_` 引用形参）而不是零参；要零参必须写 `{ => 7 }`
- **`<->` 与 `↔` 等价但别混用风格**：命题层 ASCII/Unicode 归一发生在规范化阶段，二者等价；工程内统一一种
- **区间 `..` 不是箭头**：`0..10` 是 RANGE token，别和箭头家族混淆
- **诊断里的 `->`**：错误信息可能写成「期望表达式，实际'->'」——这是 lexer 保留 ARROW 的唯一用途，不代表语言接受它

# 函数类型

> wiki/02-类型-函数类型
> 主题域：函数类型 `(T) => U`、零参 `() => Null`、`@impure`/`@root` 修饰、高阶函数
> 事实来源：_langfacts.md（§2/§3/§5/§6）+ Parser.kt / Ast.kt(FunType) / Checker.kt / CallCheck.kt / Symbols.kt / Types.kt / Evaluator.kt / core 下 .subl 标准库 / CheckerTest / E2ETest

函数是**值**，函数类型是这类值的类型。它由「参数表 + `=>` + 返回类型」三段构成，可再带纯度（`@impure`）、理论参数（`[T]`）与命题上下文（`<$1 ∈ xs>`）。lambda 的词法形态（`{ x => … }`、尾随 lambda 等）见 [箭头家族](01-基础-箭头家族.md)，本文只讲**类型层**。

## 语法

### 类型形态

| 形态 | 写法 | 出处 |
|---|---|---|
| 一参 | `(Nat) => Bool` | `parseFunOrTupleType`（Parser.kt:565） |
| 多参 | `(Nat, Str) => Null` | 同上 |
| 零参 | `() => Null` | 空参数表 + `=>`（Parser.kt:583） |
| 多态 | `[T](T) => T` | `parsePolyFunType`（Parser.kt:485） |
| 不纯 | `@impure (A) => Null` | 类型位注解（Parser.kt:516） |
| 带上下文 | `(T)<$1 ∈ xs> => Null` | Parser.kt:581 |

以 Parser 为准的文法片段：

```
类型注解   ::= "@mut" | "@atomic" | "@impure"      // @impure 只能修饰函数类型
多态前缀   ::= "[" TypeParam ("," TypeParam)* "]" 函数类型
函数类型   ::= "(" (类型 (",")*)? ")" ("<" 命题 ">")? "=>" 类型
```

要点：

- 参数表**必须带括号**——`Nat => Nat` 不是函数类型（`Nat` 被当具名类型解析，随后的 `=>` 无从归属）
- `=>` 是函数类型唯一的箭头；`->` 修正案后全位非法（详见陷阱）
- `@impure` 有两个同名但不同通道的用法：**类型位**（参数/变量/字段的类型标注里，如 `f: @impure (A) => Null`）与**声明位**（`@impure fun …`，函数自己的注解）
- `@root` 只能写在声明位修饰 `fun`，**不能进类型位**——类型位注解只有 `@mut`/`@atomic`/`@impure` 三种（Parser.kt:521）
- 函数类型可作类型别名右值：`type Pred = (Nat) => Bool`（CheckerTest:547）

### 声明位注解组合

```subl
@impure fun main() { … }                        // 副作用入口
@impure @async
@root fun runBoth(f: () => Null, g: () => Null): Null   // core/async/async.subl:9，无体内建声明
```

### 值形态（高阶函数的「值」侧）

| 形态 | 写法 | 出处 |
|---|---|---|
| lambda | `{ x, y => x + y }`；零参 `{ => 7 }`；隐式单参 `{ x + 1 }` | Parser.kt:1690 |
| 匿名函数 | `fun(x: A): C = f(g(x))`（`=` 体与 `{ … }` 体互斥，决策 73） | `parseAnonFunExpr`（Parser.kt:839） |
| 尾随 lambda | `f(a, b) { x => … }`（追加为**末位**实参，发 D-TRAILING 提示） | Parser.kt:1206 |
| 函数名作值 | `var g = shout` | E2ETest |
| 方法路径作值 | `var f = 5.shout`（绑定 self 的 `() => Str`） | E2ETest |
| 实例化表达式作值 | `var g = id<Nat>`（得 `(Nat) => Nat`） | E2ETest |

## 语义

### 判别：函数类型还是元组类型

`(` 起头的类型在 `)` 之后看一个 token：是 `=>` 就构造 `FunType`，否则是 `TupleType`（决策 57/61，Parser.kt:583）。所以 `(Nat, Str)` 是元组类型，`(Nat, Str) => Null` 是函数类型——二者仅一箭头之差，写错就跨类别。

### FunType 的五个字段（Ast.kt:152）

`params / ret / purity / theory / context`：

- `purity`：空串或 `"impure"`。来源有二：类型位 `@impure`，或 checker 对 lambda 体的纯度推导
- `theory`：`[T]` 前缀的类型参数是**绑定者**，类型代入时屏蔽（α 安全）；比对当前对 theory 位宽松（V1，后续收紧）
- `context`：命题表达式列表（解析自 `<…>`），形如 `(T)<$1 ∈ xs> => Null`

### 纯度系统（@impure 的三张面孔）

1. **声明位**：决策 34——每个未标 `@impure` 的具名函数自动注册 `pure<f>` 事实；纯函数体内调用 `@impure` 函数报 **E-IMPURE-CALL**。另有一条硬规则：函数参数类型含 `@mut` 时函数必须标 `@impure`，否则 **E-IMPURE-REQUIRED**（Checker.kt:291）
2. **类型位/推导位**：lambda 体内发生 impure 调用、或给外部捕获的 `@mut` 变量赋值 → `curLambdaImpure` 置位 → 该函数值的类型 `purity="impure"`（Checker.kt:1082–1142、:1311–1344）。纯上下文里调用这种函数值报 **E-IMPURE-CALL**（CheckerTest:335 双报错、:1215 lambda 改外层 @mut）
3. **借用效应**：被调用的函数值恰是**本函数声明的** `@impure` 函数值形参时放行——形参即显式效应能力，能构造 impure lambda 的调用方本身必非纯（CallCheck.kt:476–486，CheckerTest:852 的 forEach 形态）

方向性：**纯 lambda 可传入 `@impure (T) => Null` 形参**；反过来把不纯 lambda 赋给纯函数类型报 **E-TYPE-MISMATCH**（CheckerTest:645）。纯 lambda 另登记 `pure<{…}>` 命题（Checker.kt:1140）。

### @root：内建声明机制

- `@root fun 名字(…)` 允许**不写函数体**；普通函数无体报 **E-FUN-NO-BODY**（Symbols.kt:263）
- 名字必须在 `ROOT_WHITELIST`（Types.kt:277–300：`print`/`readFile`/`runBoth`/`withMutex`/`timeNow`…），否则 **E-ROOT-NOT-ALLOWED**；命中发 H-ROOT-BUILTIN 提示
- @root 无体声明的**纯度由内建表决定，用户注解不参与**（Symbols.kt:19–24）：如 core/time 写 `@root fun timeNow(): Nat`（无 @impure），但内建表把 `timeNow` 标为 impure——这避免用户误注册 `pure<readFile>` 类假证明
- codegen 按名字特判翻译为原生 JS，不生成函数定义；`@android` 与之同构（白名单门 + 无体豁免）

### 多态函数类型

`[T](T) => T`：函数值调用时显式实例化 `id<Nat>(3)` 优先，否则由实参类型反推；显式实例化后逐位核对实参与实例化形参，不符报 **E-TYPE-MISMATCH**（CallCheck `checkInlineFunCall`）。`[T](a, b)` 这种「理论前缀 + 元组」形态直接语法报错（Parser.kt:500）。

### 上下文函数类型

`(T)<$1 ∈ xs> => Null`：调用该函数值前须证明其携带的上下文（`$1` 按实参代入后的命题），证不出报 **E-CTX-UNPROVEN**（CallCheck.kt；CheckerTest:1695 的 forEach 用例）。这是把「供证明的命题」随函数类型一起传递的通道，`$n` 指函数类型的第 n 个形参（从 1 起，仅前件/后件位）。

### 捕获语义

- 解释器侧：lambda **创建时**深拷贝捕获变量（`ClosureFun.copyCapture` + `copiedFrame` 沿父链逐值拷，Evaluator.kt:833–863）——闭包内改的是自己的快照
- JS 侧：`__dc` 深拷贝对函数**穿透**（不递归拷函数值）为既定边界
- 类型层后果：lambda 改外部捕获的 `@mut` 变量会被推导为不纯（见纯度系统第 2 点），因为「赋值即版本前进」与「捕获快照」语义冲突

### 高阶函数

函数类型作形参或返回类型即高阶函数，标准库大量使用：

- `fun map[A, B](fa: List[A], f: (A) => B): List[B]`、`fold`、`filter`、`flatMap`（core/collection/list.subl:12 等）
- 借用效应签名 `fun forEach[T](xs: List[T], f: @impure (T) => Null): Null`（list.subl:121）
- 零参 `() => Null` 是「把代码块当参数」的惯用形态：`runBoth(f, g)`、`runSeq`（async.subl）、`withMutex(m, f)`（mutex.subl:10）
- 类型类成员以函数类型为形参实现多态分发：`impl Functor for List[a]` 的 `map(f: (A) => B)`

## 示例

```subl
// 1) 高阶函数 + 函数类型作形参与返回类型（E2ETest v30 综合验收节选）
fun id[T](x: T): T = x
fun inc(x: Nat): Nat = x + 1
fun compose[A, B, C](f: (B) => C, g: (A) => B): (A) => C =
    fun(x: A): C = f(g(x))

@impure fun main() {
    var g = id<Nat>              // 实例化表达式作值：(Nat) => Nat
    print(g(7))                  // 7
    print(compose(inc, inc)(5))  // 7
    print(take(id<Nat>, 5))      // 5（take 见下）
}
fun take(f: (Nat) => Nat, x: Nat): Nat = f(x)
```

```subl
// 2) 借用效应：@impure 函数值形参（CheckerTest:854）
fun forEach(f: @impure (Nat) => Null): Null = f(1)
@impure fun go(): Null = forEach({ x => null })   // 纯 lambda 传入 @impure 形参，放行
```

```subl
// 3) 零参函数类型：代码块当参数
fun once(f: () => Nat): Nat = f()
@impure fun main() { print(once({ => 42 })) }    // 42
```

```subl
// 4) 类型别名与上下文函数类型（CheckerTest:547 / :1695）
type Pred = (Nat) => Bool
fun use(p: Pred): Bool = p(1)

enum List[T] { Nil(), Cons(T, List[T]) }
fun forEach[T](xs: List[T], f: (T)<$1 ∈ xs> => Null) {
    when(xs) { Nil => null
               is Cons(h, t) => { f(h); forEach(t, f) } }
    return null
}
fun needNotZero(n: Nat)<n ≠ 0> { }
@impure fun main() {
    var xs = Cons(1, Cons(2, Nil()))
    axiom ∀ e. e ∈ xs → (e ≠ 0)      // 独立 axiom 语句供给上下文
    xs.forEach { _.needNotZero() }    // 尾随 lambda：$1 ∈ xs 已证
}
```

```subl
// 5) @root 内建声明（标准库真实形态，core/async/async.subl）
@impure @async
@root fun runBoth(f: () => Null, g: () => Null): Null
```

## 陷阱

- **`->` 全位非法**：`(T) -> U`、`() -> Null`、`{ x -> x }` 全都不解析；命题蕴含用 Unicode `→`，程序位一律 `=>`（两通道互不可达，见 [箭头家族](01-基础-箭头家族.md)）
- **漏括号**：`Nat => Nat` 不被解析为函数类型，参数表必须 `(Nat) => Nat`
- **元组与函数类型一字之差**：`(Nat, Str)` 是元组类型，`(Nat, Str) => Null` 才是函数类型
- **零参 lambda 漏箭头**：`{ 7 }` 是隐式单参体（`_` 引用形参），零参必须写 `{ => 7 }`
- **类型位 `@impure` 只能修饰函数类型**：`@impure Nat` 直接解析报错；类型位注解也只有 `@mut`/`@atomic`/`@impure`——`@root` 不能进类型位
- **`@root` 白名单**：名字不在 ROOT_WHITELIST 报 E-ROOT-NOT-ALLOWED；无体函数不带 `@root` 报 E-FUN-NO-BODY；`@root` 声明的纯度以内建表为准，别再手动叠加 `pure<f>` 语义
- **纯上下文调用不纯函数值**：`@impure fun log(x: Nat): Nat = x` 之后，`fun main() { var f = {x => log(x)}; var g = f(1) }` 在 lambda 构造与函数值调用两处都报 E-IMPURE-CALL
- **纯度方向**：不纯 lambda 塞进纯 `(T) => U` 形参报 E-TYPE-MISMATCH；纯 lambda 传 `@impure (T) => Null` 放行（方向不可反）
- **参数带 @mut 却忘标 @impure**：报 E-IMPURE-REQUIRED（Checker.kt:291）
- **`= { … }` 混写**：匿名函数与具名函数同受决策 73 约束——`=` 表达式体与 `{ … }` 块体互斥，`fun(x: A): C = { … }` 直接报错
- **尾随 lambda 的边界**：只追加为**最后**一个实参；`Task { … }` /`Flow { … }` 是代码块而非 lambda（决策 93），别指望它们接收尾随函数值
- **V1 宽容别依赖**：函数值调用当前不做参数个数与逐位配对核对（CallCheck.kt:472 的 V1 注释），`f(v)` 单元组形态被宽容放行——写调用仍按声明个数传，该核对后续轮次要收紧
- **闭包捕获是快照**：lambda 创建时深拷贝捕获变量（解释器机制），别指望用闭包给外部变量「传值」出去——要回结果走返回值；给捕获的 `@mut` 变量赋值还会把 lambda 推导为不纯
- **`$1` 只在上下文位**：函数类型的 `<$1 ∈ xs>` 指其第 1 形参；把它误写到别处不成立
- **别名右值的旧文档说法过时**：旧形式化文法称「函数类型/元组右值不支持」，实现与测试已支持 `type Pred = (Nat) => Bool`（CheckerTest:547）——以实现为准

# 证明链（∵ ∴）

> wiki/03-证明-证明链 · 主题域：手动证明的 ∵ 前提逗号分隔、∴ 结论、证明义务语义、失败诊断（E-CANNOT-PROVE / E-PREMISE-UNPROVEN / W-PROP-UNBOUND）、`expr by [q]` 直接供给、与 Γ 闭包（MP）的关系
> 事实来源：_langfacts.md §4；compiler/.../checker/Checker.kt:633-655（BTS 检查）、:656-683（分类讨论）、:762-766（ByStmt）、:1264-1269（ByExpr）；checker/Prop.kt:398-481（closure/MP）；checker/Diffusion.kt:41（allFacts）、:208-367（proveOrDeep/searchTheorems）；frontend/.../parser/Parser.kt:642-698（parseBTS）、:1027、:1103-1113、:1657-1672；lexer/Lexer.kt:43/114-115/138；ast/Ast.kt:259/273-278/436；Evaluator.kt:191/250；JsCodeGen.kt:796/930/1514；cli/Main.kt 诊断解释表；root doc/手动证明.md（结构参照，旧文法处已按修正案改写）

证明链是手动证明的主干语法：用户用 `∵` 列出**形式与前提**、用 `∴` 声明**结论**，编译器在上下文 Γ 中逐条检验，通过后把结论注入 Γ 供后续消费。它是一条纯粹的编译期义务——运行时被擦除，不产生任何值或副作用。

## 语法

### 因为-所以语句

```subl
∵ form, p₁, p₂, … ∴ conclusion     // 完整形态
∴ q                                  // 裸 ∴：等价 ∵ ⊤ ∴ q（反糖）
∵ p                                  // 裸 ∵：等价 ∵ ⊤ ∴ p（先证 p 再注入 p）
∵ form ∴ q                           // 无前提形态（逗号可有可无）
```

- `∵`（BECAUSE）与 `∴`（THEREFORE）是固定的单字符 token（Lexer.kt:138），且不得作为符号标识符首字符（Lexer.kt:100-101）；`by` 是关键字（Lexer.kt:43）。
- `∵` 后第一个表达式是**形式位**（form），随后以**逗号分隔**的才是前提（Parser.kt:682-698）：`∵ p, p → q ∴ q` 中 form 是 `p`，前提列表是 `[p → q]`。
- 前提列表允许**尾随逗号**：`∵ p, q, ∴ r` 中末尾逗号被跳过（Parser.kt:692）。
- form、前提、结论都是普通表达式，经 `parseExpr(angle = false)` 解析——全左结合、**无优先级**，复杂命题必须加括号。
- 语句位置合法：函数体内、脚本顶层语句位，以及 `when[p ∨ q]` 分支体、`if[p]` 两支等语句块内；不能出现在表达式位（`var x = ∴ q` 非法）。
- 归一沿用命题层规则：`<->` ↔ `↔`、`<=` ↔ `≤`、`!=` ↔ `≠` 等在入 Γ 时统一（langfacts §4）。
- AST 节点是 `BTSStmt(form, premises, conclusion)`（Ast.kt:273-278）；裸形态的 form 位放 `TopExpr` 占位（Parser.kt:644/688）。

### by 断言（t30 后；旧「直接供给」已废除）

```subl
expr by [q]                    // 表达式位：值与类型同 expr，断言 q 成立（proveOrDeep 核对）
expr by [p] by [q]             // 后缀可链（parseExpr 循环内 continue）
by [q]                         // ✗ 语句位已移除（E-BY-REMOVED）；要免验证供给改用 axiom q
```

- 语句位 `by […]`（Parser.kt:652 仍解析）在 Checker 报 **E-BY-REMOVED** 并给出迁移指引（改 `axiom` 语句）；表达式后缀位 `expr by […]`（Parser.kt:1027）保留，语义改为**断言**（详见「03-证明-by」条目）。
- 方括号内是逗号分隔的命题列表（parseBracketList，Parser.kt:1657-1672），同样允许尾随逗号；空列表 `by []` 合法但无意义。
- AST：语句位 `ByStmt(props)`（Ast.kt:259）、表达式位 `ByExpr(target, props)`（Ast.kt:436）。

## 语义

### 证明义务：四步流水线

对每条 `∵ form, p₁…pₙ ∴ q`，检查器（Checker.kt:633-655）依次执行：

1. **前提逐条自动证明**：每个前提 `pᵢ` 用 `proveOrDeep(f.allFacts(), pᵢ)` 或定理空间搜索 `searchTheorems(pᵢ, 0, f.localTheorems)` 检验；任一失败报 `E-PREMISE-UNPROVEN`：「因为-所以的前提 pᵢ 没证出。当前已知事实 Γ：…」。循环不短路——多个前提失败会各报一条。
2. **结论证明**（仅当前提全部通过，`premisesOk` 短路）：`proveOrDeep(f.allFacts() + 前提, q)` 或 `searchTheorems(q, …)`；失败报 `E-CANNOT-PROVE`：「因为-所以的结论 q 证不出。已试的定理：…；当前已知事实 Γ：…」。
3. **注入**：成功后 `f.inject(conclusion)`，结论进入当前帧的事实池（沿父帧链并入 allFacts，Diffusion.kt:41），后续语句可直接消费；同时给出 `D-BTS` 补充级提示。
4. **擦除**：运行时求值为 `Null`（Evaluator.kt:191），JS 代码生成完全不产出（JsCodeGen.kt:796/1514/1564）——证明只活在编译期。

判定式概括：

$$\frac{\Gamma \vdash p_1 \quad \cdots \quad \Gamma \vdash p_n \quad \Gamma, p_1, \dots, p_n \vdash q}{\Gamma \vdash q \ \text{（注入 Γ）}} \quad (\text{BTS})$$

### 与 Γ 闭包（MP）的关系

前提检验与结论证明都不是「点对点查表」，而是在 Γ 的**饱和闭包**上判定（Prop.kt:426-481）：

- 闭包做合取分解（`p ∧ (p → q)` 拆成 `p` 与 `p → q`）、∀ 单名实例化、**前向分离规则 MP**（`p` 与 `p → q` 产 `q`）、modus tollens（`p → q` 与 `¬q` 产 `¬p`）、矛盾产 `⊥`，迭代至不动点。
- 因此前提不必重复 Γ 中已由别处推出的事实：写 `axiom p ∧ (p → q)` 后，`∵ p, p → q ∴ q` 的两个前提会由闭包拆出，结论经 MP 自动成立。
- 结论证明时前提被临时加入 Γ（`f.allFacts() + premises`，Checker.kt:646）——所以前提本身也是后续推理的可用事实，链条可以逐步 accumulate。
- 闭包的关键表达式集合在义务开始时固定、不随新事实膨胀（Prop.kt:429-431），防止复合项自我增殖导致笛卡尔爆炸；义务过于复杂时报 `E-DEEP-SATURATION`，建议拆成小步（Diffusion.kt:328-329）。
- MP 闭包是**有向**饱和：`q` 与 `p → q` 不产 `p`（详见「命题」条目）。

### 通道顺序与定理搜索

`proveOrDeep` 内部按序短路尝试（Diffusion.kt:278-337）：自定义命题展开 → 常量/类型判定 → 算术通道（ArithProve，不等式与等式链）→ 通用证明器（闭包）→ 定理搜索；激进模式（CLI 标志）额外开启反证法（需挂载 @classic）与命题维 ∀ 实例化。

- **定理空间**：只有 `@theorem` 标注的函数（以及块内局部函数，即 ∀ 引入）进入搜索空间（Diffusion.kt:339-340、Checker.kt:751-760）；命中判据是定理**后件与目标的结构合一**，theory 参数（如 `[p]`）是可绑定到任意项的元变量，搜索深度上限两跳（超限报 `E-THEOREM-SEARCH-DEPTH`，Diffusion.kt:347-349）。
- **形式位（form）的现状**：解析后不被检查器使用——Checker.kt 的 BTS 分支只引用 `premises` 与 `conclusion`，`.form` 仅被语言服务与注解扫描器遍历（LspAnalysis.kt:662、AnnotationScanner.kt:91）。根文档《手动证明》所述「编译器按形式查找定理函数」在实现中由对**结论**的后件合一承担（待核：form 位未来是否回归形式匹配语义）。
- 因此「完整形态」里 form 目前是**文档性占位**：写成什么不影响检验结果（但必须是合法可解析的表达式）。

### by 的断言语义（t30）

- `expr by [q]` **不再注入 Γ**：props 作为证明义务，延迟到包围语句/绑定完成后经 `proveOrDeep` 核对，证不出报 `E-CANNOT-PROVE`（Checker 的 ByExpr 分支 + flushByAsserts 队列）。旧的免验证供给（D-BY 提示、注入 Γ）已删除——免验证入口只剩 `axiom` 语句。
- 与 `axiom` 的区别：axiom 是**免验证**的「公理声明」（注入 Γ）；by 断言是**义务**（证出才通过、不注入 Γ）。两者在 t30 后成了严格互补：信任用 axiom，验证用 by。
- 表达式位 `expr by [q]` 类型与值都等于 `expr`（求值时只算目标，Evaluator.kt:250；JS 生成只保留目标，JsCodeGen.kt:930）——断言贴在产生值的表达式上，编译期核对、运行期零成本。

### 失败诊断速查

| 诊断码 | 级别 | 触发位 | 含义（CLI 解释表/cli/Main.kt） |
| --- | --- | --- | --- |
| E-PREMISE-UNPROVEN | 错误 | ∵ 前提 | 前提编译器证不出；前提必须是上下文已知事实，先证它或用 axiom 声明 |
| E-CANNOT-PROVE | 错误 | ∴ 结论 | 结论在当前上下文证不出；前面用 ∵ 注入事实、换 axiom，或检查命题是否写错 |
| E-DEEP-SATURATION | 错误 | 任意证明义务 | 自动证明器到最深也没证出；把大结论拆成小步逐步推 |
| E-THEOREM-SEARCH-DEPTH | 警告 | 定理搜索 | 搜索深度超限（默认两跳） |
| W-PROP-UNBOUND | 警告 | when[p ∨ q] | 分类讨论的析取前提不在 Γ 中（先用 axiom 注入或证出） |
| E-PROP-UNBOUND | 警告（warn 位） | ∃ 消去 | 前提命题不在已知事实里，先用 ∵ 或 ∃ 引入 |
| D-BTS | 补充 | 链成功 | 证明成立的正面提示（D-BY 随旧 by 供给在 t30 删除） |

## 示例

以下四例均经 `sublimation.jar check` 实跑通过（frontend/compiler 当前提交）。

### 1. 基本链：MP 闭包 + by + 算术通道

```subl
@impure fun main() {
    var x = 3                       // 注入 x : Nat、x = 3、x ≥ 0
    axiom p ∧ (p → q)               // 闭包拆成 p 与 p → q
    ∵ p, p → q ∴ q                  // 前提各自由 Γ 可证；结论经 MP 产 q 并注入
    var y = x + 1 by [x + 1 ≤ 5]    // y 是 4；断言 x + 1 ≤ 5 经算术通道核对（不再供给 Γ）
    ∵ x + 1 ≤ 5 ∴ x ≤ 4             // 算术通道：由 x = 3 链式推出
    ∴ x ≤ 4                         // 已在 Γ，直通
    print(y)
}
```

### 2. 定理形与完整形态

```subl
@theorem fun plusComm[a, b]: Null <a + b = b + a>

@impure fun main() {
    var n = 0
    ∴ (1 + 2) = (2 + 1)             // searchTheorems 后件合一命中 plusComm
    ∵ ∀n. (n : Nat) → (n ≥ 0),      // form 位（当前为文档性占位）
      n : Nat                       // 前提：由 var n = 0 注入的 n : Nat 可证
    ∴ n ≥ 0                         // 结论由 Γ 直接可证，注入
}
```

### 3. 裸形态：先证再注入

```subl
@impure fun main() {
    var n = 0
    ∵ n ≥ 0                         // 反糖为 ∵ ⊤ ∴ (n ≥ 0)：从 Γ 证出后注入
    ∴ n = 0                         // Γ 已含 n = 0，直通
}
```

### 4. 分类讨论中嵌套证明链（W-PROP-UNBOUND 的正对照）

```subl
@impure fun main() {
    axiom p ∨ q                     // 缺这一条则 W-PROP-UNBOUND
    axiom p → r
    axiom q → r
    when[p ∨ q] {
        p => { ∵ p → r, p ∴ r }     // 分支内假设 p，链出 r
        q => { ∵ q → r, q ∴ r }     // 分支内假设 q，链出 r
    }
    ∴ r                             // 两支公共结论 r 已注入 Γ，直通
}
```

### 5. 失败样例（实跑复现的诊断原文）

```subl
@impure fun main() {
    var x = 1
    ∵ ⊤, r ∴ r                       // 前提 r 不在 Γ
    ∵ x = 1 ∴ x = 2                  // 结论证不出
    when[p ∨ q] { p => { ∴ p } q => { ∴ q } }   // 析取式不在 Γ
}
```

对应诊断（CLI check 输出）：

- `E-PREMISE-UNPROVEN: 因为-所以的前提 r 没证出。当前已知事实 Γ：>=<1, 0>； >=<x, 0>； =<x, 1>； :<x, Nat>`
- `E-CANNOT-PROVE: 因为-所以的结论 =<x, 2> 证不出。已试的定理：（无定理函数）；当前已知事实 Γ：…`
- `W-PROP-UNBOUND: 分类讨论的析取前提 (p | q) 不在 Γ 中`（附带 `W-WHEN-NO-COMMON`：两支各证自己的前提，无公共结论）

## 陷阱

- **前提失败时结论不被检验**：`premisesOk` 为假时跳过结论证明（Checker.kt:646 的短路），所以一个 `E-PREMISE-UNPROVEN` 不会附带 `E-CANNOT-PROVE` 的二次定位——修前提时别等结论诊断。
- **form 位写错不报警**：当前实现不使用 form 匹配定理（见语义节），形式位与实际证明脱钩；反过来，指望「写对 form 就能调到定理」是错的，真正起作用的是结论的后件合一（待核）。
- **裸 `∵ p` 是「证明并注入」，不是「假设 p」**：前提必须已在 Γ 可证；要假设某命题成立再做推理，用分类讨论 `when[p ∨ q]` 的分支或 `if[p]` 的两支（分支内各自注入假设）。
- **换行不是 token**：结论/前提表达式的解析会吞掉下一行开头的 `by` 与符号算符（`+ - * / = < > → ∧ ∨` 等分支无同行检查，Parser.kt:1027/1071）——实踩：`∴ q` 换行接 `by [r]` 会解析成结论 `q by [r]`，报出形如「结论 `__t__<?>` 证不出」的怪诊断。只有 IDENT 中缀糖有同行约束（infixOperandAhead，Parser.kt:1103-1113）。换行处用 `;` 或调整语句顺序。
- **无优先级左结合**：`∴ 1 + 2 = 2 + 1` 被解析为 `((1 + 2) = 2) + 1` 而证不出；必须写 `∴ (1 + 2) = (2 + 1)`。
- **W-PROP-UNBOUND 不属于 ∵∴ 链本身**：它由分类讨论语句 `when[p ∨ q]` 在析取式不在 Γ 时发出（Checker.kt:660-662）；∃ 消去的前提缺失走的是 `E-PROP-UNBOUND`（warn 位，Checker.kt:742）——诊断码形似而触发点不同。
- **分类讨论要「同结论」而非「同前提」**：两支各证自己的析取支（`p => { ∴ p }`）没有公共结论，虽不报错但只给 `W-WHEN-NO-COMMON`，什么也不注入（Checker.kt:673-681）。
- **不纯表达式不参与结构相等**：含 @impure 调用的等式（如 `∵ log(1) = log(1)`）不会因「长得一样」而成立，只认 Γ 中显式事实（Diffusion.kt:159、CheckerTest.kt:1191）。
- **`+∵`（又因为）未接入文法**：lexer 产出独立 token PLUS_BECAUSE（Lexer.kt:15、114-115），但 Parser 的语句分派与表达式循环都没有它的分支，写出 `+∵ p` 会解析失败；语言服务仅在折叠层级识别它（LspAnalysis.kt:1505）（具体报错文案与其规划用途待核）。
- **`by` 关键字重载**：`impl C for T by field` 的委托位要求 `by` 后跟字段名（Parser.kt:969-978），与证明位的 `by [命题]` 形态互斥，别混用。
- **「已试的定理」仅含 @theorem 函数**：非 @theorem 的纯 Null 函数不进定理空间（Diffusion.kt:339-340），`E-CANNOT-PROVE` 里显示「（无定理函数）」多半是忘了标 @theorem。
- **证明语句在运行时被擦除**：`∴ q` 不产生断言或任何运行期效果（Evaluator/JsCodeGen 均丢弃）——它只是编译期义务（运行期断言机制待核）。

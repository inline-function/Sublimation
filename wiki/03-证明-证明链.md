# 证明链（∵ ∴）

> wiki/03-证明-证明链 · 主题域：手动证明的 ∵ 前提逗号分隔、∴ 结论、证明义务语义、失败诊断（E-CANNOT-PROVE / E-PREMISE-UNPROVEN / W-PROP-UNBOUND）、`expr by [q]` 直接供给、与 Γ 闭包（MP）的关系
> 事实来源：_langfacts.md §4；compiler/.../checker/Checker.kt:633-655（BTS 检查）、:762-766（ByStmt）、:1264-1269（ByExpr）；checker/Prop.kt:398-481（closure/MP）；checker/Diffusion.kt:41（allFacts）、:208-367（proveOrDeep/searchTheorems）；frontend/.../parser/Parser.kt:642-698（parseBTS）、:1027、:1657-1672；lexer/Lexer.kt:43/114-115/138；Evaluator.kt:191/250；JsCodeGen.kt:796/930/1514；cli/Main.kt 诊断解释表；root doc/手动证明.md（结构参照，旧文法处已按修正案改写）

证明链是手动证明的主干语法：用户用 `∵` 列出**形式与前提**、用 `∴` 声明**结论**，编译器在上下文 Γ 中逐条检验，通过后把结论注入 Γ 供后续消费。它是一条纯粹的编译期义务——运行时被擦除，不产生任何值或副作用。

## 语法

### 因为-所以语句

```subl
∵ form, p₁, p₂, … ∴ conclusion     // 完整形态
∴ q                                  // 裸 ∴：等价 ∵ ⊤ ∴ q（反糖）
∵ p                                  // 裸 ∵：等价 ∵ ⊤ ∴ p（先证 p 再注入 p）
∵ form ∴ q                           // 无前提形态（逗号可有可无）
```

- `∵`（BECAUSE）与 `∴`（THEREFORE）是固定的单字符 token（Lexer.kt:138），且不得作为反引号外的符号标识符首字符（Lexer.kt:100-101）。
- `∵` 后第一个表达式是**形式位**（form），随后以**逗号分隔**的才是前提（Parser.kt:682-698）：`∵ p, p → q ∴ q` 中 form 是 `p`，前提列表是 `[p → q]`。
- 前提列表允许**尾随逗号**：`∵ p, q, ∴ r` 中末尾逗号被跳过（Parser.kt:692）。
- form、前提、结论都是普通表达式，经 `parseExpr(angle = false)` 解析——全左结合、**无优先级**，复杂命题必须加括号。
- 语句位置合法：函数体内、脚本顶层语句位，以及 `when[p ∨ q]` 分支体、`if[p]` 两支等语句块内；不能出现在表达式位（`var x = ∴ q` 非法）。
- 固定返回 `Null`——「万物皆为表达式」哲学下它仍是 Null 类型表达式（Checker.kt:654）。

### by 直接供给

```subl
by [q₁, q₂]                    // 语句位：无条件注入命题
var y = expr by [q]            // 表达式位：值与类型同 expr，顺带注入 q
expr by [p] by [q]             // 后缀可链（parseExpr 循环内 continue）
```

- `by` 是关键字（Lexer.kt:43），两种位形：语句位 `by […]`（Parser.kt:652）与表达式后缀位 `expr by […]`（Parser.kt:1027）。
- 方括号内是逗号分隔的命题列表（parseBracketList，Parser.kt:1657-1672），同样允许尾随逗号；空列表 `by []` 合法但无意义。

## 语义

### 证明义务：四步流水线

对每条 `∵ form, p₁…pₙ ∴ q`，检查器（Checker.kt:633-655）依次执行：

1. **前提逐条自动证明**：每个前提 `pᵢ` 用 `proveOrDeep(f.allFacts(), pᵢ)` 或定理空间搜索 `searchTheorems(pᵢ, 0, f.localTheorems)` 检验；任一失败报 `E-PREMISE-UNPROVEN`：「因为-所以的前提 pᵢ 没证出。当前已知事实 Γ：…」。
2. **结论证明**（仅当前提全部通过）：`proveOrDeep(f.allFacts() + 前提, q)` 或 `searchTheorems(q, …)`；失败报 `E-CANNOT-PROVE`：「因为-所以的结论 q 证不出。已试的定理：…；当前已知事实 Γ：…」。
3. **注入**：成功后 `f.inject(conclusion)`，结论进入当前帧的事实池（沿父帧链并入 allFacts，Diffusion.kt:41），后续语句可直接消费；同时给出 `D-BTS` 补充级提示。
4. **擦除**：运行时求值为 `Null`（Evaluator.kt:191），JS 代码生成完全不产出（JsCodeGen.kt:796/1514/1564）——证明只活在编译期。

### 与 Γ 闭包（MP）的关系

前提检验与结论证明都不是「点对点查表」，而是在 Γ 的**饱和闭包**上判定（Prop.kt:426-481）：

- 闭包做合取分解（`p ∧ (p → q)` 拆成 `p` 与 `p → q`）、∀ 单名实例化、**前向分离规则 MP**（`p` 与 `p → q` 产 `q`）、modus tollens（`p → q` 与 `¬q` 产 `¬p`）、矛盾产 `⊥`，迭代至不动点。
- 因此前提不必重复 Γ 中已由别处推出的事实：写 `axiom p ∧ (p → q)` 后，`∵ p, p → q ∴ q` 的两个前提会由闭包拆出，结论经 MP 自动成立。
- 结论证明时前提被临时加入 Γ（`f.allFacts() + premises`，Checker.kt:646）——所以前提本身也是后续推理的可用事实。
- 闭包的关键表达式集合在义务开始时固定、不随新事实膨胀（Prop.kt:429-431），防止复合项自我增殖导致笛卡尔爆炸；过于复杂时报 `E-DEEP-SATURATION`，建议拆成小步（Diffusion.kt:328-329）。

### 通道顺序与定理搜索

`proveOrDeep` 内部按序短路尝试（Diffusion.kt:278-337）：自定义命题展开 → 常量/类型判定 → 算术通道（ArithProve，不等式与等式链）→ 通用证明器（闭包）→ 定理搜索；激进模式（CLI 标志）额外开启反证法（需挂载 @classic）与命题维 ∀ 实例化。

- **定理空间**：只有 `@theorem` 标注的函数（以及块内局部函数，即 ∀ 引入）进入搜索空间（Diffusion.kt:339-340、Checker.kt:751-760）；命中判据是定理**后件与目标的结构合一**，theory 参数（如 `[p]`）是可绑定到任意项的元变量，搜索深度上限两跳（超限 `E-THEOREM-SEARCH-DEPTH`，Diffusion.kt:347-349）。
- **形式位（form）的现状**：解析后不被检查器使用——Checker.kt 的 BTS 分支只引用 `premises` 与 `conclusion`，`.form` 仅被语言服务与注解扫描器遍历（LspAnalysis.kt:662、AnnotationScanner.kt:91）。根文档《手动证明》所述「编译器按形式查找定理函数」在实现中由对**结论**的后件合一承担（待核：form 位未来是否回归形式匹配语义）。
- 因此「完整形态」里 form 目前是**文档性占位**：写成什么不影响检验结果（但必须可解析）。

### by 的供给语义

- `by […]` **不做任何证明**，直接把命题注入当前帧并给出 `D-BY` 补充级提示（Checker.kt:762-766、1264-1269）。
- 与 `axiom` 的区别（Ast.kt:255-258 注释）：axiom 是「公理声明」，by 语义上标注「这是人给的中间步骤」，诊断只走补充级，可被语言服务高亮为待补证明点。
- 语句位 `by […]` 返回 `Null`；表达式位 `expr by [q]` 类型与值都等于 `expr`（求值时只算目标，Evaluator.kt:250；JS 生成只保留目标，JsCodeGen.kt:930）——所以它能直接嵌在供给位，如 `g(f() by [前件])` 类形态（待核：角表显式供给与之的交互约定）。

## 示例

以下三例均经 `sublimation.jar check` 实跑通过（frontend/compiler 当前提交）。

### 1. 基本链：MP 闭包 + by + 算术通道

```subl
@impure fun main() {
    var x = 3                       // 注入 x : Nat、x = 3、x ≥ 0
    axiom p ∧ (p → q)               // 闭包拆成 p 与 p → q
    ∵ p, p → q ∴ q                  // 前提各自由 Γ 可证；结论经 MP 产 q 并注入
    var y = x + 1 by [x + 1 ≤ 5]    // y 是 4；同时直接供给 x + 1 ≤ 5
    ∵ x + 1 ≤ 5 ∴ x ≤ 4             // 算术通道：由 x = 3 链式推出
    ∴ x ≤ 4                         // 已在 Γ，直通
    print(y)
}
```

### 2. 定理形与完整形态

```subl
@theorem fun plusComm[a, b]: Null <a + b = b + a>

@impure fun main() {
    var n = 0
    ∴ (1 + 2) = (2 + 1)             // searchTheorems 后件合一命中 plusComm
    ∵ ∀n. (n : Nat) → (n ≥ 0),      // form 位（当前为文档性占位）
      n : Nat                       // 前提：由 var n = 0 注入的 n : Nat 可证
    ∴ n ≥ 0                         // 结论由 Γ 直接可证，注入
}
```

### 3. 裸形态：先证再注入

```subl
@impure fun main() {
    var n = 0
    ∵ n ≥ 0                         // 反糖为 ∵ ⊤ ∴ (n ≥ 0)：从 Γ 证出后注入
    ∴ n = 0                         // Γ 已含 n = 0，直通
}
```

### 4. 失败样例（实跑复现的诊断原文）

```subl
@impure fun main() {
    var x = 1
    ∵ ⊤, r ∴ r                       // 前提 r 不在 Γ
    ∵ x = 1 ∴ x = 2                  // 结论证不出
    when[p ∨ q] { p => { ∴ p } q => { ∴ q } }   // 析取式不在 Γ
}
```

对应诊断（CLI check 输出）：

- `E-PREMISE-UNPROVEN: 因为-所以的前提 r 没证出。当前已知事实 Γ：>=<1, 0>； >=<x, 0>； =<x, 1>； :<x, Nat>`
- `E-CANNOT-PROVE: 因为-所以的结论 =<x, 2> 证不出。已试的定理：（无定理函数）；当前已知事实 Γ：…`
- `W-PROP-UNBOUND: 分类讨论的析取前提 (p | q) 不在 Γ 中`（附带 `W-WHEN-NO-COMMON`）

## 陷阱

- **前提失败时结论不被检验**：`premisesOk` 为假时直接跳过结论证明（Checker.kt:646 的短路），所以一个 `E-PREMISE-UNPROVEN` 不会附带 `E-CANNOT-PROVE` 的二次定位——修前提时别等结论诊断。
- **form 位写错不报警**：当前实现不使用 form 匹配定理（见语义节），形式位与实际证明脱钩；反过来，指望「写对 form 就能调到定理」是错的，真正起作用的是结论的后件合一（待核）。
- **裸 `∵ p` 是「证明并注入」，不是「假设 p」**：前提必须已在 Γ 可证；要假设某命题成立再做推理，用分类讨论 `when[p ∨ q]` 的分支或 `if[p]` 的两支（分支内各自注入假设）。
- **换行不是 token**：结论/前提表达式的解析会吞掉下一行开头的 `by` 与符号算符（`+ - * / = < > → ∧ ∨` 等分支无同行检查，Parser.kt:1027/1071）——实踩：`∴ q` 换行接 `by [r]` 会解析成结论 `q by [r]`，报出形如「结论 `__t__<?>` 证不出」的怪诊断。只有 IDENT 中缀糖有同行约束（infixOperandAhead，Parser.kt:1103-1113）。换行处用 `;` 或调整语句顺序。
- **无优先级左结合**：`∴ 1 + 2 = 2 + 1` 被解析为 `((1 + 2) = 2) + 1` 而证不出；必须写 `∴ (1 + 2) = (2 + 1)`。
- **W-PROP-UNBOUND 不属于 ∵∴ 链**：它由分类讨论语句 `when[p ∨ q]` 在析取式不在 Γ 时发出（Checker.kt:660-662）；∃ 消去的前提缺失走的是 `E-PROP-UNBOUND`（warn 位，Checker.kt:742）——诊断码形似而触发点不同。
- **不纯表达式不参与结构相等**：含 @impure 调用的等式（如 `∵ log(1) = log(1)`）不会因「长得一样」而成立，只认 Γ 中显式事实（Diffusion.kt:159、CheckerTest.kt:1191）。
- **`+∵`（又因为）未接入文法**：lexer 产出独立 token PLUS_BECAUSE（Lexer.kt:15、114-115），但 Parser 的语句分派与表达式循环都没有它的分支，写出 `+∵ p` 会解析失败；语言服务仅在折叠层级识别它（LspAnalysis.kt:1505）（具体报错文案与其规划用途待核）。
- **`by` 关键字重载**：`impl C for T by field` 的委托位要求 `by` 后跟字段名（Parser.kt:969-978），与证明位的 `by [命题]` 形态互斥，别混用。
- **「已试的定理」仅含 @theorem 函数**：非 @theorem 的纯 Null 函数不进定理空间（Diffusion.kt:339-340），`E-CANNOT-PROVE` 里显示「（无定理函数）」多半是忘了标 @theorem。
- **证明语句在运行时被擦除**：`∴ q` 不产生断言或任何运行期效果（Evaluator/JsCodeGen 均丢弃）——想落运行期断言要另走别的机制（待核）。

# 注解处理器（解释执行版 v2）

注解处理器是一段**用 Sublimation 自己写的程序**，由解释器解释执行。它读注解、输出 AST 变换
（加/删注解），编译器在检查前统一应用，让注解真正改变代码的语义。

## 为什么要解释执行

处理器跑在解释器上（root doc 11）：它能调用语言本身的 when/递归/List，与被处理的代码同源，
不需要为处理器单独设计 DSL。编译器内置一个 `ProcessorEngine`：多轮驱动、幂等收敛、轮数上限保护。

## 管线位置

```
解析 -> 符号收集(阶段A) -> [注解处理器] -> 语义检查(阶段B/C) -> 代码生成
```

处理器**先于**语义检查跑：处理器的产出（如 `@allMut` 引入的 `@mut`）是"要被合法化的代码"，
变换后再统一进检查器，"所有代码都过检查"的契约仍然成立。

## 内建注解：@allMut

标在结构体上，表示**结构体可变且全部字段可变**。等价于把它改写：

```subl
@allMut
struct Point(x: Nat, y: Nat)

// 处理器变换为：
@mut struct Point(@mut x: Nat, @mut y: Nat)
```

然后 `var p: @mut Point = Point(1, 2); p.x = 5` 合法。

## 处理器文件（CLI 装载）

处理器脚本以 `.subs` 文件存在：

- **`annotation processer/`**（仓库根，默认目录）——内建的 `@allMut` 脚本就在这里：
  `annotation processer/allMut.subs`
- 文件主名 = 处理器名 = 关注的注解名（`allMut.subs` → 处理器 `allMut`，只对 `@allMut` 起反应）
- 文件里是普通脚本：顶层语句直接执行，用 `//` 注释（不支持 `#`），遍历列表用 `when(Nil/Cons)`

### 编译时附加处理器：`-p <路径>`

```sh
java -jar sublimation.jar compile demo/app -p "annotation processer"          # 装载默认目录
java -jar sublimation.jar compile demo/app -p myprocs/mine.subs               # 单文件
java -jar sublimation.jar compile demo/app -p procsA -p procsB -o out.js      # 可多次、与 -o 并用
```

路径不存在 / 不是 `.subs` 文件或目录 → `[错误] 注解处理器路径不存在`（退出 2）或
`E-PROCESSOR-LOAD`。无论是否传 `-p`，默认目录 `annotation processer/` 的处理器总会装载
（目录不存在时静默跳过，适合打包发布）。自定义示例：

```subs
// demo/cproc/twice.subs —— 标了 @twice 的函数，逐个报警告
fun warnAll(xs: List[Str]): Null = when(xs) {
    Nil -> null
    is Cons(s2, rest) -> {
        processorWarn(concat("twice hits ", s2))
        warnAll(rest)
    }
}
warnAll(funsWithAnnotation("twice"))
```

```sh
java -jar sublimation.jar check demo/cproc -p demo/cproc
# [警告] W-PROCESSOR-SCRIPT: twice hits helper
# [完成] 模块检查通过
```

## 写一个自己的处理器

处理器 = 一段脚本（脚本模式顶层语句直接执行）+ 关注的注解名。脚本通过一组宿主函数
（`@host` 注入解释器）只读查询声明、累积注解编辑：

| 宿主函数 | 作用 |
|---|---|
| `structNames(): List[Str]` | 全部结构体名 |
| `structsWithAnnotation(a): List[Str]` | 带注解 a 的结构体名 |
| `structAnnotations(n): List[Str]` | 结构体的注解列表 |
| `structHasAnnotation(n, a): Bool` | 结构体是否有注解 a |
| `structFields(n): List[Str]` | 结构体字段名（声明序） |
| `fieldAnnotations(s, f): List[Str]` | 字段的注解列表 |
| `funNames()` / `funsWithAnnotation(a)` / `funAnnotations(n)` | 函数族查询 |
| `addStructAnnotation(n, a)` / `removeStructAnnotation(n, a)` | 结构体注解增删 |
| `addFieldAnnotation(s, f, a)` / `removeFieldAnnotation(s, f, a)` | 字段注解增删 |
| `addFunAnnotation(n, a)` / `removeFunAnnotation(n, a)` | 函数注解增删 |
| `processorError(m)` / `processorWarn(m)` / `processorHint(m)` / `processorInfo(m)` | 报诊断 |

脚本执行期**不改 AST**——编辑函数只累积指令，引擎收尾时以不可变方式重建 AST
（root doc 3.2：处理器只能创建新实例）。增注解幂等：已存在不重复加，多轮自然收敛。<…>

### 示例：脚本处理器

```kotlin
val mine = ScriptProcessor(
    name = "mine",
    interestedAnnotations = setOf("verify"),
    scriptSource = """
        fun processStructs(xs: List[Str]): Null = when(xs) {
            Nil -> null
            is Cons(s, rest) -> {
                processorWarn(s)
                processStructs(rest)
            }
        }
        processStructs(structsWithAnnotation("verify"))
    """,
)

// 单文件管线
val (ast2, bag) = ProcessorPipeline.run(ast, listOf(mine))

// 多模块管线（宿主默认装了 @allMut）
val pbag = mm.processModules(ProcessorPipeline.builtinModuleTransformer())
```

脚本里不能用 `#` 注释（脚本模式顶层不支持）；递归遍历列表用 `when(Nil/Cons)` 即可。

### 编译管线默认装载

`check` / `compile` 默认装内建处理器（当前 `@allMut`）。
源码里没有任何关注注解时引擎整轮跳过，AST 引用不变，零开销。

## 诊断码

| 码 | 含义 |
|---|---|
| E-PROCESSOR-LOOP | 处理器循环不收敛（反复改写超过最大轮数） |
| E-PROCESSOR-ERROR | 处理器脚本执行失败（脚本类型检查/运行时错误） |
| E-PROCESSOR-SCRIPT | 处理器脚本主动调 processorError 报错 |
| W-PROCESSOR-SCRIPT | 脚本警告 |
| W-PROCESSOR-EDIT | 编辑的注解目标不存在（名字拼错？） |

## 宿主外壳（脚本宿主用法）

`AnnotationProcessorHost` 装了内建处理器，配合脚本模式的 @host 函数
（loadProject / processAnnotations / writeGenerated）可用脚本驱动整个处理流程。

## 限制（v2）

- 只能加/删注解，不能新增声明或改类型（v2 范围）；
- 处理器脚本的 `typeOf` 查询大多返回 null（类型信息在弥散上下文，不在 AST 上）；
- settings 里注册第三方处理器（`processor` 行）待定（root doc 12）。

# 宿主桥注册陷阱（同名内建遮蔽）

卷名：05-工程-宿主桥注册陷阱
主题域：工程与工具链 / 宿主互操作
事实来源：interpreter/src/main/kotlin/sugared/functor/interpreter/Interpreter.kt（register 重载、registerStdlib、hostEntries，行号以当前源码为准）；compiler/src/main/kotlin/sugared/functor/checker/{Types,Symbols,CallCheck,Checker}.kt；bug 实例为 t88（geometry.subs 第 21 行 forEach lambda 体报「E-TYPE-MISMATCH lambda 体类型 Any 与期望返回 Null 不符」，修复见提交 57c78e2）

脚本模式下宿主函数经 `register` 注册后会被注入为 `@host` 声明供 Checker 检查。**当宿主函数与内建表（`builtinimpure`/`builtinPure`）同名时，注入的声明会遮蔽内建签名**——若宿主侧签名不齐，调用点类型随之错乱，且只在 lambda 体位等「有期望类型」的位置暴露。本页记录这条链路、诊断方法与规避规则。

## 语法

### 注册重载与兜底签名

Interpreter 提供两个 `register`（Interpreter.kt:55 / 76）：

```kotlin
// 带签名（推荐）
fun register(name: String, vararg params: Pair<String, ScriptType>,
             retType: ScriptType = ScriptType.Null, fn: (List<Any?>) -> Any?)

// 无签名（兼容旧接口）——**retType 兜底为 Any**
fun register(name: String, fn: (List<Any?>) -> Any?) = register(name, retType = ScriptType.Any, fn = fn)
```

注释明说无签名时「签名按 Any→Any 处理」（Interpreter.kt:75）。注入侧（Interpreter.kt:156 起的 `hostEntries`）把宿主签名逐条翻成 FunDecl，其中 `ScriptType.Any` 直翻 `NamedType("Any")`（Interpreter.kt:170），形参为空时补一个 `x: Any`（Interpreter.kt:155 注释、:158）。

### 内建表与查找优先级

内建签名在编译器侧：`builtinimpure("print")` 的签名是 `(v: 任意) => Null`（Types.kt:57 起）。调用点解析走：

```kotlin
fun findFun(name): FunDecl? = funs[name] ?: builtinimpure(name) ?: builtinPure(name) ?: builtinAndroid(...)
//                                                ^^^^^^^^^^
```

`Types.kt:398`：**`syms.funs`（含注入的 @host 声明）优先于内建表**。于是 `@host print(x: Any): Any` 一旦注入，`print(...)` 的类型就是 `Any`，而非内建的 `Null`。

 注意：**纯度/副作用不受遮蔽影响**——`Symbols.kt:24` 在注册 `pure<f>` 事实时按内建表覆盖注解（`anns = builtin.annotations`），所以 `print` 依然算 `@impure`，`E-IMPURE-CALL` 等检查照常。被遮蔽的只有**签名本身**（形参与返回类型），这扩大了隐蔽性。

## 语义

### 症状：只在 lambda 体位暴露

以 t88 为例（geometry.subs:21，脚本模式 + `--global-inference`）：

```sublimation
shapes.forEach { s => print(s.describe() + " 面积=" + toStr(s.area())) }
```

`forEach` 的签名期望 lambda 返回 `Null`（core 标准库：`f: @impure (T) => Null`），而 lambda 体 `print(...)` 被遮蔽后的 `@host print` 类型化为 **`Any`**——`Checker.kt:1176` 的双向推导核对失败：

```
[E-TYPE-MISMATCH] lambda 体类型 Any 与期望返回 Null 不符
```

同一脚本里**其余 print 语句全部静默通过**：表达式语句位没有期望类型，`Any` 不与任何东西核对。这就是该 bug 的全部迷惑性——

- 不是全局类型推导的问题（不带 `--global-inference` 同样挂）；
- 不是 impl 方法返回类型没回流调用点（t88 原始假设，实为误判——describe 的 `: Str` 声明始终有效）；
- 不是 `forEach`/lambda 本身的问题。

三条排查线索全部指向别处，只有「有期望类型的值位」才让 `Any 显形。

### 根因链（t88 实测）

1. `registerStdlib()` 用**单参重载**注册 `print`：`register("print") { ... }` → `retType = ScriptType.Any`；
2. `hostEntries` 生成 `@host fun print(x: Any): Any` 注入待检文件；
3. Checker 收集后 `syms.funs["print"] = @host 声明`，`findFun` 因 `funs` 优先返回它，内建 `(v) => Null` 被遮蔽；
4. 全部 `print` 调用类型化为 `Any`；语句位无期望静默放行，lambda 体位期望 `Null` 时报 `E-TYPE-MISMATCH`。

geometry 是六个示例脚本中唯一在 lambda 体位调 `print` 的，故六脚本里只有它挂（bank/collections 全过）。

### 修复与规则

**修复**（Interpreter.kt:293，一行）：注册时显式给齐内建签名——

```kotlin
register("print", retType = ScriptType.Null) { args -> ... }
```

`@host` 声明即与 `builtinimpure` 的 print 签名一致，遮蔽不再产生类型分歧。修复后 `show/解释器` 六脚本 `--global-inference` 全部跑通（geometry 输出 圆(半径1) 面积=3.14 / … / 最大面积=10）。

**规则（写宿主桥时遵守）**：

1. **与内建同名的宿主函数必须显式对齐内建签名**（形参与返回类型），不要依赖兜底 `Any`；
2. 更稳妥的做法是**同名内建设不注册**——Checker 经内建表自行解析签名，`register` 仅作 Evaluator 兜底实现（Interpreter.kt:292 注释原本就是这个意图，但注册仍会注入声明）；
3. 新增宿主内建后，**在 lambda 体位做回归**（`xs.forEach { x => myHostFn(x) }` 形态），语句位测试发现不了这类遮蔽；
4. 若要彻底切断遮蔽，需改注入逻辑：`@host` 声明对 `builtinimpure`/`builtinPure` 已收录的名字整条跳过（本页成文时未做，属后续可选改进）。

### 诊断清单（遇到「lambda 体类型 Any」类报错时）

- 报错的调用名是否在宿主注册表里？看 `registerStdlib()`（或用户侧 `register` 调用）用的是哪个重载；
- 该名字是否同时在 `builtinimpure`/`builtinPure`（Types.kt:56 / :162 起）？在 → 遮蔽风险；
- 查注入声明：`hostEntries` 翻出的 `retType` 是否为 `Any`（`ScriptType.Any` 兜底的直接标志）；
- 对比内建签名：`findFun` 命中的是 `funs[name]`（@host）还是内建表。

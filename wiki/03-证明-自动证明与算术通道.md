# 自动证明与算术通道

> 主题域：自动证明机制——算术通道（ArithProve）、Γ MP 闭包、命题维 ∀ 实例化、激进模式 CLI 开关
> 事实来源：_langfacts.md §4/§8；compiler/.../checker/ArithProve.kt（410 行）、Aggressive.kt（309 行）、Prop.kt、Diffusion.kt、Checker.kt；cli/.../Main.kt；根文档《手动证明.md》（§策略 结构参照）

证明义务（`∴ q`、`∵ … ∴ q`、when 穷尽、上文约束）并不依赖用户手工找定理：编译器内部有一条**自动证明流水线**，其中**算术通道**（ArithProve）专门裁决整数线性算术片段——把约束归一为 `Σ cᵢ·vᵢ ≤ C`，用常量折叠、绝对界、差分图（Bellman–Ford）与等式链代换定谳；**Γ MP 闭包**（Prover.closure）做命题层面的饱和推理；**激进模式**（`--prover=aggressive`）在健全性底线不变的前提下把搜索做得更深更广。

## 语法

### 喂给算术通道的命题形态

```subl
∴ (1 + 1) = 2                    // 常量折叠：纯整数 + - * / 表达式
∴ x + 1 ≤ 5                      // 移项：左端含变量的线性不等式
∴ 2 * y ≤ 6                      // 系数提取（一侧须为常量）
∴ a ≤ c                          // 差分传递：Γ 里已有 a ≤ b、b ≤ c
∴ x = z                          // 等式链：x = y ∧ y = z
∴ x in (1 .. 3)                  // 区间原子（in + 区间 ..）（∴ 位表层语法待核）
when[n < 0 ∨ n == 0 ∨ n > 0] { … }   // 析取穷尽目标：单变量叶子域差集反证
@simp[(3 * 2 + 6) = 12]           // 策略语句：点名调用算术通道
```

可被通道消费的前提/目标形态（ArithProve.kt:81–104, 282–315）：

- 比较原子 `=` `==` `!=` `≠` `<` `>` `<=` `≤` `>=` `≥`（命题层 ASCII⇄Unicode 归一）；
- 区间原子 `x in (l .. r)`（`in` 的 PAtom，区间两端须为整数字面量）；
- 合取前提 `p ∧ q` 自动拆开逐条消费；否定前提 `¬p`（p 为比较原子）并入图参与矛盾检测。

进入 Γ 的语法入口：`axiom p1, p2`（顶层与函数内通用）、上文约束位 `<a ≤ b>`、`∵ p1, p2` 前提、下文弥散事实、`expr by [q]`。

### CLI 开关

```
sublimationc check <文件|目录> --prover=aggressive
sublimationc compile <文件|目录> -o out.js --prover=aggressive
  --prove-verbose             提高进度输出频率
  --prove-dump=<路径>          诊断报告路径（默认 sublimation-prover-dump.md，仅中断时写）
  --prove-interval=<2s|500ms> 进度节流间隔（默认 5 秒）
```

`--prover=aggressive` **只作用于 compile/check**（Main.kt:34–39, 195–200）；无中间档。进程级语义：Ctrl-C → 中断位 → 诊断报告 + 退出码 130（详见语义节「中断与报告」）。
## 语义

### 通道在证明流水线里的位置

`proveOrDeepInner` 按序尝试各通道，**命中即短路**（Diffusion.kt:278–337）：自定义命题展开 → 否定/蕴含常量拆解 → 常量原子真值 → 常量类型 → 纯度结构相等 → 类型判定 → 常量归约 → Real 代数重写 → **线性算术** → 通用证明器 → 反证法（@classic）→ 定理搜索。算术通道刻意靠前：用更精确的判定率先定谳，避免被后续宽通道误吞。注意其短路条件唯一为 `ArithProve.proves(gamma, goal) == true`（Diffusion.kt:326）——**判 false 或 null 都继续**走后续通道。

### 三态语义与健全性底线

- `true` = 片段内判定成立 → 短路返回；
- `false` = 片段内判定**不成立**（如 `a ≤ b ∧ b ≤ c` 下问 `c ≤ a`）→ 不短路，交给后续通道；
- `null` = 形态不在片段内（如 `x * y` 双非常量、字段访问 `self.x`、`x : T`）→ 跳过。

健全性（ArithProve.kt:19–20, 45–47）：无法表达的前提**直接跳过**——少用前提只会更保守，绝不因无关事实放弃通道；片段内前提矛盾（负环/界空）→ 蕴含一切（爆炸原则）：

$$\frac{\Gamma \vdash \bot}{\Gamma \vdash \varphi} \quad (\text{爆炸})$$

### 线性化与常量折叠

所有项先经 `linOf` 归一为线性型 `Σ coefs·v + c`（ArithProve.kt:173–201）：整数字面量、变量名（系数 1）、一元负、`+`/`-` 任意组合；`*` 只允许一侧为常量（`2 * y` 收系数，`x * y` 返回 null）；`/` 只在整除精确时折叠（`10 / 2 → 5`，`7 / 2` 不可表达）。纯常量目标直接由 `evalConst` 判真值（`(3 * 2 + 6) = 12` 两边各折叠为 12 后判等）。

### 绝对界（单变量 + 系数）

单变量约束 `a·v ≤ C` 收紧绝对界 `[lo, hi]`（整数上/下取整，两端安全，ArithProve.kt:136–150）：

- `x + 1 ≤ 5` 移项 → `hi(x) = 4`；`2y ≤ 6` 系数 → `hi(y) = 3`；`-x ≥ 5` → `lo(x) = -5`；
- `lo(v) > hi(v)` → 矛盾（`contradicted`，`proves` 直接返回 true）。

### 差分图（双变量 ±1）

双变量约束 `x − y ≤ C` 建差分边（ArithProve.kt:151–160）：边 `[from, to, w]` 的含义是 `to ≤ from + w`。`a ≤ b` 产生边 `b → a` 权 0；`x ≤ y + 2` 产生边 `y → x` 权 −2。传递性由 Bellman–Ford 最短路涌现（ArithProve.kt:238–252）：

$$\frac{a \le b \quad b \le c}{a \le c} \quad (\text{差分传递})$$

前提集负环 = 前提矛盾 → 爆炸。目标侧用反证：`¬(a ≤ b)` 并入图判负环即证 `a ≤ b`（negateAndApply，ArithProve.kt:317–352；`a ≤ b ∴ b ≥ a` 走此路）。

### 等式链代换

`x = y` 在命题层是原子约束，通道把它拆成 `≤` 与 `≥` 两侧（ArithProve.kt:115–127，M7 快照回滚：任一侧不可表达则整体不注入，避免半注入残留）——等价于**双向差分边**。于是 `x = y ∧ y = z ∧ z ≤ 7` 中，等式链把上界传播到 x：`upperBound` 把单变量界转 ZERO 边后从 ZERO 出发求最短路，`upper(x) = 7`（ArithProve.kt:254–278）。两变量等式目标判 ≤ 与 ≥ 双向蕴含都成立：

$$\frac{\Gamma \vdash x \le y \quad \Gamma \vdash x \ge y}{\Gamma \vdash x = y} \quad (\text{等式引入})$$

### 析取目标反证（when 穷尽）

`POr` 目标在叶子都是同一变量的单变量域比较时，用叶子域差集反证（disjRefute，ArithProve.kt:354–372）：`Γ` 的 `[lo(v), hi(v)]` 依次减去每个析取支的区间，差集空 ⇒ 穷尽成立。`in` 目标同样走区间比较（ArithProve.kt:284–289），但只读绝对界 `lo/hi`，不吃差分链传播来的相对界（见陷阱）。
### Γ MP 闭包（普通模式）

`Prover.closure` 的饱和闭包（Prop.kt:426–481）：合取分解 + **∀ 单名实例化**（候选项 = Γ 现有项 ∪ 目标项的 ground terms）+ 前向 MP + modus tollens + 矛盾检测（`p` 与 `¬p` 同在 → `⊥`），迭代至不动点或有界轮数（普通模式 `maxRounds = 3`，Checker.kt:41）。

$$\frac{p \quad p \rightarrow q}{q} \quad (\text{MP}) \qquad \frac{p \rightarrow q \quad \neg q}{\neg p} \quad (\text{MT})$$

关键表达式集合**一次性固定**（Prop.kt:429–431）：从初始事实与目标收集一次后不再随新增事实扩张，否则复合项会自我增殖（`(1+2) → (1+2)+(2+1) → …`）笛卡尔爆炸、永不达不动点。实例化矩阵（`∀` 的候选替换）预计算一次，避免每轮 Kⁿ 重建。

### 激进模式（`--prover=aggressive`）

激进模式是**更彻底的搜索，不是更宽松的判定**（Aggressive.kt:7–17）：健全性底线——不猜、不近似、不接受未证前提；池的守门人是「有约束来源」：候选只来自程序里实际出现过的项/类型/命题，超出的构造一律不做。

- **会话与搜索上限**：`aggressive` 时才创建 `ProverSession`（Checker.kt:37–39），`Prover` 的 `maxRounds` 由 3 改为 `Int.MAX_VALUE`（Checker.kt:41）——饱和**轮数无上限，靠不动点判据退出**（本轮无新事实即停，Prop.kt:484–487）；深度走迭代加深；正向记忆化**只记已证**（失败可能只是深度不够，记失败会误杀）。
- **三维关键池**（KeyPool，Aggressive.kt:198–231）：表达式维（代码 AST 子项 + Γ ground 项，上限 500）、类型维（`:` 事实右端 + 符号表类型名提示，上限 200）、命题维（Γ/目标里出现的一切子命题，上限 200）。超限时按与目标重叠度排序后截断。
- **命题维 ∀ 实例化**（dimsOf，Aggressive.kt:256–280）：名字在体里的位置决定去哪个池取候选——裸原子 `p`（0 元）→ **命题池**；`:` 事实右端 `T` → 类型池；其余项位置 → 表达式池；无命中默认表达式维。每条 ∀ 的实例化取候选的笛卡尔积，受 `maxCombos = 4096` 截断（Aggressive.kt:41, 283–309）。典型场景：`axiom ∀p. p ∨ ¬p` 的 `p` 分派到命题池，实例化出 `r ∨ ¬r`——普通模式只有表达式维，命题变量实例化不出来。
- **反证法与前向排中律**：`Γ ∪ {¬goal}` 饱和出 `⊥` ⇒ `Γ ⊢ goal`（Prop.kt:416–420，Diffusion.kt:330–333），以及排中律形态定理（后件形如 `p ∨ ¬p` 的 @theorem）的前向注入（lemAugment/lemPosts，Diffusion.kt:260–276）——**仅经典逻辑**：未挂 `core.classic` 绝不启用（直觉主义只得 `¬¬goal`；健全性看守测试见 AggressiveModeTest.kt）。
- **进度与中断**：每步记数，逢节流阀（默认 5 秒或 100 步）打 stderr 一行——含已证/待证义务数、当前目标、当前 Γ 前 4 条、最近尝试的定理、三维池规模（Aggressive.kt:99–130）。Ctrl-C 经 shutdown hook 置中断位（Main.kt:197–199），搜索循环在下一个 `checkAbort` 抛 `ProverInterrupted`（Aggressive.kt:21–22, 132–137），checker 内无吞异常，一路打到 CLI：`writeReport` 写诊断报告后 `halt(130)`（Main.kt:359–365）。报告四节：卡住的目标 + 完整 Γ、证明义务已证/总计、搜索统计（总步数、池规模、最近定理）、提交 issue 的模板（Aggressive.kt:140–174）。
- **不停机风险**：不动点判据不保证到达（这正是「可能很慢甚至不停机」的实现根源）；池上限与 `maxCombos` 只截搜索不损健全性。

## 示例

### 常量折叠与移项

```subl
@impure fun main() {
    ∴ (1 + 1) = 2              // 两侧 evalConst 各折叠为 2
    ∴ 10 / 2 = 5               // 整除精确才折叠
    var x = 3
    ∵ x + 1 ≤ 5                // hi(x) = 4（x = 3 亦注入事实，x + 1 ≤ 5 可证）
    ∴ x ≤ 4
}
```

### 差分传递（上文约束位入 Γ）

```subl
fun transit<a, b, c><a ≤ b, b ≤ c>: Null {
    ∴ a ≤ c                    // 差分图传递：c → b → a
    ∴ b ≥ a                    // 否定蕴含：¬(b ≤ a) 并入图判负环
    // ∴ c ≤ a                 // 反例：推不出——通道判 false，此处编译报 E-CANNOT-PROVE
}
```

### 等式链代换

```subl
fun eqChain<x, y, z><x = y, y = z, z ≤ 7>: Null {
    ∴ x ≤ 7                    // 等式双向差分边 + ZERO 边传播 upper(x) = 7
    ∴ x = z                    // ≤ 与 ≥ 双向蕴含皆成立
}
```

### 策略指名调用

```subl
@impure fun main() {
    @simp[(3 * 2 + 6) = 12]    // 策略语句 → simpProve → ArithProve（Checker.kt:688, 1445）
}
```

### Γ 闭包与 ∀ 实例化（普通模式即可）

```subl
@impure fun main() {
    axiom forall n. tagged<n>
    ∵ forall m. tagged<m>
    ∴ tagged<3>                // 表达式维实例化：m 分派 Γ 中的项 3
}
```

### 激进模式专享：命题维与反证法

```subl
// 以下三个函数均需 @classic 挂载（core.classic）
@classic
fun propInst[r]: Null {
    axiom ∀p. p ∨ ¬p
    ∴ r ∨ ¬r                   // 普通模式证不出：p 是命题变量，一维池无候选
}

@classic
fun raaCase[@p, @q]<¬p → q, ¬p → ¬q>: Null {
    ∴ p                        // 反证：假设 ¬p 饱和出 q ∧ ¬q → ⊥
}

@classic
fun lemCase[@p, @q]<p → q, ¬p → q>: Null {
    ∴ q                        // 排中律前向注入后两支分情况都出 q
}
```

编译：`sublimationc compile proj/ --prover=aggressive`。长时间搜索时可 Ctrl-C：

```
[激进证明] 已证 12 / 待证 30 | 搜索中
  当前目标：q
  当前 Γ 相关事实：p → q， ¬p → q（共 2 项）
  最近尝试的定理：LEM
  池规模：表达式 88 | 类型 12 | 命题 31（步 1402）
^C
# 写出 sublimation-prover-dump.md，退出码 130
```

## 陷阱

- **算术通道只覆盖整数线性片段**：`x * y` 双非常量、`7 / 2` 非精确除、`self.x` 字段访问、`x : T` 类型事实——`linOf` 返回 null → 通道**跳过**（返回 null），不是「假」。Rat/Real 等式走 Real 代数重写通道（Diffusion.kt:318–322），也不是这里。
- **「判不成立」不等于「报错」**：只有 `== true` 才短路（Diffusion.kt:326）；false/null 继续走通用证明器、定理搜索。因此「通道说假但目标仍被证出」可能来自其他通道；反过来，片段内的 false 是准确的。
- **等式拆双向边可能整体跳过**：`x = self.y` 右侧不可线性表达时，M7 快照回滚使整条等式**完全不注入**（ArithProve.kt:115–127），不会出现「半截约束」——但也意味着该等式在通道内不可用。
- **`in` 目标只读绝对界**：`atomImplied` 的 `in` 分支只查 `lo/hi`（ArithProve.kt:284–289），不查 `upperBound` 的差分链传播；`x = y ∧ y ≤ 5` 下问 `x in (0..10)` 可能因 `hi(x)` 未直接收紧而漏判（是否由后续通道兜底待核）。`∴ x in (1 .. 3)` 的 ∴ 位表层语法亦待核；when 分支条件位的 `x in (90 .. 100)` 已有测试（CheckerTest.kt:663）。
- **普通模式有界**：`maxRounds = 3`、深度有限，链式 ∴ 证不出**不等于不可证**；深度饱和仍未证出报 `E-DEEP-SATURATION`，把大结论拆成小步骤（`+…` 与 `∴ …` 逐步推）。
- **keyTerms 一次性固定**：饱和运行中新生的复合项不再成为实例化候选（防自增殖的代价）——需要某个实例化候选时，最好事先在 Γ/目标里显式写出该项。
- **激进模式可能不停机**：饱和靠不动点退出，不保证到达；Ctrl-C 才是正常退路（报告 + 130）。进度行只在节流阀触发时打，`--prove-verbose` 提高频率。
- **池与组合上限是搜索截断**：`maxExprs = 500`、`maxTypes = 200`、`maxProps = 200`、`maxCombos = 4096`（每条 ∀）——截断只少搜，不猜；大项目里被截掉的候选不会被补造。
- **反证法/排中律前向实例化需 @classic**：未挂 `core.classic` 绝不启用，直觉主义下 `¬p → q, ¬p → ¬q` 只给 `¬¬p`——这不是 bug，是健全性看守。
- **记忆化只记已证**：同一目标重复证不会积累「失败结论」，迭代加深后仍可能证出。
- **`--prover=aggressive` 只作用于 compile/check**：run / run-script 等子命令不受影响；挂了标志的编译**不会**把证不出的目标放过——证不出照报 `E-CANNOT-PROVE` / `E-PREMISE-UNPROVEN`。
- **命题维实例化的候选只来自程序里出现过的命题**：池的守门人是「有约束来源」——不枚举命题空间，`∀p. p ∨ ¬p` 的 `p` 只能分派到 Γ/目标里实际存在的子命题（Aggressive.kt:196, 213–224）。
- **`@` 前缀的定理参数是元变量**：排中律 `@theorem fun LEM[@p]: Null <p ∨ ¬p>` 的 `@p` 在定理搜索/实例化时绑定到目标对应位置，与普通函数参数语义不同（根文档《手动证明.md》§定理）。

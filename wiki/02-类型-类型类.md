类型类是语言的接口抽象机制：`class` 声明一组方法签名（≈ Haskell typeclass / Rust trait），`impl <类型类> for <类型>` 给具体类型提供实例。方法不绑定到类型本身，而由编译器按接收者类型查「字典」分发——类型类是**编译期约束、无运行时 tag**（Checker.kt:1423）。标准库三大容器抽象 Functor / Foldable / Monad 即以此形态声明（core/collection/typeclass.subl），数学律（函子律、单子律）写在注释里作为实现依据，不由语言检查。

## 语法

### 声明：class

```subl
class Show[T] { fun show(): Str }                     // 普通类型类：成员无接收者形参（隐式 self）
class Num { }                                         // 无成员可省花括号（≡ class Num）
class Functor[F[_]] {                                 // HKT：F 是 arity 1 的类型构造子形参
    fun map[A, B](fa: F[A], f: (A) => B): F[B]
}
class Foldable[F[_]] {
    fun fold[A, R](fa: F[A], init: R, f: (R, A) => R): R
}
class Monad[F[_]] : Functor[F] {                      // 子类型类：父类型类逗号分隔
    fun pure[A](x: A): F[A]
    fun flatMap[A, B](fa: F[A], f: (A) => F[B]): F[B]
}
```

文法（parseClass Parser.kt:860-891）：

- `class 名 理论参数? : 父类型类, …? { 成员fun … }`，**只能写在顶层**（parseEntry :195）
- 理论参数（parseTheory :339-380）：`[T]` 普通类型变量、`[T: Show]` 带类型类约束、`[F[_]]` kind 形参（arity 1）、`[F[_, _]]`（arity 2）、`[F[_]: Foldable]`（v3.0 起 kind 形参也可带约束）、`[@p]` 命题参数
- 成员是 FunDecl：**无体 = 抽象签名**；带体 = 默认实现（v3.0 特性 4，impl 缺该方法时自动补齐，CheckerTest.kt:1410）；可带注解（`@impure` / `@mut`）
- kind 形参的 arity 是实参个数（kind `*→*…` 的广度），0 = 普通类型变量（Ast.kt TypeParam）

### 实例：impl 的五种形态

```subl
//① 经典：impl <类型类> for <实例类型>
impl Functor for List[a] { … }          // 零实参小写名 = 隐式类型变量（字典名只取构造子名）
impl Monad for Optional[a] { … }
impl Tuple for (a, b) { … }             // self 可以是元组形状（类型族实例）
impl Show for Nat { … }                 // self 可以是内建类型

//② 简写（无 for）：impl <类型类>[实例头[…]]
impl Functor[List]                      // ≡ impl Functor for List[a]
impl Functor[Result[_, E]]              // _ 是 kind 应用槽，E 是成员可引用的隐式类型变量

//③ 无类型类（单纯方法添加，承担重载职责）
impl List[a] { fun doubled(): List[a] = self.map({ x => x + x }) }

//④ 委托
impl Showable for B by a                // 未写的方法转发到 a 字段的同名方法

//⑤ 带默认实现的类只写差异方法
class M { fun f(): Nat = 1 }
impl M for S { }                        // f() 由默认实现补齐
``
（parseImpl Parser.kt:949-995；③ 在 parseFile :151-163 直接脱糖为带 `self` 首参的自由函数、self 的 kind 占位提升为该函数的类型参数——AST 级展开，后续全链路零感知。）

### 成员签名的两种接收者形态

| 类型类形态 | 成员签名 | 接收者 | JS 字典签名 |
|---|---|---|---|
| 普通类型类（无 arity>0 形参） | `fun show(): Str` | 隐式 `self`（体内裸用，字段名 ⟝ self.field） | `(d, __self, args…)` |
| kind 类型类（含 `[F[_]]` 等） | `fun map[A, B](fa: F[A], f: …): F[B]` | kind 应用位形参 `fa` | `(d, f, fa…)`（无 __self） |

（JsCodeGen.kt:622-627、Evaluator.kt:610-623）kind 应用位由类声明签名决定（`fa: F[A]` 是第几位形参都行，hktKindParamIndex CallCheck.kt:552-565）；标准库一律把 fa 放在首位。

impl 成员可带注解；**不属于类声明的方法必须标 `@new`**，否则 E-IMPL-EXTRA（CheckerTest.kt:136）。

### 调用形态

```subl
xs.map({ n => n * 2 })              // 点号式：接收者插进 kind 应用位（fa）
map(xs, { n => n * 2 })             // 自由式：fa 在首形参位（接收者即首实参）
o.printMyself()                     // 普通类型类点号式：接收者 → __self
show(Good())                        // 普通类型类自由式：首实参即接收者
xs.fold(0) { acc, x => acc + x }    // 尾随 lambda = 末位实参糖
```

- 方法路径（点号式 / 自由式方法形态）**不支持命名参数** → E-NAMED-ARG（CallCheck.kt:147）
- 自由式 `m()` 没有接收者 → E-NO-SELF（CallCheck.kt:329）

### 约束式泛型

```subl
fun showAll[T: Show](xs: List[T]): Str = xs.fold("") { acc, x => acc + x.show() }
fun inc[F[_]: Functor](xs: F[Nat]): F[Nat] = xs.map({ n => n + 1 })
``
约束写在函数/类型的方括号理论参数位（`[T: Show]`、`[F[_]: Foldable]`），不是尖括号。

## 语义

**类型类 = 编译期约束 + 字典分发。** 调用点按接收者类型解出唯一实例，把该实例的字典作为隐藏实参传入；接收者表达式本身仍按普通实参位传递：

$$rac{Gamma \vdash e : T \qquad \texttt{impl} C\ \texttt{for} T \in \Pi}{\Gamma \vdash e.m(\bar{a}) \Rightarrow \texttt{dict}\_C\_T.m(\texttt{dict}\_C\_T, e, \bar{a})} \quad (\text{字典分派})$$

### 字典分派（决策 60）

- impl → JS 字典对象：`const dict_Functor_List = { map: function(d, f, fa) { … } }`（genDict JsCodeGen.kt:610-645）；跨模块声明带模块前缀 `dict_<模块>_<Trait>_<Type>`
- kind self（`List[a]` / `Result[_, E]`）的字典名只取**构造子名**（dict_Functor_List / dict_Functor_Result，ImplCheck.kt:77-86）
- 自由式与点号式统一：生成 `dict.m(dict, 接收者, …)`（JsCodeGen.kt:1388-1439）
- 解释器（run-script / 工程模式解释执行）按**运行时类型 tag** 查 `methodImpls`（Evaluator.kt:598-608）；多候选立即抛消歧错误

### 约束字典槽（P6，决策 82）

`fun f[T: Show]` 的 JS 签名带隐藏槽参 `d_Show_T`：体内 `x.show()`（x: T）走槽而非全局 impl（Checker.kt:317-321、CallCheck.kt:336-352）；调用点按 T 的实例化类型注入字典实参，如 `showAll(Cons(1, Nil()))` → `showAll(dict_Show_Nat, xs)`（JsCodeGen.kt:1439；E2E 验证 ModuleE2ETest.kt:314-323）。

### 隐式 self 提升（O2，决策 68）

- impl 成员体内**不写接收者**：`checkFun(fn, selfT)` 往帧里注入 `self` 变量 + 结构体字段，字段裸名 ⟝ self.field（injectSelfAndFields Checker.kt:481-503）；`@mut` 方法体内 self 持 @mut 视图（可改实现结构体的可变属性）
- 形参名遮蔽字段 → H-FIELD-SHADOW（遮蔽合法，但提醒裸名从此指向参数，Checker.kt:350-352）
- HKT 形态不注入 self（接收者就是 fa 形参）
- 无类型类 impl 的 AST 级提升（parseFile :151-163）：`impl List[a] { fun m(): … }` → `fun m[a](self: List[a]): …`，kind 占位 a 升格为函数类型参数

### 实例解析与诊断

`resolveDict` 按方法名 + 接收者类型匹配（占位通配：`List[a]` 的 a 接受任何同位置实参，ImplCheck.kt:240-267）：

- 零匹配 → **E-NO-INSTANCE**（并提示「写一个 impl <类型类> for <类型>」）
- 只有 class、没有任何 impl：方法名仍登记为候选（syms.traitMethods），调用报 E-NO-INSTANCE 而非「未定义函数」（决策 60，Symbols.kt:171）
- 多匹配：仅当存在**父子类型类关系**时子类实例胜出（Rust 子特质语义）；无关实例 → **E-AMBIGUOUS-INSTANCE**（ImplCheck.kt:115-123）
- `Any` 是自动类型类（恒满足、零方法无字典）；`Nothing` 是底类型，任何约束对它都跳过字典（Types.kt:8、ImplCheck.kt:139）
- impl 顶层检查：类型类未声明 E-UNBOUND-NAME；缺方法 E-IMPL-INCOMPLETE（类有默认实现则补齐）；签名不一致 E-IMPL-MISMATCH；多出方法未标 @new → E-IMPL-EXTRA；委托字段不存在 E-BY-UNBOUND（ImplCheck.kt:17-70、:299-306）

### 子类型类（v2.1）

`class Sub[T] : Base[T]`：`impl Sub for X` 时**必须先实现父类型类**（checkSubTraitParents，父类 impl 可以声明在后，收集完成后统一检查），否则 E-NO-INSTANCE 并引导先写父类 impl；父类字典因此恒可用（Ast.kt ClassDecl 注、ImplCheck.kt:222-235）。`isSubTrait` 沿父链传递判定，用于多实例分派时选最具体者。

### 标准库实例清单（core/，标准库即事实）

| 类型类 | 声明 | 实例 |
|---|---|---|
| `Functor[F[_]]`（map） | typeclass.subl:12 | List、Optional、Set |
| `Foldable[F[_]]`（fold，f 为 `(R, A) => R`、累积在前） | :20 | List、Optional、Set |
| `Monad[F[_]] : Functor[F]`（pure / flatMap） | :27 | List、Optional（**Set 无**） |
| `Tuple`（size / isEmpty） | tuple.subl:6 | EmptyTuple、SingleTuple[a]、(a,b) … (a,…,j) 共十种元组形状 |
| `Num`（标记类型类，无成员） | num.subl:9 | 仅 Rat——数值族宽松匹配，`f(true)` 报 E-NO-INSTANCE |

标准库自身两种调用形态混用：list.subl 的 map 体内递归写 `t.map(f)`（点号式），fold 体内写 `fold(t, f(init, h), f)`（自由式），同一路由。`Result` 是二阶类型（T*E 双参数），**没有 Functor/Monad 实例**——成功路径映射走自由函数 `mapOk` / `flatMapOk`（typeclass.subl 注释、result.subl:32）。

## 示例

### 普通类型类：Show（examples/类型类.subl，可运行）

```subl
enum Grade { Excellent(), Good(), Pass(), Fail() }

class Show[T] { fun show(): Str }

impl Show for Grade {
    fun show(): Str = when(self) {        // 隐式 self：接收者在体内裸用
        Excellent() => "优秀"
        Good() => "良好"
        Pass() => "及格"
        Fail() => "挂科"
    }
}

@impure
fun main() {
    unchecked print(show(Good()))         // 良好（自由式：首实参即接收者 → dict_Show_Grade）
    unchecked print(show(Fail()))         // 挂科
}
```

### 隐式 self + 字段裸用（同上示例）

```subl
struct A(name: Str = "unknown")
class Boast {
    @impure
    fun printMyself()
}
impl Boast for A {
    @impure
    fun printMyself() {
        print(name)                       // 裸字段名 ≡ self.name
    }
}
``

fun main() {

    print(xs.map({ x => x + 1 }).fold(0) { acc, x => acc + x })   // 5（fold 尾随 lambda）

## 陷阱

1. **只有 class、没有 impl** → 调用报 E-NO-INSTANCE（不是「未定义函数」）。诊断会让你写 `impl <类型类> for <类型>`。同理：`Set.flatMap`、`Result.map` 这类「看起来该有」的方法——Set 无 Monad 实例、Result 无 Functor/Monad 实例（用 mapOk / flatMapOk），都会落到 E-NO-INSTANCE。
2. **无关多实例歧义**：同一类型对同名方法有多个 impl 且无父子类型类关系 → E-AMBIGUOUS-INSTANCE；想让编译器自动选，得让类型类之间有继承关系（子类型类实例优先）。
3. **子类型类先父后子**：`class Sub : Sup` 时 `impl Sub for X` 前必须先 `impl Sup for X`，否则 E-NO-INSTANCE「必须先实现它的父类型类」（父类 impl 允许声明在文件后部，收集完才检查）。
4. **impl 必须补齐类声明的全部方法且签名一致**：缺方法 → E-IMPL-INCOMPLETE（除非类里有默认实现）；签名不一致 → E-IMPL-MISMATCH；多出来的方法要标 `@new`，否则 E-IMPL-EXTRA。
5. **kind 占位不要混用**：经典形态 `impl Functor for List[a]` 的 a 是隐式占位（通配匹配、字典名取 List）；简写形态 `impl Functor[Result[_, E]]` 里 `_` 才是 kind 应用槽，零实参大写名（E）是保留绑定（成员签名可引用）。把 E 当槽位或把 a 当具名变量都会让字典命名 / 签名匹配错位。
6. **两种接收者形态不可混写**：普通类型类成员不声明接收者（隐式 self，点号式收者进 __self）；kind 类型类成员必须把接收者写成 `fa: F[A]` 形参（字典签名无 __self）。写错 → 字典签名错位或 E-IMPL-MISMATCH。
7. **自由式的接收者位置固定不可乱放**：普通类型类固定是首实参（`show(Good())`）；HKT 按 kind 应用位（标准库形态 fa 在首位：`map(xs, f)`）。若自定义 HKT 成员把 fa 写成第二位（`map(f, fa)`），编译模式按 kind 位解出，但 `run-script` 解释器按**首实参**找接收者——`map(f, xs)` 在解释器里会报「未定义的函数」。待核：解释器对 fa 非首位的支持范围（Evaluator.kt:524-532 按首实参走字典分发）。
8. **方法路径不支持命名参数**（E-NAMED-ARG）；`m()` 自由式无接收者（E-NO-SELF）需写成 `x.m()` 或 `m(x)`。
9. **`is` 不能判断类型类**（`x is Show` → E-TYPE-MISMATCH）：类型类是编译期约束、无运行时 tag（对齐 Rust 语义）。
10. **@mut 类型类方法**只能在接收者持 @mut 视图时调用（`var o : @mut T`），否则 E-NOT-MUT；方法内 self 相应持可变视图。
11. **委托 by 的字段必须存在**（self 须为结构体且有该字段），否则 E-BY-UNBOUND；转发方法签名照抄类声明。
12. **约束是编译期的**：`[T: Num]` 只给 Rat 一个实例，靠数值族宽松匹配（Nat/Int/Rat 互相放行），Bool/Str/结构体不命中——`fun f[T: Num](n: T): T = n` 对 `f(true)` 报 E-NO-INSTANCE。

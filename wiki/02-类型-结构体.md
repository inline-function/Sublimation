# 结构体（struct）

> wiki/02-类型-结构体 · 主题域：struct / 字段默认值 / 命名字段构造 / @mut 字段 / @mut struct / 伴生命题

结构体是语言的**乘积类型（product type）**载体，与枚举（和类型）互为表里：一个名义类型 + 一组**带名字**的字段，每个字段可有默认值。它同时是可变性的落地场——`@mut` 字段与 `@mut struct` 把「谁可以改、以什么身份改」写进类型；也是命题系统的一等公民——声明位的**伴生命题**让构造承担证明义务。

## 语法

### 声明

```subl
struct Point(x: Nat, y: Nat)                        // 基本形态：圆括号字段表
struct User(name: Str = "unknown", age: Nat = 0)    // 字段默认值（决策 69，O3）
struct Pair[A, B](first: A, second: B)              // 泛型（theory 头）
struct P                                            // 无字段可省括号（≡ struct P()，P3 v2.1）
@mut struct Cell(@mut n: Nat)                       // 可变结构体 + 可变字段（root doc）
struct Natural(n: Nat) <n ≠ 0>                      // 伴生命题（v3.0 特性 1）
```

文法要点（Parser.kt parseStruct :893-909）：

- `struct 名 类型参数? (字段, …) 伴生命题?`；**体只能是圆括号字段表**——写大括号体会在解析期直接报错并给出改写指引（:898）
- 字段形态为 `@注解* 名: 类型 = 默认值?`：注解吃在名字位（`@mut n: Nat`，parseParams :388-391）；类型工程模式不可省（脚本模式 allowUntyped 才允许 InferMarker 占位）；默认值是任意表达式（:400）
- 类型参数走方括号 `[T]`（parseTheory，可带类型类约束 `[T: Show]` 与命题参数 `[@p]`）
- 无字段可省括号写成 `struct P`，发提示 H-EMPTY-DECL；无字段也可带伴生命题（:901-903）
- 伴生命题是字段表后紧跟的 `<...>`（:906-907），识别方式与 fun 的下文位相同
- **尾随逗号合法**（遇 `)`/`]`/`}` 自动收尾）
- struct 只能写在**顶层**（parseEntry :194-205；parseStmt :631 无 struct 分支，函数体内不能声明）；struct 上的注解一律放行，语义由宿主/注解处理器解释（:201-202）

### 构造

```subl
var p = Point(1, 2)                 // 位置实参
var u = User(name = "alice")        // 命名字段构造：age 取默认值 0
var v = User("bob")                 // 位置式尾部缺省（age 有默认值）
var w = User()                      // 全部字段取默认值
var q = Pair(1, "a")                // 泛型实参推断 → Pair[Nat, Str]
```

两种构造在**解析期就分道扬镳**（Parser.kt :1190-1194）：后缀括号调用时，若被调者是**大写裸名**（不含 `::`）且括号形态是 `(IDENT =`，产出独立的 StructCtorExpr 节点；否则仍是普通 CallExpr。分派前提（looksLikeNamedCtor :455-460）有三个细节：

- `()` 空括号**不算**命名字段构造——零参调用要让给 `None()` 这类枚举构造子；`User()` 因此走位置式通道（全默认值补齐）
- `E::A(...)` 枚举成员路径不走命名通道（复合名含 `::`）
- 小写名字的结构体即使写 `s(f = 1)` 也不触发命名构造——实参落进函数命名参数通道，而结构体位置构造只按位置核对，结果多为 E-FIELD-MISSING（待核：小写结构体名约定上不使用，语言未禁止）

### 字段访问、解构与写入

```subl
var x = p.x                                       // 字段访问（点前无空格）
var total = if (p is Point(a, b)) a + b else 0    // ifis 结构体解构（E2ETest :90）
fun f((a, b): Point): Nat = a + b                 // 元组式参数解构（P4 v2.1）
var n = when(p) { is Point(x, y) => x + y }       // when 解构（须显式 is）

@mut struct Cell(@mut n: Nat)
@impure fun main() {
    var c : @mut Cell = Cell(0)
    c.n = 1                                       // 字段写入：需 @mut 字段 + @mut 视图
}
```

## 语义

**struct = 名义乘积类型。** 声明只给形状：取值靠构造，拆解靠字段访问与模式匹配，正确性由类型层与命题层共同保证。

### 声明期检查（Symbols.kt）

- 重名 `E-DUP-DECL`（:152）；无字段发 `H-EMPTY-DECL` 提示（:155）
- 字段类型可解析（checkDeclTypes :221-230）；**默认值在空帧里检查类型**，与字段类型不符报 `E-TYPE-MISMATCH`（:224-229）——默认值因此不能引用其它字段或局部值；`Any` 字段豁免类型核对
- 伴生命题引用了 `@mut` 字段 → `E-STRUCT-MUT-PROP`（声明位 :159-162，构造位另有防御闸 :1145-1150）

### 构造期检查（CallCheck.kt）

| 检查项 | 位置式（checkStructCall :655） | 命名式（checkStructCtor :24） |
|---|---|---|
| 实参数 | 多了 `E-TYPE-MISMATCH`；少了要求**尾部字段全部有默认值**，否则 `E-FIELD-MISSING`（:665-671） | 缺字段且无默认值 → `E-FIELD-MISSING`（:45-48），**可随意缺省任意有默认值的字段** |
| 字段名 | 按声明序 | 未知字段 `E-UNBOUND-NAME`（:34）、重名 `E-DUP-FIELD`（:33） |
| 字段类型 | 逐项名义相等；`Any` 字段接受任意实参（决策 59） | 同（:41-43） |
| 泛型实参 | 由字段实参反推（`Pair(1, "a")` → `Pair[Nat, Str]`，:660-664；类型参数字段跳过相等核对） | 同（:28-39） |

### 伴生命题（v3.0 特性 1）

`struct Natural(n: Nat) <n ≠ 0>` 把「恒成立的性质」钉在类型上，四个位置自动生效：

1. **构造位证明**：字段名替换成实参（缺省字段填声明默认值）后交证明器；证得出才放行并注入作用域，证不出报 `E-STRUCT-PROP-UNPROVEN`（checkStructProps :1151-1159）。位置式与命名式都走这条闸（:49-52 / :683-685）
2. **构造成功注入**：`var t = Natural(3)` 之后帧里自动有 `t.n = 3` 与 `t.n ≠ 0`（Checker.kt :561-578）
3. **结构体形参自动注入**：`fun f(t: Natural)` 体内等价自带前件（:360-372）
4. **方法体注入**：`impl` 成员体内伴生命题按裸字段名（`n` 而非 `self.n`）注入（injectSelfAndFields :499-506）

伴生命题的证明义务**不经 unchecked 闸**（checkStructProps 无 uncheckedDepth 分支），这与 E-IMMUT-ASSIGN 等闸门不同——`unchecked` 前缀救不了非法构造。

### 默认值的运行时落地

- **编译模式**：struct 生成 JS 工厂函数，默认值直接变成 JS 参数默认值——`const User = (name = "unknown", age = 0) => ({ tag: "User", name, age })`（JsCodeGen.kt :577-583）；命名字段构造按字段声明序排成位置实参，缺省位传 `undefined` 让 JS 默认值兜底（structCtorJs :1452-1473）
- **解释器**：StructInfo.fieldDefaults 保留默认值表达式，构造时对缺省字段现求值；找不到默认值抛 InterpreterError（Evaluator.kt :918-934）；位置构造先按下标折算成字段名再走同一条路（:482-489）

### 可变性：@mut 字段与 @mut struct

- **字段写入双重闸**（checkMutFieldWrite :858-873）：①字段本身必须标 `@mut`（否则 `E-NOT-MUT`：字段不可变）；②持有者须有 `@mut` 视图——变量类型是 `@mut T` 或变量本身 `@mut` 声明（否则 `E-NOT-MUT`：须持 @mut 视图）。两闸独立：`@mut var a = T(0)` 配不可变字段、纯视图配 `@mut` 字段都写不进去
- `@mut struct` 是 root doc 的可变结构体声明（Ast.kt :59）；checker 把「struct 注解含 mut **或**任一字段含 @mut」统一判为**可变结构体**（isMutStructType :876-880）——其绑定等式事实不再注入：`var a = T(0)`、`var b = T(0)` 之后 `∵ a = b` 证不出（E-CANNOT-PROVE），自反式 `∵ a = a` 仍可证（CheckerTest :1235-1244）。注意 struct 级 `@mut` **不放松字段写闸**——字段仍要逐个标 `@mut`；嫌繁琐可用内建注解处理器 `@allMut`（annotationproc 引擎默认装载，给 struct 及其全部字段加 @mut）
- `@mut T` 形参的函数必须标 `@impure`（E-IMPURE-REQUIRED，Checker.kt :293）；`@mut` 方法（`@mut fun`）体内 self 持可变视图可改 @mut 字段（:326-328），调用点仍要求接收方持 `@mut` 视图（E-NOT-MUT，CheckerTest :1253-1258）
- 绑定/赋值涉及 @mut 视图时按四条款拷贝规则深拷或别名（详见 wiki/02-类型-拷贝规则.md）：如 `var b : T = a`（a 是 @mut 视图）深拷隔离、双侧 @ref 别名共享（E2ETest :749-801）
- **不可变性自动命题**：struct 无 @mut 字段且全部字段类型 immutable（不动点迭代，含容器实参递归）→ 全局事实 `immutable<T>`（Symbols.kt :60-100，I-2/I-3 规则）

### 与命题系统、模式匹配的其他接口

- 字段访问类型按符号表查（泛型字段按 self 类型实参代入），未知字段 `E-UNBOUND-NAME`（:974-978）
- 结构体形参解构 `fun f((a, b): Point)`：分量按字段序列绑定，数量不符 `E-DESTRUCT`（Checker.kt :336-348）；lambda 解构参数同构（:1092-1110）
- 模式 `is T(a, b)` 解构：绑定按字段声明序，JS 侧结构体字段按名存储（matchJs :1796-1803）；解构血缘链登记进 structSub，供纯函数递归停机判定
- `==` 结构相等：按 tag + 字段递归（__eq 助手，JsCodeGen.kt :293-303）；`is T` 按 tag 名义判定（__isa :283-292）
- 跨模块：`core.Point(...)` 限定调用按 QSymKind.STRUCT 路由进同一段检查（checkQualifiedCall，P0 模块系统）

## 示例

综合示例（结构体与枚举.subl 同款用法，可直接跑）：

```subl
struct User(name: Str = "unknown", age: Nat = 0)
struct Pair[A, B](first: A, second: B)
struct Natural(n: Nat) <n ≠ 0>

@impure fun main() {
    var u = User(name = "alice")            // 命名构造，age 取默认值 0
    var v = User("bob")                     // 位置式尾部缺省
    var p = Pair(1, "a")                    // 推断为 Pair[Nat, Str]
    var t = Natural(3)                      // 3 ≠ 0 常量可证 → 构造通过

    var sum = if (p is Pair(a, b)) a else 0     // 结构体解构（E2ETest :90 同款）
    var nm = u.name
    var yr = p.first

    print(u.name)                       // alice
    print(toStr(u.age))                 // 0
    print(toStr(sum + yr))              // 2
    print(toStr(t.n))                   // 3
}
```

可变结构体（E2ETest :749 验证的隔离语义）：

```subl
@mut struct Cell(@mut n: Nat)

@impure fun main() {
    var a : @mut Cell = Cell(0)
    var b : Cell = a                // 目标纯 ← 源 @mut → 深拷贝
    a.n = 1                         // @mut 字段 + @mut 视图 → 合法
    print(toStr(b.n))               // 0：b 是独立副本，改 a 不影响 b
}
```

伴生命题（CheckerTest :1362-1396 测过的三条路径）：

```subl
struct Natural(n: Nat) <n ≠ 0>

// 形参自动注入：体内等价于自带前件 <t.n ≠ 0>
fun rewrap(t: Natural): Natural { return Natural(t.n) }

@impure fun main() {
    var t = Natural(5)              // 等式事实 t = 5 推进 5 ≠ 0 → 通过
    var u = rewrap(t)
    print(toStr(u.n))               // 5
}
```

反例（非法构造）：

```subl
struct Natural(n: Nat) <n ≠ 0>
@impure fun main() {
    var bad = Natural(0)            // E-STRUCT-PROP-UNPROVEN：0 ≠ 0 证不出
}
```

## 陷阱

1. **大括号体**：从 Kotlin/Rust 过来容易写 `struct P { x: Nat }`——解析期即报错并提示改写为 `P(x: Nat)`（:898）
2. **位置构造只能缺省尾部**：`User("bob")` 合法（age 有默认值），但想跳过中间字段必须改用命名构造——位置实参没有「跳过」语法
3. **命名构造的分派前提**：只认「大写裸名 + `(IDENT =`」。`User()` 走位置式（依赖全默认值）；`E::A(x = 1)` 不走命名通道；小写结构体名的 `s(f = 1)` 会落进函数命名参数通道而非结构体构造
4. **默认值不是「可选字段」的糖**：默认值表达式在空帧检查，不能引用其它字段（`struct A(n: Nat, m: Nat = n)` 会因 `n` 无定义报 E-UNBOUND-NAME）；函数形参的默认值规则与 struct 不同——须**尾部连续**（首个默认值之后全要有，否则 E-DEFAULT-PARAM），类型类成员与 impl 方法仍全面禁止默认值（Symbols.kt :272/:281）
5. **伴生命题与 @mut 字段互斥**：命题引用 @mut 字段在声明位即 `E-STRUCT-MUT-PROP`（可变字段的值会变，无法保证恒成立）
6. **@mut struct 不等于字段可写**：写入闸只看字段注解与持有视图。struct 级 @mut 的影响在「不注入相等绑定事实」与处理器约定（@allMut），不放松 E-NOT-MUT
7. **可变结构体不承认相等命题**：`var b = a` 之后 `∵ b = a` 对可变 struct 证不出（E-CANNOT-PROVE），但不可变 struct 可以（CheckerTest :1235-1250）——写证明时先想清楚 struct 有没有 @mut
8. **构造泛型 struct 时类型实参靠反推**：`Pair(1, "a")` 推出 `Pair[Nat, Str]`；字段类型与实参名义不符（除 Any 字段）即 E-TYPE-MISMATCH，不会被推断「修复」
9. **unchecked 救不了伴生命题**：证明义务不经 uncheckedDepth 闸；想绕过非法构造只能改实参或去掉命题
10. **解构必须显式 is**：`is Point(a, b)` 合法，裸 `Point(a, b)` 在 when 分支位只允许空参值比较（parsePattern :1644-1648）

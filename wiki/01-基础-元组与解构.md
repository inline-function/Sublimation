## 语法

```subl
// ---- 元组字面量：逗号是判据（决策 62；Parser.kt:1332-1339）----
(1, "a")            // 二元组，类型 (Nat, Str)
(1, 2, 3)           // 三元组
(1, 2,)             // 尾随逗号合法（v3.0）
(x)                 // 不是元组——只是括号表达式
(x,)                // 这才是一元组字面量
((1, 2), (3, 4))    // 嵌套元组字面量

// ---- 元组类型：类型位的 ( 由 => 决定归属（决策 57/61；Parser.kt:565-585）----
(Nat, Str)          // 元组类型
(Nat) => Str        // 函数类型（不是元组类型）
() => Null          // 零参函数类型（() 位置已归函数）
type Pair = (Nat, Nat)        // 类型别名承载元组类型
fun pair[T](x: T, y: T): (T, T) = (x, y)   // 元组作返回类型、泛型元素

// ---- var 解构声明：var 后紧跟 ( 读扁平分量名（Parser.kt:816-825）----
var (a, b) = (1, 2)
var (a, b) = pair(3, 4)       // 初值可为任意元组类型表达式
@mut var (m, n) = (1, 2)      // 注解逐分量传导（m、n 都登记可变）

// ---- 函数形参 / lambda 解构参数（P4，v2.1）----
fun tsum((x, y): (Nat, Str)): Str = y
fun psum((a, b): Point): Nat = a + b        // 结构体形参也可解构
var f = { (a, b) => b }                     // lambda 单个元组参数解构

// ---- when 元组模式（Parser.kt:1614-1622；分支分隔符 =>）----
when(p) {
    (a, b) => a + b            // 绑定两个分量
    (0, 0) => 0                // 字面量分量
    (_, b) => b                // 通配分量（_ 不绑定变量）
    ((x, y), z) => x           // 嵌套元组模式
    (a, b) if a > b => a       // 守卫（if 子句在 => 前）
    else => 0                  // 兜底（_ 与 else 同义）
}
```

解构在语言里有**三个位置**，语法形态各异但分量绑定语义一致：

| 位置 | 形态 | 分量来源 |
| --- | --- | --- |
| var 声明 | `var (a, b) = e` | 初值元素类型 |
| 函数/lambda 形参 | `fun f((a, b): T)` / `{ (a, b) => … }` | 声明类型（元组按 items / 结构体按字段） |
| when 模式 | `when(p) { (a, b) => … }` | 主题类型的元素类型 |

## 语义

- **字面量与类型**：`(1, "a")` 的检查结果是 `TupleType([Nat, Str])`——元组字面量的类型即元素类型之积（Checker.kt:1271-1273）。元素按源码顺序逐元求值；表达式全部左结合、无优先级，元组内多元素不需要额外括号，跨元组的混合运算需要括号。
- **结构类型而非名义类型**：`TupleType` 的内部名是哨兵 `"(tuple)"`，按类型名查表的逻辑对元组天然 miss——元组没有构造子、没有 impl 形态的归属，类型相等按结构逐元比较（Ast.kt:131-134、179-185）。
- **运行时表示**：解释器里元组是 `ScriptValue.ListV`（Evaluator.kt:240），JS 代码生成里是数组字面量（JsCodeGen.kt:920）。 JS 侧 `print` 输出形如 `[1,2]`（E2ETest 570-580），与列表同形。元组相等 `==(t, u)` 按长度相等 + 逐元 `structEquals` 判定（Evaluator.kt:411）。
- **取元没有下标/字段语法**：语言未提供 `t.0` / `t[0]` 这类写法（解释器对元组值只解析方法路径，Evaluator.kt:227-235）。取元素只能靠解构（var 声明、when 模式、形参解构）；标准库 `core/collection/tuple.subl` 为 0 到 10 元组 impl 了 `Tuple` 接口（`size()` / `isEmpty()`），但注意下条陷阱。
- **元组与列表同表示**：解释器的运行时类型标签 `typeTag` 把 `ListV` 一律打成 `"List"`（Evaluator.kt:642-643），元组值与列表值无法在方法派发层区分——元组上调用 `size()` 会按 `"List"` 标签查 impl，不一定命中元组的 `Tuple` 实现（`待核`：两条路径的实际派发行为；生产代码请用解构取元）。
- **when 元组模式**（WhenCheck.kt:256-268）：匹配成功后向分支帧注入等式 `subj = (p₁, p₂)`，分量按对应位置元素类型递归绑定（`bindTupleVars` → `bindVars`，支持嵌套）。`_` 分量不绑定变量。分量数与元组元素数不符、或对非元组主题使用元组模式，报 **E-TYPE-MISMATCH**（WhenCheck.kt:259-262）。供穷尽性判定的分支命题把等式中出现的绑定变量 ∃ 封闭（`patternTerm`，WhenCheck.kt:345-366）。
- **运行时模式匹配**：解释器对 `PatTuple` 判"是 ListV + 长度相等 + 逐分量递归匹配"（Evaluator.kt:741-745）；JS 侧生成 `Array.isArray(t) && t.length === n` 再逐元匹配（JsCodeGen.kt:1770-1774）。由于元组与列表同表示，元组模式在**运行时**会匹配任何恰好等长的 ListV 值；静态检查（主题类型必须是元组类型）负责挡住对列表主题写元组模式。
- **顺序与穷尽性**：when 顺序敏感，后分支的 Γ 含前面全部分支命题的否定（WhenCheck.kt:129）——即 `when(p) { (0, 0) => A (a, b) => B }` 的第二分支里 `¬(p = (0, 0))` 作为前提可用。元组主题**没有覆盖律**（不像名义枚举有全构造子清单），判不出穷尽时按决策 66 **静默退化为 Null 值类型、不发 W-NON-EXHAUSTIVE**（WhenCheck.kt:155-179；CheckerTest 560-565）；只有写 `else`/`_` 兜底（或证明器证出分支析取恒真）才算穷尽。解释器对非穷尽 when 固定返回 Null、不抛异常（Evaluator.kt:723）。退化后的 Null 若流向函数声明的非 Null 返回类型，由 **E-NON-SEALED-MATCH** 兜住（Checker.kt:401-403）。

$$\frac{\Gamma \vdash \text{subj} : (T_1, T_2) \qquad \Gamma,\ \text{subj} = (p_1, p_2) \vdash e : U}{\Gamma \vdash \textsf{when}(\text{subj})\ \{ (p_1, p_2) => e \} : U} \quad (\text{T3·元组模式})$$

- **var 解构声明**（Checker.kt:515-535）：初值类型展开后必须是 `TupleType`，否则报 **E-TUPLE-DESTRUCT**；分量数 ≠ 元组元素数报 **E-TUPLE-ARITY**。通过后逐分量按对应元素类型声明变量（每个分量单独发 `D-TYPE-INFERRED` 提示推导结果），`@mut` 注解对每个分量登记可变；解构作为语句不产值（返回 Null）。
- **形参 / lambda 解构参数**（Checker.kt:336-348、1091-1111）：按声明类型拆分——元组按 items、结构体按字段；类型不可解构（既非元组也无可解构结构体）报 **E-DESTRUCT**，分量数不符也报 **E-DESTRUCT**。带解构形参的函数调用禁用指名实参（`f(a = 1, b = 2)` 报 **E-NAMED-ARG**，CheckerTest 237-241）。lambda 的解构参数在无期望类型时各分量按占位类型绑定；JS 侧函数入口生成 `const a = __dt0[0]; const b = __dt0[1];`（JsCodeGen.kt:724-733）。
- **拷贝与可变性**：解构声明整体先按[拷贝规则](02-类型-拷贝规则.md)决定是否深拷（JS 生成 `const [a, b] = __dc(初值)`，JsCodeGen.kt:797-807），再拆分分量；元素类型里的 `@mut` / `@ref` 语义与普通变量一致（`@ref T ← T` 共享只读、`@mut T ← T` 深拷等，详见拷贝规则条目）。
- **分支返回类型**：穷尽的 when 的值类型是各分支体类型的 join（`TypeInfer.unify` 逐分支合并，WhenCheck.kt:152-153）；各分支体为表达式或 `{ 语句 }` 块均可，块按语句流处理（允许提前 return）。
- **多值返回的载体**：语言没有独立的多返回值语法，`返回多个值`的惯例就是返回元组、调用处用 var 解构或 when 模式取回（如 `fun divmod(a: Nat, b: Nat): (Nat, Nat) = (a / b, a % b)`，调用方写 `var (q, r) = divmod(7, 2)`）。
- **空元组 / 单元组**：`()` 在类型位是零元组类型（`TupleType([])`），但零元组/单元组的**值构造**走内建具名形态 `emptyTuple()` / `singleTuple(x)`（Ast.kt:179 注：EmptyTuple/SingleTuple 是具名形态、走 NamedType，决策 62；CheckerTest 573-576）。

## 示例

```subl
// 元组与解构——工程模式可运行示例
struct Point(x: Nat, y: Nat)

fun fst(p: (Nat, Nat)): Nat = when(p) { (a, b) => a else => 0 }

fun tsum((x, y): (Nat, Str)): Str = y

fun pair[T](x: T, y: T): (T, T) = (x, y)

@impure fun main() {
    var p = (3, 4)
    print(fst(p))                    // 3
    print(fst((9, 1)))               // 9
    print(tsum((7, "x")))            // x

    var (a, b) = (1, 2)
    print(a + b)                     // 3

    var q = pair("s", "t")
    print(q)                         // [s,t]（JS 侧数组形态）

    // 嵌套元组模式 + 守卫 + 通配
    var nested = ((2, 3), 4)
    when(nested) {
        ((x, y), _) if x + y > 4 => print(x + y)   // 5
        ((x, y), z) => print(z)
    }

    // lambda 解构参数
    fun apply(f: (Nat, Str) => Str, v: (Nat, Str)): Str = f(v)
    print(apply({ (n, s) => s }, (7, "ok")))       // ok
}
```

var 解构声明的各分量推导可从诊断提示看到（每个分量一条 `D-TYPE-INFERRED`）；元组相等按逐元结构比较：

```subl
@impure fun main() {
    var (n, s) = (7, "x")   // D-TYPE-INFERRED: var n 推导为 Nat / var s 推导为 Str
    print(n)
    print(s)

    print(==((1, 2), (1, 2)))   // true：长度相等且逐元相等
    print(==((1, 2), (1, 3)))   // false
}
```

## 陷阱

- **`(x)` 不是元组**：逗号才是元组判据（Parser.kt:1333），`(x)` 只是括号表达式、类型就是 `x` 的类型；想要一元组字面量须写 `(x,)`（尾随逗号让元数变 1）
- **类型位的括号归 `=>` 管**：`(Nat, Str)` 是元组类型，`(Nat) => Str` 是函数类型（Parser.kt:583-584）；`() => Null` 是零参函数类型而非空元组类型。空元组/单元组的值只能用内建 `emptyTuple()` / `singleTuple(x)`
- **分支箭头必须写 `=>`**（修正案后）：`(a, b) -> a` 这种旧写法现在非法（`->` 词法出 token 仅供诊断）；命题位的蕴含才用 Unicode `→`。非法示例（陷阱节专用，勿模仿）：

  ```subl
  when(p) { (a, b) -> a }        // 非法：分支分隔符应为 =>
  ```

- **元组主题漏兜底是静默退化、不是报错**：元组无覆盖律，非穷尽的 when 不发 W-NON-EXHAUSTIVE，值类型直接退化为 Null（决策 66）；只有当这个 Null 流向函数声明的非 Null 返回类型时才以 E-NON-SEALED-MATCH 报出——`fun f(p: (Nat,Nat)): Nat = when(p) { (a, b) => a }` 就是靠这条兜住的
- **全通配元组模式也不被认作穷尽**：枚举主题的绑定式构造子分支有 `bindingCovered` 兜底判定（WhenCheck.kt:193-208），元组没有等价机制——`when(p) { (a, b) => a }`、`when(p) { (_, _) => 0 }` 都需证明器证出析取恒真才算穷尽，而元组主题无覆盖律通常证不出；要值类型不退化，老老实实写 `else =>` 兜底
- **三个元数/解构报错要分清**：

  ```subl
  var n = 5
  var (b, c) = n              // E-TUPLE-DESTRUCT：初值不是元组
  var t = (1, 2, 3)
  var (b, c) = t              // E-TUPLE-ARITY：分量数 2 ≠ 元组元素 3
  fun f(p: (Nat, Nat)): Nat = when(p) { (a, b, c) => a }   // E-TYPE-MISMATCH：元组模式分量数不符
  fun g(n: Nat): Nat = when(n) { (a, b) => a }             // E-TYPE-MISMATCH：对非元组主题用元组模式
  ```

- **没有下标取元**：`t.0` / `t[0]` 形态不存在（解释器对 ListV 只找方法路径）；要元素就解构，要元目数用解构计数。标准库虽为元组 impl 了 `size()`/`isEmpty()`，但元组与列表共享运行时表示、方法派发按 `"List"` 标签查找（Evaluator.kt:642-643），元组上调用方法的行为`待核`——别依赖
- **打印形态与列表同形**：`print((1, 2))` 在 JS 侧输出 `[1,2]`，与列表输出无法从字符串区分（表示同源）
- **解构形参不能用指名实参**：`fun f((a, b): (Nat, Nat))` 的调用只能写 `f(1, 2)`，`f(a = 1, b = 2)` 报 E-NAMED-ARG；`fun f((a, b): Nat)` 直接报 E-DESTRUCT（Nat 不可解构）
- **run-script 解释器路径的 var 解构不拆分**（`待核`）：Evaluator 的 VarStmt 分支（Evaluator.kt:162-169）未判 `destruct`，而 Parser 又把 `destruct.first()` 填进 `stmt.name`（Parser.kt:809）——解释器会把**整个元组绑到第一个分量名**，其余分量不存在；只有 compile/JS 路径生成 `const [a, b] = ...`（JsCodeGen.kt:801）。脚本模式里暂不依赖 `var (a, b)`，改用 when 解构
- **`@mut var (m, n)` 的注解是逐分量传导**：不是给"元组整体"加可变视图；想描整个元组变量的可变性须写到类型位（`var t: @mut (Nat, Nat)` 这类形态`待核`，语法层类型位支持 `@mut` 修饰元组类型，但具体检查行为未在测试中覆盖）

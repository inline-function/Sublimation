## 语法

### 四个触发点

拷贝判据只在四个句法位置上被求值（解释器与检查器各持同一谓词 `bindCopy` / `binderNeedsCopy`）：

| 触发点 | 句法 | 解释器（run-script） | JS 生成（compile） |
|---|---|---|---|
| 绑定/赋值 | `var b : @mut T = a`、`@mut var b = a`、`b = a` | `Evaluator.bindCopy`（:166/:174/:246） | `__dc(...)` 包装（:801/:805/:817） |
| 参数 | `f(x: @mut T)` 的实参→形参 | **不拷**（:584-596 原样 declareVar） | **不拷**（:900 裸形参名） |
| 解构 | `var (a, b) = t` | **不拷且损坏**（只绑首个名） | `__dc` 仅在留痕成立时包装（:801） |
| 闭包捕获 | lambda / 匿名函数持有的外层变量 | 由前三个触发点**穿透进函数值**而引发（:156） | **永不拷贝**（`__dc` 对函数穿透） |

### 标注形态

```subl
@mut var sum = 0                    // 注解式：变量可重绑（declareMut 登记，Checker.kt:583）
var box : @mut T = e                // 类型位：可写字段、不可重绑（见陷阱）
@ref var view : @mut T = e          // @ref 只作变量注解；与 @mut 组合成共享可变别名（check 通过）
fun f(x: @mut T): Null { … }        // 参数可变语义；函数须标 @impure（否则 E-IMPURE-REQUIRED）
```

深拷在 JS 后端是**编译期留痕 + 运行时执行**两段式：Checker 在判据成立时往 `deepCopyHits`（IdentityHashMap，按 AST 节点）记一笔，并发 **D-DEEP-COPY** 补充级诊断（「`b` 是独立副本，改它不影响源」）；JsCodeGen 只在留痕非空时才注入 `__dc` 运行时助手（:319-332），逐绑定/赋值位点用 `dcWrap` 决定是否包一层（:790-791）。

## 语义

### 同一谓词，两处清算

$$\frac{tgt\text{含}\,@mut \wedge (\neg tgt\text{含}\,@ref \vee src\text{纯}) \;\vee\; src\text{含}\,@mut \wedge tgt\text{纯} \;\vee\; src\text{含}\,@ref \wedge \neg tgt\text{含}\,@ref}{绑定/赋值 \Rightarrow \texttt{deepCopy}(v)} \quad (\texttt{binderNeedsCopy} \equiv \texttt{bindCopy})$$

（源纯 = 源既无 `@mut` 也无 `@ref`；目标纯同理。）完整矩阵与读法见 [拷贝规则](02-类型-拷贝规则.md)。效应侧要记住的是：**谓词在两处清算、结果并不总是一致**——解释器按注解与类型即时求值，JS 按编译期留痕回放，而留痕的条件更窄（见下文）。

### 绑定与赋值：@mut 目标即快照点

判据成立时，解释器对值递归深拷：结构体逐字段、列表逐元素、Optional/Result 连通内部（`deepCopy`，Evaluator.kt:145-158；`mutableFields` 是类型元数据，只读共享不复制）。JS 侧生成 `let b = __dc(a);`——`__dc` 对数组 `map` 递归、对普通对象逐键递归。

**留痕只认 NameRef 源**：Checker 三处留痕条件都要求源表达式是名字引用（:587/:626/:1299）。于是 `var b : @mut T = T(0)`（构造器源）在解释器里照拷（`bindCopy` 无此限制），在 JS 里**不生成 `__dc`**（实测编译产物对照确认）。两后端在此分叉；可观测差异只在「构造器表达式自身闭包了外部状态」的场合（见示例 3 的两后端对照）。

### 参数：判据书上有，运行时不发生

类型组文档把参数位列入拷贝判据的适用位，但**两个后端都不执行拷贝**：解释器 `invokeFunDecl` 把实参原样 `declareVar`（:584-596），JS 的形参表是裸名（:900）。实测 `@impure fun touch(x: @mut T) { x.n = 1 }` 调用后**调用方的 `a.n` 变为 1**——参数位是共享，不是拷贝（两后端行为一致）。效应侧的正确表述：`@mut T` 形参只交付**写权限**（并强制函数标 `@impure`，见 [副作用与 @impure](04-效应-副作用与@impure.md)），不交付副本。要隔离就在函数入口显式重建，要表达「只来看」就用 `@ref T` 形参。

### 解构：两后端都没拷贝，解释器还坏了

`var (a, b) = (1, 2)`：JS 侧生成 `let [a, b] = ...;`，行为正确（纯元组本就不触发判据，无 `__dc`）；**解释器侧忽略 destruct 子句**——首个名 `a` 被绑成整个元组（实测 `print(a)` 输出 `[1, 2]`），`b` 未定义（引用即报「未定义的变量」）。when 模式绑定（PatBind）与 lambda 形参绑定同样不做拷贝（Evaluator.kt:731/:736/:813/:826）。结论：**解构当前不是事实上的拷贝触发点**；判据文档与实现何时对齐，待核。

### 闭包捕获：不是「创建时」，而是「函数值被深拷时」

这是效应侧最容易被误传的一条（_langfacts §6 的措辞是「lambda 创建时深拷」——实现机制实为两段）：

- lambda / 匿名函数**创建时共享创建帧**——`evalLambda` 直接持有 `frame`（:838-854），调用时在其子帧求值。因此 `var f = { => x.n = 5 }` 之后 `f()` 会**写穿**捕获的 `x`（实测 `x.n` 变为 5）；纯目标绑定 lambda 不构成拷贝。
- 只有当**函数值本身被深拷**（作为 `@mut` 绑定的值、或作为被拷结构体/容器的一个字段）时，`deepCopy` 的 Fun 分支触发 `copyCapture()`（:156）——它用 `copiedFrame` 沿父链收集全部局部并逐值深拷、装入新帧（:130-143），快照在此刻定型。

$$\frac{\texttt{deepCopy}(v) \qquad v = \lambda}{\texttt{copyCapture} \Rightarrow \text{新帧} := \texttt{deepCopy}(\text{捕获集})} \quad (\text{捕获快照})$$

快照是**双向隔离**的：经深拷的闭包读不到外部后续前进（实测 `h.f()` 返回 0，而外部 `y.n` 已是 9）；它写捕获也落不到原件（实测闭包内写 `y.n = 5`，外部 `y.n` 仍为 0）。

**对别名的影响**：快照点与拷贝点重合——一个 `@mut` 对象只要经过一次判据拷贝再进入闭包，闭包持有的就是独立副本，别名被拷贝切断。反过来，未经拷贝路径（`@ref @mut` 别名、直接共享的纯值）进入闭包时，闭包看到的是活对象。

**对并发的影响**：异步原语只在 JS 后端存在（解释器对 Task/Flow 直接抛「异步特性不在脚本中支持」，Evaluator.kt:268），而 JS 侧 `__dc` 对函数值**穿透**——跨 `runBoth` / Flow 边界共享的闭包**一律共享捕获**，可变状态的并发竞争靠 `withMutex` / Channel 纪律而非拷贝隔离（见 [异步 Task 与 Flow](04-效应-异步Task与Flow.md)、[mutex](04-效应-mutex.md)）。拷贝隔离并发这一效应当前只在解释器脚本模式成立，而那里没有并发原语——设计缺口，待核。

### @mut 赋值：运行时版本前进；Γ 侧实测不注入

运行时：`@mut var sum = 0` 之后 `sum = 41` 是**版本前进**——AssignStmt 的 `bindCopy` 对 `@mut` 目标再走一次判据（规则 1 恒拷），用新副本替换绑定，旧对象被孤立。注意：**此前的 `@ref @mut` 别名留在旧对象上**（实测：重绑后 `c.n = 5` 而 `d.n = 0`）——重绑换的是句柄，不是对象迁移。

Γ 侧：旧文档称「@mut 的每次写把值等式注入 Γ」。**实测当前实现不注入**——`@mut var sum = 0; sum = 41` 之后，`∴ (sum == 41)` 与 `∴ (sum == 0)` 都报 E-CANNOT-PROVE；诊断转储的 Γ 里只有 `:<sum, Nat>`（类型事实）与 `>=<sum, 0>`（Nat 蕴含的自然命题），**没有任何 `==` 等式**。对照纯变量 `var n = 0` 的 `∴ (n == 0)` 可证（ Checker.kt:594 的 `!mut` 条件把 @mut/@ref 绑定排除在等式注入之外，:1302 同理）。效应侧结论：**@mut 的值在 Γ 里是不可预测量**——涉及它的命题只能走作者显式供给（`axiom` / `by [q]` / 下文弥散），与 `@ref` 的待遇一致（见 [@ref](02-类型-@ref.md)）。「版本等式注入」标待核（实现未落实；另见 [@mut](02-类型-@mut.md) 的 `@var` 表达式通道——那条弥散路径属于 `var` 表达式，不属于注解式 `@mut var`）。

### 两后端对照

| 维度 | 解释器（run-script） | JS（compile + node） |
|---|---|---|
| 绑定/赋值判据 | `bindCopy` 即时求值，不限源形态 | 留痕回放，**仅源为名字引用时**包 `__dc` |
| 函数值 | 深拷递归进捕获（`copyCapture`） | `__dc` **穿透**（`typeof v !== "object"` 早退） |
| 捕获语义 | 快照隔离（读/写都不穿） | 活捕获共享（JS 闭包不透明，既定边界） |
| 参数位 | 共享（不拷） | 共享（不拷） |
| 解构 | 损坏（只绑首个名） | `let [a, b] = ...` 正常 |
| 帧上存在闭包时深拷函数值 | **StackOverflowError**（自指递归） | 无此机制（函数穿透） |

## 示例

（下列输出均为实测：解释器 = `run-script`，JS = `compile` + node v24。）

**1) 绑定的四个判据分支**（解释器；输出 `0 / 1 / 0 / 0 / 5` 分别对应 深拷 / 别名共享 / 深拷 / 别名留旧对象 / 新值）：

```subl
@mut struct T(@mut n: Nat)

var a0 : T = T(0)
var b0 : @mut T = a0          // 规则 1：目标 @mut、源纯 → 深拷
b0.n = 1
unchecked print(a0.n)         // 0

var a1 : @mut T = T(0)
@ref var b1 : @mut T = a1     // @ref @mut ← @mut：别名共享
b1.n = 1
unchecked print(a1.n)         // 1

@ref var a2 : T = T(0)
var b2 : T = a2               // 规则 3：源 @ref、目标纯 → 深拷
unchecked print(b2.n)         // 0（与源独立）

@mut var c : T = T(0)
@ref var d : @mut T = c       // 别名
c = T(5)                      // 版本前进：c 换新对象
unchecked print(d.n)          // 0（别名留在旧对象上）
unchecked print(c.n)          // 5
```

**2) 参数位是共享**（两后端输出一致，均为 `1`）：

```subl
@mut struct T(@mut n: Nat)
@impure fun touch(x: @mut T): Null { x.n = 1 }
var a : @mut T = T(0)
unchecked touch(a)
unchecked print(a.n)          // 1——实参未被深拷，参数交的是写权限
```

**3) 闭包捕获快照——同一程序两后端分叉**（解释器输出 `0`，JS 输出 `9`）：

```subl
@mut struct T(@mut n: Nat)
struct Holder(f: () => Nat)
var y : @mut T = T(0)
var h : @mut Holder = Holder({ => y.n })   // 结构体字段是函数 → 绑定深拷穿透进闭包
y.n = 9
unchecked print(h.f())
```

**4) 闭包写隔离**（解释器输出 `0`）：

```subl
@mut struct T(@mut n: Nat)
struct Holder(f: () => Null)
var y : @mut T = T(0)
var h : @mut Holder = Holder({ => y.n = 5 })
unchecked h.f()
unchecked print(y.n)          // 0——经深拷的闭包写落在自己的捕获副本上
```

**5) 留痕与诊断**（`check -v`，工程模式）：

```subl
@mut struct T(@mut n: Nat)
@impure fun main(): Null {
    var a : T = T(0)
    var b : @mut T = a        // [补充] D-DEEP-COPY: 绑定涉及 @mut 类型，发生深拷贝：
                              //         `b` 是独立副本，改它不影响源
    print("ok")
}
```

**6) 陈旧闭包引发深拷无限递归**（解释器；反面示例，勿模仿）：

```subl
@mut struct T(@mut n: Nat)
struct Holder(f: () => Nat)
var y : @mut T = T(0)
var g = { => y.n }            // 作用域里存在一个闭包变量
var h : @mut Holder = Holder({ => y.n + 1 })
// 解释器：StackOverflowError（deepCopy → copyCapture → copiedFrame 扫到 g
//         → deepCopy(g) → copyCapture → 同一批帧 → 自指递归）
// JS：正常运行（__dc 对函数穿透，根本不扫帧）
```

## 陷阱

- **参数位不是拷贝点**：判据文档把 `fun f(x: @mut T)` 写成深拷，实测两后端都直接共享——调用方的对象会被被调函数改写。要副本在入口重建，要免共享改用 `@ref T` 形参。
- **解释器的解构绑定是坏的**：`var (a, b) = t` 只绑 `a`（值为整个元组），`b` 未定义；JS 侧正常。跨后端移植脚本时先确认解构只在 JS 后端跑，或等实现修复（待核）。
- **陈旧闭包 + 函数值深拷 = StackOverflowError**：只要被扫帧（闭包创建帧及其父链）上存在任何闭包变量，解释器的 `copiedFrame` 就构成自指递归。规避：别把 lambda 存进变量后，再让含函数字段的结构体/`@mut` 绑定触发深拷；这类代码目前只在 JS 后端安全（`__dc` 穿透函数，不扫帧）。
- **`__dc` 对函数穿透是既定边界**：JS 侧闭包捕获**永不复制**，含函数字段的深拷在 JS 里是浅的。同一程序在解释器里「捕获快照隔离」、在 JS 里「活捕获共享」——跨后端行为不同（示例 3）。
- **留痕只认名字引用源**：`var b : @mut T = T(0)`（构造器源）的 JS 输出里没有 `__dc`，解释器却照拷。差异只在构造器闭包了外部状态时可观测，但写跨后端代码时要心里有数。
- **类型位 `@mut T` ≠ `@mut var`**：前者允许字段写（接收者类型是 MutType），但**不允许重绑**——E-IMMUT-ASSIGN 只认 `declareMut` 登记的注解式 `@mut var`（Checker.kt:583/:612）。版本前进（重绑）只属于注解式。
- **Γ 里没有版本等式**：`@mut` 变量的值在证明层是不可预测量——`sum = 41` 之后 `sum == 41` 与 `sum == 0` 都证不出（Γ 只剩 `: Nat` 与 `≥ 0`）；涉及 @mut 变量的命题只能靠 `axiom` / `by` / 下文弥散显式供给。旧文档的「赋值即版本前进、旧值等式入 Γ」当前未实现（待核）。
- **重绑不迁移别名**：`@ref var d : @mut T = c` 之后 `c = T(5)`，`d` 仍指向旧对象（句柄换了，别名没跟着走）——别把重绑当对象级的「就地更新广播」。
- **深拷有代价**：`@mut` 目标从任何源绑定都深拷（规则 1），循环里反复绑定/传值大数据会放大拷贝开销；只读场景用 `@ref` 视图或纯共享。
- **闭包捕获在纯目标绑定时共享**：`var f = { => x.n = 5 }` 不触发任何拷贝，`f()` 直接写穿外部 `x`——「闭包创建时深拷捕获」的说法在两个后端都不成立；快照只发生在函数值被深拷的那一刻。

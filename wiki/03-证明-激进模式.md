# 03 · 证明 —— 激进模式

> **一句话**：激进模式是「更彻底的**搜索**」，不是「更宽松的**判定**」——健全性底线不变，证不出的目标照样报 `E-CANNOT-PROVE`，绝不猜测。

激进模式由 CLI 旗标 `--prover=aggressive` 打开，作用于 `compile` / `check` 两条命令（含目录即模块形态）。它把命题证明器的搜索预算从有界改为不动点驱动 + 迭代加深，并配齐可观测性（进度节流、义务计数、正向记忆化）与中断协议（Ctrl-C → 诊断报告 + 退出码 130）。本条目只讲激进模式特有的东西；命题系统的公共机制（Γ、MP 闭包、axiom 语句、`∵ … ∴`）见「01/02 证明」相关条目。

## 语法

### CLI 旗标

| 旗标 | 取值 | 默认 | 作用 |
|---|---|---|---|
| `--prover=aggressive` | 无值开关 | 关 | 激进证明开关，**只作用于 compile/check**（USAGE:36）；目录模式经 `MultiModule` 透传给每个模块的 Checker（MultiModule.kt:26/61/106），单文件经 `checkFile(..., aggressive = true)`（Checker.kt:1437）或直接构造 `Checker(ast, aggressive = ...)`（Main.kt:314） |
| `--prove-verbose` | 无值开关 | 关 | 提高进度输出频率：命中节流阀即打一行进度到 **stderr**（Aggressive.kt:103） |
| `--prove-dump=<路径>` | 文件路径 | `sublimation-prover-dump.md` | 诊断报告路径，**仅中断时写**（Main.kt:362–363） |
| `--prove-interval=<2s/500ms>` | 数值 + `s`/`ms` 后缀 | `5s`（5000ms） | 进度节流间隔（Main.kt:51–53；解析见 56–60） |

命令形态示例：

```shell
subl compile myproj --prover=aggressive --prove-verbose --prove-interval=500ms --prove-dump=dbg.md -o out.js
subl check myproj --prover=aggressive            # 目录即模块：扫全树检查
subl check f.subl --prover=aggressive -v          # -v 额外输出补充级诊断，与激进旗标正交
```

旗标解析在 `parseProveFlags`（Main.kt:47–54）：`aggressive` 用全等匹配，`verbose` 用 `contains`，dump/interval 取首个 `--prove-*=...` 前缀串。旗标在参数串中的位置不影响其它参数（`-p`/`-A`/`-o` 各自独立扫描）。

### 源码侧形态

激进模式**不引入任何新的源码语法**——它改变的是现有命题构造被证明的方式：

- 前件 `<p → q, ¬p → q>`、下文 `<$ = 7>` 的供给与兑现照旧；
- `axiom p1, p2` 语句、`∵ … ∴ q` 证明义务照旧；`expr by [q]` 在 t30 后改为断言（核对 成立，不注入 Γ）；
- 蕴含一律 Unicode `→`（程序位才用 `=>`，本文无程序位新语法）；
- 排中律 / 反证法依赖 `@classic`：文件内任一声明带 `@classic` 注解即视为挂载 `core.classic`（Symbols.kt:186–187、Types.kt:360、Checker.kt:704 的 `E-NEED-CLASSIC`）。

```subl
@classic                       // 挂载 core.classic：排中律前置 + 反证法通道的开闸条件
fun raa[@p, @q]<¬p → q, ¬p → ¬q>: Null {
  ∴ p                         // 激进模式经反证法证出；普通模式报 E-CANNOT-PROVE
}
```

## 语义

### 1. 它改了什么

普通模式与激进模式的差别集中在证明器构造点（Checker.kt:38–41）：

$$rac{	ext{aggressive} = 	ext{false}}{	ext{session} = ot,quad 	ext{maxRounds} = 3} qquad rac{	ext{aggressive} = 	ext{true}}{	ext{session} = 	ext{ProverSession}(dots),quad 	ext{maxRounds} = 	ext{Int.MAX_VALUE}}$$

`session = null` 时，证明器内所有激进分支（三维池、不动点饱和、迭代加深、∨ 消去）**全部编译期关闭**——普通模式行为完全不变。

激进饱和（`closureAggressive`，Prop.kt:488–563）：

$$rac{\Gamma \text{ 本轮未产出新事实}}{\Gamma \text{ 已达不动点，停止}} \quad (\text{§5.1 判停})$$

- 轮数无上限——**靠不动点判据退出**（本轮无 `facts.add` 成功即 `break`）；
- 由此可能很慢甚至不停机（USAGE:34–35），终止保证改为：Ctrl-C 中断位（`ProverSession.aborted`）→ 每轮每步 `checkAbort` 抛 `ProverInterrupted`（Aggressive.kt:135–137）。

目标侧（`provesAggressive`，Prop.kt:577–596）采用**迭代加深**：深度预算 4 → 8 → 16 → … 无上限；某轮未被深度截断（`deepAborted = false`）仍证不出，才判「真不可证」并照常报错。

### 2. 三维关键池与命题维穷举

这是「命题维实例化穷举」的落点。池里的一切候选都来自程序里**实际出现**过的项（Aggressive.kt:15–16、196）：

- **表达式维**：代码 AST 子项 + Γ ground 项（与普通模式 keyTerms 同源，固定不随饱和扩张）；
- **类型维**：`:` 事实的右端 T + 符号表类型名提示（Checker 收集的结构体/枚举/类型类名）；
- **命题维**：Γ / 目标里出现的一切子命题——排中律 `p ∨ ¬p` 这类命题定理的实例化候选。

每条 `∀` 的绑定名按其在体里的位置分派维度（`dimsOf`，Aggressive.kt:256–280）：

$$rac{x \text{ 是 0 元裸原子}}{x \mapsto \text{命题池}} \qquad rac{x \text{ 出现在 } e : T \text{ 的右端}}{x \mapsto \text{类型池}} \qquad rac{x \text{ 出现在其余项位置}}{x \mapsto \text{表达式池}}$$

实例化取候选的笛卡尔积（`instCombos`），每条 `∀` 的组合上限 `maxCombos = 4096`；池规模上限 `maxExprs = 500`/`maxTypes = 200`/`maxProps = 200`（Aggressive.kt:37–41）。**上限只截搜索、不破健全性**——超出的候选一律不构造，不会被截成"猜"。

### 3. 前向实例化、∨ 消去与反证法

- **排中律前向实例化**（Diffusion.kt:250 起）：可见定理里形状为 `p ∨ ¬p` 的（如 `core.classic` 的 `tertiumNonDatur`），激进模式把命题池候选代进去注入 Γ，随后分情况。
- **∨ 消去**（Prop.kt:663–682）：Γ 含 `A ∨ B` 时两支都证出目标才算成；分支内 `p` 与 `¬p` 并存则该支矛盾、任意目标成立（析取三段论的落点）。同一析取在一条路径上只拆一次（`curUsedOr`）。
- **反证法**（`provesByContradiction`，Prop.kt:416–420；调用点 Diffusion.kt:331）：`Γ ∪ {¬goal}` 饱和出 `⊥` ⇒ `Γ ⊢ goal`。**仅经典逻辑语境**（需 `@classic`）——直觉主义只给 `¬¬goal`，未挂载时该通道绝不启用（有反面测试看守：AggressiveModeTest:59–62）。

### 4. 健全性底线

$$rac{\Gamma \nvdash q \text{（穷尽搜索后）}}{\text{报 } \texttt{E-CANNOT-PROVE} \text{，不放宽判定}} \qquad rac{\text{Ctrl-C}}{\text{写诊断报告，退出码 130，未证目标如实列为未证}}$$

诊断码族不变：`E-CANNOT-PROVE` / `E-PREMISE-UNPROVEN` / `W-PROP-UNBOUND` 在两种模式下语义一致；激进模式只是让"穷尽"更接近真正的穷尽。正向记忆化只记**已证**（失败可能只是深度不够，记失败会误杀，Aggressive.kt:29）。

### 5. 中断协议

1. 启用时注册 shutdown hook：`AggressiveRuntime.interrupt()`（Main.kt:198–200）；
2. Ctrl-C → `session.abort()` 置位（`AggressiveRuntime.active` 是进程级引用）；
3. 搜索循环下一个 `checkAbort` 抛 `ProverInterrupted`，checker 内无吞异常，一路打到 CLI；
4. main 捕获（Main.kt:359–365）：`session.writeReport(路径)` → stderr 提示 → `Runtime.halt(130)`。

报告四节（Aggressive.kt:140–174）：卡住的目标（含完整 Γ）、证明义务（已证/总计）、搜索统计（总步数、三维池规模、最近尝试的定理）、提交 issue 的模板。写失败不阻断主流程。

## 示例

### 例 1：析取三段论（饱和层 ∨ 消去）

```subl
fun disjSyl[@a, @b]<a ∨ b, ¬a>: Null {
  ∴ b
}
```

普通模式无 ∨ 消去：`b` 不是任何蕴含的后件，回溯也够不着 → 报错；激进模式消去析取支后 `a` 支矛盾爆炸、`b` 支直接命中（AggressiveModeTest:28–33 双面断言）。

### 例 2：排中律前向实例化（需 @classic）

```subl
@theorem fun LEM[@p]: Null <p ∨ ¬p>

@classic
fun lemCase[@p, @q]<p → q, ¬p → q>: Null {
  ∴ q
}
```

`∀p. p ∨ ¬p` 的 `p` 分派到命题池，实例化出与 `@q` 相关的分支后两支都出 `q`（AggressiveModeTest:40–45）。

### 例 3：命题维实例化（axiom + ∀）

```subl
@classic
fun propInst[r]: Null {
  axiom ∀p. p ∨ ¬p
  ∴ r ∨ ¬r
}
```

普通模式的一维 closure 只有表达式维（`PForall` 无 ground 项），命题变量实例化不出来；激进模式把 `∀p` 的 `p` 派到命题池，以候选 `r` 实例化（AggressiveModeTest:69–73）。

### 例 4：反证法（需 @classic）

```subl
@classic
fun raaCase[@p, @q]<¬p → q, ¬p → ¬q>: Null {
  ∴ p
}
```

假设 `¬p` 导出 `q` 与 `¬q` 矛盾 ⇒ `p`。去掉 `@classic` 后激进模式也**绝不**启用此通道（健全性看守）。

### 例 5：进度输出（stderr，节流后）

```
[激进证明] 已证 3 / 待证 7 | 搜索中
  当前目标：r ∨ ¬r
  当前 Γ 相关事实：∀p. p ∨ ¬p， r（共 2 项）
  最近尝试的定理：tertiumNonDatur
  池规模：表达式 12 | 类型 4 | 命题 9（步 1042）
```

触发条件：`--prove-verbose` 时每步都打；否则每 100 步或每 `--prove-interval` 打一次（Aggressive.kt:103）。

### 例 6：中断后得到的诊断报告

```markdown

  - ¬p → q
```

## 陷阱

1. **只作用于 compile/check**——`parse`/`tokens`/`run-script` 不经证明器，旗标被静默忽略（USAGE:36 明示"只作用于 compile/check"）。run-script 路径由解释器直接求值（Main.kt:350–356），无 `session`。
2. **可能不停机**——饱和轮数改 `Int.MAX_VALUE`，靠不动点退出；迭代加深无上限。遇到长耗时模块的正确姿势是 Ctrl-C 看报告，不是干等。
3. **诊断报告仅中断时写**——正常编译结束（含证出全部义务）不生成 `sublimation-prover-dump.md`；别拿不到文件当成没跑激进模式（Main.kt:362–363）。
4. **退出码 130 ≠ 编译失败**——Ctrl-C 中断经 `halt(130)` 立即退出，绕过其余 shutdown 处理；脚本据此区分"被中断"与"检查未通过（exit 1）"。
5. **`@classic` 是反证法/排中律的开闸条件**——文件内任一声明带注解即挂载；忘了挂会退回直觉主义强度（心证不出的全称命题直接报错），且 `if[p]` 前置检查会报 `E-NEED-CLASSIC` 警告（Checker.kt:704）。
6. **池上限是硬截断**——`maxExprs = 500` / `maxTypes = 200` / `maxProps = 200` / `maxCombos = 4096` 超限即截断（命题维按"是否目标的子命题"稳定排序后保留重叠度高者，Aggressive.kt:227–230）。截断**只影响能否搜到**，不影响判定方向；但大模块里确实可能因截断而漏证——此时报告里池规模会顶到上限，可作为线索（精确截断策略以代码为准，本文不再展开，部分细节**待核**）。
7. **记忆化只记成功**——同 (`Γ`, goal) 证一次即可复用；失败不记，因此反复证同一不可证目标的开销不会摊薄（Aggressive.kt:29）。
8. **进度打在 stderr**——`--prove-verbose` 配合重定向时注意把 stderr 与 stdout 分开收集，否则进度行会混进 `compile` 打印的 JS（单文件 compile 的 JS 走 stdout，诊断走 stderr，见 Main.kt:304/322）。
9. **健全性底线不变**——激进模式**不**接受未证前提、不做近似、不猜。若某目标在激进模式下仍报 `E-CANNOT-PROVE`，那是真的没证出来；不要指望"更激进"能放过它。
10. **`--prove-interval` 解析**——`s`/`ms` 后缀；非法值回退默认 5 秒（Main.kt:56–60 的分支未逐一审计，精确回退行为**待核**）。
11. **普通模式零回归是设计约束**——`session == null` 时三维池/不动点/迭代加深/∨ 消去全部关闭（Checker.kt:37–41 的注释明示"普通模式行为完全不变"）；给同一份代码切旗标做 diff 调试时，差异应只出现在证明义务的诊断上，若类型/可变性/纯度诊断也变了，那是 bug。
12. **对 `∀` 的多名字量词**：组合按维度笛卡尔积展开，多名字 `∀` 的组合数随名字数指数增长（受 `maxCombos` 截断）；写 `∀p, q. …` 时心里要有数。

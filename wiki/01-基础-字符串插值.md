# 字符串插值

> wiki/01-基础-字符串插值 · 主题域：字符串字面量、转义序列、插值解糖 · 事实来源：_langfacts.md §1/§2/§7；frontend Lexer.kt readString（:168）；frontend Parser.kt parseStringLit（:1262）、matchInterpBrace（:1302）、模式位 STR（:1625）；core/string/string.subl（:7/:19）；compiler Types.kt builtinPure（:152/:166）、Checker.kt（:941/:1397）；JsCodeGen.kt（:275/:1215/:1227）；interpreter Interpreter.kt（:295/:313）；E2ETest.kt:393

字符串插值是**语法糖**：`"hello $name"` 与 `"${1 + 2}"` 在解析期被改写为 `concat`/`toStr` 的调用链，语言不为它新增 AST 节点（P8，决策 84）。词法器只负责剥离引号与处理转义，把含 `$` 的原始文本原样交给解析器切分。

## 语法

字符串字面量以 `"` 起止，词法器读为单个 STR token，文本为引号内**原始内容**（不含引号；Lexer.kt:168 readString）。未闭合抛词法错误「字符串未闭合」（Lexer.kt:173）。

### 转义序列

反斜杠引导的转义在**词法层**完成还原（Lexer.kt:174 附近）：

| 写法 | 结果 | 说明 |
|---|---|---|
| `\n` | 换行 LF | |
| `\t` | 制表符 | |
| `\r` | 回车 CR | |
| `\"` 与 `\\` | `"` 与 `\` | 引号与反斜杠自身 |
| 其他 `\x` | `x` | **任何其他字符**按原字符收下，反斜杠静默丢弃 |

即 `\'` 得到 `'`、`\d` 得到 `d`、`\$` 得到 `$`——没有 `\0`、没有 Unicode 转义，也没有「非法转义」报错。

### 插值段

解析器在 STR token 上扫描 `$`（Parser.kt:1262 parseStringLit），两种形态：

| 形态 | 语法 | 解糖为 |
|---|---|---|
| 名字插值 | `$` 紧跟**字母**（Unicode 字母亦可），后续续字母/数字/`_` | `toStr(名字)` |
| 表达式插值 | `${ 任意表达式 }`，`{`/`}` 计数嵌套 | `toStr(表达式)` |

由扫描代码直接决定的边界：

- `$` 后必须紧跟字母才插值；后随 `_`、数字、空格或位于串尾都是**字面 `$`**
- 名字插值只认**裸标识符**：字段访问、方法调用、模块路径须写成 `${…}` 形态
- `${}`（空白内芯）**不生成任何段**，被静默丢弃
- 无 `$` 或无匹配插值的串按普通 `StrLit` 处理

## 语义

### 解糖目标：concat 右嵌套链

`"a${e1}b$e2c"` 被改写为右嵌套 concat 调用（Parser.kt:1293-1296）：

```subl
concat("a", concat(toStr(e1), concat("b", concat(toStr(e2), "c"))))
```

- 段为 `StrLit`（字面部分）或 `CallExpr(toStr, …)`（插值部分），插值段恒包 `toStr`
- **单段直接返回**：`"$name"` 就是 `toStr(name)`，无 concat；`"abc"` 就是 `StrLit("abc")`，连 toStr 都不出现
- 不含 `$` 的串零开销：解糖在解析期完成，检查器/求值器/代码生成看到的只是普通字面量与内建调用

### toStr 与 concat 是内建函数

二者为 `@root` 内建（core/string/string.subl:7/:19），检查器内建表登记签名（Types.kt:152/:166），**无需 import**：

- `concat : (Str, Str) => Str` —— 二元拼接
- `toStr : [T](T) => Str` —— 泛型化正是为插值服务（Types.kt:167 注释），任意类型段都能定型
- 均列于 `builtinPure` 白名单（Types.kt:289）：**插值本身不引入副作用**——被插值表达式纯，则整个串可在纯函数中使用
- `+` 对 `(Str, Str)` 同样定型 `Str`（Checker.kt:1397）：`"a" + "b"` 与插值是同一件事的两种写法

### 运行时渲染

编译侧把内建特判映射到 JS：`concat` → `(a + b)`（JsCodeGen.kt:1215），`toStr` → `__dshtoStr(…)`（:1227）。`__dshtoStr`（:275）与解释器宿主函数（Interpreter.kt:295）互相对齐：

| 值 | 渲染为 |
|---|---|
| 数字（Nat/Int/Rat） | 字面十进制；整数浮点去掉 `.0` 尾巴 |
| List | `[1,2,3]` —— 元素逗号分隔、**无空格** |
| 无参枚举值（单键 tag 对象，如 `None`） | tag 名 `None` |
| 带参枚举值（tag + 载荷，如 `Some(7)`） | 两端不一致：解释器 `Some(7)` 形态，JS 侧落入 `String(v)`（待核统一） |
| 空结构体 | 解释器侧类型名，JS 侧回到 `String` |
| Null/null | 两端分别为 `null` 与 `Null` 形态 |
| 函数值 | 解释器 `<fun>`；JS 侧为 `String(fn)` 输出 JS 源码（两端不一致，待核是否有意） |

### `${}` 内的子解析器

`${expr}` 的内芯被**重新词法+解析**：`Parser(Lexer(inner, fileName).tokenize(), fileName).parseExpr(angle = false)`（Parser.kt:1283）。因此：

- 内芯是完整表达式：调用、lambda、嵌套括号皆可——`${Some(5).map({ x => x + 1 }).getOrElse(0)}` 合法，渲染结果为 6（ModuleE2ETest.kt:357）
- `matchInterpBrace`（Parser.kt:1302）按计数匹配嵌套花括号，内层 `{`/`}` 无需转义
- 子解析器用的就是普通 parseExpr：**同样无运算符优先级、左结合**——`${1 + 2 * 3}` 求值 9，不是 7
- 内芯的词法/语法错误照常抛：`${1 +}` 会以解析失败中断

### 字符串内外的 `$` 是两套机制

字符串外，`$` 是返回值符号、`$n` 是第 n 形参引用（词法粘连为单 token）；字符串内**没有**这条通道——`"$1"` 是字面文本。二者只是恰好共用一个字符。

## 示例

```subl
// 名字插值与表达式插值（E2ETest.kt:393 验收形态）
@impure fun main() {
    var name = "alice"
    print("hello, $name")              // hello, alice
    print("${1 + 2} is three")         // 3 is three
}
```

```subl
// 转义：词法层完成还原
@impure fun main() {
    print("a\tb\nc")                   // 制表、换行
    print("\"quoted\" \\ backslash")   // "quoted" \ backslash
    print("\d")                        // d —— 未知转义丢弃反斜杠
}
```

```subl
// Unicode 名字与复合表达式内芯
@impure fun main() {
    var 数 = 3
    print("数 = $数")                  // 数 = 3（isLetter 认中文字母）
    var xs = [1, 2, 3]
    print("长度 ${xs.size()}，结果 ${xs.map({ x => x * 2 })}")  // 长度 3，结果 [2,4,6]
}
```

```subl
// 字面 $：$ 后跟非字母即字面
@impure fun main() {
    print("price: $100, $_x, or just $")   // price: $100, $_x, or just $
    print(concat("$", "name"))             // $name —— 要输出“$+字母”用 concat 拼接
}
```

```subl
// 枚举值先取载荷再插值，绕开两端渲染差异
@impure fun main() {
    var o = Some(7)
    print("值 ${o.getOrElse(0)}")       // 值 7
}
```

```subl
// 插值段类型任意（toStr 泛型），整体可纯
fun tag(n: Nat): Str = "第 $n 个"       // 无 @impure：解糖只引入纯内建

@impure fun main() {
    print(tag(7))                        // 第 7 个
}
```

## 陷阱

- **`\$` 不能取消插值**：词法器把 `\$` 转义还原为字面 `$`（Lexer.kt readString 的 else 分支），解析器随后照常把它当插值起点——`"\$name"` 与 `"$name"` 一样插值 name。要输出字面 `\$name` 用 `concat("$", "name")` 之类拼接
- **`${}` 静默丢弃**：`"a${}b"` 得到 `ab`，不报错也不留痕（Parser.kt:1284 isNotBlank 判定）
- **`$1` 不是形参引用**：字符串内必须字母开头，`"参数: $1"` 原样输出；引用形参写 `${$1}`
- **`$_x` 不插值**：起点须 isLetter()；下划线、数字、串尾 `$` 一律字面
- **`${1 + 2 * 3}` 等于 9**：无优先级、左结合（子解析器同一规则）；先乘除须写 `${1 + (2 * 3)}`
- **`${…}` 内别放含 `}` 的字符串字面量**：花括号按原文计数（Parser.kt:1302），内层字符串里的 `}` 会提前闭合并切出错误的内芯——解析器注释明确列为当前限制（“字符串字面量内 `} 暂不处理”）。先求值到变量再插值
- **模式里的字符串不插值**：模式位直接用 token 原文构造 PatLit（Parser.kt:1625），`is "$x"` 匹配两个字面字符，与变量 x 无关
- **`$obj.field` 只吃标识符**：插值 toStr(obj)，随后的 `.field` 变字面文本；字段/方法须写 `${obj.field()}`
- **多行字符串在词法层被接受**：readString 不禁止原文换行（反引号标识符显式拒绝换行，字符串没有）——但 `\n` 才是可移植写法，原文换行属顺带行为（待核是否有意保留）
- **插值未定义名照常报错**：`$name` 的 name 未声明走 E-UNBOUND-NAME（Checker.kt:941），不因身处字符串而豁免
- **带参枚举值别直接插值**：`Some(7)` 的渲染两端不同（见语义表），跨端运行前先取载荷（`${o.getOrElse(0)}` 之类）
- **渲染格式跨后端个别差异**：函数值两端不同（见语义表），列表/数字两端一致

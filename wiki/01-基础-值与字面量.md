# 01 基础：值与字面量

卷名：01-基础；主题域：值与字面量（Nat / Int / Rat / Str / Bool(⊤⊥) / 元组 / 转义 / 插值）
事实来源：`_facts/_langfacts.md`（事实表）＞源码：`frontend/src/main/kotlin/sugared/functor/lexer/Lexer.kt`（全文 245 行逐行审读）、`frontend/src/main/kotlin/sugared/functor/parser/Parser.kt`、`compiler/src/main/kotlin/sugared/functor/checker/{Checker,TypeInfer,Types}.kt`、`interpreter/src/main/kotlin/sugared/functor/interpreter/{Evaluator,ScriptValue,GlobalInference}.kt`、`compiler/src/main/kotlin/sugared/functor/codegen/JsCodeGen.kt`；关键行为均经预编译 CLI（`cli/build/install/cli` 下 `run-script` / `compile`）实测复核，未确证之处显式标「待核」。

## 语法

### 空白与注释

空格、制表符、回车、换行一律跳过——**换行不是 token**，语句边界由「中缀糖同行 + 前后空格」等规则在语法层涌现（`Lexer.kt:69-84`）。源文件开头的 BOM（U+FEFF）同样被跳过（`Lexer.kt:74`）。注释只有一种形态：`//` 行注释，吃到换行为止；词法层**没有**块注释（`Lexer.kt:76-78`）。

每个 token 都带一个 `precededBySpace` 邻接标记（`Lexer.kt:23-29`）：紧贴名字的 `<` 是角表实例化/上下文供给，带空格的 `<`、`>` 才是比较。词法层只记录事实，消歧在语法层（`Lexer.kt:19-22`）。

### 数值字面量

| 写法 | 词法 token | 说明 |
|---|---|---|
| `123` | INT | 纯数字串；无十六进制/二进制/下划线分隔 |
| `1.0`、`0.5` | FLOAT | 必须**小数点后紧跟数字**（`Lexer.kt:159-166`） |
| `-5` | MINUS + INT | 语言没有负数字面量，负号是一元运算符 |

三条边界（实测复核）：

- `1.` 不是浮点：词法切成 INT + DOT（`Lexer.kt:159-166`），下游报的是莫名其妙的 `E-UNBOUND-NAME` 而非明确词法错误。
- `1.x` 同理切成 INT + DOT + 标识符。
- 想要 Rat 写 `1.0`；整除需求请用 `floor` 等标准库函数（`Interpreter.kt:359` 注册 `floor`）。

### 布尔字面量

布尔的字面量**只有**两个 Unicode 符号：`⊤`（TOP，真）与 `⊥`（BOT，假）（`Lexer.kt:49`、`136`）。二者属于逻辑单 token 集合 `{∀ ∃ ∧ ∨ ¬ → ↔ ⊤ ⊥}`，**不能**当符号标识符或运算符用（`Lexer.kt:47-49`）。关键字表里没有 `true` / `false`（`Lexer.kt:39-45`）——写成那样只是未绑定的标识符。

### 字符串字面量与转义

双引号字符串，转义表如下（`Lexer.kt:168-189`）：

| 转义 | 含义 |
|---|---|
| `\\n` `\\t` `\\r` | 换行 / 制表 / 回车 |
| `\\"` `\\\\` | 引号 / 反斜杠本身 |
| 其他（如 `\\q`、`\\$`） | **字符本位**：原样保留该字符 |

未闭合的字符串抛 `LexFailure`：「字符串未闭合」，带 `[词法][文件:行:列]` 前缀（`Lexer.kt:31-32`、`173`）。换行在字符串里只是普通字符——字符串可以跨行，因此「未闭合」会一直吞到文件末尾或下一个引号（见陷阱 4）。

### 字符串插值

插值在**语法层**去糖，词法层只产出整段原始文本 STR token（`Parser.kt:1258-1261`）：

- `$name`：`$` 后跟字母，续字母/数字/下划线 → 段名（`Parser.kt:1284-1290`）。
- `${{expr}`：按嵌套大括号计数匹配 `}`，内部文本**重新词法 + 解析**为表达式（`Parser.kt:1273-1283`、`1302-1313`）。

只有原始文本含 `$` 时才进入去糖（`Parser.kt:1265`）。已知限制：`${{}` 内部不能再出现可能吃掉 `}` 的字符串字面量（`Parser.kt:1261`）。

### 元组

| 形态 | 语义 | 出处 |
|---|---|---|
| `(e1, e2)` | 元组字面量：**逗号是唯一判据** | `Parser.kt:1329-1339` |
| `(e)` | 括号表达式，不是元组 | 同上 |
| `(e,)` | 一元组（尾随逗号仍触发元组分支） | 同上；实测 `print((1,))` → `[1]` |
| `()` | **不支持**：实测报「期望表达式」 | 同上 |
| `(T, U)` | 元组类型（类型位的 `(`，其后无 `=>` 即元组） | `Parser.kt:565-585` |
| `(T) => U`、`() => U` | 函数类型（与元组类型由 `=>` 区分） | 同上 |
| `var (a, b) = e` | 元组解构声明（**仅扁平分量名**） | `Parser.kt:816-825` |
| `fun f((a, b): T)` | 函数元组形参解构 | `Parser.kt:392`、`414` |
| `when` 模式 `(p1, p2)` | 元组模式（至少一个逗号） | `Parser.kt:1614-1621` |
| `{(a, b) => …}` | lambda 单元组参数 | `Parser.kt:1692` |

元组各位置允许尾随逗号（`Parser.kt:1336`、`574`）。

### 标识符

- **普通名**：字母（含 Unicode：中文、希腊字母等）或 `_` 开头，续字母/数字/`_`（`Lexer.kt:208-213`）。实测 `var 中文_α = 3` 合法。
- **反引号名**：`@|B|@@任意字符`——空格、符号均可，禁换行与反引号本身；一律产出 IDENT，**不进关键字表**（`@|B|@@when` 是普通标识符，`Lexer.kt:191-206`）。实测 `var @|B|@@when` = 5` 合法。
- **内部 `$` 段粘连**：标识符**中部**的 `$` 段（后随字母/`_`）会并入同一 token，服务注解处理器的合成名 `recomposion$Box$1`（`Lexer.kt:217-225`）。
- **`$` 开头走 DOLLAR**：`$` 紧跟数字则粘连为单 token（`$1`，决策 65）；`$` 后跟字母则切成 DOLLAR + IDENT 两个 token（`Lexer.kt:146-150`）。

### 符号名与逻辑单 token

- `isSymbolStart`：非 ASCII、非空白、非字母数字、且不属于逻辑单 token → 连续符号串粘成**一个 SYMBOL 标识符**（`Lexer.kt:230-242`）。
- 于是 `∈ ≠ ≤ ≥ ≡ ⊕` 这类数学符号都是 SYMBOL；能否当值层中缀用取决于各后端运算符表：`≠` 可以（`Evaluator.kt:288`），`≤` / `≥` 不可以（实测报「不支持中缀运算符「≤」」）。
- 命题层另有 ASCII⇄Unicode 归一（`<=`↔`≤` 等，langfacts §4），但那是命题层规则，不是值层运算符。
- `&&` / `||` 在词法层即归一为 `∧` / `∨`（`Lexer.kt:121-122`）。

### 关键字与多字符运算符

保留关键字 16 个：`fun class struct enum var impl for if else unchecked when is by type return def`（`Lexer.kt:39-45`）。`in` 已去关键字化——词法上是普通 IDENT，由 ops 表按运算符识别（`Lexer.kt:44` 注释；运行时 `in` / `∈` 同通道，`Evaluator.kt:301`）。

多字符运算符（最长匹配优先，`Lexer.kt:106-122`）：

| 写法 | token | 说明 |
|---|---|---|
| `<->` | IFF | 等价（命题位） |
| `=>` | DARROW | 程序位（lambda、when 分支、函数类型） |
| `==` `!=` | EQ / NEQ | 值相等/不等 |
| `<=` `>=` | LE / GE | 比较 |
| `->` | ARROW | **修正案后全位非法**，lexer 出此 token 仅供诊断；命题蕴含用 `→`，程序位用 `=>` |
| `∃!` | EXISTS1 | 唯一存在 |
| `+∵` | PLUS_BECAUSE | 又因为 |
| `..` | RANGE | 区间 |
| `::` | COLON2 | 枚举成员访问 |
| `&&` `||` | LAND / LOR | 文本归一为 `∧` / `∨` |

单字符算符：`+ - * / % ^ = < > & | !`（`Lexer.kt:124-132`；`^` 词法是 POW）。标点：`( ) [ ] { } , ; : . @ \ $ #`（`Lexer.kt:124-129`）。逻辑单 token 另含 `∵` `∴`（`Lexer.kt:138`）。

## 语义

### 字面量的类型归属

| 字面量 | 静态类型 | 命题层副作用 | 出处 |
|---|---|---|---|
| `123` | Nat | 注入 `n ≥ 0` | `Checker.kt:896-900` |
| `1.0` | Rat（IEEE double） | — | `Checker.kt:901` |
|`"…"` | Str | — | `Checker.kt:902` |
| `⊤` / `⊥` | Bool | 归一为 PTop / PBot | `Checker.kt:903`、`Prop.kt:30-31` |
| `(e1, e2)` | `(T1, T2)`（积类型） | — | `Checker.kt:1271-1274` |

`Nat / Int / Rat / Real / Str / Bool / Null / Nothing / Any` 均在基础类型表 `BASE_TYPES`（`Types.kt:10`）；数值塔偏序与运算规则见下。

### 数值塔与提升

$$\\frac{\\Gamma \\vdash e_1 : N_1 \\qquad \\Gamma \\vdash e_2 : N_2 \\qquad N_1, N_2 \\in \\{Nat, Int, Rat\\}}{\\Gamma \\vdash e_1 \\oplus e_2 : N_1 \\sqcup N_2} \\quad (\\text{数值升格};\\ \\oplus \\in \\{+, -, *, \\%\\})$$

其中 `sqcup` 取数值偏序之宽者：`Nat < Int < Rat`（`numericRank`，`TypeInfer.kt:114-115`；合一取宽者在 `TypeInfer.kt:126-127`，四则归并在 `138-139`）。实测 `1 + 0.5` → `1.5`、`3 * 0.5` → `1.5`。

$$\\frac{\\Gamma \\vdash e_1 : N_1 \\qquad \\Gamma \\vdash e_2 : N_2}{\\Gamma \\vdash e_1\\ /\\ e_2 : Rat} \\quad (\\text{真除恒产 Rat})$$

`/` 无论操作数类型，结果恒为 Rat（`TypeInfer.kt:140`）；实测 `1 / 2` → `0.5`。比较类运算恒产 Bool（`TypeInfer.kt:141@@B @@）。

**Int 没有字面量**：一元负号在 checker 中保留操作数类型——`-5` 的表达式类型仍是 `Nat`（`Checker.kt:947`），只有与 `Int` 语境合一时才升格（数值宽松 `Nat↔Int` 放行，`TypeInfer.kt:95`）；解释器全局推导则直接把 `-5` 定型为 `Int`（`GlobalInference.kt:549`）。两端口径不一致，统一与否待核。

### 字面量命题注入

$$\\frac{n \\in \\mathbb{N}}{\\Gamma \\vdash n : Nat \\qquad \\Gamma \\vdash n \\geq 0} \\quad (\\text{字面量注入})$$

每个 Nat 字面量 `n` 在检查时自动注入原子命题 `PAtom(">=", [n, 0])`（`Checker.kt:897-898`）。配合算术通道（`ArithProve.kt` 的差分图与常量折叠），凡由字面量构成的非负性、等式目标均无需额外 `axiom` 即可 discharge。示例见「示例 3」。

### 元组语义

$$\\frac{\\Gamma \\vdash e_i : T_i \\quad (i = 1..n)}{\\Gamma \\vdash (e_1, \\dots, e_n) : (T_1, \\dots, T_n)} \\quad (\\text{积类型};\\ n \\geq 2\\ \\text{或尾随逗号})$$

元组是无需声明即可使用的结构化值；字面量类型即元素类型之积（决策 61，`Checker.kt:1271-1274`）。元组可嵌套（实测 `(2, (3, 4))` → `[2, [3, 4]]`）；`(x)` 是括号表达式、`(x,)` 才是一元组；空元组不存在。解构的各形态见语法表，其**后端可用性**见陷阱 11。

### 插值的去糖语义

$$\\frac{\\Gamma \\vdash \\text{static parts} : Str \\qquad \\Gamma \\vdash e : T}{\\Gamma \\vdash \\texttt{"}\\dots\\texttt{${{e}}\\dots\\texttt{"} : Str} \\quad (\\text{每段插值恒包}\\ toStr)$$

具体而言：每个 `$name` / `${{expr}` 段被包成 `toStr(...)`（`toStr` 已泛型化，任意类型可插），静态片段仍是 `StrLit`，最后组装成右折 `concat` 链；若只有一个片段则直接返回该片段（`Parser.kt:1276-1298`）。`${{}` 内的表达式由子解析器重新词法+解析（`Parser.kt:1279`）。标准库层面「任意值转字符串（插值段恒包 toStr）」（`core/string/string.subl:18`），`concat` 为核心字符串函数。

### 值模型与两后端

| 类型 | 解释器（ScriptValue） | JS 生成 |
|---|---|---|
| Nat / Int | `Num(Long)` | number |
| Rat | `Real(Double)` | number |
| Str | `Str(String)` | string |
| Bool | `Bool(Boolean)`（但 ⊤/⊥ 求值为 Null，见陷阱 6） | boolean |
| 元组 | `ListV` | 数组（`JsCodeGen.kt:920`，决策 61） |

值模型定义于 `ScriptValue.kt:19-71`。算术中任一端是 Real 则结果为 Real（`Evaluator.kt:311-316`）。

## 示例

以下均为脚本模式（`.subs`，每文件独立执行，无需 main），输出为 CLI `run-script` 实测结果，以注释标注。

示例 1：数值塔与字面量

```subs
print(0.5)           // 0.5   —— Rat 字面量（FLOAT）
print(1.0)           // 1.0
print(-5)            // -5    —— 一元负号 + Nat 字面量
print(1 + 0.5)       // 1.5   —— Nat ⊔ Rat = Rat
print(1 / 2)         // 0.5   —— / 恒产 Rat
print(1 + 2 * 3)     // 9     —— 左结合、无优先级，改优先级须加括号
print(7 % 3)         // 1
print(pow(2, 3))     // 8.0   —— 标准库指数（返回 Real）
```

示例 2：字符串、转义与插值

```subs
var name = "alice"
print("hello, $name")          // hello, alice
print("${{1 + 2} is three")     // 3 is three
print("制表\t结束")            // 制表<TAB>结束
print("未知转义保留字面：\q")   // 未知转义保留字面：q
print("first\nsecond")         // first 换行 second
print(concat("a", toStr(1)))   // a1
print("$" + "name")            // $name —— 拆分拼接以输出字面 $name
```

示例 3：Bool 与命题（修正案后文法）

```subs
fun lit(): Bool {
  ∵ 3 ≥ 0
  ∴ 3 ≥ 0
  return ⊤
}
print(lit())        // null —— 解释器下 ⊤ 的运行时表示问题，见陷阱 6（编译端为 true）
print(⊤ == ⊤)       // true —— 比较结果才是真 Bool
print(1 < 2)        // true
```

示例 4：元组

```subs
var p: (Nat, Str) = (2, "y")
print(p)               // [2, y]
print((1, "x"))        // [1, x]
print((2, (3, 4)))     // [2, [3, 4]] —— 可嵌套
print((1,))            // [1]         —— 尾随逗号 → 一元组
print((1))             // 1           —— 无逗号 → 括号表达式
```

元组解构（`var (a, b) = e` / 函数元组形参）目前仅在 JS 编译后端可用，见陷阱 11。

## 陷阱

1. **`->` 全位非法**（修正案）：lexer 仍产出 ARROW token 仅供诊断；命题蕴含用 `→`，程序位（lambda、when 分支、函数类型、零参 lambda）用 `=>`。
2. **`\\$` 不能阻止插值**：lexer 先把 `\\$` 还原成字面 `$`（`Lexer.kt:180-184`），去糖阶段仍按 `$name` 插值——实测 `"\\$name"` 输出的是变量值。要输出字面 `$name`，将 `$` 单独成串再拼接：`print("$" + "name")`（实测 → `$name`）。
3. **`1.` 不是浮点**：词法切成 INT + DOT（`Lexer.kt:159-166`）；浮点必须 `1.0`。且该错误的下游诊断不直观（实测报 `E-UNBOUND-NAME`）。
4. **未闭合字符串不限于本行**：字符串可跨行（换行是普通字符），缺右引号会吞掉后续行直到下一个引号或 EOF；错误形如 `[词法][f.subs:1:10] 字符串未闭合`（`Lexer.kt:173`）。
5. **Unicode 比较符号大多是 SYMBOL 标识符而非运算符**：`1 ≤ 2` 实测报「不支持中缀运算符「≤」」（`Evaluator.kt:307`）；比较请写 `<=` / `>=`。例外：`≠` 在解释器等同于 `!=`（`Evaluator.kt:288`）。`<` / `>` 不在 `binops` 集合（`Parser.kt:50-55`），走中缀糖/符号调用路径，实测 `1 < 2` → `true`。
6. **Bool 在解释器后端失真**：⊤ 与 ⊥ 运行时都求值为 `ScriptValue.Null`（`Evaluator.kt:270`）——实测 `print(⊤)` → `null`、`⊤ == ⊥` → `true`、`¬⊤` → `true`（Null 被当作假值）。JS 编译端正确生成 `true` / `false`（`JsCodeGen.kt:867-868`），命题层 PTop/PBot 亦正确区分（`Prop.kt:30-31`）。是否既定边界待核；跨端代码勿依赖布尔字面量的运行时真值。
7. **`^` 无值层实现**：词法是 POW 且在 `binops`（`Parser.kt:51`），但解释器没有实现——实测 `2 ^ 3` 报「不支持中缀运算符「^」」（`Evaluator.kt:307`）；`TypeInfer.builtinOp` 表中也无 `^`（`TypeInfer.kt:135-146`）。指数用 `pow(2, 3)`（实测 → `8.0`）。
8. **`→` / `↔` 是命题运算**：不参与运行时求值——解释器抛「蕴含是命题运算，不参与运行时求值」（`Evaluator.kt:299-300`）。
9. **没有运算符优先级，全左结合**：`1 + 2 * 3` 实测为 `9`；要优先级必须加括号（langfacts §2）。
10. **Nat 不变量不被负字面量保障**：checker 中一元负号保留操作数类型（`-5` 表达式类型仍是 Nat，`Checker.kt:947`），靠数值宽松 `Nat↔Int` 放行（`TypeInfer.kt:95`）；实测 `var n: Nat = -5` 通过检查并存入 `-5`。解释器全局推导则直接给 `-5 : Int`（`GlobalInference.kt:549`）——两端口径不一致（待核统一）。
11. **元组解构仅在 JS 编译后端可用**：解释器中 `var (a, b) = (1, "x")` 的 `a` 绑住整个元组、`b` 未定义（实测报「未定义的变量「b」」——解释器源码对 `destruct` 零处理）；JS 编译端生成 `const [a, b] = [1, "x"]` 正常（实测输出 `1` / `x`）。函数元组形参同理：`fun g((a, b): (Nat, Str)): Nat = a` 解释器返回整个元组，编译 + node 返回 `7`。
12. **解构只支持扁平分量名**：`var (a, (b, c)) = e` 实测报「期望标识符，实际'('」（`Parser.kt:816-825` 只读扁平名表）；嵌套取值请逐层解构。
13. **括号 vs 元组的判据是逗号**：`(x)` 是括号表达式而非一元组；`(x,)` 才是一元组；空元组 `()` 不被支持（实测报「期望表达式」）。
14. **`$1` 的两种身份**：字符串内 `$1` 是字面量（插值只认 `$`+字母 或 `${{`）；代码位 `$1` 是粘连的参数引用 token（`Lexer.kt:146-150`），且只允许出现在前件/后件位——函数体内使用报 `E-PARAM-REF-IN-BODY`（`Checker.kt:904-907`）。
15. **元组打印格式两端不同**：解释器输出 `[1, x]`（逗号 + 空格），JS 运行时 `__dshtoStr` 用 `,` 连接输出 `[1,x]`。Rat 打印保留小数位（`1.0` → `1.0`，实测）。
16. **全角标点有专用报错**：`（）【】＜＞＝，；："'！＆｜` 等字符会触发「这是中文全角符号，请换成英文半角符号」（`Lexer.kt:51`、`140`）。
17. **反引号名可绕开关键字但不能跨行**：`@|B|@@when` 是普通标识符（实测 `var @|B|@@when` = 5` 合法），但反引号名内禁换行与反引号本身（`Lexer.kt:193-206`）。
18. **`check` 与 `run-script` 的顶层规则不同**：`check`（工程模式）顶层只接受声明，语句须放进 `fun main()`（实测报「期望顶层只能写声明，执行代码请放进 fun main()」）；`run-script`（脚本模式）直接执行顶层语句。调试本文示例时注意区分。

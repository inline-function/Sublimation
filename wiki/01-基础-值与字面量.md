## 语法

### 数值字面量：Nat 与 Rat 的两种词法形态

| 写法 | 词法 token | 静态类型 | 说明 |
|---|---|---|---|
| `0` `42` `2024` | INT（`[0-9]+`） | Nat | 纯数字串；无进制前缀、无下划线分隔 |
| `1.0` `0.5` `3.14` | FLOAT | Rat | 必须**小数点两侧都有数字**（Lexer.kt:159-166） |
| `-5` | MINUS + INT | Nat（见陷阱 2） | 语言没有负数字面量——负号是一元运算符 |

三条实测边界（都不构成数值字面量）：

- `1.`：词法切成 INT + DOT，再随上下文产生下游错误（实测 `print(1.)` 报「期望标识符」——词法层没有任何提示）。
- `.5`：`.` 走 DOT token，实测报「期望表达式」。
- `1e3`：无科学计数法，词法切成 INT + IDENT，实测报「期望RPAREN」。

### 布尔字面量：⊤ 与 ⊥

`⊤`（TOP）与 `⊥`（BOT）是**固定逻辑单 token**，属于集合 `{∀ ∃ ∧ ∨ ¬ → ↔ ⊤ ⊥}`（Lexer.kt:47-49、136）：不与符号标识符合并、不能当中缀运算符。它们是这门语言最字面意义上的布尔真值（与 `true`/`false` 的分工见语义节）。

### 字符串字面量与转义表

双引号字面量，词法层产出整段 STR token（Lexer.kt:168-189）。转义表（`Lexer.kt:180-184`）：

| 转义序列 | 实际字符 | 备注 |
|---|---|---|
| `\n` | 换行（U+000A） | |
| `\t` | 制表符（U+0009） | |
| `\r` | 回车（U+000D） | |
| `\"` | `"` | |
| `\\` | `\` | |
| 其他 `\<c>` | `c` 本身 | **反斜杠被静默丢弃**：`\'` 得 `'`、`\q` 得 `q`、`\$` 得 `$`（后果见陷阱 1） |

未闭合的字符串抛 `LexFailure`「字符串未闭合」（Lexer.kt:173）。换行在字符串内是普通字符——字符串可以跨多行（实测 `print("line1<换行>line2")` 输出两行），也因此缺右引号时会一直吞到下一个引号或 EOF（陷阱 4）。字符串原生支持 Unicode，无需任何前缀。

### 字符串插值

插值在**语法层**脱糖（Parser.kt:1258-1299），两种形态：

- `$name`：`$` 后紧跟字母，续字母/数字/下划线（Parser.kt:1284-1290）。`$1`、`$ ` 等不触发——字符串内 `$1` 就是字面文本（实测 `print("a $1 b")` → `a $1 b`）。
- `${expr}`：按嵌套大括号计数匹配配对的 `}`（Parser.kt:1302-1313），内部文本**重新词法 + 解析**为表达式（Parser.kt:1279）。空白的 `${}` 被静默丢弃（实测 `print("a${}b")` → `ab`）。文档限制：`${}` 内不要出现可能吃掉 `}` 的文本（Parser.kt:1260 注释）。

### 元组字面量

括号内以**逗号为唯一判据**（决策 62；Parser.kt:1329-1339）：

| 形态 | 结果 |
|---|---|
| `(e1, e2, …)` | 元组字面量；各位置允许尾随逗号（`(1, 2,)`） |
| `(e)` | 括号表达式——不是元组 |
| `(e,)` | 一元组（尾随逗号仍触发元组分支） |
| `()` | 不支持——实测报「期望表达式」 |

元组字面量的类型位写法是 `(T, U)`；带 `=>` 的 `(T) => U` / `() => U` 是函数类型，由 `=>` 与元组类型区分。

## 语义

### 字面量的定型规则

$$\frac{}{\Gamma \vdash n : \text{Nat} \qquad \Gamma \vdash n \geq 0} \quad (\text{Nat 字面量注入})$$

每个 Nat 字面量在检查时同时向上下文注入原子命题 `n ≥ 0`（Checker.kt:896-900），配合算术通道（ArithProve 的差分图与常量折叠），由字面量构成的非负性目标无需额外 `axiom` 即可 discharge（实测见示例 5）。

$$\frac{}{\Gamma \vdash 1.0 : \text{Rat}} \; (\text{Rat}) \qquad \frac{}{\Gamma \vdash \texttt{"s"} : \text{Str}} \; (\text{Str}) \qquad \frac{}{\Gamma \vdash \top,\bot : \text{Bool}} \; (\text{Bool})$$

（Checker.kt:901-903。Rat 即「IEEE double via JS Number」（Ast.kt:379 注释）。）

$$\frac{\Gamma \vdash e_i : T_i \quad (i = 1..n)}{\Gamma \vdash (e_1, \dots, e_n) : (T_1, \dots, T_n)} \quad (\text{积类型；Checker.kt:1271-1274})$$

元组类型保留各元素的原类型，不做合并或求并（`(1, "x") : (Nat, Str)`）。

### 数值塔：Nat ⊑ Int ⊑ Rat

- Int **没有自己的字面量**：整数常量一律定型为 `Nat`。`Int` 值来自 Int 语境（如标准库 `strCmp` 的返回类型，Types.kt:163-165）或数值升格。
- 升格偏序 `numericRank`：Nat=0 < Int=1 < Rat=2，合一取宽者（TypeInfer.kt:114-127）。实测 `1 + 0.5` → `1.5`。
- 数值三型彼此**宽松等价**（`looseNumeric`，TypeInfer.kt:94-95）：`var x: Rat = 1`、`var i: Int = -5` 均实测通过；但跨出数值塔即报错——`var s: Str = 1` 实测 `E-TYPE-MISMATCH`。
- Rat 通道意味着 `/` 恒产 Rat：实测 `10 / 4` → `2.5`（Evaluator.kt:284）——**Nat 除法不是整除**。

### ⊤⊥ 与 true/false 的关系

两者**类型都是 Bool**（Checker.kt:903 与预声明枚举），但身份与适用层面不同：

| | `⊤` / `⊥` | `true` / `false` |
|---|---|---|
| 词法 | 固定逻辑单 token（TOP/BOT，Lexer.kt:136） | 普通字母标识符，非关键字 |
| AST | `TopExpr` / `BotExpr`（Ast.kt:387-388） | `NameRef` |
| 语义身份 | **命题层**真值常元：归一为 `PTop`/`PBot`（Prop.kt:30-31） | **值层**布尔：预声明枚举 `enum Bool { true, false }` 的零参构造子（Checker.kt:183 注册；ModuleTree.kt:154 亦列入保留名） |
| 值层用法 | 可作表达式，类型 Bool | 可绑定、可 `==`、可在 `when` 模式按构造子分派（实测 `when (b) { true => …; false => … }` 正确） |
| JS 编译 | `true` / `false`（JsCodeGen.kt:867-868） | `true` / `false`（JsCodeGen.kt:843；枚举成员跳过声明，:586） |
| 解释器求值 | `ScriptValue.Null`（Evaluator.kt:270）⚠ | `ScriptValue.Bool(true/false)`（Evaluator.kt:209-210） |

用法结论：

- **命题与逻辑式用 ⊤⊥**：`p → ⊤`、`¬⊥`、`∀n. n ≥ 0`。`∧ ∨ ¬` 及词法归一后的 `&&`/`||`（Lexer.kt:121-122）对两者等价可用。
- **需要「值」的场合用 true/false**：变量绑定、相等比较、`when` 模式匹配。
- **不要相互比较**：`⊤ == true` 实测在解释器为 `false`（⊤ 求值为 Null），在 JS 编译端为 `true`（两端都生成 JS `true`）——跨端不一致，见陷阱 5。

### 字符串与插值的脱糖语义

$$\frac{\Gamma \vdash e : T}{\Gamma \vdash \texttt{"}\dots\$e\dots\texttt{"} \rightsquigarrow \texttt{concat}(\dots, \texttt{toStr}(e), \dots) : \text{Str}} \quad (\text{每段插值恒包 toStr})$$

每个 `$name` / `${expr}` 段被包成泛型 `toStr(...)`（Types.kt:166-167，插值段类型任意），静态片段仍是 `StrLit`，最后组装成右折 `concat` 链（Parser.kt:1276-1298），故插值字符串的类型恒为 `Str`。实测 `print("tuple: ${(1, 2)}")` → `tuple: [1,2]`。

语言没有字符（Char）类型：单字符即长度为 1 的 Str，`charAt` 的返回类型也是 Str（Types.kt:157-159）。

### 值模型与两后端

| 类型 | 解释器（ScriptValue） | JS 生成 |
|---|---|---|
| Nat / Int | `Num(Long)`（Evaluator.kt:201-205） | number |
| Rat | `Real(Double)`（Evaluator.kt:206） | number（字面量原文直出，JsCodeGen.kt:840） |
| Str | `Str`（Evaluator.kt:207） | string（`q()` 转义包装，JsCodeGen.kt:841） |
| Bool（true/false） | `Bool(Boolean)` | boolean |
| Bool（⊤/⊥） | `Null`（Evaluator.kt:270）⚠ | boolean（`true`/`false`） |
| 元组 | 列表 | 数组（实测 `(1, "x")` 生成 `[1, "x"]`） |

整数精确性与精度边界（实测）：

- 字面量在解释器内保留精确 `Long`：`print(9007199254740993)` 原样输出。
- 但算术走 double 通道：`print(9007199254740991 + 2)` → `9007199254740992`（2 的 53 次方精度丢失，Evaluator.kt:311-316）。
- 词法与静态检查**没有**数值范围校验：超出 Int64 的字面量（如 `100000000000000000000`）通过 `check`，在解释器运行时报「非法整数」（Evaluator.kt:202-203）。

## 示例

以下均为脚本模式（`.subs`，`run-script` 直接执行顶层语句），输出为实测结果、以注释标注。

示例 1：数值字面量与数值塔

```subs
print(42)            // 42
print(1.0)           // 1.0    —— Rat 字面量（小数点两侧都要有数字）
print(0.5)           // 0.5
print(1 + 0.5)       // 1.5    —— Nat ⊔ Rat = Rat
print(10 / 4)        // 2.5    —— / 恒产 Rat，Nat 除法不是整除
print(1 + 2 * 3)     // 9      —— 全左结合、无优先级，要优先级须加括号
print(2 * (1 + 2))   // 6      —— 括号可强制优先级
var x: Rat = 1       // 数值塔宽松等价：Nat 初值可绑定到 Rat
print(x)             // 1
```

示例 2：字符串转义与插值

```subs
var name = "subl"
print("hello, $name!")            // hello, subl!
print("${1 + 2} is three")     // 3 is three
print("a\nb\tc\'d\"e\\f")  // a 换行 b<TAB>c'd"e\f —— 转义表逐项演示
print("未知转义静默丢反斜杠：\q")  // 未知转义静默丢反斜杠：q
print("a $1 b")                    // a $1 b    —— $ 后非字母，不插值
print("tuple: ${(1, 2)}")      // tuple: [1,2]
```

示例 3：Bool 的两个面孔

```subs
var b: Bool = true              // true/false：Bool 枚举构造子，值层用
print(b)                        // true
when (b) {
  true => print("T")            // T   —— when 按构造子模式分派
  false => print("F")
}
print(⊤ ∧ ⊥)                    // false —— 逻辑运算对 ⊤⊥ 正确
print(¬⊥)                       // true
print(1 < 2)                    // true  —— 比较的结果才是真 Bool
```

示例 4：元组

```subs
var p: (Nat, Str) = (2, "y")    // 元组类型即元素类型之积
print(p)                        // [2, y]
print((2, (3, 4)))              // [2, [3, 4]]  —— 可嵌套
print((1,))                     // [1]          —— 尾随逗号 → 一元组
print((1))                      // 1            —— 无逗号 → 括号表达式
```

示例 5：Nat 字面量的命题注入（修正案后文法）

```subs
fun nonneg(n: Nat): Bool {
  ∵ ⊤
  ∴ n ≥ 0          // Nat 形参自带 n ≥ 0（Checker.kt:497），直接 discharge
  return true
}
print(nonneg(3))                // true

var k = 5
∵ ⊤
∴ k ≥ 0           // 字面量 5 注入 5 ≥ 0，算术通道代换为 k ≥ 0
print(k)                        // 5
```

## 陷阱

1. **\$ 不能阻止插值**：lexer 的兜底分支先把 \$ 还原成字面 `$`（Lexer.kt:180-184），脱糖阶段仍按 `$name` 插值——实测 `"\$name"` 报 `E-UNBOUND-NAME`（没找到 `name`）。要输出字面 `$name`：把 `$` 单独成串再拼接，实测 `print(concat("price: \$", "name"))` → `price: $name`；`"price: \$" + "name"` 亦可（→ `price: $name`，`+` 对 Str 做拼接）。
2. **`-5` 的类型是 Nat 而非 Int**：一元负号在 checker 中保留操作数类型（Checker.kt:947），Nat 非负性只在命题层（`n ≥ 0` 注入）而非类型层强制——实测 `var n: Nat = -5` 通过检查并输出 `-5`。解释器的全局推导则把 `-字面量` 直接定型为 `Int`（GlobalInference.kt:549），两端口径不一致（待核统一）。真需要 Int 语义时靠 Int 语境或 `strCmp` 等标准库出口。
3. **Rat 形态三个坑**：`1.`（INT+DOT）、`.5`（DOT 开头）、`1e3`（无科学计数法）都不是浮点字面量，且报错位置在下游而非词法层。Rat 必须写成 `1.0` 形。
4. **未闭合字符串不限于本行**：字符串可跨行（换行是普通字符），缺右引号会吞掉后续行直到下一个引号或 EOF；错误形如 `[词法][f.subs:1:10] 字符串未闭合`（Lexer.kt:173）。
5. **⊤⊥ 在解释器后端失真**：`⊤` 与 `⊥` 运行时都求值为 `ScriptValue.Null`（Evaluator.kt:270）——实测 `print(⊤)` → `null`、`if (⊤) { … }` 不进分支、`⊤ == true` → `false`（Null 被当作假值）。JS 编译端正确生成 `true`/`false`（JsCodeGen.kt:867-868），命题层 `PTop`/`PBot` 亦正确区分（Prop.kt:30-31）。是否既定边界待核；跨端代码勿依赖 ⊤⊥ 的运行时真值，需要布尔值就用 `true`/`false`。
6. **运算符优先级不存在**：表达式全左结合（langfacts §2），`1 + 2 * 3` 实测为 `9`；要优先级必须加括号。
7. **括号与元组的判据是逗号**：`(x)` 是括号表达式而非一元组，`(x,)` 才是一元组，空元组 `()` 无字面量写法（`EmptyTuple` 类型虽在 BASE_TYPES 中预声明，但无构造语法，Types.kt:11、147）。
8. **整数范围只在运行时查**：超出 Int64 的字面量词法与 `check` 均通过，解释器执行时抛「非法整数」（Evaluator.kt:202-203）。此外算术经 double：`9007199254740991 + 2` 实测为 `9007199254740992`（2 的 53 次方以上丢精度），而字面量本身精确。
9. **字符串内 `$1` 是字面、代码位 `$1` 是参数引用**：插值只认 `$`+字母 或 `${`；代码位 `$` 紧贴数字会粘连为 DOLLAR token（Lexer.kt:146-150），且 `$n` 只允许出现在前件/后件位——函数体内使用报 `E-PARAM-REF-IN-BODY`（Checker.kt:904-907）。
10. **`&&`/`||` 只是语法糖**：词法层即归一为 `∧`/`∨`（Lexer.kt:121-122），写出来是同一个运算；`<->`→IFF、`->`→ARROW 等多字符算符按最长匹配优先（Lexer.kt:106-122），其中 `->` 修正案后全位非法（仅供诊断）。
11. **插值的 `${}` 内别放字符串**：子解析器按括号计数找 `}`，内部文本若含 `}` 会被提前截断（Parser.kt:1260 注释记录的已知限制）；空白 `${}` 被静默丢弃而非报错。
12. **全角标点有专用报错**：`（）【】＜＞＝，；："＇！＆｜` 等字符触发「这是中文全角符号，请换成英文半角符号」（Lexer.kt:51、140）。
13. **调试时区分两种模式**：`check`/`compile` 对单文件也走工程模式，顶层只接受声明，语句须放进 `fun main()`（实测报「期望顶层只能写声明，执行代码请放进 `fun main()`」）；`run-script` 才是直接执行顶层语句的脚本模式。本文示例均为脚本模式，且工程模式下 `print` 受纯性闸门约束（需 `unchecked print(…)` 或供给 `pure<print>`）。

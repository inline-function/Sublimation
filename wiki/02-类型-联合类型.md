# 联合类型（Nat | Str）与 is 类型判别

联合类型把若干类型 `A | B | C` 拼成一个**内联和类型**：值是其中任意一个变体，类型只在检查器里存在，运行时不加包装（Parser.kt:529 注释：枚举=和类型，联合是「内联无 tag 形式」）。要分辨一个联合值属于哪个变体，靠 `is T` 类型测——以及它带出来的智能收窄。可以把它想成「不声明构造子的枚举」：枚举用构造子区分变体，联合用 `is` 按类型区分（对照 [枚举](02-类型-枚举.md)）。

## 语法

### 联合类型写法

```subl
type JsonVal = Nat | Str | Bool        // 三个变体（从左到右平坦展开）
type Pair = (Nat, Nat) | Nat           // 元组也可以作变体
fun f(o: Nat | Str): Nat = 1           // 形参位（两变体 Nat | Str）
struct Box(v: Nat | Str)               // 字段位
```

文法要点（Parser.kt:506-541）：

- 联合可以出现在**任何类型位**：形参/返回类型标注、字段、类型别名、类型实参
- `|` 解析为平坦列表：`A | B | C` → `UnionType([A, B, C])`，不嵌套（Ast.kt:206-211）；render 与诊断回显都用 `" | "` 连接，如 `Str | Nat`
- **第一个操作数**走完整 parseType（可带 `@mut`/`@atomic` 前缀，:508-522）；**`|` 之后的变体**只接受具名类型或括号类型（:535：`(` → parseFunOrTupleType，否则 parseNamedType）——所以 `Nat | @mut Str` 解析失败，而 `@mut Str | Nat` 可以（见陷阱 3）
- `is` 是词法关键字（Lexer.kt:43），`|` 是单字符 PIPE（Lexer.kt:132）。表达式位没有 `a | b` 运算（按位或不是本语言算符），`|` 只在类型位出现

### is 类型判别（表达式位）

```subl
fun q(o: Nat | Str): Bool = o is Nat       // 中缀类型测，结果是 Bool 值
fun r(o: Nat | Str): Bool = o is Any       // Any：解释器恒真（JS 后端另有行为，见陷阱 10）
```

- 中缀 `表达式 is 类型`（Parser.kt:1044-1061）：右操作数是**类型名**，不是值表达式（v2.1，对齐 Rust）；类型类判定由 checkTypeTest 在语义层拦截
- **同行约束**：`is` 必须与被测表达式同一行，否则解析器把它让给下一个 when 分支的模式（:1045-1047，防 `is Str => 0` 换行后的 is 被误吞）
- `is Ctor(...)` 形态（is 后跟圆括号构造调用）一律按**模式**处理，不建 TypeTestExpr（:1048-1058）；`if (o is Some(e))` 作 if 整条件时脱糖为 when（IsPatExpr，:1052-1055）

### when 类型分支

```subl
fun categorize(o: Nat | Str): Str =
    when(o) {
        is Nat => "数"                // 类型分支：is + 类型
        is Nat as n if n > 100 => "大"  // as 绑定 + if 守卫
        is Str as s => s              // 绑定变量按被测类型用
        else => "其它"                // 兜底（联合主题下反收窄）
    }
```

- 分支分隔符是 `=>`（Parser.kt:1545-1546：修正案把原 `->` 改为 `=>`，与蕴含中缀彻底解耦）
- 类型模式 `is T`，可选 `as x` 绑定（PatIs，Parser.kt:1606-1608）；守卫写 `模式 if 表达式`
- 绑定主题 `when(var e = 0)`、无主题 when、模板 when 是另外的入口，此处只讲类型分支

## 语义

### 联合的成员关系

联合是检查器层的概念。值进入联合主要靠**调用位放宽**：形参声明为 `Nat | Str` 时，实参只要命中任一变体即通过（CallCheck.kt:874-887）：

```subl
fun f(o: Nat | Str): Nat = 1
fun g(): Nat = f(7)          // OK：Nat 是变体
fun h(): Nat = f("x")        // OK：Str 是变体
```

`f(true)` 则报 `E-TYPE-MISMATCH：实参 0 Bool 与形参 Nat | Str 不符`——Bool 不是任何变体。

放宽**只发生在调用位**。变量绑定与函数返回都不做联合拓宽：TypeInfer.unify 对联合不相交的两类型返回 null（TypeInfer.kt:123-130），compatibleView 只认 `@mut` 视图（Checker.kt:848-855），于是 `var x: Nat | Str = 7` 与 `fun k(): Nat | Str = 7` 都报 E-TYPE-MISMATCH（见陷阱 1）。

联合的不可变性按变体逐一看：`Nat | Str` 整体不可变，含可变变体的联合按可变处理（Symbols.kt:75 reprImm 对 UnionType 逐变体合取），于是走进 [拷贝规则](02-类型-拷贝规则.md) 的同一套判定。

### is 的运行时判定

检查器侧（checkTypeTest，Checker.kt:1421-1430）：`is T` 返回 Bool，T 必须可解析，且**只能判结构体/枚举/基本类型**——类型类（`class` 声明）是编译期约束、无运行时 tag，`s is Show` 直接报 E-TYPE-MISMATCH。

运行时是**结构判定**，解释器与 JS 后端规则一致（Evaluator.kt:797-815 matchType / JsCodeGen.kt:283-292 __isa）：

| 被测类型 T | 判定规则 |
|---|---|
| Nat / Int | 数值（ScriptValue.Num / `typeof v === "number"`） |
| Rat | Real 或 Num（JS：number） |
| Str / Bool | 字符串 / 布尔 |
| Null | 空值（或 tag 为 Null） |
| List / Set / Map | 数组 / 数组 / Map 链结构 |
| 结构体、枚举 | 值的 typeName / tag 等于 T |
| Any | 解释器恒真；JS 后端走 tag 分支（见陷阱 10） |

联合值不加包装：`Nat | Str` 里的 7 在运行时就是 7，判别全靠上表。

### 智能收窄与反收窄

- **if**：条件是 `x is T` 且 x 是名字时，then 分支帧把 x 重新声明为 T，并注入命题 `x : T`（Checker.kt:1179-1186）；else 分支若 x 原先是联合且 T 是其变体，则收窄为「联合减 T」（:1208-1218）：

```subl
@impure
fun test(o: Str | Nat) =
    if(o is Str)
        print(strUpper(o))      // then：o : Str，可调 Str 专用内建
    else
        print(o + 1)            // else：o 反收窄为 Nat，可做算术
```

- **when**：`is T` 分支把主题（或 `as x` 绑定量）按 T 重新声明（WhenCheck.kt:251-253），分支命题是原子 `subj : T`（:254）；`else` 分支对联合主题做同样反收窄（:139-143）
- 收窄只对**名字**生效：`x.v is Nat` 这种字段目标不会反过来收窄 `x.v`（IfExpr 分支帧要求 NameRef，:1182-1187；when 同理 :253）

### 穷尽性

联合主题的 when 有专门规则（WhenCheck.kt:170-174）：**所有无守卫 `is` 分支合起来覆盖全部变体 → 判密封**，when 值类型即各分支类型的 join，可作表达式返回非 Null 值：

```subl
fun describe(o: Nat | Str): Str =
    when(o) {
        is Nat => "数"
        is Str => "串"
    }                            // 无需 else：is 分支覆盖 Nat 与 Str 两个变体
```

覆盖不全时**没有 W-NON-EXHAUSTIVE 警告**——该警告只发给有覆盖律的名义枚举主题或无主题 when（:175-178）；联合主题静默退化为「未密封」，值类型按 Null 处理，一旦流向非 Null 上下文（如函数返回类型）由 E-NON-SEALED-MATCH 兜住：

```subl
fun p(o: Nat | Str): Nat =
    when(o) { is Nat => 1 }
// 上段故意不穷尽：E-NON-SEALED-MATCH「函数 p 的返回值来自 when 表达式，
// 但分支不穷尽（值可能为空 Null）」
```

判密封只统计**无守卫**的 is 分支（:172）：守卫分支不参与覆盖统计，但仍可正常匹配。分支命题按顺序否定累积（:129）——后分支的帧里带着前分支命题的否定。

## 示例

**结构与判别**（脚本模式，实测输出如下）：

```subl
struct Point(x: Nat, y: Nat)
struct Label(text: Str)

fun describe(g: Point | Label): Str =
    when(g) {
        is Point => "点(${g.x}, ${g.y})"     // 分支内 g 收窄为 Point，可取字段
        is Label => "标签:${g.text}"
    }

print(describe(Point(3, 4)))    // 点(3, 4)
print(describe(Label("hi")))    // 标签:hi
```

**if 收窄、else 反收窄、is 作布尔值**：

```subl
fun classify(o: Nat | Str): Str =
    if(o is Nat) "数" else "串"       // then: o : Nat / else: o : Str

fun isNat(o: Nat | Str): Bool = o is Nat
```

**as 绑定与守卫**（守卫分支不参与密封统计，另两个无守卫 is 分支补全变体）：

```subl
fun discount(o: Nat | Str): Nat =
    when(o) {
        is Nat as n if n > 100 => n - 20
        is Nat as n => n
        is Str => 0
    }

print(discount(150))     // 130
print(discount(7))       // 7
print(discount("abc"))   // 0
```

**联合别名**（别名展开后与联合同形）：

```subl
type JsonVal = Nat | Str | Bool

fun j(v: JsonVal): Str =
    when(v) {
        is Nat => "数"
        is Str => "串"
        is Bool => "布尔"
    }

print(j(true))           // 布尔
```

## 陷阱

1. **绑定/返回位不拓宽联合**：只有调用位接受「命中变体即入参」。`var x: Nat | Str = 7` 报「var x 标注了 Nat | Str，但初值是 Nat，两边类型不一致」；`fun k(): Nat | Str = 7` 报「函数 k 声明返回 Nat | Str，但函数体是 Nat」。要造联合值就经形参传入
2. **数值变体运行时不可区分**：Nat/Int/Rat 共用同一运行时表示（Num / number），`is Nat`、`is Int`、`is Rat` 对任意数值**同时为真**。`fun kind(o: Nat | Int): Str = when(o) { is Nat => "Nat"  is Int => "Int"  else => "?" }` 调 `kind(7)` 永远命中首个分支打印 "Nat"——`Nat | Int` 没有判别力，匹配顺序敏感
3. **`|` 右侧变体不能带类型注解**：变体位只解析具名/括号类型，`Nat | @mut Str`、`Nat | @ref Str` 直接解析失败（报「期望标识符 '@'」）。带注解的类型只能放第一个操作数（`@mut Str | Nat` 可解析，但仍受 @mut 形参须 @impure 等规则约束）
4. **is 模式遇括号类型会被 `=>` 吞掉**：联合本身可以含元组变体（`(Nat, Nat) | Nat` 合法），但 when 分支写 `is (Nat, Nat) => …` 时，parseType 见 `)` 后的 `=>` 会按函数类型 `(Nat, Nat) => …` 继续吃，报「期望标识符」。元组变体目前无法用 is 模式直接匹配 `待核`（是否后续支持）
5. **is 联合外变体直接报错**：`when(o: Str | Nat) { is Bool => … }` 报「is Bool 不在联合 Str | Nat 中」——检查器要求被测类型必须是某变体（WhenCheck.kt:249-250）
6. **类型类不能用 is**：`class Show[T] { … }` 之后写 `s is Show` 报「is 不能判断类型类 Show（类型类是编译期约束，无运行时 tag）」。运行时判别只针对结构体/枚举/基本类型
7. **联合主题非穷尽静默退化**：与枚举主题不同，联合主题判不出穷尽**不发 W-NON-EXHAUSTIVE**，值类型按 Null 走；流向非 Null 上下文才报 E-NON-SEALED-MATCH。别拿「没有警告」当「已穷尽」
8. **重复变体与重复分支都不拦截**：`Nat | Nat` 合法（无去重检查）；两个 `is Nat` 分支也合法，但第二个在顺序否定与运行时首命中的双重作用下永远不可达
9. **分支类型不一致的两种待遇**：if 两分支名义类型不同直接报错（`if(c) 1 else "x"` → E-TYPE-MISMATCH「if 分支 Nat 与 Str 不一致」）；when 分支类型不一致**不报错**，值类型静默回退为**首个分支**的类型（unify 失败时保留 lastT，WhenCheck.kt:152-153），不会自动联合化——混合分支 when 的返回类型以第一支为准 `待核`（join 失败是否应联合）
10. **`is Any` 两后端不一致**：解释器 matchType 对 Any 恒真（:800）；JS 后端 __isa 没有 Any 特判，落到 tag 比较（`v.tag === "Any"`），基本类型值恒假。跨后端代码别依赖 `is Any` `待核`
11. **旧文法残留**：when 分支写 `is Nat -> …` 在修正案后**全位非法**（`->` 仅作词法诊断保留），分支位一律 `=>`；命题位的蕴含用 Unicode `→`，两者不可混用（见 [箭头家族](01-基础-箭头家族.md)）

# 上下文：上文 / 下文与作用域弥散（Frame · FunType）

> wiki/03-证明-上下文与上文下文 · 主题域：上下文系统（_langfacts §5）
> 事实来源：_langfacts.md §5；Diffusion.kt（Frame、dollarOf）；Checker.kt（checkFun、$n 闸体、lambda 期望位注入、块弥散）；CallCheck.kt（checkFnCall、函数值上下文、checkStructProps）；Prop.kt（structuralHeads）；Symbols.kt（pure<f> 等自然命题）；Parser.kt（parseFun、parseAngleList、$/$n 初等项）；Ast.kt（FunType.context、ParamRefExpr）；examples/上下文弥散.subl；compiler CheckerTest「弥散」组。文中行号为近似定位，以代码语义为准。

上下文是函数签名上的**编译期命题契约**：上文（precondition）是调用方在调用前必须已证的事实，下文（postcondition）是函数体必须兑现、兑现后**弥散进调用方作用域**的事实。它与程序层的值流分流，只活在检查器的作用域帧 Frame 与证明通道里；解释器与 JS 生成都不读它，因而零运行时代价。

## 语法

```subl
fun 名字[理论参数](实际参数)<上文> : 返回类型<下文> { 体 }
```

冒号是上/下文的分界（Parser.kt parseFun）：**冒号前**的 `<…>` 是上文，**返回类型后**的 `<…>` 是下文；省略返回类型时可把下文直接写在冒号后。`<…>` 内是逗号分隔的命题表达式列表（允许多条与尾随逗号）。

```subl
fun test2()<p>: Null {}                             // 上文（冒号前）
fun get7(): Int <$ = 7> { return 7 }                // 下文（返回类型后）
fun k(): <q> {}                                    // 省返回类型：冒号后直接写下文
fun ordered(a: Nat, b: Nat) <$1 <= $2>: Null {}     // $n 指第 n 个形参（1 起）
fun double(n: Nat): Nat <$1 >= 0> = n * 2           // 下文里同样可用 $n
fun graded(score: Nat)<score <= 100>: Nat = score   // 约束表（v3.0 形态）
fun check(f: (Nat)<$1 >= 0> => Bool, x: Nat): Bool = f(x)  // 函数类型携带上下文
struct Positive(n: Nat) <n > 0>                     // 结构体伴生命题
fun witness[@q]<q>: Null {}                         // 超越函数：理论命题参数 @q
witness<tagged<7>>()                                // 调用点显式供给（紧贴的 <>）
```

语法要点：

- **尖括内启 angle 上下文**（parseAngleList）：`>` 一律是列表终止符，除非「前有空格且后有操作数」才作比较中缀——所以 `<n > 0>` 里第一个 `>` 是中缀、末尾的 `>` 收尾；带空格的 `<` 仍是中缀，故 `<a < b>` 是合法上文；紧贴名字的 `<p>` 是命题施加/显式供给。
- **内联标识**：`$` 指代返回值（只在上文/下文位有效）；`$n` 粘连为单 token，指代第 n 个形参（1 起，**只允许出现在前件/后件位**）；`this` 指代函数本体（声明期内联为函数名）；方法签名里的 `self` 指代接收者。
- **约束表**（v3.0）：`fun f()<score <= 100>` 按「角括内首项为 IDENT 且后随带空格的比较运算符」与命题上文分派；约束项只在调用点按实参核对（详见语义节）。
- **下文不是返回类型的一部分**：`<$ = 7>` 是命题；类型仍是 `Int`。函数类型的 `render()` 把上下文拼成 `(Nat)<$1 >= 0> => Bool`（Ast.kt FunType）。
- **多条上下文**：`<p, q>` 逗号分隔——上文须**全部**在调用点证出，下文须**全部**在体内兑现、并全部弥散进调用方作用域。

## 语义

### Frame：弥散的载体

每个函数检查期持一所局部帧 `Frame(null)`（Checker.kt checkFun）；帧间以 parent 链嵌套（块、lambda、分支各开新帧）。帧承载三类东西：变量类型环境 `vars`、命题事实池 `facts`（LinkedHashSet：保序、O(1) 去重）、局部定理表 `localTheorems`。`inject` 跳过 `PTop`，`allFacts()` 沿父链收集全部事实——上文注入的上文、弥散进来的下文、axiom、自然命题都在同一个 Γ 里，由 MP 闭包、∀ 实例化、算术通道与定理搜索统一消费（见 [命题](03-证明-命题.md)）。

弥散的方向性（Diffusion.kt 文档）：**块事实回溢父帧**——语句块/函数体产出的事实（下文弥散、axiom、赋值等式）在块结束后注入父帧，这是「下文弥散进作用域」的结构基础；**lambda 帧隔离**——lambda 体内可以读到外层事实（查询沿父链），但体内新产出的事实不回溢，防止回调的临时事实污染调用方。

### 声明期：上文进帧，下文成义务

检查函数声明时（Checker.kt checkFun）：

1. **形参事实**：每个形参注入 `x : T`；`Nat` 形参额外注入自然命题 `x >= 0`；结构体类型的形参把该结构体的伴生命题按 `形参名.字段` 形态注入体内（如 `fun f(p: Positive)` 体内自动有 `p.n > 0`）。
2. **上文改写**：上文里的 `$n` 换成形参名（越界报 E-PARAM-REF，并发提示级 H-PARAM-REF 建议直接写参数名）、`this` 换成函数名；重写后的上文命题**注入函数体所在帧**——体内直接把它们当前提用。
3. **下文义务**：以 `dollarOf` 取「`$` 的所指」——块体里有且仅有一处带值的显式 `return e` 则 `$ := e`，否则取尾表达式，都没有则 `null`；**多路 return（if/else 各 return）保守取 null**，不猜、不归一，猜了会产生「看似通过实则错误」的证明。随后逐条证明下文（`$` 代入后），证不出报 **E-POST-UNPROVEN**。
4. **@axiom 函数**：下文签名即公理——编译器信任、不做证明义务，只发补充级 D-AXIOM-POST；**上文仍在调用点强制**（函数体仍正常做类型检查与代码生成）。

### 调用期：证明上文，兑现下文

每次函数调用（CallCheck.kt checkFnCall）按序做四件事：

1. **命题参数供给**（超越函数的 `@q`）：显式供给 `witness<torch>()` 优先；供给的命题在作用域不成立只降级为**警告 E-PROP-UNBOUND**（不误杀）。否则自动供给：从 `allFacts` 收集 0 元原子候选，**排除结构性原子**（`structuralHeads`：`= == != < > <= >=` 及 `$ : __call__ __inst__ __t__`——等式/归属事实不算弥散命题候选，Prop.kt）；0 个候选 → E-PROP-UNBOUND 警告，多于 1 个 → **E-PROP-AMBIGUOUS** 错误，须显式供给。
2. **上文证明**：形参名→实参表达式代入（方法调用路径把 `self` 内联为接收者），`$n`→形参名、`this`→函数名，命题参数→绑定；对 Γ 证明，证不出报 **E-PRE-UNPROVEN**。
3. **伴生记录**：把调用本身注入帧——`witness<torch>()` 产生原子命题 `witness<torch>`（`PAtom(函数名, 实参列表)`）。根文档规定「从伴生命题可以推出函数的下文」（`f<> → p`）；实现未走显式注册蕴含式的路径，而是在调用点直接注入下文（见下），效果上兑现该规定。
4. **下文弥散**：下文里的 `$` 替换为**调用表达式本身**后注入调用者帧——`get7()` 兑现 `<$ = 7>` 后，Γ 里多出 `get7() = 7`。之后同一作用域里的后续证明（`∴`、别的函数的上文、when 命题条件）都能直接消费它。

约束表在调用点按实参核对：编译器能**反证**条件不成立（`¬goal` 可证）→ **E-CONSTRAINT-VIOLATED** 错误；静态证不出（值运行时才确定）→ **W-CONSTRAINT-UNPROVEN** 警告，不误杀未知实参。

### 函数值调用与函数类型上下文

函数类型的 `context` 位让「供证明的命题」随值一起流动：调用函数值 `f(x)` 时， FunType 上下文里的 `$n` 内联为第 n 个**实参表达式**后要求可证，证不出报 **E-CTX-UNPROVEN**（CallCheck.kt）。反过来，lambda 字面量被期望为带上下文的函数类型时，上下文命题注入 lambda 帧作前提（`$n` 按 lambda 形参重写）——`(Nat)<$1 >= 0> => Bool` 的 lambda 体内一开始就有「第一个参数 >= 0」可用。

### 全局事实与自然命题

除上下文外，Γ 还吞入全局事实：每个非 `@impure` 函数注册 `pure<f>`、`@async` 函数注册 `async<f>`（Symbols.kt registerPureFacts，跨模块按裸名补全）。这些与上文/下文弥散产的命题同池同通道。上文里写 `pure<this>` 这类形态即可被消费（`this` 内联为函数名后命中 `pure<f>`）。

### 编译期边界

上下文系统是**纯编译期机制**：解释器求值与 JS 代码生成都忽略 preps/posts（两处源码均无引用），下文不会变成运行时断言。代价是零；反面是——编译器证不出就报错，没有运行时兜底。注意 `unchecked` 语句**不豁免**证明义务：`unchecked use()` 照样报 E-PRE-UNPROVEN（unchecked 闸门只管可变性与纯度）。

### 诊断码速查

| 检查位 | 义务 | 诊断 |
|---|---|---|
| 声明期·下文 | 体内须证出每条下文（`$` 代入后） | E-POST-UNPROVEN |
| 声明期·下文 | `@axiom` 函数：签名即公理、不做义务 | D-AXIOM-POST（补充级） |
| 声明期·`$n` | 上下文里的 `$n` 越界 | E-PARAM-REF + H-PARAM-REF（建议写参数名） |
| 声明期·函数体 | 函数体内出现 `$n` | E-PARAM-REF-IN-BODY |
| 调用期·上文 | 对 Γ 证明每条上文（实参代入后） | E-PRE-UNPROVEN |
| 调用期·命题参数 | 显式供给的命题不成立 / 无候选 | E-PROP-UNBOUND（警告） |
| 调用期·命题参数 | 0 元原子候选多于 1 个 | E-PROP-AMBIGUOUS（错误） |
| 调用期·约束表 | 反证条件不成立 / 静态证不出 | E-CONSTRAINT-VIOLATED / W-CONSTRAINT-UNPROVEN |
| 调用期·结构体 | 构造位须证出伴生命题 | E-STRUCT-PROP-UNPROVEN |
| 声明位·结构体 | 伴生命题禁引 @mut 字段 | E-STRUCT-MUT-PROP |
| 函数值调用 | FunType 上下文（`$n`→实参）须可证 | E-CTX-UNPROVEN |

## 示例

镜像 `examples/上下文弥散.subl`（被 CheckerTest「整个示例语义通过」断言，预期 stdout `7`）：

```subl
fun test1(): Null <p> {
    axiom p                    // 体内 axiom 兑现下文
}

fun test2()<p>: Null {}        // 上文：调用方须供给

fun get7(): Int <$ = 7> {      // $ 指代返回值：唯一 return 7 ⇒ 后件成立
    return 7
}

fun needTagged()<tagged<7>>: Null {}

fun witness[@q]<q>: Null {}    // 超越函数：@q 是理论命题参数

fun main() {
    axiom forall n. tagged<n>
    test1()                    // 下文弥散：p 进入作用域
    test2()                    // 上文 p 由弥散自动供给
    unchecked print(get7())    // 7
    needTagged()               // tagged<7> 由 forall 实例化供给
    witness<tagged<7>>()       // 显式供给
}
```

弥散产出的命题与 axiom 同池，可直接被证明链消费：

```subl
fun emitP(): Null <p> {
    axiom p
}

fun main() {
    emitP()                    // 下文弥散：p 进入作用域
    axiom p ∧ (p → q)
    ∵ p ∴ q                     // p 来自弥散，MP 闭包产出 q
}
```

上文 `$n`、结构体伴生命题与构造位证明：

```subl
struct Positive(n: Nat) <n > 0>

fun half(p: Positive): Nat = p.n
// 结构体形参伴生命题自动注入：体内等价于有 p.n > 0

fun ordered(a: Nat, b: Nat) <$1 <= $2>: Null {}
// 上文用 $1/$2 写（编译器提示可直接写参数名 a/b）

@impure
fun main() {
    var p = Positive(4)         // 构造位证明 4 > 0，成功后命题弥散
    unchecked print(toStr(half(p)))
    ordered(1, 2)               // 常量通道自动证 1 <= 2
}
```

函数类型携带上下文（lambda 期望位注入前提，函数值调用位证明）：

```subl
fun check(f: (Nat)<$1 >= 0> => Bool, x: Nat): Bool = f(x)
// f 的类型自带前提：调用 f 前须证「实参 >= 0」

@impure
fun main() {
    unchecked print(toStr(check({ y => y >= 0 }, 3)))   // OK：x 是 Nat ⇒ x >= 0
}
```

## 陷阱

- **箭头不可混用**：上下文里的蕴含写 `→`（如 `<p → q>`），`->` 是非法 token（只供诊断）；函数类型仍用 `=>`：`(Nat)<$1 >= 0> => Bool`。
- **兑现下文用 axiom 语句**：旧的 `unchecked.axiom[p]` 形态已废除（解析器报错并引导改写），在体内写独立 `axiom p` 即可把下文 `p` 兑现；同理 `unchecked <语句>` 是绕可变性/纯度闸的，不豁免证明义务（见下）。
- **`$n` 只活在前件/后件位**：函数体内写 `$1` 报 **E-PARAM-REF-IN-BODY**（请直接写参数名）；上文/下文里 `$n` 越界报 **E-PARAM-REF**。
- **E-PROP-UNBOUND 是警告、不是错误**：显式供给的命题在作用域里不成立只降级警告——但紧接着的上文证明会以 E-PRE-UNPROVEN 把问题兜住，看到两个诊断时先治供给。
- **自动供给怕「多」**：超越函数 `[@q]<q>` 的自动供给要求恰好一个 0 元原子候选；作用域里同时有 `axiom a`、`axiom b` 就 **E-PROP-AMBIGUOUS**，必须 `f<a>()` 显式供给。等式/归属类结构性事实不会进候选集（structuralHeads 排除）。
- **下文里的 `$` 取决于唯一 return**：多路 return（if/else 各 return 一个值）时 `dollarOf` 保守取 null，后件核对显式失败——不是「证不出」，是「无法确定 `$` 指谁」。改成单一 return 或表达式体即可。
- **尖括号里 `>` / `<` 的邻接规则**：`<n > 0>` 的第一个 `>` 必须前带空格才作中缀（否则它就是列表终止符）；`<a < b>` 是合法上文（带空格的 `<` 是中缀），但 `<a<b>` 会被吃成实例化/供给形态。约束表与上文的分派也靠着带空格的比较运算符这一邻接标记。
- **结构体伴生命题禁引 @mut 字段**：可变字段的值会变，无法保证恒成立 → **E-STRUCT-MUT-PROP**（声明位检查 + 构造位防御）。
- **构造位即证明位**：`Positive(0)` 报 **E-STRUCT-PROP-UNPROVEN**；构造这关过不了，伴生命题就不会弥散，后续以上文/形参形式消费它的代码也跟着失败。
- **上下文不做运行时检查**：preps/posts 只在编译期存在，别指望下文在运行时挡住非法值——运行期合法性的兜底属于 Result/Optional 与 when 穷尽检查。
- **`unchecked` 不豁免证明义务**：`unchecked use()` 仍报 E-PRE-UNPROVEN；unchecked 闸门（E-IMMUT-ASSIGN、纯度、impure 调用）只管可变性与纯度，不管命题。
- **弥散进来的命题按调用表达式记账**：`get7()` 兑现后 Γ 里是 `get7() = 7`，而不是某个变量的等式；要让结果以变量身份参与后续证明，先 `var x = get7()`（var 绑定另有自然命题通道）。

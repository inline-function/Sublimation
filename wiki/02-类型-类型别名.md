# 类型别名（type）

> wiki/02-类型-类型别名 · 主题域：类型别名 / 泛型头 / 编译期展开 / 模块无关
> 事实来源：_langfacts.md §2/§3；Parser.kt（parseTypeAlias :226、parseTheory :339、parseType :506、parseEntry :194、parseDecl :214）；Ast.kt（TypeAliasDecl :77、NamedType.substT :147）；Symbols.kt（登记 :200、二遍查重 :293、tpNamesOf :310、tpArityOf :321）；Types.kt（aliases :371、expand :383-408、baseOf :411）；Checker.kt（:549/:1287 展开注入、:559 Nat 命题）；JsCodeGen.kt（:605 零输出）；AnnotationScanner.kt（:16/:177）；LspAnalysis.kt（:622）；并用 build/libs/sublimation.jar 对 _facts_tmp 下若干探针文件做了 check / compile / run-script 实测。

类型别名是纯类型层的**改名**设施：给一个（可能带类型参数的）类型起个新名字，编译期按位置代入展开，不生成任何运行时代码。它不是新类型——别名与目标在类型检查中完全互通，这既是它的便利所在，也是它大部分陷阱的来源。

## 语法

### 声明

```subl
type Celsius = Rat                        // 简单别名
type NatOpt = Optional[Nat]               // 容器别名（应用类型右值）
type Box[a] = Optional[a]                 // 泛型头别名（头参按位置代入）
type Dict[k, v] = Map[k, v]               // 多参数泛型头（右值数量任意）
type Pred = (Nat) => Bool                 // 函数类型右值
type Thunk = () => Nat                    // 零参函数类型右值
type PairT = (Nat, Str)                   // 元组类型右值
type MutNat = @mut Nat                    // @mut 视图右值
type AtomicN = @atomic Nat                // @atomic 右值
type Work = @impure (Nat) => Null         // @impure 函数类型右值
type Mixed = Nat | Str                    // 联合右值
type Fwd = Later                          // 前向引用（Later 可在后面才声明）
type Later = Nat
```

文法（Parser.kt :226-234）：

| 部分 | 形态 | 说明 |
|---|---|---|
| 头 | `type Name` | 关键字 type + 标识符名 |
| 泛型头 | `[a, b, …]` | 可选，走 parseTheory（:339），与 struct/enum/[T](T)=>T 的 theory 同族 |
| 约束头 | `[T: Show]`、`[F[_]: Foldable]` | 可带类型类约束与高阶占位（parseTheory 支持） |
| 右值 | 完整的 parseType 文法（:506） | 具名/应用类型、函数类型、元组、联合、@mut/@atomic/@impure 前缀全部可解析 |
| 分隔 | `=` 后必须跟一个类型 | 右值结束即声明结束（换行不是 token，语句边界涌现） |

要点：

- **只能写顶层**：parseEntry（:194）/parseDecl（:214）把 `type` 路由到 parseTypeAlias；函数体内写 `type Local = Nat` 直接解析报错（实测：「期望表达式，实际'type'」）。脚本模式同样只接受顶层声明形态
- **类型参数用方括号** `[]`（声明位与代入位同形）；尖括号 `<…>` 是上下文/显式供给位，不能当类型实参用
- **别名不能加注解**：TypeAliasDecl 无 annotations 字段，注解扫描器把它列为「天然扫不到」的节点（AnnotationScanner.kt :16）；注解分支（parseEntry :199-205）也不接收 type 声明
- 节点形态：`TypeAliasDecl(name, theory, target, pos)`（Ast.kt :77-82）

### 使用

```subl
type Box[a] = Optional[a]

fun first(b: Box[Nat], d: Nat): Nat = when(b) {     // 参数位：展开为 Optional[Nat]
    is Some(v) => v
    None => d
}

fun main() {
    var o: Box[Nat] = Some(6)          // 标注位：Some(6) 直接赋给别名标注
}
```

别名可出现在任何类型位：函数形参/返回类型、var 标注、结构体字段、枚举构造子字段、函数类型的参数与返回、`is T` 类型测试。表达式位不认别名（见陷阱 1）。

## 语义

**别名 = 编译期文本替换，运行时不存在这个名字。** 整条流水线是：登记 → 展开 → 消费。

### 登记（两遍）

- 第一遍 collectDecl：`syms.aliases[name] = decl`（Symbols.kt :200-204）；同名别名第二次出现报 `E-DUP-DECL 类型别名 … 重复声明`；同时登记 typeParamNames 与 kind arity（:203/:321）
- 第二遍 checkDeclTypes（Symbols.kt :293-300）：此时 struct/enum/class 均已就位，别名与 **BASE_TYPES（Nat/Int/Rat/Str/Bool/Null…）/ struct / enum / class 重名**一律报 `E-DUP-DECL 类型别名 … 与既有类型重名`；并以别名自己的头参集合检查右值可解析性。因为查重在第二遍，**别名右值可以前向引用**（实测：`type Fwd = Later` 在 `type Later = Nat` 之前合法）

### 展开（代入规则）

$$rac{Sigma(	ext{name}) = 	ext{TypeAliasDecl}(	ext{name}, [], 	ext{target})}{	ext{expand}(	ext{NamedType}(	ext{name}, [])) = 	ext{expand}(	ext{target})} quad (	ext{ALIAS-SIMPLE})$$

$$rac{Sigma(	ext{name}) = 	ext{TypeAliasDecl}(	ext{name}, [a_{1}dots a_{k}], 	ext{target})}{	ext{expand}(	ext{NamedType}(	ext{name}, [	au_{1}dots 	au_{k}])) = 	ext{expand}(	ext{target}[a_{1} := 	au_{1}, dots, a_{k} := 	au_{k}])} quad (	ext{ALIAS-GENERIC})$$

实现要点（Types.kt expandNamed :395-408）：

- 泛型头按**位置**逐位代入：`tps.zip(cur.args)` 配对后交给 `target.substT`——实参多/少都不报错（见陷阱 2）
- 代换只换**裸类型变量**：`NamedType.substT` 仅当 `name in sub && args.isEmpty()` 时整体替换（Ast.kt :147-149）；形参以应用形态出现在右值里不会替换（见陷阱 2）
- 链式别名（`type Outer[a] = Optional[a]`、`type Inner[a] = Outer[a]`）在 while 循环里逐层展开（实测 `Inner[Nat]` 合法）
- 复合包装（`@mut/`@atomic/联合/函数/元组别名）继续穿透内层递归展开（Types.kt :385-393）
- **深度与步数双上限 16**：递归别名经复合类型包装时 steps 计数会失效（M2 注释），靠贯通全展开的 depth 计数兜底，超限即停止——所以循环别名不栈溢出，但也**不被诊断**（见陷阱 3）

### 透明性：别名与目标完全互通

- 名义解析 `baseOf` 把别名名与 struct/enum/class 同等对待（Types.kt :411-417），因此 `Optional[Nat]`、`NatOpt`、`Box[Nat]` 都能解析为合法名义类型
- 检查器在约 40 处调用 `syms.expand`（Checker/CallCheck/Diffusion），别名展开后才做比较、分派与命题注入：
  - 函数实参/返回比较（CallCheck 多处）、结构体字段默认值（Symbols.kt :226）
  - 纯度闸：`type MutNat = @mut Nat` 用于函数参数会展开成 `@mut Nat` 并触发 `E-IMPURE-REQUIRED`（实测）
  - 命题注入：`var v: MutNat = 7` 后 `syms.expand(t).name == "Nat"` 命中，注入 `v ≥ 0`（Checker.kt :559）
  - 方法糖/构造接收者类型走展开（CallCheck :423/:440）
- 方向是双向的：把 `Vec2` 值传给 `V2` 形参、把 `V2` 值传给 `Vec2` 形参、`var v: V2 = Vec2(1, 2)`、`v is V2`、when 解构 `is V2` 构造子——实测全部通过
- 别名不是新类型：没有包装/装箱成本，也不能用它区分两个相同底层类型（`type Celsius = Rat` 之后 Celsius 与 Rat 是**同一个**类型，不存在强制转换或类型陷阱保护）

### 纯类型层

- JsCodeGen：`is TypeAliasDecl -> {}`——**零输出**，别名在 checker 就已展开完毕（JsCodeGen.kt :605）
- 运行时（解释器与 JS）看到的只有目标类型：编译 `type V2 = Vec2` 的程序，产物里只有 `Vec2` 的构造函数；`when (o) { is Some(v) => … }` 按 Optional 展开后的 tag 分派
- 语言服务把别名列为 `type` 符号（LspAnalysis.kt :622）；注解处理器按 TYPE_ALIAS 节点种类扫描，但别名节点永远没有注解可挂（AnnotationScanner.kt :16/:177）

## 示例

**综合**（已用 `run-script` 实测，输出 74.0 / 6 / true / 25）：

```subl
type Celsius = Rat
type Box[a] = Optional[a]
type Pred = (Nat) => Bool

struct Vec2(x: Nat, y: Nat)
type V2 = Vec2

fun doubleC(c: Celsius): Celsius = c * 2
fun isZero(p: Pred): Bool = p(0)
fun first(b: Box[Nat], d: Nat): Nat = when(b) {
    is Some(v) => v
    None => d
}
fun len2(v: V2): Nat = (v.x * v.x) + (v.y * v.y)

@impure
fun main() {
    var c: Celsius = 37.0
    unchecked print(doubleC(c))          // 74.0 —— 简单别名与 Rat 完全互通
    var o: Box[Nat] = Some(6)
    unchecked print(first(o, 0))         // 6 —— 泛型头按位置代入
    var f: Pred = { x => x == 0 }        // 标注位反推 lambda 参数类型
    unchecked print(isZero(f))           // true —— 函数类型别名
    unchecked print(len2(Vec2(3, 4)))    // 25 —— struct 别名字段访问与方法分派
}
```

**前向引用与链式别名**（实测 check 通过）：

```subl
type Fwd = Later
type Later = Nat

type Outer[a] = Optional[a]
type Inner[a] = Outer[a]

fun use(i: Inner[Nat], f: Fwd): Nat = 1
```

**别名对效应层的透明性**（`@mut` 右值与普通 `@mut` 参数同等待遇）：

```subl
type MutNat = @mut Nat

@impure                          // 少这行会报 E-IMPURE-REQUIRED（别名展开后即 @mut Nat）
fun bump(m: MutNat): Nat = 1
```

## 陷阱

1. **别名不能当构造子调用**：`var w = V2(3, 4)` 报 `E-UNBOUND-NAME 没找到函数 V2`（实测）。构造调用按 struct/函数名查符号表，别名只注册进 `syms.aliases`；struct 别名要写 `Vec2(3, 4)`，enum 别名要用真实构造子名（`type EA = E` 时写 `A()` 而不是 `EA()`）
2. **使用点不检查实参数**：`Box[Nat, Str]`（多填）的额外实参被 zip 静默丢弃、`Box`（少填/裸用）也通过检查——后者展开成带悬空类型变量 `a` 的 `Optional[a]`，错误推迟到使用处才暴露（实测 `var o: Box = Some(1)` 检查期无类型错误）。高阶头更糟：`type WrapF[F[_]] = F[Nat]` 的右值里 F 是应用形态，substT 只替换裸名，`WrapF[Optional]` 展开后仍是 `F[Nat]`，调用点报「实参 0 Optional[Nat] 与形参 F[Nat] 不符」。**别名头参数只在右值里裸用才可靠**
3. **循环别名无诊断**：`type A = B` + `type B = A`、`type A = @mut A`、`type SelfB = SelfB` 声明期全部不报错（实测）；展开靠 16 步/16 深截断，使用时给出的是无关的 `E-TYPE-MISMATCH`（`var v: CycleA = 1` 报「标注了 CycleA，但初值是 Nat」）。循环引用要自己避免
4. **E-DUP-DECL 报错后别名仍已注册**：putIfAbsent 在报错前完成，被判重名的别名（如 `type Vec2 = Nat` 撞上 struct Vec2）仍留在 `syms.aliases` 里，导致后续诊断混乱（实测：`var v: V2 = Vec2(1, 2)` 报「标注了 V2，但初值是 Vec2」，因为 V2 → Vec2 → Nat 被链式展开成 Nat）。编译本来就是失败的，但次要错误的措辞会误导
5. **函数体内不能声明别名**：`fun main() { type Local = Nat }` 解析报错「期望表达式，实际'type'」；别名只能写顶层
6. **别名不能加注解**：`@mut type X = Nat` 之类写法在解析层就被拒（注解分支不接收 type 声明），TypeAliasDecl 也没有 annotations 字段；想要带语义标注的类型只能用 struct/enum
7. **右值限制的旧文档已过时**：《形式化文法.md》与 Ast.kt 注释称「右值仅具名/应用类型，函数类型/元组右值待扩展」——实测 `(Nat) => Bool`、`() => Nat`、`(Nat, Str)`、`@mut`、联合右值均可解析可检查（checker 的 expand 完整覆盖 FunType/TupleType/UnionType）。记忆口径以实测为准
8. **联合别名不能直接装单一变体**：`var n: Nat | Str = 1` 本身就报 `E-TYPE-MISMATCH`（联合标注不接受单变体初值），`type Num = Nat | Str` 后写 `var n: Num = 1` 同样报错——这不是别名的特例，是联合的通用行为，换个别名绕不开
9. **别名不出现在运行时**：编译产物与调试输出里按目标类型名找值；写 `print(Vec2(…))` 输出的是 struct 的 tag，而不是别名名
10. **头部类型类约束不参与校验**：`type Showable[T: Show] = Optional[T]` 中即使从未声明 Show 类型类，声明期也不报错（实测）——约束目前只是记录，不触发字典解析或 `E-NO-INSTANCE`，不能指望它像函数 `[T: Show]` 那样把关
11. **别名与目标不是「子类型」而是「同一类型」**：期望靠 `type UserId = Nat` 与 `type OrderId = Nat` 区分两种 id 是做不到的——两者互相赋值完全合法。要区分只能上 struct/枚举（新名义类型）
12. **跨模块别名可见性：待核**——单文件检查中别名的可见性由本文件 `Symbols` 保证；跨工程模块时裸名/限定名引用别名的解析规则（typeVisible/allSymbols 的交互）未实测，引用前请自行验证

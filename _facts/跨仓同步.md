# 跨仓真源与同步纪律

> 本文记录 .subs 注解处理器与 core 标准库的**真源决定、各消费者同步机制与运行约定**。
> 事实来源：2026-10-25 用户决定 + t9/t10/t11/t26 交付报告 + 各仓源码（引用见各节）。

## 一、真源决定（用户批准，2026-10-25）

- **注解处理器真源** = 主仓 `F:\KotlinProject\Sublimation\annotation processer\`（目录名带空格为刻意）。
  统一前存在四处分叉副本（主仓 / CandyIDE / SfA 两处），内容各自漂移；统一以主仓为准（t9）。
- **core 标准库真源** = 主仓 `core\`（15 个子包）。
- **纪律**：消费者侧**禁止手工编辑** `.subs` 与 `core` 内容；任何改动先落主仓，再走同步。

## 二、各消费者的同步机制（均已落地并可复现）

| 消费者 | 机制 | 位置 |
| --- | --- | --- |
| CandyIDE | 构建期镜像：`copyStdlib` + `copyProcs`（Copy 任务，均挂 `:app` 的 `preBuild`）——preBuild 时自动从主仓拉取 core 与处理器 | `CandyIDE/app/build.gradle.kts`（t10） |
| SfA | `scripts/sync-deps.ps1`：三级探测主仓（`-MainRepo` > `$env:SUBLIMATION_REPO` > 常见路径）；core → 仓根 `core/`（gitignore 不入库）+ `app/core/`（入库）；处理器 → 仓根 + `sdk-lite\`；幂等、先清后拷 | SfA 仓 `scripts/`（t26） |
| SfG / SfW | 同约定的 `sync-deps.ps1`（与 SfA 同构） | 各仓 `scripts/`（t25） |

机制差异说明：CandyIDE 是 Gradle 工程可挂构建钩子（自动）；SfA/SfG/SfW 仓根非 Gradle，靠手动跑脚本（无自动钩子可挂）。

## 三、行文规范

- `.subs` / `.subl` **统一 LF、无 BOM**（主仓 `allMut.subs` 已于 2026-10-25 归一化 CRLF→LF）。
- 新增/修改处理器：先写主仓 → 消费者侧跑同步（CandyIDE 下次构建自动；SfA/SfG/SfW 跑 `sync-deps.ps1`）。
- `sdk-lite\` 副本为**有意冻结的本地快照**（gitignore），同步脚本会将其一并刷新。

## 四、运行约定

- SfA/SfG/SfW：**从各仓根运行 compile**——编译器按 CWD 相对路径装载 `annotation processer` 与 `core`（详见 SfA `android doc/运行环境.md`）。
- **勿从主仓根运行**用户工程：会装载主仓自己的处理器副本，绕过本仓同步内容。
- CLI `-A` 选项须用**绝对路径**：postcompile 的 ProcessBuilder 以 appDir 为 CWD，相对 sdkDir 会失效（E-PROCESSOR-SCRIPT）。

## 五、已知限制（待用户决策）

- CandyIDE 的 Copy 语义为增量同步、**不删除目标目录多余文件**：真源删除某处理器时需手工清理 `assets/android/procs`（机制与 copyStdlib 一致）。
- SfA/SfG/SfW 非自动：何时跑同步靠纪律。
- `@impure` 回调标注漂移：CandyIDE 平台/视图回调普遍标 `@impure`（pickFile、activity 生命周期、Button/Checkbox/Slider/Switch/TextField 回调），SfA 仍是纯函数类型——待统一（t11 报告提出）。
- 各仓均有未提交改动（夜间任务产出），**提交由用户统一处理**，按任务归属分批（见队长晨报清单）。

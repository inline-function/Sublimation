# 诊断信息设计文档

> 目标：让新手（甚至"傻逼"）看到编译报错后，能自己改对，不用翻文档。
> 作者：把发生在词法、语法、类型、证明、纯度、模式、异步等每个环节的典型犯错，逐一设计报错文案。

## 0. 设计原则（每条诊断必须做到）

1. **说人话**：不引用"决策 59""root doc 第 39 行""CH-4"这类内部编号——用户看不到也看不懂。
2. **三件套**：① 哪里错（位置自动附源码片段）② 为什么错 ③ 怎么改（给具体改法或反例）。
3. **给例子**：能给出正确写法的，直接塞到消息里。
4. **分级准确**：错误/警告/提示/补充，语义一致（例如 E-NON-EXHAUSTIVE 现在消息里却写"警告"，要改）。

## 0.5 四级含义

| 等级 | 标记 | 含义 | 例子 |
|------|------|------|------|
| 错误 | [错误] | 编译阻断，必须修 | 类型不匹配、前件未证出 |
| 警告 | [警告] | 能编译但有风险 | when 未穷尽、不可达代码 |
| 提示 | [提示] | 建议改进，可忽略 | 参数遮蔽同名字段 |
| 补充 | [补充] | 编译器替你做了某事（-v 才显示） | var 推导类型、方法糖展开 |

# 线性作用域规范（含资源扩展）

> **定位**：本文是**实现依据**。第一波（可变版本化）的权威细节以 `boring doc/线性作用域-形式化版.md` 为准，
> 本文第二条要点（资源/锁）是第二波的设计基准。规则一旦实现，回写 `boring doc` 卷册。
>
> **引用的既有机制**：伴生命题与上下文弥散（第五卷）、效应与深拷贝（第六卷）、结构体与类型类（第三卷）。

---

## 1. 术语

| 术语 | 定义 |
|---|---|
| 线性作用域 `%{ … }` | 带 `%` 前缀的块（`%` 与 `{` 紧贴无空白，第一卷邻接规则） |
| 线性域族 `family(B)` | `B` 自身 + `B` 内所有嵌套线性作用域（递归）；版本计数器与版本表 Ω 在域族内共享 |
| 线性实体 `Lin` | 域族内声明或赋值、标注 `@mut`（变量）或持 `@mut` 视图（字段路径）、非 `@ref`、未被 lambda 赋值性捕获 |
| 资源实体 `Res` | `@resource struct` 的实例，在域内声明并持有 |
| 版本名 `x#k` | 编译期内部名，`#` 不是合法标识符字符，用户不可书写；诊断消息还原为 `x` |

---

## 2. 语法

```
PostfixOp → '%' '{' Block '}'          ⟶ LinearBlock（表达式位）
Stmt      → '%' BlockExpr               ⟶ ExprStmt(LinearBlock)（语句位）

@resource 'struct' Name '(' 字段 ')' ['<' 伴生命题 '>']   ⟶ 资源类型声明
```

`@resource` 作用于 struct 声明，声明该类型的实例为资源实体。资源类型的伴生命题称为**相位**（如 `<open>`/`<held>`）。

---

## 3. 可变版本化（第一波，要点指针）

权威细节见 `boring doc/线性作用域-形式化版.md`，此处仅列实现要求的规则清单：

| 规则 | 含义 |
|---|---|
| LV-RESOLVE-LIN / LV-RESOLVE-PLAIN | 名字解析：线性实体解析到当前版本 `x#k`；非线性名字原样 |
| LV-RESOLVE-FIELD | 版本索引附着在字段路径的根变量上 |
| LV-DECL / LV-ASSIGN | 声明与赋值产生新版本并注入 Γ（`x#k = e`） |
| LV-MERGE / LV-MERGE-N | 分支合并点产生合并版本，注入各支析取 |
| LV-INVALIDATE | 不纯调用（`@mut` 视图传参）后，该实体的版本化等式与伴生命题失效；类型归属与类型不变量不失效 |
| LV-ENTER / LV-EXIT | 域进入创建 LinearFrame，域出口销毁 F′ |
| LV-SPILL | 域出口只回溢**不含版本名**的普通事实 |
| LV-OUTER-MUT | 域外声明的 `@mut` 实体可在域内修改；域出口不获得任何新事实 |
| LV-LAMBDA-READ | lambda 只读捕获线性实体 → 捕获**快照版本**，且该实体失去线性实体身份 |
| LV-NO-RETURN | 禁止带值提前返回（域尾裸 `return` / `return null` 允许） |

**零运行时成本**：`x#k` 在代码生成时映射回同一个目标平台变量；不含 `%` 的源文本解析、检查、生成路径完全不变。

## 4. 资源扩展（第二波）

### 4.1 设计思路

资源 = 唯一所有权 + 确定性释放 + 相位约束。三项都在已有机制上：

- 唯一所有权 ← 线性域的 `Lin` 约束（禁逃逸、禁别名）
- 确定性释放 ← `LV-EXIT` 是完备的收尾点（`LV-NO-RETURN` 保证提前返回不跳过收尾）
- 相位约束 ← **伴生命题 + 前件检查**：相位就是伴生命题，相位转换就是带下文的函数

`@resource` 只负责一件事：把 struct 标记为**不可复制、不可逃逸、域绑生命周期**。相位本身不需要新机制。

### 4.2 资源 API 的正字法

```subl
@resource struct File(path : Str) <open>

@impure fun openFile(p : Str) : File <open>              // 构造函数：注入相位
@impure fun close(f : @mut File) : Null <closed>          // 转换函数：消费 <open>，写入 <closed>
@impure fun write(f : @mut File, s : Str) : Null <open>   // 使用函数：要求当前相位为 <open>
```

约定：资源类型的**构造函数**返回带相位的实例；**转换函数**以 `@mut` 视图接收实例，其前件为旧相位、下文为新相位；**使用函数**的前件为允许操作的相位。前件不满足时由既有 `E-PRE-UNPROVEN` 拦下——失效后再次使用、二次 close 都落在这条老规则上。

### 4.3 规则

```
RS-NOESCAPE（资源不可逃逸）
资源类型的值不得出现在：
  ① 域的尾表达式 / return 表达式 / 外层不可变绑定
  ② 结构体字段、元组分量、Any/存在类型的传递
  ③ 任何 lambda 的捕获集
违者报 E-RESOURCE-ESCAPE。

RS-NOCOPY（资源不可复制）
第六卷 §6.6 的深拷贝规则对资源类型不适用：任何会触发深拷贝的绑定/转换（@mut 视图互传、不可变互传）
若传达类型为资源类型，报 E-RESOURCE-COPY。资源只能以 @mut 视图传给资源 API。

RS-USE（相位即前件）
使用函数（前件 <φ>）被调用时，Γ 中必须存在当前版本 x#k 的 <φ>；
否则 E-PRE-UNPROVEN。相位事实的注入、失效、重证均走第五卷既有机制。

RS-EXIT（域出口兜底释放）
LV-EXIT 时，对每个仍在某「未释放相位」的资源实体，编译器合成一次默认释放调用
（该资源类型声明的默认释放函数，见 §4.5）；并发出 D-RESOURCE-CLOSED 补充级诊断。
已显式释放（当前相位为终态相位）的资源不再兜底。

RS-TRANSITION（相位转换）
转换函数执行后，资源实体产生新版本，下文相位注入新版本；旧相位事实保留（关于历史）。

RS-ALIAS
资源实体声明 @ref → 复用 E-LINEAR-ALIAS。
```

### 4.4 运行时

资源扩展**引入必要的运行时调用**：释放调用本身（这与可变版本化的零成本不同——释放是资源语义的一部分，不是追踪开销）。
目标语言需提供：

- 资源对象的分配与类型标记（不分配引用计数；资源为唯一所有权）
- 释放函数的调用点插入位置（域出口；`LV-OUTER-MUT` 修改点不涉及资源释放）
- 释放失败 = 运行时错误，其语义另行规定（本规范不引入异常机制）

### 4.5 默认释放函数

资源类型声明时可附带一个默认释放函数，约定签名：

```subl
@impure fun release(r : @mut R) : Null <closed>
```

名为 `release`，或由 `@resource(release = 自定义名)` 指定。`RS-EXIT` 生成的兜底调用指向它。
未声明默认释放函数的资源类型：兜底什么都不做，但 `RS-NOESCAPE`/`RS-NOCOPY`/`RS-USE` 照常生效。

## 5. 锁：资源的并发实例

锁是第二波的特殊成员，因为它**不需要任何额外机制**：`lock`/`unlock` 就是相位转换函数。

```subl
@resource struct Mutex() <unlocked>

@impure fun lock(m : @mut Mutex) : Null <unlocked>      // 转换：<unlocked> → <held>
@impure fun unlock(m : @mut Mutex) : Null <held>
```

临界区的正确写法由两条**既有**性质自动保证：

1. `@ref` 在域内被禁（`RS-ALIAS`/`E-LINEAR-ALIAS`）——共享数据只能域外声明、域内使用，而它不是线性实体、**从不进入 Γ**，所以不存在需要失效的事实；
2. 临界区内把共享数据冻结成不可变快照（`var snapshot = shared.x`）再证明——与第五卷 §10.3「把可变性割掉」同构。

**明确不纳入**（本波不做）：

- 死锁与锁顺序分析（需要全程序信息）
- 持锁等待/条件变量（涉及调度，属异步层，见 §7）
- 乐观并发（`@atomic`/CAS）的编译期版本号验证（Ω 是编译期单线程的，CAS 的版本号是运行时跨线程的，机制不可复用）

## 6. 与既有机制的边界

| 机制 | 关系 |
|---|---|
| 第六卷 §6.6 深拷贝 | `RS-NOCOPY` 例外：资源类型不参与深拷贝 |
| 第五卷 前件/下文检查 | 资源相位的全部表达力来源（`RS-USE`），不新增命题连接词 |
| `unchecked` | 资源域内仍允许（全语言统一逃逸口）；健全性不变 |
| Any/存在类型 | 资源值经 `Any` 传递 = 逃逸，`RS-NOESCAPE` 拦下 |
| 类型类字典分派 | 资源类型可被实例化，方法调用按 `RS-USE` 检相位；分派目标不可静态确定时不影响相位判定（相位是 callee 声明的，与分派无关） |

**不变量**：

- 不含 `%` 的源文本：行为逐字节不变（`RS-*` 规则只在域内/资源类型上触发）
- 不含 `@resource` 的源文本：含 `%` 的行为与第一波完全一致（资源规则惰性激活）

---

## 7. 与异步的边界（明确排除）

域内**不提供** `yield`/`await`/效应器/`by` 委托。理由沿用形式化版 §12.3：

- 线性作用域是纯静态机制；异步需要运行时（续体、调度器）
- 效应着色问题（IO 值随调用链传染）
- 快照捕获（`LV-LAMBDA-READ`）与事件回调「读当前值」的需求已被《安卓标准库设计.md》记录为冲突

异步走独立设计（见 `root doc/异步.md`）。锁能搭车资源第二波，正是因为它是**同步**原语。

## 8. 诊断码

| 码 | 级别 | 含义 |
|---|---|---|
| E-LINEAR-ESCAPE | 错误 | lambda 赋值性捕获域内 @mut 实体 |
| E-LINEAR-ALIAS | 错误 | 域内声明 @ref（含资源实体，`RS-ALIAS`） |
| E-LINEAR-RETURN | 错误 | 域内带值提前返回 |
| D-LINEAR-VERSION | 补充 | 赋值前进到新版本 |
| **E-RESOURCE-ESCAPE** | 错误 | 资源值逃逸（尾表达式/return/字段/元组/Any/lambda 捕获） |
| **E-RESOURCE-COPY** | 错误 | 资源值参与深拷贝转换 |
| **D-RESOURCE-CLOSED** | 补充 | 域出口兜底释放 |

用后释放、二次关闭不引入新码——它们是 `RS-USE` 的自然推论，落在既有 `E-PRE-UNPROVEN` 上。

## 9. 实现验收

**检查器**：

1. `RS-NOESCAPE`/`RS-NOCOPY` 在预扫描与 `checkStmt` 的拷贝判定点生效；误报方向必须保守（拿不准当逃逸）
2. 相位事实的版本化流转正确：构造注入、转换前进、失效后重证；`E-PRE-UNPROVEN` 时机正确
3. `RS-EXIT` 的合成调用点 = `LV-EXIT` 同一位点；未释放相位的判定基于当前版本的事实查找

**代码生成**：

4. 可变版本化部分：与等价普通 `@mut` 代码逐字节相同（第一波判据不变）
5. 资源部分：生成的释放调用与显式调用的正字法一致；无追踪开销

**测试矩阵**：

| 组 | 断言 |
|---|---|
| 可变 | 版本化、分支析取、失效、不回溢、@mut 视图字段写入、域外声明实体 |
| 资源 | 开/关/用/兜底关/逃逸/复制/二次关（E-PRE-UNPROVEN）/无默认释放函数 |
| 锁 | 临界区进出相位、共享数据域外声明、快照写法 |
| 回归 | 不含 `%`/`@resource` 的既有测试全绿，产物逐字节不变 |

异常路径（运行时释放失败）不在本波验收内。

## 1. 我们的工程是什么

**Sublimation** 是一门「类型即证明」的实验编程语言，编译器把 Sublimation 源码编译成 JavaScript。
核心特性（新会话一定要先懂这些，否则看不懂报错）：

- **纯函数是默认**：函数默认不允许副作用；要副作用必须标 `@impure`。
- **可变性显式**：`@mut`（可变视图，绑定/赋值会深拷贝）、`@ref`（引用别名，不拷贝）。
- **空安全**：`Optional[T]`，`None`/`Some(x)`，`?.f()` 安全调用、`a ?: b` Elvis 兜底。
- **类型类**：`class Show { … }` + `impl Show for User { … }`，类似 Rust trait。
- **自动证明器**：函数可声明前置/后置命题，编译器自动证明；`+…`/`∵…`/`∴…` 是命题注入/求证语句。
- **异步**：`@async` 函数、`Task`、`Channel`；异步调用会自动 await（无需写 await）。
- **方法糖/中缀糖/尾随 lambda**：`o.f(args)` 等价 `f(o, args)`；`a f b` 等价 `f(a, b)`。

## 3. 怎么构建/运行/测试

```
.\gradlew.bat compileKotlin        # 只编译
.\gradlew.bat test                 # 跑全部 511 测试
.\gradlew.bat fatJar               # 打可执行 jar
java -jar build/libs/sublimation.jar <parse|tokens|check|compile|explain> ...
```

诊断相关验证技巧：
- 单文件：`java -jar … check 文件.subl`
- 目录模式（自动挂 stdlib，会触发多模块诊断）：`java -jar … check 目录 -v`（`-v` 显示补充级）
- `java -jar … explain <CODE>` 看某诊断码的解释

## 4. 诊断系统怎么设计（已确立的约定）

四级（`Diag.kt` 的 `Severity` 枚举）：
- **错误 ERROR** — 必须改才能编译
- **警告 WARN** — 能编译，但很可能有 bug
- **提示 HINT** — 风格/习惯建议
- **补充 SUPPLEMENT** — 用了自动推导/语法糖时加说明（如 `var x 推导为 Nat`）。**只在 `-v` 下显示**。

诊断码命名约定：
- 前缀 `E-` 错误、`W-` 警告、`H-` 提示、`D-` 补充
- 码必须和 severity 匹配（**曾有 bug：`E-CANNOT-PROVE` 实际是 warn，已改成 `W-CANNOT-PROVE`**）

渲染格式：`[错误][line:col] CODE: 消息` + 源码片段带 `^` 箭头。
`DiagBag.report()` 负责渲染；`EXPLAIN` 映射（Main.kt）负责 `explain <CODE>`。

## 7. 关键坑/注意点（新会话务必知道）

1. **`explain` 不覆盖代码里所有码**：`explain <CODE>` 只读 EXPLAIN 映射；lexer/parser 异常没有码。补 explain 时要同时更新 Main.kt 的 EXPLAIN。
2. **单文件模式不挂 stdlib**：`check 单文件` 会报 `listOf` 未定义；目录模式才自动挂 `stdlib/` 。
3. **根模块 modulePath 是空串 `""`**（不是 `"/"`）；stdlib 是 `"stdlib"`（不带前导斜杠）。过滤补充就用 `dropSupplementsOutside("")`。
4. **测试改名要同步**：改了诊断码（如 E→W）必须同步改 `DiagCoverageTest.kt` 和 `CheckerTest.kt` 里的断言字符串，否则测试挂。
5. **Kotlin 字符串里 `$` 和 `"` 要小心**：报错消息里想显示 `$name` 或嵌套双引号时，要用 `\$` 转义或改用「」全角引号，否则编译失败。
6. **诊断消息风格约定**：面向新手，每条要含「发生了什么 + 为什么 + 怎么改」，禁止内部术语（决策 N、CH-N、HKT-S5 这种）。
7. **`checkExpr` 里的 `return`**：很多诊断直接在 `when` 分支里 `return`，改消息时注意不要破坏控制流。
8. 标准库 `stdlib/` 里也有大量 .subl 源码会触发自己的诊断——这就是为什么加了 `dropSupplementsOutside` 过滤补充级，但错误/警告/提示仍会显示 stdlib 的（这是预期行为）。

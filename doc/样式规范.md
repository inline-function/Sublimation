# 样式规范

> **本文档状态**：v0.1（2026-10-10）
>
> **本文档定位**：Sublimation 的代码风格与书写规范。约束**怎么写**（不是**写什么**——语法在《语言语法.md》，语义在《形式化规范.md》）。
>
> **本文档的性质**：**建议性 + 部分强制性**。标 ⟨强制⟩ 的由编译器/语言服务检查；标 ⟨建议⟩ 的只作风格引导，编译器不报错。
>
> **维护纪律**：风格变更必须同步本文档。语言服务与代码格式化工具以本文档为权威依据。

---

## 1. 命名约定

### 1.1 类型 ⟨强制⟩

**类型名（struct / enum / class）用 `PascalCase`。**

```sublimation
struct Point(x: Nat, y: Nat)
enum Color { Red(), Green(), Blue() }
class Show { fun show(): Str }
type Pred = (Nat) => Bool
```

**基本类型同样 `PascalCase`**：`Nat` / `Int` / `Rat` / `Str` / `Bool` / `Null` / `Nothing` / `Any` / `EmptyTuple` / `SingleTuple`。

### 1.2 函数与变量 ⟨强制⟩

**函数名与变量名用 `camelCase`。**

```sublimation
fun listLength(xs: List[Nat]): Nat { ... }
fun mapResult(f: (T) => U, r: Result[T, E]): Result[U, E] { ... }

var userName = "alice"
var counter = 0
```

### 1.3 命题 ⟨强制⟩

**命题原子用小写。**

```sublimation
fun f() <valid<7>>: Null { ... }
fun g() <irrational<sqrt(2)>>: Null { ... }
fun h() <pure<f>>: Null { ... }
fun k() <immutable<Point>>: Null { ... }
```

**理由**：命题来自逻辑系统，惯例是全小写（`p` / `q` / `valid` / `irrational`）。让命题和值层标识符在视觉上一眼可分。

**复合命题**通过算符连接——本身不命名：

```sublimation
m ≠ 0 ∧ n > 0
```

### 1.4 模块、目录与文件 ⟨强制⟩

**目录名、文件名、模块名用 `snake_case`。**

```
project/
├── project.settings
├── main.subl
├── string_data.subl
├── number_data.subl
└── core_math/
    ├── core_math.settings
    └── extra.subl
```

**理由**：和目录命名习惯一致；跨平台无大小写问题（macOS/Windows 文件系统大小写不敏感，`StringData.subl` 和 `stringdata.subl` 可能撞车）。

### 1.5 注解 ⟨强制⟩

**注解全小写。**

```sublimation
@mut
@unpure
@new
@async
@tuple
@lazy
```

## 2. 注解书写位置

### 2.1 变量注解 ⟨强制⟩

**变量注解与声明同行。**

```sublimation
@mut var counter = 0
@lazy var cache = computeExpensive()
@mut var buffer: Array[Nat] = ...
```

**理由**：变量注解短（`@mut` / `@lazy`），同行不挤。

### 2.2 函数、类型、类型类注解 ⟨强制⟩

**函数、结构体、枚举、类型类的注解独立成行，在声明之前。**

```sublimation
@unpure
fun logMessage(msg: Str): Null { ... }

@async
fun fetchData(url: Str): Str { ... }
```

```sublimation
@new
struct Point(x: Nat, y: Nat)
```

```sublimation
@new
class Show {
    fun show(): Str
}
```

**多个注解时逐行排列**：

```sublimation
@unpure
@async
fun streamData(): Null { ... }
```

**理由**：函数注解较长（`@unpure` / `@async`），独立行不挤压签名。和 Kotlin 的 `@JvmStatic fun` 风格一致。

---

## 3. 缩进 ⟨强制⟩

**4 空格。**

```sublimation
fun example(n: Nat): Nat {
    if (n > 0) {
        return n * 2
    }
    return 0
}
```

**禁止 Tab**——统一空格。**理由**：和 Kotlin 一致，缩进层次清晰。

---

## 4. 括号风格 ⟨强制⟩

**K&R**——左花括号与语句同行。

```sublimation
// ✅ K&R
if (c) {
    ...
}

fun f(n: Nat): Nat {
    return n
}

when (x) {
    Some(v) -> ...
    None -> ...
}
```

```sublimation
// ❌ Allman
if (c)
{
    ...
}
```

**理由**：Kotlin / Rust / JS 全线 K&R。

---

## 5. 空行 ⟨建议⟩

按国际惯例：

| 位置 | 空行数 |
|---|---|
| 函数之间 | 1 |
| 类型声明之间 | 1 |
| 逻辑块之间 | 0-1（按可读性） |
| 文件末尾 | 1 |
| 文件头部 | 无强制 |

```sublimation
fun f(): Nat {
    return 1
}

fun g(): Nat {
    return 2
}

struct Point(x: Nat, y: Nat)

enum Color { Red(), Green() }
```

## 6. 注释 ⟨建议⟩

**与 Kotlin 一致**：

### 6.1 行注释

```sublimation
// 这是行注释

var n = 5   // 行尾注释
```

### 6.2 文档注释

```sublimation
/**
 * 除法：返回 Optional 结果。
 *
 * @param n 被除数
 * @param m 除数
 * @return m ≠ 0 时返回 Some(n/m)；m = 0 时返回 None
 */
fun div(n: Rat, m: Rat): Rat? <
    m ≠ 0 ↔ $ : Rat,
    m = 0 ↔ $ = None
> {
    if (m = 0) {
        return None
    }
    return Some(n / m)
}
```

**标记**：`@param` / `@return` / `@throws` / `@see` 等。

**理由**：和 Kotlin 的 KDoc 一致，语言服务能识别并生成文档。

## 7. 标识符 ⟨强制⟩

### 7.1 纯符号标识符允许

**运算符可以自定义，符号名可作标识符**（仿 Scala）。

```sublimation
fun >>=(a: M, b: (T) => M): M { ... }
fun <>(x: Nat, y: Nat): Bool { ... }
fun ∘(f: (B) => C, g: (A) => B): (A) => C { ... }
```

**符号名可中缀调用**：

```sublimation
result >>= \x => ...
```

### 7.2 符号不能与字母混合 ⟨强制⟩

**标识符要么全字母数字，要么全符号——不能混合。**

```sublimation
// ✅ 合法
fun listLength(xs: List[Nat]): Nat { ... }
fun >>=(a: M, b: (T) => M): M { ... }

// ❌ 非法
fun >>=fff(...) { ... }    // 符号与字母混合
var a>>b(...) { ... }      // 同上
```

**理由**：混合后词法无法确定边界——`>>=` 后跟字母是"符号后接标识符"还是"一个混合标识符"？

### 7.3 Unicode 标识符允许 ⟨强制⟩

**支持 Unicode 标识符**——数学符号、逻辑符号均可。

```sublimation
fun ∘(f, g) { ... }
fun ≠(a, b): Bool { ... }
fun ∀x(...) { ... }
```

**理由**：和 Kotlin / Scala 一致。数学/逻辑代码中 Unicode 让语义更直观。

### 7.4 命题层倾向 Unicode ⟨建议⟩

**命题层推荐使用 Unicode 算符。**

```sublimation
// ✅ 推荐
fun div(n: Rat, m: Rat): Rat? <
    m ≠ 0 ↔ $ : Rat,
    m = 0 ↔ $ = None
> { ... }
```

**命题层的 Unicode 算符**：

| 含义 | Unicode |
|---|---|
| 蕴含 | `→` |
| 等价 | `↔` |
| 合取 | `∧` |
| 析取 | `∨` |
| 否定 | `¬` |
| 全称 | `∀` |
| 存在 | `∃` |
| 唯一存在 | `∃!` |
| 真 | `⊤` |
| 假 | `⊥` |

### 7.5 关于 u-系写法的正式澄清 ⟨重要⟩

**`u!=` / `u->` / `u&` / `u|` / `u<->` 从来不是 Sublimation 语言的一部分。**

这些写法**只出现在早期设计文档中**——是**文档编辑者打不出 Unicode 时的临时替代表示**。它们**不是语法**，**编译器不认识**。

**推论**：

- 写 `u->` 会**报错**（`u` 被识别为标识符，`->` 被识别为箭头）
- **没有**"打 `u->` 自动替换为 `→`"的语言服务功能
- **文档一律直接写 Unicode**——打不出来就复制粘贴

**待办**（见《待办.md》修-1 修订）：

- `Lexer.kt` 的 `uOps` 表（5 条映射）**必须删除**——它是误实现
- `LexerTest.kt` 里对 u-系的断言**必须删除**
- `语言语法.md §1` 里 u-系算符的条目**必须删除**

## 8. 完整示例

```sublimation
/**
 * 除法：返回 Optional 结果。
 * m ≠ 0 时返回 Some(n/m)；m = 0 时返回 None。
 */
fun div(n: Rat, m: Rat): Rat? <
    m ≠ 0 ↔ $ : Rat,
    m = 0 ↔ $ = None
> {
    if (m = 0) {
        return None
    }
    return Some(n / m)
}

@unpure
fun logDivide(n: Rat, m: Rat): Null {
    var r = div(n, m)
    when (r) {
        Some(v) -> print("结果：$v")
        None -> print("除数为零")
    }
}

@mut var globalCounter = 0

struct Point(x: Nat, y: Nat)

class Show {
    fun show(): Str
}

impl Show for Point {
    fun show(): Str = "Point"
}

fun >>=(a: M, b: (T) => M): M { ... }

fun main() {
    var p = Point(1, 2)
    unchecked print(p.show())
}
```

**这份示例体现了所有规则**：

- 类型 `Rat?` / `Point` / `Show` —— PascalCase
- 函数 `div` / `logDivide` / `show` —— camelCase
- 变量 `r` / `globalCounter` —— camelCase
- 命题 `m ≠ 0` / `$ : Rat` —— Unicode
- 注解 `@unpure` 独立一行
- 注解 `@mut` 与变量同行
- 缩进 4 空格
- K&R 括号
- 文档注释 `/** */`
- 纯符号标识符 `>>=`

## 10. 语言服务职责 ⟨目标⟩

以下检查由语言服务（LSP）实现，编译器本身不报错（风格违规不是编译错误）：

| 检查 | 级别 |
|---|---|
| 类型非 `PascalCase` | 提示 |
| 函数/变量非 `camelCase` | 提示 |
| 命题非全小写 | 提示 |
| 模块/文件名非 `snake_case` | 提示 |
| 缩进非 4 空格 | 提示 |
| 括号非 K&R | 提示 |
| 标识符符号字母混合 | **错误**（语法层拒绝） |
| 使用 `u->` 等伪算符 | **错误**（`u` 未定义或 `->` 位置错误） |

**"标识符符号字母混合"是唯一的编译期错误**——其余是风格建议，由语言服务提示。

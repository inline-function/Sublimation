## 工具链

- **0 代码生成手写，不找库**。square 系只有 JavaPoet/KotlinPoet/SwiftPoet，没有 JS 版；且源到源打印的 AST 结构简单，手写打印器可控。生成产物如需格式化交给 prettier，不进编译器。
- **1 编译顺序**：词法 → 语法 → 语义 → JS 生成，四段独立可测。每段用 Gradle 命令行验证（`gradlew test` / `gradlew run`），不接管 IDE。

## 语法设计

- **2 尖括号传命题（`<>`）保留，大括号留给 lambda/尾随调用**。冲突点只有"实例化 vs 比较"（C++ 模板的老问题）；而 `{}` 已被 `{arg => arg}`、尾随 lambda `f(1){y => y}`（Scala/Kotlin 惯例）占用，挤不进第三职责。**消歧 = 邻接规则**：紧贴名字的 `<` 是实例化，带空格的 `<` 是比较。代价：`a<b` 不带空格即改变含义，靠语言服务提示补救。
- **3 方括号与尖括号的分工**：方括号 `[...]` 里放命题的**名字**（声明 `fun f[@q]`、公理 `unchecked.axiom[q]`）；尖括号里放**实际命题**（`q<p>`、供给 `witness<torch>()`）。
- **4 供给自动优先，显式仅解歧**。作用域检索歧义（同时有 `p<1>`、`p<2>`）时报 `E-PROP-AMBIGUOUS` 让用户显式，平时禁止 `test<p>` 式冗余显式。
- **5 `unchecked` 一个关键字两种逃逸**：`unchecked.axiom[q]`（逃证明义务）与 `unchecked f(x)`/`unchecked v = 1`（逃纯度/可变性）。统一自旧写法 `uncheck.law`，`law` 已由用户决议改为 `axiom`。
- **6 声明关键字**：`fun` 函数、`class` 型类（Rust 的 trait 换 Haskell 拼写，即 tarit→返璞归真）、`struct` 结构体、`enum` 枚举、`var` 绑定、`impl ... for ...`。
- **7 `@new` 是 override 的反向**：impl 成员默认必须对应 class 方法；新增不属于类方法集的函数必须显式标 `@new`。让"必须实现"成为零成本的默认。
- **8 `let` 全废**：语句绑定统一 `var`，默认不可变，`@mut` 开可变；文档的 let-in 表达式不进 v1。
- **9 无修饰符，注解承担一切**；变量注解求短（`@mut`），函数专用注解不限长度（`@unpure`）。
- **10 运算符皆函数、符号可作标识符**（仿 Scala）：`1+1 == +(1,1)`，二元函数即可中缀。**无优先级、左结合**：`1 + 1 * 1 = (1+1)*1`，语言服务提示显式括号。命名函数的中缀（如 `xs filter f`）语法上可行但有分句歧义，**v1 只开放符号名中缀**。
- **11 数值类型**：`Nat/Int/Rat/Str/Null/Nothing`；`Rat` v1 运行期即 IEEE double（换名不换实），语义空间留给未来的精确实数与复数。`Null` 吸收 Unit 职责，同时是 Optional 的成员名；`Nothing` 仿 Rust/Kotlin 空类型。
- **12 bool 不是关键字**：标准库 `enum Bool { true, false }`，消费靠 `if`。
- **13 命题层 Unicode 优先**：`∀ ∃ ∃! ∧ ∨ ¬ → ↔ ⊤ ⊥`；`forall` 等保留 ASCII；"补全成 Unicode"是语言服务的活，编译器 lexer 直接吃两种。
- **14 v1 分支：`if` + `switch`，`match` 永久出局（2026-10-03 用户决议）**。`switch x { case 1, 3, 5 => …; case other => … }`——用户自查该形态本就不具模式匹配能力（case 只比标签：字面量/名字，不解构、无变量绑定、无嵌套），这是刻意取舍而非缺陷：语义层无需生成判定树/refinement，检查器只当普通求值。带字段枚举的消费暂靠选择函数。`other` 不是保留字，仅 case 值位上下文识别。
- **26 新增注解 `@vararg`（可变长参数）与 `@lazy`（惰性初始化，Kotlin `by lazy` 语义）**（2026-10-03 用户决议）。解析层已天然支持（注解是通用 `@ IDENT`），语义/代码生成层 M3/M4 落实。
- **27 `@unpure` 作废**（2026-10-03 用户决议）。解读：用户函数默认且只能纯，非纯性仅内建（print 等）携带，用户侧逃逸走 `unchecked` 前缀。**遗留洞：impl/递归等场景里"非纯"的唯一来源即内建清单，M3 需定内建非纯函数集**（当前默认：print）。

## 语义设计（M3 预研）

- **15 命题检查 = Γ 饱和 + 合一**。Γ 归一为事实原子集（类型事实、等式、谓词原子、命题绑定、伴生记录），合取分解；∀ 特化做谓词头匹配 + 项的一阶合一（变量单向实例化），∃ 只做见证直配；深度上限默认 6，超限报 `E-DEEP-SATURATION`（可配）。定理表中可判定子集即推理规则集。
- **16 明确不做的推理**：算术推理（`abs ≥ 0` 不可证，须 `unchecked.axiom` 或命题参数传递）；等式取语法同一性，不建模公理闭包；∨/→/¬ 出现在"待证"侧只作语法匹配（正向演算的固有边界）。
- **17 `$` 是下文专属变量**：体内 `$ ≡ 末表达式`；调用注入时 `$ ≡ 调用表达式`，`var y = f(x)` 时 `$ ≡ y`。
- **18 函数体是证明义务，声明非可信公理**：下文必须在体尾作用域成立；逃生门只有 `unchecked.axiom`。`fun bad(): Null <p> = {}` 必须报 `E-POST-UNPROVEN`——p 不可凭空合法。
- **19 型类解析选单态化**：`impl Show for Int` 的 `show` 按用到的具体类型生成特化 JS 函数（`show$Int`），不传运行时字典——保持"零擦除、零运行时"。代价：产物可能膨胀、递归型类解析 v1 不处理。**（已被决策 60 推翻）**
- **20 class 约束与命题参数同构但不强行合并**：`fun f[T: Show]` 编译期可视为约束事实 `Show<T>`；与 `@p` 走同一供给/歧义搜索机制。这是"上下文弥散"的第二实例（弥散的不仅是逻辑命题，还有能力约束）。
- **21 函数体独立检查**：体看不到顶层主序列弥散的命题（可移植性）；`@mut` 赋值不产生等式事实（不追踪可变值）。

## 三轮拍板（2026-10-04，用户在《待办.md》逐条批注）

- **28 单值类型改名 Null→`None`**：`enum Optional[T] { None(), Some(T) }`；None 兼具"单值类型"与"Optional 空成员"双角色，用户裁定共存无碍。
- **29 when 即真模式匹配**：Java 式 switch 全盘废弃，关键词统一 `when`（承接 Kotlin）；含解构、嵌套、守卫（`is Nat if n u!= 0`）、`when(var e = 0)` 绑定主题。带字段枚举的解构随 ADT/代数效应/注解处理器同批实装（L-2），此前构造子只可整体比较。
- **30 `type` 别名落地**：`type IO = @unpure ()=>None`——**纯度写进函数类型**（类型级 `@unpure` 前缀），这是代数效应的类型预形。
- **31 Any 与 Nothing 都引入**（受限子类型）；**v1 类型推导先行阉割**：排除 Any 参与、无子类型规则；scala 式完全推断为远期方向（原则二"受限子类型与高阶类型推导支持"）。
- **32 `==` 是内建结构相等函数**：struct 所有字段相等⇒真；**禁止重写 ==**——不同等价语义另开具名函数（如 `nameEq`）。代码生成：`==` 展开为逐字段比较（内联生成，维持零运行时）。
- **33 `$n` 索引参数引用**：具名函数与函数类型均合法（存在隐式证明 `n = $1`）；`$` 指返回值。**内联语义**：下文注入时 `$` 替换为**实际表达式**——`fun f(): Int<$ : Nat>` 经 `var n = f()` 后注入的是 `f() : Nat` 而非 `n : Nat`；`$n` 同样内联为对应实参表达式。
- **34 纯度体系全案**：纯函数禁调非纯（`unchecked` 例外）；每个未标 `@unpure` 的函数，编译器自动给出 `pure<name>` 证明；**非纯函数可证条件纯**：`fun test(f: @unpure (Nat)=>Nat): Nat<pure<f> -> pure<this>>`（`this`=本函数，`self`=结构体接收者，严格区分）；lambda 纯性静态检测：`test { _ + 1 }` 中编译器判定该 lambda 纯→产出 `pure<λ>`→经下文链接得 `pure<this>`，调用点被认可为纯表达式。`_` 为默认单参名（Scala 的 `_`，即 Kotlin 的 `it`）。
- **35 可变变量的命题语义**：`@mut` 变量仅保有自反相等 `v = v`；**非自反相等论据一律忽略**（`v = 0` 视为不成立）。⚠️ 修正现有实现：var 语句带 @mut 时不得注入 `n = 初值` 等式。
- **36 停机性**：纯函数不得随意递归，必须证明终止或 `unchecked` 逃逸。机制待细化（工程师提案见 C 轨：`@terminates(n)` 注解 + 语法子项判定），用户点名要我思考。**（决策 44 拍板，P9 落地）**
- **37 when 穷尽（密封）判定**：用户两处表述为"所有分支命题的**合取**恒真"——⚠️ 逻辑存疑：`b=true ∧ b=false` 是 ⊥ 非 ⊤，密封应为**析取**可证恒真（顺序否定传播下两式等价于 `⊢* p₁∨…∨pₙ`）；待用户确认后写入规范。其余定案：不密封→统一返回 `None`；密封→返回类型为分支类型的**交（join）**；后分支继承前分支命题的否定（已实现）。
- **38 伴生命题恢复为主机制**（推翻"下文直接注入"旧案）：函数被调用 ⇔ 伴生命题 `f<args>` 被证明；下文经定义时登记的公理 **`f<x> → ps₂[x]`** 派生。伴生命题由此承载**调用痕迹性质**（用户例：map 的下文 `self.size() u!= 0 u<-> ∃a. a u_in self . f<a>`——列表非空当且仅当 f 以某元素被调用过）。⚠️ 修正现有实现：调用点仅注入 `f<args>`，`ps₂` 改走公理规则库。**（后经决策 55 修正为共存两通道）**
- **39 ∃! 唯一量化**：直接做（消去 + 单见证）。
- **40 证明器话术与承诺定位**：报错文案"该命题尚未从自动定理证明器中推理出来"，并提示可手动证明（axiom）或使用**证明策略**；可靠性承诺对标 lean4 类定理证明器 + `unchecked` 公理承诺 + 自动证明流程。**证明策略（tactics）为新增挂钩**，机制待设计。
- **41 设计原则宪法八条**（L-10 定稿）：①万物皆为表达式 ②受限子类型与高阶类型推导支持 ③完全模式匹配 ④上下文系统 ⑤不受检操作 ⑥代数效应 ⑦ADT ⑧Kotlin 系语法糖（尾随匿名函数、中缀调用法、默认单参名 `_`、**指名参数、字符串模板、动态元组（≈vararg，异型元组同属一族）**）。其中指名参数/字符串模板/动态元组为新语法债，进 C 轨。
- **42 排期确认**：X 生态暂缓但 LSP 必做（先跑通一次编译）；B 吉祥物/品牌待编译器可编译后谈；R 基建本轮不议。
- **43 穷尽性判定定案析取**（用户确认 L-8 为口误）：密封 ⟺ `Γ ⊢* p₁ ∨ … ∨ pₙ`（顺序否定传播下等价于"分支条件析取恒真"）。
- **44 递归停机机制采纳结构递归**（用户批准）：纯函数自递归调用要求实参为某形参的**语法子项**（机械可判，Lean 风格）；不满足者须 `unchecked` 或未来 `@decreases(度量式)`。`fun die(): Nothing = die()` 属非结构递归→警告。
- **45 Null/None 拆分修订**（用户改判 28）：单值类型（Unit 职责）= `Null`，唯一值小写 `null`；`Optional[T] = { None(), Some(T) }`，`None` 专属 Optional。一名两用取消，类型位/值位不再双关。
- **46 ADT 与模式匹配同批开发**（用户授权我定）：带字段枚举 + when 解构（`Some(x)`、嵌套、通配 `_`）+ 穷尽性枚举覆盖律，合并进 A1；代数效应/注解处理器仍后置。
- **47 工程师默认决议（用户可否决）**：Null 的值写 `null`；零参函数类型记 `()=>T`；`u_in`（T-2 map 例）视为 stdlib 用户级命题，不进 u-系内建清单。
- **48 `by` 辅助策略**（用户引入，2026-10-05）：`by [q₁,…]`（语句式 ByStmt）与 `e by [q]`（后缀式 ByExpr）把人给的中间命题注入当前 Γ 供证明器使用，诊断走补充级 D-BY。与 `unchecked.axiom` 区别：axiom 是"信任承诺"、by 是"辅助步骤标注"。`by` 已进词法保留字，未来复用作 Kotlin 系委托语法糖（决策 26 的 `by lazy`）。
- **49 when 真模式匹配 + 穷尽性判定落地**（2026-10-05，A1/A2）：`switch/case` 全废，改 `when(e){pat->body}`；模式含字面量、构造子解构（`Some(x)`、嵌套、裸名实参按绑定）、`is T [as x]`、`_`、`else`；主题支持绑定式 `when(var e=0)`。分支命题：字面/构造子→`subj=pat`（带字段全绑定时 ∃ 封闭），`is T`→`subj:T`，else/_→⊤；顺序否定累积。穷尽判定：①**枚举覆盖律就地生成**（按 when 主题的**具体类型**，非全局 ∀——避免泛型枚举 `Optional<T>` 因类型实参不匹配导致 MP 触发不了）；②**构造子单射** `C<a>=C<b>→a=b`（Prover.injective）；③**析取子集规则** `(A∨B)⊢(A∨B∨C)`（Prover.disjSubset，取代会自递归爆深度的"分情况"）；④**α-等价**（PropLogic.alphaEq，使命题变量名差异不影响匹配）。**非穷尽→值类型为带标记的 Null（`unsealedT()`），流向非 Null 上下文时报专属错误 `E-NON-SEALED-MATCH`「作为表达式的模式匹配没有密封」**（2026-10-06 用户拍板，推翻本条早先"保守保留 join 类型不降级"的工程师方案；另配 W-NON-EXHAUSTIVE 警告）。v1 限制：嵌套构造子（`Some(Some(y))`）的穷尽性需对见证递归应用覆盖律，超出当前片段，保守判非穷尽（健全，绝不误判穷尽）。附带修复：块体尾表达式重复检查（诊断翻倍）、饱和闭包矛盾检测（p 与 ¬p→⊥）。
- **50 A3-A6 + B 轨落地**（2026-10-06）：A3 声明皆表达式（`VarExpr`/`AnonFunExpr`，`var n=var m=0`、`fun _` 匿名、`_` 不入符号表不可引用）；A4 u-系算符（词法粘连识别 + 中缀 + 归约，`u!=`→`¬(=)`）；A5 prelude 注入 Bool/Null/Optional + 警告通道（W-UNREACHABLE Nothing 不可达追踪、W-DIV-ZERO）；B1 JS 生成器（零成本擦除，when→IIFE if-else 链支持解构、struct/enum→工厂、命题/类型/理论参数全擦除、axiom/by→审计注释）；B2 `compile` 子命令（语义错误即拒产）；B3 e2e 集成测试 9 项（gradle test 内调 node 断言 stdout）。测试 74 全绿。端到端暴露并修复的真 bug：一元负号误判 Bool 类型、when 三元链缺 else 分支（改 IIFE if-else）、零参构造子值引用未生成调用 `None()`、构造子字段为类型参数 `T` 时误参与相等检查（应跳过并由实参推断）、`None` 作值引用丢多态类型实参、`typeLooseEq` 不递归比较类型实参、变量持有 lambda 的调用误报未定义函数。

## 补充细化（2026-10-05~06）

- **51 `by` 辅助策略暂缓**（用户 2026-10-06）：项目重心是**自动证明**（期望用户不必手写证明过程），`by` 已实现且测试通过但**停止投入**，保留代码待自动证明遇到瓶颈时再启用。词法保留字不撤（未来仍可复用作委托语法糖）。
- **52 `Any` 受限顶类型**（用户 2026-10-06）：支持顶类型，但**使用条件严苛**——不能在涉及复杂类型推导的地方使用，"其实和没有差不多"，只在非常非常好的条件下允许。已把 `Any` 加入 `BASE_TYPES`；具体准入规则待类型推导器扩展时定（用户亲自写）。
- **53 `==` 结构相等落地 codegen**（用户 2026-10-06，实现决策 32）：生成的 JS 里相等函数改成我们的逻辑——结构体内所有字段相等则结构体相等。实现为按需注入的 `__eq` 递归助手（比 tag 与全字段），源码未用 `==`/`!=` 时不注入，保持零运行时。注意 `==` 禁中缀（决策 32），只能前缀 `==(a,b)`，故 codegen 的 `SymbolCallExpr` 分支必须生成 `__eq` 调用（曾是占位实现，会把 `==(a,b)` 生成逗号表达式 `(a,b)` 丢掉运算符）。
- **54 `pure` 是上下文命题，不是代数效应内容**（用户 2026-10-06，重要概念澄清）：`pure` 是**单参命题**，属上下文系统。命题不只用于传参，**还能改变代码行为**：持有 `e : Nat` 时可直接用 `e` 的 `+`；持有 `pure<f>` 时编译器认为对 `f` 的调用是纯的。已实现：`registerPureFacts()` 为所有未标 `@unpure` 的具名函数/impl 方法自动注册 `pure<name>` 进 `globalFacts`，`proveOrDeep` 并入全局事实，纯作用域调用非纯函数时若 `⊢ pure<callee>` 则放行。这是"命题驱动行为"的第一个落地实例。
- **55 下文注入与伴生命题公理共存**（用户 2026-10-06，修正决策 38 的"二选一"表述）：两者**不是**择一关系，应用场景不同——调用时直接注入下文（`ps₂`）用于**直接使用**；伴生命题 `f<args>` 经公理 `f<x> → ps₂[x]` 推理出下文，大部分情况下用于**证明函数参数被调用过**（如 map 的 `self.size() u!= 0 u<-> ∃a. a u_in self . f<a>`）。当前实现已注入两者；伴生公理规则库待上下文系统扩展时补。
- **56 代数效应与辅助策略（tactics）均待定**（用户 2026-10-06）：两者用户都"还没想好具体做法"。辅助策略定位明确为**自动证明失败时的手动证明语法糖**——凡能纳入自动证明的就不做成手动策略，故当前不投入。代数效应同待定（注意：`pure` 纯性证明不属于它，见决策 54）。

- **58 `$n` 参数引用规则**（用户）：函数**类型**的前后件里 `$n` 指第 n 个形参；具名函数的上/下文里 `$1` 与参数名等价（存在隐式证明 `n = $1`，体内初始就在），编译器对后者给「提示：可以直接使用参数名」；函数体内禁止 `$n`；`$` 仍指返回值。
- **59 `Any` 严苛准入**（用户）：`fun f(x: Any)` 声明合法；但禁止直接调用含 Any 参数/返回值的函数、禁止调用含 Any 成员结构体的函数、禁止创建/赋值含 Any 成员的结构体——一律需 `unchecked`；**涉及 Any 的类型推导全部失效，须手动标注**。（修正：上轮回复中曾口头宣布 57-63 已归档，实际未写入，本轮补档——纪律 #1 的再犯实录。）
- **60 型类走字典传递**（用户，**推翻决策 19 的单态化**）：不为 Rust 级性能，取 Kotlin 式便利。影响：JS 函数多带字典参数，决策 22"零成本擦除"加此例外；顺带解决 impl 跨 trait 同名冲突（工程规范 §codegen 限制条目作废）。
- **61 元组与 `@tuple`**（用户）：各 arity 元组实现 `Tuple` 型类（**带成员**，成员集第 2 轮定）；变长参数用 **`@tuple`**（**推翻决策 26 的 `@vararg`**），语义=同类型变长元组：`fun setOf[T](@tuple o : T)` 可传 `(a,b)`、`(a,b,c)`……
- **62 EmptyTuple / SingleTuple**（用户补充）：`EmptyTuple`、`SingleTuple[T]` 是元组家族成员但**无字面量**，必须 `emptyTuple()` / `singleTuple(a)` 构造；`(a)` 保持括号表达式。EmptyTuple ≠ Null：Null 是单元类型，EmptyTuple 额外携带元组共有函数（Tuple 型类成员）。

### 第 2 轮：类型系统 T1–T6

- **65 类型系统 T1–T6 落地（第 2 轮，2026-10-06，Max 出指导文档 `doc/plan/2.类型系统落地.md`、Flash 实现）**：决策 57–62 全案实现，110 项测试全绿（Checker 65 + E2E 12 + Lexer 7 + Parser 26），四示例产物逐字节不变。各阶段要点与踩坑：

  - **T3 元组**：`TupleExpr`（判据=逗号，`(a)` 仍是括号表达式）、`TupleType`、`PatTuple` 解构、JS→数组、内建 `emptyTuple()`/`singleTuple()`。**当时**把积类型穷尽性判不出处理成"一律要求 `else`/`_` 兜底"，**已被决策 66 推翻**（改为无覆盖律主题静默退化为 Null、不要求兜底）。
  - **T4 `@tuple` + Any 准入**：`Param.annotations` 承载 `@tuple`，只接受元组字面量实参（裸名报 `E-TUPLE-VARARG`），codegen 预扫描打包为数组；`containsAny()` 递归判定，含 Any 成员的结构体禁直接构造（`E-ANY-STRUCT`）、调用涉 Any 报 `E-ANY-CALL`、`Any` 形参/字段接受任意实参。**踩坑**：`unchecked` 逃逸要覆盖到**表达式通道**——块体尾表达式、lambda 体、if 分支都要继承 `uncheckedDepth`，否则 `unchecked P(1)` 形式仍被纯度检查拦下（新增 `uncheckedDepth` 状态位，I-? 级教训：逃逸语义必须贯通所有求值通道）。
  - **T5 字典传递**（推翻决策 19 单态化）：`resolveDict(方法名, 实参类型)` 在 impl 表找唯一实例（零匹配 `E-NO-INSTANCE`、多匹配 `E-AMBIGUOUS-INSTANCE`）；**字典名以 impl 声明的自类型为准**（`dict_<Trait>_<Type>`），不能用实参类型拼——数值提升会把 `Int` 实参测成 `Nat`，两边名字不一致导致 JS 引用未定义变量（本阶段最隐蔽的坑）。语义层留痕 `Checker.dictHits`（**方法名→字典名**，不是 CallExpr→名字：检查器不重写 AST，按名匹配更稳且同名调用共用字典），经 `generate(ast, dictHits)` 传入 codegen；`impl` 生成字典对象、命中调用生成分发。**偏离规格一处**：指导文档写"字典作第一个隐藏参数 `f(d, x)`"，实际取**直调形态 `dict_X.m(x)`**——等价且 JS 里少一个死参数，e2e 实跑输出正确。仅有 class 声明而无任何 impl 时，方法名也要登记进 `syms.traitMethods`，否则报"未定义函数"而非专属的 `E-NO-INSTANCE`。
  - **T6 `$n` 参数引用**：词法把 `$` 紧贴数字粘连成单 token；解析产出 `ParamRefExpr`。**上/下文里的 `$n` 在声明期由 `rewriteDollarN` 统一改写为参数名**并发 `H-PARAM-REF` 提示，越界报 `E-PARAM-REF`；**函数体内出现 `$n` 直接报 `E-PARAM-REF-IN-BODY`**（`$` 返回值仍合法）。推论：`PropLogic.substDollar` 不需处理 `ParamRefExpr`（上游已清空），保持了"禁止改 Prop.kt 推理规则"的红线——本轮 Prop.kt 只加了 `fromExpr`/`termTag`/`termEq` 三处识别分支。**踩坑**：最初让 `$n` 一路活到调用注入才替换，导致体内后件证明与 Γ 事实形态失配；改为声明期一次性归一后问题消失（与 I-14"同构优先"同源的方法论）。
- **66 穷尽性降级为"提示"而非"要求"**（用户 2026-10-06，第 2 轮收尾拍板）：**不要求 when 穷尽**——判不出穷尽的 when 就按默认值返回 `Null`。实现分两种情形：①主题**有覆盖律**（名义枚举）却覆盖不全 → 保留 `W-NON-EXHAUSTIVE` 警告，因为这是用户确实可以补分支的疏忽；②主题**无覆盖律**（元组/函数类型等结构化类型，判穷尽需等式合同推理，超 v1 片段）→ **静默退化不警告**，因为这不是用户写错，而是编译器判不出，打扰用户不合理。两种情形都退化为 `unsealedT()`，流向非 Null 上下文仍由 `E-NON-SEALED-MATCH` 兜住（决策 49 不变）。
  **撤销的旧立场**：第 2 轮 T3 曾以"积类型穷尽性不可判"为由要求元组主题必须写 `else`/`_`，本条推翻该要求。副产品：遗留问题"元组/函数类型穷尽性依赖等式合同闭包（T-0 #4）"从**阻塞项**降级为**能力增强项**——补上闭包只是让编译器能多判出一些穷尽、少发一些警告，不再是任何功能的前提。
- **67 表达式位不能用语句前缀**（实现教训，非新语义）：`unchecked` 是语句前缀，`when(c) { Red() -> unchecked print(1) }` 语法不过（分支体是表达式位）。要逃逸就在块体里写：`{ unchecked print(1); null }`。写测试与文档示例时容易踩，记此备忘。

### 第 3 轮：对象与方法 O1–O4

- **68 对象与方法回合（第 3 轮，2026-10-06，用户样本驱动，Max 指导 `doc/plan/3.对象与方法落地.md`、Flash 实现）**：用户贴出目标代码要求"能跑"，暴露 6 条表面语法缺口，据此定四阶段。
  - **O1 省略 `=` 的块体**（Kotlin 风格单表达式糖的推广）：`fun f(): T { … }` 与 `fun f(): T = { … }` 等价，函数/匿名函数/impl 成员三处都支持；**class 成员的无体签名**靠上下文标志豁免（头后 `}` 属外层），实现为 `parseFun(braceBodyAllowed)`。
  - **O2 隐式 self + 接收者调用糖**（用户拍板"隐式 self"）：impl 方法**不写接收者参数**，体帧先注入 `self: 自类型` 与结构体各字段（字段裸用 = `self.字段`，故 `print(name)` 合法）；参数名遮蔽字段合法、发 `H-FIELD-SHADOW`。调用 `o.m(args)` 与 `m(o, args)` **双形态等价**，点号形态字段优先（函数值字段不被同名方法截胡）、否则按型类方法解析字典。方法实参数用专属码 `E-METHOD-ARGS`（不含 self）。字典留痕键从**方法名**改为**CallExpr 实例**（IdentityHashMap），修掉同名方法多类型实例的分发 bug。codegen 侧方法签名 `(d, __self, args…)`，裸字段名按"字段集 − 体内全部绑定名"保守重写为 `__self.字段`。
- **69 struct 圆括号 + 字段默认值 + 命名字段构造**：结构体声明维持 `struct A(字段: 类型 = 默认值)` 圆括号体（用户先要 `{}`，后改口"还是用 `()`"）；大括号体明确拒绝并给改写指引。默认值**只属于 struct 字段**，函数形参带默认值报 `E-DEFAULT-PARAM`（默认值是数据构造语义，不是调用语义，v1 不做函数默认参数）。构造两种形态：位置式可缺省尾部（须有默认值，否则 `E-FIELD-MISSING`）、命名字段式 `A(name = "test")`（独立节点 `StructCtorExpr`，未知字段 `E-UNBOUND-NAME`、重复 `E-DUP-FIELD`）。**解析判据**：大写名 + `(IDENT =` 形态才算命名字段构造，`()` 空括号不算（留给 `None()` 这类零参构造子，误判破坏 prelude）。JS 侧靠参数默认值补齐缺省字段。

### 第 4 轮：Kotlin 风格收尾与质量体检

- **71 显式 return**（第四轮，用户点名"返回用return，语法风格向kotlin看齐"）：`return` 升为硬关键字（`Kind.RET`），AST 节点 `ReturnStmt(expr: Expr?)`——带值 `return e` 与裸 `return`（仅返回 Null 的函数合法）两形态。v1 规则：**只允许出现在具名函数/方法体块的顶层语句位**（一次性令牌 `pendingFunReturn` 由 `checkFun` 发放、只被函数体自身块领走）。lambda 体、`if`/`when` 的分支块、块当值用——全部报 `E-RETURN-OUTSIDE`，文案直述根因（IIFE 无法跨层返回）并给出改写方案（改用尾表达式）。实现细节：①带值 return 核对声明返回类型（`E-RETURN-TYPE`），裸 return 要求函数声明返回 Null；②return 语句返回 `Nothing` 标记，复用 A5 通道让 `return` 之后的语句触发 `W-UNREACHABLE`；③体内出现过合法 return 时（`bodyHasReturn`），`checkFun` 让块类型整体核对给逐 return 核对让位（`{ return 7 }` 的块值是 null，不该误报 E-TYPE-MISMATCH）；④codegen 侧 `genFun`/字典方法统一走 `genBlockBody` 展平（语句逐条发射，尾表达式转 return，末语句是 return 时不补 `return null`），字典块体方法从箭头 IIFE 改为 `m: function (d, __self, args…) {…}` 真函数形态——**否则体内 return 只退出 IIFE，静默错位**；⑤`dollarOf`（`$` 返回值指代）扩展：体内**唯一**一处带值 return → `$` := 该表达式（新风格示例 `fun get7(): Int <$ = 7> { return 7 }` 的后件靠它才证得出）；多路/裸 return 无法归一为单一项 → 保守取尾表达式或 null，绝不猜测（猜了会产生"看似通过实则错误"的证明）。**后续扩展项：语句位 `if`/`when` 展平（让 `if c { return 1 }` 合法）列入下轮候选——已由决策 75 落地**。
- **72 诊断码全覆盖体检（第四轮，用户点名"检查一下报错是正常的吗"）**：新增 `DiagCoverageTest`（48 项，每码一触发场景），体检结论——**39 个诊断码全部可正常触发**，并顺带钉出四个事实：①**E-PARSE 不入诊断表**——解析失败以 `ParseFailure` 异常直接抛给 CLI 打印（语法错误无从继续语义分析，设计使然），测试断言异常路径而非诊断码；②**E-ANY-INFER 是预留码**，当前由 `E-ANY-CALL`/`E-ANY-STRUCT` 落地，测试断言其"不触发"防误报；③**E-DEEP-SATURATION 需要右嵌套括号才触发**——`u->` 左结合的长链在闭包阶段一次下钻就转查原子目标（不触发深度守卫），`p1 u-> (p2 u-> (…))` 才把递归深度真正堆过 `maxDepth`；④字段赋值 `p.x = 2` 正确触发 `E-ASSIGN-TARGET`（左值仅支持名字）。体检还确认两条作用域事实：**函数体是独立帧**，顶层 `var` 与顶层 `unchecked.axiom` 不进函数体（巡礼示例的 main 须自带数据与公理）；**@unpure 函数不自动注册 `pure<name>`**，`pure<side>` 类前件需显式供给——这两条已写入《快速上手.md》。
- **73 函数体两形态互斥**（第四轮返工定稿，用户点名"语法风格向 Kotlin 看齐"）：函数体只允许两种形态——**单表达式体 `= 表达式`（无花括号）** 或 **语句块体 `{ 语句… }`（无等号）**，**`= {` 混写一律拒绝**。实现：`parseFun`/`parseAnonFunExpr` 读完头后，若 `peek(ASSIGN) && toks[pos+1] is LBRACE` → 抛 `ParseFailure`，文案直接给出改法「单表达式请去掉花括号写 `= 表达式`，块体请去掉等号写 `{ … }`」。理由：Kotlin 铁律；混写有语义歧义（`= { … }` 是"表达式体返回一个块值"还是"块体返回块末表达式"？两个解释都成立，必须靠约定消歧——不如直接禁掉）；风格统一。代价：写惯 Scala/Java 的人（以及早期文档 §5.1 示例 `fun test1(): unit <p> = { unchecked.axiom[p] }` 这种写法）会不适应；错误提示必须给出改写方案，不能只说"错了"。测试：`ParserTest.体形态互斥 - 等号接花括号报错`、`CheckerTest.体形态互斥 - 等号接花括号报错`。
- **74 顶层只声明，执行代码进 `main()`**（第四轮返工定稿，Kotlin 化收口）：文件顶层只允许**声明**（`fun`/`class`/`struct`/`enum`/`impl`/`type` + `@` 注解开头的函数）；任何执行代码（调用、赋值、`unchecked.axiom`、变量声明）都必须放进 `fun main()`。实现：`Parser.parseEntry` 遇到非声明位直接抛 `ParseFailure`，文案「顶层只能写声明，执行代码请放进 `fun main()`（脚本模式后续支持）」。理由：单文件也强制有清晰入口；避免顶层副作用的弥散污染（与决策 21"函数体独立检查"一脉相承）；Kotlin 化收口的一部分。代价：**脚本模式（类 `.kts`，顶层即主序列）暂不支持**——列为将来特性；早期文档的"顶层主序列 = 隐式 main，编译进 IIFE"（决策 24）表述作废，入口统一由 `fun main()` 承载（决策 70）。测试：`ParserTest.顶层禁语句 - 执行代码须进 main`、`CheckerTest.顶层禁语句 - 裸调用报解析错`。**连带影响**：决策 21 里"顶层声明的名字/签名全文件可见"仍成立，但"顶层主序列弥散的命题"这个说法作废（现在没有顶层主序列）——所有 `var`/`axiom` 都在 `main()` 或函数体内。
- **75 return 检查从"一次性令牌"改为"flow 传播模型"**（第四轮返工定稿，**推翻决策 71 的令牌方案**）：决策 71 落实后，发现一次性令牌模型有两个表达不出的场景：①**语句位 `if` 的分支里 return**（`if c { return 1 }` 应当是合法的，因为它展平成真正的 JS if，return 直接退出函数）；②**尾 `if` 全路径 return**（`if c { return 1 } else { return 2 }`，所有分支都发散，整个 `if` 也是语句而非值）。令牌模型只认"函数体自身的块"，无法把合法范围推广到这两处。新模型：`checkExpr`/`checkStmt` 增加 `flow: Boolean` 参数（默认 `false` = 值位），**flow 的传播规则**——①函数体块（`checkFun` 设 `flow=true`）；②语句位 `if`/`when` 的分支块继承上游 flow（因为 codegen 把它们展平成真正的 JS 控制语句）；③**值位（var 初值/实参/尾表达式/值位 `if`·`when` 分支/lambda 体）恒 `flow=false`**（这些编译成 IIFE，return 逃不出去）；④尾 `if` 且所有分支 `diverges()` 时，整块按语句流处理（复用 `diverges` 判据，与 codegen `genBlockBody` 严格对齐）。合法性判据统一为：**`return` 合法 ⟺ `flow == true && funRetType != null`**。附带：`funRetType` 由 `checkFun` 设/清；`diverges(e)` 与 `exprHasStmtReturn(e)` 提为 AST 工具（`Ast.kt`），checker 与 codegen 共用同一份判据（避免两处各自判断漂移）。理由：flow 显式传播天然覆盖"语句位 if 内 return""尾 if 全路径 return"两个令牌模型覆盖不了的新场景，且不需要维护"令牌是否已被领走"这类易错状态。代价：`checkExpr`/`checkStmt` 加 `flow` 参数（所有调用点默认值兜底，签名变化可控）；`ReturnStmt` 检查要读 `flow` 而不只读 `funRetType`；`dollarOf` 的 `$` 指代规则未变（仍认"体内唯一带值 return"）。**测试新增**：`CheckerTest.提前return - 语句位if分支合法`、`CheckerTest.提前return - 尾if全路径return合法`、`E2ETest.提前return - 语句位if分支端到端`、`E2ETest.提前return - 尾if全路径分支端到端`。**连带影响**：《快速上手.md》的 return 边界表（决策 71 版本）需按新模型更新——把"语句位 `if` 的分支"从 ✗ 改为 ✓，且明确"**值位 `if`（`var x = if …`）仍 ✗**"。

- **76 模块系统（v1.0 P0，目录即模块 + 挂载）**：目录即模块——每个目录（含编译入口根目录）是一个模块，目录名即模块名；同模块内所有 `.subl` 文件共享一个符号表（扁平，无文件级隔离）。**模块树**（`checker/ModuleTree.kt`）：`scanModuleTree` 递归扫描（忽略隐藏目录与 `build`/`out`/`node_modules` 等构建产物目录）；`absPath` = 从根起的 `/` 连接路径（根 = `""`，全局唯一键）。**可见性（I-20）**：`visiblePathsOf(M)` = M ∪ 后代 ∪ 自身及所有祖先的挂载可达（**传递**，"收编即全收"；挂载只向下流淌、不上溯）；父→子可见且传递，子→父不可见，兄弟默认不可见靠挂载建立，**后代看不到根模块**（根 = 编译入口容器，真正可复用的代码放子模块）；`main` 是唯一例外——codegen 扫全树找全局唯一 main，不走可见性检查。**挂载**：`<模块名>.settings` 逐行 `mount <绝对路径> [as <别名>]`（绝对 = 从根起，如 `mount core` 指 `/core`；引用式不复制代码；可多父指向同一份符号；挂载链成环报 `E-CIRCULAR-MOUNT`；本地目录名与挂载名冲突报 `E-DUP-DECL`；settings 语法错报 `E-PARSE-SETTINGS`）。**引用路径相对当前模块视角**：从当前模块的**可见集合**找起点名字，剩下按路径走；挂载传递后 `project` 与其后代 `project/data` 引用 `core` 写法一致（都写 `core.math.gcd`）；同模块内裸名、跨模块点号限定、**类型名同样支持点号限定**（`c.Point`，AST 新增 `QualifiedType`——结构化子类而非名字字符串拼接，换取 I-15 不动 + 编译期 when 穷尽安全网）。**mangle（codegen，M8 合并编译为一个 JS）**：根模块无前缀；非根 `mangleModule(absPath)__<name>`（`core/math.subl` 的 `gcd` → `core_math__gcd`）；字典名 `dict_<mangled>_<Trait>_<Type>`（单下划线，`dict_core_math_Show_Point`）；codegen 通过 Checker 按**引用点实例留痕**（`moduleHits`，IdentityHashMap）取 mangle 名——限定调用/限定引用/同模块非根调用都留痕，局部变量与字段不留，杜绝"裸名猜归属"。**CLI**：`compile`/`check` 都接受目录（M7，check 目录不特殊对待 main）；单文件模式默认参数兜底，完全向后兼容。**型类字典**：`resolveDict` 按当前模块可见路径集合收集 impl（同一条 impl 经多挂载路径到达按绝对路径去重），字典名带声明模块前缀。**限制（P0 文档化）**：跨模块 when 模式、跨模块 typealias 展开、`impl` 的 self 用限定类型（codegen 字段重写失效）、限定函数类型作形参时的 lambda 双向推导未支持；根模块无 settings（无法声明根级挂载）；跨模块 `@unpure` 调用须 `unchecked` 逃逸（P0 无跨模块 pure 事实，每模块只注册本模块函数）。测试：`ModuleTreeTest`（23 项，M1–M8 逐条验收）、`ModuleE2ETest`（5 项，多模块 node 实跑）；基线 198 全绿，实测 226 全绿。

# 空安全系统

> **本文档状态**：设计草案 v0.3（2026-10-09）
>
> **v0.3 相对 v0.2 的变化**：明确**中缀调用的合法性边界**——中缀仅支持**两参函数**与**类型类的单参方法**（因为方法有隐式 self）；**普通单参函数不能中缀**；**零参函数必须写空括号 `()`**。`a ?.f b` 中缀形式按此规则约束。
>
> **v0.2 相对 v0.1 的变化**：`e : T` **不再作为语句位的"编译期断言操作"**——它**只是命题**。要注入用它写 `unchecked.axiom[e : T]`（信任承诺，不检查）；要检查用 `if (e ? T)`（运行时）。

---

## 0. 摘要

### 0.1 问题

**`Optional[T]` 是值，不是类型。** `Some[Rat]` 和 `Rat` 之间**没有子类型关系**——即使调用者知道 `$ : Some[Rat]`，`+` 还是调不了。

### 0.2 答案

**三层组合**：

1. **`T?` 作为 `Optional[T]` 的语法糖**——让"可能缺失的值"成为**类型层**的一等公民
2. **`$ : T` 作为后件**——用**命题**表达"返回值是非空 `T`"，复用现有智能转换
3. **自动解构**——当编译器需要 `T` 而表达式是 `Some[T]` 时，**自动解包**——**代替子类型**

**加上四个运算符**：`a >: T`（安全转换）、`a?.f()` / `a ?.f b`（安全调用）、`a ?: b`（空替代）、`a ? T`（运行时类型测）。

### 0.3 与 Kotlin 的关键差异

| Kotlin | Sublimation | 差异 |
|---|---|---|
| `as T` | **不引入** | 用户改用 `unchecked.axiom[e : T]`（信任承诺）+ `if (e ? T)`（运行时检查） |
| `as? T` | `a >: T` | 符号不同（省关键字） |
| `is T` | `a ? T` | 符号不同 |
| `!!` | **不引入** | 运行时异常违背哲学 |
| 子类型 `Some<T> <: T?` | **不引入** | 用**自动解构**代替 |

**核心立场**：**`e : T` 是命题，不是操作。** 它本身不做任何检查——检查必须显式（`if (e ? T)` 或 `unchecked.axiom[e : T]`）。

## 1. 类型层

### 1.1 `T?` 语法糖

**规则 NS-1**：`T?` 是 `Optional[T]` 的**语法糖**——两者**同一个类型**。⟨目标⟩

```
Rat?        ≡  Optional[Rat]
Str?        ≡  Optional[Str]
List[Nat]?  ≡  Optional[List[Nat]]
```

**推论**：编译器内部**不区分**两者——解析时统一为 `Optional[T]`。

### 1.2 `T??` 嵌套

**规则 NS-2**：`T??` 是 `Optional[Optional[T]]` 的语法糖。⟨目标⟩

任意深度嵌套——`?` 后缀可以叠加。

### 1.3 `None` 统一

**规则 NS-3**：`None` 是**所有可空类型的缺失值**。⟨目标⟩

**没有 `null`**——`None` 是唯一表示缺失的构造子。

### 1.4 `Optional` 保留

**规则 NS-4**：`Optional[T]` 继续存在——`T?` 只是它的语法糖。⟨目标⟩

**风格建议**：日常用 `T?`，泛型签名用 `Optional[T]`——两者等价。

## 2. 五个运算符

### 2.1 `e : T`——类型事实命题

**形态**：两参命题——用 `:` 连接两个项。⟨实现⟩

**位置**：

| 位置 | 形式 | 说明 |
|---|---|---|
| **上文 / 下文 / 公理** | `fun f(x) <x : Nat>` | 作为**命题**出现 |
| **类型参数约束** | `fun f[T : Show]` | 类型层约束——同一 `:` 符号 |
| **形参类型标注** | `fun f(n : Nat)` | 形参的类型声明 |
| **语句位** | **不直接写** | 需用 `unchecked.axiom[e : T]` 注入 |
| **表达式位** | **不写** | 需用 `e ? T` 运行时检查 |

**语义**：

- `e : T` **是命题**——不是操作、不是语句、不检查
- 它作为命题住在 Γ 里——和其他命题**平等**
- 要**注入**它到 Γ：写 `unchecked.axiom[e : T]`——**信任承诺，不检查**
- 要**运行时检查**：写 `if (e ? T) { ... }`——**运行时判定**
- 注入后，`e` 可用 `T` 的方法——**智能转换**

**示例**：

```sublimation
fun useNat(n: Rat): Null {
    unchecked.axiom[n : Nat]    // 注入 n : Nat 到 Γ（信任承诺，不检查）
    print(n + 1)                // ✅ n 可用 Nat 的 +
}
```

**如果不确定 `n` 是不是 `Nat`**——不能写 `unchecked.axiom`，要运行时检查：

```sublimation
fun useNat(n: Rat): Null {
    if (n ? Nat) {
        print(n + 1)            // ✅ 分支内 n : Nat
    } else {
        // 处理不是 Nat 的情况
    }
}
```

**与 Kotlin `as` 的对比**：

| Kotlin | Sublimation | 说明 |
|---|---|---|
| `n as Nat` | `unchecked.axiom[n : Nat]` | **信任承诺**（不检查）——比 `as` 更诚实 |
| `n as? Nat` | `n >: Nat` | 安全转换，返回 `Nat?` |
| `n is Nat` | `n ? Nat` | 运行时检查 |

**Kotlin 的 `as` 会抛异常**——Sublimation **不引入这种"运行时爆炸"**。

**统一性**：

`:` 是**同一个符号**——在类型参数、形参、上文、下文、公理里含义一致——**"两参命题"**：

```sublimation
fun f[T : Show](n : Nat): Nat <n : Nat> { ... }
//   └───┬──┘ └───┬───┘      └───┬───┘
//   类型参数约束  形参类型标注     下文命题
```

### 2.2 `a ? T`——运行时类型测

**形态**：中缀。

**位置**：**表达式位**。

**语义**：⟨目标⟩

- **运行时**检查 `a` 的类型是否是 `T`（见 §7 结构判定）
- 返回 `Bool`
- 在 `if (a ? T) { ... }` 分支内，编译器**智能转换** `a : T`

**示例**：

```sublimation
fun describe(x: Any): Str {
    if (x ? Rat) {
        return "rat"           // 分支内 x : Rat
    }
    return "other"
}
```

### 2.3 `a >: T`——安全转换

**形态**：中缀。

**语义**：⟨目标⟩

- 尝试把 `a` 转换为 `T`
- 成功 → 返回 `Some(a)`（类型 `T?`）
- 失败 → 返回 `None`
- **不抛异常**

**示例**：

```sublimation
var x: Any = 5
var r: Rat? = x >: Rat        // Some(5)
var s: Str? = x >: Str        // None
```

### 2.4 `a?.f(b)`——安全调用

**标准形式**：`a?.f(b)`——⟨目标⟩

**语义**：

- `a` 是 `Some(x)` → 展开为 `x.f(b)`，结果包成 `Some(...)`
- `a` 是 `None` → 直接返回 `None`（短路）
- **返回类型**：`f` 的返回类型加上 `?`

**示例**：

```sublimation
var r: Rat? = Some(5)
r?.toString()                  // Some("5")
r?.add(3)                      // Some(8)

var n: Rat? = None
n?.toString()                  // None
```

### 2.5 `a ?.f b`——安全调用的中缀形式（受限）

**形态**：中缀。

**核心限制**：**中缀形式只在 `f` 满足以下条件时合法**（见 §6.3 完整规则）。⟨目标⟩

**合法场景**：

| 场景 | 示例 | 说明 |
|---|---|---|
| **类型类的单参方法** | `r ?.add 3` | 方法有隐式 self（= `r`）+ 1 显式参数（= `3`），中缀语义是"两参" |
| **两参函数** | `r ?.combine x` | `f` 是两参函数，第一个参数是 receiver |

**非法场景**：

| 场景 | 示例 | 为什么不合法 |
|---|---|---|
| **普通单参函数** | `r ?.inc` | 单参函数**不能中缀**——`inc` 只有一个参数 |
| **零参函数** | `r ?.toString` | **零参函数必须写空括号** —— 应写 `r?.toString()` |
| **多参函数** | `r ?.f a b` | 多参不能中缀——应写 `r?.f(a, b)` |

**正确写法**：

```sublimation
var r: Rat? = Some(5)

// ✅ 类型类方法中缀（self + 1 参）
r ?.add 3

// ✅ 两参函数中缀
r ?.combine x

// ❌ 普通单参函数——不能中缀
// r ?.inc

// ❌ 零参函数——必须写 ()
// r ?.toString

// ✅ 零参函数正确写法
r?.toString()
```

**为什么零参函数必须写 `()`**：

- `r?.toString` 单独出现时，语义歧义——是"调用 `toString`"还是"引用 `toString` 函数值"？
- **函数调用必须写括号**——这是语言的一致性规则（见 §6.3）
- 函数值引用（不带 `()`）只在**明确需要函数值**的位置（如作为高阶函数参数）

### 2.6 `a ?: b`——空替代

**形态**：中缀。

**语义**：⟨目标⟩

- `a` 是 `Some(x)` → 返回 `x`
- `a` 是 `None` → 返回 `b`
- **类型**：`a` 的内层类型与 `b` 的类型的 join

**示例**：

```sublimation
var r: Rat? = None
var x: Rat = r ?: 0            // 0
```

### 2.7 不引入的运算符

**`!!`**：强制非空，运行时抛异常——**不引入**。

**`as T`**：不安全转换，运行时抛异常——**不引入**。

**`n : T` 作为语句位操作**：**不引入**——`:` 是命题，不是操作。

**替代**：

| 想要 | 写 |
|---|---|
| `n as T`（Kotlin） | `unchecked.axiom[n : T]`（信任承诺） |
| `n !!`（Kotlin） | `if (n ? T) { ... }`（运行时检查）或 `unchecked.axiom[n : T]` |
| `n as? T`（Kotlin） | `n >: T` |

## 3. 自动解构

### 3.1 定义

**自动解构**：当编译器需要类型 `T`，而表达式 `e` 的编译期类型是**单字段构造子的应用**（如 `Some[T]`），编译器**自动把 `e` 解构为内部值**。⟨目标⟩

**示例**：

```sublimation
fun takeRat(n: Rat): Null { ... }

fun call() {
    takeRat(Some(5))       // ✅ 自动解构：Some(5) → 5
    takeRat(None)          // ❌ E-TYPE-MISMATCH：None 无内部值
}
```

### 3.2 为什么需要它

**代替子类型**——Kotlin 用 `Some<T> <: T?` + 智能转换；Sublimation **不引入子类型**，用**自动解构**顶替。

### 3.3 触发条件

**规则 AD-1**：自动解构**只在类型检查失败时尝试**。⟨目标⟩

**规则 AD-2**：自动解构**只对单字段构造子**生效。⟨目标⟩

- `Some(T)` / `Ok(T)` / `Err(E)`——单字段 ✅
- `Cons(T, List[T])`——双字段 ❌

**规则 AD-3**：自动解构**单向**——`Some[T] → T` 自动，反向**不自动**。⟨目标⟩

**规则 AD-4**：自动解构**不改表达式的类型**——只在**需要解构的位置**临时解包。⟨目标⟩

```sublimation
var x = Some(5)          // x : Rat?
takeRat(x)               // ✅ 实参位自动解构
print(x)                 // x 仍是 Rat?
```

### 3.4 与 `when` 的关系

**`when` 解构是显式的**——不受自动解构影响：

```sublimation
when (x) {
    Some(v) -> ...       // 显式解构，v : Rat
    None -> ...
}
```

### 3.5 边界

**规则 AD-5**：自动解构**不穿透函数边界**。⟨目标⟩

**规则 AD-6**：自动解构**不进上下文**——不注入 `untouched` / `immutable` 等事实。⟨目标⟩

## 4. 后件弥散与智能转换

### 4.1 `div` 的完整形态

```sublimation
fun div(n: Rat, m: Rat): Rat? <
    m ≠ 0 ↔ $ : Rat,
    m = 0  ↔ $ = None
> {
    if (m = 0) {
        return None
    } else {
        return Some(n / m)
    }
}
```

**验证**：

- `then` 分支：`m = 0` 在 Γ。需证 `$ = None`。`$ := None` 后成立 ✅
- `else` 分支：`m ≠ 0` 在 Γ。需证 `$ : Rat`。`$ := Some(n/m)`——**自动解构**，`$ : Rat` 成立 ✅

### 4.2 调用点的智能转换

```sublimation
var r = div(6, 3)
// 后件弥散：6/3 ≠ 0 ↔ r : Rat

var y = r + 1               // ✅ 6/3 ≠ 0 可证 → r : Rat 在 Γ → + 可用
```

### 4.3 三种"得到 `e : T`"的途径

| 途径 | 场景 | 检查 | 代价 |
|---|---|---|---|
| **函数后件弥散** | 调用 `div(6,3)` 后自动获得 `r : Rat` | **编译器推导** | 零 |
| **`unchecked.axiom[e : T]`** | 用户确信 `e` 是 `T` | **不检查** | 用户承担 |
| **`if (e ? T)` 分支** | 运行时条件判定 | **运行时检查** | 一次判定开销 |

**三条路覆盖所有场景**。**没有任何"隐式检查"或"隐式抛异常"**——每条路用户都明确选择。

### 4.4 需要"报错"怎么办

要 `assert` 语义，用户自己写：

```sublimation
fun assertType[T](o: Any, msg: Str): Null {
    if (o ? T) {
        return None
    } else {
        unchecked.panic(msg)    // 或用户定义的失败处理
    }
}
```

**语言不提供 `assert` 语法糖**——因为"报错"的具体行为（抛异常 / 打印 / 记录 / 退出）由用户决定，**不引入隐式异常**。

## 5. 与上下文系统的整合

### 5.1 五个运算符的语境

| 运算符 | 语境 | 是否影响 Γ |
|---|---|---|
| `e : T` | **命题**（上文/下文/公理/类型参数/形参） | ✅ 在命题位就是命题本身 |
| `unchecked.axiom[e : T]` | 语句位 | ✅ 注入 `e : T` 到 Γ |
| `a ? T` | 表达式位 | ❌ 只在 `if` 分支内注入 |
| `a >: T` | 表达式位 | ❌ |
| `a ?.f(b)` | 表达式位 | ❌ |
| `a ?: b` | 表达式位 | ❌ |

### 5.2 分支内的智能转换

```sublimation
if (x ? Rat) {
    // Γ 注入：x : Rat
    x + 1                    // ✅
}
```

**`if (a ? T)` 的条件注入**：

- `then` 分支：注入 `a : T`
- `else` 分支：注入 `¬(a : T)`——语义待定 ⬜

### 5.3 与 `if[P]` 的关系

**两种 `if`**：

| 形式 | 语境 | 分支条件 |
|---|---|---|
| `if (c) { } else { }` | **运行时** | `c` 求值为 Bool |
| `if[P] { } else { }` | **编译期** | `P ∨ ¬P` 的排中律分派 |

**两者不冲突**——`if (c)` 做运行时判断，`if[P]` 做编译期分派。**语法上区分**（`if (...)` vs `if[...]`）。

**`if[a : T]` 合法**——因为 `a : T` 是命题，`if[P]` 接受任意命题。**这统一了编译期分派的语法**。

### 5.4 与型类字典的关系

```sublimation
class Show { fun show(): Str }

impl Show for Rat { ... }

var r: Rat? = Some(5)

r?.show()          // ✅ 解构 → Rat → 字典分发
r.show()           // ❌ Rat? 不是 Rat 的 impl 接收者
```

## 6. 语法修正

### 6.1 `if` / `when` 改用 Kotlin 式括号

**修正**：`if` 和 `when` 的**条件 / 主题**一律带括号。⟨实现⟩

```sublimation
// ❌ 旧风格
if c { ... }
when x { ... }

// ✅ 新风格（Kotlin 一致）
if (c) { ... }
when (x) { ... }
```

**理由**：与 Kotlin 一致；消除 `if c { ... }` 的视觉歧义。

**注意**：`if[P]` 保持方括号——**这是编译期分派**。

**破坏性变更**——所有示例、测试、文档同步更新。

### 6.2 邻接规则补充

**规则 NS-L1**：`a?.f`、`a ?: b`、`a >: T` 是**双字符/多字符 token**——与 `?.` / `?:` / `>:` 粘连识别。⟨目标⟩

**规则 NS-L2**：`a ? T` 里 `?` 前后**必须有空格**——`?` 紧贴类型名是 `T?` 后缀。⟨目标⟩

**消歧表**：

| 语法形态 | 含义 |
|---|---|
| `T?` | 类型后缀——`Optional[T]` 语法糖 |
| `a?.f` | 安全调用（`.` 紧贴） |
| `a ?: b` | 空替代 |
| `a >: T` | 安全转换 |
| `a ? T`（`?` 前后空格） | 运行时类型测 |

### 6.3 中缀调用的合法性规则

**这是本文档新增的核心规则**，适用于**所有中缀调用**（不只 `?.`）。⟨目标⟩

**规则 INFIX-1**：中缀调用 `a op b` 合法，当且仅当以下之一成立：

1. **`op` 是两参函数**——`op(a, b)` 可以中缀为 `a op b`
2. **`op` 是类型类的单参方法**——方法有隐式 self，`a.op(b)` 等价 `op(a, b)`，中缀为 `a op b`

**规则 INFIX-2**：**普通单参函数不能中缀**。`f(x)` 必须写 `f(x)`，不能写 `x f` 或 `f x`。

**规则 INFIX-3**：**零参函数必须写空括号 `()`**。`f` 单独出现是**函数值引用**，不是调用。`f()` 才是调用。

**规则 INFIX-4**：**多参函数（3 个及以上）不能中缀**。必须写 `f(a, b, c)`。

**规则 INFIX-5**：`a ?.f b` 中缀合法，当且仅当 `f` 满足 INFIX-1——即 `f` 是两参函数或类型类单参方法。

**规则 INFIX-6**：`a ?.f` 不合法——**零参函数必须写 `()`**，应写 `a?.f()`。

### 6.4 中缀规则示例

| 写法 | 合法？ | 说明 |
|---|---|---|
| `a + b` | ✅ | `+` 是两参函数 |
| `a ?: b` | ✅ | `?:` 是两参函数 |
| `a >: T` | ✅ | `>:` 是两参函数 |
| `a ? T` | ✅ | `?` 是两参函数（运行时类型测） |
| `self.show()` | ✅ | 零参方法——**必须写 `()`** |
| `self ?.show()` | ✅ | 零参方法安全调用——**必须写 `()`** |
| `x.f` | ❌ | 零参函数**不能省略括号**——应写 `x.f()` |
| `r ?.toString` | ❌ | 零参函数——应写 `r?.toString()` |
| `r ?.toString()` | ✅ | 零参安全调用 |
| `f x`（`f` 单参函数） | ❌ | 单参函数不能中缀——应写 `f(x)` |
| `r ?.add 3` | ✅ | `add` 是类型类单参方法（self + 1 参） |
| `r ?.f a b` | ❌ | 多参不能中缀——应写 `r?.f(a, b)` |

**规则 INFIX-7**：`?.` 的中缀形式在**解析层**desugar 为 `CallExpr(FieldExpr(a, f), [b])`——不引入新 AST 节点。⟨目标⟩

## 7. 结构判定的限制

### 7.1 JS 动态类型的挑战

`a ? T` 是**运行时类型测**——但 JS **不记录类型信息**。

**方案**：**用结构判断**——如果 `a` 的结构和 `T` 的结构相同，则视为同一类型。

### 7.2 结构判定的语义

**规则 SD-1**：`a ? T` 运行时检查以下之一：⟨目标⟩

1. **基本类型**：`typeof a` 匹配——`Nat`/`Int`/`Rat` → `"number"`，`Str` → `"string"`，`Bool` → `"boolean"`
2. **枚举构造子**：`a.tag === T` 的构造子标签
3. **结构体**：递归检查所有字段的结构类型匹配
4. **函数**：`typeof a === "function"`

**这是结构相等**，不是名义相等——和决策 32/53 的 `==` 语义一致。

### 7.3 局限

- 两个**结构相同但语义不同**的类型无法区分——`struct A(x: Nat)` 和 `struct B(x: Nat)` 在结构判定下**是同一种**
- `EmptyTuple` 与 `Null` 都无字段——无法区分

**这是 JS 动态类型的固有代价。**

**待定** ⬜：是否引入 **tag 字段**做名义区分？

**Max 倾向**：v1 用结构判定——简单、零开销。用户报告歧义时再考虑 tag。

## 11. 设计权衡记录

### 11.1 `e : T` 为什么是命题，不是操作

1. **和 Kotlin 的 `as` 划清界限**——语义根本不同
2. **统一 `:` 的用法**——类型参数、形参、上文、下文、公理里都是"两参命题"
3. **检查和信任分离**——要检查用 `if (e ? T)`；要信任用 `unchecked.axiom[e : T]`

### 11.2 为什么中缀只支持两参和类型类单参方法

**理由**：

- **两参函数**——中缀的经典形态（`a + b` = `+(a, b)`）
- **类型类单参方法**——有隐式 self，语义上是"两参"（`a.m(b)` = `m(a, b)`）
- **普通单参函数**——中缀会歧义（`f x` 是"调用 f 还是引用 f 后接 x"）
- **零参函数**——必须写 `()`，否则与函数值引用混淆
- **多参函数**——中缀语法无法表达 3 个及以上参数

**这是一条"最小化中缀"的规则**——中缀只在"语义清晰、无歧义"时开放。

### 11.3 为什么不用子类型

**决策 31 维持**。**自动解构代替子类型**。

### 11.4 为什么不用 `!!` 和 `as`

**运行时异常违背哲学**。替代见 §2.7。

### 11.5 为什么 `if` / `when` 加括号

**Kotlin 一致**——视觉宪法。

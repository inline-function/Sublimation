# 模块系统（P0，决策 76）

> Sublimation 的代码组织方式：**目录即模块 + 显式挂载**。本文是用户向文档——读完能组织一个多模块项目并跑通。
> 规格的权威版本见 `doc/important/v1.0补全计划.md` §2；实现细节见 `checker/ModuleTree.kt` / `checker/MultiModule.kt`。

## 1. 一句话

每个目录是一个 **模块**（目录名 = 模块名，根目录 = 根模块 `/`）；同模块内所有 `.subl` 文件共享一个符号表（互相裸名可见）；跨模块引用用 **点号限定路径**；跨模块复用要靠 **挂载**（`<模块名>.settings` 里的 `mount` 声明）。

## 2. 最小可运行示例

目录结构：

```
myproj/
├── main.subl          ← 属于根模块 /
├── core/
│   └── math.subl      ← 模块 core
└── util/
    └── util.subl      ← 模块 util
```

`core/math.subl`：

```sublimation
fun gcd(a: Nat, b: Nat): Nat = a + b
```

`util/util.subl`：

```sublimation
fun greet(): Str = "hi"
```

`main.subl`（根模块，父→子可见，跨模块用点号）：

```sublimation
fun main() {
    unchecked print(util.greet())
    unchecked print(core.gcd(20, 22))
}
```

编译并运行（目录作为编译入口 = 根模块 `/`）：

```powershell
.\gradlew.bat -q run --args="check myproj"          # 语义检查（目录）
.\gradlew.bat -q run --args="compile myproj -o out.js"   # 合并编译
node out.js
```

输出：

```
hi
42
```

单文件模式不受影响：`.\gradlew.bat -q run --args="compile a.subl"` 照旧。

## 3. 可见性规则

| 方向 | 规则 |
|---|---|
| 同模块内文件 | **完全互相可见**（裸名，共享符号表） |
| 父 → 子 | 可见，且**传递**（父能看到任意深度的后代） |
| 子 → 父 | **不可见** |
| 兄弟 → 兄弟 | **默认不可见**，靠挂载建立 |
| 根 `/` | 可访问所有后代 |
| 后代 → 根 | **不可见**（子→父规则的特例） |
| `main` 函数 | 唯一例外——codegen **扫全树**找全局唯一 `main`，在产物末尾追加调用，**不走可见性检查** |

**为什么子模块看不到根模块？** 根模块只是"编译入口容器"——真正可复用的代码放在子模块（`core`、`stdlib`），让任何人通过挂载引用它，而不是依赖"恰好和入口目录在同一棵树下"。

## 4. 挂载（`<模块名>.settings`）

模块目录下的 `<模块名>.settings`（如 `project/project.settings`）声明该模块（及其所有后代）对别的模块的挂载：

```
# 每行一个 mount；路径是绝对的（从根 / 起）；空行与 # 注释忽略
mount core
mount core/math as math        # as 别名可选
mount lib/parser
```

规则：

- **引用式**：挂载不复制代码，只在命名空间里加一条映射；同一模块被多父挂载时是**同一份符号**（按绝对路径识别，不会重复 codegen）
- **传递性**：`project` 挂 `core`、`core` 挂 `foo` → `project` 也能看到 `foo`
- **别名**：`mount core as c` 后，当前模块里写 `c.gcd(...)`；别名同时是"本地目录名冲突"的解法
- **挂载链成环** → `E-CIRCULAR-MOUNT`
- **本地目录名与挂载别名冲突** → `E-DUP-DECL`（用 `as` 别名解决）
- **挂载了不存在的模块** → `E-UNBOUND-NAME`
- **settings 语法错** → `E-PARSE-SETTINGS`

## 5. 引用路径（相对当前模块视角）

从当前模块的**可见集合**里找起点名字，剩下的按路径走：

| 场景 | 写法 |
|---|---|
| 同模块内引用（文件共享符号表） | `func(...)`（裸名） |
| 引用子模块 | `data.func(...)` |
| 引用挂载的模块 | `core.math.gcd(...)` |
| 引用跨模块的类型 | `c.Point`（类型名同样支持点号限定） |

**关键**：挂载传递后，`project` 与 `project/data` 引用 `core` 时**写法一致**——都是 `core.math.gcd`，不会因为引用点在不同深度的子模块而改变路径。挂载声明里的路径是绝对的（`mount core`），源码里的引用是相对当前模块视角的（`core.gcd`），两者不冲突。

## 6. 例：stdlib 隐式挂载（P2，决策 78）

`List` 等集合类型来自标准库。编译入口根目录下若有 `stdlib/` 子模块，编译器**自动为每个模块隐式挂载它**（写好代码即可用，无需写 settings）：

```
myproj/
├── stdlib/
│   └── list.subl             ← enum List[T] + listLength/map/fold/range…
├── main.subl                 ← 无需 settings，直接 stdlib.xxx(...)
└── data/
    └── leaf.subl             ← 深处子模块同样 stdlib.xxx(...)
```

```sublimation
// main.subl
fun main() {
    unchecked print(stdlib.listLength(stdlib.range(0, 3)))        // 3
    unchecked print(stdlib.fold(0, \(x, acc) => acc + x,
        stdlib.map(\(x) => x * x, stdlib.range(1, 11))))          // 385
}
```

规则：根模块**本就**透过父→子可见 `stdlib`；非根模块由编译器自动追加 `mount stdlib`；若某模块**自带同名 `stdlib/` 子目录**（用户自备），自动挂载被跳过、以本地为准。`stdlib` 内建原语（Str 操作/IO/数组）仍是编译器注入，不作为 stdlib 模块存在（I-21）。

## 7. 例子：挂载传递 + 深层模块写法一致

```
proj/
├── proj.settings            ← mount core
├── main.subl                ← 写 core.gcd(...)
└── data/
    ├── data.settings        ← （无挂载也行——core 经 proj 传递可见）
    └── leaf.subl            ← 也写 core.gcd(...)，与 main.subl 一致
core/
├── core.settings            ← mount foo
└── mid.subl
foo/
└── f.subl
```

`proj/data/leaf.subl`：

```sublimation
fun viaData(): Nat = core.gcd(2, 2)
```

## 8. impl 也要挂载（显式装配）

`d` 想用 `c` 里的 `impl Show for Point`，**必须挂载 `c`**——这是"显式装配"，不是"隐式发现"：

```
d/d.settings:   mount core
core/c.subl:    struct Point(x: Nat)
                class Show { fun show(): Str  fun getX(): Nat }
                impl Show for Point {
                    fun show(): Str = "P"
                    fun getX(): Nat = x
                }
d/main.subl:    fun main() {
                    var p = core.Point(5)
                    unchecked print(show(p))     // 自由式：跨模块字典分发
                    unchecked print(p.getX())    // 点号式：也是字典分发
                }
```

不挂载 `core` → `show(p)` 报 `E-NO-INSTANCE`；挂载了 `c` 与 `e` 且两者都提供同一 impl → `E-AMBIGUOUS-INSTANCE`。

## 9. 产物（M8 合并编译）

- 所有模块合并成**一个** JS 文件；根模块的函数**不加前缀**，非根模块加模块路径前缀：`core/math.subl` 的 `gcd` → `core_math__gcd`
- 字典名同样带前缀（单下划线）：`dict_core_math_Show_Point`
- `main` 在哪个模块都行（全局唯一），产物末尾自动 `mangle(main)();`

## 10. 本版限制（P0 文档化）

- 跨模块 **when 模式**、跨模块 **typealias 展开**、`impl` 的 self 用**限定类型**（如 `impl Show for core.Point`）、限定函数类型作形参时的 lambda 双向推导——暂不支持
- 根模块没有 settings 文件（无法声明根级挂载）；根只是入口容器
- 跨模块 `@unpure` 调用须 `unchecked` 逃逸（P0 没有跨模块 pure 事实，每模块只注册本模块函数）
- 成员可见性暂不分档（全部 public，v1.0 不做 `@pub`/`private`）

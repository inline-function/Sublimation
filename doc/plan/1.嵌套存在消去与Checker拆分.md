## 2. 任务 A：拆分 Checker.kt

### 2.1 关键技术约束（先读，否则会编译不过）

Kotlin **不允许**把一个类的成员函数分散到多个文件。所以拆分方式是：

- `Checker` 类**只保留**：构造参数、4 个状态字段、`run()`、以及表达式/语句分派（`checkExpr`、`checkStmt`、`checkBin`）。
- 其余函数改成 **`internal fun Checker.xxx(...)` 扩展函数**，分散到各文件。
- 被跨文件访问的字段和函数，可见性从 `private` 改为 **`internal`**。
- 所有文件都在 **同一个 package** `sugared.functor.checker`，扩展函数才能互相调用、才能访问 `internal` 成员。

扩展函数之间可以互相递归调用，无声明顺序问题（这点和局部函数不同，见工程规范 I-13）。

## 3. 任务 B：嵌套存在消去（+ 修一个真 bug）

### 3.1 重要：本轮**不改 `Prop.kt`**

原计划以为要教证明器做 ∃-消去（skolem 化）。实际设计后发现**不需要**：只要让"覆盖律"和"分支命题"两边生成**同构的 ∃ 形态**，现有的 `alphaEq` + `disjSubset`（工程规范 I-5、I-6）就能直接匹配。

所以任务 B 只改 `WhenCheck.kt`（`bindPattern`、`enumCoverageDisj`、新增 `coverShapes`）+ 测试 + 示例。**`Prop.kt` 一行都不许动。**

### 3.2 问题复现（先跑，确认现象）

```sublimation
fun depth(o: Optional<Optional<Nat>>): Nat = {
    when(o) { Some(Some(y)) -> y   Some(None) -> 0   None -> 0 }
}
```

当前行为：报 `W-NON-EXHAUSTIVE`（假阳性）+ `E-NON-SEALED-MATCH`（因为非密封 when 值类型是 `(未密封)`，与声明的 `Nat` 冲突）。
期望行为：**零诊断**。这三个分支在语义上确实穷尽了 `Optional<Optional<Nat>>`。

### 3.3 根因（两处，都要修）

**根因 1：`bindPattern` 的 `ctorTerms` 对嵌套模式丢结构（真 bug，比穷尽性更严重）**

当前代码（WhenCheck.kt，`is PatCtor ->` 分支内）：

```kotlin
val ctorTerms = p.args.map { ap -> bareName(ap)?.let { NameRef(it) } ?: litValue(ap) ?: NameRef("_") }
```

对 `Some(Some(y))`：外层 arg 是 `PatCtor("Some", [PatCtor("y",[])])`，`bareName` 返回 null（因为有 args），`litValue` 返回 null，于是落到 `NameRef("_")`。
结果注入 Γ 的等式是 **`o = Some(_)`**——**内层 `Some(y)` 的结构整个丢了**，`y` 也没出现在命题里。这会让任何依赖该等式的推理都拿到错误前提。

**根因 2：覆盖律只展开一层**

`enumCoverageDisj` 对 `Optional<Optional<Nat>>` 生成 `∃__cov0. o=Some(__cov0) ∨ o=None`，而分支命题（修好根因 1 后）是 `∃y. o=Some(Some(y))`。两者 `alphaEq` 匹配不上 → 判非穷尽。

### 3.4 修法

#### B-1 新增 `patternToExpr`：模式 → 项表达式（递归，保结构）

放在 WhenCheck.kt：

```kotlin
/**
 * 把模式还原为项表达式，用于构造分支命题 `subj = <pattern-as-term>`。
 * 必须递归，否则嵌套模式 Some(Some(y)) 会退化成 Some(_) 丢掉结构（根因 1）。
 */
internal fun Checker.patternToExpr(p: Pattern): Expr = when (p) {
    is PatBind -> NameRef(p.name)
    is PatLit -> p.value
    is PatCtor -> if (p.args.isEmpty()) NameRef(p.name)
                  else CallExpr(NameRef(p.name), p.args.map { patternToExpr(it) })
    is PatIs -> NameRef("_")      // 类型模式不产生项（其分支命题是 subj : T，不走这里）
    is PatElse -> NameRef("_")
}
```

然后把 `bindPattern` 里那行 `ctorTerms` 改为：

```kotlin
val rhs = patternToExpr(p)
val eq = PAtom("=", listOf(subj, rhs))
```

（删掉 `ctorTerms` 和依赖它的 `rhs` 三元判断。）

#### B-2 新增 `patternBoundNames`：递归收集绑定变量名

```kotlin
/** 递归收集模式里所有绑定变量名（不含 `_`），用于 ∃ 封闭分支命题 */
internal fun Checker.patternBoundNames(p: Pattern): List<String> = when (p) {
    is PatBind -> if (p.name == "_") emptyList() else listOf(p.name)
    is PatCtor -> if (p.args.isEmpty()) {
        // 裸名：是已知构造子则无绑定变量，否则它本身是绑定变量
        if (syms.ctors.containsKey(p.name)) emptyList()
        else if (p.name == "_") emptyList() else listOf(p.name)
    } else p.args.flatMap { patternBoundNames(it) }
    is PatIs -> p.bind?.let { if (it == "_") emptyList() else listOf(it) } ?: emptyList()
    else -> emptyList()
}
```

#### B-3 统一 `bindPattern` 的 `PatCtor` 返回命题：一律 ∃ 封闭自由变量

把当前那段"全绑定则 ∃ 封闭、否则保留 ground"的分支判断（`if (ctorTerms.isEmpty() || !p.args.all { isBindingPattern(it) }) eq else { … PExists(evs, …) }`）**整段替换**为：

```kotlin
val freeVars = patternBoundNames(p)
if (freeVars.isEmpty()) eq else PExists(freeVars, eq)
```

效果对照（`o : Optional<Optional<Nat>>`）：

| 模式 | 返回的分支命题 |
|---|---|
| `Some(x)` | `∃x. o = Some(x)` |
| `Some(Some(y))` | `∃y. o = Some(Some(y))` |
| `Some(None)` | `o = Some(None)`（无自由变量） |
| `None` | `o = None` |
| `_` / `x`（裸绑定） | 仍返回 `PTop`（走 `is PatBind` / 未知构造子分支，不变） |

注意：`nf.inject(eq)` 注入帧的仍是 **ground 等式**（`o = Some(Some(y))`），这样体内能用 `y`、构造子单射也能工作；只有**返回给穷尽性判定**的命题才 ∃ 封闭。这个区分不要搞混。

`isBindingPattern` 函数在 B-3 之后可能变成无引用——如果确实没人用了就删掉（连同它的 KDoc），别留死代码。删之前用 Grep 确认全仓库无引用。

#### B-4 覆盖律改为递归深展开

替换 `enumCoverageDisj`，并新增 `coverShapes` 与一个计数字段。

在 `Checker` 类里加字段（Checker.kt，和 `globalFacts` 放一起）：

```kotlin
/** 覆盖律展开的临时变量计数（每次 enumCoverageDisj 调用前重置） */
internal var covCounter = 0
```

在 WhenCheck.kt：

```kotlin
/** 覆盖律展开深度上限；超限则把字段当不可展开类型，保守但保证终止 */
private const val COVER_DEPTH = 3

/** 覆盖律展开的安全阀：形状数超过此值即放弃（返回 null → 保守判非穷尽） */
private const val COVER_MAX_SHAPES = 64

/**
 * 覆盖律的一个"形状"：vars 是要 ∃ 封闭的变量，conjs 是合取项。
 * 渲染为 `∃vars. (c1 ∧ c2 ∧ …)`；vars 为空时就是纯合取。
 */
internal data class CoverShape(val vars: List<String>, val conjs: List<Prop>)

/**
 * 递归生成枚举类型的覆盖形状（决策 49 + 本轮嵌套 ∃ 消去）。
 *
 * 关键设计：内层形状若只给出一条 `v = term` 等式，就把 term **直接代入**外层项，
 * 而不是与外层等式合取。这样生成结果与 bindPattern 的 ∃ 形态**同构**，
 * 现有 alphaEq + disjSubset 就能匹配，无需给证明器加 ∃-消去规则。
 *
 * 例：Optional<Optional<Nat>> →
 *   [ (__cov0, [o = Some(Some(__cov0))]),  ([], [o = Some(None)]),  ([], [o = None]) ]
 * 渲染 → `∃c. o=Some(Some(c)) ∨ o=Some(None) ∨ o=None`
 *
 * v1 限制：
 *  - 多字段构造子不深展开（整体一个 ∃，因为无法把多个内层覆盖律组合成同构形态）
 *  - 字段类型不是枚举时停止展开（如 Nat）
 *  - 超过 COVER_DEPTH 层停止；形状数超过 COVER_MAX_SHAPES 放弃
 * 以上都只会导致"保守判非穷尽"，绝不会误判穷尽（健全性方向正确）。
 */
internal fun Checker.coverShapes(subj: Expr, ty: Type, depth: Int): List<CoverShape> {
    val ed = syms.enums[ty.name] ?: return emptyList()
    val sub = ed.theory.filterIsInstance<TypeParam>().map { it.name }.zip(ty.args).toMap()
    val out = ArrayList<CoverShape>()
    for (c in ed.ctors) {
        // 零元构造子：直接等式
        if (c.fields.isEmpty()) {
            out += CoverShape(emptyList(), listOf(PAtom("=", listOf(subj, NameRef(c.name)))))
            continue
        }
        // 多字段构造子：v1 不深展开
        if (c.fields.size != 1) {
            val vs = c.fields.indices.map { "__cov${covCounter++}" }
            out += CoverShape(vs, listOf(PAtom("=", listOf(subj,
                CallExpr(NameRef(c.name), vs.map { NameRef(it) })))))
            continue
        }
        val ft = c.fields[0].substT(sub)
        val v = "__cov${covCounter++}"
        val vRef = NameRef(v)
        val wrap = { inner: Expr -> CallExpr(NameRef(c.name), listOf(inner)) }
        if (depth > 0 && syms.enums.containsKey(ft.name)) {
            val inner = coverShapes(vRef, ft, depth - 1)
            if (inner.isEmpty()) {
                out += CoverShape(listOf(v), listOf(PAtom("=", listOf(subj, wrap(vRef)))))
            } else {
                for (s in inner) {
                    val single = s.conjs.singleOrNull()
                    // 注意：类型判定必须直接写在 if 条件里，Kotlin 才会把 single 智能转换成 PAtom。
                    // 先算一个 Boolean 再在分支里用 single!! 是编译不过的（Prop 上没有 terms 成员）。
                    if (single is PAtom && single.head == "=" && single.terms.size == 2 &&
                        single.terms[0] is NameRef && (single.terms[0] as NameRef).name == v
                    ) {
                        // 内层就是 `v = term`：代入外层，v 不再需要量化
                        out += CoverShape(s.vars, listOf(PAtom("=", listOf(subj, wrap(single.terms[1])))))
                    } else {
                        out += CoverShape(s.vars + v,
                            s.conjs + PAtom("=", listOf(subj, wrap(vRef))))
                    }
                }
            }
        } else {
            out += CoverShape(listOf(v), listOf(PAtom("=", listOf(subj, wrap(vRef)))))
        }
        if (out.size > COVER_MAX_SHAPES) return emptyList()   // 安全阀
    }
    return out
}

/**
 * 枚举覆盖律（决策 49）：按 when 主题的**具体类型**就地生成析取式。
 * 不用全局 `∀b. b:E→…`——泛型枚举的全局律会因类型实参不匹配（Optional vs Optional<Nat>）
 * 导致 MP 永远触发不了（工程规范 I-3）。
 */
internal fun Checker.enumCoverageDisj(subj: Expr, subjT: Type): Prop? {
    if (!syms.enums.containsKey(subjT.name)) return null
    covCounter = 0
    val shapes = coverShapes(subj, subjT, COVER_DEPTH)
    if (shapes.isEmpty()) return null
    val disjuncts = shapes.map { s ->
        val body = s.conjs.reduce { a, b -> PAnd(a, b) }
        if (s.vars.isEmpty()) body else PExists(s.vars, body)
    }
    return disjuncts.reduce { a, b -> POr(a, b) }
}
```

`COVER_DEPTH` / `COVER_MAX_SHAPES` 是文件级 `private const val`，放在 WhenCheck.kt 顶部。

**注意**：`wrap` 那个 lambda 每次调用都新建 `CallExpr`，若同一 `inner` 被复用没问题；但不要在循环外缓存 `wrap(vRef)` 的结果复用到多个 shape（会让多个分支共享同一个 Expr 实例，虽然 data class 是值语义无害，但容易看错）。按上面写法即可。

## 4. 本轮必须遵守的不变量

全部见《工程规范.md》§2，其中本轮高危的四条：

- **I-5 α-等价**：`disjSubset` 靠 `alphaEq` 匹配，别改成 `render()` 字符串比较。任务 B 的整个设计就建立在它上面。
- **I-6 析取子集方向**：`have ⊆ want` 才成立，反向会让缺分支的 when 误判穷尽。**不要**为了"让嵌套用例通过"而放宽这个方向——那是用健全性换测试绿灯。
- **I-7 目标项作候选但不入事实**：`proves(gamma, goal)` 里 `closure(gamma, listOf(goal))` 的第二参数只贡献实例化候选项。本轮不动 Prop.kt，所以不会碰到，但别顺手"优化"它。
- **I-8 块体尾表达式只检查一次**：搬移 `checkExpr` 的 `BlockExpr` 分支时，保持"循环跳过 tail → facts 回溢 → 单独查 tail"的顺序，否则诊断翻倍。

本轮新增一条，请记入《工程规范.md》§2 作为 **I-14**（文档同步义务见 §6）：

> **I-14 分支命题必须 ∃ 封闭其模式绑定变量，覆盖律必须与分支命题同构。**
> 分支命题若留自由变量（`o = Some(y)` 里 `y` 未量化），穷尽性判定会与覆盖律的 `∃` 形态失配；
> 覆盖律若与分支命题不同构（一边 `∃c. o=Some(Some(c))`、一边 `∃c. o=Some(c)`），`alphaEq` 匹配不上就会假阳性。
> 两边同构 + α-等价，是不给证明器加 ∃-消去规则也能判嵌套穷尽的关键。

## 1. 阶段 O1：省略 `=` 的块体

用户写 `fun printMyself() { ... }`，当前语法要求 `= { ... }`。这是 Kotlin 味的第一道坎。

### 1.1 规则

- `funDecl` 的体：`'=' blockExpr` **或** 直接 `block`（头后紧跟 `{` 即体，无需 `=`）。
- 判定在 `Parser.parseFun`：读完头（params/preps/retType/postps）后，若 `peek(LBRACE)` 且下一个不是 `=>`（排除大括号 lambda 歧义），直接 `parseBlockExpr` 作 body。
- `AnonFunExpr`（`fun _(){...}`）同样支持。
- 风险点：`class`/`impl` 的成员列表用 `{` 包裹——成员头后的 `{` 会被认作块体。这是**期望行为**（用户样本就是这么写的），但要确保成员读完体后外层 `}` 仍能正确闭合。用 `impl B for A { fun m() { ... } }` 的双层花括号做解析测试。

### 1.2 验收

```kotlin
@Test fun `O1 无等号块体`()   // parse: fun f(): Nat { 1 } 的 body 是 BlockExpr
@Test fun `O1 impl成员块体`()  // parse: impl B for A { fun m() { null } } 成员数=1、体在
@Test fun `O1 语义通过`()      // ok("fun f(): Nat { 1 }")
```

## 2. 阶段 O2：隐式 self + 点号方法调用（本轮核心）

### 2.1 语义模型（用户拍板）

型类方法**不再显式写接收者**：

```sublimation
class B {
    @unpure
    fun printMyself()          // 签名：self 隐式，类型 = 被 impl 时的自类型
}

impl B for A {
    @unpure
    fun printMyself() {
        print(name)            // name 裸用 = self.name
    }
}

var o = A("test")
o.printMyself()                // 点号调用（主形态）
printMyself(o)                 // 自由式调用（兼容保留：首实参即 self）
```

- **方法体内**：注入 `self`（隐式名，不可与用户标识符撞——用户写不出 `self`？能写出。规则：**参数名 > 局部变量 > 字段**，同名时内层遮蔽外层，遮蔽字段发提示 `H-FIELD-SHADOW`）。
- 字段裸用：checker 为 impl 方法的每个结构体字段 `declareVar(fname, ftype)` + 注入事实 `fname = self.fname`；codegen 把自由出现的字段名重写为 `self.fname`。
- `class` 成员 v1 只允许**无体签名**（self 类型未定）；若写了体 → `E-SELF-UNKNOWN`「型类成员不能有函数体，体属于 impl」。

### 2.2 破坏性迁移：显式接收者退役

T5 旧风格 `class Show[T] { fun show(v: T): Str }` 里 `v` 兼职了接收者。隐式 self 落地后，形参**全部是真实参数**，接收者一律隐式。迁移：

- `E2ETest.型类字典`：改为 `class Show[T] { fun show(): Str }` + `impl Show for Int { fun show(): Str = "num" }`，调用 `show(5)` 不变（首实参=self）。
- `E2ETest.型类字典方法真正使用参数`：`fun nameOf(a: A): Str = a.name` → `fun nameOf(): Str = name`。
- `ImplCheck.resolveDict` 与 `checkCall` 的类型匹配仍按**首实参**（自由式）/ **点号左值**（点号式）——这两者本来就是 self。
- `signatureMatch`：class 与 impl 成员 params 直接对照（都不含 self），无需改。

### 2.3 dictHits 换键：名字键 → 调用点 IdentityHashMap

**已知 bug**（本轮必修）：`dictHits: Map<String,String>` 按方法名记字典，同名方法对多个类型有 impl 时（`show` for Int + `show` for Str），后一次解析覆盖前一次，两处调用共用一个字典 → 分发错误。

- 改为 `IdentityHashMap<CallExpr, String>`（**Identity** 而非普通 HashMap——CallExpr 是 data class，结构相等会让两个"长得一样"的调用点互相污染；identity 键要求 checker 与 codegen 遍历**同一 AST 实例**，这一点在 T5 已验证成立）。
- `checkCall` 命中字典时 `dictHits[c] = res.dictName`（c 是遍历到的节点实例）。
- `JsCodeGen.call()` 查 `dicts[c]`；`Main.kt`/`E2ETest.run` 的传出链不变（类型签名跟着换）。
- 回归测试：同名方法两个类型各有 impl，两次调用分别走各自字典（e2e 实跑输出两值）。

### 2.4 点号调用的解析与检查

- 解析：`o.printMyself()` 现在就能产出 `CallExpr(FieldExpr(o, printMyself), [])`，Parser 不用动。
- `checkCall`：callee 为 `FieldExpr(t, mname)` 且 `mname` 在 `syms.methods`/`traitMethods` → 方法路径：
  1. `tt = checkExpr(t)`；`resolveDict(mname, tt)`（报错语义不变）；
  2. 剩余实参按 fn.params（真实参数，不含 self）检查；
  3. 返回 `fn.retType`；`dictHits[call] = dictName`；
  4. 注入伴生 `mname<self, args…>` 沿用现状。
- callee 为 FieldExpr 但 mname 不是方法名 → 走现有字段访问（字段持函数值的调用回退 synthetic，与自由式一致）。

### 2.5 codegen：方法签名 `(d, self, args…)` 与字段重写

- `genDict` 成员签名改为 `(d, self, ${params})`；`self` 用固定 JS 名 `__self`（避免与用户变量撞名）。
- 生成体时设上下文 `methodFields: Set<String>`（该 impl 自类型的字段名）：
  - `expr()` 的 NameRef 分支：名字在**局部作用域栈**（参数/声明的 var/块内 let）→ 正常 mangle；否则在 `methodFields` → 输出 `__self.<field>`；否则正常。
  - 作用域栈：`genFun`/块遍历维护（简单 List<Set<String>>，进块 push、出块 pop；`genStmt` 的 VarStmt 记入当前层）。
  - 裸用字段在**语句体**里出现于 dict 方法体外（普通函数）时 `methodFields` 为空 → 不重写，行为不变。
- 自由式 `printMyself(o)` → `dn.printMyself(dn, o)`；点号式 `o.printMyself(x)` → `dn.printMyself(dn, o, x)`（self 与 d 补位）。查表用 `dicts[c]`（§2.3）。
- checker 侧 `self`：`checkFun` 加参数 `selfT: Type?`，impl 成员检查时注入 `self` 变量与字段绑定（§2.1）。`checkDeclBody` 的 ImplDecl 分支把 `impl.self` 传进去。

### 2.6 验收

- 迁移后的 2 个 e2e 用例 + 新增同名多型类分发用例 + 点号调用 e2e（`o.printMyself()` 实跑输出）。
- CheckerTest：点号调用合法、字段遮蔽提示、class 成员带体报 `E-SELF-UNKNOWN`。
- ParserTest 不受影响。四示例逐字节不变。

## 3. 阶段 O3：字段默认值 + 命名字段构造（圆括号形态）

> 用户第 3 轮引导修订（2026-10-06）：struct 声明**保持 `()`**、不引入大括号体；命名字段构造**用圆括号**。

### 3.1 语法

```sublimation
struct A(name: Str = "unknown", age: Nat)   // 声明仍 ()；字段可带默认值
var o = A(name = "test")                     // 命名字段构造：按名给值，缺省字段用默认值
var p = A("test", 3)                         // 位置式保留；v1 位置式仍须全量传参
```

- `Param` 加 `default: Expr? = null`（带默认值的新字段，既有构造点零改动——同 T4 注解做法）。`parseParams` 里字段/形参 type 之后若 `peek(ASSIGN)` → 解析默认值。**仅 struct 字段允许默认值**：函数形参写 `=` → `E-DEFAULT-PARAM`「v1 形参不支持默认值」（区分报错，别静默吞）。
- 新 AST 节点 `StructCtorExpr(name: String, assigns: List<Pair<String, Expr>>, pos)`。
- 解析判据（纯语法层）：primary 位 NAME **首字母大写** 紧跟 `(`，且括号内是 `IDENT = expr (',' IDENT = expr)*` 全赋值形态 → StructCtorExpr；lookahead 不满足**整体回退**按普通 CallExpr 解析（同 braceIsLambda 手法）。`A()` 空括号 = 空 assigns（全默认值）。
- 消歧说明：`f(x = 1)`（小写 callee / 非全赋值形态）维持命题等式实参语义不变；`Some(x = 1)` 会被 parser 认成 StructCtorExpr，由 checker 判 `E-NON-STRUCT`。

### 3.2 检查

- callee 名必须在 `syms.structs`，否则 `E-NON-STRUCT`「X 不是结构体，不能命名字段构造」。
- assigns：字段名必须存在（`E-UNBOUND-NAME`）、不重复（`E-DUP-FIELD`，新码）；值类型核对复用现行规则（名义相等 + Any 接受任意 + synthetic 放行）。
- 未覆盖字段：有默认 → 放行；无默认 → `E-FIELD-MISSING`（新码，错误信息列出缺哪些）。
- StructCtorExpr 的类型 = `namedT(name)`；默认值表达式在**声明的符号上下文不可见**，v1 只在构造点展开求值（checker 对每个用到的 default 表达式在**当前帧**再 check 一遍，保证默认值里的引用在调用点合法）。
- 命题注入：`var o = A(name = "test")` 走现行 var 通道（`o = 构造表达式`），默认值补全发生在 codegen，不在 checker 重写 AST。

### 3.3 codegen

- struct 工厂**不改**（仍位置式）。
- StructCtorExpr 生成时按字段声明顺序合成全量位置实参：assigns 提供的用调用点的表达式，未提供的**内联展开默认值**（每次构造重新求值，非原型共享——注释写明）。
- `walkExprEq`/预扫描加 StructCtorExpr 分支（遍历 assigns 值）与 `Param.default`（结构体声明遍历时）。

### 3.4 验收

- ParserTest：带默认值的 struct 声明；`A(name = "test")` 出 StructCtorExpr；`f(x = 1)`（小写）仍是 CallExpr；`A()` 空 assigns。
- CheckerTest：缺必填 `E-FIELD-MISSING`；未知字段 `E-UNBOUND-NAME`；重复 `E-DUP-FIELD`；全默认 `A()` 放行；非结构体名 `E-NON-STRUCT`；形参默认值 `E-DEFAULT-PARAM`。
- E2E：`struct A(x: Nat = 7)` + `unchecked print(A().x)` → 7（或经解构/字段访问输出）；混合缺省位实跑。四示例逐字节不变。

## 4. 阶段 O4：main 入口

- 规则：文件顶层若存在**具名函数 `main`**（无参或有参都行，推荐 `fun main()`），codegen 在主序列末尾自动追加 `main();`。不存在 main → 不追加，顶层语句照常。
- checker 不为自动调用附加前件证明义务（编译器生成的调用点，v1 视为unchecked级自动注入，记提示 `D-MAIN-CALL` 补充级）。
- `main` 带 `@unpure` 直接允许非纯体（用户样本）；纯 main 调非纯仍须 unchecked（规则不分叉）。
- 实现落点：`JsCodeGen.generate` 的 entries 扫一遍 `FunDecl.name == "main" && 顶层`；line 追加。

### 4.1 验收

- E2E：`fun main() { 1 }` 产物含 `main()`；`@unpure fun main() { println("hello") }` 实跑输出 hello（顶层语句与 main 共存时先语句后 main）。
- CheckerTest：main 不存在时产物不含调用。四示例逐字节不变（它们没有 main）。

## 6. 终局验收：目标形态样本跑通

> 用户第 3 轮引导修订：struct 声明/命名字段构造均**圆括号**（大括号形态作废）。样本由用户原稿按下述规则改写（①struct 体→()`；②`A { name = … }`→`A(name = …)`，其余保持原样）。

```sublimation
struct A(name: Str = "unknown")

class B {
    @unpure
    fun printMyself()
}

impl B for A {
    @unpure
    fun printMyself() {
        print(name)
    }
}

@unpure
fun main() {
    var o = A(name = "test")
    o.printMyself()
}
```

必须：①`check` 通过（0 错误；允许提示级）；②`compile` 产物 node 实跑输出 `test`。
覆盖：O1（两处无 `=` 块体）、O2（隐式 self、裸用 `name`、`o.printMyself()`）、O3（字段默认值、命名字段构造）、O4（main 自动调用）。

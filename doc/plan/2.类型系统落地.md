## 1. 阶段 T1：`Type` 改 sealed + 兼容层

### 1.1 为什么这么改

当前 `data class Type(name: String, args: List<Type>)` 无法表达函数类型 `(A,B)=>C` 与元组类型 `(T,U)`——它们不是"名字 + 实参"。用户已选定方案：改 sealed。

### 1.2 兼容层设计（**核心，逐字照做**）

在 `ast/Ast.kt` 中，把 `Type` 改成 sealed interface + 三个实现：

```kotlin
// ---------- 类型 ----------

/**
 * 类型表示（第 2 轮 T1：sealed 化，决策 57）。
 *
 * **兼容层约定**：`name` 与 `args` 是 interface 的计算属性，让 sealed 化之前
 * 写下的 ~220 处读取点（`t.name`、`t.args`、`typeEq`、`substT`、`baseOf`…）无需改动：
 *  - `NamedType`：返回真实的名字与实参（行为与旧 `data class Type` 完全一致）
 *  - `FunType`：`name` 返回 `"(fn)"`，`args` 返回 `params + ret`
 *  - `TupleType`：`name` 返回 `"(tuple)"`，`args` 返回 `items`
 * 两个哨兵名不可能与用户类型重名（用户标识符不含括号），因此
 * `syms.baseOf` / `aliases` / `structs` 等按 name 查表的逻辑对函数/元组类型天然 miss，
 * 这正是期望行为（它们不是名义类型）。
 */
sealed interface Type {
    val name: String
    val args: List<Type>
    fun render(): String
    fun substT(sub: Map<String, Type>): Type
}

/** 名义类型 / 类型参数引用：`Nat`、`Optional<Nat>`、`T` */
data class NamedType(override val name: String, override val args: List<Type> = emptyList()) : Type {
    override fun render(): String =
        if (args.isEmpty()) name else "$name<" + args.joinToString(", ") { it.render() } + ">"
    override fun substT(sub: Map<String, Type>): Type =
        if (name in sub && args.isEmpty()) sub.getValue(name)
        else NamedType(name, args.map { it.substT(sub) })
}

/** 函数类型 `(A,B)=>C`（决策 57，v1 为 Kotlin 级：无理论参数、无前后件） */
data class FunType(val params: List<Type>, val ret: Type, val purity: String = "") : Type {
    override val name: String get() = "(fn)"
    override val args: List<Type> get() = params + ret
    override fun render(): String =
        (if (purity.isEmpty()) "" else "$purity ") +
            "(" + params.joinToString(", ") { it.render() } + ")=>" + ret.render()
    override fun substT(sub: Map<String, Type>): Type =
        FunType(params.map { it.substT(sub) }, ret.substT(sub), purity)
}

/** 元组类型 `(T,U)`；`EmptyTuple` / `SingleTuple<T>` 是具名形态，走 NamedType */
data class TupleType(val items: List<Type>) : Type {
    override val name: String get() = "(tuple)"
    override val args: List<Type> get() = items
    override fun render(): String = "(" + items.joinToString(", ") { it.render() } + ")"
    override fun substT(sub: Map<String, Type>): Type = TupleType(items.map { it.substT(sub) })
}

/** 构造具名类型的工厂（替代旧 `Type(name, args)` 的全部构造点） */
fun namedT(name: String, args: List<Type> = emptyList()): Type = NamedType(name, args)
```

**关键**：`name` 与 `args` 提到 interface 上后，所有 `t.name` / `t.args` 读取点**一行都不用改**。这是兼容层的全部意义。

### 1.4 需要**语义调整**的读取点（只有这几处，其余靠兼容层）

兼容层覆盖了绝大多数，但下列位置因为"函数/元组类型不是名义类型"而必须显式处理：

**(a) `checker/Types.kt` 的 `isSynthetic` / `isNominal` / `isUnsealed`**

```kotlin
fun syntheticT(reason: String): Type = namedT("(推导:$reason)")
fun Type.isSynthetic(): Boolean = name.startsWith("(推导:") && args.isEmpty()
fun unsealedT(): Type = namedT("(未密封)")
fun Type.isUnsealed(): Boolean = name == "(未密封)" && args.isEmpty()

/** 名义类型：首字母大写的具名类型（不含哨兵名）。函数/元组类型返回 false。 */
fun Type.isNominal(): Boolean = this is NamedType && name.isNotEmpty() &&
    name.first().isUpperCase() && !isSynthetic()
```

`isNominal` 加 `this is NamedType` 是关键——`FunType.name` 是 `"(fn)"`，首字母 `(` 不是大写，本来也会 false，但显式判定更稳（且防止未来哨兵名改大写）。

**(b) `checker/Types.kt` 的 `typeEq`**

```kotlin
/** 名义匹配（v1 同名义相等；T 未绑定时不在此处理）。函数/元组类型按结构相等。 */
fun typeEq(a: Type, b: Type): Boolean = when {
    a is NamedType && b is NamedType ->
        a.name == b.name && a.args.size == b.args.size && a.args.zip(b.args).all { typeEq(it.first, it.second) }
    a is FunType && b is FunType ->
        a.params.size == b.params.size && a.purity == b.purity &&
            a.params.zip(b.params).all { typeEq(it.first, it.second) } && typeEq(a.ret, b.ret)
    a is TupleType && b is TupleType ->
        a.items.size == b.items.size && a.items.zip(b.items).all { typeEq(it.first, it.second) }
    else -> false
}
```

**(c) `checker/Types.kt` 的 `typeToExpr`**（命题层的类型→项转换）

```kotlin
fun typeToExpr(t: Type): Expr = when (t) {
    is NamedType -> if (t.args.isEmpty()) NameRef(t.name)
                    else InstExpr(NameRef(t.name), t.args.map { typeToExpr(it) })
    // 函数/元组类型在命题层用哨兵名表示（v1 不支持对它们做命题推理）
    is FunType -> NameRef("(fn)")
    is TupleType -> NameRef("(tuple)")
}
```

**(d) `checker/Diffusion.kt` 的 `typeLooseEq`** —— 加函数/元组分支：

```kotlin
internal fun Checker.typeLooseEq(a0: Type, b0: Type): Boolean {
    val a = syms.expand(a0); val b = syms.expand(b0)   // 别名展开（决策 30）
    if (a.isSynthetic() || b.isSynthetic()) return true
    if (a.isUnsealed() || b.isUnsealed()) {
        val other = if (a.isUnsealed()) b else a
        return other.isUnsealed() || other.name == "Null"   // §49
    }
    // 函数/元组类型：结构递归比较（T1 只加通道，实际匹配在 T2/T3 才被触发）

}
```

## 2. 阶段 T2：函数类型 `(A,B)=>C`

### 2.1 语法

**只在类型位**（形参类型、返回类型、别名右值、`var` 标注）支持：

```
typeExpr ::= '(' type (',' type)* ')' '=>' type      # (A,B)=>C；零参 ()=>C
           | NAME ('<' type (',' type)* '>')?        # 既有具名/应用类型
```

`=>` 已是词法 token `DARROW`。**v1 不做**：函数类型带理论参数、带前后件（`[T,@p](T)<p>=>T<q>` 属「完美匿名函数」，后置）。

### 2.2 改动清单

**`parser/Parser.kt`**
- `parseType()` 开头加分支：若 `peek(Kind.LPAREN)`，**尝试**解析为函数类型；失败则回退（因为 `(expr)` 在表达式位是括号，但类型位只有函数类型会以 `(` 开头，所以类型位不需要回退——但 `parseType` 也被 `parseParams` 等调用，那些位置 `(` 只可能是函数类型，安全）。
  ```kotlin
  private fun parseType(): Type {
      if (peek(Kind.LPAREN)) return parseFunType()
      // …既有具名类型逻辑不变…
  }

  /** `(A,B)=>C`；零参 `()=>C`。v1 无理论参数与前后件（决策 57） */
  private fun parseFunType(): Type {
      at(Kind.LPAREN)
      val ps = ArrayList<Type>()
      if (!peek(Kind.RPAREN)) {
          while (true) {
              ps += parseType()
              if (peek(Kind.COMMA)) { pos++; continue }
              break
          }
      }
      at(Kind.RPAREN)
      at(Kind.DARROW)
      return FunType(ps, parseType())
  }
  ```
- 注意 `parseTypeArgs()` / `parseParams()` 内部调 `parseType()`，因此 `Optional<(Nat)=>Str>` 自动可用，无需额外改动。

**`checker/Checker.kt`**
- `checkTypeResolvable`：`FunType`/`TupleType` 不查符号表，但要递归检查其子类型：
  ```kotlin
  internal fun Checker.checkTypeResolvable(t: Type, tps: List<String>) {
      when (t) {
          is FunType -> { t.params.forEach { checkTypeResolvable(it, tps) }; checkTypeResolvable(t.ret, tps) }
          is TupleType -> t.items.forEach { checkTypeResolvable(it, tps) }
          is NamedType -> {
              if (t.name in tps) return
              if (syms.baseOf(t) == null) d.error("E-UNBOUND-NAME", "", "未知类型 ${t.render()}")
              t.args.forEach { checkTypeResolvable(it, tps) }
          }
      }
  }
  ```
- `checkExpr` 的 `LambdaExpr` 分支：**双向推导**（决策 55 的 Kotlin 味）。给 `checkExpr` 加一个可选的期望类型参数：
  ```kotlin
  internal fun checkExpr(e: Expr, f: Frame, pure: Boolean, expect: Type? = null): Type
  ```
  **默认参数保证所有既有调用点不用改**（这是本阶段唯一允许的签名扩张）。
  `LambdaExpr` 分支改为：
  ```kotlin
  is LambdaExpr -> {
      val nf = Frame(f)
      val ft = expect as? FunType
      e.params.forEachIndexed { i, pname ->
          val pt = ft?.params?.getOrNull(i) ?: syntheticT("参数")
          nf.declareVar(pname, pt)
          if (ft != null) nf.inject(PAtom(":", listOf(NameRef(pname), typeToExpr(pt))))
      }
      if (ft != null && e.params.size != ft.params.size)
          d.error("E-TYPE-MISMATCH", e.pos, "lambda 有 ${e.params.size} 个参数，期望类型要求 ${ft.params.size} 个")
      val bt = checkExpr(e.body, nf, pure)
      if (ft != null && !bt.isSynthetic() && !typeLooseEq(bt, ft.ret))
          d.error("E-TYPE-MISMATCH", e.pos, "lambda 体类型 ${bt.render()} 与期望返回 ${ft.ret.render()} 不符")
      ft ?: syntheticT("匿名函数")
  }
  ```
- `checkCall`：实参是 `LambdaExpr` 且形参类型是 `FunType` 时，把期望类型传下去：
  ```kotlin
  // 在 checkCall 开头，argTypes 的计算改为：
  val paramTypes = /* 见下 */
  val argTypes = c.args.mapIndexed { i, a ->
      if (a is LambdaExpr) checkExpr(a, f, pure, expect = paramTypes.getOrNull(i))
      else checkExpr(a, f, pure)
  }
  ```
  **难点**：`paramTypes` 需要先知道 `fn`，但 `fn` 的解析在 `argTypes` 之后（因为构造子/结构体判定依赖 argTypes）。**解法**：先按旧方式算一遍 `argTypes`（lambda 无期望类型），解析出 `fn` 后再对 lambda 实参**二次检查**（带期望类型）。二次检查只对 `LambdaExpr` 实参做，成本可控：
  ```kotlin
  // 在 fn.params.forEachIndexed 的实参类型检查循环之后追加：
  fn.params.forEachIndexed { i, p ->
      val a = c.args.getOrNull(i) ?: return@forEachIndexed
      if (a is LambdaExpr) {
          val want = syms.expand(p.type).substT(tsub)
          if (want is FunType) checkExpr(a, f, pure, expect = want)   // 带期望二次检查
      }
  }
  ```
  **不要**改 `argTypes` 的计算方式（会破坏构造子/结构体判定顺序）。

**`checker/TypeInfer.kt`**
- `unify`：加函数/元组分支（结构相等即统一）：
  ```kotlin
  fun unify(a: Type, b: Type): Type? = when {
      typeEq(a, b) -> a
      a.isSynthetic() || b.isSynthetic() -> a.takeUnless { it.isSynthetic() } ?: b
      a.isNumeric() && b.isNumeric() ->
          if (numericRank.getValue(a.name) >= numericRank.getValue(b.name)) a else b
      a is FunType && b is FunType && a.params.size == b.params.size ->
          if (a.params.zip(b.params).all { unify(it.first, it.second) != null } && unify(a.ret, b.ret) != null) a else null
      a is TupleType && b is TupleType && a.items.size == b.items.size ->
          if (a.items.zip(b.items).all { unify(it.first, it.second) != null }) a else null
      a is NamedType && b is NamedType && a.name == b.name && a.args.size == b.args.size -> a
      else -> null
  }
  ```

- 函数类型在 JS 里就是箭头函数，**擦除后无痕迹**。需要处理的只有：lambda 作为实参传递时已经生成 `(x) => …`，无需改。

## 3. 阶段 T3：元组

### 3.1 语法与语义

- 类型：`(T,U)`（`TupleType`，T1 已就位）。**零元/单元组用具名形态**：`EmptyTuple`、`SingleTuple[T]`（决策 62）——它们是 prelude 里的具名类型，不是 `TupleType`。
- 表达式：`(a,b)` 是元组字面量；`(a)` **仍是括号表达式**（决策 62）；`()` 不合法。
- 创建：`emptyTuple()` / `singleTuple(a)` 两个 prelude 函数。
- `Tuple` 型类：成员 `size: Nat`、`isEmpty: Bool`（决策 61「有成员」+ 决策 62「EmptyTuple 与 Null 的区别是有元组共有函数」）。

**关键歧义**：`(a,b)` 在**表达式位**是元组字面量，但 `parsePrimary` 里 `(` 已被括号表达式占用。判定规则：
- `( expr )` → 括号表达式
- `( expr , expr (, expr)* )` → 元组字面量（**逗号是判据**）

这条规则与 Kotlin 一致，无歧义。

### 3.2 改动清单

**`ast/Ast.kt`**：新增
```kotlin
/** 元组字面量 `(a,b)`；`(a)` 是括号表达式不产出本节点，`()` 不合法（决策 62） */
data class TupleExpr(val items: List<Expr>, override val pos: String = "") : Expr
```

**`parser/Parser.kt`** 的 `parsePrimary`：`LPAREN` 分支改为
```kotlin
t.kind == Kind.LPAREN -> {
    pos++
    val first = parseExpr(angle = false)
    if (peek(Kind.COMMA)) {
        val items = ArrayList<Expr>()
        items += first
        while (peek(Kind.COMMA)) { pos++; items += parseExpr(angle = false) }
        at(Kind.RPAREN)
        TupleExpr(items, "${t.line}:${t.col}")
    } else { at(Kind.RPAREN); first }
}
```

**prelude 注册（单一方案，照此执行）**

`EmptyTuple`/`SingleTuple` 是**具名类型**（进 `BASE_TYPES`），`emptyTuple()`/`singleTuple(a)` 是**内建纯函数**——不要用 `registerEnum` 造构造子（那会让 `singleTuple` 变成枚举构造子，与"函数"语义不符）。

第 1 步，`checker/Types.kt`：
```kotlin
// BASE_TYPES 追加两个具名元组类型（决策 62）
val BASE_TYPES = setOf("Nat", "Int", "Rat", "Str", "Bool", "Null", "Nothing", "Any",
    "EmptyTuple", "SingleTuple")

/** 内建纯函数（prelude）：元组构造（决策 62）。与 builtinUnpure 并列。 */
fun builtinPure(name: String): FunDecl? = when (name) {
    "emptyTuple" -> FunDecl("emptyTuple", emptyList(), emptyList(), emptyList(),
        emptyList(), namedT("EmptyTuple"), emptyList(), null)
    "singleTuple" -> FunDecl("singleTuple", emptyList(), listOf(TypeParam("T", null)),
        listOf(Param("a", namedT("T"))), emptyList(),
        namedT("SingleTuple", listOf(namedT("T"))), emptyList(), null)
    else -> null
}
```
并把 `Symbols.findFun` 改为：
```kotlin
fun findFun(name: String): FunDecl? = builtinUnpure(name) ?: builtinPure(name) ?: funs[name]
```
**不需要**把 `builtinPure` 注册进 `globalFacts`：`checkCall` 的纯度检查只对 `"unpure" in fn.annotations` 触发，而 `builtinPure` 返回的 `FunDecl` 注解为空，天然放行。不要多加代码。

第 2 步，`checker/Symbols.kt` 的 `collect()`：只注册 `Tuple` 型类（供决策 61 的"元组共有函数"）
```kotlin
syms.classes["Tuple"] = ClassDecl("Tuple", listOf(TypeParam("T", null)), listOf(
    FunDecl("size", emptyList(), emptyList(), listOf(Param("self", namedT("T"))),
        emptyList(), namedT("Nat"), emptyList(), null),
    FunDecl("isEmpty", emptyList(), emptyList(), listOf(Param("self", namedT("T"))),
        emptyList(), namedT("Bool"), emptyList(), null),
))
```
`Tuple` 型类的 impl（`impl Tuple for EmptyTuple` 等）**v1 不做**——型类成员的实际解析要等 T5 字典传递跑通后再补，本轮只登记型类声明本身，使 `Tuple` 成为合法类型名。

**`checker/Checker.kt`** 的 `checkExpr`：加 `TupleExpr` 分支
```kotlin
is TupleExpr -> {
    val ts = e.items.map { checkExpr(it, f, pure) }
    TupleType(ts)
}
```
`FieldExpr` 分支：元组的字段访问 v1 不支持（用 when 解构或 `singleTuple` 的取值函数）——若 `t is TupleType` 则报 `E-UNBOUND-NAME`「元组无字段访问，v1 请用解构」。

**`checker/WhenCheck.kt`**：`Pattern` 加元组解构
```kotlin
/** 元组模式 `(p1, p2)`（决策 61/62） */
data class PatTuple(val items: List<Pattern>, override val pos: String = "") : Pattern
```
- `parser/Parser.kt` 的 `parsePattern`：`LPAREN` 开头 → 解析逗号分隔的子模式 → `PatTuple`。
- `WhenCheck.bindPattern`：`PatTuple` 分支——注入 `subj = (p1项, p2项)` 等式（用 `TupleExpr` 作为项）、递归 `bindVars` 到各分量（分量类型取 `subjT` 的 `TupleType.items[i]`）、返回 ∃ 封闭命题（复用 `patternBoundNames`，需为 `PatTuple` 加分支递归收集）。
- `JsCodeGen.matchJs`：`PatTuple` → 条件为分量逐个匹配（路径 `s[0]`、`s[1]`），绑定同理。
- `JsCodeGen` 的 `ctorNames`/`matchJs` 里，元组值在 JS 中生成数组 `[a, b]`；`__eq` 已能递归比较数组（`Object.keys` 对数组返回索引字符串），**验证一次**即可。

**`codegen/JsCodeGen.kt`**：
```kotlin
is TupleExpr -> "[" + e.items.joinToString(", ") { expr(it) } + "]"
```
`EmptyTuple`/`SingleTuple` 是具名类型，其构造函数 `emptyTuple()`/`singleTuple(a)` 走普通函数调用路径——但它们没有 JS 实现。**必须在 codegen 里内置**：
```kotlin
// call() 中，与 print 的特判并列：
if (name == "emptyTuple") return "[]"
if (name == "singleTuple") return "[${e.args.joinToString(", ") { expr(it) }}]"
```
并在 `generate()` 里**不要**为它们生成 `const`（它们不是用户声明）。

## 4. 阶段 T4：`@tuple` 变长参数 + `Any` 严苛准入

### 4.1 `@tuple`（决策 61，取代 `@vararg`）

语法：`fun setOf[T](@tuple o : T)`。**调用写法：裸实参自动收集**（用户选定 `setOf(1,2,3)`）。

- `ast/Ast.kt` 的 `Param` 加注解字段：
  ```kotlin
  data class Param(val name: String, val type: Type, val annotations: List<String> = emptyList())
  ```
  默认值保证既有构造点不用改。
- `parser/Parser.kt` 的 `parseParams`：解析 `@` 前缀注解。
- `checker/CallCheck.kt`：形参带 `@tuple` 时，**跳过实参个数检查**，且期望类型是 `TupleType`/`EmptyTuple`/`SingleTuple`——把收集到的实参类型组装成 `TupleType(argTypes)` 与形参声明比对。
- `codegen`：`@tuple` 形参在 JS 里用 rest 参数 `...name`，调用点裸实参天然匹配。

### 4.2 `Any` 严苛准入（决策 59）

规则（用户原话）：声明合法；禁止直接调用含 Any 参数/返回值的函数；禁止调用含 Any 成员结构体的函数；禁止创建/赋值含 Any 成员的结构体；一律需 `unchecked`；涉 Any 的推导失效须手动标注。

- `checker/Types.kt` 加判定：
  ```kotlin
  /** 类型是否含 Any（递归，决策 59：涉 Any 则调用受限、推导失效） */
  fun Type.containsAny(): Boolean = when (this) {
      is NamedType -> name == "Any" || args.any { it.containsAny() }
      is FunType -> params.any { it.containsAny() } || ret.containsAny()
      is TupleType -> items.any { it.containsAny() }
  }
  ```
- `checker/CallCheck.kt`：在函数解析成功后、实参检查前插入
  ```kotlin
  val anyInSig = fn.params.any { it.type.containsAny() } || (fn.retType?.containsAny() == true)
  if (anyInSig && pure)
      d.error("E-ANY-CALL", c.pos, "禁止直接调用含 Any 的函数 $name（决策 59：用 unchecked 前缀）")
  ```
- 结构体创建/赋值：`syms.structs[name]` 分支里，若任一字段 `containsAny()` 且 `pure`，报 `E-ANY-STRUCT`。
- 推导失效：`checkExpr` 中凡推导出 `containsAny()` 的类型，**不注入** `n : T` 事实（`var` 语句与 `VarExpr` 两处），并在无显式标注时报 `E-ANY-INFER`「含 Any 的类型推导已失效，请手动标注类型」。
- 新诊断码登记进《语言语法.md》§6。

## 5. 阶段 T5：字典传递（决策 60，推翻单态化）

### 5.1 语义

`class Show[T] { fun show(v: T): Str }` + `impl Show for Int { … }`：
- 调用 `show(x)` 时，按 `x` 的类型在 impl 表中查字典，把字典作为**第一个隐藏参数**传入。
- 带约束的泛型函数 `fun f[T: Show](x: T)`：`f` 自己也接收一个字典参数，调用点把实参类型对应的字典传进去。

### 5.2 JS 形态（零运行时库，字典是普通对象）

```js
const dict_Show_Int = { show: (v) => `${v}` };
function show(d, v) { return d.show(v); }
function f(d, x) { return show(d, x); }      // T: Show 约束 → 多一个字典参数
f(dict_Show_Int, 3);
```

### 5.3 改动清单

- `checker/Symbols.kt`：`Methods` 表已按方法名收集 `MethodEntry(self, fn, annotations)`。新增字典解析函数：给定方法名 + 实参类型，返回唯一匹配的 `MethodEntry`；多匹配报 `E-AMBIGUOUS-INSTANCE`，零匹配报 `E-NO-INSTANCE`。
- `checker/CallCheck.kt`：方法调用路径（`syms.methods[name]` 命中）改为走字典解析，并把"该调用需要字典"记下来（供 codegen 用——**但 codegen 不读符号表**，所以要在 AST 上留痕，见下）。
- **AST 留痕方案**（关键设计）：codegen 是纯语法变换、不读符号表（工程规范 §codegen 说明）。因此字典解析的结果必须写进 AST。做法：给 `CallExpr` 加一个**可空的解析结果字段**：
  ```kotlin
  data class CallExpr(
      val callee: Expr, val args: List<Expr>,
      /** T5：语义层解析出的型类字典名（如 "dict_Show_Int"）；null = 非方法调用 */
      val dict: String? = null,
      override val pos: String = "",
  ) : Expr
  ```
  默认值保证既有构造点不用改。语义层解析成功后 `c.copy(dict = "...")`——但 `checkExpr` 目前不返回修改后的 AST。**因此需要引入"语义层重写 AST"的机制**：
  - 方案：`Checker` 增加 `val rewrites = HashMap<CallExpr, CallExpr>()`，语义层把解析结果记进去；`Main.kt` 的 `compile` 分支在 `checkFile` 之后、`JsCodeGen().generate` 之前，用一次 AST 遍历把 `rewrites` 应用回去。
  - 这个遍历函数放 `checker/Rewrite.kt`（新文件，Flash 可写，逻辑是纯结构递归）。
- `codegen/JsCodeGen.kt`：
  - `genDecl` 的 `ImplDecl`：不再直接 `genFun`，而是生成 `const dict_<Trait>_<Type> = { m1: (…)=>…, … };`
  - `call()`：`c.dict != null` 时生成 `m(dict_X, args…)`。
  - `ClassDecl` 成员与 `ImplDecl` 成员的函数体：形参列表前插一个 `d`，体内对同类方法的递归调用也传 `d`。

## 6. 阶段 T6：`$n` 参数引用（决策 58）

### 6.1 规则（用户原话）

- 函数**类型**的前后件里 `$n` 指第 n 个形参（类型上无名字）。**但 v1 函数类型不带前后件**（决策 57），所以这条本轮**只在具名函数上生效**。
- 具名函数的上/下文里 `$1` ≡ 第一个形参名，编译器给**提示级**诊断「可以直接使用参数名」。
- 函数体内**禁止** `$n`（`$` 指返回值仍合法）。
- 隐式等式 `n = $1` 在函数体内**最初就有**。

### 6.2 改动清单

- `lexer/Lexer.kt`：`$` 后跟数字 → 新 token `DOLLAR_N`（`text` 存完整 `$1`）。当前 `$` 是 `DOLLAR`。
- `ast/Ast.kt`：`data class ParamRef(val index: Int, override val pos: String = "") : Expr`。
- `parser/Parser.kt`：`parsePrimary` 加 `DOLLAR_N` 分支 → `ParamRef`。
- `checker/Checker.kt` 的 `checkFun`：
  - 上文/下文的 `ParamRef(i)` → 替换为 `NameRef(params[i-1].name)`，并发 `d.hint("H-PARAM-REF", …, "\$$i 可以直接使用参数名 ${params[i-1].name}")`。
  - 体内初始注入隐式等式：`fn.params.forEachIndexed { i, p -> f.inject(PAtom("=", listOf(NameRef(p.name), ParamRef(i+1)))) }`。
  - 体内出现 `ParamRef` → 报 `E-PARAM-REF-IN-BODY`「函数体内不能用 \$n 引用参数，请直接用参数名」。
- `checker/Prop.kt`：`PropLogic.fromExpr` 加 `is ParamRef -> PAtom("\$${e.index}", emptyList())`。
- `ast/AstPrinter.kt` / `codegen/JsCodeGen.kt`：加 `ParamRef` 分支（打印 `$n`；codegen 里 `$n` 只出现在命题层，值层应已被替换，若漏到 codegen 则生成 `undefined` 并报错——**加断言**）。

### 6.3 T6 验收

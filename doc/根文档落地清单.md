## 〇、封存声明（2025-10 路线重规划）

**手动证明语法**与**异步专题**当前处于封存状态：

| 对象 | 封存做法 |
| --- | --- |
| ∵ / ∴ / +∵ / `if[p]` / ∃ 引入·消去 / @theorem 值级调用 / `E-CANNOT-PROVE` `E-PROP-UNBOUND` `E-NEED-CLASSIC` `E-IF-CONCLUSION-MISMATCH` `E-QUANT-UNPROVEN` `E-THEOREM-VALUE-CALL` 等 | 证明失败**降级为警告**（错误码保留、语义同旧，仅 `d.warn` 不再产生 error），**不阻塞主流程**；证明成功的路径照旧注入命题 |
| 异步（Task/Channel/@async/await，`doc/异步.md`） | **代码零改动**，仅文档层面标注封存；后续路线重做 |

封存期约束：不得重写被封存证明语义；不得删除警告码；解封以作者指令为准。

## 二、错误码语义变更（封存）

以下错误码在封存期由 `d.error` 降级为 `d.warn`（码不变、语义描述不变）：

`E-CANNOT-PROVE` `E-IF-CONCLUSION-MISMATCH` `E-QUANT-UNPROVEN` `E-PROP-UNBOUND` `E-NEED-CLASSIC` `E-THEOREM-VALUE-CALL`（另见 Checker.kt:CANNOT_PROVE 附近与 CallCheck.kt:551 等注释）。

涉及文件：`Checker.kt`、`CallCheck.kt`、`Diffusion.kt`。

## 三、新特性落地清单（本轮根文档落实新增）

- Lexer：`def` 关键字（Kind.DEF）
- AST：`PropDefDecl`
- Parser：`parseEntry`/`parseDecl` 顶层分支、`parsePropDef`、`parseUnary` 命题括号 `<e>`、`parseQuant` 多名字 + angle 透传
- Symbols：`propDefs` 登记（查重 E-DUP-DECL）
- Diffusion：`expandDefined`（定义展开）、`constTypeAtom`（字面量类型）、`typeJudgement`（e:T 归属）、`containsImpureCall`（纯度结构相等拦截）
- Prop.kt：`Prover.closure` 多变量笛卡尔矩阵
- Checker：`substThisExpr`（this 内联）、lambda pure 登记
- JsCodeGen / AstPrinter：PropDefDecl 零输出/打印分支

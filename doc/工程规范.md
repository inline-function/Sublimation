# 工程规范（v3.0 追加）

> 架构与不变量。历史不变量 I-1~I-25 见旧档（v2.0）；本文档登记 v3.0 新增/修订并给出文件行数基线。

## 1. 架构

- 管线：Lexer → Parser → checker/（Symbols / Checker / ImplCheck / WhenCheck / Diffusion / Prop / Types）→ codegen/JsCodeGen → JS（node 运行）。
- v3.0 新增：`Vector`/`Range[T]` 内建 + codegen 运行时注入（`__range` 等）；`@theorem`/`@classic` 注解由 Symbols 收集；局部定理随 Frame（作用域随帧）。

## 2. 不变量（v3.0 新增）

- **V-1**：∵∴、if[p]、∃ 语句、@theorem/@classic 声明**不产生运行时代码**（genStmt/stmtStr/lambdaStmtToLines 三处同步擦除）。
- **V-2**：`∴ q` 只搜索 Γ 事实、`@theorem` 函数、当前帧局部函数——**不搜索普通函数**（编译时间保护）。
- **V-3**：`if[p]` 未挂载 core.classic 必报 E-NEED-CLASSIC；两支结论集不等必报 E-IF-CONCLUSION-MISMATCH。
- **V-4**：∃ 消去前提必须已注入（E-PROP-UNBOUND）；∃ 引入实例证不出报 E-QUANT-UNPROVEN；∀ 引入的局部函数必须有体（非"签名即证明"）。
- **V-5**：`.` 字段访问规则 —— 点前无空格或点在新行行首才是字段访问/链式；同行带空格点是 ∃/量词分隔符（不得回归换行链）。
- **V-6**：错消息保留信息密度 —— E-CANNOT-PROVE 与 E-PROP-UNBOUND 均列当前 Γ。

## 4. 纪律

1. 改 lexer/parser 必须同步《语言语法.md》；改语义必须同步《形式化规范.md》。
2. 每个第一批特性独立验收独立 commit；全绿后才进下一个。
3. 禁止改 `Prop.kt` 推理规则（除非特性明确要求）。
4. 跨文件可见性用 `internal`，禁止把 `private` 改 `public`。
5. 新诊断码须在 DiagCoverageTest 覆盖，新语法须有 E2E 端到端。

## 2. 架构不变量（违反任何一条都会引入难查的 bug）

### I-1 邻接规则（消歧的地基）
词法器为每个 token 记录 `precededBySpace`。**紧贴前 token 的 `<` = 实例化**（命题项 `p<v>`、显式供给 `f<q>()`、类型实参 `Optional<Nat>`、声明位的上文/下文）；**带空格的 `<` = 比较中缀函数**。

- `parseType()` 有回退逻辑：紧贴 `<` 但实参表不合法时（如返回类型后的下文 `<$ = 7>`），回退交回结构位处理。**删掉这个 try/catch 回退就会让所有带下文的函数解析失败。**
- `parseAngleList()` 内的 `>` 一律是终止符；带空格的 `<` 在 angle 上下文仍是比较中缀。
- `braceIsLambda` 的判定收紧为"深度 1 内首个 `=>` 前只有名字与逗号"，防 when 块体被误判尾随 lambda。

### I-2 `==`/`!=` 是函数且**禁止中缀**；`=` 是命题等式**可以中缀**
决策 32。因此：
- `Parser.binops` 含 `ASSIGN`（`=`）和 `COLON`（`:`），**不含** `EQ`/`NEQ`。
- `EQ`/`NEQ` 只能走 `symbolCallStart` 前缀路径 → 产出 `SymbolCallExpr`。
- **codegen 必须处理 `SymbolCallExpr`**。曾经这里是占位实现 `"(${args.joinToString(", ")})"`，把 `==(a,b)` 生成 JS 逗号表达式 `(a, b)`，**运算符整个丢失**。已修为调用 `symbolCall()`。任何新增前缀符号都要同步。
- 预扫描 `walkExprEq` 也必须识别 `SymbolCallExpr` 的 `==`/`!=`，否则 `__eq` 助手不注入 → node 运行期 ReferenceError。

### I-3 覆盖律必须**按 when 主题的具体类型就地生成**，不能用全局 `∀`
`enumCoverageDisj(subj, subjT)` 现地造析取。
原因：泛型枚举的全局律 `∀b. b:Optional → …` 里的类型是裸 `Optional`，与事实 `o:Optional<Nat>` **不匹配**，MP 永远触发不了（Kotlin `Type` 的 `args` 参与相等比较）。
历史教训：早期用全局 `coverageAxioms` + `∀` + MP，`Bool` 的 when 穷尽性全部证不出。

### I-4 非密封 when 的类型是**带标记的 Null**，不是普通 Null
`unsealedT() = Type("(未密封)")`，`isUnsealed()` 判定。`typeLooseEq` 里它**只与 Null 相容**。
流向非 Null 返回类型时报专属错误 `E-NON-SEALED-MATCH`「作为表达式的模式匹配没有密封」（用户拍板，否决过工程师的"不降级"保守方案）。
**不要**把它降级成普通 `Type("Null")`——那会让 `fun f(): Nat = { 非穷尽when }` 报含糊的 E-TYPE-MISMATCH；也**不要**保留分支 join 类型。

### I-5 命题变量名靠 **α-等价**匹配，不是 `render()` 字符串相等
覆盖律用 `__cov0`，分支命题用模式绑定名，名字必然不同。`PropLogic.alphaEq` 按绑定变量出现序重命名为 `#k` 再比结构。
`disjSubset` 用 `alphaEq`。**改回字符串比较会让所有带字段枚举的穷尽性判定失效。**

### I-6 析取判定用**子集规则**，不是"分情况"规则
`disjSubset(facts, goal)`：事实的析取子项 ⊆ 目标的析取子项 ⇒ 目标成立。方向不可反：`(A∨B) ⊢ (A∨B∨C)` 有效，反之无效（否则缺分支的 when 会被误判穷尽）。
历史的"分情况"规则（假设 `f.a` 证目标 且 假设 `f.b` 证目标）会对同一条覆盖律**无限自递归**，把非穷尽 when 报成 `E-DEEP-SATURATION`。

### I-7 证明器的 `∀` 实例化候选必须包含**目标项**
`proves(gamma, goal)` 调 `closure(gamma, listOf(goal))`，`extraGoals` 的项只作实例化候选、**不作为事实加入**（否则目标平凡可证，破坏健全性）。
少了这个，`∀n. valid<n>` 永远举不出 `valid<7>` 里的 `7`。

### I-8 块体尾表达式只能检查**一次**
`BlockExpr` 分支：先循环检查非尾语句（含 Nothing 不可达追踪）→ `facts` 回溢 → 再单独检查尾表达式。
曾经"循环全部 + 又单独查尾表达式"，导致**所有块体的诊断翻倍**。这个 bug 影响面极大且不易察觉。

### I-9 `@mut` 变量**不注入**初值等式
决策 35：可变变量仅保有自反相等，`v = 0` 视为不成立。`checkStmt(VarStmt)` 里 `if (isPureValue(value) && !mut)` 才注入 `n = 初值`；类型事实 `n : T` 两者都注入。

### I-10 数值提升判定必须**先于** name 相等判定
`typeLooseEq` 顺序：synthetic → unsealed → **numeric** → name/args → 递归 args。
把 numeric 放后面会让 `Nat` vs `Int`（name 不同）提前 return false，`fun get7(): Int = { 7 }` 误报类型不匹配。

### I-11 构造子字段是类型参数时**跳过相等检查**，由实参反推
`Some(7)`：字段类型是 `T`（`isNominal()` 因首字母大写而误判为真），若参与比较必然报"实参 Nat 与字段 T 不符"。
正确流程：先算 `tps` → 用实参填 `inferred` → 比较时 `if (!isTP && …)` → 返回 `Type(enum, tps.map{inferred[it] ?: synthetic})`。

### I-12 零参构造子作**值引用**时生成调用
`None` 在 `NameRef` 分支 → `None()`（靠 `nullaryCtors` 集合），不是函数引用 `None`。
否则 `describe(None)` 传进去的是函数对象，`.tag` 为 undefined，所有分支不中，返回 null。

### I-13 Kotlin 局部函数**不能互相前向引用**
`walk` 调 `walkStmt`、`walkStmt` 调 `walk` 这种互递归，必须提升为**类成员函数**（或扩展函数）。`needEqPreScan` 就是这么踩坑的。

### I-14 分支命题必须 ∃ 封闭其模式绑定变量，覆盖律必须与分支命题**同构**
分支命题若留自由变量（`o = Some(y)` 里 `y` 未量化），穷尽性判定会与覆盖律的 `∃` 形态失配；覆盖律若与分支命题不同构（一边 `∃c. o=Some(Some(c))`、一边 `∃c. o=Some(c)`），`alphaEq` 匹配不上就假阳性。
两边同构 + α-等价，是**不给证明器加 ∃-消去规则**也能判嵌套穷尽的关键（决策 64 的实现路线）。
注意区分：注入分支帧的等式必须保持 **ground**（`o = Some(Some(y))`，体内才能用 `y`、单射才能推分量等式）；只有**返回给穷尽析取**的命题才 ∃ 封闭。
旧 `ctorTerms` 对嵌套模式退化为 `NameRef("_")` 丢结构（错误前提）——已被 `patternToExpr` 递归取代，防回归测试：`T0 嵌套模式等式保留完整结构`。

### I-15 `Type` 是 sealed；`name`/`args` 是兼容层计算属性，哨兵名不可与用户类型比较
第 2 轮 T1：`Type` 改为 `sealed interface` + `NamedType`/`FunType`/`TupleType`。全仓 ~220 处 `t.name`/`t.args` 读取点靠 **interface 上的计算属性**兼容：`NamedType` 返回真实名字与实参；`FunType` 的 `name="(fn)"`、`args=params+ret`；`TupleType` 的 `name="(tuple)"`、`args=items`。
- 两个哨兵名不可能与用户标识符重名（用户标识符不含括号），但**绝不能拿它们参与名义类型相等比较**——判"是不是名义类型"一律用 `isNominal()`（要求 `NamedType` 且首字母大写）。
- 新增 `Type` 子类时，编译器会在所有穷尽 `when(t)` 处报错，这是护栏；**禁止**加 `else ->` 消错。

### I-16 `$n` 参数引用只在声明期改写为参数名，体内出现即报错
第 2 轮 T6（决策 65）：词法把 `$` 紧贴数字粘连成单 token；解析产出 `ParamRefExpr`。**具名函数的上/下文**里的 `$n` 由 `checkFun` 的 `rewriteDollarN` 统一替换成 `NameRef(第 n 个形参)` 并发 `H-PARAM-REF` 提示；越界报 `E-PARAM-REF`。**函数体内出现 `$n` 直接报 `E-PARAM-REF-IN-BODY`**（请用参数名）；`$`（返回值）仍合法。
推论：`PropLogic.substDollar` 不需要处理 `ParamRefExpr`（上游已清空），若漏到此处说明覆盖不全。

### I-17 型类方法的隐式 self 只在方法体帧注入，签名不写接收者
第 3 轮 O2（决策 68）：impl 方法体内可裸用自类型字段名。`checkFun(fn, selfT)` 的 `selfT` 参数**只对 impl 成员非空**（`checkDeclBody` 的 `ImplDecl` 分支传入）；class 成员 v1 禁止带体（`E-SELF-UNKNOWN`），因为声明期自类型未定。注入顺序固定：先 `injectSelfAndFields`（`self : 自类型` + 各字段 `f : T`），后声明形参——形参遮蔽字段靠"后声明覆盖"实现，发 `H-FIELD-SHADOW` 提示。codegen 侧 `expr(NameRef)` 按"字段集 − 体内全部绑定名"重写为 `__self.字段`（`methodFields`/`methodLocals` 上下文栈），**保守原则**：存在同名局部绑定时整体不重写，宁让 JS 报未定义也不产静默错值；`collectBinders` 必须是类成员函数（I-13）。

### I-18 字典留痕按 CallExpr 实例记录，绝不按方法名
第 3 轮 O2 修正：`Checker.dictHits` 键是 **CallExpr 实例**（codegen 侧按引用查表）。旧按名方案在**同名方法多类型实例**时分发错误（`show` 同时 impl 于两个类型时，后一个调用点覆盖前一个的映射）。`generate(ast, dictHits)` 按调用点取字典名；点号形态 `o.m(args)` 与自由式 `m(o, args)` 统一补齐隐藏首参 `d`（字典自身）与接收者 `__self`，方法签名恒为 `(d, __self, args…)`。

### I-19 return 一次性令牌：只发给函数体自身的块，与 codegen 展平形态严格对齐
第 4 轮（决策 71）：`checkFun` 设 `pendingFunReturn=rt`（体是块才发；单一表达式体不发，否则会被 if 分支块误领），`checkExpr(BlockExpr)` 进块即**消费置 null**——所以只有函数/方法体块的直接语句能领到 `funRetType`，嵌套块（if/when 分支、块当值用、lambda 体）拿到的永远是 null → `E-RETURN-OUTSIDE`。这个"严格顶层"是刻意与 codegen 对齐的：`genBlockBody` 把函数体/字典方法体展平成真正的 JS 函数（语句逐条发射、尾表达式转 return、末语句是 return 时**不补** `return null`），嵌套 if/when/lambda 全是 IIFE——IIFE 里的 return 只退出 IIFE 本身（静默错位），宁可拒绝。推论：①字典块体方法必须是 `m: function (d, __self, …) { … }` 形态，箭头函数会吞 return；②`dollarOf` 认"体内唯一带值 return"作为 `$` 的指代（多路/裸 return 保守取尾表达式或 null，禁止猜测）；③return 语句检查返回 `Nothing` 标记，复用 A5 通道触发后续语句 `W-UNREACHABLE`；④`bodyHasReturn` 时 `checkFun` 的块类型核对让位（`{ return 7 }` 块值是 null，不该误报 E-TYPE-MISMATCH）。

### I-20 模块可见性是"计算出来的集合"，不是"查表的布尔"（P0）
`canSee(from, to)` 不能只判断父子关系——它必须计算 from 的**完整可见路径集合**（后代 + 挂载目标及其后代，**递归传递**）。因为挂载使可见性不再由树结构单独决定。
**推论**：每次符号查找都要传入这个集合，不能依赖全局符号表。模块扫描 + 可见性集合的计算必须在所有 `lookupXXX` 入口之前完成。

**P0 补充约束**：
- **根模块 `/` 的后代看不到根模块**（子→父不可见）。根里的函数不能被子模块引用——这是设计意图（根是"编译入口容器"）。`main` 是唯一例外：codegen 扫全树找它，不走可见性检查。
- **引用路径是相对当前模块视角**：从当前模块的可见集合里找起点名字，剩下的按路径走。挂载传递后，`project/main.subl` 和 `project/data/stringData.subl` 引用 `core` 时**写法一致**（都是 `core.math.gcd`）。
- **挂载是传递的**（`project` 挂 `core`、`core` 挂 `foo` → `project` 能访问 `foo`）。

### I-21 内建函数集是"语法写不出来的原语"，不是"方便函数"（P1–P3）
`concat`/`length`/`readLine`/`arrayGet` 这类**能通过内建访问 JS 原生能力**的才加内建（`builtinPure`/`builtinUnpure`）。`map`/`filter`/`sort` 这类**能用 Sublimation 自己写**的一律进 `stdlib/*.subl`。
判断标准：**"用 Sublimation 能写出来吗？"能，就自举；不能，才内建。**

### I-22 约束事实与命题参数同构（P6，决策 20 落地）
`T: Show` 编译期视为约束事实，和 `@p` 走**同一套**供给/歧义搜索机制。
**不要为约束单独造一套解析逻辑**——复用 `resolveDict` + 可见性过滤（I-20）。

### I-23 等式推理必须在目标侧做，不在闭包侧（P4）
对称、传递、等量代换都不修改 Γ（避免事实库指数膨胀）。`Prover.prove` 在目标判定时按需搜索等式图，深度受 `maxDepth` 限制。
**这是 P4 保持性能的关键**——如果把这些规则塞进 `closure`，等式图会被每轮饱和反复展开，深层程序编译时间会爆炸。

### I-24 等量代换必须浅层（一层），不递归（P4）
递归等量代换会导致不动点计算，超出 v1.0 片段。浅层覆盖 90% 日常场景，剩余靠 `unchecked.axiom` 逃逸。
**推论**：`proveWithSubst` 只对目标做一次替换尝试；不做"替换后再替换"的递归。

## 3. 已实现的语义能力（别重复造）

> **本节描述第 4 轮完成后、P0 开工前的状态。** P0–P11 会陆续加入字符串内建、集合、IO、Result、泛型约束字典透传等；新能力加入后本节要同步更新，避免后续轮次"以为没有而重新实现"。

**Γ 弥散**：`var n = e` → `n = e` + `n : T`（@mut 只注 `:`，I-9）；类型测 `n : Nat` → 注入（智能转换）；`unchecked.axiom[q]` → 直接注入；函数上文注入体、下文注入调用点（`$` := 调用表达式）；伴生记录 `f<args>`；块事实回溢父帧，lambda/函数体隔离。

**证明器**（`Prover`，maxRounds=3 / maxDepth=6）：饱和闭包（合取分解、双否、`∀` 单名实例化含目标项、MP 前向链接、**矛盾检测 p∧¬p→⊥**）；目标判定（结构同一、复合目标事实直配、`=`/`==` 自反、`∃` 单见证、`∨` 子集（方向受限，I-6）、`⊥` 爆炸、`PImp` 前件/后件匹配）；**构造子单射** `C<a>=C<b>→a=b`（Prop.injective）；**α-等价**。
**P4 会新增**：等式对称/传递/等量代换/类型事实等式推理（I-23、I-24）。

**when（决策 29/43/46/64）**：字面量、构造子解构（含**嵌套**、`_`、裸名绑定）、`is T [as x]`、`else`、守卫 `if`、绑定主题 `when(var e=0)`；分支命题 ∃ 封闭绑定变量（I-14）+ 顺序否定累积；**穷尽性判定含嵌套展开**（coverShapes 深展开，`COVER_DEPTH=3`/`COVER_MAX_SHAPES=64` 安全阀，越限只保守不误判）；非密封 → `W-NON-EXHAUSTIVE` + `unsealedT` → 流向非 Null 报 `E-NON-SEALED-MATCH`。多字段构造子（`Pair(a,b)`）暂不深展开。

**pure 驱动纯度**（决策 34/54）：`registerPureFacts()` 为所有未标 `@unpure` 的具名函数/impl 方法注册 `pure<name>` 进 `globalFacts`；`proveOrDeep` 并入；纯作用域调用 `@unpure` 函数时若 `⊢ pure<callee>` 则放行。**"命题改变代码行为"的落地实例**——第 2 轮的 `e : Nat` 驱动方法可用性是同类扩展。

**类型系统（第 2 轮 T1–T6，决策 57–65）**：
- **函数类型 `(A,B)=>C` / `()=>C`**（T2）：`FunType(params, ret)`；类型位 `(` 由 `parseFunOrTupleType` 按有无 `=>` 分流。lambda 实参带期望类型二次检查（双向推导）。v1 函数类型**不带前后件**。
- **元组**（T3）：`TupleType(items)`；`(a,b)` 是 `TupleExpr`（判据=逗号，`(a)` 仍是括号表达式，`()`) 不合法）；类型位 `(T,U)`；`when` 支持 `PatTuple` 解构。积类型的穷尽性需等式合同推理（超 v1 片段），**按决策 66 处理**：无覆盖律主题判不出穷尽时**静默退化为 Null、不发警告**（`enumCoverageDisj` 返回 null 即此信号）。JS 形态=数组。内建 `emptyTuple()`/`singleTuple()`（`builtinPure`）。具名形态 `EmptyTuple`/`SingleTuple` 进 `BASE_TYPES`。
- **`@tuple` 形参**（T4，决策 61）：`Param.annotations` 承载；只接受**元组字面量**实参，裸名报 `E-TUPLE-VARARG`；codegen 预扫描 `tupleParamPos` 把该位起的实参打包成数组。
- **`Any` 严苛准入**（T4，决策 59）：`containsAny()` 递归判定；含 Any 成员的结构体禁直接构造（`E-ANY-STRUCT`，`uncheckedDepth` 上下文内放行）；调用涉及 Any 报 `E-ANY-CALL`；`Any` 形参/字段接受任意实参（受限顶类型）。
- **型类字典传递**（T5，决策 60，推翻单态化）：`resolveDict(方法名, 实参类型)` 在 impl 表找唯一实例，零匹配 `E-NO-INSTANCE`、多匹配 `E-AMBIGUOUS-INSTANCE`；**字典名以 impl 声明的自类型为准**（`dict_<Trait>_<Type>`，数值提升 Nat↔Int 靠 `typeLooseEq` 宽松匹配）；语义层留痕 `Checker.dictHits`（**CallExpr 实例→字典名**，见 I-18），经 `generate(ast, dictHits)` 传入 codegen；codegen 把 `impl` 生成字典对象、命中调用生成 `dict_X.m(args)` 分发。

**对象与方法（第 3 轮 O1–O4，决策 68/69/70）**：
- **O1 省略 `=` 的块体**：`fun f(): T { … }` ≡ `fun f(): T = { … }`（函数/匿名函数/impl 成员三处）；class 成员的无体签名靠 `parseFun(braceBodyAllowed=false)` 豁免——头后的 `}` 属外层容器，不能贪（决策 68）。
- **O2 隐式 self + 双形态调用糖**：`o.m(args)` ≡ `m(o, args)`；点号位**字段优先**（函数值字段不被同名方法截胡），否则按型类方法解析字典（`resolveDict`）。方法体帧见 I-17，留痕见 I-18。诊断：`E-NO-SELF`（自由式缺接收者）、`E-METHOD-ARGS`（方法参数数不含 self）。
- **O3 struct 字段默认值 + 两种构造**：`struct A(name: Str = "u", age: Nat = 0)`；位置式可缺省尾部（`E-FIELD-MISSING`），命名字段式 `A(age = 3)` 是**独立 AST 节点** `StructCtorExpr`（`E-DUP-FIELD`/`E-UNBOUND-NAME`）；解析触发条件=大写名 + `(IDENT =` 前瞻（`()` 空括号**不算**，否则 `None()` 破坏 prelude）；JS 工厂用参数默认值补齐，缺省字段传 `undefined`。默认值只属于 struct 字段，函数形参带 `=` 报 `E-DEFAULT-PARAM`；默认值表达式声明期用空帧检查类型。
- **O4 main 入口**：具名零参 `fun main()` 由 codegen 尾部自动追加 `main();`，与顶层主语句共存（main 排最后）；带形参/类型参报 `E-MAIN-PARAMS`，重复声明由 `E-DUP-DECL` 兜住。

**显式 return（第 4 轮，决策 71）**：`return` 硬关键字 + `ReturnStmt(expr?)`；仅函数/方法体块顶层语句位合法（I-19 一次性令牌），if/when 分支块与 lambda 体报 `E-RETURN-OUTSIDE`；带值核对返回类型（`E-RETURN-TYPE`）、裸形要求 Null 函数；return 后语句触发 `W-UNREACHABLE`；`$` 指代认唯一带值 return。

**诊断码全覆盖（第 4 轮，决策 72）**：`DiagCoverageTest` 48 项，39 码逐一构造触发场景全过，钉实四条作用域/触发事实（详见决策 72 与《快速上手.md》）。

**集合（P2，决策 78）**：两路——**内建数组原语**（I-21 例外）：`arrayOf`（vararg 打包）/`arrayGet`（`Some`/`None` 包装）/`arraySet`（`slice()` 复制设值）/`arrayLength`，纯函数，codegen 特判；**stdlib List**（用户拍板 B：隐式挂载的 stdlib 模块）：`stdlib/list.subl` 是模块树正常模块（`enum List[T]` + `listLength`/`head`/`map`/`filter`/`fold`/`append`/`reverse`/`range` 自举），编译器在扫描后为每个非根模块自动追加 `mount stdlib`（本地名占用时跳过；stdlib 自身不注入）。**推断补强**：`extractTpBinding`（嵌套类型参数 + FunType 同构递归，合成不绑定）、`checkCtorCall` 字段比较 subst 化、lambda 返回实际组合类型 + `checkFnCall` 反推类型参数、`checkBin` synthetic 操作数不兜底 Bool、lambda 期望返回未解析类型参数时跳过核对。

**IO（P3，决策 79）**：4 个 `@unpure` 内建（`readLine`/`readFile`/`writeFile`/`getArgs`）；`getArgs` 返回 `List<Str>`（复用 stdlib 的 `List`，codegen 逆序构建 Cons/Nil）；产物内联 `require('fs')`（node 模块缓存）。

**模块系统（P0，决策 76）**：目录即模块——每个目录（含编译入口根目录）是一个模块，目录名即模块名，同模块内所有 `.subl` 文件共享一个符号表（扁平，无文件级隔离）。`checker/ModuleTree.kt`：递归扫描（忽略隐藏目录与 `build`/`out`/`node_modules` 等）、`<模块名>.settings` 行式解析（`mount <绝对路径> [as <别名>]`）、挂载图环检测、I-20 可见路径集合计算（`visiblePathsOf(M)` = M ∪ 后代 ∪ 自身及祖先挂载可达，传递）、限定引用解析（`resolveQChain`：纯名字链相对当前模块视角，首名非局部变量）；`checker/MultiModule.kt`：多模块驱动（阶段 A 全树收集建 `allSymbols` → B 类型可解析性/impl/pure → C 声明体），`bag.absorb` 合并诊断 + main 全局唯一检查（>`E-DUP-DECL`）。可见性：父→子且传递、子→父不可见（含后代→根）、兄弟默认不可见靠挂载、**根 = 入口容器**、`main` 唯一例外（codegen 扫全树，不走可见性检查）。跨模块引用：点号限定路径、同模块裸名、**类型同样支持限定**（`c.Point`）——AST 用结构化子类 `QualifiedType`（不把模块编码进名字字符串，保住 I-15 兼容层与编译期 when 穷尽安全网）。codegen（M8 合并编译）：根无前缀、非根 `mangleModule(absPath)__<name>`、字典名 `dict_<mangled>_<Trait>_<Type>`（单下划线）、Checker 按引用点实例留痕 `moduleHits` 传 mangle 名（不猜裸名归属）。CLI：`check`/`compile` 接受目录；单文件模式默认参数兜底零改动。限制：跨模块 when 模式 / typealias 展开 / impl self 限定类型 / 限定函数类型形参的双向推导未支持；根模块无 settings；跨模块 `@unpure` 调用须 `unchecked`（P0 无跨模块 pure 事实）。

**其他**：impl 完整性 + `@new` 反向规矩、签名匹配、u-系命题算符（`u!= u-> u<-> u& u|`，粘连识别）、声明皆表达式（`VarExpr`/`AnonFunExpr`、`fun _` 省略式、`_` 不入符号表）、`type` 别名（决策 30：`syms.expand` 展开 + 两处类型位接入 + `baseOf` 认识别名 + 第二遍收集查重名）、Nothing 不可达警告、字面量除零警告、四级诊断（错误/警告/提示/补充）。

## 6. 工作纪律（血泪换来的）

1. **汇报前必须磁盘验证**。`Edit` 返回 `old_string not found` / `already occurs` / 空结果时，立即 `Read`/`Grep` 核对真实状态，**不得视为成功**。已两次实犯：改名未落盘却汇报通过；口头宣布"决策 57-63 已归档"实际未写入（决策 59 里自我记录）。
2. **端到端跑 node**。语义测试全绿 ≠ 生成的 JS 能跑。累计 8 个真 bug 里约 5 个是 node 实跑才暴露（三元链缺 else、`None` 未调用、`SymbolCallExpr` 丢运算符、负号类型、lambda 变量调用）。
3. **加完测试必须 `--rerun-tasks` 或确认 test 真的执行了**。曾只跑 `compileTestKotlin` 却读旧报告误判"新测试通过"。
4. **改语义必跑全量**。`typeLooseEq` 加一行递归比较回归了两个不相干测试（I-10）。
5. **决策入档**。每条用户拍板写进《草案思路.md》编号（已到 72，**v1.0 阶段需要补 73–75，之后 P0–P11 陆续加 76+**），代码注释引用编号；写注释前先确认编号存在。
6. **保守分析不产生假错误**，但**用户要求报错的场景要报专属错误**（I-4）。取舍有分歧时问，别自己拍。
7. **工具参数名要准**。曾三次把 `file_path` 写成 `path` 导致空调用。
8. **文档数字必须实测**。写"测试 N 项""行数 M"前先跑统计命令。（**当前 198 是 v1.0 计划写作时的实测值；`工程规范.md`/`语言简介.md`/`任务链.md` 里出现的 183 是第 4 轮完成值，两者不一致——v1.0 开工前先跑一次实测统一。**）
9. **遇到 `⬜ 待用户拍板` 停下问用户**，不许自己决定（v1.0 计划里有一批）。
10. **卡住超过 3 种改法就停下上报**——那通常意味着设计层面有问题，需要 Max 介入。不要连续硬扛。

## 7. 验证命令（一律走 CLI，不接管 IDE）

```powershell
cd F:\KotlinProject\sublimation
.\gradlew.bat test                                        # 全量（增量，可能跳过）
.\gradlew.bat test --rerun-tasks                          # 强制重跑
.\gradlew.bat -q run --args="check examples/when.subl"    # 语义检查（单文件）
.\gradlew.bat -q run --args="check examples/x.subl -v"    # 含补充级诊断
.\gradlew.bat -q run --args="compile examples/x.subl -o build/x.js"
node build/x.js                                           # 端到端实跑
.\gradlew.bat -q run --args="parse examples/x.subl"       # 语法树
.\gradlew.bat -q run --args="tokens examples/x.subl"      # token 流（含邻接标记）
```

**P0 后新增的目录形式**（P0 完成时启用）：

```powershell
.\gradlew.bat -q run --args="check <目录>"                 # 扫全树 → 语义检查
.\gradlew.bat -q run --args="compile <目录> -o out.js"      # 多模块合并编译
```

**逐轮验收**：四示例（diffuse/value/optional/when）产物必须与基线逐字节一致，且 `examples/goal.subl`（用户目标代码）必须编译并 node 实跑输出 `test`。
基线陈旧会伪装成回归：第 3 轮验收发现 `build/optional.js` 停留在决策 64 之前（flatten 去 else），对比报 identical=False 却实为源码演进——**改动波及 codegen 时先重新生成基线**再比对，并用 node 实跑输出对照佐证（输出相同 + 产物不同 = 死代码/格式差异，非行为回归）。

守护进程若因环境变化被换掉、出现 `Could not connect to Kotlin compile daemon`：先 `.\gradlew.bat --stop` 再重跑（旧进程会带着旧的文件可见范围）。

**工具调用纪律**：Read/Edit 的文件路径参数名是 `file_path`，写成 `path` 会被 schema 拒绝并白白消耗一轮；Grep 才用 `path`。同一条消息里混用两类工具时逐个核对参数名。

# 设计哲学

> 本文档面向编译器内部与语言设计者。公开特性速览见 `wiki/`。

## 一句话

Sublimation 是一门「类型即命题、程序即证明」的静态语言：把类型系统做成可证明的（伴生命题），把证明做成可自动搜索的（定理空间与关键表达式），同时保留面向实践的 Kotlin 风格表达力与可预测的 JS 后端。

## 核心取舍

1. **以伴生命题为纲，但不强制推理负担**
   命题挂在声明上（前件 `<...>`、后件 `<...>`），只有需要证明的位置（`∴`、`when` 穷尽、`if[p]`）才触发证明。绝大多数代码与普通语言无异。

2. **自动证明信奉「数据驱动」而非「完备逻辑」**
   - 结构相同的表达式自动自反：`1 + 2 = 1 + 2` 可直接证明；`1 + 2 = 3` 不证。
   - `when(n in _)` 的穷尽判定 = 收集区间端点（0,10,11,20,21,30…）作为**关键表达式**，排序衔接覆盖；再用定理空间里一切可用的定理补证。
   - 证明义务解决不了就报 `E-CANNOT-PROVE` 并列出尝试过的定理，绝不悄悄放过。

3. **定理是普通函数的特化，不是独立机制**
   定理 =「无副作用 + 不修改参数 + 返回 Null」的函数。**只有 `@theorem` 标注才是定理函数**：登记+编译器擦除（只供证明位）；未标注者（即使纯+Null）不是定理、照常生成。`∵`/`∴` 是调用定理的语法糖。

4. **所有容器统一实现 `Collection` 类型类，方法糖优先自由函数**
   `xs.f()` 的分派：先找同名自由函数（含「没有实现类型类的实现」即扩展方法）按接收者匹配；未命中再查类型类字典。`class` 声明本身不劫持方法名（只有实现了 impl 的类型才参与字典分派）。

5. **副作用与可变性是显式标注**（`@impure` / `@mut`），语言默认纯函数式；上下文中的表达式必须是纯的。

6. **模块 = 目录**，`mount` 挂载，std 隐式挂载；跨模块定理搜索可见路径的全部定理空间。

## 非目标

- 不做完全的数学证明器（不完备是特性：证明义务留在边界）。
- 不做运行时类型擦除的承诺（`Optional` 等有 JS 表示 `{ '0': v, tag: 'Some' }`）。
- 不为证明牺牲可读性：命题用人类可读的 `∈`/`≥`/`≤`/`∀`/`∃` 等记号。

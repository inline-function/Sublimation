## 1. 跑起来

编译器是纯命令行的 Gradle 项目（零第三方依赖，产物为 JS，用 node 运行）：

```powershell
cd F:\KotlinProject\sublimation
.\gradlew.bat -q run --args="check examples/showcase.subl"           # 语义检查（单文件）
.\gradlew.bat -q run --args="compile examples/showcase.subl -o out.js"
node out.js                                                         # 运行
.\gradlew.bat test                                                  # 全部测试

# P0：目录即模块——check / compile 接受目录
.\gradlew.bat -q run --args="check <项目根目录>"
.\gradlew.bat -q run --args="compile <项目根目录> -o out.js"
```

其它子命令：`parse`（打印语法树）、`tokens`（打印 token 流，看邻接标记很有用）。
**注意**：`check` / `compile` 不接受无参数默认 cwd——路径必须显式传（P0 明确不做）。

## 2. 两条铁律（先记住，少踩坑）

1. **顶层只能写声明**。`struct` / `enum` / `class` / `impl` / `type` / `fun` 之外，任何执行代码（调用、赋值、`unchecked.axiom`）都必须放进 `fun main()`。脚本模式（类 `.kts`，顶层即主序列）是将来特性，现在语法层直接拒绝。
2. **函数体两种形态互斥**（学 Kotlin）：
   - 单表达式体：`= 表达式`，**不带花括号** —— `fun add(a: Nat, b: Nat): Nat = a + b`
   - 语句块体：直接 `{ 语句… }`，**不带等号**
   - `= { … }` 混写会被拒（报错告诉你去掉哪一边）。

## 3. 三个心智模型

1. **万物皆表达式**。`var n = 0` 本身有值（就是 0），`when` / `if` / 块都是表达式。
2. **命题会弥散**。函数上文 `<p>` 要求作用域里有 `p`，下文 `<q>` 在调用后把 `q` 注入作用域，不用手动传。
3. **`unchecked` 是唯一逃逸口**。纯度、可变性、`Any`、公理注入都靠它，逃逸处留注释供审计。

## 4. 最小可跑程序

```sublimation
struct User(name: Str = "unknown", age: Nat = 0)

@unpure
fun main() {
    var u = User(name = "alice")
    print(u.name)     // alice
    print(u.age)      // 0（未传的字段取默认值）
}
```

写 `fun main()` 就是入口，编译器自动调用它。

## 5. 语法速览

### 函数与 return

```sublimation
fun add(a: Nat, b: Nat): Nat = a + b          // 单表达式体，无花括号

fun classify(n: Nat): Str {                    // 块体，无等号
    if n > 100 { return "big" }                // ✓ 提前 return（语句位）
    if n > 10  { return "mid" }
    return "small"
}
```

**return 的边界**（决策 75，与 codegen 严格对齐）：

| 位置 | 能否 `return` | 写法 |
|---|---|---|
| 函数 / 方法体的语句、**语句位** `if` 的分支 | ✓ 合法 | `if c { return 1 }` |
| 尾 `if`（**所有**分支都 return） | ✓ 合法 | `if c { return 1 } else { return 2 }` |
| **值位**：`var x = if …`、实参、块当值用、lambda 体 | ✗ `E-RETURN-OUTSIDE` | 改用尾表达式：`return if c { 1 } else { 2 }` |

值位为什么禁：它们编译成 JS 的 IIFE，`return` 只能跳出 IIFE、逃不出函数——静默错位，不如明确拒绝。

### 数据：struct 圆括号，字段可带默认值

```sublimation
struct Point(x: Nat, y: Nat)
struct Conf(host: Str = "localhost", port: Nat = 8080)

var p = Point(1, 2)              // 位置式（无默认值的字段须给全）
var c = Conf(port = 9090)        // 命名字段式，host 取默认值
```

命名字段构造只对**结构体**生效（大写名 + `字段 = 值` 触发）；函数命名传参 `f(x = 1)` 仍是命题等式中缀，未实现。默认值**只属于 struct 字段**，函数形参带 `=` 报 `E-DEFAULT-PARAM`。

### 枚举与解构（ADT）

```sublimation
enum Color { Red(), Green(), Blue() }
enum Shape { Circle(Nat), Rect(Nat, Nat) }

fun area(s: Shape): Nat = when(s) {
    Circle(r) -> 3 * r * r
    Rect(w, h) -> w * h
}                                   // 穷尽时无需 else
```

`when` 支持：字面量、构造子解构（可嵌套 `Some(Some(y))`）、元组解构 `(a, b)`、`is T [as x]`、通配 `_`、守卫 `if`、兜底 `else`、绑定主题 `when(var e = 0)`。
**穷尽性是提示不是要求**：判不出时值退化为 `Null`；只有名义枚举覆盖不全才发 `W-NON-EXHAUSTIVE`。

### 守卫的正确写法（重要陷阱）

守卫是**运行期条件**，必须用返回 Bool 的运算，不能用纯命题算符：

```sublimation
fun range(n: Nat): Str = when(n) {
    0 -> "zero"
    m if !=(m, 0) & !=(m, 1) -> "many"     // ✓ 前缀 !=、& → JS 条件
    else -> "small"
}
```

`≠` / `∧` / `=` 这些**命题算符**在值位会被擦成 `true`（它们是编译期逻辑，不进 JS 运行值），守卫里用了逻辑恒真，是坑。

### 元组与函数类型

```sublimation
var pair = (1, "a")                         // 逗号是判据；(1) 只是括号表达式
fun twice(f: (Nat) => Nat, x: Nat): Nat = f(f(x))
twice({ n -> n + 1 }, 10)                     // 11 —— v1.1 大括号 lambda
```

### 语法糖：隐式单参 lambda 与变量元组解构

**① 隐式单参 lambda `{ _ + 1 }`（无箭头）**——v1.1 Kotlin 化的省写。大括号里**没有箭头**时，整块成一个**单参 lambda**，参数由体里的 `_` 引用：

```sublimation
var inc: (Nat) => Nat = { _ + 1 }      // 等价 `{ x -> x + 1 }`
xs.map { _ * 2 }                        // 尾随调用同理
xs.filter { _ > 3 }
```

- 等价显式写法：`{ x -> x + 1 }`（参数名任意）。
- 只支持**单参**；多参仍需箭头 `{ a, b -> … }`。
- `_` 在**隐式单参 lambda 体**里引用该参数；在 `when`/构造子模式里仍是**通配**，两者不冲突。

**② 变量元组解构 `var (b, c) = a`**——把元组解构到多个变量（when 解构的声明级）：

```sublimation
var point = (1, 2)
var (x, y) = point       // 等价于 var x = point.0; var y = point.1
var name = "alice"
var (b, c) = name        // ✗ E-TUPLE-DESTRUCT：初值须为元组
```

- 初值**必须**是元组（否则 `E-TUPLE-DESTRUCT`），分量数**必须**一致（否则 `E-TUPLE-ARITY`）。
- 支持注解：`@mut var (a, b) = pair` 解构出可变变量。

### 型类（class ≈ trait）与隐式 self

```sublimation
class Named { fun describe(): Str }          // 成员只写签名，无接收者参数

impl Named for User {
    fun describe(): Str { return name }       // name ≡ self.name（隐式接收者）
}

u.describe()          // 点号调用（推荐）
describe(u)           // 自由式，等价；首实参即接收者
```

方法调用按实参类型解析型类字典分发。无实例报 `E-NO-INSTANCE`，多实例歧义报 `E-AMBIGUOUS-INSTANCE`，自由式漏接收者报 `E-NO-SELF`。

### 注解

| 注解 | 位置 | 含义 |
|---|---|---|
| `@mut` | var | 变量可赋值 |
| `@unpure` | fun | 声明非纯；纯作用域调用它需 `unchecked` 或供给 `pure<f>` |
| `@tuple` | 形参 | 变长参数=元组；只接受元组字面量实参 |
| `@new` | impl 成员 | 声明这不是实现型类的方法 |
| `@lazy` | var | 预留，未实现 |

### 上下文与命题

```sublimation
fun fact(): Null <answered> { unchecked.axiom[answered] }
fun usesIt()<answered>: Null {}

fun main() {
    fact()        // answered 弥散进作用域
    usesIt()      // 编译器自动找到 answered，无需手写
}
```

**命题可以改变代码行为**（核心）：

```sublimation
@unpure fun side(): Null {}
fun pureCaller()<pure<side>>: Null { side() }    // 持有 pure<side> ⇒ 放行非纯调用

fun main() {
    unchecked.axiom[pure<side>]    // @unpure 函数不自动注册 pure<name>，须显式供给
    pureCaller()
}
```

未标 `@unpure` 的函数，编译器自动给出 `pure<name>`。`$` 指代返回值（`fun get7(): Nat <$ = 7> { return 7 }`）。

### 多模块与挂载（P0，已可用）

**目录即模块**：每个目录是一个模块，同名 `.subl` 文件共享一个符号表。

```
project/                        ← 编译入口可以是这个目录
├── project.settings            ← 模块清单（挂载声明）
├── main.subl                   ← 属于 project 模块
├── data/
│   ├── stringData.subl
│   └── numberData.subl
└── processor/
    └── formatter.subl
core/
├── core.settings
└── math.subl
```

`project/project.settings`：

```
# 每行一个 mount；路径从根 / 起（绝对）
mount core
mount core/math as math        # as 别名可选
```

**可见性方向**：

| 方向 | 规则 |
|---|---|
| 同模块内 | 完全互相可见（裸名） |
| 父 → 子 | 可见，且**传递**（父看任意深度后代） |
| 子 → 父 | **不可见** |
| 兄弟 → 兄弟 | **默认不可见**，靠挂载建立 |
| 根 `/` | 可看所有后代；后代**看不到根**（根只是入口容器） |
| `main` | 唯一例外——codegen 扫全树找它，不走可见性检查 |

**引用路径**（相对当前模块视角）：

```sublimation
fun main() { unchecked print(core.gcd(3, 4)) }   // project/main.subl
fun via()  { core.gcd(1, 1) }                     // project/data/leaf.subl 写法一致
```

**impl 也要挂载**（显式装配，非隐式发现）：`d` 想用 `c` 里的 `impl Show for Point`，必须挂载 `c`，否则报 `E-NO-INSTANCE`。

**多父挂载**：同一模块被多处挂载，指向同一份符号（按绝对路径去重）。**挂载链成环**报 `E-CIRCULAR-MOUNT`；**本地名与挂载别名冲突**报 `E-DUP-DECL`（用 `as` 别名可解）。

**编译入口**：目录模式下 codegen 扫全树，**整个项目有且仅有一个 `main`**。

### 作用域须知（实测钉实）

**函数体是独立作用域帧**：顶层的 `var` 与顶层的 `unchecked.axiom` **不会**自动进入函数体。要用数据或公理，在所属函数内准备（或经参数、命题上文供给）。这也是为什么上面例子把 `axiom` 写进了 `main`。

## 6. 报错怎么读

四级诊断，都带 `[行:列]`：

- **错误**（无法编译）：`E-TYPE-MISMATCH`、`E-PRE-UNPROVEN`（前置命题没证据）、`E-IMPURE-CALL`、`E-RETURN-OUTSIDE`、`E-RETURN-TYPE`、`E-NO-INSTANCE`、`E-AMBIGUOUS-INSTANCE`、`E-ANY-STRUCT`、`E-FIELD-MISSING`、`E-CIRCULAR-MOUNT`、`E-PARSE-SETTINGS` 等
- **警告**（能编译但大概率有问题）：`W-NON-EXHAUSTIVE`、`W-UNREACHABLE`（return / Nothing 之后）、`W-DIV-ZERO`
- **提示**（建议改）：`H-PARAM-REF`（`$1` 可直接写参数名）、`H-FIELD-SHADOW`（参数遮蔽同名字段）
- **补充**（默认不显示，加 `-v`）：`D-TYPE-INFERRED`（推导出的类型）、`D-BY`

命题证不出 ≠ 它是假的——自动证明器健全但不完备。补一条 `unchecked.axiom[你的命题]` 即可继续。解析错误以异常直接抛给命令行打印（语法错无从继续语义分析），不进诊断列表。

## 7. 与 Kotlin 的差异要点

| 项目 | Kotlin | Sublimation |
|---|---|---|
| 结构体 | `data class` | `struct Point(x: Nat)`（圆括号，可带默认值） |
| 函数体 | 表达式体 `=`、块体无 `=` | 同，且**互斥**（`= {` 被拒） |
| 返回 | 任意层 `return` | **仅函数体语句流**（值位 / lambda 禁，改尾表达式） |
| 类型类 | 接口 + 实现 | `class` / `impl for`，隐式 self |
| 修饰符 | `val` / `var` / `private…` | 全部注解（`@mut` / `@unpure`） |
| 运算符优先级 | 有 | **无**，一律左结合：`1 + 1 * 1` 就是 `(1+1)*1` |
| 数值类型 | Int / Double | `Nat` / `Int` / `Rat`（无浮点术语） |
| 脚本 | `.kts` 顶层执行 | 暂不支持，执行代码进 `main`（脚本模式将来加） |
| 模块 | `package` / `import` | **目录即模块** + `<模块名>.settings` 挂载；引用用 `core.gcd` 点号路径 |
